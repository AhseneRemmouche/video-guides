The MCP Server: FastMCP & the First Tool

Create server.py with FastMCP and expose create_task as an MCP tool with @mcp.tool.

▶ Watch this part (32:27)

The database can store tasks, but nothing outside Python can reach it yet. In this step we build the MCP server with FastMCP and wrap our first database function in an MCP tool called create_task. Once a function is a tool, any MCP client, including an AI agent, can call it over the network.

What this step builds

We create a new file, src/mcp_server/server.py. It does three things: it imports our three database functions, it creates a FastMCP server object, and it turns the "create a task" action into a tool the outside world can use. We stop before the other two tools; those come in step 09.

The presenter starts this part of the video at 32:27. By the end you will be able to start a server that listens on http://127.0.0.1:8000/mcp and offers a create_task tool.

The concepts

An MCP server is just a normal program that advertises a set of tools and waits for a client to call them. FastMCP is the library that does the hard part for us: it takes an ordinary Python function and exposes it as a tool, including the tool's name, its description, and the shape of its inputs and outputs.

The way you turn a function into a tool is a decorator: you write @mcp.tool(...) on the line above the function. That one line registers the function with the server (the presenter walks through this around 34:00).

Why the tool name and description matter. Around 35:28–36:17 the presenter stresses that the name and description you give a tool are not decoration. When an AI agent is connected to this server, it reads each tool's name and description to decide whether and when to use that tool. The agent never sees your Python code; it only sees the words you wrote. A clear description like "this tool is to create new tasks" is how the model knows that "add a task for me" should call create_task. A vague or wrong description means the agent picks the wrong tool, or no tool at all.

Build it

  1. Create the file src/mcp_server/server.py next to database.py.
  2. Add the imports: the Literal helper, uuid4, FastMCP, and the three functions from database.py.
  3. Create the server object: mcp = FastMCP("MCP Server ACL").
  4. Write the create_task function and put @mcp.tool(...) on the line above it.
  5. Add the if __name__ == "__main__": block at the bottom so the file can start the server.

Why from mcp_server.database import ... works. This line imports from the package mcp_server, not from a file sitting next to server.py. It works because uv installed our project into the environment back in step 03, so Python can find the mcp_server package by name from anywhere. If you had not installed the project, this import would fail with ModuleNotFoundError.

The whole file

Here is the complete server.py. Read it once top to bottom; the tables below break it into pieces. The two further tools (list_tasks and update_task_status) are shown here too, but we only explain create_task on this page.

from typing import Literal
from uuid import uuid4

from fastmcp import FastMCP

from mcp_server.database import get_all_tasks, save_task, update_task_status_in_db

mcp = FastMCP("MCP Server ACL")


@mcp.tool(name="create_task", description="this tool is to create new tasks")
def create_task(title: str, priority: str = "medium", description: str = "") -> dict:
    """
    this function creates new tasks in our database
    """
    task_id = str(uuid4())
    status = "to do"
    task = {
        "task_id": task_id,
        "title": title,
        "description": description,
        "status": status,
        "priority": priority,
    }
    save_task(task)
    return task


@mcp.tool(
    name="list_tasks",
    description="this tool provides a list of all the tasks in our database",
)
def list_tasks() -> list[dict]:
    """this function returns all the tasks in our database"""
    return get_all_tasks()


@mcp.tool(
    name="update_task_status",
    description="this tool will update the status of a task based on its id",
)
def update_task_status(
    task_id: str, status: Literal["in progress", "completed"]
) -> dict:
    """this function will update the status for a specific task based on its id"""
    return update_task_status_in_db(task_id, status)


if __name__ == "__main__":
    mcp.run(transport="http", port=8000)

New to decorators? What they are and why they matter

A decorator is a line starting with @ written directly above a function. It is Python shorthand for "take this function and hand it to that other function, then use the result." Here, @mcp.tool(...) hands create_task to FastMCP, which registers it as a tool and remembers its name, description, inputs and output. You still call create_task(...) like normal in your own code, but now the server also knows about it. Remove the decorator and the function still runs in Python, but no MCP client can see or call it.

New to docstrings? What they are and why they matter

A docstring is a string written as the very first line inside a function (or module or class), usually in triple quotes. Python stores it as the function's documentation, and tools like editors and FastMCP can read it. It is not a comment: comments start with # and are thrown away, while a docstring stays attached to the function. Write it as a short, plain sentence describing what the function does.

New to type hints? What they are and why they matter

Type hints are the small annotations after a colon, like title: str (title is text), and after the arrow, like -> dict (this function returns a dictionary). Python does not force them at run time, but they document your intent and let tools check your code. FastMCP reads them to describe each tool's inputs and output to clients, and an agent uses that shape to send valid arguments. A special hint, Literal[...], restricts a value to an exact list of allowed choices; we use it in step 09.

New to UUIDs? What they are and why they matter

A UUID (universally unique identifier) is a long random id such as 3f2b1c9a-...-9d4e. The point is that if you generate one, it is practically guaranteed never to clash with any other UUID generated anywhere. That makes it a safe choice for a primary key: two tasks created at the same moment still get different ids. uuid4() returns a UUID object, so we wrap it in str(...) to store it as text.

New to HTTP transport and ports? What they are and why they matter

A transport is the channel a client and server use to talk. transport="http" means they talk over HTTP, the same protocol your web browser uses. A port is a numbered door on your machine; port=8000 tells the server to listen behind door 8000. Putting those together, the full address (the endpoint) is http://127.0.0.1:8000/mcp, where 127.0.0.1 means "this same computer."

What you should see. When you run the file, the terminal shows FastMCP's startup banner and a line saying the server is running on http://127.0.0.1:8000/mcp. The terminal then stays busy (it does not return to the prompt) because the server is waiting for clients. That is correct — leave it running and open a second terminal for the client in step 08. Stop it with Ctrl+C.

Common mistakes.

  • Do not run uv add uuid. Around 09:42 the video adds it, but uuid ships with Python. The PyPI uuid package is an old back-port that can shadow the real one. Just import it.
  • Forgetting the decorator. If you write create_task without @mcp.tool(...) above it, the server starts but offers no tools, and the client sees an empty list.
  • A vague description. Since an agent chooses tools by their description, a blank or misleading one makes the model skip the tool. Write a plain sentence that says what it does.
  • Import error. If from mcp_server.database import ... fails with ModuleNotFoundError, the project was not installed; re-run the install step from step 03 in the project root, with the environment active. Here it is again, so you don't need to switch pages: 
    uv add fastmcp langchain langchain-openai python-dotenv
