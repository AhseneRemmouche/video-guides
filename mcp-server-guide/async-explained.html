Async, await & asyncio

What async and await mean, why MCP clients and agents need them, and how asyncio.run starts everything.

Several files in this project use words you may not have seen before: async, await, and asyncio. They appear because the MCP client and the LangChain agent spend a lot of their time waiting for a reply over the network. This page explains, for an absolute beginner, what that waiting has to do with the code, and what each keyword actually does. You can read it before Step 08, or come back to it whenever a snippet uses await.

The short version

Talking to a server means waiting. Asynchronous code lets your program do other useful work during that wait instead of freezing. In Python you mark the waiting functions with async, you await each slow call, and you start the whole thing with asyncio.run(main()).

Synchronous vs asynchronous

A synchronous program does one thing at a time, in order. When it reaches a slow step, it stops and waits there until that step finishes before moving to the next line. That is simple to follow and it is how most beginner code works.

An asynchronous program can start a slow step, set it aside while it waits, and get on with something else in the meantime. When the slow step is ready, the program comes back to it. Nothing runs at the exact same instant — it is one worker who stops staring at the kettle and does other chores while the water heats, not two workers.

New to "blocking"? What it means and why it matters

A step is blocking when it holds up everything behind it until it is done. Reading a reply from a network server is blocking: the data has not arrived yet, so a synchronous program simply sits there. Asynchronous code turns that dead waiting time into time the program can spend elsewhere. For a program that makes many network calls, this is the difference between finishing quickly and crawling.

Why MCP clients and agents are async

Our MCP client does almost nothing by itself. It sends a request to the MCP server over HTTP and then waits for the answer to travel back. The LangChain agent is the same story, only more so: it waits for the LLM to think and reply, then waits for each tool call to finish. Most of the elapsed time is network waiting, not computing.

Because the libraries are built for that waiting, their calls are asynchronous. That is why you see await client.call_tool(...) in the FastMCP client and await agent.ainvoke(...) in the LangChain client. The a in ainvoke even stands for "async". Using these calls the async way is not optional — it is how the libraries are designed to be used.

What a coroutine is

When you put async in front of def, you create an asynchronous function. Calling it does not run its body right away. Instead it hands you a coroutine — an object that represents the work, ready to run but not started.

async def greet():
    return "hello"

result = greet()     # this does NOT print or return "hello"
print(result)        # <coroutine object greet at 0x...>

This surprises almost everyone the first time. The function looked normal, but calling it gave back a coroutine instead of the value. To actually get the value, you have to run the coroutine, and that is what await and asyncio.run are for.

What await does

await runs a coroutine and pauses the current async function until that coroutine finishes, then gives you its result. While it is paused, the event loop is free to run other coroutines, so the waiting is not wasted. You can only use await inside a function marked async.

async def main():
    message = await greet()   # run the coroutine, wait, get the value
    print(message)            # hello

Read await as "start this, let me wait for it without freezing everything, and give me the answer." Every slow call in this project — connecting to the server, calling a tool, invoking the agent — is awaited for exactly that reason.

What async with does

A plain with block in Python opens something, lets you use it, and cleans it up automatically at the end even if an error happens. The FastMCP client needs the same safe open-and-close, but opening and closing a network connection are themselves async steps. async with is the asynchronous version: it awaits the setup when the block starts and awaits the cleanup when the block ends.

async def main():
    async with Client("http://127.0.0.1:8000/mcp") as client:
        tools = await client.list_tools()
        print(tools)
    # the connection is closed automatically here

Inside the block the connection is open and ready; the moment you leave the block, FastMCP closes it for you. You do not have to remember to disconnect.

What asyncio.run(main()) does

Everything above needs something to actually run the coroutines. That something is the event loop, and asyncio provides it. asyncio.run(main()) creates a fresh event loop, runs your top-level coroutine main() on it until it finishes, and then shuts the loop down cleanly.

import asyncio

async def main():
    print("doing async work")

if __name__ == "__main__":
    asyncio.run(main())

This is the bridge between ordinary synchronous Python (the bottom of your file) and the async world (everything you awaited). You call asyncio.run(...) once, at the top level, and let it drive the rest.

The "coroutine was never awaited" warning

This is the most common async mistake, and the video hits it on screen (at 61:55). It happens when you call an async function but forget to await it or to pass it to asyncio.run(...). You created a coroutine and then threw it away without ever running it, so Python warns you.

async def main():
    print("hello")

main()   # WRONG: builds a coroutine, never runs it
# RuntimeWarning: coroutine 'main' was never awaited
How to avoid it
  • Put await in front of every async call inside an async function.
  • Start your program's top-level async function with asyncio.run(main()), not a bare main().
  • If your editor underlines the result of an async call as a "coroutine", you almost certainly forgot an await.
What you should see

When the keywords line up correctly — async def main(), await on each slow call, and asyncio.run(main()) at the bottom — the program runs, prints its results, and exits with no warnings. That is the pattern used by both client.py and langchain_client.py.

Recap
  • Synchronous code waits idly at every slow step; asynchronous code uses that waiting time for other work.
  • MCP clients and agents are async because they spend most of their time waiting on the network and the model.
  • Calling an async function returns a coroutine, which does nothing until it is run.
  • await runs a coroutine and waits for its result without freezing the program; it only works inside an async function.
  • async with safely opens and closes something whose setup and cleanup are themselves async, like the FastMCP client connection.
  • asyncio.run(main()) starts the event loop, runs your top-level coroutine, and shuts the loop down.
  • "coroutine ... was never awaited" means you built a coroutine but never ran it — add the missing await or asyncio.run(...).
