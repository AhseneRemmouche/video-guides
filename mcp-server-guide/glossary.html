Glossary

Every technical term in this guide, explained for beginners.

Every term used in this guide, explained in plain language. You do not need to read this page top to bottom. Each step links the first time it uses a word, and the link jumps straight to the matching entry here. If something in a step feels unfamiliar, come back and look it up.

MCP & protocols

MCP (Model Context Protocol)
A shared set of rules that lets an AI application ask an outside program for tools and data. Instead of hard-wiring a model to one app, MCP gives any client a standard way to discover and call the same tools. In this project the tools manage a task list.
MCP server
A program that offers tools over MCP and waits for requests. Our server is written with FastMCP, is named "MCP Server ACL", and exposes three tools: create a task, list tasks, and update a task's status.
MCP client
A program that connects to an MCP server, asks what tools it has, and calls them. In this guide three different clients talk to the same server: a plain FastMCP client, a LangChain agent, and Codex.
MCP tool
A single action an MCP server offers, with a name, a description, and typed inputs. A client (or the model behind it) picks a tool by name and passes arguments. Our tools are create_task, list_tasks and update_task_status.
FastMCP
A Python library that makes building an MCP server or client easy. You create a FastMCP object, mark functions as tools with a decorator, and call mcp.run(...). This guide uses FastMCP version 4.1.6.
Protocol
An agreed format and order for messages so two programs can understand each other. MCP is a protocol; HTTP is another. When both sides follow the same protocol, they can talk even though they were written separately.
Transport
The channel that carries protocol messages between client and server. Our server uses the http transport, so messages travel over a network connection on your own machine.
HTTP
The request-and-response protocol the web is built on. A client sends a request and the server sends back a response. FastMCP can carry MCP messages over HTTP, which is how our clients reach the server.
Endpoint
A specific address a client sends requests to. Our server's endpoint is http://127.0.0.1:8000/mcp — the host, the port, and the /mcp path all together.
Port
A numbered door on a computer that a program listens on, so several programs can share one machine without clashing. Our server listens on port 8000.
localhost
A name for your own computer, with the numeric address 127.0.0.1. When the client connects to 127.0.0.1:8000 it is talking to a server running on the same machine, not over the internet.

Clients, servers & agents

Client
The program that starts a conversation by sending a request. In a client/server pair the client asks and the server answers. Our FastMCP client and LangChain agent are both clients of the MCP server.
Server
The program that waits for requests and sends back responses. It keeps running so clients can connect whenever they need to. Here the server holds the task tools and the database behind them.
Agent
An AI program that is given a goal and a set of tools, and decides on its own which tools to call to reach that goal. Our LangChain agent reads a user message, picks one of the MCP tools, calls it, and replies.
LLM (large language model)
The AI model that turns text into text and can decide which tool to use. This project uses OpenAI's gpt-4o-mini as the model behind the agent.
OpenAI API
OpenAI's online service for sending prompts to their models and getting replies back. Code reaches it over the network using an API key. LangChain's langchain-openai package talks to it for us.
API key
A secret string that proves your code is allowed to use a paid service such as the OpenAI API. It is kept in the .env file and never committed to git. Treat it like a password.

LangChain & LLMs

LangChain
A Python framework for building applications around LLMs: agents, tools, messages, and more. This guide uses LangChain version 1.4.9, whose agent builder is create_agent.
LangGraph
A companion library to LangChain that runs agents as a graph of steps and can save their state between calls. We use its InMemorySaver as the agent's memory store.
create_agent
The LangChain 1.x function that builds a ready-to-run agent from a model, a list of tools, a system prompt, and an optional memory saver. You then call the agent to let it reason and use the tools.
Checkpointer
An object that saves an agent's conversation state so a later call can continue where the last one stopped. We pass InMemorySaver(), which keeps that state in memory (it is lost when the program ends).
thread_id
A label that tells the checkpointer which conversation a call belongs to. Reusing the same thread_id continues one chat; a new id starts a fresh one. It is passed inside config={"configurable": {"thread_id": ...}}.
System prompt
Background instructions given to the model before the user's message, telling it how to behave and what job it has. Our agent's system prompt tells it that it manages tasks with the available tools.
HumanMessage
A LangChain object that represents a message from the user. You wrap your text in HumanMessage(content=...) and pass it to the agent. In LangChain 1.x it is imported from langchain.messages.
Tool calling
The ability of a model to reply not with text but with a request to run a named tool and its arguments. The agent runs the tool, feeds the result back, and the model continues. This is how the LLM actually creates and lists tasks.
MCP adapter
A bridge that turns MCP tools into LangChain tools so an agent can use them. In LangChain 1.x it is built in: from langchain.mcp import MCPAdapter. It is a beta module and the editor may underline it, but it runs.

Databases & SQL

SQLite
A small database engine that stores everything in a single file and needs no separate server to run. Python includes it in the standard library, so no install is needed. Our tasks live in data/tasks.db.
Database
An organised store of data that you can add to, change, and query reliably. This project's database holds one table of tasks.
Table
A named grid inside a database, with columns for the fields and rows for the records. Our single table is called tasks.
Row
One record in a table — here, one task with its id, title, description, priority, and status. Adding a task adds a row.
Column
One named field that every row in a table has, such as title or priority. The columns define the shape of each record.
Primary key
The column whose value uniquely identifies each row, so no two rows share it. In the tasks table the primary key is task_id, a UUID string.
SQL
The language you use to talk to a relational database: create tables, insert rows, update them, and read them back. SQLite understands SQL. Our database functions send SQL strings to it.
INSERT
The SQL command that adds a new row to a table. Forgetting its VALUES keyword is a mistake the video shows on screen.
UPDATE
The SQL command that changes values in rows that already exist, usually limited with a WHERE clause so only the matching row changes. We use it to set a task's status.
SELECT
The SQL command that reads rows out of a table without changing them. get_all_tasks uses a SELECT to return every task.
CRUD
Short for Create, Read, Update, Delete — the four basic things you do with stored data. Our tools cover create, read, and update (there is no delete tool).
Connection
An open link to a database that lets you run commands on it. In Python's sqlite3 you open one with sqlite3.connect(path) and close it when done.
Cursor
An object you get from a connection and use to run SQL statements and read their results. You call cursor.execute(sql, ...) and then fetch the rows.
Commit
Saving the changes you have made so they become permanent in the database file. Without connection.commit() an insert or update can be lost when the connection closes.
Row factory
A setting on a SQLite connection that decides what shape each returned row takes. Setting it to sqlite3.Row lets the code read columns by name and turn each row into a dictionary.

Python language

Python
The programming language this whole project is written in. It is beginner-friendly and comes with SQLite, UUIDs, and asyncio built in. This guide uses Python 3.12.
Dictionary
A Python value that maps keys to values, written with curly braces, like {"title": "Buy milk"}. Our database functions return each task as a dictionary of column names to values.
UUID
A universally unique identifier — a long random-looking string that is practically guaranteed not to repeat. We use one as each task's id. Python makes them with the built-in uuid module; do not install a uuid package.
Decorator
A line starting with @ placed above a function to add behaviour to it. @mcp.tool(...) is a decorator that registers a function as an MCP tool.
Docstring
A short text written in triple quotes at the top of a function that describes what it does. For MCP tools the docstring also tells the model what the tool is for, so it is worth writing clearly.
Type hint
A note in the code that says what kind of value a variable or argument should be, such as title: str. Type hints help editors catch mistakes, and FastMCP uses them to describe a tool's inputs.
Literal type
A type hint that limits a value to a fixed list of allowed options, written like Literal["in progress", "completed"]. The update tool uses one so only those two status values are accepted.
async
A keyword that marks a function as asynchronous, meaning it can pause while waiting (for a network reply, say) and let other work run. Calling such a function gives you a coroutine that must be awaited. See the Async explained page.
await
A keyword used inside an async function to run another async call and wait for its result without blocking everything else. The MCP client calls such as await client.call_tool(...) use it.
asyncio
Python's built-in library for running asynchronous code. asyncio.run(main()) starts the event loop and runs your top-level async function. Like uuid, it is part of the standard library — do not install it.
Coroutine
The special object you get when you call an async function. It does not run until it is awaited (or handed to asyncio.run). Forgetting to await it triggers the "coroutine ... was never awaited" warning.
Event loop
The engine inside asyncio that runs coroutines, switching between them whenever one is waiting. asyncio.run(...) creates a loop, runs your code on it, and shuts it down at the end.
JSON
A simple, text-based format for structured data, built from objects, lists, strings, and numbers. Configuration such as mcp.json and many MCP messages are written in JSON.

Tooling & environment

uv
A fast Python package and project manager. It creates the project, makes a virtual environment, and installs dependencies with commands like uv init, uv venv and uv add.
Virtual environment
A private folder of Python packages for one project, so its dependencies do not clash with other projects or the system. uv venv creates it; you activate it before working.
Package manager
A tool that downloads and tracks the outside libraries your project needs and records their versions. uv is the package manager used here.
Dependency
An outside library your project needs in order to run, such as fastmcp or langchain. Dependencies are listed in pyproject.toml and installed into the virtual environment.
python-dotenv
A small library that reads key/value pairs from a .env file and loads them as environment variables when the program starts. This is how the OpenAI API key reaches the code without being written in it.
.env file
A plain text file holding secret settings such as OPENAI_API_KEY, one per line. It is listed in .gitignore so it is never committed. A safe .env.example with empty values is shared instead.
.gitignore
A file that tells git which files and folders to leave out of version control, such as the real .env and the data/tasks.db file. It keeps secrets and generated files out of the repository.
Terminal
The text window where you type commands to run tools like uv and to start the server. On Windows this guide uses PowerShell, where the prompt looks like PS D:\ACL\MCP_Server>.
VS Code
Visual Studio Code, the free code editor used throughout the video. It has a built-in terminal and shows warnings from tools like Pylance as underlines in your code.
Codex
An AI coding assistant that can itself act as an MCP client. In the bonus step you point it at our server with an mcp.json file so it can call the task tools too.
