Project Setup

Create the project with uv, a Python 3.12 virtual environment, the dependencies, and .env files.

What the presenter sets up (at 07:13)

The presenter is on Windows, working inside VS Code with its built-in terminal open (the prompt looks like PS D:\ACL\MCP_Server>, which is PowerShell). Before writing any project code, they do four things: make sure the tools are installed, create an isolated place for this project's packages, record the project's details in a config file, and install the libraries. We follow the same order.

The package manager used throughout is uv. It is a fast, modern replacement for pip and venv rolled into one tool. It creates the virtual environment, keeps track of your dependencies in pyproject.toml, and installs them.

New to virtual environments? What they are and why they matter

A virtual environment is a private copy of Python and its installed packages that belongs to one project. Without it, every pip install drops packages into one shared system Python, so two projects that need different versions of the same library will clash. With a virtual environment, this project's fastmcp and langchain live in a local folder (here called .venv) and touch nothing outside it. You "activate" the environment to switch your terminal into using it, and everything you install afterwards goes only there. Delete the folder and the project's packages are gone, cleanly.

New to package managers and uv? What uv does

A package manager downloads the libraries your code imports, picks versions that work together, and records them so anyone else can reproduce the exact same setup. Python's traditional tools are pip (installs packages) and venv (makes environments). uv does both jobs and is much faster. When you run uv add fastmcp, uv installs fastmcp into .venv, adds a line to pyproject.toml, and writes a lock file so the versions are pinned. You never edit pyproject.toml by hand for dependencies; you let uv do it.

Step by step

  1. Open the project folder in VS Code. Create an empty folder for the project (the presenter calls it MCP_Server), then open it with File → Open Folder, or from a terminal already inside the folder run code . (the dot means "this folder"). Then open the integrated terminal with Ctrl+` (the backtick key).
  2. Confirm Python is installed. In the terminal, check the version: 
    python --version
    You should see something like Python 3.12.x. Any version from 3.11 to 3.13 is fine for this project. If the command is not found, install Python from python.org first.
  3. Confirm uv is installed. 
    uv --version
    If you see a version number, you are set. If not, install uv (on Windows, the quickest way is pip install uv, or follow the official installer), then reopen the terminal.
  4. Initialise the project with uv. This creates a pyproject.toml (the project's config file) and a few starter files: 
    uv init
    Run this once, in the project's root folder.
  5. Create the virtual environment. Ask uv for a Python 3.12 environment. uv puts it in a folder named .venv: 
    uv venv --python 3.12
    If you only have 3.11 or 3.13 installed, use that number instead; the project works on all three.
  6. Activate the virtual environment. On Windows (PowerShell), run the activation script that uv created: 
    .venv\Scripts\activate
    Your prompt now shows (.venv) at the start, which means the environment is active. On macOS or Linux the command is source .venv/bin/activate instead.
  7. Add the project's dependencies. One command installs all four libraries and records them in pyproject.toml: 
    uv add fastmcp langchain langchain-openai python-dotenv
    uv resolves compatible versions, downloads them into .venv, and updates the config and lock file.
  8. Create the three secrets files in the project root: .env (your real key, never shared), .env.example (a blank template, shared), and .gitignore (tells Git what to leave out). Their contents are shown below.
Common mistake: do not run uv add uuid asyncio. In the video the presenter also runs uv add uuid and uv add asyncio (around 09:42). Do not copy that. Both uuid and asyncio are already part of Python's standard library, so they ship with Python itself. The packages of the same name on PyPI are old back-ports from years ago; installing them can shadow the real built-in modules and cause confusing errors. You never install them. In your code you simply write import uuid and import asyncio and it just works. The only dependencies this project needs are the four in step 7.

The dependencies, recorded in pyproject.toml

After uv add, your pyproject.toml lists the four libraries under dependencies. This is the file that describes the whole project: its name, its Python requirement, and what it depends on. You did not type these lines; uv wrote them for you.

[project]
name = "mcp-server-acl"
version = "0.1.0"
description = "A task-manager MCP server, its clients, and a LangChain agent."
requires-python = ">=3.11,<3.14"
dependencies = [
    "fastmcp>=4.1.6",
    "langchain>=1.4.9",
    "langchain-openai>=1.7.4",
    "python-dotenv>=1.2.4",
]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

New to environment variables and dotenv? What they are

An environment variable is a named value that lives in your operating system or terminal session, not in your source code. Programs read them to get settings and secrets, such as an API key. Hard-coding a secret key straight into a .py file is dangerous, because that file usually gets committed to Git and shared. Instead you put the key in a .env file and use the dotenv library to load it into an environment variable at run time. Your code then reads the variable, never the raw key.

Secrets: .env, .env.example and .gitignore

This project calls an OpenAI model, which needs an API key. That key is a secret: anyone who has it can spend money on your account. So the real key goes in a file named .env that you never commit to Git, and a safe-to-share template named .env.example shows which variables are expected, with the values left blank.

Create .env yourself with your real key, like OPENAI_API_KEY=sk-...your-key.... It is not shown here on purpose. The committed template looks like this:

OPENAI_API_KEY=

The last file, .gitignore, tells Git which files and folders to leave out of version control. This is how your real .env, your local database, and the big .venv folder stay off GitHub.

Line by line: .gitignore

LineCodeWhat it does & why
1.venv/Ignores the virtual environment folder. It is large and machine-specific; anyone can rebuild it from pyproject.toml, so it should never be committed.
2__pycache__/Ignores Python's compiled-bytecode cache folders. They are generated automatically and add noise to a repository.
3data/Ignores the data folder, where the SQLite database file is created at run time. Local data does not belong in version control.

Common mistakes.
  • Forgetting to activate. If your prompt does not show (.venv), you are not in the environment, and uv add may install to the wrong place. Re-run the activate command.
  • Wrong activate path on Windows. It is .venv\Scripts\activate with a backslash and Scripts, not bin. The bin form is for macOS and Linux.
  • Running uv add uuid asyncio. Explained above: do not. They are standard-library modules.
  • Committing .env. Make sure .gitignore exists and contains .env before your first commit, or your key could be pushed to GitHub.
Recap
  • You opened the project in VS Code and confirmed Python and uv are installed.
  • uv init created pyproject.toml; uv venv --python 3.12 created the virtual environment; activating it switched your terminal into it.
  • uv add fastmcp langchain langchain-openai python-dotenv installed the four real dependencies and recorded them.

  • .env holds your real key and is git-ignored; .env.example is the shared blank template; .gitignore keeps secrets, the database and .venv out of Git.
