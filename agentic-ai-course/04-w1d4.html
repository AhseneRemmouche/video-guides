Week 1 Day 4 · A chatbot that acts like you, with an evaluator

Frameworks, resources versus tools, a Gradio chatbot built from your LinkedIn PDF, and a second model that rejects bad replies.

What this day builds

The start of Project 1, "your career alter ego": a chatbot for your website that answers questions about your career as if it were you. Day 4 builds it in three moves. First, two theory lectures place the agent frameworks on a ladder and explain the difference between giving an LLM resources (more context) and tools (the power to make your code do something). Then the lab reads your LinkedIn profile from a PDF, puts it in the system prompt and wraps a chat function in a Gradio page. Finally a second LLM checks every reply with a structured output and forces a retry when the reply is bad: Day 2's evaluator–optimizer pattern, built without any framework.

TypeScript: the chatbot logic lives in src/career.ts (shared with Day 5), the evaluator demo in src/lab3.ts (pnpm lab3). PDF text comes from the unpdf package; the structured output uses the openai package's zod helper.

Where the frameworks sit (lecture 16)

Frameworks provide "glue code or abstraction code that takes away some of the detail of interacting with LLMs" so you can focus on the business problem. The slide arranges them in three tiers by weight. At the bottom, no framework: calling the APIs directly, as this week does, and the approach Anthropic's Building Effective Agents post argues for, because "you get to see exactly what's going on under the hood". Next to it, MCP, which is "not a framework, it is a protocol" for connecting models to data and tools (Week 6). In the middle, the OpenAI Agents SDK ("super lightweight and simple and clean and flexible… one of my very favourites", Week 2) and CrewAI ("a low-code angle… configuration through YAML files", Week 3). At the top, LangGraph and AutoGen, heavier with a steeper learning curve: with LangGraph "you're signing up for the ecosystem… it becomes much less of an agentic AI project and more of a LangGraph project" (Weeks 4 and 5). "My bias is towards downwards. I like the ones that stay out of your way" (05:37).

Resources versus tools (lecture 17)

Resources improve an LLM's expertise, and "basically, this just means shoving data relevant to the question into the prompt." An airline support bot could carry every ticket price in its prompt; techniques like RAG (retrieval-augmented generation, covered in the presenter's other course) pick only the relevant part. Today's chatbot uses resources: your profile goes into the system prompt.

Tools give the LLM the power to do something "at its discretion", "one of the key tricks to giving an LLM some autonomy". It sounds "kind of creepy", as if OpenAI could reach into your computer. In practice it cannot: "in the prompt to the LLM, you just list out everything that it's able to ask for, and you tell it to respond in JSON… at the end of the day, you have to write an if statement in your code… if the LLM wants to do X, then do X, and then call the LLM a second time with the results" (04:05). The presenter demonstrates the idea in ChatGPT with a plain prompt that says "just respond only 'Use tool to fetch ticket price for London'"; asked about Paris, it replies "Use tool to fetch ticket price for Paris." Tools arrive on Day 5; today is resources.

The system prompt and the chat function (04:34–08:02)

"The system prompt is intended to be more the overall instructions that sets the context for the task at hand… the user prompt is the actual question coming from the user." This one tells the model it is acting as you on your website, should be professional "as if talking to a potential client or future employer", and adds "If you don't know the answer, say so", which is "very good prompting". Then it appends the summary and the LinkedIn text under markdown headings and a final reminder to stay in character.

Gradio's ChatInterface needs one callback: a function that takes the user's new message and the history of the conversation so far (already in OpenAI's role/content format) and returns the reply. gr.ChatInterface(chat, type="messages").launch() is "beautifully simple": a chat page appears inside the notebook.

def chat(message, history):
    messages = [{"role": "system", "content": system_prompt}] + history + [{"role": "user", "content": message}]
    response = openai.chat.completions.create(model="gpt-4o-mini", messages=messages)
    return response.choices[0].message.content
// Week 1 Day 4 — the chatbot plus an evaluator that can reject a reply (TypeScript version of 1_foundations/3_lab3.ipynb)
// The lab's "pig latin" trick forces a bad reply so you can watch the evaluator catch it and the rerun fix it.
import type OpenAI from "openai";
import { NAME, evaluate, evaluatorSystemPrompt, loadResources, type ChatTurn } from "./career.js";
import { model, openai } from "./setup.js";

const { summary, linkedin } = await loadResources();
const system =
  `You are acting as ${NAME}. You are answering questions on ${NAME}'s website, ` +
  `particularly questions related to ${NAME}'s career, background, skills and experience. ` +
  `Your responsibility is to represent ${NAME} for interactions on the website as faithfully as possible. ` +
  `You are given a summary of ${NAME}'s background and LinkedIn profile which you can use to answer questions. ` +
  `Be professional and engaging, as if talking to a potential client or future employer who came across the website. ` +
  `If you don't know the answer, say so.` +
  `\n\n## Summary:\n${summary}\n\n## LinkedIn Profile:\n${linkedin}\n\n` +
  `With this context, please chat with the user, always staying in character as ${NAME}.`;
const evaluatorSystem = evaluatorSystemPrompt(summary, linkedin);

async function complete(messages: OpenAI.ChatCompletionMessageParam[]) {
  const r = await openai.chat.completions.create({ model: model("gpt-4o-mini"), messages });
  return r.choices[0]!.message.content ?? "";
}

/** Retry with the rejected answer and the reason in the system prompt. */
async function rerun(reply: string, message: string, history: ChatTurn[], feedback: string) {
  const updated =
    system +
    "\n\n## Previous answer rejected\nYou just tried to reply, but the quality control rejected your reply\n" +
    `## Your attempted answer:\n${reply}\n\n## Reason for rejection:\n${feedback}\n\n`;
  return complete([{ role: "system", content: updated }, ...history, { role: "user", content: message }]);
}

/** A chat turn that is evaluated before it is returned. "patent" triggers a deliberately bad pig-latin reply. */
async function chat(message: string, history: ChatTurn[]) {
  const sys = message.includes("patent")
    ? system + "\n\nEverything in your reply needs to be in pig latin - it is mandatory that you respond only and entirely in pig latin"
    : system;
  let reply = await complete([{ role: "system", content: sys }, ...history, { role: "user", content: message }]);
  const evaluation = await evaluate(evaluatorSystem, reply, message, history);
  if (evaluation.is_acceptable) {
    console.log("Passed evaluation - returning reply");
  } else {
    console.log("Failed evaluation - retrying");
    console.log(evaluation.feedback);
    reply = await rerun(reply, message, history, evaluation.feedback);
  }
  return reply;
}

for (const q of ["Where are you from?", "do you hold a patent?"]) {
  console.log(`\nUSER: ${q}`);
  console.log(`BOT: ${await chat(q, [])}`);
}

An evaluator that can say no (lecture 19)

The plan, from the notebook's markdown: "1. Be able to ask an LLM to evaluate an answer. 2. Be able to rerun if the answer fails evaluation. 3. Put this together into 1 workflow. All without any Agentic framework!" This is "that agentic design pattern where we have an evaluator–optimizer".

A schema for the verdict

Pydantic is "a framework for specifying a schema… using classes". The verdict has two fields: is_acceptable and feedback. The evaluator gets the same summary and LinkedIn text as the agent, plus a user prompt with the conversation, the latest message and the latest reply. Then a structured-output call: "a way that you can require an LLM to respond in a form of an object like this. It's just JSON behind the scenes… the client library is going to take that JSON and use it to populate the object. So it gives you the impression that you're getting code back from the LLM. But that's another of these conjuring tricks" (03:54). The evaluator is Gemini through its OpenAI-compatible endpoint, as on Day 3, but "you can just simply replace this with the normal OpenAI or with Llama if you want to run locally" (03:28).

// ---------- the evaluator (Day 4) ----------
export const Evaluation = z.object({ is_acceptable: z.boolean(), feedback: z.string() });
export type Evaluation = z.infer<typeof Evaluation>;

export function evaluatorSystemPrompt(summary: string, linkedin: string) {
  return (
    `You are an evaluator that decides whether a response to a question is acceptable. ` +
    `You are provided with a conversation between a User and an Agent. Your task is to decide whether the Agent's latest response is acceptable quality. ` +
    `The Agent is playing the role of ${NAME} and is representing ${NAME} on their website. ` +
    `The Agent has been instructed to be professional and engaging, as if talking to a potential client or future employer who came across the website. ` +
    `The Agent has been provided with context on ${NAME} in the form of their summary and LinkedIn details. Here's the information:` +
    `\n\n## Summary:\n${summary}\n\n## LinkedIn Profile:\n${linkedin}\n\n` +
    `With this context, please evaluate the latest response, replying with whether the response is acceptable and your feedback.`
  );
}

const gemini = compatibleClient("https://generativelanguage.googleapis.com/v1beta/openai/", process.env.GOOGLE_API_KEY);

/** Ask a second model (Gemini in the course) to judge a reply, with a structured output. */
export async function evaluate(evaluatorSystem: string, reply: string, message: string, history: ChatTurn[]): Promise<Evaluation> {
  const user =
    `Here's the conversation between the User and the Agent: \n\n${JSON.stringify(history)}\n\n` +
    `Here's the latest message from the User: \n\n${message}\n\n` +
    `Here's the latest response from the Agent: \n\n${reply}\n\n` +
    `Please evaluate the response, replying with whether it is acceptable and your feedback.`;
  const response = await gemini.chat.completions.parse({
    model: model("gemini-2.5-flash"),
    messages: [{ role: "system", content: evaluatorSystem }, { role: "user", content: user }],
    response_format: zodResponseFormat(Evaluation, "evaluation"),
  });
  return response.choices[0]!.message.parsed ?? { is_acceptable: true, feedback: "evaluator returned nothing" };
}

Rerun with the rejection in the prompt (06:45)

When the evaluator says no, rerun calls the model again with an expanded system prompt: the original, then "## Previous answer rejected", the attempted answer, and the reason for rejection. That is "the bottom arrow, the red feedback arrow" of Day 2's diagram.

def rerun(reply, message, history, feedback):
    updated_system_prompt = system_prompt + "\n\n## Previous answer rejected\nYou just tried to reply, but the quality control rejected your reply\n"
    updated_system_prompt += f"## Your attempted answer:\n{reply}\n\n"
    updated_system_prompt += f"## Reason for rejection:\n{feedback}\n\n"
    messages = [{"role": "system", "content": updated_system_prompt}] + history + [{"role": "user", "content": message}]
    response = openai.chat.completions.create(model="gpt-4o-mini", messages=messages)
    return response.choices[0].message.content

The pig-latin test (09:40)

To see a failure on demand, the final chat poisons its own system prompt whenever the message contains "patent": "Everything in your reply needs to be in pig latin". The evaluator, which has the clean instructions, should reject that reply, and the rerun should produce normal English. "My sister and I used to be really great at speaking quickly in pig Latin… it would probably drive a future employer crazy too."

def chat(message, history):
    if "patent" in message:
        system = system_prompt + "\n\nEverything in your reply needs to be in pig latin - \
              it is mandatory that you respond only and entirely in pig latin"
    else:
        system = system_prompt
    messages = [{"role": "system", "content": system}] + history + [{"role": "user", "content": message}]
    response = openai.chat.completions.create(model="gpt-4o-mini", messages=messages)
    reply =response.choices[0].message.content

    evaluation = evaluate(reply, message, history)
    
    if evaluation.is_acceptable:
        print("Passed evaluation - returning reply")
    else:
        print("Failed evaluation - retrying")
        print(evaluation.feedback)
        reply = rerun(reply, message, history, evaluation.feedback)       
    return reply

Structured outputs and tools are cousins

The presenter asks you to notice "the analogy between using structured outputs with using tools" (12:00). In both, you give the model a JSON schema you defined, and the model replies with JSON that fits it. With structured outputs the reply always takes that shape and is your answer. With tools, the model may choose to reply with a request ("call record_unknown_question with these arguments") instead of an answer, and your code acts on it. Day 5 is about the second.

Video vs repo. The video imports from PyPDF2 import PdfReader; the repo uses the maintained successor pypdf. The evaluator model is gemini-2.0-flash on screen and gemini-2.5-flash in the repo. The chat and rerun calls still use gpt-4o-mini in both. The repo adds the "Special note for people not using OpenAI" cell about cleaning the Gradio history. A few lines on screen carry a harmless extra f prefix.

Common mistakes

  • FileNotFoundError: me/linkedin.pdf: the notebook must run from 1_foundations; check the file name and that you kept the me folder.
  • Odd characters when reading the summary on Windows: pass encoding="utf-8" to open.
  • The bot invents facts about you: your resources are thin. Add more to summary.txt, and keep "If you don't know the answer, say so".
  • Second message fails with a non-OpenAI provider: clean the history to role and content only (the repo's note).
  • AttributeError: 'NoneType' object has no attribute 'is_acceptable': the evaluator returned nothing parseable; check the Gemini key, or switch the evaluator to an OpenAI model.
  • "Patent" does not trigger the trap: the check is case-sensitive; type "patent".
  • Gradio port already in use: an earlier launch() is still running; restart the kernel or let Gradio pick the next port.
Recap
  • Frameworks range from none (full control) to LangGraph and AutoGen (more power, more ecosystem). This week uses none.
  • Resources put relevant data in the prompt; tools let the LLM ask your code to act. "It's JSON and if statements."
  • A Gradio chat needs one function, chat(message, history), which rebuilds the message list and returns the reply.
  • Structured outputs (parse with a Pydantic or zod schema) turn the model's JSON into a typed object.
  • An evaluator with the same context can reject a reply; a rerun with the reason attached fixes it. That is evaluator–optimizer without a framework.
