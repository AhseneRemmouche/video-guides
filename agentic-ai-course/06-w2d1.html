Concepts from the lectures

Why asynchronous code, and the short version (lecture 1, 01:48–05:02)

The presenter's argument: when you call a paid model, almost all the time is spent waiting for the network. While one call waits, another could be running. Operating-system threads can do that but carry "a lot of baggage"; multiprocessing spawns whole Python processes. asyncio, added in Python 3.5, is a lightweight alternative that needs neither, so "you can have thousands or tens of thousands of these things all running". Every agent framework in the course uses it.

The short version you can live with (04:07): put async before def for any function that may run concurrently, and put await before every call to such a function. result = do_some_processing() becomes result = await do_some_processing().

The real story: coroutines and the event loop (lecture 1, 05:29–08:53)

Strictly, async def does not define a function but a coroutine: "something special that Python can pause and resume". Calling it runs nothing; it returns a coroutine object. await schedules that object on the event loop, a loop inside asyncio that executes one coroutine at a time. When the running coroutine blocks on I/O (say, waiting for OpenAI), the loop pauses it and runs another one that is ready. The presenter calls it "a manual approach to implementing multithreading, but only really working when something is blocked waiting on I/O".

With only await there is no concurrency: each call blocks until it finishes. The construct that gives concurrency is asyncio.gather (10:40): results = await asyncio.gather(a(), b(), c()) schedules all three; whenever one waits on I/O another runs; the result is a list with one entry per coroutine, in the same order. You will use it on Day 2 to write three emails at once.

New to async in Python? The three rules and the one gotcha

Rule 1: a function that awaits anything must itself be async def. Rule 2: call it with await. Rule 3: at the very top you need something that starts the event loop. In a Jupyter notebook the loop is already running, so you can write await directly in a cell (that is why the course can type result = await Runner.run(...) in a notebook). In a plain .py file you would write asyncio.run(main()) once at the bottom.

The gotcha: forgetting await does not raise an error. You get a coroutine object that never runs, and a warning later. The lab shows this on purpose (lecture 3 at 04:38).

New to async in TypeScript? Promises, await and the Node event loop

JavaScript was asynchronous long before Python: a Node program has one event loop by default, and every network call returns a promise, an object that will hold a value later. await pauses the current function until the promise settles, exactly like Python's await on a coroutine. An async function always returns a promise. Running several promises together is Promise.all([...]), the twin of asyncio.gather.

In this project the files are ES modules ("type": "module" in package.json), so you may write await at the top level of a file, outside any function, just as the notebook cells do.

What the SDK is, and its three words (lecture 2)

The presenter's framing (00:00–01:46): the SDK, formerly known as Swarm, is "super lightweight, very flexible" and not opinionated, meaning it does not force a particular way of structuring your program. At the same time it removes the boilerplate you suffered in Week 1: "all of that gunk that we had to do with the JSON around tools" is generated for you. He also admits it is his favourite framework, and promises it will return in Week 6 for MCP.

Three terms (03:07): an agent is a package around calls to an LLM with a particular role; a handoff is the SDK's name for an interaction between agents; a guardrail is a check that keeps an agent from "going off the rails". Three steps (03:57): create an instance of Agent; use with trace to keep a log you can inspect on OpenAI's platform; call Runner.run, which is a coroutine, so await Runner.run(...).

Step by step: the first agent (lecture 3)

  1. Open the lab (00:00)

  2. Import the three names (00:50)

    The package is installed as openai-agents but imported as agents, "a bit strange that they use such a generic name". From it you import Agent, Runner and trace.

    The package is @openai/agents; the names are Agent, run (a function, not a class) and withTrace. The file also imports MODEL from setup.ts, which loads .env.

  3. Load the environment variables (01:36)

    load_dotenv(override=True) reads .env. The cell prints True when the file was found.

    import "dotenv/config" at the top of setup.ts does the same.

  4. Create the agent (01:52)

    An instance of Agent with a name ("Jokester"), instructions ("You are a joke teller", which is the system prompt) and a model. Passing a plain model name string means "an OpenAI model"; the SDK also works with other providers, which Day 3 shows. Printing the agent shows its other attributes: handoffs=[], tools=[], model_settings, input and output guardrails.

  5. Run it the wrong way first (03:50)

    result = Runner.run(agent, "Tell a joke about Autonomous AI Agents") followed by print(result) prints a coroutine object, because Runner.run is a coroutine. The presenter restarts the kernel afterwards "so that we don't have one hanging out there not scheduled".

    In TypeScript run(agent, "...") without await gives a pending Promise; console.log would print Promise { <pending> }. Same lesson: await it.

  6. Run it the right way, inside a trace (05:27–07:17)

    await Runner.run(...) waits for the answer and result.final_output is the joke. Wrapping the call in with trace("Telling a joke"): tells OpenAI to record the interaction under that heading.

  7. Look at the trace (07:41)

    Go to platform.openai.com/traces: "Telling a joke" is the top row. Inside it, one call: the system instructions ("You are a joke teller"), the user prompt and the assistant's reply. Not profound for one call, "but there will come cases in the future when this is going to be invaluable".

The code

The notebook has four code cells. They are shown as the repo has them (commit 0fb280d5); the video typed the same lines.

The TypeScript version is one file, src/lab1.ts, plus the shared src/setup.ts. The Python cells are listed first so you can compare line by line.

# The imports

from dotenv import load_dotenv
from agents import Agent, Runner, trace
// Week 2 Day 1 — first look at the OpenAI Agents SDK (TypeScript version of 2_openai/1_lab1.ipynb)
// Python: Agent(name, instructions, model) · Runner.run(agent, prompt) · with trace("...")
// TypeScript: new Agent({ name, instructions, model }) · run(agent, prompt) · withTrace("...", async () => ...)
import { Agent, run, withTrace } from "@openai/agents";
import { MODEL } from "./setup.js";

// Make an agent with name, instructions, model
const agent = new Agent({ name: "Jokester", instructions: "You are a joke teller", model: MODEL });

// Run the joke with run(agent, prompt) then print finalOutput
await withTrace("Telling a joke", async () => {
  const result = await run(agent, "Tell a joke about Autonomous AI Agents");
  console.log(result.finalOutput);
});

The shared file:

// Shared setup for every lab: environment variables, the model to use, and an optional local-model mode.
//
// Default (like the course): OPENAI_API_KEY in .env, the Responses API and tracing on platform.openai.com.
// Local mode (no OpenAI key): set OPENAI_BASE_URL=http://localhost:11434/v1 OPENAI_API_KEY=ollama MODEL=llama3.2
// The SDK then talks Chat Completions to Ollama's OpenAI-compatible endpoint and tracing is switched off,
// because traces can only be uploaded to OpenAI with a real key.
import "dotenv/config";
import OpenAI from "openai";
import { setDefaultOpenAIClient, setOpenAIAPI, setTracingDisabled } from "@openai/agents";

export const MODEL = process.env.MODEL ?? "gpt-4o-mini";
export const LOCAL = Boolean(process.env.OPENAI_BASE_URL);

if (LOCAL) {
  setDefaultOpenAIClient(new OpenAI({ baseURL: process.env.OPENAI_BASE_URL, apiKey: process.env.OPENAI_API_KEY ?? "ollama" }));
  setOpenAIAPI("chat_completions");
  setTracingDisabled(true);
}

/** Send an email through SendGrid's REST API (the Python labs use the sendgrid package; here plain fetch is enough).
 *  Without SENDGRID_API_KEY the email is printed instead of sent, so every lab still runs end to end. */
export async function sendEmail(subject: string, body: string, type: "text/plain" | "text/html" = "text/plain") {
  const key = process.env.SENDGRID_API_KEY;
  const from = process.env.EMAIL_FROM ?? "you@example.com"; // must be a verified sender in SendGrid
  const to = process.env.EMAIL_TO ?? from;
  if (!key) {
    console.log(`\n[email not sent: no SENDGRID_API_KEY] subject=${JSON.stringify(subject)} type=${type}\n${body.slice(0, 400)}\n`);
    return { status: "printed" };
  }
  const res = await fetch("https://api.sendgrid.com/v3/mail/send", {
    method: "POST",
    headers: { Authorization: `Bearer ${key}`, "Content-Type": "application/json" },
    body: JSON.stringify({
      personalizations: [{ to: [{ email: to }] }],
      from: { email: from },
      subject,
      content: [{ type, value: body }],
    }),
  });
  console.log("SendGrid status", res.status); // 202 means accepted
  return { status: res.status === 202 ? "success" : `error ${res.status}` };
}

Running without an OpenAI key (how this guide verified the code)

Every Week 2 notebook was executed on this guide's laptop with Ollama serving llama3.2 at http://localhost:11434/v1, an OpenAI-compatible endpoint. Two settings make the SDK work there: the Responses API is replaced by Chat Completions, and tracing is switched off. In Python that is:

from agents import set_default_openai_api, set_tracing_disabled

set_default_openai_api("chat_completions")
set_tracing_disabled(True)
# with OPENAI_BASE_URL=http://localhost:11434/v1 and OPENAI_API_KEY=ollama in the environment,
# and model="llama3.2" instead of "gpt-4o-mini"

In TypeScript the same lines sit in setup.ts (lines 14–18) and switch on automatically when OPENAI_BASE_URL is set:

OPENAI_BASE_URL=http://localhost:11434/v1 OPENAI_API_KEY=ollama MODEL=llama3.2 pnpm lab1

The trade-off: a small local model follows instructions and tool protocols less reliably than GPT-4o-mini, and the Traces page stays empty. Where this guide quotes outputs, it says which model produced them.

Vibe coding: the five tips (lecture 4)

The term comes from Andrej Karpathy's viral post about letting an LLM generate code and "going with it". The presenter encourages it, with a survival guide:

TipWhat to doWhy
Good vibes (01:21)Spend time on a reusable prompt: ask for short, concise, clean code; state today's date and ask for APIs current as of that date.LLMs are verbose, wrap everything in exception handlers, and reach for older APIs that dominate their training data.
Vibe but verify (01:50)Ask the same question to two or three models (the presenter keeps ChatGPT and Claude open side by side).One answer is often long-winded or misses the point; comparing shows which.
Step up the vibe (02:36)Never ask for 200 lines at once. Ask for ten-line, independently testable pieces; if you cannot split the problem, ask the LLM to propose 4–5 small steps first (without code).Students send "200 lines that don't work"; small pieces can each be run and checked.
Vibe and validate (04:34)Take the generated answer to another model and ask it to confirm it is correct, concise and bug-free.A manual version of the evaluator–optimizer pattern.
Vibe with variety (05:32)Ask for three different solutions with their rationale.Forces the model to consider alternatives and explains the choice to you.

And the rule behind all five (06:18): afterwards, ask the LLM to explain the code until "you understand every single thing that's going on". Otherwise vibe coding "is going to become painful and frustrating when something goes wrong".

Common mistakes

  • Forgot await: you see <coroutine object …> (Python) or Promise { <pending> } (TypeScript) instead of a joke. Add await; in Python, restart the kernel to clear the unscheduled coroutine.
  • ImportError: No module named agents: the notebook is not using the project's .venv kernel, or uv sync did not run. Select the kernel again. Note the package is installed as openai-agents but imported as agents.
  • load_dotenv returned False: the file is not named exactly .env, is not in the project root, or was not saved.
  • The agent answers but the Traces page is empty: traces upload asynchronously a few seconds later; refresh. With a non-OpenAI endpoint and tracing disabled, nothing is uploaded at all.
  • Another package named agents: if you ever created your own agents folder or module in the project, Python imports that instead. Rename yours.
Recap
  • async def defines a coroutine; calling it returns an object; await runs it on the event loop; asyncio.gather runs several at once. TypeScript: promises, await, Promise.all.
  • The OpenAI Agents SDK has three concepts (agent, handoff, guardrail) and three steps (create an Agent, open a trace, await the run).
  • An Agent is a description: name, instructions (the system prompt) and model. Runner.run / run executes it; final_output / finalOutput is the answer.
  • Every run inside with trace("name") appears on platform.openai.com/traces with its prompts and timings.
  • Vibe coding works when you generate small testable pieces, verify across models, and make sure you understand the result.
