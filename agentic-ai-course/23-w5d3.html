What this day covers

One layer down: AutoGen Core, "the fundamental infrastructure behind it all". You define your own message type, write agents whose handlers receive it, register agent types with a runtime, and address agents by ID. It ends with rock-paper-scissors between GPT-4o-mini and a local Llama 3.2, judged by a third agent. The presenter is upfront: "I'm only going to do this at a high level… the examples will be somewhat superficial… I know you're anxious to get to MCP."

TypeScript: pnpm lab3. AutoGen Core has no JavaScript version, so src/core/runtime.ts is a small teaching runtime (137 lines) with the same names and behaviour as the parts this lab uses. Reading it shows exactly what an agent runtime does.

What Core is for (lectures 8–9)

The slide: "Decouples an Agent's logic from how messages are delivered. The framework handles creation & communication. The Agents are responsible for their logic - that is not the remit of Autogen Core." It is "agnostic. It doesn't care about… the actual abstraction you have around agents, you could be just calling LLMs directly".

Compared with LangGraph, both are about interactions and neither cares how an agent works inside. But "LangGraph is all about this idea of robustness and repeatability… being able to replay back in time", while Core's driving idea is agents that "could be in very distributed places… very diverse". (An aside: Microsoft's Semantic Kernel is something else, "more akin to something like LangChain".)

The runtime is "the kind of world in which agents interact". A standalone runtime "runs on your box in a simple way"; a distributed one "could allow remote agents to interact with each other". Standalone today, distributed tomorrow.

A message and a routed agent (lecture 9)

Start with the message, just as LangGraph started with the State: "Core's fundamental idea is all about messaging." A @dataclass "is something that holds data".

A Core agent is not an LLM. It is "a thing that can be messaged, it can be created, it can be managed, it can be referred to… But what you do with this is your responsibility." Every agent has an AgentId of two parts, a type and a key. A RoutedAgent's methods marked @message_handler receive messages, routed by the type of their message argument. The first example has no AI at all: "Maybe I should call it a disagreeable agent… but that doesn't matter to AutoGen Core."

class SimpleAgent(RoutedAgent):
    def __init__(self) -> None:
        super().__init__("Simple")

    @message_handler
    async def on_my_message(self, message: Message, ctx: MessageContext) -> Message:
        return Message(content=f"This is {self.id.type}-{self.id.key}. You said '{message.content}' and I disagree.")
        
// ---------- A simple agent with no LLM: "the disagreeable agent" ----------
class SimpleAgent extends RoutedAgent {
  constructor() {
    super("Simple");
  }

  @messageHandler(Message)
  async onMyMessage(message: Message, ctx: MessageContext): Promise<Message> {
    return new Message(`This is ${this.id.type}-${this.id.key}. You said '${message.content}' and I disagree.`);
  }
}

The teaching runtime

This is the whole standalone runtime the TypeScript labs use. The table maps it to AutoGen's names.

// A small teaching runtime that mirrors the ideas of AutoGen Core. AutoGen has no JavaScript version, so this file
// is NOT a port of the library: it is about 100 lines that behave like the parts Lab 3 uses.
//
//   AutoGen Core (Python)                     this file (TypeScript)
//   @dataclass class Message                  class Message { constructor(public content: string) {} }  (in each lab)
//   class X(RoutedAgent)                      class X extends RoutedAgent
//   @message_handler + type hint "Message"    @messageHandler(Message)   (TypeScript types vanish at run time,
//                                                                          so the message class is passed explicitly)
//   MessageContext (sender, cancellation_token) MessageContext (sender, signal: AbortSignal)
//   AgentId(type, key)                        new AgentId(type, key)
//   SingleThreadedAgentRuntime                new SingleThreadedAgentRuntime()
//   await X.register(runtime, "x", lambda: X()) await X.register(runtime, "x", () => new X())
//   await runtime.send_message(msg, agent_id) await runtime.sendMessage(msg, agentId)
//   self.send_message(msg, agent_id)          this.sendMessage(msg, agentId)
//   runtime.start() / stop() / close()        runtime.start() / stop() / close()
//
// The fundamental principle is the same: the runtime handles creation and delivery; the agent only has logic.

export type MessageClass<M = any> = new (...args: any[]) => M;
type Handler = (message: any, ctx: MessageContext) => Promise<unknown>;

/** Every message class used by a handler, by name. The distributed runtime needs it to rebuild messages from JSON. */
export const messageTypes = new Map<string, MessageClass>();

/** The address of one agent: its type (the registered kind) plus a key (which instance). */
export class AgentId {
  constructor(readonly type: string, readonly key = "default") {}
  toString() {
    return `${this.type}/${this.key}`;
  }
}

/** Extra information delivered with each message. signal plays the part of AutoGen's CancellationToken. */
export interface MessageContext {
  sender: AgentId | null;
  signal: AbortSignal;
}

/** What an agent can ask of the runtime it lives in. Implemented here and by the worker in distributed.ts. */
export interface AgentRuntime {
  register(type: string, factory: () => RoutedAgent): Promise<string>;
  sendMessage<R = any>(message: object, recipient: AgentId, sender?: AgentId | null): Promise<R>;
}

/** Decorator: "this method receives messages of this class" (Python: @message_handler, routed by the type hint). */
export function messageHandler(type: MessageClass) {
  messageTypes.set(type.name, type);
  return (method: Handler, context: ClassMethodDecoratorContext) => {
    context.addInitializer(function (this: unknown) {
      (this as RoutedAgent).handlers.set(type, method.bind(this));
    });
  };
}

/** Base class for agents: routes each incoming message to the handler registered for its class. */
export abstract class RoutedAgent {
  readonly handlers = new Map<MessageClass, Handler>();
  id!: AgentId; // filled in by the runtime when it creates the instance
  runtime!: AgentRuntime;

  constructor(readonly description: string) {}

  /** Python: await SimpleAgent.register(runtime, "simple_agent", lambda: SimpleAgent()). Declares a type; creates nothing yet. */
  static async register<T extends RoutedAgent>(runtime: AgentRuntime, type: string, factory: () => T) {
    await runtime.register(type, factory);
    return { type }; // Python prints AgentType(type='simple_agent')
  }

  async onMessage(message: object, ctx: MessageContext): Promise<unknown> {
    const handler = this.handlers.get(message.constructor as MessageClass);
    if (!handler) throw new Error(`${this.id} has no handler for ${message.constructor.name}`);
    return handler(message, ctx);
  }

  /** Message another agent through the runtime, by address, never by holding a reference to it. */
  sendMessage<R = any>(message: object, recipient: AgentId): Promise<R> {
    return this.runtime.sendMessage<R>(message, recipient, this.id);
  }
}

/** The bookkeeping every runtime shares: factories by type, instances created lazily on the first message. */
export abstract class BaseAgentRuntime implements AgentRuntime {
  protected factories = new Map<string, () => RoutedAgent>();
  protected instances = new Map<string, RoutedAgent>();
  protected abort = new AbortController();

  async register(type: string, factory: () => RoutedAgent) {
    if (this.factories.has(type)) throw new Error(`Agent type ${type} is already registered`);
    this.factories.set(type, factory);
    return type;
  }

  abstract sendMessage<R = any>(message: object, recipient: AgentId, sender?: AgentId | null): Promise<R>;

  /** Find (or create, with the factory) the recipient and call its handler. */
  protected async deliver(message: object, recipient: AgentId, sender: AgentId | null): Promise<unknown> {
    let agent = this.instances.get(recipient.toString());
    if (!agent) {
      const factory = this.factories.get(recipient.type);
      if (!factory) throw new Error(`No agent type ${recipient.type} registered`);
      agent = factory();
      agent.id = recipient;
      agent.runtime = this;
      this.instances.set(recipient.toString(), agent);
    }
    return agent.onMessage(message, { sender, signal: this.abort.signal });
  }
}

/** The standalone runtime: everything in this one process. Messages wait in a queue until start() is called. */
export class SingleThreadedAgentRuntime extends BaseAgentRuntime {
  private running = false;
  private queue: (() => void)[] = [];

  sendMessage<R = any>(message: object, recipient: AgentId, sender: AgentId | null = null): Promise<R> {
    return new Promise<R>((resolve, reject) => {
      const job = () => this.deliver(message, recipient, sender).then((r) => resolve(r as R), reject);
      if (this.running) job();
      else this.queue.push(job);
    });
  }

  start() {
    this.running = true;
    for (const job of this.queue.splice(0)) job();
  }

  async stop() {
    this.running = false; // new messages queue up again; ones already being handled finish
  }

  async close() {
    this.abort.abort(); // tell any handler still running that we are done
    this.instances.clear();
    this.factories.clear();
  }
}

An agent that delegates to an LLM (lecture 10, 03:05–09:04)

MyLLMAgent could call OpenAI directly, "but we can also use AutoGen AgentChat and we might as well since it's AutoGen week". It keeps an AssistantAgent in self._delegate. Watch the two message classes, "a common confusion": the Core Message comes in, an AgentChat TextMessage goes to the delegate.


class MyLLMAgent(RoutedAgent):
    def __init__(self) -> None:
        super().__init__("LLMAgent")
        model_client = OpenAIChatCompletionClient(model="gpt-4o-mini")
        self._delegate = AssistantAgent("LLMAgent", model_client=model_client)

    @message_handler
    async def handle_my_message_type(self, message: Message, ctx: MessageContext) -> Message:
        print(f"{self.id.type} received message: {message.content}")
        text_message = TextMessage(content=message.content, source="user")
        response = await self._delegate.on_messages([text_message], ctx.cancellation_token)
        reply = response.chat_message.content
        print(f"{self.id.type} responded: {reply}")
        return Message(content=reply)
    
// ---------- An agent that delegates to an LLM agent ----------
class MyLLMAgent extends RoutedAgent {
  private delegate: AssistantAgent<string>;

  constructor() {
    super("LLMAgent");
    // Python: self._delegate = AssistantAgent("LLMAgent", model_client=OpenAIChatCompletionClient(model="gpt-4o-mini"))
    this.delegate = new AssistantAgent(new Agent({ name: "LLMAgent", model: MODEL, instructions: "You are a helpful AI assistant." }));
  }

  @messageHandler(Message)
  async handleMyMessageType(message: Message, ctx: MessageContext): Promise<Message> {
    console.log(`${this.id.type} received message: ${message.content}`);
    const reply = await this.delegate.reply(message.content, ctx.signal); // core Message -> text -> LLM -> text
    console.log(`${this.id.type} responded: ${reply}`);
    return new Message(reply);
  }
}

The judge asks each player for one word through the runtime, then asks its own LLM who won. "The rock paper scissors agent discovered these two agents by name… through the runtime."

JUDGE = "You are judging a game of rock, paper, scissors. The players have made these choices:\n"

class RockPaperScissorsAgent(RoutedAgent):
    def __init__(self, name: str) -> None:
        super().__init__(name)
        model_client = OpenAIChatCompletionClient(model="gpt-4o-mini", temperature=1.0)
        self._delegate = AssistantAgent(name, model_client=model_client)

    @message_handler
    async def handle_my_message_type(self, message: Message, ctx: MessageContext) -> Message:
        instruction = "You are playing rock, paper, scissors. Respond only with the one word, one of the following: rock, paper, or scissors."
        message = Message(content=instruction)
        inner_1 = AgentId("player1", "default")
        inner_2 = AgentId("player2", "default")
        response1 = await self.send_message(message, inner_1)
        response2 = await self.send_message(message, inner_2)
        result = f"Player 1: {response1.content}\nPlayer 2: {response2.content}\n"
        judgement = f"{JUDGE}{result}Who wins?"
        message = TextMessage(content=judgement, source="user")
        response = await self._delegate.on_messages([message], ctx.cancellation_token)
        return Message(content=result + response.chat_message.content)
const JUDGE = "You are judging a game of rock, paper, scissors. The players have made these choices:\n";

class RockPaperScissorsAgent extends RoutedAgent {
  private delegate: AssistantAgent<string>;

  constructor(name: string) {
    super(name);
    this.delegate = new AssistantAgent(new Agent({ name, model: MODEL, modelSettings: { temperature: 1.0 } }));
  }

  @messageHandler(Message)
  async handleMyMessageType(message: Message, ctx: MessageContext): Promise<Message> {
    const instruction = "You are playing rock, paper, scissors. Respond only with the one word, one of the following: rock, paper, or scissors.";
    message = new Message(instruction);
    const inner1 = new AgentId("player1", "default");
    const inner2 = new AgentId("player2", "default");
    const response1 = await this.sendMessage<Message>(message, inner1); // through the runtime, found by name
    const response2 = await this.sendMessage<Message>(message, inner2);
    const result = `Player 1: ${response1.content}\nPlayer 2: ${response2.content}\n`;
    const judgement = `${JUDGE}${result}Who wins?`;
    const verdict = await this.delegate.reply(judgement, ctx.signal);
    return new Message(result + verdict);
  }
}

What you should see. "Player 1: rock / Player 2: Scissors / Player 1 wins because rock beats scissors. TERMINATE" in 3.2 seconds. The trailing TERMINATE is never explained in the video: an AssistantAgent created without a system message gets AutoGen's default one, which tells it to end with that word. Common mistakes

  • Mixing the two message classes: Core's Message dataclass is not AgentChat's TextMessage; convert between them in the handler.
  • Expecting register to create an agent: it declares a type; the instance appears on the first message.
  • Forgetting runtime.start(): messages are not processed until the runtime runs.
  • Starting a new runtime without stopping the old one: call stop() and close() first.
  • Ollama not running: player 2 fails; start Ollama and ollama pull llama3.2.
  • "TERMINATE" in replies: AutoGen's default system message; set your own.
Recap
  • Core separates agent logic from message delivery; the runtime creates agents and routes messages.
  • Define a message type, subclass RoutedAgent, mark handlers with @message_handler.
  • register(runtime, type, factory) declares a type; AgentId(type, key) addresses an instance.
  • Agents message each other through the runtime; inside, they can call any LLM or none.
  • In TypeScript, a short teaching runtime shows that this machinery is a lookup table, a factory and a queue.
