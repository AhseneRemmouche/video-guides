Glossary

Every technical term in this guide, explained for beginners.

Every technical term used in this guide, explained in plain language. Pages link here the first time a term appears. Terms are grouped by topic; use your browser's find (Ctrl+F / Cmd+F) to jump to one.

Tools, files and the command line

Terminal (command line)
A text window where you type commands instead of clicking. In Cursor or VS Code you open one with Ctrl+` (the backtick key) or View ▸ Terminal. The course runs everything from the project folder agents.
uv
A fast Python package and project manager. uv sync installs exactly the versions listed in uv.lock into a .venv folder; uv run script.py runs a script inside that environment, so you never have to "activate" anything. The course uses uv instead of pip.
Virtual environment (.venv)
A private copy of Python plus the packages one project needs, kept in a folder (here .venv) so different projects cannot break each other. Jupyter notebooks must be told to use it ("Select Kernel").
Jupyter notebook (.ipynb)
A file made of cells. Markdown cells hold text; code cells hold Python you run one at a time with Shift+Enter. Variables stay alive between cells, which is why order matters and why "Restart" clears everything.
Kernel
The Python process that executes a notebook's cells. Picking the .venv (Python 3.12) kernel makes the notebook use the project's packages.
.env file
A plain text file named exactly .env in the project root with lines like OPENAI_API_KEY=sk-proj-.... It keeps secrets out of your code and out of git.
Environment variable
A named value the operating system passes to programs, such as OPENAI_API_KEY. load_dotenv(override=True) reads the .env file and sets these variables; Python reads them with os.getenv("NAME"), Node with process.env.NAME.
API key
A secret string that identifies your account to a web service and lets it bill you. Never paste one into code or share it; keep it in .env.
pnpm
A package manager for JavaScript and TypeScript projects, like uv for Python. pnpm install installs what package.json lists; pnpm lab1 runs the script named lab1 in package.json.
TypeScript
JavaScript with types. The compiler (tsc) checks that you use values correctly before the code runs. The TypeScript projects in this guide run .ts files directly with tsx.
Vite
A development server and build tool for web apps. vite serves the React app with instant reload; vite build produces the optimised files in dist/.
React
A JavaScript library for building user interfaces from components. A component is a function that returns HTML-like markup (JSX) and re-renders when its state changes.
Hono
A small web framework for Node (and other runtimes) used here for the API that the React app talks to. It is the TypeScript counterpart of the Gradio server the course uses.
Server-Sent Events (SSE)
A simple way for a server to push a stream of text events to the browser over one HTTP response. The deep-research app uses it to show progress lines while the agents work.
Hugging Face Spaces
A free hosting service for small web apps such as Gradio apps. gradio deploy uploads your app and its secrets there so other people can use it.

Language models and prompts

LLM (large language model)
A neural network trained to predict the next token of text. Given a conversation it produces the most likely continuation, which is why careful prompts and structured outputs matter so much.
System prompt
The instructions sent to the model before the user's message: who it is, what it does, what tone to use, what constraints to obey. In the Agents SDK it is called instructions.
Instructions
The Agents SDK's name for an agent's system prompt. Each agent is "an LLM with one particular system prompt designed around one task".
Chat Completions API
OpenAI's classic endpoint: you send a list of messages (role + content) and get one assistant message back. Most other providers copy its shape, which is what makes "OpenAI-compatible endpoints" possible.
Responses API
OpenAI's newer endpoint that the Agents SDK uses by default (traces show POST /v1/responses). It supports hosted tools such as web search. Other providers usually offer only Chat Completions, so the SDK can be switched with OpenAIChatCompletionsModel.
OpenAI-compatible endpoint
A web address that speaks the Chat Completions protocol even though another company runs the model: Gemini, DeepSeek, Groq, OpenRouter, and Ollama on your own machine. You point the OpenAI client at it with base_url (Python) or baseURL (TypeScript).
Base URL
The first part of every API address the client calls, e.g. https://api.deepseek.com/v1. Change it and the same client code talks to a different provider.
Ollama
A program that runs open models (llama3.2, gemma, qwen…) locally and exposes an OpenAI-compatible endpoint at http://localhost:11434/v1. The runs in this guide used it because no OpenAI key was available.
Structured output
Asking the model to answer in a fixed shape (fields with types) instead of free text. Behind the scenes the shape becomes a JSON schema in the request; the SDK parses the JSON into a Pydantic object (Python) or a zod-validated object (TypeScript).
output_type / outputType
The agent option that turns structured output on: give it a Pydantic class or a zod schema and final_output becomes an object of that type.
JSON schema
A JSON document that describes the allowed shape of other JSON: field names, types, which are required. Tools and structured outputs are both described to the model with JSON schemas, generated for you by the SDK.
Pydantic
A Python library for data classes with validation. A class that extends BaseModel declares fields with type hints; Pydantic checks incoming data and can produce the JSON schema the model needs.
zod
A TypeScript library for describing and validating data shapes at run time (z.object({ query: z.string() })). The Agents JS SDK uses zod schemas for tool parameters and structured outputs, the way the Python SDK uses Pydantic.
Type hint
A Python annotation such as body: str or -> Dict[str, str]. Python ignores it at run time, but the Agents SDK reads it to build the tool's JSON schema.
Docstring
The string right under a def line, in triple quotes. The SDK copies it into the tool description the model sees, so write it for the model, not for yourself.
Decorator
A line starting with @ placed above a function. It passes the function through another function that returns a replacement; @function_tool replaces your function with a FunctionTool object that still calls your code.
Knowledge cut-off
The date up to which a model saw training data. It explains why a generated email said "© 2023" and why the search agent did not know newer frameworks.

Agents and the OpenAI Agents SDK

n8n
A low-code workflow tool with AI nodes, used in the course's first demo to build an agent that controls smart lights without writing code.
Agentic system
Anthropic's umbrella term for both workflows (LLMs and tools orchestrated through code paths you wrote) and agents (LLMs that direct their own process and tool use).
Reasoning model
A model trained to work through intermediate steps before answering (OpenAI's o-series and GPT-5, DeepSeek R1). Slower and pricier per answer, often better on hard problems.
Parameters
The learned numbers inside a model; "3B" means about three billion. More parameters usually means more capable but far more memory: around 3B runs on a laptop, 70B needs a server, 671B a data centre.
LLM as judge
Using one model to score or rank other models' outputs, as in the Week 1 Day 3 contest. Hide model names from the judge and ask for structured output you can parse.
Agent
In the Agents SDK, an object with a name, instructions, a model and optionally tools, handoffs, guardrails and an output type. Running it starts a loop: call the model, run any tools it asked for, repeat until the model answers without tool calls.
OpenAI Agents SDK
OpenAI's lightweight framework for building agents (Python package openai-agents, imported as agents; JavaScript package @openai/agents). It grew out of the experimental "Swarm" project. Three concepts: agents, handoffs, guardrails.
Runner
The class that executes an agent: Runner.run(agent, input) returns a result whose final_output is the agent's answer. In TypeScript the function is simply run(agent, input).
Trace
A recording of everything that happened during one workflow: every model call, tool call and handoff with timings and prompts. with trace("name") groups the calls under one heading on platform.openai.com/traces.
Context manager
A Python object used with with. It runs setup code when the block starts and cleanup when it ends. with trace("…"): starts a trace and closes it after the block.
Tool
Something an agent can call: a function you wrote, another agent wrapped as a tool, or a hosted tool such as web search. The model sees each tool's name, description and parameter schema and decides when to call it.
Function tool
A tool made from an ordinary function. Python: @function_tool above the function. TypeScript: tool({ name, description, parameters, execute }).
Hosted tool
A tool that runs on OpenAI's servers rather than on your machine: web search, file search over vector stores, computer use. Only available through OpenAI's own API.
WebSearchTool
The hosted tool that lets an agent search the web. search_context_size can be "low", "medium" or "high" and changes both quality and price.
Agent as a tool
Wrapping a whole agent so another agent can call it like a function: agent.as_tool(tool_name=…, tool_description=…). The caller gets the wrapped agent's answer back and continues.
Handoff
Passing control from one agent to another. The receiving agent finishes the job; control does not come back. Set with handoffs=[…] and described with handoff_description.
handoff_description
A sentence that tells other agents what this agent can take over ("Convert an email to HTML and send it"). It plays the role a tool description plays for tools.
Guardrail
A check that runs on the input of the first agent or the output of the last agent. It can be a plain function or an agent of its own. If the check fails it "trips the tripwire" and the run stops with an exception.
Input guardrail
A guardrail that inspects the user's input before the first agent runs. Python: @input_guardrail; TypeScript: an object with name and execute in inputGuardrails.
Tripwire
The flag a guardrail sets (tripwire_triggered=True) to say "stop, this is not allowed". The SDK then raises InputGuardrailTripwireTriggered.
ModelSettings
Per-agent options for the model call: temperature, maximum tokens, and tool_choice. tool_choice="required" forces the model to call a tool.
tool_choice
Whether the model may, must, or must not call a tool on its next turn: "auto" (default), "required", "none", or the name of one tool.
SDR (sales development representative)
A salesperson who finds prospects and sends the first ("cold") emails. The Week 2 project automates that job with agents.
SendGrid
A Twilio service for sending emails from code. Needs an API key and a verified sender address; a successful send returns HTTP status 202.
Workflow vs agent
Anthropic's distinction: in a workflow your code decides the order of LLM calls; in an agent the LLM decides what to do next (which tools to call, whether to loop). Giving the Sales Manager tools and letting it choose is the line that crosses from one to the other.
Agentic design pattern
Reusable shapes for LLM applications: prompt chaining, routing, parallelization, orchestrator–workers, evaluator–optimizer. The Week 2 labs use parallelization (three writers), an orchestrator (the manager) and a picker that acts as an evaluator.
Vibe coding
Letting an LLM generate code and iterating on it conversationally. The course's five tips: craft a reusable prompt that asks for concise current code; ask several models; generate small testable pieces; have another model validate; ask for several solutions and explanations.

CrewAI (Week 3)

CrewAI
An agent framework for Python in which you describe agents (role, goal, backstory) and tasks in YAML and run them as a crew. The course uses its open-source framework and its "Crews" flavour (not "Flows").
Task (CrewAI)
A unit of work with a description, an expected output and the agent that does it; optionally a context list, an output_file and a structured output (output_pydantic).
Crew
A team of agents and the tasks they carry out, run with a process: sequential (tasks in order) or hierarchical (a manager agent delegates).
Role, goal and backstory
The three texts CrewAI turns into an agent's system prompt: "You are {role}. {backstory} Your personal goal is: {goal}".
YAML
A human-friendly text format for configuration, based on indentation. In CrewAI's files, key: > starts a folded block: the indented lines below are joined into one paragraph.
LiteLLM
A library that calls many LLM providers through one interface. CrewAI uses it, so a model is named provider/model, for example openai/gpt-4o-mini or ollama/llama3.2.
Hierarchical process
A crew mode where a manager agent receives the tasks and delegates them to the other agents, instead of running them in a fixed order.
Context (CrewAI task)
The list of earlier tasks whose outputs are given to a task. Without the list, a task in a sequential crew receives all earlier outputs.
uv tool
A command-line program installed globally by uv (uv tool install crewai==0.130.0), so crewai works in any folder.
Serper
A paid-per-query Google Search API (serper.dev) with 2,500 free queries; CrewAI's SerperDevTool uses it with the SERPER_API_KEY. SERP means search engine results page.
Agent memory
Information an agent keeps between steps or runs. CrewAI offers short-term memory (recent context, in a vector store), long-term memory (results of past runs, in SQLite) and entity memory (facts about people, places and companies).
RAG (retrieval augmented generation)
Finding stored text that is similar in meaning to the current question and adding it to the prompt. CrewAI's short-term and entity memory work this way.
Embedding
A list of numbers (a vector) that represents the meaning of a piece of text, made by an embedding model such as OpenAI's text-embedding-3-small. Texts with similar meaning get nearby vectors.
Chroma
An open-source vector database that stores embeddings and finds the closest ones. CrewAI keeps it in memory/chroma.sqlite3.
Coder agent
An agent that writes code and runs it as a step towards solving a problem, then reads the output. In CrewAI: allow_code_execution=True with code_execution_mode="safe".
Docker
Software that runs programs in isolated containers. CrewAI's "safe" code execution runs the agent's Python inside a Docker container so it cannot touch your files.

LangGraph (Week 4)

LangChain
A library of abstractions for LLM apps (model wrappers, prompt templates, RAG, ready-made tools), from the company of the same name. The course uses its chat model class and tools inside LangGraph.
LangGraph
A framework for agent workflows drawn as graphs of nodes and edges, with checkpoints for memory and recovery. Python package langgraph; JavaScript package @langchain/langgraph.
LangSmith
LangChain's hosted monitoring service: it records every LLM call and tool call of a LangGraph run as a trace you can inspect. Switched on with environment variables.
Graph
The whole workflow: nodes connected by edges, with a START and an END.
State (LangGraph)
The object that holds everything the graph knows at a moment, such as the list of messages. Every node receives it and returns an update.
Node
A function in the graph that receives the state, does some work (an LLM call, a tool, a side effect) and returns the fields to update.
Edge
A connection that says which node runs next. A simple edge always leads to the same node.
Conditional edge
An edge with a function that reads the state and returns the name of the next node, for example "tools" if the model asked for a tool, otherwise END.
Reducer
A function attached to a state field that says how a node's update is combined with the current value. For messages, add_messages appends instead of replacing.
Graph builder
The StateGraph object you add nodes and edges to before compiling.
Compile
Turning a laid-out graph into a runnable one (graph_builder.compile()), optionally with a checkpointer.
Super-step
One full run of the graph for one user input: all the node calls from START to END. Nodes that run in parallel are part of the same super-step.
Checkpoint / checkpointer
A saved copy of the state after each step. A checkpointer (MemorySaver in memory, SqliteSaver in a file) stores them, which gives the graph memory between invocations.
Thread ID
The name of one conversation's checkpoints ({"configurable": {"thread_id": "1"}}). Same ID, same memory; new ID, fresh start.
Time travel
Going back to an earlier checkpoint of a thread to inspect it or run again from there.
ToolNode
A ready-made LangGraph node that runs whichever tools the last model message asked for and adds their results as tool messages.
Playwright
A library that drives a real web browser (Chromium) from code: open pages, click, read text. Used for testing, and here as an agent's browser.
Evaluator (worker–evaluator loop)
A second LLM that checks the worker's answer against success criteria, using structured output, and sends it back with feedback if it falls short.

AutoGen (Week 5)

AutoGen
Microsoft's open-source multi-agent framework. The course uses the 0.4+ line, installed as autogen-agentchat, autogen-core and autogen-ext. It has no JavaScript version.
AG2
A community fork of the older AutoGen 0.2 by original developers who left Microsoft. It owns the PyPI name autogen, so pip install autogen gives you AG2, not Microsoft's AutoGen.
AgentChat
AutoGen's high-level API: model clients, messages, AssistantAgent, tools and teams. The part comparable to CrewAI and the OpenAI Agents SDK.
AutoGen Core
AutoGen's lower layer: an agent runtime that creates agents and delivers messages between them, whatever each agent does inside.
Agent runtime
The program that hosts agents and routes messages to them by ID. Standalone runs everything in one process; distributed spreads agents over several processes or machines.
RoutedAgent and message handler
An AutoGen Core agent class whose methods marked @message_handler are called for messages of a given type.
AgentId
The address of an agent in a runtime: a type (the kind of agent) and a key (which instance).
Team (round robin)
A group of AgentChat agents that take turns on one conversation until a termination condition, such as a reply containing "APPROVE" or a maximum number of turns.
gRPC
A fast way for programs to call each other over the network. AutoGen's distributed runtime uses it between the host and the worker processes.

MCP and the trading floor (Week 6)

MCP (Model Context Protocol)
Anthropic's open standard for sharing tools, resources and prompts with any LLM app: "the USB-C of Agentic AI". A protocol, not a framework.
MCP host
The application that uses MCP servers, such as Claude Desktop or your Agents SDK program.
MCP client
A small piece inside the host that talks to one MCP server; one client per server.
MCP server
A separate program that offers tools (and optionally resources and prompts). Most run on your own machine, started with uvx (Python) or npx (Node).
stdio transport
The host starts the server as a child process and they exchange messages over standard input and output. The usual way for local servers.
MCP resource
Read-only information a server offers for the prompt, addressed by a URI such as accounts://accounts_server/Ed, as opposed to a tool the model calls.
FastMCP / McpServer
The quick way to write your own MCP server: FastMCP in Python's mcp package, McpServer in the TypeScript SDK; functions become tools with a decorator or a registration call.
Polygon (Massive)
A stock-market data API. The free plan gives end-of-day prices; paid plans add delayed or real-time prices.
Spread
The small extra cost of trading: in the course's accounts code a buy costs 0.2% above the price and a sell gets 0.2% below it.

Asynchronous Python and JavaScript

async / await
async def declares a coroutine; await runs one and waits for its result while letting other coroutines run in the meantime. JavaScript has the same two keywords for promises.
Coroutine
What async def defines. Calling it does not run it; it returns a coroutine object that the event loop can pause and resume. Printing one shows <coroutine object …>, the sign that you forgot await.
Event loop
The scheduler inside asyncio (and inside Node). It runs one coroutine until that coroutine waits for something (a network reply), then switches to another one. No threads are involved, which is why thousands of coroutines are cheap.
asyncio.gather
Runs several coroutines concurrently and returns a list of their results in the same order: results = await asyncio.gather(a(), b(), c()). JavaScript: await Promise.all([a(), b(), c()]).
Promise.all
JavaScript's way to wait for several promises at once; the TypeScript labs use it where the Python labs use asyncio.gather.
Generator
A function that uses yield to hand back values one at a time while keeping its place. An async generator (async def with yield, or async function* in TypeScript) does the same inside asynchronous code. Gradio and the React app read these values to show progress.
Async generator
See generator: the version you iterate with async for (Python) or for await (TypeScript).
Streaming
Receiving the model's answer piece by piece as it is produced, instead of waiting for the whole text. Runner.run_streamed and run(agent, input, { stream: true }) expose those pieces as events.

User interfaces

Gradio
A Python library that builds a web UI from a few lines: gr.ChatInterface(fn) for a chat, or gr.Blocks with text boxes, buttons and markdown wired to callback functions. launch() starts a local web server.
Callback
A function you hand to a framework so it can call it later, for example when a button is clicked. In Gradio, run_button.click(fn=run, inputs=…, outputs=…) registers run as the click callback.
Markdown
Lightweight text formatting with # headings, **bold** and lists. Models love to answer in it; Gradio's gr.Markdown and the marked library in the React app render it as HTML.
