Week 5 Day 5 · Agents that create agents

A Creator agent writes, imports and registers new agents at run time; twenty of them trade business ideas, with clear safety warnings.

Course lectures (Udemy) · code verified against the repo

What this day builds

The week's "out there" project: a Creator agent that writes new agents. It reads agent.py as a template, asks GPT-4o-mini for a brand-new agentN.py with its own personality, imports it while the program is running, registers it with the runtime, and asks it for a business idea. The new agents sometimes pass their ideas to each other for refinement. world.py launches 20 creations at once and saves each idea to ideaN.md.

TypeScript: pnpm world (3 agents by default; HOW_MANY_AGENTS=20 pnpm world for the full run). The Creator writes src/agentN.ts files and imports them with import(), on Week 5's teaching runtime.

Read this before running it. The slide's minuses are "Uncommercial (but a twist)", "Unreliable" and "Unsafe". "It's unreliable… by its very nature… may sometimes fail, and also it's unsafe. So we are going to be building something that's going to be creating and running Python code… generally without guardrails on, which means you have to run this at your own risk." The generated code runs on your machine with your permissions, in Python and in TypeScript alike. Read the generated files, keep the number of agents small, or watch instead of running.

Cost too: about "a couple of cents" for 20 agents on GPT-4o-mini, "if you do it for like three agents, it costs nothing. But… the agent creator could change the model".

The idea (lecture 15)

From the slide: "Explore the dynamic nature of autogen. Make a "Creator" agent that can write a python module. The python module is.. an Agent: An AutoGen AgentChat Agent in AutoGen Core. Then have the Creator agent actually register its creation with a distributed runtime." The goal can be anything: "you can spawn this army of agents that can think about something and interact with each other, and you can… plant the initial seed and then see what happens." The second lesson is async: "It would be quite a drag if this thing had to happen in a serial way."

The template and the messages (lecture 16, 00:00–05:52)

agent.py "is like our template… we will clone it and make various versions of it, or we won't. An agent will." Its two comments are instructions for the LLM. The handler was renamed live to handle_message: "Fewer tokens is always good." The Message class sits in its own module "because I want to put as little code in here as possible to avoid mistakes".

export const AGENTS_DIR = path.dirname(fileURLToPath(import.meta.url)); // src/, where agent.ts and agentN.ts live

/** Pick a random created agent by looking at the agentN.ts files on disk (the course calls this "super hacky":
 *  the file may not be registered yet, and the agent may pick itself). */
export function findRecipient(): AgentId {
  try {
    const agentFiles = readdirSync(AGENTS_DIR).filter((f) => /^agent\d+\.ts$/.test(f)); // Python: glob("agent*.py") minus "agent"
    const agentNames = agentFiles.map((f) => path.parse(f).name);
    if (agentNames.length === 0) throw new Error("no agents yet");
    const agentName = agentNames[Math.floor(Math.random() * agentNames.length)];
    console.log(`Selecting agent for refinement: ${agentName}`);
    return new AgentId(agentName, "default");
  } catch (e) {
    console.log(`Exception finding recipient: ${e}`);
    return new AgentId("agent1", "default");
  }
}

find_recipient is "super hacky": it picks a random agent*.py file in the folder. "There's some chance that we'll return the agent itself. The agent might talk to itself… But I thought, whatever, it doesn't matter." The file may also exist on disk before its agent is registered, which makes that message fail. And the folder is relative, so run the script from 5_autogen/.

class Creator(RoutedAgent):

    # Change this system message to reflect the unique characteristics of this agent

    system_message = """
    You are an Agent that is able to create new AI Agents.
    You receive a template in the form of Python code that creates an Agent using Autogen Core and Autogen Agentchat.
    You should use this template to create a new Agent with a unique system message that is different from the template,
    and reflects their unique characteristics, interests and goals.
    You can choose to keep their overall goal the same, or change it.
    You can choose to take this Agent in a completely different direction. The only requirement is that the class must be named Agent,
    and it must inherit from RoutedAgent and have an __init__ method that takes a name parameter.
    Also avoid environmental interests - try to mix up the business verticals so that every agent is different.
    Respond only with the python code, no other text, and no markdown code blocks.
    """


    def __init__(self, name) -> None:
        super().__init__(name)
        model_client = OpenAIChatCompletionClient(model="gpt-4o-mini", temperature=1.0)
        self._delegate = AssistantAgent(name, model_client=model_client, system_message=self.system_message)

    def get_user_prompt(self):
        prompt = "Please generate a new Agent based strictly on this template. Stick to the class structure. \
            Respond only with the python code, no other text, and no markdown code blocks.\n\n\
            Be creative about taking the agent in a new direction, but don't change method signatures.\n\n\
            Here is the template:\n\n"
        with open("agent.py", "r", encoding="utf-8") as f:
            template = f.read()
        return prompt + template   
        

    @message_handler
    async def handle_my_message_type(self, message: messages.Message, ctx: MessageContext) -> messages.Message:
        filename = message.content
        agent_name = filename.split(".")[0]
        text_message = TextMessage(content=self.get_user_prompt(), source="user")
        response = await self._delegate.on_messages([text_message], ctx.cancellation_token)
        with open(filename, "w", encoding="utf-8") as f:
            f.write(response.chat_message.content)
        print(f"** Creator has created python code for agent {agent_name} - about to register with Runtime")
        module = importlib.import_module(agent_name)
        await module.Agent.register(self.runtime, agent_name, lambda: module.Agent(agent_name))
        logger.info(f"** Agent {agent_name} is live")
        result = await self.send_message(messages.Message(content="Give me an idea"), AgentId(agent_name, "default"))
        return messages.Message(content=result.content)
// Week 5 Day 5 — the Agent Creator (TypeScript version of 5_autogen/creator.py)
//
// The Creator receives a file name such as "agent5.ts", asks an LLM to write a new agent using src/agent.ts as the
// template, saves it, imports it with a dynamic import() (Python: importlib.import_module), registers the new agent
// type with the runtime it lives in, and asks the new agent for a business idea.
// (agent.ts itself carries no header comment on purpose: its whole text is sent to the LLM as the template.)
//
// SAFETY, as the presenter says: this writes LLM-generated code to disk and then RUNS it on your machine with no
// guardrails. Run it at your own risk, read the generated files, keep HOW_MANY_AGENTS small, or don't run it at all.
// The generated code can import anything Node can (files, network), exactly like the Python version.
import { readFileSync, writeFileSync } from "node:fs";
import path from "node:path";
import { pathToFileURL } from "node:url";
import { Agent as LLMAgent } from "@openai/agents";
import { AssistantAgent } from "./core/assistant.js";
import { AgentId, messageHandler, RoutedAgent, type MessageContext } from "./core/runtime.js";
import * as messages from "./messages.js";
import { MODEL } from "./setup.js";

export class Creator extends RoutedAgent {
  // Change this system message to reflect the unique characteristics of this agent

  systemMessage = `
    You are an Agent that is able to create new AI Agents.
    You receive a template in the form of TypeScript code that creates an Agent using a small AutoGen-Core-like runtime and the OpenAI Agents SDK.
    You should use this template to create a new Agent with a unique system message that is different from the template,
    and reflects their unique characteristics, interests and goals.
    You can choose to keep their overall goal the same, or change it.
    You can choose to take this Agent in a completely different direction. The only requirement is that the class must be named Agent,
    and it must extend RoutedAgent and have a constructor that takes a name parameter.
    Also avoid environmental interests - try to mix up the business verticals so that every agent is different.
    Respond only with the TypeScript code, no other text, and no markdown code blocks.
    `;

  private delegate: AssistantAgent<string>;

  constructor(name: string) {
    super(name);
    const llm = new LLMAgent({ name, model: MODEL, modelSettings: { temperature: 1.0 }, instructions: this.systemMessage });
    this.delegate = new AssistantAgent(llm);
  }

  getUserPrompt() {
    const prompt =
      "Please generate a new Agent based strictly on this template. Stick to the class structure. " +
      "Respond only with the TypeScript code, no other text, and no markdown code blocks.\n\n" +
      "Be creative about taking the agent in a new direction, but don't change method signatures.\n\n" +
      "Here is the template:\n\n";
    const template = readFileSync(path.join(messages.AGENTS_DIR, "agent.ts"), "utf-8");
    return prompt + template;
  }

  @messageHandler(messages.Message)
  async handleMyMessageType(message: messages.Message, ctx: MessageContext): Promise<messages.Message> {
    const filename = message.content; // e.g. "agent5.ts"
    const agentName = filename.split(".")[0];
    let code = await this.delegate.reply(this.getUserPrompt(), ctx.signal);
    // Not in the Python: small local models often wrap the code in ``` fences anyway, so strip them if present
    code = code.replace(/^\s*```[a-z]*\s*\n/i, "").replace(/\n```\s*$/, "\n");
    const file = path.join(messages.AGENTS_DIR, filename);
    writeFileSync(file, code, "utf-8");
    console.log(`** Creator has created code for agent ${agentName} - about to register with Runtime`);
    const module = await import(pathToFileURL(file).href); // Python: importlib.import_module(agent_name)
    await module.Agent.register(this.runtime, agentName, () => new module.Agent(agentName));
    console.log(`** Agent ${agentName} is live`);
    const result = await this.sendMessage<messages.Message>(new messages.Message("Give me an idea"), new AgentId(agentName, "default"));
    return new messages.Message(result.content);
  }
}

The world (lecture 17)

world.py "is just a Python script… Everything else you've seen has been agents." It starts a host and a worker, registers the Creator, and asks for HOW_MANY_AGENTS creations at the same time.

from autogen_ext.runtimes.grpc import GrpcWorkerAgentRuntimeHost
from agent import Agent
from creator import Creator
from autogen_ext.runtimes.grpc import GrpcWorkerAgentRuntime
from autogen_core import AgentId
import messages
import asyncio

HOW_MANY_AGENTS = 20

async def create_and_message(worker, creator_id, i: int):
    try:
        result = await worker.send_message(messages.Message(content=f"agent{i}.py"), creator_id)
        with open(f"idea{i}.md", "w") as f:
            f.write(result.content)
    except Exception as e:
        print(f"Failed to run worker {i} due to exception: {e}")

async def main():
    host = GrpcWorkerAgentRuntimeHost(address="localhost:50051")
    host.start() 
    worker = GrpcWorkerAgentRuntime(host_address="localhost:50051")
    await worker.start()
    result = await Creator.register(worker, "Creator", lambda: Creator("Creator"))
    creator_id = AgentId("Creator", "default")
    coroutines = [create_and_message(worker, creator_id, i) for i in range(1, HOW_MANY_AGENTS+1)]
    await asyncio.gather(*coroutines)
    try:
        await worker.stop()
        await host.stop()
    except Exception as e:
        print(e)




if __name__ == "__main__":
    asyncio.run(main())
// Week 5 Day 5 — launch the world (TypeScript version of 5_autogen/world.py). This is a plain script, not an agent.
//
// It starts the host and one worker (src/core/distributed.ts, a teaching stand-in for AutoGen's gRPC runtime),
// registers the Creator, then asks it to create HOW_MANY_AGENTS agents AT THE SAME TIME and saves each idea to ideaN.md.
//
// SAFETY: every creation writes LLM-generated TypeScript to src/agentN.ts and runs it. See the warning in creator.ts.
// COST: the course runs 20 with gpt-4o-mini ("a couple of cents"). The default here is 3; HOW_MANY_AGENTS=20 pnpm world for more.
import { writeFileSync } from "node:fs";
import { WorkerAgentRuntime, WorkerAgentRuntimeHost } from "./core/distributed.js";
import { AgentId } from "./core/runtime.js";
import { Creator } from "./creator.js";
import * as messages from "./messages.js";

const HOW_MANY_AGENTS = Number(process.env.HOW_MANY_AGENTS ?? 3);

async function createAndMessage(worker: WorkerAgentRuntime, creatorId: AgentId, i: number) {
  try {
    const result = await worker.sendMessage<messages.Message>(new messages.Message(`agent${i}.ts`), creatorId);
    writeFileSync(`idea${i}.md`, result.content, "utf-8");
  } catch (e) {
    console.log(`Failed to run worker ${i} due to exception: ${e}`); // one bad generated file must not stop the others
  }
}

async function main() {
  const host = new WorkerAgentRuntimeHost("localhost:50051");
  await host.start();
  const worker = new WorkerAgentRuntime("localhost:50051");
  await worker.start();
  await Creator.register(worker, "Creator", () => new Creator("Creator"));
  const creatorId = new AgentId("Creator", "default");
  // Python: coroutines = [...]; await asyncio.gather(*coroutines). In JavaScript calling an async function already
  // starts it, so build the array of promises and wait for all of them with Promise.all.
  const promises = [];
  for (let i = 1; i <= HOW_MANY_AGENTS; i++) promises.push(createAndMessage(worker, creatorId, i));
  await Promise.all(promises);
  try {
    await worker.stop();
    await host.stop();
  } catch (e) {
    console.log(e);
  }
}

// Python needs asyncio.run(main()) to start an event loop; Node always has one running.
await main();

Common mistakes

  • Running from the wrong folder: find_recipient and the template path are relative; run from 5_autogen/ (or week5-ts/).
  • Leftover agentN files from an earlier run: find_recipient may pick an agent that is not registered in this run, and that message fails. Delete old files first.
  • A generated file that does not compile: its creation fails and is printed; the others continue.
  • Port 50051 still in use: an earlier host is running.
  • Running 20 agents on a weak or expensive model: start with three.
Recap
  • A Creator agent writes agent code from a template, imports it at run time and registers it with the runtime.
  • Created agents message each other by name; the runtime does the delivery.
  • asyncio.gather (or Promise.all) runs many creations at once.
  • Educational, entertaining and edgy, but unreliable and unsafe: generated code runs without guardrails.
