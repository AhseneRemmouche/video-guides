Async, and why nest_asyncio (lecture 13)

Browser tools are asynchronous, so the graph is run asynchronously too. "Otherwise it's just the same": tool.run(inputs) becomes await tool.arun(inputs), graph.invoke(state) becomes await graph.ainvoke(state). In a notebook there is one complication. asyncio runs one event loop, the notebook is already running one, and Playwright needs another inside it. nest_asyncio.apply() patches asyncio to allow "an event loop within an event loop". "When we later put this into Python code, we actually won't need this anymore."

JavaScript has no such issue: everything is asynchronous already, so there is no sync/async pair of methods and nothing to patch.

Playwright is Microsoft's browser automation, "the next generation of Selenium". It was made for testing, but it is widely used for scraping because it renders the page and runs its JavaScript, unlike a plain HTTP request. It can run headless (no window) or "headful"; the course runs headful so you can watch the agent work.

uv run playwright install                       # Mac and Windows
uv run playwright install --with-deps chromium  # Linux and WSL

(The video's slide reads -with-reps, a typo for --with-deps.)

Windows and notebooks. The repo's lab 3 warns that on Windows, Playwright inside a notebook can raise NotImplementedError. Its workaround edits the Jupyter kernel's own code; the simpler way out is Day 5, where the same code runs as plain Python files.

// Browser tools for the agent, written on the `playwright` npm package.
// This file replaces Python's PlayWrightBrowserToolkit (langchain_community), which LangChain JS does not have.
// The seven tools keep the toolkit's names and arguments, so the model sees the same tools as in the course:
// navigate_browser, extract_text, extract_hyperlinks, get_elements, click_element, current_webpage, previous_webpage.
import { chromium, type Browser, type Page } from "playwright";
import { tool, type StructuredToolInterface } from "@langchain/core/tools";
import { z } from "zod";

/** The page the tools act on: the last open page, or a new one (the toolkit's get_current_page does the same). */
async function currentPage(browser: Browser): Promise<Page> {
  const context = browser.contexts().at(-1) ?? (await browser.newContext());
  return context.pages().at(-1) ?? (await context.newPage());
}

const MAX_TEXT = 8000; // keep tool results small enough for a small local model's context window

/** Python: PlayWrightBrowserToolkit.from_browser(async_browser=browser).get_tools() */
export function browserTools(browser: Browser): StructuredToolInterface[] {
  const navigate_browser = tool(
    async ({ url }) => {
      const page = await currentPage(browser);
      const response = await page.goto(url, { waitUntil: "domcontentloaded", timeout: 30_000 });
      return `Navigating to ${url} returned status code ${response?.status() ?? "unknown"}`;
    },
    { name: "navigate_browser", description: "Navigate a browser to the specified URL", schema: z.object({ url: z.string().describe("url to navigate to") }) },
  );

  const extract_text = tool(
    async () => {
      const page = await currentPage(browser);
      const text = (await page.innerText("body")).replace(/\s+/g, " ").trim(); // the Python tool uses BeautifulSoup's get_text
      return text.slice(0, MAX_TEXT);
    },
    { name: "extract_text", description: "Extract all the text on the current webpage", schema: z.object({}) },
  );

  const extract_hyperlinks = tool(
    async ({ absolute_urls }) => {
      const page = await currentPage(browser);
      const links = await page.$$eval("a[href]", (as, abs) => as.map((a) => (abs ? (a as HTMLAnchorElement).href : a.getAttribute("href") ?? "")), absolute_urls);
      return JSON.stringify([...new Set(links)].slice(0, 200));
    },
    {
      name: "extract_hyperlinks",
      description: "Extract all hyperlinks on the current webpage",
      schema: z.object({ absolute_urls: z.boolean().default(false).describe("Return absolute URLs instead of relative URLs") }),
    },
  );

  const get_elements = tool(
    async ({ selector, attributes }) => {
      const page = await currentPage(browser);
      const elements = await page.$$eval(selector, (els, attrs) =>
        els.slice(0, 50).map((el) => Object.fromEntries(attrs.map((a) => [a, a === "innerText" ? (el as HTMLElement).innerText : el.getAttribute(a)]))),
        attributes,
      );
      return JSON.stringify(elements);
    },
    {
      name: "get_elements",
      description: "Retrieve elements in the current web page matching the given CSS selector",
      schema: z.object({
        selector: z.string().describe("CSS selector, such as '*', 'div', 'p', 'a', #id, .classname"),
        attributes: z.array(z.string()).default(["innerText"]).describe("Set of attributes to retrieve for each element"),
      }),
    },
  );

  const click_element = tool(
    async ({ selector }) => {
      const page = await currentPage(browser);
      try {
        await page.click(selector, { timeout: 5_000 }); // only visible elements, like the toolkit's default
      } catch {
        return `Unable to click on element '${selector}'`;
      }
      return `Clicked element '${selector}'`;
    },
    { name: "click_element", description: "Click on an element with the given CSS selector", schema: z.object({ selector: z.string().describe("CSS selector for the element to click") }) },
  );

  const current_webpage = tool(async () => (await currentPage(browser)).url(), {
    name: "current_webpage",
    description: "Returns the URL of the current page",
    schema: z.object({}),
  });

  const previous_webpage = tool(
    async () => {
      const response = await (await currentPage(browser)).goBack();
      return response ? `Navigated back to the previous page with URL '${response.url()}'. Status code ${response.status()}` : "Unable to navigate back; no previous page in the history";
    },
    { name: "previous_webpage", description: "Navigate back to the previous page in the browser history", schema: z.object({}) },
  );

  return [click_element, navigate_browser, previous_webpage, extract_text, extract_hyperlinks, get_elements, current_webpage];
}

/** Python (sidekick_tools.py): playwright_tools() → (tools, browser, playwright). Here the browser object also stops Playwright.
 *  The course runs headful (headless=False) so you can watch the agent; set HEADLESS=true to hide the window. */
export async function playwrightTools() {
  const browser = await chromium.launch({ headless: process.env.HEADLESS === "true" });
  return { tools: browserTools(browser), browser };
}

Lab 4: structured outputs for an evaluator (lecture 15)

Step one of structured outputs is a schema: a Pydantic object describing the JSON the model must return. This one is for an evaluator, "something which is going to decide whether or not an answer from an LLM is good". On camera he edits "worker's response" to "assistant's response" because "that's going to be more words that it will understand".

# First define a structured output

class EvaluatorOutput(BaseModel):
    feedback: str = Field(description="Feedback on the assistant's response")
    success_criteria_met: bool = Field(description="Whether the success criteria have been met")
    user_input_needed: bool = Field(description="True if more input is needed from the user, or clarifications, or the assistant is stuck")
# The state

class State(TypedDict):
    messages: Annotated[List[Any], add_messages]
    success_criteria: str
    feedback_on_work: Optional[str]
    success_criteria_met: bool
    user_input_needed: bool
// For structured outputs, we define a schema — a zod object plays the role of the Pydantic model
const EvaluatorOutput = z.object({
  feedback: z.string().describe("Feedback on the assistant's response"),
  success_criteria_met: z.boolean().describe("Whether the success criteria have been met"),
  user_input_needed: z.boolean().describe("True if more input is needed from the user, or clarifications, or the assistant is stuck"),
});

// The state: messages uses the reducer; the other fields have none, so a new value simply overwrites the old one
const State = Annotation.Root({
  messages: Annotation<BaseMessage[], BaseMessageLike[]>({ reducer: messagesStateReducer, default: () => [] }),
  success_criteria: Annotation<string>(),
  feedback_on_work: Annotation<string | null>(),
  success_criteria_met: Annotation<boolean>(),
  user_input_needed: Annotation<boolean>(),
});
type StateT = typeof State.State;

The State now carries real information. Only messages has a reducer, so replies are appended; the other four fields have none, so a returned value simply overwrites the old one "for anything that is downstream of you in the graph". Optional[str] means "if this can be null".

The worker (lecture 15, 05:39–09:16)

The worker's system prompt took "the last couple of hours". The line "simply reply with the answer" is there because "these models love to reply with things like can I help you with anything else? And that then might confuse our evaluator." When the evaluator has rejected an attempt, its feedback is added. Swapping the system message in is "a little bit hokey… worth doing some testing".

# The worker node

def worker(state: State) -> Dict[str, Any]:
    system_message = f"""You are a helpful assistant that can use tools to complete tasks.
You keep working on a task until either you have a question or clarification for the user, or the success criteria is met.
This is the success criteria:
{state['success_criteria']}
You should reply either with a question for the user about this assignment, or with your final response.
If you have a question for the user, you need to reply by clearly stating your question. An example might be:

Question: please clarify whether you want a summary or a detailed answer

If you've finished, reply with the final answer, and don't ask a question; simply reply with the answer.
"""
    
    if state.get("feedback_on_work"):
        system_message += f"""
Previously you thought you completed the assignment, but your reply was rejected because the success criteria was not met.
Here is the feedback on why this was rejected:
{state['feedback_on_work']}
With this feedback, please continue the assignment, ensuring that you meet the success criteria or have a question for the user."""
    
    # Add in the system message

    found_system_message = False
    messages = state["messages"]
    for message in messages:
        if isinstance(message, SystemMessage):
            message.content = system_message
            found_system_message = True
    
    if not found_system_message:
        messages = [SystemMessage(content=system_message)] + messages
    
    # Invoke the LLM with tools
    response = worker_llm_with_tools.invoke(messages)
    
    # Return updated state
    return {
        "messages": [response],
    }
// The worker node
async function worker(state: StateT) {
  let system_message = `You are a helpful assistant that can use tools to complete tasks.
You keep working on a task until either you have a question or clarification for the user, or the success criteria is met.
This is the success criteria:
${state.success_criteria}
You should reply either with a question for the user about this assignment, or with your final response.
If you have a question for the user, you need to reply by clearly stating your question. An example might be:

Question: please clarify whether you want a summary or a detailed answer

If you've finished, reply with the final answer, and don't ask a question; simply reply with the answer.
`;
  if (state.feedback_on_work) {
    system_message += `
Previously you thought you completed the assignment, but your reply was rejected because the success criteria was not met.
Here is the feedback on why this was rejected:
${state.feedback_on_work}
With this feedback, please continue the assignment, ensuring that you meet the success criteria or have a question for the user.`;
  }

  // Add in the system message: replace an old one if there is one, otherwise put it first
  // (Python edits message.content in place; here we build a new list, which is the safer JavaScript habit)
  const found_system_message = state.messages.some((m) => SystemMessage.isInstance(m));
  const messages = found_system_message
    ? state.messages.map((m) => (SystemMessage.isInstance(m) ? new SystemMessage(system_message) : m))
    : [new SystemMessage(system_message), ...state.messages];

  // Invoke the LLM with tools
  const response = await worker_llm_with_tools.invoke(messages);
  return { messages: [response] };
}

Lines 60–63: Python edits an existing system message in place; the TypeScript version builds a new list instead, the safer habit when state must stay immutable.

Routers, the evaluator and the graph (lecture 16)

A router is a plain function used in a conditional edge: tool calls go to "tools", anything else to "evaluator". format_conversation turns the message objects into "User: … / Assistant: …" text for the evaluator, with "[Tools use]" for tool-only turns.

def worker_router(state: State) -> str:
    last_message = state["messages"][-1]
    
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tools"
    else:
        return "evaluator"
function worker_router(state: StateT): "tools" | "evaluator" {
  const last_message = state.messages.at(-1);
  return AIMessage.isInstance(last_message) && last_message.tool_calls?.length ? "tools" : "evaluator";
}

function format_conversation(messages: BaseMessage[]): string {
  let conversation = "Conversation history:\n\n";
  for (const message of messages) {
    if (HumanMessage.isInstance(message)) conversation += `User: ${message.content}\n`;
    else if (AIMessage.isInstance(message)) conversation += `Assistant: ${message.content || "[Tools use]"}\n`;
  }
  return conversation;
}
def format_conversation(messages: List[Any]) -> str:
    conversation = "Conversation history:\n\n"
    for message in messages:
        if isinstance(message, HumanMessage):
            conversation += f"User: {message.content}\n"
        elif isinstance(message, AIMessage):
            text = message.content or "[Tools use]"
            conversation += f"Assistant: {text}\n"
    return conversation

The evaluator is told to judge the last answer against the criteria, and to decide whether the user must step in. Two prompting lessons: "there's never a harm in being repetitious with prompting. Be clear. Be instructive. Repeat yourself." And the anti-loop sentence ("If you're seeing the Assistant repeating the same mistakes…") exists "because I was testing this and it kept messing up by the evaluator sending back the same problem again and again… it's research and development."

def evaluator(state: State) -> State:
    last_response = state["messages"][-1].content

    system_message = """You are an evaluator that determines if a task has been completed successfully by an Assistant.
Assess the Assistant's last response based on the given criteria. Respond with your feedback, and with your decision on whether the success criteria has been met,
and whether more input is needed from the user."""
    
    user_message = f"""You are evaluating a conversation between the User and Assistant. You decide what action to take based on the last response from the Assistant.

The entire conversation with the assistant, with the user's original request and all replies, is:
{format_conversation(state['messages'])}

The success criteria for this assignment is:
{state['success_criteria']}

And the final response from the Assistant that you are evaluating is:
{last_response}

Respond with your feedback, and decide if the success criteria is met by this response.
Also, decide if more user input is required, either because the assistant has a question, needs clarification, or seems to be stuck and unable to answer without help.
"""
    if state["feedback_on_work"]:
        user_message += f"Also, note that in a prior attempt from the Assistant, you provided this feedback: {state['feedback_on_work']}\n"
        user_message += "If you're seeing the Assistant repeating the same mistakes, then consider responding that user input is required."
    
    evaluator_messages = [SystemMessage(content=system_message), HumanMessage(content=user_message)]

    eval_result = evaluator_llm_with_output.invoke(evaluator_messages)
    new_state = {
        "messages": [{"role": "assistant", "content": f"Evaluator Feedback on this answer: {eval_result.feedback}"}],
        "feedback_on_work": eval_result.feedback,
        "success_criteria_met": eval_result.success_criteria_met,
        "user_input_needed": eval_result.user_input_needed
    }
    return new_state
async function evaluator(state: StateT): Promise<typeof State.Update> {
  const last_response = state.messages.at(-1)!.content;

  const system_message = `You are an evaluator that determines if a task has been completed successfully by an Assistant.
Assess the Assistant's last response based on the given criteria. Respond with your feedback, and with your decision on whether the success criteria has been met,
and whether more input is needed from the user.`;

  let user_message = `You are evaluating a conversation between the User and Assistant. You decide what action to take based on the last response from the Assistant.

The entire conversation with the assistant, with the user's original request and all replies, is:
${format_conversation(state.messages)}

The success criteria for this assignment is:
${state.success_criteria}

And the final response from the Assistant that you are evaluating is:
${last_response}

Respond with your feedback, and decide if the success criteria is met by this response.
Also, decide if more user input is required, either because the assistant has a question, needs clarification, or seems to be stuck and unable to answer without help.
`;
  if (state.feedback_on_work) {
    user_message += `Also, note that in a prior attempt from the Assistant, you provided this feedback: ${state.feedback_on_work}\n`;
    user_message += "If you're seeing the Assistant repeating the same mistakes, then consider responding that user input is required.";
  }

  const eval_result = await evaluator_llm_with_output.invoke([new SystemMessage(system_message), new HumanMessage(user_message)]);
  return {
    messages: [{ role: "assistant", content: `Evaluator Feedback on this answer: ${eval_result.feedback}` }],
    feedback_on_work: eval_result.feedback,
    success_criteria_met: eval_result.success_criteria_met,
    user_input_needed: eval_result.user_input_needed,
  };
}

Each UI session gets its own thread ID from uuid4, so "we could actually… have multiple different people that come on and use the interface and each have different conversations." process_message starts one super-step and returns the worker's answer (messages[-2]) and the evaluator's feedback (messages[-1]). Mixing Gradio's history with LangGraph's memory is "a little bit of a confusion", "so I thought, keep it simple".

type ChatMessage = { role: "user" | "assistant"; content: string };

async function process_message(message: string, success_criteria: string, history: ChatMessage[], thread: string) {
  const config = { configurable: { thread_id: thread } };
  const state = { messages: [{ role: "user", content: message }], success_criteria, feedback_on_work: null, success_criteria_met: false, user_input_needed: false };
  const result = await graph.invoke(state, config); // stops with GraphRecursionError after 25 steps (LangGraph's default)
  const user: ChatMessage = { role: "user", content: message };
  const reply: ChatMessage = { role: "assistant", content: String(result.messages.at(-2)!.content) }; // the worker's answer
  const feedback: ChatMessage = { role: "assistant", content: String(result.messages.at(-1)!.content) }; // the evaluator's verdict
  return [...history, user, reply, feedback];
}

Common mistakes

  • Playwright not installed: the Python package and the npm package each need playwright install to download their own Chromium.
  • Running async tools synchronously: in Python, use arun and ainvoke (and nest_asyncio in a notebook).
  • Tools that return nothing: the model sees null; return a short success message.
  • A model without structured-output support: with_structured_output fails; ask for JSON in the prompt and parse it yourself.
  • Endless worker–evaluator loops: keep the anti-loop sentence and the "user input needed" exit, and expect long loops on hard tasks.
  • Leaving the browser open: a script must close it (browser.close()), or the program never exits.
Recap
  • Playwright gives an agent a real browser; seven low-level tools let the model navigate, read and click.
  • Async in Python means arun/ainvoke, plus nest_asyncio inside notebooks; JavaScript is async already.
  • Structured output: a schema (Pydantic or zod) plus with_structured_output gives a parsed object.
  • The Sidekick is a worker that uses tools and an evaluator that judges against success criteria, joined by router functions.
  • The loop ends when the criteria are met or the user is needed.
