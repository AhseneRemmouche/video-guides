Week 6 Day 4 · An autonomous trader with a researcher

What this day builds

The capstone begins: an autonomous trader. A trader agent gets its tools from three MCP servers (the account, push notifications, market prices) and has a researcher agent as a tool; the researcher has its own servers (fetch, Brave search, memory). Day 4 builds one trader, "Ed", first in the notebook and then as Python modules. "Please don't use this for actual trading decisions… This is, of course, an experimental project and nothing more than that."

TypeScript: pnpm lab4 resets Ed and runs one trader turn with src/traders.ts; pnpm count-tools counts the servers and tools. Without Brave and Polygon keys the trader runs with 5 servers and 14 tools; with the course's paid set-up it is 6 and 44.

The plan (lecture 15)

"Autonomous Traders" is chosen because it is "something that is commercial", where many agent projects are "quite technical in nature… teams of coders". It also brings back the Week 3 crew's accounts.py. The method: "approach agent projects with a data scientist's hat on": experiment in the lab, then move to modules when it works.

The trader's servers depend on your Polygon plan: the official Polygon server with all its tools on a paid plan, otherwise the one-tool market_server, so the model "is not overwhelmed" and the end-of-day cache keeps you inside the rate limit. The push server keeps all its logic inside the server; "there's absolutely nothing stopping you from just having this as a tool. In fact, that would be the better way", but it is a good small example.

function createServer(): McpServer {
  const mcp = new McpServer({ name: "push_server", version: "1.0.0" });
  mcp.registerTool(
    "push",
    {
      description: "Send a push notification with this brief message",
      inputSchema: z.object({ args: z.object({ message: z.string().describe("A brief message to push") }) }),
    },
    async ({ args }) => {
      console.error(`Push: ${args.message}`);
      if (pushoverUser && pushoverToken) {
        await fetch(pushoverUrl, { method: "POST", body: new URLSearchParams({ user: pushoverUser, token: pushoverToken, message: args.message }) });
      }
      return { content: [{ type: "text", text: "Push notification sent" }] };
    },
  );
  return mcp;
}

A researcher as a tool (lecture 16)

The trader calls the researcher as a tool, "a very common pattern with OpenAI Agents SDK": control returns to the trader afterwards, unlike a handoff (Week 2). The current date is in the instructions, not a tool. max_turns is raised from the default ten ("up to ten sets of tool calls") to 30 for deep research; a lower number stops agents "overthinking".

async def get_researcher(mcp_servers) -> Agent:

trade_message(…) · rebalance_message(…)The two alternating user messages: look for new opportunities, or rebalance and possibly change strategy. They carry the strategy and the account JSON.

Prompt quirks worth knowing. The free-plan note says "use you get_share_price tool", but the tool is called lookup_share_price. The trade message forbids a "get company news" tool that no server offers. And the trader instructions promise memory that only the researcher has. Models usually cope, but fix these if you build on the code.

// Port of 6_mcp/traders.py — one autonomous trader: a trader agent whose tools come from MCP servers (accounts, push,
// market) plus a researcher agent (fetch, Brave search, memory servers) wrapped as a tool. Each run opens every MCP server,
// runs the agent, closes the servers again, and switches between "trade" and "rebalance" for the next run.
// Differences: connectAll() + try/finally replace Python's AsyncExitStack; withTrace(name, fn, {traceId}) replaces
// "with trace(...)"; the provider clients in getModel() are created only when needed (a missing key then fails only
// for that model). In local mode (setup.ts) a plain model name goes to Ollama.
import OpenAI from "openai";
import { Agent, MCPServerStdio, OpenAIChatCompletionsModel, run, withTrace, type Model, type Tool } from "@openai/agents";
import { model } from "./setup.js";
import { readAccountsResource, readStrategyResource } from "./accounts_client.js";
import { makeTraceId } from "./tracers.js";
import { rebalanceMessage, researcherInstructions, researchTool, tradeMessage, traderInstructions } from "./templates.js";
import { researcherMcpServerParams, traderMcpServerParams, type StdioParams } from "./mcp_params.js";

const DEEPSEEK_BASE_URL = "https://api.deepseek.com/v1";
const GROK_BASE_URL = "https://api.x.ai/v1";
const GEMINI_BASE_URL = "https://generativelanguage.googleapis.com/v1beta/openai/";
const OPENROUTER_BASE_URL = "https://openrouter.ai/api/v1";

const MAX_TURNS = 30;

const chat = (baseURL: string, apiKey: string | undefined, modelName: string) =>
  new OpenAIChatCompletionsModel(new OpenAI({ baseURL, apiKey }), modelName);

/** Pick the provider from the model name, as in the course: "a/b" -> OpenRouter, deepseek, grok, gemini, else OpenAI. */
export function getModel(modelName: string): string | Model {
  if (modelName.includes("/")) return chat(OPENROUTER_BASE_URL, process.env.OPENROUTER_API_KEY, modelName);
  else if (modelName.includes("deepseek")) return chat(DEEPSEEK_BASE_URL, process.env.DEEPSEEK_API_KEY, modelName);
  else if (modelName.includes("grok")) return chat(GROK_BASE_URL, process.env.GROK_API_KEY, modelName);
  else if (modelName.includes("gemini")) return chat(GEMINI_BASE_URL, process.env.GOOGLE_API_KEY, modelName);
  else return modelName;
}

async function getResearcher(mcpServers: MCPServerStdio[], modelName: string): Promise<Agent> {
  return new Agent({ name: "Researcher", instructions: researcherInstructions(), model: getModel(modelName), mcpServers });
}

async function getResearcherTool(mcpServers: MCPServerStdio[], modelName: string): Promise<Tool> {
  const researcher = await getResearcher(mcpServers, modelName);
  return researcher.asTool({ toolName: "Researcher", toolDescription: researchTool() });
}

/** Start every server in the list; if one fails, close the ones already started (what AsyncExitStack does for us in Python). */
async function connectAll(paramsList: StdioParams[]): Promise<MCPServerStdio[]> {
  const servers: MCPServerStdio[] = [];
  try {
    for (const params of paramsList) {
      const server = new MCPServerStdio({ ...params, clientSessionTimeoutSeconds: 120 });
      await server.connect();
      servers.push(server);
    }
    return servers;
  } catch (e) {
    await closeAll(servers);
    throw e;
  }
}

async function closeAll(servers: MCPServerStdio[]): Promise<void> {
  for (const server of [...servers].reverse()) await server.close().catch(() => {});
}

export class Trader {
  agent: Agent | null = null;
  doTrade = true;

  constructor(
    public name: string,
    public lastname = "Trader",
    public modelName = model("gpt-4o-mini"),
  ) {}

  async createAgent(traderMcpServers: MCPServerStdio[], researcherMcpServers: MCPServerStdio[]): Promise<Agent> {
    const tool = await getResearcherTool(researcherMcpServers, this.modelName);
    this.agent = new Agent({
      name: this.name,
      instructions: traderInstructions(this.name),
      model: getModel(this.modelName),
      tools: [tool],
      mcpServers: traderMcpServers,
    });
    return this.agent;
  }

  /** The account as JSON, without the (long) portfolio value time series. */
  async getAccountReport(): Promise<string> {
    const account = JSON.parse(await readAccountsResource(this.name));
    delete account.portfolio_value_time_series;
    return JSON.stringify(account);
  }

  async runAgent(traderMcpServers: MCPServerStdio[], researcherMcpServers: MCPServerStdio[]) {
    const agent = await this.createAgent(traderMcpServers, researcherMcpServers);
    const account = await this.getAccountReport();
    const strategy = await readStrategyResource(this.name);
    const message = this.doTrade ? tradeMessage(this.name, strategy, account) : rebalanceMessage(this.name, strategy, account);
    return run(agent, message, { maxTurns: MAX_TURNS });
  }

  async runWithMcpServers() {
    const traderMcpServers = await connectAll(traderMcpServerParams);
    try {
      const researcherMcpServers = await connectAll(researcherMcpServerParams(this.name));
      try {
        return await this.runAgent(traderMcpServers, researcherMcpServers);
      } finally {
        await closeAll(researcherMcpServers);
      }
    } finally {
      await closeAll(traderMcpServers);
    }
  }

  async runWithTrace() {
    const traceName = this.doTrade ? `${this.name}-trading` : `${this.name}-rebalancing`;
    const traceId = makeTraceId(this.name.toLowerCase());
    return withTrace(traceName, () => this.runWithMcpServers(), { traceId });
  }

  /** One run; errors are printed, not thrown, so one failing trader does not stop the others. */
  async run() {
    let result;
    try {
      result = await this.runWithTrace();
    } catch (e) {
      console.log(`Error running trader ${this.name}: ${e}`);
    }
    this.doTrade = !this.doTrade;
    return result;
  }
}

The trace "Ed-trading" shows the researcher's search, many price lookups, buys of Amazon, Apple and Microsoft, a sale and a push notification. The challenge: add tools ("the more the merrier"), but "start by adding in those tools, working in the lab".

Video vs repo. The video's traders.py used the default five-second server timeout; the repo uses 120 seconds. The push tool's return value was added after recording. mcp_params.py pins the Polygon server to @v0.1.0 (the video used @master, and the repo's lab 4 notebook still does). Despite their titles, lectures 16 and 18 show no user interface and only one trader.

Common mistakes

  • Five-second timeouts: six servers starting at once need longer; use 120 seconds.
  • No BRAVE_API_KEY in the Python version: the Brave server exits and the trader run fails. Get a free key, or remove it from mcp_params.py.
  • Forgetting to reset an account: earlier runs' holdings and strategy carry over.
  • A tool that returns nothing: the SDK reports an error result; return a short confirmation.
  • Treating the output as advice: it is a simulation.
Recap
  • A trader agent gets its tools from MCP servers and a researcher agent through as_tool.
  • Account and strategy resources are text put into the prompt; the date goes in too.
  • mcp_params lists the servers, templates the prompts, traders the logic.
  • Each run opens six servers, runs up to 30 turns, closes them and switches between trading and rebalancing.
