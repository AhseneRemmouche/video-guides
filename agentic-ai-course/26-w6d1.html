What MCP is, and is not (lecture 1)

"It's not really a framework at all. It's a protocol." Not a way to build agents, not "some sort of fundamental change to anything". Anthropic calls it "the USB-C of Agentic AI" (the presenter notes the slide's AI-generated picture shows a USB-A plug). It is "a simple way to integrate your agents with tools or resources or prompts that have been written by other people". Tools are where the excitement is; resources are "fairly popular"; shared prompts have "not particularly taken off".

Reasons not to be excited (slide)The reason to be excited
"It's just a standard, it's not tools themselves." "LangChain already has a big Tools ecosystem." "You can already make any function into a Tool"; for your own tools MCP "makes that harder".It "makes it frictionless to integrate" someone else's tool, with its description and parameters included. "It's really about the ecosystem": thousands of servers. Standards matter once they are adopted, like HTML.

Hosts, clients and servers (lecture 2)

  • The host is the whole application: Claude Desktop, or our Agents SDK program.
  • An MCP client is "a small piece of software, think of it like a plugin that runs inside that host", one per server.
  • An MCP server is a separate program that provides tools, resources and prompts.

The common misunderstanding: "MCP servers mostly run on your box. You typically download them and you run them locally." Three set-ups exist: a local server that works locally (files), a local server that calls a web API ("by far the most common": fetch, search, weather), and a remote hosted server ("quite rare"). Two transports carry the messages: stdio, where the client starts the server as a process and talks over standard input and output (what this course uses), and SSE over HTTPS, which remote servers need.

Using MCP servers from the Agents SDK (lectures 3–4)

Windows. The course says MCP servers do not work reliably on native Windows ("as of May 4th, 2025") and uses WSL, the Windows Subsystem for Linux; setup/SETUP-WSL.md walks through it. Tip: start WSL by typing ubuntu, so you land in the Linux home folder.

The TypeScript port was built and tested on Windows: Node starts npx and uvx servers there without WSL.

"Everything begins with parameters": a server is described by a command and its args, literally the command line that starts it. uvx mcp-server-fetch downloads and runs a Python package; npx does the same for Node packages (you need a recent Node; check with npx --version). The default timeout of five seconds "is very hit or miss… so I always pass in 30 or 60s".

/** Open a server, list its tools, close it (cells 5, 8 and 9). */
async function listTools(label: string, params: Params) {
  const server = new MCPServerStdio({ ...params, clientSessionTimeoutSeconds: 60 });
  await server.connect();
  try {
    const tools = await server.listTools();
    console.log(`\n${label}: ${tools.length} tools`);
    for (const t of tools) console.log(`- ${t.name}: ${(t.description ?? "").split("\n")[0].slice(0, 110)}`);
  } finally {
    await server.close();
  }
}

Marketplaces and security (lectures 5–6)

Where to find servers: mcp.so (with an Explore page by category), Glama (with security, licence and quality ratings), Smithery, Anthropic's reference servers, "Awesome MCP servers" lists, and two Hugging Face articles on the subject.

Security: running an MCP server "is like doing a pip install or an npm install… as dangerous as just doing a pip install of someone else's code". Check the publisher (Microsoft and Anthropic are fine), GitHub stars, an active community and security reviews; some servers can run in Docker. The bigger worry is non-technical users adding servers to Claude Desktop.

Video vs repo. The video uses 30-second timeouts; the repo uses 60. The repo adds the sandbox line to the instructions, a note about the newer SDK's server.session.list_tools(), and a link to setup/SETUP-node.md for installing Node.

Common mistakes

  • Native Windows with the Python course code: use WSL, as the course advises.
  • An old Node: npx servers need a recent version; upgrade with nvm.
  • The five-second default timeout: the first npx run downloads the package and times out. Pass 30 or 60 seconds.
  • No sandbox folder: the filesystem server needs it to exist.
  • Trusting any server: it runs on your machine with your permissions.
Recap
  • MCP is a protocol for sharing tools, resources and prompts; its value is the ecosystem.
  • Host, client (one per server), server (usually local); transports stdio and SSE.
  • MCPServerStdio(params) starts a server from a command line; pass servers to an agent with mcp_servers (mcpServers in TypeScript).
  • Installing an MCP server deserves the same care as installing any package.
