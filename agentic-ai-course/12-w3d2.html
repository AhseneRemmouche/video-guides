Week 3 Day 2 · Financial researcher with web search

A researcher and an analyst crew with the Serper search tool and task context, and what happens when a small local model loops on search.

Course lectures (Udemy) · code verified against the repo

What this day builds

A two-agent crew that writes a report on a company: a researcher gathers facts, an analyst turns them into a polished report. Two new CrewAI ideas carry the day. Context passes one task's output into another task explicitly. Tools give an agent a capability; here the researcher gets SerperDevTool, a Google search through Serper. The first run, without a tool, produces a report stuck in 2023, which shows the knowledge cut-off problem; the second run, with search, fixes it.

TypeScript: pnpm financial "Tesla" in week3-ts. The researcher gets searchTool from src/tools.ts, which calls Serper's REST API when SERPER_API_KEY is set and returns canned text otherwise.

The five steps of a CrewAI project (lecture 7)

The slide is titled "Five Steps" but shows four; the fifth is spoken:

  1. Create the project with crewai create crew my_project.
  2. Fill in the config YAML files to define the agents and tasks.
  3. Complete crew.py to create the agents, tasks and crew, referencing the config.
  4. Update main.py to set any config and run.
  5. Run crewai run from within the project folder.

"Going deeper" adds two concepts: tools, "equipping agents with capabilities", and context, "information passed from one task to another". "This is how you tell Crew what information is to be passed from one task to another."

Serper: Google searches from code (lecture 7, 03:23)

"Another of these APIs… you'll be pleased to hear it's another free one", a contrast with Week 2's OpenAI web search at 2.5 cents a call. Sign up at serper.dev (2,500 free queries, no credit card), open "API key" in the dashboard, and add the key to the root .env:

SERPER_API_KEY=...

Watch the name: SERP is "search engine results page", and a different service called SerpAPI exists; "be sure that you use SERPER_API_KEY".

The crew, with a tool

Giving an agent a tool "is really rather easy" (ironic, lecture 9): import the tool and put an instance in the agent's tools list. Only the researcher gets it.

# src/financial_researcher/crew.py
from crewai import Agent, Crew, Process, Task
from crewai.project import CrewBase, agent, crew, task
from crewai_tools import SerperDevTool

@CrewBase
class ResearchCrew():
    """Research crew for comprehensive topic analysis and reporting"""

    @agent
    def researcher(self) -> Agent:
        return Agent(
            config=self.agents_config['researcher'],
            verbose=True,
            tools=[SerperDevTool()]
        )

    @agent
    def analyst(self) -> Agent:
        return Agent(
            config=self.agents_config['analyst'],
            verbose=True
        )

    @task
    def research_task(self) -> Task:
        return Task(
            config=self.tasks_config['research_task']
        )

    @task
    def analysis_task(self) -> Task:
        return Task(
            config=self.tasks_config['analysis_task'],
            output_file='output/report.md'
        )

    @crew
    def crew(self) -> Crew:
        """Creates the research crew"""
        return Crew(
            agents=self.agents,
            tasks=self.tasks,
            process=Process.sequential,
            verbose=True,
        )
// Week 3 Day 2 — the financial researcher crew (TypeScript version of 3_crew/financial_researcher)
// The researcher gets the search tool; the analyst receives the research through "context: [research_task]".

The search tool (src/tools.ts):

// The tools the Week 3 crews use, as Agents SDK function tools:
// web search (CrewAI's SerperDevTool), push notification (the course's custom PushNotificationTool),
// and Python code execution in Docker (CrewAI's allow_code_execution with code_execution_mode="safe").
import { execFile } from "node:child_process";
import { tool } from "@openai/agents";
import { z } from "zod";

/** Google search through serper.dev; without SERPER_API_KEY it returns canned text labelled as test data. */
export const searchTool = tool({
  name: "search_the_internet",
  description: "Search the internet with a search query and get the top results.",
  parameters: z.object({ search_query: z.string().describe("Mandatory search query you want to use to search the internet") }),
  execute: async ({ search_query }) => {
    const key = process.env.SERPER_API_KEY;
    console.log(`[search] ${search_query}${key ? "" : " (stand-in: no SERPER_API_KEY)"}`);
    if (!key) {
      return (
        "Search results (canned offline test data, not real news): 1. NovaChip Inc. (ticker NVCP) shares rose after it " +
        "announced a low-power AI accelerator for laptops. 2. Cloudwise Systems (ticker CLWS) reported record cloud revenue " +
        "and a new partnership with a large bank. 3. Quantia Labs (ticker QNTA) published a roadmap for error-corrected " +
        "quantum hardware by 2028."
      );
    }
    const res = await fetch("https://google.serper.dev/search", {
      method: "POST",
      headers: { "X-API-KEY": key, "Content-Type": "application/json" },
      body: JSON.stringify({ q: search_query }),
    });
    const data = (await res.json()) as { organic?: { title: string; link: string; snippet: string }[] };
    return (data.organic ?? []).slice(0, 8).map((r) => `${r.title}\n${r.link}\n${r.snippet}`).join("\n\n");
  },
});

/** Push notification through Pushover (prints only when the keys are missing). */
export const pushTool = tool({
  name: "send_push_notification",
  description: "This tool is used to send a push notification to the user.",
  parameters: z.object({ message: z.string().describe("The message to be sent to the user.") }),
  execute: async ({ message }) => {
    console.log(`Push: ${message}`);
    const user = process.env.PUSHOVER_USER, token = process.env.PUSHOVER_TOKEN;
    if (user && token) {
      await fetch("https://api.pushover.net/1/messages.json", { method: "POST", body: new URLSearchParams({ user, token, message }) });
    }
    return '{"notification": "ok"}';
  },
});

/** Run Python in a throw-away Docker container: no network, limited memory, a time limit. */
export function runPythonInDocker(code: string, timeoutSeconds = 30): Promise<string> {
  return new Promise((resolve) => {
    const child = execFile(
      "docker",
      ["run", "--rm", "-i", "--network", "none", "--memory", "256m", "python:3.12-slim", "python", "-"],
      { timeout: timeoutSeconds * 1000, maxBuffer: 1024 * 1024 },
      (err, stdout, stderr) => resolve(err && !stdout ? `Error: ${stderr || err.message}` : stdout + (stderr ? `\n[stderr]\n${stderr}` : "")),
    );
    child.stdin?.end(code);
  });
}

export const codeTool = tool({
  name: "run_python",
  description: "Run Python 3 code in a sandboxed Docker container and return what it prints. Print anything you need to see.",
  parameters: z.object({ code: z.string().describe("The complete Python program to run") }),
  execute: async ({ code }) => {
    console.log(`[run_python] ${code.split("\n").length} lines`);
    return runPythonInDocker(code);
  },
});

Run 1: no tool, stale facts (lectures 8–9)

"Didn't we set up Serper?… all in good time. Let's first just try running this without making any proper Google lookup." The researcher on DeepSeek "takes its time… a good 30 seconds", the analyst on Groq is instant, and the report is solid but dated: "as of October 2023", with "Q3 2023" figures. "That's clearly not right now." The model only knows what it saw in training: "the knowledge cut off from DeepSeek… was last trained back in 2023". The fix "is the big plan for this week": a tool.

Run 2: with search (lecture 9, 02:16–04:42)

With SerperDevTool on the researcher (and the researcher switched back to openai/gpt-4o-mini "so that we have a faster time of it"), the log shows "🔧 Used Search the internet with Serper (1)", then (2), (3), (4), with the raw Google JSON (peopleAlsoAsk, relatedSearches, 'credits': 1) printed on the way. The report now opens its news section with "In early 2025, Tesla's sales fell by 13% to 336,681 deliveries". "This is actually a high quality output… if you spent about ten minutes, 15 minutes yourself searching the internet… you probably would come up with something quite similar. It's proper work." And "this has cost us nothing": it came out of the free credits.

What you should see. The first report reads like 2023. The second shows "🔧 Used Search the internet with Serper" in the log, mentions recent events, ends with the market outlook and the "should not be used for trading decisions" note, and is saved to output/report.md. Our run

This guide ran the repo's crew with llama3.2 (local) for both agents. Search was replaced by a stand-in that returns the same canned paragraph about three invented companies, whatever the query, so no API key or network was needed.

Two lessons: when a tool returns nothing useful, a small model loops; and a polished report proves nothing about whether the tool helped. Read the log.

Video vs repo. The video's class is FinancialResearcher with explicit config paths; the repo's is ResearchCrew without them and repeats output_file in code. The video used Tesla, the repo Apple. The video's models were DeepSeek (then OpenAI) for the researcher and Groq's Llama 3.3 70B for the analyst; the repo uses openai/gpt-4o-mini for both. The video's YAML wrote output/analysis.md; the repo writes output/report.md and prints a "Report has been saved" line.

Common mistakes

  • Using a SerpAPI key: different service. The variable is SERPER_API_KEY, from serper.dev.
  • The report is out of date: the researcher has no tool, or the key is missing so the tool errors; check the log for "Used Search the internet with Serper".
  • Forgetting context: in a longer crew the analyst might receive irrelevant earlier outputs, or with a hierarchical process none at all. Name the tasks you need.
  • The tool on the wrong agent: only agents with the tool can search; the analyst cannot.
  • Cursor's "Problems" count on crew.py: the editor's Python is the course's environment, not the crew's own, so it cannot resolve crewai_tools. The crew still runs with crewai run.
  • Treating the report as advice: the prompt itself says it "should not be used for trading decisions".

Recap
  • Every CrewAI project: create, YAML, crew.py, main.py, crewai run.
  • context: [task] passes chosen task outputs into a task's prompt.
  • tools=[SerperDevTool()] on one agent gives it Google search through Serper (2,500 free queries, SERPER_API_KEY).
  • Without a tool a model answers from training data that stops at its cut-off; search brings current facts.
  • Each agent can run on a different provider's model through its llm: string.
