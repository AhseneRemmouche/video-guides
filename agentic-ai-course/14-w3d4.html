Five kinds of memory (lecture 13, 01:12–04:44)

Memory here means "how you provide information, contextual information to LLMs each time you call them". You could do it yourself, "just by storing variables and then passing them in". CrewAI's version is "more prescriptive": you get up and running quickly, but "there's a learning curve, and it obscures some of the detail of how prompts actually work behind the scenes". The slide lists five kinds:

MemorySlide textStored in
Short-term"Temporarily stores recent interactions and outcomes using RAG, enabling agents to access relevant information during the current executions"Vectors in Chroma, found by RAG
Long-term"Preserves valuable insights and learnings, building knowledge over time"A SQLite database
Entity"Information about people, places and concepts encountered during tasks… Uses RAG for storing entity information"Vectors in Chroma ("very similar to short term memory, actually")
Contextual"Maintains the context of interactions by combining all the above"Nothing of its own: "a bit misleading… just a sort of umbrella term"
User"Stores user-specific information and preferences… (this is up to us to manage and include in prompts)"Whatever you build; not used in the course

The trade-off: "A lot of work happens behind the scenes… the trade off is that you've got less visibility into it. So if things don't go the way you want, then it's a bit harder to debug."

Memory in TypeScript: the idea without the machinery

CrewAI's memory needs Chroma, SQLite and an embedding model. The TypeScript version takes the lecture's point literally: save what the crew concluded, and put it into the prompt next time. One JSON file, no vector search.

// Week 3 Day 4 — memory, the simple way: save what the crew produced, and put it back into the prompt next time.
// CrewAI's memory=True does this with Chroma (vector search) and SQLite; one JSON file is enough to show the idea.
import { mkdir, readFile, writeFile } from "node:fs/promises";
import { dirname } from "node:path";

export type MemoryEntry = { date: string; task: string; output: string };

/** Everything remembered so far (an empty list on the first run). */
export async function recall(file: string): Promise<MemoryEntry[]> {
  try {
    return JSON.parse(await readFile(file, "utf-8")) as MemoryEntry[];
  } catch {
    return [];
  }
}

/** Add new entries and keep the last 20. */
export async function remember(file: string, entries: MemoryEntry[]) {
  const all = [...(await recall(file)), ...entries].slice(-20);
  await mkdir(dirname(file), { recursive: true });
  await writeFile(file, JSON.stringify(all, null, 2), "utf-8");
}

/** Text added to an agent's backstory. CrewAI's memory also ends up as extra text in the prompt. */
export function memoryPrompt(entries: MemoryEntry[], max = 6) {
  if (!entries.length) return "";
  const lines = entries.slice(-max).map((e) => `- ${e.date.slice(0, 10)} ${e.task}: ${e.output.slice(0, 400)}`);
  return `\n\nWhat you remember from previous runs (use it, and do not pick the same companies again):\n${lines.join("\n")}`;
}

The run with memory (lecture 13, 09:24–10:38)

Just crewai run again. A memory/ folder appears with a UUID-named folder (the Chroma index), chroma.sqlite3 and the long-term SQLite file. The finder's answer was Apple ("Major design overhaul in iPhone 15"), Google and Microsoft, followed by two harmless PydanticDeprecatedSince211 warnings from Chroma. The decision: "Chosen Company: Microsoft Corporation (MSFT)". "That definitely took a bit longer. It was going around the houses a little bit, but it completed it. Recommended Microsoft this time. Remember, don't use this for real decisions."

Spot the old news. iPhone 15 and "by the end of 2023" are the model's training data, not fresh search results. The presenter did not comment. When a research crew's facts look dated, check whether the search tool was really used.

The repo ships the author's memories. stock_picker/memory/ is committed (a chroma.sqlite3 of about 2.4 MB, long_term_memory_storage.db and an index folder), and .gitignore does not exclude it. If you run the repo copy, your crew starts with someone else's past picks. Delete the folder for a clean start.

A coder agent (lecture 14)

An agent that can write code, "execute it in a Docker container, and investigate the results". Docker is "a sort of sandboxed, ring fenced environment that doesn't have access to do damage to your computer". In CrewAI it is two parameters. "I had to like close down Docker to make sure that it failed when it was closed because I almost couldn't believe it was happening. It's that simple. And this is where frameworks like crew really stand out."

When people talk about coder agents, "they're not just talking about agents that can deliver code" but agents that "generate Python and then run that Python as steps towards solving a greater problem… more a means to an end". The project: crewai create crew coder (OpenAI, gpt-4o-mini).

coder:
  role: >
    Python Developer
  goal: >
    You write python code to achieve this assignment: {assignment}
    First you plan how the code will work, then you write the code, then you run it and check the output.
  backstory: >
    You're a seasoned python developer with a knack for writing clean, efficient code.
  llm: gpt-4o-mini

/** Run Python in a throw-away Docker container: no network, limited memory, a time limit. */
export function runPythonInDocker(code: string, timeoutSeconds = 30): Promise<string> {
  return new Promise((resolve) => {
    const child = execFile(
      "docker",
      ["run", "--rm", "-i", "--network", "none", "--memory", "256m", "python:3.12-slim", "python", "-"],
      { timeout: timeoutSeconds * 1000, maxBuffer: 1024 * 1024 },
      (err, stdout, stderr) => resolve(err && !stdout ? `Error: ${stderr || err.message}` : stdout + (stderr ? `\n[stderr]\n${stderr}` : "")),
    );
    child.stdin?.end(code);
  });
}

export const codeTool = tool({
  name: "run_python",
  description: "Run Python 3 code in a sandboxed Docker container and return what it prints. Print anything you need to see.",

  execute: async ({ code }) => {
    console.log(`[run_python] ${code.split("\n").length} lines`);
    return runPythonInDocker(code);
  },
});

A test the model cannot fake (lecture 15)

main.py sets the assignment. "Hello world" would be too easy: "it could generate the Python code and then pretend it ran it. So we want something that it can't do any pretending for." Four times the series 1 − 1/3 + 1/5 − 1/7 + … tends to pi, but 10,000 terms give "a bad approximation of pi". A model that only recognised the formula would say 3.14159; a real run gives a number that is wrong after a few decimal places.

The run (lecture 15, 03:19–05:29)

cd coder, crewai run. The trace shows "Agent: Python Developer", then in red "🔧 Failed Code Interpreter (1)", then "Using Code Interpreter (2)": "it's its first try and it's trying again. So it's not like it always works. At least it shows us that something is trying to run in an interpreter." The answer contained the code, with "this idea of take minus one to the power of the index, which is either going to be minus one or plus one. It's a clever trick", and the output 3.1414926535900345: "3.14149, not 3.14159, because it is just an approximation of pi".

The repo's committed output/code_and_output.txt is from another run: it multiplies with total *= 4, puts the result in a comment, and is wrapped in stray code fences. Same number.

Our run: the test caught a fake

This guide ran the coder crew on llama3.2 (local) with Docker running. It took 20 minutes and 25 attempts to use the Code Interpreter. Most failed before any code ran: the model passed libraries_used as the text 'numpy' where the tool requires a list, and later attempts had Python syntax errors. The final answer:

The first 10,000 terms of the series 1 - 1/3 + 1/5 - 1/7 + ... multiplied by 4 is 3.183,
which is the result of the given mathematical series.

No code and a wrong number: the true value is 3.14149. This is exactly what the presenter's test is designed to expose. The model never got its code to run, so it guessed, and the guess is neither pi nor the 10,000-term value. A strong model with working code execution gives 3.1414926535900345, as in the video.

Common mistakes

  • Docker not running: safe mode needs Docker Desktop started. The course's setup notes do not mention it; the only pointer is the comment in crew.py.
  • Windows and Chroma: without Microsoft Build Tools, "CrewAI will fail with an obscure error involving Chroma" (README). Memory is what pulls Chroma in.
  • Memory on every agent: a researcher with memory may reuse old research instead of searching again.
  • Forgetting the instructions: memory only helps if the prompt asks the agent to use it ("don't pick the same company twice").
  • Testing with an easy task: a model can "run" hello world in its head. Use a task with an answer it cannot guess.
  • Giving up after "Failed Code Interpreter (1)": a failed first attempt is normal; the retry limit decides how often it may try again.
Recap
  • CrewAI memory: memory=True on the crew, plus short-term (Chroma), long-term (SQLite) and entity (Chroma) memory objects; memory=True on the agents that should remember.
  • Memory is more text in the prompt; the TypeScript version shows it with a JSON file and a few lines.
  • A coder agent: allow_code_execution=True and code_execution_mode="safe" run the agent's code in Docker; in TypeScript, a run_python tool that calls docker run.
  • max_execution_time and max_retry_limit cap time and retries.
  • Prove a tool really ran with a result the model cannot guess.
