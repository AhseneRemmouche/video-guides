Week 1 Day 3 · Many models, one API and an LLM judge

One question to six providers through two API styles, Ollama locally, and a judge that ranks the answers as JSON.

Course lectures (Udemy) · code verified against the repo

What this day builds

A small contest. One model invents a hard question; the same question goes to six models from six providers (OpenAI, Anthropic, Google, DeepSeek, an open model on Groq, and a local model on Ollama); then a seventh call, the judge, ranks their answers and returns the ranking as JSON. Along the way you learn the two API styles the industry uses, why one client library can talk to almost every provider, and how to ask a model for machine-readable output. In Day 2's terms it is parallelization plus an evaluator.

TypeScript: src/lab2.ts in week1-ts, run with pnpm lab2. It skips any provider whose key you have not set, and in local mode every provider becomes the same Ollama model so the code path still runs.

// Week 1 Day 3 — many models, one question, one judge (TypeScript version of 1_foundations/2_lab2.ipynb)
import Anthropic from "@anthropic-ai/sdk";
import type OpenAI from "openai";
import { z } from "zod";
import { LOCAL, compatibleClient, model, openai } from "./setup.js";

const request =
  "Please come up with a challenging, nuanced question that I can ask a number of LLMs to evaluate their intelligence. " +
  "Answer only with the question, no explanation.";
let response = await openai.chat.completions.create({ model: model("gpt-5-mini"), messages: [{ role: "user", content: request }] });
const question = response.choices[0]!.message.content ?? "";
console.log(question);

const competitors: string[] = [];
const answers: string[] = [];
const messages: OpenAI.ChatCompletionMessageParam[] = [{ role: "user", content: question }];

/** Ask one competitor through an OpenAI-compatible client and record its answer. Missing keys are skipped. */
async function ask(name: string, client: OpenAI, modelName: string) {
  try {
    const r = await client.chat.completions.create({ model: model(modelName), messages });
    competitors.push(LOCAL ? `${modelName} (local stand-in)` : modelName);
    answers.push(r.choices[0]!.message.content ?? "");
    console.log(`--- ${name} answered`);
  } catch (e) {
    console.log(`--- ${name} skipped: ${(e as Error).message.slice(0, 80)}`);
  }
}

await ask("OpenAI", openai, "gpt-5-nano");

// Anthropic has its own SDK (no OpenAI-compatible endpoint): messages.create needs max_tokens
if (process.env.ANTHROPIC_API_KEY && !LOCAL) {
  const claude = new Anthropic();
  const r = await claude.messages.create({ model: "claude-sonnet-4-5", messages: [{ role: "user", content: question }], max_tokens: 1000 });
  const block = r.content[0];
  competitors.push("claude-sonnet-4-5");
  answers.push(block?.type === "text" ? block.text : "");
}

await ask("Gemini", compatibleClient("https://generativelanguage.googleapis.com/v1beta/openai/", process.env.GOOGLE_API_KEY), "gemini-2.5-flash");
await ask("DeepSeek", compatibleClient("https://api.deepseek.com/v1", process.env.DEEPSEEK_API_KEY), "deepseek-chat");
await ask("Groq", compatibleClient("https://api.groq.com/openai/v1", process.env.GROQ_API_KEY), "openai/gpt-oss-120b");
await ask("Ollama", compatibleClient("http://localhost:11434/v1", "ollama"), "llama3.2");

// Put all the answers together, numbered, for the judge
let together = "";
answers.forEach((a, i) => (together += `# Response from competitor ${i + 1}\n\n${a}\n\n`));

const judge = `You are judging a competition between ${competitors.length} competitors.
Each model has been given this question:

${question}

Your job is to evaluate each response for clarity and strength of argument, and rank them in order of best to worst.
Respond with JSON, and only JSON, with the following format:
{"results": ["best competitor number", "second best competitor number", "third best competitor number", ...]}

Here are the responses from each competitor:

${together}

Now respond with the JSON with the ranked order of the competitors, nothing else. Do not include markdown formatting or code blocks.`;

response = await openai.chat.completions.create({ model: model("gpt-5-mini"), messages: [{ role: "user", content: judge }] });
const results = response.choices[0]!.message.content ?? "";
console.log(results);

// Validate the judge's JSON instead of trusting it: small models answer "competitor 2" instead of "2"
const Ranking = z.object({ results: z.array(z.union([z.string(), z.number()])) });
const ranks = Ranking.parse(JSON.parse(results)).results;
ranks.forEach((r, i) => {
  const n = Number(String(r).match(/\d+/)?.[0]);
  console.log(`Rank ${i + 1}: ${competitors[n - 1] ?? `unknown (${r})`}`);
});

Two API styles, one client library (lecture 13)

OpenAI's format and Anthropic's

Every competitor cell has the same ending, competitors.append(model_name) and answers.append(answer), but the call differs. Anthropic's is claude.messages.create(...), it requires max_tokens ("the maximum number of tokens that's allowed to generate before it stops. OpenAI doesn't require that"), and the text is response.content[0].text rather than response.choices[0].message.content.

# Anthropic has a slightly different API, and Max Tokens is required

model_name = "claude-sonnet-4-5"

Why Gemini, DeepSeek and Groq use the OpenAI library (01:09–03:22)

The OpenAI package "isn't like an LLM… This is a lightweight library that just wraps HTTP calls to an endpoint of a particular structure." OpenAI's endpoints became so popular that "a lot of people decided that they would offer endpoints with exactly the same format… pretty much everyone has done that. Everyone, that is, apart from Anthropic." So you create the same client with a different base_url and the other provider's key. DeepSeek "only supports the OpenAI library. They don't have their own." Groq's answer arrives "in just a second or two" thanks to its custom hardware.

The judge (lecture 14)

With six answers collected, a loop joins them into one string labelled "Response from competitor 1", "…2", and so on. zip walks two lists together and enumerate gives an index with each item, "+1 so the first competitor is number one rather than competitor number zero" (01:21).

together = ""
for index, answer in enumerate(answers):
    together += f"# Response from competitor {index+1}\n\n"
    together += answer + "\n\n"
// Put all the answers together, numbered, for the judge
let together = "";
answers.forEach((a, i) => (together += `# Response from competitor ${i + 1}\n\n${a}\n\n`));

Try the video's version: the bug caught by printing (lecture 14 at 02:11). The presenter first typed the line without the f prefix:

together += "# Response from competitor {index+1}\n\n"

Without f the braces are not filled in, so print(together) showed the literal text # Response from competitor {index+1}. "Oh, look at that. There's a mistake. Just as well I did print it." He added the f and reran. The lesson: print intermediate results.

The judge prompt (cell 24) tells the model how many competitors there are, repeats the question, asks it to rank the responses "for clarity and strength of argument", and demands JSON only: {"results": ["best competitor number", …]}. Two Python details (03:23): a triple-quoted f-string spans many lines, and inside an f-string a literal brace is written twice, {{ and }}. The last sentence, "Do not include markdown formatting or code blocks", is there because "these models love to add in a little extra JSON tag around things" (04:40). The judge sees competitor numbers, never model names, which keeps it fair even when it comes from the same family as a competitor (05:08).

judge = f"""You are judging a competition between {len(competitors)} competitors.
Each model has been given this question:

{question}

Your job is to evaluate each response for clarity and strength of argument, and rank them in order of best to worst.
Respond with JSON, and only JSON, with the following format:
{{"results": ["best competitor number", "second best competitor number", "third best competitor number", ...]}}

Here are the responses from each competitor:

{together}

Now respond with the JSON with the ranked order of the competitors, nothing else. Do not include markdown formatting or code blocks."""

Cell 27 sends it (repo: model="gpt-5-mini"; video: o3-mini, "something that really pays attention") and cell 28 turns the JSON into a ranking:

# OK let's turn this into results!

results_dict = json.loads(results)
ranks = results_dict["results"]
for index, result in enumerate(ranks):
    competitor = competitors[int(result)-1]
    print(f"Rank {index+1}: {competitor}")

Our run (no keys except a local Ollama, so three local stand-ins competed: llama3.2, dolphin3:8b, llama3.2) shows why output validation matters. On the first attempt the small judge answered {"results": ["competitor 2", "competitor 1", "N/A"]} and cell 28 crashed with ValueError: invalid literal for int() with base 10: 'competitor 2'. On the rerun it answered {"results": [1, 2, 3]} and the ranking printed. The TypeScript version extracts the digits and validates the shape, so both answers work. Logs: runs/out/W1-lab2.md.

Exercise and the business case (lecture 14, 07:40–09:25)

  • "Which pattern(s) did this use? Try updating this to add another Agentic design pattern." The fan-out to six models is parallelization (code splits and gathers); the judge is an evaluator. Adding a loop where the best answer is improved using the judge's feedback would make it evaluator–optimizer.
  • Make the judging fairer: have each competitor rank the others and average the ranks.
  • Share it: a pull request into community_contributions with the notebook outputs cleared.
  • Why businesses care: sending a task to several models and evaluating the results is "universally applied to business projects where accuracy is critical": summaries, emails, requirement documents, "voting on the best outcome".

Common mistakes

  • NameError on Anthropic or display: the import cell (cell 2) was not run.
  • "Key not set" for a provider: fine; skip that cell. Each provider needs its own key under the exact name.
  • 404 model not found: model names change; check the provider's current list. For Gemini keep the trailing openai/ in the URL.
  • Ollama connection refused: Ollama is not running; open http://localhost:11434, or run ollama serve.
  • Pulling llama3.3: tens of gigabytes; your laptop will grind to a halt. Use llama3.2.
  • json.decoder.JSONDecodeError: the judge wrapped its JSON in a markdown code fence or added words; strengthen the instruction, strip the fence, or use structured outputs (Day 4).
  • Literal {index+1} in the output: missing f before the string, as in the video.
Recap
  • Six providers, two API shapes: OpenAI's chat.completions.create (copied by almost everyone) and Anthropic's messages.create with max_tokens.
  • One client library reaches Gemini, DeepSeek, Groq and Ollama by changing base_url and the key.
  • Ollama runs small open models free on your machine; stay around 3B parameters.
  • An LLM can judge other LLMs if you ask for JSON only and hide the model names.
  • Never trust model output blindly: print it, and validate its shape before you parse it.
