// ---------- 1. Multimodal ----------
// Python: PIL Image -> AGImage -> MultiModalMessage(content=[text, img], source="User")
// Here: download the bytes, turn them into a base64 data URL, and send an input_image part next to an input_text part.
const url = "https://edwarddonner.com/wp-content/uploads/2024/10/from-software-engineer-to-AI-DS.jpeg";

async function imageMessage(text: string) {
  const bytes = Buffer.from(await (await fetch(url)).arrayBuffer());
  const dataUrl = `data:image/jpeg;base64,${bytes.toString("base64")}`;
  return user([
    { type: "input_text", text },
    { type: "input_image", image: dataUrl },
  ]);
}

if (wants("image")) {
  const describer = new Agent({ name: "description_agent", model: MODEL, instructions: "You are good at describing images" });
  const response = await run(describer, [await imageMessage("Describe the content of this image in detail")]);
  console.log(response.finalOutput);
}

Lines 22–29: download the picture, turn it into a base64 data URL, and send it as an input_image part next to an input_text part. That is what AGImage and MultiModalMessage do for you in Python.

The model "got the joke": the only clue that the picture is about AI is the label on the door, and the description noticed it ("possibly symbolizing the power of artificial intelligence (noted by the "AI" label on the door)").

Structured output (lecture 5, 05:00–09:27)

"An old chestnut that you know well." A Pydantic class with described fields, and one new argument on the agent, output_content_type=ImageDescription. Uses he suggests: show it in a UI, catalogue it, store it in a database. orientation is a Literal, so only three values are allowed. And behind the scenes, "it's all just JSON… the model returns JSON and the wrapper code then populates this object from the JSON."

The agent searched, then stopped: "I will now write the details to a file called flights.md." "One of the interesting things about AutoGen is the way that it handles the interactions… agents typically will then stop." So a second message, "OK proceed", goes to the same agent. That works because an AssistantAgent keeps its conversation between on_messages calls. The file listed five fares, and the agent picked Virgin Atlantic at $497, "one of my favorite airlines, but is the most expensive of the options": the prompt said "best", not "cheapest".

There is no adapter in TypeScript, so src/tools.ts writes the search and the seven file tools directly with tool() and zod, keeping the LangChain names. The Agents SDK's run() forgets between calls, so a 26-line wrapper reproduces the one AutoGen behaviour this lab needs: memory between messages.

// A stand-in for AutoGen AgentChat's AssistantAgent, built on the OpenAI Agents SDK. Not a library class: it is these lines.
//
// The one behaviour that matters for the course: an AutoGen AssistantAgent REMEMBERS its conversation between
// on_messages() calls (that is why "OK proceed" works in Lab 2). The SDK's run() is stateless, so this wrapper keeps
// result.history and sends it back next time.
import { run, user, type Agent, type AgentInputItem } from "@openai/agents";

export class AssistantAgent<TOutput = any> {
  history: AgentInputItem[] = [];

  constructor(public readonly agent: Agent<any, any>, private readonly maxTurns = 10) {}

  /** Python: response = await agent.on_messages([message], cancellation_token). Returns the SDK's RunResult. */
  async onMessages(input: string | AgentInputItem[], signal?: AbortSignal) {
    const items = typeof input === "string" ? [user(input)] : input;
    const result = await run(this.agent, [...this.history, ...items], { maxTurns: this.maxTurns, signal });
    this.history = result.history; // remember everything, including tool calls and their results
    return result;
  }

  /** Shortcut for the common case: send text, get the final text (or structured object) back. */
  async reply(text: string, signal?: AbortSignal): Promise<TOutput> {
    const result = await this.onMessages(text, signal);
    return result.finalOutput as TOutput;
  }
}

A team: primary and evaluator (lecture 6, 06:15–13:36)

Two AssistantAgents. "Any guesses what pattern I might be about to work with here?" The evaluator-optimizer from Week 1. RoundRobinGroupChat means "one after the other… the simplest way that you could have some kind of relationship between them"; "a bit like a crew… but… somewhat simpler". The chat ends when a message contains "APPROVE" (TextMentionTermination): "a little bit brittle… You would probably want to… have structured outputs here and use that to test." A team is run with await team.run(task=prompt), which returns all the messages.

    name: "primary",

    model: MODEL,

  const MAX_TURNS = 20; // "otherwise this can get into a loop.." (the fix for the runaway run in the video)
  const team = [primaryAgent, evaluationAgent];
  const messages: { source: string; content: string }[] = [{ source: "user", content: prompt }];

  // Every agent sees the whole conversation: its own messages as "assistant", everyone else's as "user"
  const viewFor = (name: string): AgentInputItem[] =>
    messages.map((m) => (m.source === name ? assistant(m.content) : user(`${m.source}: ${m.content}`)));

  for (let turn = 0; turn < MAX_TURNS; turn++) {
    const speaker = team[turn % team.length]; // round robin: one after the other
    const result = await run(speaker, viewFor(speaker.name));
    const content = String(result.finalOutput ?? "");
    messages.push({ source: speaker.name, content });
    if (content.includes("APPROVE")) break; // TextMentionTermination("APPROVE")
  }
  for (const m of messages) console.log(`${m.source}:\n${m.content}\n\n`);
}
result = await team.run(task=prompt)
for message in result.messages:
    print(f"{message.source}:\n{message.content}\n\n")

The runaway loop. His first version used longer prompts that asked for "another different option" each time, and no turn limit. It "was running for more than a minute, like going backwards and forwards", so he interrupted it and restarted the kernel. "You don't want to spend all of your tokens." A first look at MCP (lecture 7)

"MCP is a topic for next week… all the rage." It is "a nice, simple, elegant way that we can package up tools so that different models can use those tools… not an abstraction layer. It's not particularly code. It's just an agreement." Here AutoGen launches someone else's server, mcp-server-fetch, asks it for its tools, and hands them to an agent. "We've just used a tool that someone else has written… because that tool uses this open standard… We're able to just drop that tool in."

from autogen_agentchat.agents import AssistantAgent
from autogen_ext.models.openai import OpenAIChatCompletionClient
from autogen_ext.tools.mcp import StdioServerParams, mcp_server_tools

# Get the fetch tool from mcp-server-fetch.
fetch_mcp_server = StdioServerParams(command="uvx", args=["mcp-server-fetch"], read_timeout_seconds=30)
fetcher = await mcp_server_tools(fetch_mcp_server)

# Create an agent that can use the fetch tool.
model_client = OpenAIChatCompletionClient(model="gpt-4o-mini")
agent = AssistantAgent(name="fetcher", model_client=model_client, tools=fetcher, reflect_on_tool_use=True)  # type: ignore

# Let the agent fetch the content of a URL and summarize it.
result = await agent.run(task="Review edwarddonner.com and summarize what you learn. Reply in Markdown.")
display(Markdown(result.messages[-1].content))
// ---------- 5. MCP teaser ----------
// Python: mcp_server_tools(StdioServerParams(command="uvx", args=["mcp-server-fetch"], read_timeout_seconds=30))
// The SDK launches the same server as a child process and talks MCP to it over stdin/stdout.
// Note: mcp-server-fetch downloads a page over HTTP and converts it to Markdown; it does not drive a browser.
if (wants("mcp")) {
  const fetchMcpServer = new MCPServerStdio({ name: "fetch", command: "uvx", args: ["mcp-server-fetch"], clientSessionTimeoutSeconds: 30 });
  await fetchMcpServer.connect();
  try {
    const agent = new Agent({ name: "fetcher", model: MODEL, mcpServers: [fetchMcpServer] });
    const result = await run(agent, "Review edwarddonner.com and summarize what you learn. Reply in Markdown.");
    console.log(result.finalOutput);
  } finally {
    await fetchMcpServer.close();
  }
}

Common mistakes

  • A team without max_turns: two agents can talk forever on your tokens. Interrupt the kernel if it runs long.
  • Expecting the agent to finish in one go: AgentChat agents often stop and wait; send a follow-up to the same agent.
  • "Best" when you mean "cheapest": the model does exactly what the prompt says.
  • Termination by text: an evaluator that writes "I don't APPROVE yet" ends the chat. Structured output is safer.
  • MCP on Windows: stdio servers may fail natively; use WSL as the repo advises.
  • Missing sandbox folder: the file tools write into it; create it first.
Recap
  • MultiModalMessage sends text and an image together; in TypeScript, an input_image part.
  • output_content_type (or outputType) turns the reply into a typed object.
  • LangChainToolAdapter lets AutoGen use any LangChain tool.
