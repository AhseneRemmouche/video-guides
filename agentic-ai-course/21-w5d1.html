Which AutoGen? (lecture 1)

In January 2025 Microsoft released AutoGen 0.4, "a from-the-ground rewrite, adopting an asynchronous, event-driven architecture": "a straight-up replacement for AutoGen 0.2 with a very different kind of feel". The video uses 0.5.1 ("0.5.1 isn't very different to 0.4"); the repo's lock file installs 0.7.5, with the same API for everything the labs use. When you read documentation, check whether it is for 0.4+ or 0.2, "which looks and feels quite different".

Then the drama. In late 2024 several original developers left Microsoft and forked AutoGen 0.2 as AG2. The slide's punchline: "If you pip install autogen, you get AG2!" The course installs Microsoft's packages through uv, so uv sync already did the right thing.

The stack and the building blocks (lecture 2)

  • AutoGen Core: "a fabric for agents to run within… an agent runtime", agnostic to what each agent does inside.
  • AgentChat: the lightweight, simple layer on top, the direct comparison with CrewAI and the OpenAI Agents SDK.
  • Studio, a low-code visual tool ("not ready for production, and they state that very clearly"), and Magentic-One, a ready-made console assistant.

Unlike CrewAI or LangChain, where "monetisation… was driving some of their product roadmap", this is "a Microsoft Research for the community kind of thing". The week focuses on AgentChat, plus some Core "to give you some interest in it". The core concepts: models (the LLMs), messages (new as a first-class idea: between agents, from the user, and "events that happen within an agent's interactions" such as tool calls), agents, and teams, "a crew from Crew", which come on Day 2.

AssistantAgent is "the most fundamental class": a name, a model client, a system_message ("rather like the instructions in OpenAI") and optional streaming. You send it a list of messages with on_messages and await the response. The CancellationToken is "a sort of fiddly thing about AgentChat, but I wouldn't worry about it"; it is the handle through which a running call could be cancelled.

A tool from a SQLite database (lecture 3, 04:07–09:36)

A tickets.db with one table of round-trip prices. There are fancier approaches (an agent that writes its own SQL), "but this is just a toy example"; "for security-conscious people, there's perhaps more things I should do to validate".

# Method to get price for a city
def get_city_price(city_name: str) -> float | None:
    """ Get the roundtrip ticket price to travel to the city """
    conn = sqlite3.connect("tickets.db")
    c = conn.cursor()
    c.execute("SELECT round_trip_price FROM cities WHERE city_name = ?", (city_name.lower(),))
    result = c.fetchone()
    conn.close()
    return result[0] if result else None
// ---------- A SQLite database of ticket prices ----------
const DB = "tickets.db";
if (existsSync(DB)) rmSync(DB);
const conn = new DatabaseSync(DB);
conn.exec("CREATE TABLE cities (city_name TEXT PRIMARY KEY, round_trip_price REAL)");
conn.close();

function saveCityPrice(cityName: string, roundTripPrice: number) {
  const db = new DatabaseSync(DB);
  db.prepare("REPLACE INTO cities (city_name, round_trip_price) VALUES (?, ?)").run(cityName.toLowerCase(), roundTripPrice);
  db.close();
}

/** Get the roundtrip ticket price to travel to the city (same body as the Python get_city_price) */
function getCityPrice(cityName: string): number | null {
  const db = new DatabaseSync(DB);
  const row = db.prepare("SELECT round_trip_price FROM cities WHERE city_name = ?").get(cityName.toLowerCase()) as
    | { round_trip_price: number }
    | undefined;
  db.close();
  return row ? row.round_trip_price : null;
}

Now the nicest part, in the presenter's view "a tiny way in which AutoGen maybe is a little bit… superior": no decorator and no wrapper. You pass the plain function, and AutoGen "uses this comment [the docstring] to figure out the description of the tool"; the type hints give the parameters. reflect_on_tool_use=True makes the agent call the model again after the tool to write an answer: "it's rare that you wouldn't want that to be true."

from autogen_agentchat.agents import AssistantAgent

smart_agent = AssistantAgent(
    name="smart_airline_agent",
    model_client=model_client,
    system_message="You are a helpful assistant for an airline. You give short, humorous answers, including the price of a roundtrip ticket.",
    model_client_stream=True,
    tools=[get_city_price],
    reflect_on_tool_use=True
)
// ---------- The tool ----------
// AutoGen reads the docstring and type hints of a plain function. TypeScript types vanish at run time,
// so the description and the parameter schema are written out explicitly.
const getCityPriceTool = tool({
  name: "get_city_price",
  description: "Get the roundtrip ticket price to travel to the city",
  parameters: z.object({ city_name: z.string() }),
  execute: async ({ city_name }) => String(getCityPrice(city_name)),
});

// reflect_on_tool_use=True in AutoGen = "call the model again after the tool to write the answer".
// That is the Agents SDK default (toolUseBehavior: "run_llm_again"), so nothing extra is needed.
const smartAgent = new Agent({
  name: "smart_airline_agent",
  model: modelClient,
  instructions: "You are a helpful assistant for an airline. You give short, humorous answers, including the price of a roundtrip ticket.",
  tools: [getCityPriceTool],
});

const smartResponse = await run(smartAgent, [message]);
// Python prints response.inner_messages (FunctionCall, FunctionExecutionResult). The SDK calls them newItems.
for (const item of smartResponse.newItems) {
  if (item.type === "tool_call_item") console.log("[FunctionCall]", JSON.stringify(item.rawItem));
  if (item.type === "tool_call_output_item") console.log("[FunctionExecutionResult]", JSON.stringify(item.output));
}
console.log(smartResponse.finalOutput);
response = await smart_agent.on_messages([message], cancellation_token=CancellationToken())
for inner_message in response.inner_messages:
    print(inner_message.content)
response.chat_message.content

Common mistakes

  • pip install autogen: that is AG2. Use the course's uv sync, or install autogen-agentchat and autogen-ext[openai].
  • Reading 0.2 documentation: examples with UserProxyAgent and initiate_chat are the old API.
  • Wrong import package: model clients are in autogen_ext, agents and messages in autogen_agentchat, CancellationToken in autogen_core.
  • A tool without a docstring: AutoGen uses it as the description; without it the model has little to go on.
  • Forgetting await: on_messages is a coroutine.
Recap
  • Microsoft's AutoGen 0.4+ is three packages; autogen on PyPI is the AG2 fork.
  • Core is the runtime; AgentChat is the agent API on top.
  • Model client, TextMessage, AssistantAgent, await on_messages(...).
  • A plain function with a docstring is a tool; keep reflect_on_tool_use=True.
  • In TypeScript the same lab is an Agents SDK Agent, run() and a zod-described tool().
