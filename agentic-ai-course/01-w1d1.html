What this day is about

Day 1 is the longest day of the course (about 91 minutes) because it does three jobs. It shows what an AI agent looks like with a no-code demo. It tours the six weeks. And it installs everything you need: Git, the Cursor editor, the uv package manager and an OpenAI API key. Then, in the last 17 minutes, you write your first "agentic" program: one LLM call invents a hard question and a second call answers it.

The TypeScript project for Week 1 is week1-ts/ next to this guide. It needs Node.js and pnpm instead of Python and uv; the setup section below gives both paths. Its first lab is src/lab1.ts, run with pnpm lab1.

The demo: an agent that chooses (lecture 1)

The presenter opens n8n, a low-code workflow tool with generative AI built in, and wires three things together: a chat trigger, an "AI Agent" node backed by an OpenAI chat model, and one tool, a Philips Hue light, whose brightness and colour the AI may choose (04:26). "Tools are one of the most fundamental building blocks of agentic AI." Asking "please turn the lights on bright white" works, but "it's not really showing me autonomy" (05:17). So he asks it to "pick a color, either deep red or deep blue" and it picks red: "you just saw it making its own decision." This is the last no-code tool of the course: "for the next six weeks we're going to be rolling up our sleeves and coding agents" (06:29).

The six weeks (lecture 2)

Each week has five days, "I give you Saturday and Sunday off". Week 1 uses no framework at all, "just LLMs interacting natively". Then one framework per week: the OpenAI Agents SDK ("so simple and elegant and flexible"), CrewAI ("the fan favourite… low code"), LangGraph ("very sophisticated, quite complex, very powerful"), Microsoft AutoGen, and in Week 6 Anthropic's Model Context Protocol plus the capstone. Eight projects run across the weeks: your career alter ego (this week), a sales development rep, deep research, a stock picker, an engineering team of agents, "Sidekick" (an agent that drives a browser on your machine), an agent that creates agents, and a trading floor of autonomous traders ("this should not be used for any real investment decisions"). Every project has two goals: "highly educational" and "commercial".

Tools, costs and attitude (lecture 3)

Cursor is "the AI platform that's powered by LLMs… built on VS Code"; VS Code itself works just as well. uv "is replacing Anaconda… really fast and really simple and it just works… written in Rust", and most agent frameworks "already have uv at their core" (03:40–04:30). On cost, the presenter's whole course spend was "well under $5". OpenAI requires a $5 minimum top-up. DeepSeek is much cheaper, Gemini has a free tier, and Ollama runs models free on your own machine, though "if you use the quick models like llama 3.2, then it might have troubles being coherent". His three things to keep in mind (08:20): use the resources (the repo's guides and setup folders are "a living, breathing resource"), stay patient because roadblocks are "a great learning opportunity", and contact him.

Setup, step by step (lectures 4 and 5)

Both lectures follow the same five parts of the repo's setup/SETUP-PC.md and setup/SETUP-mac.md. Read the one for your system; it is kept more up to date than the videos.

  1. Get the code with Git. Check Git with git --version (Windows: install from git-scm.com; Mac: xcode-select --install). Then, in your home folder: 
    mkdir projects
cd projects
git clone https://github.com/ed-donner/agents.git
cd agents
    The folder agents is what the course calls the project root directory. Windows people: watch for the 260-character path limit and for antivirus software interfering, the two "gotchas" of lecture 4 (01:39).
  2. Install Cursor from cursor.com (free account), then File ▸ Open Folder ▸ agents. The explorer shows 1_foundations … 6_mcp, guides, setup, pyproject.toml and uv.lock. Install the Python and Jupyter extensions (by Microsoft) if Cursor does not offer them.
  3. Install uv with the one-line installer from docs.astral.sh/uv, then close and reopen your terminal and Cursor so the new PATH is picked up. In Cursor's terminal (View ▸ Terminal) at the project root: 
    uv --version
uv sync
    uv sync downloads Python 3.12 and every package locked in uv.lock into a .venv folder: about three minutes in the video, where Anaconda used to take "up to an hour". From now on, run scripts with uv run script.py instead of python script.py.
  4. Create an OpenAI key. At platform.openai.com: Settings ▸ Billing ▸ add the $5 minimum (the setup document recommends switching automatic recharge off), then API keys ▸ "Create new secret key". The key starts with sk-proj-. Copy it straight to the clipboard; pasting it through a word processor can turn hyphens into long dashes and break it (lecture 4, 16:10).
  5. Create the .env file at the project root, named exactly .env, with one line and no quotes or spaces: 
    OPENAI_API_KEY=sk-proj-...
    Save it. Typos in this file are "like 90% of the reason that people are frustrated in environment setup" (lecture 5, 18:28): OPEN_API_KEY, OPENAI_KEY and a doubled sk-proj-sk-proj- are the classics. Cursor shows a stop sign next to .env, which is good: it will not send your secrets to its AI.

The TypeScript setup

  1. Install Node.js 22 or newer from nodejs.org (this guide used Node 24), then pnpm: npm install -g pnpm.
  2. Install the project: in a terminal inside week1-ts, run pnpm install. It reads package.json and installs openai, @anthropic-ai/sdk, zod, dotenv, hono, unpdf, React and Vite into node_modules, the way uv sync fills .venv.
  3. Copy .env.example to .env and paste your key after OPENAI_API_KEY=. The same file can hold the other providers' keys used on Day 3.

Load the key and check it

Two cells import and call load_dotenv(override=True); it should print True. Why override=True (06:37): without it, a key you once set globally on your computer would win over the .env file, "and you wouldn't be able to figure out why on earth OpenAI is rejecting your key".

# Check the key - if you're not using OpenAI, check whichever key you're using! Ollama doesn't need a key.

import os
openai_api_key = os.getenv('OPENAI_API_KEY')

if openai_api_key:
    print(f"OpenAI API Key exists and begins {openai_api_key[:8]}")
else:
    print("OpenAI API Key not set - please head to the troubleshooting guide in the setup folder")
    
// Shared setup: environment variables, the OpenAI client, model names and an optional local-model mode.
//
// Default (like the course): OPENAI_API_KEY in .env.
// Local mode (no OpenAI key): OPENAI_BASE_URL=http://localhost:11434/v1 OPENAI_API_KEY=ollama MODEL=llama3.2
// Every model name used by the labs is then replaced by MODEL, and every provider points at the same Ollama server.
import "dotenv/config";
import OpenAI from "openai";

export const LOCAL = Boolean(process.env.OPENAI_BASE_URL);

/** The model to use: the course's model name, or MODEL in local mode. */
export function model(courseModel: string): string {
  return LOCAL ? (process.env.MODEL ?? "llama3.2") : courseModel;
}

/** An OpenAI client. new OpenAI() reads OPENAI_API_KEY and OPENAI_BASE_URL from the environment. */
export const openai = new OpenAI();

/** A client for another provider's OpenAI-compatible endpoint (in local mode: the same Ollama server). */
export function compatibleClient(baseURL: string, apiKey: string | undefined): OpenAI {
  return LOCAL ? new OpenAI({ baseURL: process.env.OPENAI_BASE_URL, apiKey: "ollama" }) : new OpenAI({ baseURL, apiKey });
}

The client and the messages format

from openai import OpenAI then openai = OpenAI(). The presenter's two clarifications (08:46–09:34): the variable name is just short for "the OpenAI Python client", and creating it does not put a model on your computer: "OpenAI is a lightweight library for connecting to OpenAI's endpoints on the cloud… a client library." A conversation is a list of dictionaries, each with a role and content, "this format that OpenAI invented and has become ubiquitous everywhere".

Two calls in a row

The first real call asks "What is 2+2?" (in the video Cursor's autocomplete wrote most of it; the answer was "2 + 2 equals 4."). Then "it's time for us to be a little bit agentic" (11:41): one call asks for "a hard, challenging question to assess someone's IQ", its output becomes the next call's input, and the second call answers it. "It's more a workflow than an agentic AI, but still it's getting there… we are orchestrating multiple calls to LLMs to solve a bigger problem."

// Week 1 Day 1 — your first agentic workflow (TypeScript version of 1_foundations/1_lab1.ipynb)
// Two calls in a row: the first LLM writes a hard question, the second LLM answers it.
import type OpenAI from "openai";
import { model, openai } from "./setup.js";

// Check the key, like the notebook's cell that prints the first 8 characters
const key = process.env.OPENAI_API_KEY;
console.log(key ? `OpenAI API Key exists and begins ${key.slice(0, 8)}` : "OpenAI API Key not set");

// A list of messages in the familiar OpenAI format: role + content
let messages: OpenAI.ChatCompletionMessageParam[] = [{ role: "user", content: "What is 2+2?" }];

// And now call it
let response = await openai.chat.completions.create({ model: model("gpt-4.1-nano"), messages });
console.log(response.choices[0]!.message.content);

// Ask for a question...
const request = "Please propose a hard, challenging question to assess someone's IQ. Respond only with the question.";
messages = [{ role: "user", content: request }];
response = await openai.chat.completions.create({ model: model("gpt-4.1-mini"), messages });
const question = response.choices[0]!.message.content ?? "";
console.log(question);

// ...then ask it again: the second call answers the first call's output
messages = [{ role: "user", content: question }];
response = await openai.chat.completions.create({ model: model("gpt-4.1-mini"), messages });
const answer = response.choices[0]!.message.content ?? "";
console.log(answer);

The cells before it set question = "Please propose a hard, challenging question to assess someone's IQ. Respond only with the question." and messages = [{"role": "user", "content": question}].

The exercise (lecture 6, 15:26) and the wrap-up (lecture 7)

"Now try this commercial application": three chained calls. First ask the LLM to pick a business area worth exploring for an agentic AI opportunity; then ask it for a pain point in that industry; then ask a third call to propose the agentic solution. The notebook leaves a skeleton (response =, business_idea = response.) for you to complete. Lecture 7 points out that letting the LLM choose the sector "also gave our LLM some autonomy… a baby step towards allowing the LLM to plot its own path, to choose its own adventure, which is one of the hallmarks of an agentic AI solution".

def ask(prompt):
    response = openai.chat.completions.create(model="gpt-4.1-mini", messages=[{"role": "user", "content": prompt}])
    return response.choices[0].message.content

sector = ask("Pick a business area that might be worth exploring for an Agentic AI opportunity. Reply with the area only.")
pain = ask(f"In the business area '{sector}', describe one pain point that might be ripe for an Agentic AI solution.")
solution = ask(f"Propose an Agentic AI solution to this pain point: {pain}")
display(Markdown(solution))

Common mistakes

  • load_dotenv prints False: the file is not saved, not named exactly .env, or not in the project root.
  • Key rejected although it looks right: an old global OPENAI_API_KEY wins; use override=True (Python) or remove the global one. Or the key was pasted through a word processor.
  • ImportError on from openai import OpenAI: wrong kernel; select the .venv one, or rerun uv sync.
  • NameError: you ran a cell before the cell that defines the name. Run from the top (the repo's guide 6 explains this error).
  • uv not recognised: open a new terminal (and restart Cursor) after installing it.
  • Cursor's autocomplete is wrong: it suggested question where answer was meant. Read what you accept.
  • 401 Incorrect API key in TypeScript: .env is not in week1-ts/, or you ran the script from another folder. Run pnpm lab1 inside the project folder.
Recap
  • An agent uses an LLM plus tools, and makes some decisions itself; the n8n demo showed both.
  • Setup is five steps: clone, Cursor, uv sync, API key, .env with OPENAI_API_KEY=.
  • load_dotenv(override=True) loads the key; OpenAI() is a thin client for the cloud API.
  • A call is chat.completions.create(model=…, messages=[{"role", "content"}]); the text is choices[0].message.content.
  • Feeding one call's output into the next is your first workflow; letting the model choose the topic is a first taste of autonomy.
