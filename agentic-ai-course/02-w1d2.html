Definitions (lecture 8)

"Agentic AI is one of these things that's been super hyped… people are using the term to mean a lot of different things" (00:27). The presenter's favourite crisp definition comes from Hugging Face's smolagents project:

"AI Agents are programs where LLM outputs control the workflow."

His gloss: "one output from an LLM is able to decide what tasks are carried out in what sequence."

In practice people call a solution agentic when it has any or all of five hallmarks (01:25–03:16):

  1. Multiple LLM calls, "a bit like the one that we just built in day one".
  2. LLMs with the ability to use tools, "often what people think of as the litmus test for whether something is agentic", like the n8n light.
  3. An environment where LLMs interact, a coordination layer that lets different models pass information to each other.
  4. A planner that coordinates activities, itself an LLM.
  5. Autonomy: "giving some ability to an LLM to control what order things happen in… to choose its own adventure."

About that last word: "what does it mean to have an LLM, a statistical language model, that is autonomous?… it's just sort of fancy use of language in many ways" (03:40). Even Day 1's exercise, where the model picked the business sector, "had a level of autonomy".

Workflows and agents (lecture 8, 04:27)

The second reference the course keeps returning to is Anthropic's post Building Effective Agents. It calls the whole family agentic systems and splits them in two:

Definition (from the slide)In this course
Workflows"Systems where LLMs and tools are orchestrated through predefined code paths."Day 1's two calls; Day 3's model comparison; the Week 2 deep-research pipeline.
Agents"Systems where LLMs dynamically direct their own processes and tool usage, maintaining control over how they accomplish tasks."The Week 1 chatbot that decides when to call its tools; the Week 2 Sales Manager.

The presenter's caution: Anthropic seems to hint "that perhaps the things that a lot of people call agents are in fact workflows… does that mean that workflows are agentic or not? I guess they are. But you can see there's some ambiguity."

Five workflow design patterns (lecture 9)

The slides draw each pattern with yellow boxes for LLM calls and blue boxes for "some code that you've written" (00:21). The diagrams below keep that distinction: filled boxes are LLM calls, outlined boxes are your code.

1 · Prompt chaining (00:00)

"Decompose into fixed sub-tasks": IN → LLM 1 → a gate (code that checks the output) → LLM 2 → LLM 3 → OUT. "Really similar to that commercial question… pick a sector, then a pain point, then a solution." The benefit is precision: "you can take care to frame each LLM call very precisely." The caveat: a chain can still give the LLM discretion, so "the way Anthropic distinguishes between workflows and agents is a little bit artificial. There is definitely a blurred line" (01:44).

2 · Routing (02:09)

"Direct an input into a specialized sub-task, ensuring separation of concerns": an LLM router classifies the input and sends it to one of several specialist LLMs. "The router's job is to classify the task, understand which of the specialists will be best equipped."

3 · Parallelization (03:36)

"Breaking down tasks and running multiple subtasks concurrently": code splits the work, several LLMs run at the same time, code aggregates the results. "It's code… that's deciding what to do." The parallel tasks may even be the same task three times, with the aggregator taking "the average or something like that."

4 · Orchestrator–worker (04:49)

"Complex tasks are broken down dynamically and combined": the same shape as parallelization, "except it's no longer code that's doing the orchestration. It's an LLM", and an LLM synthesises the results. "Saying that this is just a fixed workflow is perhaps a stretch."

5 · Evaluator–optimizer (06:31)

"LLM output is validated by another": a generator LLM produces a solution, an evaluator LLM accepts it or rejects it with feedback, and a rejection loops back to the generator. "The one that I use most commonly… I tend to call them just evaluators or validation agents." Its value is "accuracy, predictability, robustness… there's never full guarantees with LLMs, but build a higher level of guarantee." Day 4 builds exactly this.

Parallelization or orchestrator–worker? Spot the one difference

Both fan a task out to several LLMs and combine the results. In parallelization the splitting and the combining are ordinary code that you wrote, so the structure is fixed. In orchestrator–worker an LLM decides how to split the task (perhaps into a different number of pieces each time) and an LLM writes the combined answer. Week 2's deep-research app sits between the two: an LLM planner decides the searches, but plain Python runs them in parallel and passes them to the writer.

Agents, and why they are risky (lecture 10)

By contrast, agents are open-ended, run in feedback loops, and have no fixed path. The slide shows a human giving a task to an LLM call, which takes an action on an environment ("some sort of outside world… such as the lights") and gets feedback, again and again, until the LLM decides to stop. "There aren't more specific design patterns because it is in itself this sort of open-ended design pattern… the LLM gets to choose its own design for how it's going to solve the problem." That freedom is the power, and the problem: "not knowing how long it will take… whether it will complete its task at all… what kind of quality outputs we will get, and not knowing how much it will cost" (02:35).

The "Risks of Agent Frameworks" slide (03:29–05:42) lists three unpredictables, path, output and cost, and two mitigations. Monitor: see what the models did, with OpenAI's traces in Week 2 and LangSmith with LangGraph in Week 4. Guardrails, in a quote taken from the OpenAI Agents SDK: "Guardrails ensure your agents behave safely, consistently, and within your intended boundaries." "We will be building those guardrails ourselves in week two."

Common misconceptions

  • "An agent is a special kind of model." No: it is a program built around ordinary LLM calls. The model only produces text (or tool-call requests); your code runs the loop.
  • "Workflows are not agentic." Anthropic includes both under agentic systems; the boundary is blurry, as the presenter keeps pointing out.
  • "More autonomy is always better." Every freedom adds unpredictability in path, output and cost. Use the simplest pattern that solves the problem.
  • "Autonomy means the model thinks for itself." It means the model's output decides what your code does next. It is "fancy use of language" for that.
Recap
  • Definition: "AI agents are programs where LLM outputs control the workflow."
  • Five hallmarks: multiple calls, tools, an environment, a planner, autonomy.
  • Anthropic: workflows follow code paths you wrote; agents direct their own process. Both are agentic systems.
  • Five patterns: prompt chaining, routing, parallelization, orchestrator–worker, evaluator–optimizer.
  • Agents are open-ended feedback loops; their path, output and cost are unpredictable, so monitor them and add guardrails.
