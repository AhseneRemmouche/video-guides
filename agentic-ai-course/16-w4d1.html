The LangChain family (lecture 1)

One company, LangChain, ships three products.

  • LangChain is "where it began": one of the earliest abstraction libraries, first so you could swap GPT for Claude without rewriting code, then for chaining calls, RAG, prompt templates and memory. It "predates the recent explosion with agents"; it is "more of their glue code".
  • LangGraph is "a separate offering… it actually is independent from LangChain". You may use LangChain inside a graph, but "you can really use any framework or you can just call LLMs directly". Its focus is "stability, resiliency and repeatability" for workflows with many interconnected steps: feedback loops, a human in the loop, memory, and time travel.
  • LangSmith is the monitoring product. LangGraph "gives the ability to monitor, but it doesn't actually do the monitoring itself". The course uses LangSmith on Day 3.

The presenter's "love-hate relationship" with LangChain: a RAG pipeline in "like four lines of code", but "you're signing up for their way of doing things, and you have a bit less visibility into the actual prompts going on behind the scenes." LLM APIs have converged on OpenAI's shape, and "memory is really just the JSON blob of the conversations", so there is "less need to sign up for a big ecosystem". "But again there are pros and cons."

Framework, Studio and Platform (lecture 2)

LangGraph itself is three things: the framework you code with, LangGraph Studio (a visual builder), and LangGraph Platform (hosted deployment). The Platform is promoted so heavily on the website, in the presenter's view, because it is "the core commercial idea".

Then a counterpoint, read from Anthropic's post "Building effective agents": frameworks "often create extra layers of abstraction that can obscure the underlying prompts and responses, making them harder to debug… We suggest that developers start by using LLM APIs directly… If you do use a framework, ensure you understand the underlying code." "By customer they mean us." It is "a different school of thought… not in sync with the LangGraph philosophy". Week 6 shows Anthropic's alternative: MCP, "a protocol for connecting things rather than building the actual glue itself".

Four words (lecture 3)

"There's going to be terminology… put all the Crew stuff to one side, compartmentalize."

TermIn the presenter's words
GraphAgent workflows are represented as graphs: "think of like a tree structure", things connected in a hierarchy.
State"Represents the current snapshot… the status of your whole application… shared across the whole application. It's not a function. It's information."
Node"Every node is a Python function." It receives the state, does something (an LLM call, writing a file) and returns an updated state. Treat the state as immutable: "you receive a state and then you return a new state."
Edge"Python functions that determine what node should be executed next based on the state." A simple edge always leads to the next node; a conditional edge chooses.

The mantra. "Nodes do the work. Edges choose what to do next."

Five steps, two phases (lecture 3, 05:53–09:52)

Tomorrow's recipe, from the slide "Five steps to the first Graph":

  1. Define the State class (with a reducer, explained tomorrow).
  2. Start the Graph Builder.
  3. Create a Node.
  4. Create Edges. Steps 3 and 4 repeat as often as needed.
  5. Compile the Graph.

And the point he makes three times, with an apology: running a LangGraph program has two phases. First your code lays out the graph, "like writing a program, but we're sort of doing it dynamically at runtime". Then you invoke it and the graph runs. "Both of them are part of running your application."

Common mistakes

  • Mixing up LangChain and LangGraph: LangGraph does not require LangChain; the course uses LangChain only for convenience (the chat model class and ready-made tools).
  • Thinking a node is "an agent": a node is just a function. It may call an LLM, or not.
  • Thinking edges are lines on a diagram only: conditional edges are code that reads the state and picks the next node.
  • Bringing CrewAI's words along: there are no agents, tasks or crews here, only state, nodes and edges.
Recap
  • LangChain (glue), LangGraph (graph workflows: framework, Studio, Platform) and LangSmith (monitoring) come from one company.
  • State is the shared snapshot; nodes are functions that do the work; edges choose what runs next.
  • Five steps: State class, graph builder, nodes, edges, compile. Then invoke.
  • Anthropic recommends plain API calls first; LangGraph bets on structure. Know the trade-off.
