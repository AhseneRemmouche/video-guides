Your First Agent

create_agent, HumanMessage, the messages dictionary, and reading the last AIMessage.

▶ Watch this part (23:14)

Goal

In step 4 you talked to a chat model directly: you gave it one string and got one answer back. In this step you wrap that same model in an agent with create_agent, send it a proper human message, and read its reply out of the list of messages it returns.

It is only a few new lines, and the answer ("Rome") is the same as before. So why bother? Because everything the rest of the course builds needs an agent: conversation history (step 6), streaming (step 7), tools (steps 8 and 9), memory (step 10) and, in the end, the personal chef project. Today's agent has no tools yet, but the shape of the code you write here stays the same all the way to the chef.

Model vs agent: what changes

The presenter explains it at 23:38–26:20: the agent is based on the model ("an agent needs a model"), but it is smarter about the conversation. It wants to know who is talking (a human? the AI?) and it "can actually contain multiple tools". So instead of a plain string, you give the agent a dictionary with a list of messages, and you get back a dictionary with the updated list.

New to agents? What makes an agent different from a model

A large language model on its own is a text predictor: you send it text, it sends text back, done. It cannot look anything up, run code or remember you.

An agent is a small program wrapped around the model. It runs the agent loop: send the conversation to the model; if the model asks to use a tool, run that tool and send the result back; repeat until the model gives a final answer. With no tools (like today), the loop runs exactly once, so the result looks just like a plain model call.

create_agent builds that loop for you. Under the hood it is a LangGraph graph (a CompiledStateGraph), which is why you call .invoke on it just like on a model. The page How an Agent Thinks walks through the loop message by message.

New to messages? Why the agent wants to know who is talking

Chat models don't really receive "a question". They receive a conversation: a list of messages, each tagged with a role. LangChain has one class per role:

  • HumanMessage: something the user said (a human message).
  • AIMessage: something the model said (an AI message). You'll write one yourself in step 6.
  • SystemMessage: instructions for the model (a system message). In step 8 you'll set one with system_prompt.
  • ToolMessage: the result of a tool (a tool message), also in step 8.

Each message has a content (the text). When you called model.invoke("tell me story") in step 4, LangChain quietly turned your string into a HumanMessage for you. With an agent, you write it out explicitly.

The complete file

Code transcribed from the video (frames at 25:30), run against the repo's locked versions (langchain 1.3.12).

from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain.agents import create_agent
from langchain.messages import HumanMessage

load_dotenv()

# 0 to 1 from least creative to most creative
model = init_chat_model(model="gpt-5-nano",
                        temperature=1.0)

agent = create_agent(model=model)

response = agent.invoke(
    {"messages": [HumanMessage(content="what is the capital of italy?")]}
)

print(response["messages"][-1].content)

New to dictionaries and lists? The two containers this file uses

A list is an ordered row of items in square brackets: ["a", "b", "c"]. You read an item by its position, starting at 0: items[0] is "a".

A dictionary (dict) stores values under names, called keys, in curly braces: {"messages": [...]}. You read a value by its key: response["messages"].

They nest freely. The agent's input and output are both "a dictionary with one key, messages, whose value is a list of message objects". So response["messages"][-1] means: open the dictionary at the key "messages", then take the last item of the list you find there.

What happens when you run it

Here is the whole trip, from your script to OpenAI and back. With no tools, the agent loop runs once: one call to the model, then it stops.

What you should see: after a short wait, one line such as The capital of Italy is Rome. (that's the presenter's output at 26:20). The exact wording can vary from run to run; that is normal for a language model.

New to tokens? Why the response counts them

Models read and write text in small pieces called tokens (often a word or part of a word). OpenAI bills by tokens: input_tokens is what you sent (here, your question), output_tokens is what the model generated.

gpt-5-nano is a reasoning model: it may "think" in hidden tokens before answering. Those are counted as output too, which is why a one-word answer can still report a surprising number of output tokens. Watching these numbers is how you keep your $5 of credit from step 3 under control.

Why [-1] means "the last one"

Python lets you count list positions from the end with negative numbers: [-1] is the last item, [-2] the one before it. That is handy here, because the number of messages changes: two today, four in step 6, four or more once tools are involved in step 8. The agent's final answer is always the last one, so [-1] keeps working however long the list gets.

Common mistakes:

  • print(response.content) (the step 4 habit): AttributeError: 'dict' object has no attribute 'content'. The agent returns a dictionary, not a message. Use response["messages"][-1].content.
  • [0] instead of [-1]: you print your own question back, not the answer.
  • create_agent.invoke(...) instead of agent.invoke(...): AttributeError: 'function' object has no attribute 'invoke'. The presenter hits exactly this later (70:11). create_agent is the factory; agent is the thing it built.
  • A different key name, such as {"message": ...} or {"input": ...}: the agent only reads the key "messages" (plural).
  • Missing key or load_dotenv(): openai.OpenAIError: Missing credentials .... Check that .env sits in the project folder (next to models_agents.py) and contains OPENAI_API_KEY.
  • ModuleNotFoundError: the virtual environment is not active, or langchain-openai isn't installed (run uv add langchain-openai, as in step 4).
Recap
  • create_agent(model=model) wraps your chat model in an agent; the agent runs the agent loop for you.
  • An agent takes {"messages": [HumanMessage(content="...")]}: a dictionary whose "messages" key holds a list of messages.
  • It returns the same shape, with its reply (an AIMessage) added at the end; response["messages"][-1].content is the answer text.
  • Printing the whole list shows the metadata: token usage, provider, model name and more.
