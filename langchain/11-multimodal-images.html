Multimodal Messages: Sending Images

Turn an image into a base64 data URL and send it inside a HumanMessage.

▶ Watch this part (01:03:15)

Goal

So far every message you sent was text. In this step you send the agent a picture and ask "tell me what is the image about". To do that, you turn an image file into text the API can carry (a base64 data URL) and put it inside a HumanMessage next to your question.

This is the core of the personal chef project: in steps 13–14 the chef looks at a photo of your fridge or ingredients using exactly these functions (the repo's photo_decoder.py).

Where the code comes from. Code transcribed from the video (frames at 70:30), run against the repo's locked versions (langchain 1.3.12, langgraph 1.2.9, langchain-openai 1.3.4) with an offline test harness that replaced the model and the file picker with fakes.

What "multimodal" means

At 63:40 the presenter goes back to the agent diagram from the start of the course: the input box doesn't have to be text. It can also be images. A multimodal message is a message that mixes more than one kind of content, here text and an image. "Giving images to the agent is not as straightforward as text" (64:30), because a message must be text-like data (JSON) when it travels to OpenAI, and an image file is raw bytes. So we transform it first.

New to vision models? How a model can "see" a picture

A model that accepts images is called a vision or multimodal model. Behind the scenes, the provider cuts the image into small tiles and turns them into numbers the model can process, much like text is turned into tokens. That's also why images cost input tokens: a large, detailed picture costs more than a small one.

Not every model accepts images. gpt-5-nano, used in the video, does: the presenter's run describes the picture correctly (70:36). If you switch to a text-only model, the provider rejects the request with an error. Check your provider's model page for "image input" or "vision" before you choose a model.

For you as a developer, nothing about training changes. You just put the image in the message next to the text.

New to base64? How binary files become text

An image is binary data: a long list of bytes, each a number from 0 to 255. Many bytes aren't printable characters, so you can't safely put them inside JSON, which is how messages travel to OpenAI.

Base64 rewrites any bytes using only 64 safe characters: A–Z, a–z, 0–9, + and / (plus = as padding at the end). Every 3 bytes become 4 characters, so the encoded text is about 33% bigger than the original file (4 ÷ 3 ≈ 1.33). A 3 MB photo becomes about 4 MB of text.

Tiny example: the text Hi! is the bytes 72, 105, 33, and in base64 it becomes SGkh. Base64 is an encoding, not encryption: anyone can decode it back.

Build it

  1. Create a new file called multi_model_messages.py (the presenter's spelling; "multimodal" is the usual word) next to your other lesson files.
  2. Paste the helper functions (lines 1–55). At 66:25 the presenter first runs only choose_image_file() and prints the path and the encoded result, to show the long base64 string that will be sent ("this is all an encoding", 66:50). You can do the same as a check.
  3. Add the agent part (lines 57–66): create the agent, pick an image, build the message, invoke, print (67:15–69:24).
  4. Run it with python multi_model_messages.py, choose any .png, .jpg, .jpeg or .webp file in the dialog, and wait for the description.
import base64
import mimetypes
from pathlib import Path
from tkinter import TclError, Tk, filedialog
from langchain.messages import HumanMessage
from langchain.agents import create_agent
from dotenv import load_dotenv

load_dotenv()

def choose_image_file() -> Path:
    """Open a local file picker when no image path is passed on the command line."""
    root = None
    try:
        root = Tk()
        root.withdraw()
        root.attributes("-topmost", True)
        filename = filedialog.askopenfilename(
            title="Choose an image",
            filetypes=[
                ("Images", "*.png *.jpg *.jpeg *.webp"),
                ("All files", "*.*"),
            ],
        )
    except TclError:
        filename = input("Image path: ").strip().strip('"').strip("'")
    finally:
        if root is not None:
            root.destroy()

    if not filename:
        raise SystemExit("No image selected.")

    return Path(filename).expanduser()

def image_to_data_url(image_path: Path) -> str:
    image_path = image_path.expanduser().resolve()

    if not image_path.is_file():
        raise FileNotFoundError(f"Image not found: {image_path}")

    mime_type, _ = mimetypes.guess_type(str(image_path))
    if not mime_type or not mime_type.startswith("image/"):
        raise ValueError(f"Not an image file: {image_path}")

    image_b64 = base64.b64encode(image_path.read_bytes()).decode("utf-8")
    return f"data:{mime_type};base64,{image_b64}"

def build_image_message(image_path: Path) -> HumanMessage:
    return HumanMessage(
        content=[
            {"type": "text", "text": "tell me what is the image about"},
            {"type": "image_url", "image_url": {"url": image_to_data_url(image_path)}},
        ]
    )

agent = create_agent(model="gpt-5-nano")
image_path = choose_image_file()
message = build_image_message(image_path)


response = agent.invoke(
    {"messages": message}
)

print(response["messages"][-1].content)

New to try / except / finally? Handling errors without crashing

When something goes wrong, Python raises an exception. If nobody catches it, the program stops and prints a traceback.

  • try: – "attempt this code".
  • except TclError: – "if this specific error happens, run this instead". Other errors are not caught and still stop the program.
  • finally: – "always run this at the end, error or not". Perfect for clean-up such as closing a window or a file.

In choose_image_file, this pattern gives you a graceful fallback (type the path) when no window can be shown, and makes sure the hidden tkinter window is always closed.

The errors the presenter hit

The first runs in the video failed twice, which makes this a good place to practise reading errors.

  1. Missing API key (69:24). The first version had no load_dotenv(), so OPENAI_API_KEY was never loaded. The traceback ended with: 
    openai.OpenAIError: Missing credentials. Please pass an api_key ... or set the OPENAI_API_KEY environment variable

    Fix: add from dotenv import load_dotenv and call load_dotenv() near the top (69:47), before the agent is used.

  2. Calling invoke on the wrong thing (70:11). The presenter typed create_agent.invoke(...) instead of agent.invoke(...): 
    AttributeError: 'function' object has no attribute 'invoke'

    create_agent is the function that builds an agent; it has no invoke. The agent it returns (stored in agent) does. Fix: response = agent.invoke(...).

Common mistakes

  • Missing key or AttributeError: see the two errors above.
  • ValueError: Not an image file: you picked a non-image under "All files", or the file has no extension. The type is guessed from the extension, so photo without .jpg is rejected.
  • The dialog never appears: look behind your other windows or in the taskbar. On a remote machine with no screen you'll get the "Image path:" prompt instead; type or paste the path there.
  • ModuleNotFoundError: No module named 'tkinter': some Linux Python installations ship without tkinter. Install your system's tkinter package (for example python3-tk), or type the path by changing the code to use input().
  • A huge photo is slow or rejected: base64 adds about 33%, and providers limit image size. Resize large phone photos before sending.
  • A model without image input: if you change the model, make sure it supports images, or the provider returns an error.
  • Forgetting "type" keys or misspelling "image_url": the block must match the format exactly, or the model won't receive the image.

Recap
  • A multimodal message mixes content types; here a HumanMessage holds a text block and an image block.
  • Images travel as text: file → bytes → base64 → data:<mime>;base64,... data URL. Base64 makes the data about 33% larger.
  • choose_image_file opens a tkinter dialog (hidden root window, on top), falls back to typing the path on TclError, and always cleans up in finally.
  • image_to_data_url checks the file exists and is an image (by extension), then encodes it; build_image_message wraps it in content blocks.
  • The model must support image input; gpt-5-nano does.
  • Load your key with load_dotenv(), and call agent.invoke, never create_agent.invoke. Prefer {"messages": [message]} (a list).
