Chef Project: Setup, Prompts & Photo Decoder

Clone, uv init, keys, prompt.py and photo_decoder.py.

This page turns the empty GitHub repo from step 12 into a working Python project, then writes the first two files of the chef: prompt.py (what the chef is told) and photo_decoder.py (how the photo becomes something the model can read). Along the way you will meet two small bugs in the repo's code. They are worth understanding, because they are exactly the kind of bug that doesn't crash anything and is easy to miss.

The setup repeats what you did in step 3, so this page moves faster through it and explains only what's different. If any command is new to you, step 3 explains it in detail.

New to uv init? What it creates in an existing repo

uv is the project and package manager from step 3. uv init turns the current folder into a Python project by adding:

  • pyproject.toml: the project's settings file. The name is taken from the folder (ACL_FastEat_Agent becomes acl-fasteat-agent), the description is a placeholder ("Add your description here"), and readme = "README.md" points at the README GitHub created.
  • .python-version: which Python version this project uses (3.12 in the repo).
  • main.py: a "Hello from acl-fasteat-agent!" starter script. The presenter deletes its contents at 81:20.

It doesn't overwrite the existing README.md. Because the folder is already a Git repository (you cloned it), uv doesn't run git init again, and it doesn't add a .gitignore. That's why you create one yourself in the next step.

ACL_FastEat_Agent/
├── .git/              (hidden: Git's history, from git clone)
├── README.md          (from GitHub, step 12)
├── .python-version    (uv init)
├── main.py            (uv init, emptied later)
├── pyproject.toml     (uv init)
├── .gitignore         (you create it)
└── .env               (you create it, never committed)

Part 2: keys, .gitignore and packages (80:10 to 82:12)

  1. Create .gitignore and write .env in it (79:59 to 80:25)

    Create a file named exactly .gitignore (with the dot, no extension) in the project folder, with this line:

    .env

    A .gitignore lists files Git must pretend don't exist: they never appear in git status and git add . skips them. The repo's final version also has a __pycache__/ line; step 15 covers that.

  2. Create .env with your two keys (80:25 to 80:54)

    The presenter copies the .env file from the earlier lesson project. Yours should contain your own keys in this shape:

    OPENAI_API_KEY=your-openai-key-here
TAVILY_API_KEY=your-tavily-key-here

    No spaces around =, no quotes needed, one key per line. OPENAI_API_KEY is read by the OpenAI chat model, TAVILY_API_KEY by the Tavily search client (step 14). The names must be spelled exactly like this, because the libraries look for these exact names. The video shows real keys on screen and the presenter says they will delete them; never show or share your own.

  3. Add the packages (80:54 to 81:20)

    The presenter first types the command without add:

    uv langchain dotenv

    uv answers with an error saying langchain is an unrecognized subcommand. uv's first word after uv must be a command (init, add, sync, run...), and langchain isn't one. The correct command:

    uv add langchain dotenv

    add installs packages and records them as dependencies in pyproject.toml. If there's no virtual environment yet, uv creates .venv first. It also writes uv.lock, the lockfile with the exact versions. The presenter then checks everything is in sync (uv sync).

  4. Activate the virtual environment (81:41)

    The presenter writes from dotenv import load_dotenv in main.py, sees that it isn't picked up properly, and says: "I should have activated the environment." On Windows (PowerShell or the VS Code terminal):

    .venv\Scripts\activate

    On macOS or Linux: source .venv/bin/activate. They then run the add command again and the import works (82:12).

New to activating a virtual environment? What it changes

A virtual environment (.venv) is a private copy of Python with its own installed packages. uv add installs into .venv, but your terminal doesn't use it until you activate it. Activating puts .venv\Scripts first in the list of places the terminal searches for programs, so python now means the project's Python, which can see langchain and dotenv.

You know it worked when the prompt starts with the environment name in brackets, for example (ACL_FastEat_Agent) or (.venv). You have to activate again in every new terminal window.

VS Code has its own setting for which Python to use (bottom-right status bar, or Ctrl+Shift+P then "Python: Select Interpreter"). Pick the one inside .venv and the yellow underline under imports goes away.

Shortcut: uv run main.py runs the script with the project's environment without activating anything.

dotenv or python-dotenv? Which package you really installed

The code says from dotenv import load_dotenv, but the package that provides it is called python-dotenv on PyPI. The video installs a package named dotenv (the repo's pyproject.toml lists dotenv>=0.9.9). That package is a deprecated "shim": it contains no useful code of its own, and its only dependency is python-dotenv. So installing it pulls in the real package and the import works.

It works, but it's an extra hop through a package you don't need. Step 16 adds python-dotenv directly. A good habit: when a package name differs from its import name, check on pypi.org which one is the official package before installing (see supply-chain attacks).

Video vs repo: langchain-openai and tavily

At this point only langchain and dotenv are installed. The repo's final pyproject.toml also lists langchain-openai and tavily: the presenter adds them in step 14, when the program asks for them. If you want to avoid that error later, you can add langchain-openai now. For Tavily, step 9 and step 16 explain why tavily-python (the official SDK) is the better package name.

New to long strings in Python? Three ways to split them

When a string is too long for one line, you have options:

# 1. Backslash continuation (what prompt.py does)
TEXT = "first part. " \
"second part"

# 2. Parentheses: the usual modern style (what step 16 does)
TEXT = (
    "first part. "
    "second part"
)

# 3. Triple quotes: keeps the line breaks inside the string
TEXT = """first part.
second part"""

In 1 and 2, Python joins the pieces with nothing in between, so you must put the space inside one of the strings yourself. A trailing \ is fragile: a single space after it is a syntax error. Parentheses avoid that.

Bug in the repo: "photo.once"

Line 3 ends with photo." and line 4 starts with "once. Joined, the model receives ...the ingredients in the photo.once you do that search online.... Modern models usually cope with a missing space, so the demo still works, but you're relying on the model to repair your prompt. Fix: put a space before the closing quote on line 3 (photo. "). Step 16 does this and also capitalises "Your" and "Once".

Part 4: the photo decoder (82:34 to 83:52)

The presenter creates photo_decoder.py by copying the helper functions from the step 11 lesson file (multi_model_messages.py). The only change is a new prompt parameter on build_image_message. They explain why at 83:29: they want to reuse the function "for multiple things, not just one thing", so the question should be passed in instead of being written inside the function.

  1. Create photo_decoder.py in the project folder with this content:
import base64
import mimetypes
from pathlib import Path
from tkinter import TclError, Tk, filedialog
from langchain.messages import HumanMessage
from langchain.agents import create_agent
from dotenv import load_dotenv

load_dotenv()

def choose_image_file() -> Path:
    """Open a local file picker when no image path is passed on the command line."""
    root = None
    try:
        root = Tk()
        root.withdraw()
        root.attributes("-topmost", True)
        filename = filedialog.askopenfilename(
            title="Choose an image",
            filetypes=[
                ("Images", "*.png *.jpg *.jpeg *.webp"),
                ("All files", "*.*"),
            ],
        )
    except TclError:
        filename = input("Image path: ").strip().strip('"').strip("'")
    finally:
        if root is not None:
            root.destroy()

    if not filename:
        raise SystemExit("No image selected.")

    return Path(filename).expanduser()

def image_to_data_url(image_path: Path) -> str:
    image_path = image_path.expanduser().resolve()

    if not image_path.is_file():
        raise FileNotFoundError(f"Image not found: {image_path}")

    mime_type, _ = mimetypes.guess_type(str(image_path))
    if not mime_type or not mime_type.startswith("image/"):
        raise ValueError(f"Not an image file: {image_path}")

    image_b64 = base64.b64encode(image_path.read_bytes()).decode("utf-8")
    return f"data:{mime_type};base64,{image_b64}"

def build_image_message(image_path: Path, prompt) -> HumanMessage:
    return HumanMessage(
        content=[
            {"type": "text", "text": "prompt"},
            {"type": "image_url", "image_url": {"url": image_to_data_url(image_path)}},
        ]
    )

New to try / except / finally? How the file picker stays safe

An exception is Python's way of saying "something went wrong here". Without handling, it stops the program and prints a traceback. A try block lets you react instead:

  • try: run this code.
  • except TclError: if this specific error happens, run this instead. Other errors still stop the program, which is what you want: you only catch what you know how to handle.
  • finally: always run this at the end, error or not. Perfect for cleanup like closing a window.

raise does the opposite: it creates an error on purpose. Lines 32, 40 and 44 use it to stop early with a message that tells you exactly what's wrong.

Bug in the repo: the chef never sees your request (line 52)

Line 52 is {"type": "text", "text": "prompt"}. Because of the quotes, it sends the literal word prompt. The prompt parameter (which holds CHEF_PROMPT, "please find me a good recipe to cook") is accepted on line 49 but never used. The offline test harness used to verify this guide confirmed it: the model receives the text prompt.

How it happened. In the step 11 lesson the line was {"type": "text", "text": "tell me what is the image about"}, a fixed sentence in quotes. At 83:29 the presenter adds a prompt parameter and replaces the sentence, but types the new name inside the existing quotes. Python sees a valid string, so there's no error and no warning.

Why the demo still works. The system prompt already tells the model what to do: identify the ingredients in the photo and search for a recipe. So the model receives "system: be a chef and find a recipe" plus "user: prompt + photo", and does the right thing anyway. The bug shows up as soon as you try a different request, for example "find me a dessert" or "a vegetarian dinner": it is silently ignored.

The fix (step 16) is to remove the quotes: {"type": "text", "text": prompt}.

How to catch this kind of bug yourself

Print what you send before you send it. Add a temporary line in main.py after the message is built (step 14):

print(message.content[0])   # {'type': 'text', 'text': 'prompt'}

If the text isn't what you expected, you've found the bug in seconds. Also look for greyed-out names in VS Code: an unused parameter like prompt on line 49 is a hint that something isn't wired up.

Common mistakes

  • Cloning inside another project folder. You end up with a repo inside a repo. Run git clone from the folder where your projects live.
  • Naming the file .gitignore.txt or gitignore. Windows may hide extensions. The name must be exactly .gitignore, or Git ignores nothing and .env gets committed.
  • A damaged key in .env. python-dotenv accepts quotes and spaces around =, but a key copied with a missing character, an extra space inside it or a line break in the middle gives "invalid API key" errors. Keep it simple: NAME=value on one line.
  • Running uv init in the wrong folder (for example the parent folder). Check with pwd (or cd on Windows cmd) that you're inside ACL_FastEat_Agent.
  • Forgetting to activate the venv in a new terminal: ModuleNotFoundError: No module named 'dotenv' even though you installed it. Activate, or use uv run.
  • Naming your file tkinter.py, base64.py or dotenv.py. Python would import your file instead of the real module.
Recap
  • git clone copies your GitHub repo into a new folder; uv init adds pyproject.toml, .python-version and main.py.
  • .gitignore with .env comes before any commit; .env holds OPENAI_API_KEY and TAVILY_API_KEY.
  • uv add langchain dotenv installs the packages (uv langchain dotenv is a typo); dotenv is a shim for python-dotenv. Activate .venv or use uv run.
  • prompt.py holds the system prompt (who the chef is) and the user prompt (what you want). Adjacent strings are glued without a space, which produces "photo.once".
  • photo_decoder.py picks a file, turns it into a data URL and wraps it with text in a HumanMessage. Line 52 sends the word "prompt" instead of your request; step 16 fixes it.
