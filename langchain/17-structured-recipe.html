Goal

Until now the chef answers with a block of free text. That's perfect for reading in a terminal, but your code can't do much with it. Where does the title end? How many minutes does it take? Which lines are steps? In this step you ask the agent to return a typed Recipe object instead, with a title, a list of ingredients, a list of steps, a cooking time as a number, and an optional source link. This is called structured output, and it's the bridge between an AI answer and a real app.

The handbook chapter Multimodal Input & Structured Output covers the theory in more depth.

Why typed data beats free text

Imagine you want to turn the chef into a small app. With free text you would have to split the answer with string tricks ("find the line that starts with a number…"), and they break as soon as the model words things differently. With a typed object you can:

  • Save it to a database: title, minutes and source_url map straight to columns; ingredients and steps to a related table or a JSON column.
  • Show it in a user interface: the title as a heading, the ingredients as a checklist, the steps as a numbered list, the time as a badge.
  • Use it in logic: "only show recipes under 30 minutes" is just if recipe.minutes < 30.
  • Trust the shape: if the model returns something that doesn't fit, you get an error right away instead of a broken screen later.
New to Pydantic? Classes that describe and check data

Pydantic is a popular Python library for describing the shape of data. You write a class that inherits from BaseModel and list its fields with type hints:

from pydantic import BaseModel

class Point(BaseModel):
    x: int
    y: int

Point(x=1, y=2)          # OK
Point(x="one", y=2)      # ValidationError: x is not a valid integer

Pydantic does two jobs at once. It validates: data that doesn't match the types raises a ValidationError. And it can describe the class as a JSON Schema, a standard machine-readable description of the fields. LangChain sends that schema to the model so the model knows exactly what to produce. Pydantic is already installed in your project: LangChain depends on it.

New to these type hints? list[str], int and str | None
  • str: text, like "Garlic fried rice".
  • int: a whole number, like 20. Not "20 minutes" and not 20.5.
  • list[str]: a list where every item is text, like ["2 eggs", "1 cup rice"].
  • str | None: "text or nothing". The | means "or" (Python 3.10+). None is Python's "no value". Use it for information that may not exist, like a source link when the model didn't search.
New to Zod? Objects that describe and check data

Zod is a library for describing the shape of data. TypeScript's own types disappear when the program runs, so the shape must be a real value:

const Point = z.object({ x: z.number().int(), y: z.number().int() });

Point.parse({ x: 1, y: 2 }) returns the object; Point.parse({ x: "one", y: 2 }) throws an error that names the field. Like Pydantic, Zod does two jobs: it validates data, and LangChain.js turns it into a JSON Schema that is sent to the model. TypeScript also reads the type from it, so your editor knows that recipe.minutes is a number. Zod is already in the project's package.json.

New to these Zod types? z.string(), z.array(), z.number().int() and .nullable()
  • z.string(): text, like "Garlic fried rice".
  • z.number().int(): a whole number, like 20. JavaScript has only one number type, so .int() adds the "no decimals" rule.
  • z.array(z.string()): a list where every item is text, like ["2 eggs", "1 cup rice"].
  • z.string().nullable(): "text or null". null is JavaScript's "no value", like Python's None.
  • .describe("…"): the sentence the model reads for that field, like Python's Field(description=…).

import sys
from pathlib import Path

from dotenv import load_dotenv
from langchain.agents import create_agent
from pydantic import BaseModel, Field

from photo_decoder import build_image_message, choose_image_file
from prompt import CHEF_PROMPT, SYSTEM_CHEF_PROMPT
from tools import web_search

load_dotenv()


class Recipe(BaseModel):
    """A recipe that uses the ingredients found in the photo."""

    title: str = Field(description="Name of the dish")
    ingredients_seen: list[str] = Field(description="Ingredients you recognised in the photo")
    ingredients: list[str] = Field(description="Everything the recipe needs, with quantities")
    steps: list[str] = Field(description="Cooking steps, in order")
    minutes: int = Field(description="Total cooking time in minutes")
    source_url: str | None = Field(default=None, description="Web page the recipe came from, if any")


agent = create_agent(model="gpt-5-nano",
                     tools=[web_search],
                     system_prompt=SYSTEM_CHEF_PROMPT,
                     response_format=Recipe)

path = Path(sys.argv[1]) if len(sys.argv) > 1 else choose_image_file()
response = agent.invoke({"messages": [build_image_message(path, CHEF_PROMPT)]})

recipe: Recipe = response["structured_response"]
print(f"# {recipe.title}  ({recipe.minutes} min)")
print("Seen in the photo:", ", ".join(recipe.ingredients_seen))
print("\nIngredients:")
for item in recipe.ingredients:
    print(" -", item)
print("\nSteps:")
for number, step in enumerate(recipe.steps, start=1):
    print(f" {number}. {step}")
if recipe.source_url:
    print("\nSource:", recipe.source_url)
import "dotenv/config";
import { createAgent } from "langchain";
import { z } from "zod";
import { getVisionModel } from "../src/models.js";
import { buildImageMessage, chooseImageFile } from "./photo-decoder.js";
import { CHEF_PROMPT, SYSTEM_CHEF_PROMPT } from "./prompt.js";
import { webSearch } from "./tools.js";

const Recipe = z
  .object({
    title: z.string().describe("Name of the dish"),
    ingredients_seen: z.array(z.string()).describe("Ingredients you recognised in the photo"),
    ingredients: z.array(z.string()).describe("Everything the recipe needs, with quantities"),
    steps: z.array(z.string()).describe("Cooking steps, in order"),
    minutes: z.number().int().describe("Total cooking time in minutes"),
    source_url: z.string().nullable().describe("Web page the recipe came from, or null"),
  })
  .meta({ title: "Recipe", description: "A recipe that uses the ingredients found in the photo." });

const agent = createAgent({
  model: getVisionModel(),
  tools: [webSearch],
  systemPrompt: SYSTEM_CHEF_PROMPT,
  responseFormat: Recipe,
});

const imagePath = process.argv[2] ?? (await chooseImageFile());
const response = await agent.invoke({ messages: [buildImageMessage(imagePath, CHEF_PROMPT)] });

const recipe = response.structuredResponse;
// A small local model may answer in plain text instead of filling the Recipe schema: then there is no recipe object.
if (!recipe) {
  console.error("The model did not return a structured recipe. Its last message was:\n");
  console.error(response.messages.at(-1)?.text);
  process.exit(1);
}
console.log(`# ${recipe.title}  (${recipe.minutes} min)`);
console.log("Seen in the photo:", recipe.ingredients_seen.join(", "));
console.log("\nIngredients:");
for (const item of recipe.ingredients) {
  console.log(" -", item);
}
console.log("\nSteps:");
recipe.steps.forEach((step, index) => console.log(` ${index + 1}. ${step}`));
if (recipe.source_url) {
  console.log("\nSource:", recipe.source_url);
}

What the model is told

You never write instructions like "answer in JSON with these keys". LangChain turns Recipe into a JSON Schema and sends it with the request. The field names, types, the class docstring and each description all end up in it. That's why good descriptions matter: they are part of the prompt.

In TypeScript, LangChain.js turns the Zod schema into a JSON Schema in the same way: the field names, the types, every .describe() text, and the title and description from .meta() on line 18.

How the agent produces a Recipe: two strategies

Models can be made to return structured data in two different ways, and LangChain 1.x picks one for you when you pass a plain class like Recipe:

  • ProviderStrategy (the provider's native mode). Some providers, including OpenAI, can be told "your final answer must match this JSON Schema", and the provider enforces it while the model writes. With gpt-5-nano this is what LangChain chooses. The final AI message contains the JSON text, and LangChain parses it into a Recipe.
  • ToolStrategy (a fake tool). For models without that native mode, LangChain adds an extra tool named after your schema. The model "calls" it with the recipe as arguments, just as it calls web_search; LangChain takes those arguments, validates them with Pydantic, and puts the result in structured_response. If validation fails, by default LangChain sends the error back so the model can try again.

In LangChain 1.3.12 the decision is made from the model's profile (what the integration package knows about the model) or, failing that, from a built-in list of model-name patterns. You can also choose yourself:

from langchain.agents.structured_output import ProviderStrategy, ToolStrategy

agent = create_agent(model="gpt-5-nano", tools=[web_search],
                     system_prompt=SYSTEM_CHEF_PROMPT,
                     response_format=ToolStrategy(Recipe))   # force the tool approach

For this step you don't need to: passing Recipe directly lets LangChain pick the best option, and response["structured_response"] works the same way with both.

In LangChain.js createAgent makes the same choice from the model's profile. new ChatOpenAI({ model: "gpt-5-nano" }).profile.structuredOutput is true, so it uses providerStrategy and sends OpenAI response_format: { type: "json_schema", … strict: true }. ChatOllama's profile is empty ({}), so with llama3.2 or gemma4 it uses toolStrategy: an extra tool named after the schema's title, Recipe, with tool_choice: "any" (the model is asked to call a tool). You can force one with responseFormat: toolStrategy(Recipe) or providerStrategy(Recipe), both imported from "langchain". The real run below shows that the tool strategy is a request, not a guarantee: the model can still answer in plain text.

Common mistakes

  • KeyError: 'structured_response': you forgot response_format=Recipe in create_agent, so the agent only returns "messages".
  • response_format=Recipe() with brackets: that tries to create an empty recipe and fails with a ValidationError (missing fields). Pass the class, not an instance.
  • Printing response["messages"][-1].content out of habit: with the native strategy that's the raw JSON text, and with the tool strategy it's a ToolMessage starting with Returning structured response:. Neither is a Recipe object. Read structured_response.
  • Too many required fields: every required field must be filled, so the model may invent a value rather than leave it empty (a hallucination). Make uncertain fields optional with | None and default=None, as source_url is.
  • Vague descriptions: minutes: int with no description may come back as preparation time only. Say exactly what you mean in Field(description=…).
  • Using from langchain.pydantic_v1 from old tutorials: LangChain 1.x uses normal Pydantic 2. Import from pydantic.

Common mistakes

  • Reading recipe.title without checking: when the model answers in plain text, structuredResponse is undefined and you get TypeError: Cannot read properties of undefined (reading 'title'). The first real run did exactly this; lines 31–36 now check.
  • Printing response.messages.at(-1)?.text out of habit: that's the last message, not a Recipe object. Read response.structuredResponse.
  • Leaving out .meta({ title: "Recipe" }): with the tool strategy the extra tool is then called extract-1 instead of Recipe.
  • Using .optional() instead of .nullable() for source_url: OpenAI's strict JSON-schema mode needs every field to be required, so the file keeps the field required and lets it be null.
  • Vague descriptions: minutes: z.number().int() with no .describe() may come back as preparation time only. Say exactly what you mean.
New to validation errors? What happens if the model gets it wrong

Suppose the model returns "minutes": "about twenty". Pydantic can't turn that into an int, so it raises a ValidationError explaining which field failed and why. With the native strategy, the provider's schema enforcement makes this rare. With the tool strategy, LangChain's default is to send the error back to the model as a message and let it try again. Either way, you never receive a Recipe whose minutes isn't a number. That guarantee is the whole point of typed output.

Recap
  • A Pydantic BaseModel describes the answer's shape; Field(description=…) tells the model what each field means.
  • list[str], int and str | None give each field a precise type; default=None makes a field optional.
  • create_agent(…, response_format=Recipe) makes the final answer a Recipe; tools still work as before.
  • LangChain picks ProviderStrategy (native JSON Schema, used with gpt-5-nano) or ToolStrategy (an extra tool); you can force one.
