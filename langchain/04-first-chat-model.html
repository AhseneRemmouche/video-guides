About the code on this page: the lesson files of steps 04–11 are not in the presenter's repository. Code transcribed from the video (frames at 21:58), run against the repo's locked versions (LangChain 1.3.12, langchain-openai 1.3.4).

New to imports and modules? How Python files use other code

A module is a Python file (or folder of files) with code you can reuse. A package installed with uv add contains modules. To use something from a module you import it:

from dotenv import load_dotenv

reads as "from the module dotenv, bring in the name load_dotenv". After that line, load_dotenv can be used in your file. Dots in a module name are folders: langchain.chat_models is the chat_models part of the langchain package.

Note that a package's install name and its import name can differ: you install langchain-openai (dash) but Python imports langchain_openai (underscore). You install python-dotenv but import dotenv.

from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

New to chat models and invoke? What actually happens on line 10

The model does not run on your computer. invoke packs your text into a request, sends it over HTTPS to OpenAI with your API key, OpenAI runs gpt-5-nano on its servers (this is called inference), and the reply comes back. LangChain then wraps the reply in an AIMessage.

The model writes its answer one token (a word or piece of a word) at a time. You pay per token, for both your question (input) and the answer (output). Longer answers cost a little more and take longer.

gpt-5-nano is a reasoning model: before writing the visible answer it spends some hidden tokens "thinking". That is part of why even a short answer can take a few seconds.

What is inside response

The value returned by invoke is an AIMessage. You only need .content now, but it helps to know the other fields exist; step 05 prints them all.

Temperature, explained properly

At each step the model has a list of possible next tokens, each with a probability. Temperature changes how it picks from that list:

  • Low (0 or close): almost always the most likely token. Answers are focused and nearly the same every run. Good for facts, extraction, code.
  • Higher (around 1 and above): less likely tokens get picked more often. Answers vary more between runs and can feel more creative. Too high and the text becomes odd or incoherent.

The presenter describes it (20:47) as how "rigid, serious, logical" versus how creative the model is, "from zero to one". The idea is right; the range is slightly off: OpenAI's chat models accept 0 to 2, and when you do not set it, OpenAI uses 1.

Why temperature=1.0 changed nothing in the video (21:35). Two reasons, both verified with the locked versions:

  1. 1.0 is already the default. Setting it to 1.0 is the same as not setting it.
  2. gpt-5-nano does not accept other temperatures. The gpt-5 family are reasoning models that only support the default. LangChain's OpenAI integration (langchain-openai 1.3.4) knows this and silently removes any temperature other than 1 for model names starting with gpt-5 (exceptions: gpt-5-chat… models, or reasoning effort set to "none"). So temperature=0 would also be ignored, without a warning.

The answers to the Rome question stayed similar simply because it is a factual question with one obvious answer. To really see temperature at work, try a model that supports it, for example gpt-4.1-mini (model names are examples at the time of writing).

You can check this yourself. This small script needs your .env but makes no paid call, because it only creates the model objects and reads a setting:

from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

load_dotenv()

nano = init_chat_model("gpt-5-nano", temperature=0)
print(nano.temperature)

mini = init_chat_model("gpt-4.1-mini", temperature=0)
print(mini.temperature)

Why the story took so long (22:47)

When the presenter asks for a story, the terminal sits silent for a while and then prints a long story all at once. As they explain, "we didn't tell it to send us a stream": invoke waits until the model has generated every token, then returns everything together. A longer answer means a longer wait with nothing on screen. Adding "in a few lines" to the prompt would make it shorter and faster.

What you should see

  • With the Rome question: after a few seconds, a short answer such as Rome (wording varies per run).
  • With "tell me story": a pause of several seconds or more, then a complete multi-paragraph story printed at once. Your story will be different from the presenter's; that is normal.
  • A new __pycache__ folder may appear; it is ignored by Git.
  • In your OpenAI dashboard's usage page, a tiny amount of usage after a while.

Common mistakes

New to tracebacks? How to read a Python error

When Python hits an exception it does not handle, it stops and prints a traceback: the chain of function calls that led to the error, oldest first, and the error itself at the very bottom. Beginners often read from the top and get lost in library code. Start at the last line (the error type and message), then look upward for the first line that mentions your file (models_agents.py, with a line number).

For the missing package, you see two errors: the original ModuleNotFoundError: No module named 'langchain_openai', then "During handling of the above exception, another exception occurred", then LangChain's friendlier ImportError: Initializing ChatOpenAI requires the langchain-openai package. Please install it with `pip install langchain-openai`. In a uv project, use uv add langchain-openai instead of pip, so it is recorded in pyproject.toml.

Other common mistakes

  • Venv not active. You installed langchain-openai but still get ModuleNotFoundError: the terminal is using the global Python. Activate the venv (step 03) or run uv run python models_agents.py.
  • Missing key. openai.OpenAIError: Missing credentials. Please pass an api_key … or set the OPENAI_API_KEY environment variable. Causes: forgot load_dotenv(), called it after init_chat_model, .env not in the project folder, or a typo in the variable name. The presenter meets this exact error in step 11.
  • No credit. A quota or billing error from OpenAI even though the key is right. Add credit on the billing page (step 03).
  • Printing response instead of response.content. Not an error, but you get a long object with metadata instead of just the answer.
  • Typo in the model name. For example "gpt5-nano": LangChain cannot infer the provider, or OpenAI answers that the model does not exist. Copy the name exactly: gpt-5-nano.
  • Expecting temperature to change gpt-5-nano. It cannot (see above). Use a model that supports it to experiment.
  • Thinking the program froze. A long answer with invoke can take a while. Wait, or ask for a shorter answer.
Recap
  • load_dotenv() loads OPENAI_API_KEY from .env; call it before creating the model.
  • init_chat_model(model="gpt-5-nano") creates an OpenAI chat model; it needs the langchain-openai package (uv add langchain-openai).
  • model.invoke("…") sends one request and waits for the full answer; the result is an AIMessage and .content is its text.
  • Temperature controls randomness (OpenAI: 0 to 2, default 1). For gpt-5-nano it is fixed at 1, so temperature=1.0 in the video had no effect.
  • invoke does not stream: nothing appears until the whole answer is ready (streaming comes in step 07).
