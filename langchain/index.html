LangChain Crash Course: Agents, Tools & a Personal Chef

A beginner-friendly, step-by-step companion to the AI Career Lab crash course on LangChain 1.x. You set up a project, talk to a chat model, build agents that use tools and search the web with Tavily, give them short-term memory, send them images, and finish with an AI personal chef that looks at a photo of your ingredients and finds a recipe online. The video is in Python; every program also exists in TypeScript (LangChain.js 1.x), and a last part puts the chef in a React web app. Every line of code is explained. The guide also fixes two bugs found in the repo and adds four extension steps and a 10-chapter handbook.

▶ Watch the full video

How to use it

  1. Watch a chapter of the video, then read its step page. Steps 01–15 follow the video in order; steps 16–19 are extensions; step 20 is the web app.
  2. Pick your language with the Code in: switch at the top of every step page (Python or TypeScript). Code, outputs, line-by-line tables and run commands follow your choice, and the guide remembers it from page to page. The video's own code and quotes always stay in Python.
  3. Run each program yourself and compare with the output on the page. Then change something (a prompt, a tool description, the model) and run it again.

How this guide is organised

The project in two folders

The Python project is the course repo, Mohamad-Hachem/ACL_FastEat_Agent, run with uv. The lesson files of steps 04–11 are not in that repo; each step page shows them in full. The TypeScript project, fasteat-agent-ts, was written for this guide. It holds every lesson, the chef with the repo's two bugs already fixed, the three extensions, offline tests and the web app of step 20 (a Hono server and a React page). It runs with pnpm on Node.js.

Compared with the GitHub repo

The chef project (steps 12–15) is embedded unchanged from Mohamad-Hachem/ACL_FastEat_Agent (commit ea320de, "creating our personal Agent"). Checking the repo and the video against each other turned up these differences and findings. Each one is explained on the page listed:

StepDifference or finding
04–11The lesson files are not in the repo, which contains only the chef project. They were transcribed from the video frames, checked against the transcript and run against the repo's locked versions. Each page says which frames it comes from.
04Temperature does nothing with gpt-5-nano. langchain-openai 1.3.4 drops any value other than 1 for GPT-5 reasoning models, and the video's temperature=1.0 is already the default. That's why the answers didn't get "more creative". The page explains temperature and suggests a model that supports it. The TypeScript package (@langchain/openai 1.6.2) does not drop it: it sends the value you give.
09, 14Unofficial tavily package. The video runs uv add tavily and the repo depends on tavily>=1.1.0. That PyPI package is published by an individual, not by Tavily. Tavily's official SDK is tavily-python, with the same import (from tavily import TavilyClient). Version 1.1.0 of tavily only calls Tavily's API, but the guide recommends the official package. The TypeScript version uses @langchain/tavily, published by LangChain, so this problem does not apply there.
13dotenv instead of python-dotenv. The repo depends on dotenv, a deprecated shim whose only job is to install python-dotenv. It works; step 16 depends on python-dotenv directly.
13Bug: the chef never sees the request. photo_decoder.py sends {"type": "text", "text": "prompt"}, the word "prompt" in quotes instead of the prompt variable. It still works in the video because the system prompt says what to do. Fixed in step 16, and already fixed in the TypeScript chef.
13Bug: missing space in prompt.py. The two halves of SYSTEM_CHEF_PROMPT are joined without a space, so the model reads "…in the photo.once you do that…". Fixed in step 16, and already fixed in the TypeScript chef.
13The choose_image_file docstring mentions an image path "passed on the command line", but main.py never reads one. Step 16 adds it. The TypeScript chef takes the path on the command line from the start.
16–19Not in the video or the repo: extensions written for this guide and tested the same way.
20Not in the video: a React web app for the TypeScript chef, written for this guide.

How the code was verified

Python. No real API keys were used. An offline test harness replaced the OpenAI chat model with a fake one that has the same LangChain interfaces, replaced Tavily's search with a canned result, and replaced the file picker. Every lesson file, the repo's chef project and every extension file then ran end to end against the repo's locked versions (langchain 1.3.12, langgraph 1.2.9, langchain-openai 1.3.4): 13 of 13 passed. This proves that the imports, APIs, message flow, tool calling, memory, streaming, structured output and image messages work with these versions. It does not prove what a real model will answer: the wording of Python answers shown in the guide comes from the video.

TypeScript. pnpm test runs the same checks with a pretend model and no keys: 23 of 23 passed. On top of that, every lesson, the chef files and the web app were run for real with Ollama (llama3.2 for text, gemma4 for photos), because the guide had no OpenAI or Tavily key; the web search tool therefore answers that it is not configured. The TypeScript outputs on the step pages are those real runs. They come from a laptop with a 4 GB NVIDIA T500 whose memory was nearly full, so the times you see are slow, not typical. The real runs also found problems the tests could not: in step 08 llama3.2 kept calling its tool until LangGraph stopped it (recursion limit), and in step 17 gemma4 answered in plain text instead of returning a typed recipe. Both pages show what happened and why.

Your output will differ. Models are random by nature, and a different model or version gives different answers. The small local models used for the TypeScript runs make more mistakes than gpt-5-nano; the pages show those mistakes and explain them.

Before you start. In Python, like the video, you need an OpenAI API key with some credit (the presenter adds $5 on the billing page) and a free Tavily key (1,000 credits a month). In TypeScript you can use the same keys, or set MODEL_PROVIDER=ollama and run everything on your own computer with no key; Tavily is optional there. Keep keys in a .env file that is listed in .gitignore. Never paste a key into code or share it in a screenshot. The video briefly shows keys that the presenter says were deleted; this guide never reproduces them.
