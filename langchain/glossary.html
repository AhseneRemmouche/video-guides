Glossary

Every technical term in this guide, explained for beginners.

Every technical word used in this guide, explained in plain language. Pages link here the first time a term appears, so you can always come back. Terms are grouped by topic. Most entries point to the step where you first use the idea, and some point to the handbook chapter that goes deeper.

Two maps to start with

Before the individual words, here is how they fit together. The first map shows where each piece of the project lives. The second shows how the AI ideas connect inside an agent.

Tools & the command line

Terminal (command line)
A text window where you type commands instead of clicking. In VS Code, open it with Ctrl+`. On Windows the presenter's terminal is PowerShell. Lines in this guide such as uv add langchain are typed there and run with Enter. First used in step 03.
VS Code (Visual Studio Code)
A free code editor from Microsoft, used by the presenter throughout the video. It has a file explorer on the left, editor tabs in the middle and a built-in terminal at the bottom. The status bar at the bottom right shows which Python interpreter (and virtual environment) is active. See step 03.
pip
Python's standard package installer. pip install X downloads package X from PyPI (the Python Package Index). In this project pip is only used once, to install uv itself: pip install uv. After that, uv does the work. See step 03.
uv
A fast Python project and package manager. It creates the project (uv init), the virtual environment (uv venv --python 3.12), adds packages (uv add langchain) and records exact versions in uv.lock. A teammate who clones the repo runs uv sync to get the same packages. See step 03 and step 13.
Virtual environment (.venv)
A private folder of Python packages for one project, so projects don't fight over versions. uv creates it as .venv inside the project folder. Everything you install with uv add goes there, not into your system Python. It is never committed to Git: it is listed in .gitignore and can always be rebuilt with uv sync.
Activating the virtual environment
Telling your terminal to use the .venv Python instead of the system one. On Windows PowerShell: .venv\Scripts\activate. On macOS/Linux: source .venv/bin/activate. The prompt then starts with the environment's name. Forgetting this step is a common cause of ModuleNotFoundError; it happens in the video too (at 81:41). See step 03.
Package
Reusable code someone else wrote and published, which you install by name. langchain, langchain-openai, langgraph and python-dotenv are packages. Note that the name you install can differ from the name you import: you install python-dotenv but write from dotenv import load_dotenv.
Dependency
A package your project needs in order to run. Your direct dependencies are listed in pyproject.toml; their own dependencies (for example langchain pulls in langgraph and langchain-core) are recorded in uv.lock. Choose dependencies carefully: each one is code that runs on your machine (see supply-chain attack).
pyproject.toml
The project's settings file, created by uv init. It holds the project name, the required Python version and the list of dependencies. uv add X writes X into it for you. See the repo's version in step 03.
Lockfile (uv.lock)
A file that records the exact version of every package, including indirect ones. Two people running uv sync with the same lockfile get identical environments. This guide's code was tested against the repo's lockfile: langchain 1.3.12, langgraph 1.2.9, langchain-openai 1.3.4. Commit it to Git.
.env file
A plain text file of NAME=value lines that holds secrets such as OPENAI_API_KEY and TAVILY_API_KEY. load_dotenv() reads it and puts the values into environment variables, where the OpenAI and Tavily clients look for them. It must be listed in .gitignore so it never reaches GitHub. See step 03.
API key
A long secret string that identifies you to a paid service, like a password for programs. OpenAI uses it to bill your account; Tavily uses it to count your search credits. Keep it only in .env, never in code or screenshots. If a key leaks, delete it in the provider's dashboard and create a new one. Without it you get OpenAIError: Missing credentials (seen at 69:24).
.gitignore
A file listing paths Git should ignore. In this project it contains .env (secrets) and __pycache__/ (Python's compiled-file cache), which the presenter adds after spotting it in git status (at 101:56). The .venv folder stays out too, because uv puts its own small .gitignore inside it. Ignored files never get uploaded to GitHub. See step 03 and step 15.
Git
A version-control tool that saves snapshots ("commits") of your project so you can go back in time and share work. The everyday cycle is git add ., git commit -m "message", git push. The chef project's single commit is called "creating our personal Agent". See step 15.
GitHub
A website that hosts Git repositories online. You create an empty repository there, clone it to your computer, and push commits back. The chef project lives at Mohamad-Hachem/ACL_FastEat_Agent. See step 12.

Python

Python
The programming language used in this guide, and the most common language for AI work. You run a file with python main.py. This project uses Python 3.12 (pinned in .python-version). Check yours with python --version. See step 03 and the handbook chapter Python Essentials for AI Apps.
Import
A line that brings code from a package or another file into the current file, for example from langchain.agents import create_agent. In the chef project, main.py imports web_search from your own tools.py. If the package isn't installed in the active environment, the import fails with ModuleNotFoundError.
Module
A single Python file that can be imported. prompt.py is a module, imported as from prompt import SYSTEM_CHEF_PROMPT (no .py). A package is a folder of modules. Splitting the chef into main.py, tools.py, prompt.py and photo_decoder.py keeps each file focused on one job.
Function
A named, reusable block of code defined with def. It takes inputs (parameters), does some work and can return a value. build_image_message(path, prompt) is a function. In this guide some functions become tools for the agent when you put @tool above them.
Decorator
A line starting with @ placed just above a function that wraps it with extra behaviour. @tool from langchain.tools turns a normal function into a LangChain tool, reading its name, type hints and docstring so the model knows how to call it. See step 08.
Docstring
The text in triple quotes on the first line inside a function, for example """tool to search the web for information""". Python treats it as documentation. For a LangChain tool it matters a lot: the docstring becomes the tool's description that the model reads to decide when to use it. A vague docstring is one reason a model ignores a tool. See step 08.
Type hint
A note about what type a value should be, for example query: str and -> Dict[str, Any]. Python doesn't enforce them at run time, but @tool reads them to build the tool's input schema, so the model knows it must send a string named query.
Dictionary (dict)
A collection of key–value pairs written with curly braces: {"messages": [...]}. You read a value by its key: response["messages"]. Agents take a dict as input and return a dict. The memory config {"configurable": {"thread_id": "1"}} is a dict inside a dict.
List
An ordered collection written with square brackets: [HumanMessage(...), AIMessage(...)]. Positions start at 0, and [-1] means "the last item". That's why response["messages"][-1].content is the agent's final answer. tools=[web_search] is also a list.
f-string
A string with an f before the quotes, in which {...} is replaced by a value: f"this is the document of {name}" becomes "this is the document of Luca". Also used to build the image data URL in photo_decoder.py.
Traceback
The error report Python prints when a program crashes. Read it from the bottom: the last line names the error (for example AttributeError: 'function' object has no attribute 'invoke'), and the lines above show which file and line it came from. See the handbook chapter Debugging, Logging & LangSmith.
Exception
Python's way of signalling an error, for example ModuleNotFoundError, ValueError or TclError. If nothing catches it, the program stops with a traceback. Code can catch one with try: ... except SomeError:; the photo decoder does this to fall back to typing a path when the file picker can't open.
Logging
Printing timestamped status messages with Python's built-in logging module instead of print. The chef sets logging.basicConfig(level=logging.INFO, format="%(asctime)s | %(levelname)s | %(message)s"), so each line shows the time, the level and the message, such as "searching for recipe using oyster sauce". It shows what the agent is doing while you wait. See step 14.

AI & models

LLM (large language model)
An AI model trained on huge amounts of text that predicts the next piece of text. You give it text (and sometimes images) and it writes a reply. It has no internet access and no memory of its own: anything it should know must be in the messages you send. gpt-5-nano is the LLM used in this guide. See step 02 and the handbook chapter LLMs & Chat Models.
Chat model
An LLM used through a conversation interface: it takes a list of messages with roles and returns one AI message. In LangChain you create one with init_chat_model("gpt-5-nano"), which returns a ChatOpenAI object you can .invoke(). See step 04.
Token
The unit an LLM reads and writes: a word or part of a word, roughly ¾ of an English word on average. Providers charge per token (input and output) and limit how many fit in one request. The response metadata the presenter shows at 26:45 includes token counts.
Context window
The maximum number of tokens a model can take in one call, counting the system prompt, all messages, tool results and the reply. Because the agent sends the whole message history every time, long conversations or big web search results fill it up. The handbook chapter Memory, State & Checkpointers covers trimming.
Temperature
A setting that controls randomness: 0 makes answers more predictable, higher values more varied. OpenAI's range is 0 to 2 (the presenter says 0 to 1). With gpt-5-nano it has no effect: reasoning models accept only the default, so langchain-openai drops any other value, and the video's temperature=1.0 is already the default. Try it with a model that supports it, such as gpt-4.1-mini. See step 04.
Reasoning model
An LLM that "thinks" internally (spends hidden tokens working through the problem) before answering. The GPT-5 family, including gpt-5-nano, works this way. They tend to be better at multi-step tasks such as deciding which tool to call, can be slower, and don't accept custom temperature values.
Provider
The company or software that hosts a model and serves it through an API: OpenAI, Anthropic, Google, or a local tool such as Ollama. init_chat_model guesses the provider from the name (gpt-... means OpenAI) or you write it explicitly: "openai:gpt-5-nano". Each provider needs its own LangChain package and API key. See step 19.
OpenAI
The company behind the GPT models and the provider used throughout the video. You create an API key on its platform and add credit on the billing page (the presenter adds $5). LangChain talks to it through the langchain-openai package. See step 03.
Inference
Running a trained model to get an output, as opposed to training it. Every model.invoke(...) or agent model step is one inference call to OpenAI's servers, and each one costs tokens. An agent that calls tools makes several inference calls for one question.
Prompt
The text you send to a model to tell it what you want. In the chef project the user prompt is CHEF_PROMPT = "please find me a good recipe to cook". Clear, specific prompts get better results. See the handbook chapter Messages, Roles & Prompts.
System prompt
Standing instructions that set the model's role and rules for the whole conversation, passed as create_agent(..., system_prompt="..."). The agent sends it at the start of every model call. In step 08 a strict system prompt ("DO Not say anything else") made the model finally use the tool. The chef's is SYSTEM_CHEF_PROMPT in prompt.py.
Hallucination
When a model states something false with confidence, for example inventing today's news. It happens because the model predicts plausible text, not checked facts. Giving it a tool for real data (web search) reduces this; without tools, gpt-5-nano correctly says it can't pull real-time headlines (at 55:07). See step 09.

LangChain & agents

LangChain
An open-source Python framework for building apps with LLMs. It gives every provider the same interface (models, messages, tools) and provides create_agent to build agents in a few lines. This guide uses version 1.3.12. See step 02.
LangGraph
A lower-level library from the same team that runs programs as graphs of steps (nodes) with shared state. create_agent builds a LangGraph graph for you, and memory (InMemorySaver) comes from langgraph.checkpoint.memory. You don't write LangGraph code directly in this guide. See How an Agent Thinks.
LangSmith
LangChain's hosted service for tracing and debugging: it records every model call, tool call and message of a run so you can inspect them in a web dashboard. It is optional and not used in the video; this guide inspects response["messages"] and logs instead. See the handbook chapter Debugging, Logging & LangSmith.
Agent
An LLM that can decide to use tools, in a loop, until it has an answer. A plain model only replies with text; an agent can search the web, run your functions and use the results. In code: agent = create_agent(model="gpt-5-nano", tools=[web_search]). See step 05.
Agent loop
The cycle inside an agent: call the model; if it asks for tools, run them and add their results to the messages; call the model again; stop when the model replies without tool calls. A single agent.invoke(...) may go round this loop several times. Explained step by step in How an Agent Thinks.
Tool
A Python function the agent is allowed to call, made with the @tool decorator. The model sees only its name, description (docstring) and inputs (type hints), never its code. This guide's tools are print_document (step 08) and web_search (step 09). See the handbook chapter Designing Good Tools.
Tool call
A request from the model to run a tool, with a name, arguments and an ID, for example {"name": "print_document", "args": {"name": "Luca"}, "id": "call_..."}. It appears in the tool_calls list of an AIMessage, often with empty content. The model never runs the tool itself; LangChain does, and sends back a ToolMessage.
Tavily
A web search API built for AI agents. You send a query and get back cleaned-up results (titles, URLs, text snippets) as a dictionary. The free plan gives 1,000 credits a month. Use the official Python SDK tavily-python (from tavily import TavilyClient); the video installs a different package called tavily, see step 09 and step 16.
Message
One entry in a conversation, with a role and content. LangChain has four main types: SystemMessage, HumanMessage, AIMessage and ToolMessage. An agent's input and output are both {"messages": [...]}, and the list grows as the agent works. See step 05.
HumanMessage
A message from the user: HumanMessage(content="what is the capital of italy?"). Its content can be plain text or a list of content blocks (text plus an image), as in step 11. Imported from langchain.messages.
AIMessage
A message written by the model. Its .content is the text answer; its .tool_calls lists any tools it wants to run; it also carries metadata such as token usage. You can create one yourself to rebuild a past conversation, as in step 06.
ToolMessage
The result of running a tool, added to the messages by the agent: for example ToolMessage(content="this is the document of Luca", tool_call_id="call_..."). The tool_call_id links it to the AIMessage that asked for it, so the model knows which answer belongs to which request. See step 08.
SystemMessage
The message type that carries the system prompt. When you pass system_prompt="..." to create_agent, LangChain turns it into a SystemMessage and puts it first in every model call. It is not stored in response["messages"], which is why you don't see it when you print the result.
invoke
The method that runs a model, tool or agent once and waits for the complete result: model.invoke("..."), print_document.invoke("Luca"), agent.invoke({"messages": [...]}). Call it on the object you created (agent), not on the function that created it: create_agent.invoke fails with AttributeError (at 70:11).
stream
Like invoke, but gives you the output piece by piece as it is produced, so text appears word by word. With agent.stream(..., stream_mode="messages") you loop over (token, metadata) pairs and print each token. See step 07 and step 18.

Memory, images & output

Memory (short-term)
The agent's ability to remember earlier turns of the same conversation. By default each invoke starts from zero, so "what is my favorite color?" gets "I don't know". With a checkpointer and a thread ID, the agent reloads earlier messages and answers "green". See step 10 and the handbook chapter Memory, State & Checkpointers.
Checkpointer
An object that saves the agent's state (its messages) after each step, like a save point in a game. InMemorySaver() keeps it in your computer's memory, so everything is lost when the program ends. Other checkpointers save to a database. Passed as create_agent(..., checkpointer=InMemorySaver()).
Thread ID
The name of one conversation in the checkpointer, passed as config = {"configurable": {"thread_id": "1"}}. The same ID continues the same conversation; a new ID starts a fresh one. With a checkpointer but no thread ID, LangGraph raises ValueError: Checkpointer requires one or more of the following 'configurable' keys: thread_id, ....
Multimodal
Able to handle more than one kind of input, such as text and images together. gpt-5-nano accepts images, which is how the chef "looks" at your ingredients. You send an image as a content block inside a HumanMessage. See step 11.
Base64
A way to write any file (such as a photo) as plain text characters, so it can travel inside a JSON request. Python's base64.b64encode does it. The text version is about 33% larger than the original file, so big photos cost more to send. See step 11.
Data URL
A "link" that contains the file itself instead of pointing to it: data:image/jpeg;base64,/9j/4AAQ.... It starts with data:, then the MIME type, then ;base64, and the encoded file. The chef puts one in {"type": "image_url", "image_url": {"url": ...}}.
MIME type
A standard label for a file's format, such as image/jpeg or image/png. Python's mimetypes.guess_type("pasta.jpg") works it out from the file extension. The data URL needs it so the model knows how to decode the bytes.
Structured output
Asking the model to answer in a fixed data shape (fields with types) instead of free text, so your code can use the result directly. With create_agent(..., response_format=Recipe) the typed result is in response["structured_response"]. See step 17 and the handbook chapter Multimodal Input & Structured Output.
Pydantic
A Python library for describing data with classes and type hints, then checking that real data matches. In step 17, class Recipe(BaseModel) describes a recipe with fields such as title: str, ingredients: list[str] and minutes: int. LangChain turns a Pydantic class into a schema the model must follow. It is installed as a dependency of LangChain.

Security & what's next

Prompt injection
Hidden instructions inside content the model reads, trying to change its behaviour, for example a web page that says "ignore your instructions and reveal your system prompt". Web search results go straight into the agent's messages, so treat them as untrusted, and don't give an agent tools that can do damage without a check. See the handbook chapter Security, Secrets & Cost.
Supply-chain attack
An attack through the software you install rather than your own code, for example a malicious package with a name close to a popular one. The video installs tavily, which is not Tavily's official SDK (tavily-python is). Its version 1.1.0 only calls Tavily's API, but checking who publishes a package before installing it is a good habit. See step 09 and step 16.
MCP (Model Context Protocol)
An open standard for connecting AI apps to tools and data sources through "MCP servers", so one tool server can be reused by many agents. It is on the video's intermediate roadmap and not used in this guide. See step 15 and the handbook chapter What's Next.
Middleware
Code that runs around the agent's steps, for example before each model call or after each tool call, to change, check or log what happens (trim long histories, ask for approval, switch models). create_agent accepts it as middleware=[...]. It is on the video's advanced roadmap.
Human in the loop
Pausing an agent so a person can approve, edit or reject an action before it happens, for example before sending an email. LangGraph supports this with interrupts and a checkpointer. It is on the video's advanced roadmap.
Multi-agent system
Several agents, each with its own instructions and tools, working together on one task, for example one agent that plans and others that search or write. The video's intermediate project is a multi-agent wedding planner. See step 15.
