Glossary

Every technical term in this guide, explained for beginners.

Every technical word used in this guide, explained in plain language. Pages link here the first time a term appears, so you can always come back. Terms are grouped by topic. Most entries point to the step where you first use the idea, and some point to the handbook chapter that goes deeper. Where the TypeScript version of the project does something differently, the entry says so in its last sentences; the words only TypeScript needs are in the last section, TypeScript and the web app.

Two maps to start with

Before the individual words, here is how they fit together. The first map shows where each piece of the project lives. The second shows how the AI ideas connect inside an agent.

Tools & the command line

Terminal (command line)
A text window where you type commands instead of clicking. In VS Code, open it with Ctrl+`. On Windows the presenter's terminal is PowerShell. Lines in this guide such as uv add langchain are typed there and run with Enter. First used in step 03. In the TypeScript version you type pnpm commands there instead, such as pnpm lesson 04.
VS Code (Visual Studio Code)
A free code editor from Microsoft, used by the presenter throughout the video. It has a file explorer on the left, editor tabs in the middle and a built-in terminal at the bottom. The status bar at the bottom right shows which Python interpreter (and virtual environment) is active. See step 03.
pip
Python's standard package installer. pip install X downloads package X from PyPI (the Python Package Index). In this project pip is only used once, to install uv itself: pip install uv. After that, uv does the work. See step 03.
uv
A fast Python project and package manager. It creates the project (uv init), the virtual environment (uv venv --python 3.12), adds packages (uv add langchain) and records exact versions in uv.lock. A teammate who clones the repo runs uv sync to get the same packages. See step 03 and step 13. The TypeScript version uses pnpm instead: pnpm install plays the role of uv sync.
Virtual environment (.venv)
A private folder of Python packages for one project, so projects don't fight over versions. uv creates it as .venv inside the project folder. Everything you install with uv add goes there, not into your system Python. It is never committed to Git: it is listed in .gitignore and can always be rebuilt with uv sync. TypeScript has no virtual environment: pnpm install puts the packages in the project's own node_modules folder, which is listed in the TypeScript .gitignore.
Activating the virtual environment
Telling your terminal to use the .venv Python instead of the system one. On Windows PowerShell: .venv\Scripts\activate. On macOS/Linux: source .venv/bin/activate. The prompt then starts with the environment's name. Forgetting this step is a common cause of ModuleNotFoundError; it happens in the video too (at 81:41). See step 03. The TypeScript version has nothing to activate: pnpm commands always use the project's node_modules folder.
Package
Reusable code someone else wrote and published, which you install by name. langchain, langchain-openai, langgraph and python-dotenv are packages. Note that the name you install can differ from the name you import: you install python-dotenv but write from dotenv import load_dotenv. TypeScript packages come from npm, for example langchain, @langchain/openai, @langchain/tavily, dotenv and zod.
Dependency
A package your project needs in order to run. Your direct dependencies are listed in pyproject.toml; their own dependencies (for example langchain pulls in langgraph and langchain-core) are recorded in uv.lock. Choose dependencies carefully: each one is code that runs on your machine (see supply-chain attack). In TypeScript the direct dependencies are listed in package.json and every exact version is recorded in pnpm-lock.yaml.
pyproject.toml
The project's settings file, created by uv init. It holds the project name, the required Python version and the list of dependencies. uv add X writes X into it for you. See the repo's version in step 03. The TypeScript counterpart is package.json: the project name (fasteat-agent-ts), the dependencies, the Node.js version ("engines") and the short commands under "scripts", such as lesson, chef, test and api.
Lockfile (uv.lock)
A file that records the exact version of every package, including indirect ones. Two people running uv sync with the same lockfile get identical environments. This guide's code was tested against the repo's lockfile: langchain 1.3.12, langgraph 1.2.9, langchain-openai 1.3.4. Commit it to Git. The TypeScript project's lockfile is pnpm-lock.yaml. Its main versions: langchain 1.5.16, @langchain/core 1.2.17, @langchain/langgraph 1.5.0, @langchain/openai 1.6.2.
.env file
A plain text file of NAME=value lines that holds secrets such as OPENAI_API_KEY and TAVILY_API_KEY. load_dotenv() reads it and puts the values into environment variables, where the OpenAI and Tavily clients look for them. It must be listed in .gitignore so it never reaches GitHub. See step 03. In TypeScript one line loads it: import "dotenv/config";. The TypeScript .env.example adds MODEL_PROVIDER (openai or ollama), and TAVILY_API_KEY is optional there.
API key
A long secret string that identifies you to a paid service, like a password for programs. OpenAI uses it to bill your account; Tavily uses it to count your search credits. Keep it only in .env, never in code or screenshots. If a key leaks, delete it in the provider's dashboard and create a new one. Without it you get OpenAIError: Missing credentials (seen at 69:24). In TypeScript the error comes at the first model call, not when the model is created: OpenAIError: Missing credentials. Please pass an `apiKey`, …. With MODEL_PROVIDER=ollama no key is needed.
.gitignore
A file listing paths Git should ignore. In this project it contains .env (secrets) and __pycache__/ (Python's compiled-file cache), which the presenter adds after spotting it in git status (at 101:56). The .venv folder stays out too, because uv puts its own small .gitignore inside it. Ignored files never get uploaded to GitHub. See step 03 and step 15. The TypeScript .gitignore lists node_modules/, .env and dist/.
Git
A version-control tool that saves snapshots ("commits") of your project so you can go back in time and share work. The everyday cycle is git add ., git commit -m "message", git push. The chef project's single commit is called "creating our personal Agent". See step 15.
GitHub
A website that hosts Git repositories online. You create an empty repository there, clone it to your computer, and push commits back. The chef project lives at Mohamad-Hachem/ACL_FastEat_Agent. See step 12.

Python

Python
The programming language used in this guide, and the most common language for AI work. You run a file with python main.py. This project uses Python 3.12 (pinned in .python-version). Check yours with python --version. See step 03 and the handbook chapter Python Essentials for AI Apps. The TypeScript version runs on Node.js instead; see TypeScript.
Import
A line that brings code from a package or another file into the current file, for example from langchain.agents import create_agent. In the chef project, main.py imports web_search from your own tools.py. If the package isn't installed in the active environment, the import fails with ModuleNotFoundError. In TypeScript: import { createAgent } from "langchain";. Your own files are imported with a .js ending, as in import { getModel } from "../src/models.js"; (see ESM).
Module
A single Python file that can be imported. prompt.py is a module, imported as from prompt import SYSTEM_CHEF_PROMPT (no .py). A package is a folder of modules. Splitting the chef into main.py, tools.py, prompt.py and photo_decoder.py keeps each file focused on one job. In TypeScript each .ts file is a module too. It shares a name with export, for example export const webSearch = tool(...) in chef/tools.ts.
Function
A named, reusable block of code defined with def. It takes inputs (parameters), does some work and can return a value. build_image_message(path, prompt) is a function. In this guide some functions become tools for the agent when you put @tool above them. In TypeScript a function is written function name(...) { ... } or as an arrow function, such as ({ name }) => `this is the document of ${name}`.
Decorator
A line starting with @ placed just above a function that wraps it with extra behaviour. @tool from langchain.tools turns a normal function into a LangChain tool, reading its name, type hints and docstring so the model knows how to call it. See step 08. TypeScript uses no decorator here: tool(fn, { name, description, schema }) from langchain wraps the function instead.
Docstring
The text in triple quotes on the first line inside a function, for example """tool to search the web for information""". Python treats it as documentation. For a LangChain tool it matters a lot: the docstring becomes the tool's description that the model reads to decide when to use it. A vague docstring is one reason a model ignores a tool. See step 08. In TypeScript the tool's description is written out as an option: description: "...".
Type hint
A note about what type a value should be, for example query: str and -> Dict[str, Any]. Python doesn't enforce them at run time, but @tool reads them to build the tool's input schema, so the model knows it must send a string named query. TypeScript types look similar (query: string) but are removed before the code runs, so a tool's arguments are described with a Zod schema instead: z.object({ query: z.string() }).
Dictionary (dict)
A collection of key–value pairs written with curly braces: {"messages": [...]}. You read a value by its key: response["messages"]. Agents take a dict as input and return a dict. The memory config {"configurable": {"thread_id": "1"}} is a dict inside a dict. In TypeScript it is an object: { messages: [...] }, read with response.messages. The memory config is { configurable: { thread_id: "1" } }.
List
An ordered collection written with square brackets: [HumanMessage(...), AIMessage(...)]. Positions start at 0, and [-1] means "the last item". That's why response["messages"][-1].content is the agent's final answer. tools=[web_search] is also a list. In TypeScript it is an array, and the last item is response.messages.at(-1); the lessons print response.messages.at(-1)?.text.
f-string
A string with an f before the quotes, in which {...} is replaced by a value: f"this is the document of {name}" becomes "this is the document of Luca". Also used to build the image data URL in photo_decoder.py. In TypeScript it is a template literal, written in backticks: `this is the document of ${name}`.
Traceback
The error report Python prints when a program crashes. Read it from the bottom: the last line names the error (for example AttributeError: 'function' object has no attribute 'invoke'), and the lines above show which file and line it came from. See the handbook chapter Debugging, Logging & LangSmith. Node.js prints an uncaught error the other way round: the line that threw, then the error's name and message, then the at … lines of the calls. In TypeScript, read it from the top.
Exception
Python's way of signalling an error, for example ModuleNotFoundError, ValueError or TclError. If nothing catches it, the program stops with a traceback. Code can catch one with try: ... except SomeError:; the photo decoder does this to fall back to typing a path when the file picker can't open. In TypeScript errors are thrown and caught with try { ... } catch (error) { ... }.
Logging
Printing timestamped status messages with Python's built-in logging module instead of print. The chef sets logging.basicConfig(level=logging.INFO, format="%(asctime)s | %(levelname)s | %(message)s"), so each line shows the time, the level and the message, such as "searching for recipe using oyster sauce". It shows what the agent is doing while you wait. See step 14. In TypeScript, src/logger.ts prints the same format to stderr: log.info("...").

AI & models

LLM (large language model)
An AI model trained on huge amounts of text that predicts the next piece of text. You give it text (and sometimes images) and it writes a reply. It has no internet access and no memory of its own: anything it should know must be in the messages you send. gpt-5-nano is the LLM used in this guide. See step 02 and the handbook chapter LLMs & Chat Models.
Chat model
An LLM used through a conversation interface: it takes a list of messages with roles and returns one AI message. In LangChain you create one with init_chat_model("gpt-5-nano"), which returns a ChatOpenAI object you can .invoke(). See step 04. In TypeScript: await initChatModel("gpt-5-nano") (it is asynchronous), or getModel() from src/models.ts, which returns a ChatOpenAI or a ChatOllama object.
Token
The unit an LLM reads and writes: a word or part of a word, roughly ¾ of an English word on average. Providers charge per token (input and output) and limit how many fit in one request. The response metadata the presenter shows at 26:45 includes token counts.
Context window
The maximum number of tokens a model can take in one call, counting the system prompt, all messages, tool results and the reply. Because the agent sends the whole message history every time, long conversations or big web search results fill it up. The handbook chapter Memory, State & Checkpointers covers trimming.
Temperature
A setting that controls randomness: 0 makes answers more predictable, higher values more varied. OpenAI's range is 0 to 2 (the presenter says 0 to 1). With gpt-5-nano it has no effect: reasoning models accept only the default, so langchain-openai drops any other value, and the video's temperature=1.0 is already the default. Try it with a model that supports it, such as gpt-4.1-mini. See step 04. TypeScript is different: @langchain/openai 1.6.2 sends the temperature you give it. OpenAI documents only the default (1) for GPT-5 models, so another value would likely be rejected by the API (not verified: no key). On Ollama temperature works normally, and src/models.ts sets 0.
Reasoning model
An LLM that "thinks" internally (spends hidden tokens working through the problem) before answering. The GPT-5 family, including gpt-5-nano, works this way. They tend to be better at multi-step tasks such as deciding which tool to call, can be slower, and don't accept custom temperature values.
Provider
The company or software that hosts a model and serves it through an API: OpenAI, Anthropic, Google, or a local tool such as Ollama. init_chat_model guesses the provider from the name (gpt-... means OpenAI) or you write it explicitly: "openai:gpt-5-nano". Each provider needs its own LangChain package and API key. See step 19. In TypeScript the provider part uses a dash where Python uses an underscore ("google-genai:..."), and src/models.ts switches between OpenAI and Ollama with MODEL_PROVIDER.
OpenAI
The company behind the GPT models and the provider used throughout the video. You create an API key on its platform and add credit on the billing page (the presenter adds $5). LangChain talks to it through the langchain-openai package. See step 03. In TypeScript the package is @langchain/openai.
Inference
Running a trained model to get an output, as opposed to training it. Every model.invoke(...) or agent model step is one inference call to OpenAI's servers, and each one costs tokens. An agent that calls tools makes several inference calls for one question.
Prompt
The text you send to a model to tell it what you want. In the chef project the user prompt is CHEF_PROMPT = "please find me a good recipe to cook". Clear, specific prompts get better results. See the handbook chapter Messages, Roles & Prompts.
System prompt
Standing instructions that set the model's role and rules for the whole conversation, passed as create_agent(..., system_prompt="..."). The agent sends it at the start of every model call. In step 08 a strict system prompt ("DO Not say anything else") made the model finally use the tool. The chef's is SYSTEM_CHEF_PROMPT in prompt.py.
Hallucination
When a model states something false with confidence, for example inventing today's news. It happens because the model predicts plausible text, not checked facts. Giving it a tool for real data (web search) reduces this; without tools, gpt-5-nano correctly says it can't pull real-time headlines (at 55:07). See step 09.

LangChain & agents

LangChain
An open-source Python framework for building apps with LLMs. It gives every provider the same interface (models, messages, tools) and provides create_agent to build agents in a few lines. This guide uses version 1.3.12. See step 02. It also exists for JavaScript and TypeScript (LangChain.js): the TypeScript version uses langchain 1.5.16 from npm, with initChatModel and createAgent.
LangGraph
A lower-level library from the same team that runs programs as graphs of steps (nodes) with shared state. create_agent builds a LangGraph graph for you, and memory (InMemorySaver) comes from langgraph.checkpoint.memory. You don't write LangGraph code directly in this guide. See How an Agent Thinks. In TypeScript it is @langchain/langgraph 1.5.0, and the memory class is called MemorySaver.
LangSmith
LangChain's hosted service for tracing and debugging: it records every model call, tool call and message of a run so you can inspect them in a web dashboard. It is optional and not used in the video; this guide inspects response["messages"] and logs instead. See the handbook chapter Debugging, Logging & LangSmith.
Agent
An LLM that can decide to use tools, in a loop, until it has an answer. A plain model only replies with text; an agent can search the web, run your functions and use the results. In code: agent = create_agent(model="gpt-5-nano", tools=[web_search]). See step 05. In TypeScript: createAgent({ model: "gpt-5-nano", tools: [webSearch] }).
Agent loop
The cycle inside an agent: call the model; if it asks for tools, run them and add their results to the messages; call the model again; stop when the model replies without tool calls. A single agent.invoke(...) may go round this loop several times. Explained step by step in How an Agent Thinks.
Tool
A Python function the agent is allowed to call, made with the @tool decorator. The model sees only its name, description (docstring) and inputs (type hints), never its code. This guide's tools are print_document (step 08) and web_search (step 09). See the handbook chapter Designing Good Tools. In TypeScript a tool is made with tool(fn, { name, description, schema }); the chef's is webSearch in chef/tools.ts, still named web_search for the model.
Tool call
A request from the model to run a tool, with a name, arguments and an ID, for example {"name": "print_document", "args": {"name": "Luca"}, "id": "call_..."}. It appears in the tool_calls list of an AIMessage, often with empty content. The model never runs the tool itself; LangChain does, and sends back a ToolMessage.
Tavily
A web search API built for AI agents. You send a query and get back cleaned-up results (titles, URLs, text snippets) as a dictionary. The free plan gives 1,000 credits a month. Use the official Python SDK tavily-python (from tavily import TavilyClient); the video installs a different package called tavily, see step 09 and step 16. The TypeScript version uses @langchain/tavily, the official LangChain.js integration published by LangChain, so the look-alike problem does not apply. Without TAVILY_API_KEY its search tool answers "Web search is not configured (no TAVILY_API_KEY)." and the agent carries on.
Message
One entry in a conversation, with a role and content. LangChain has four main types: SystemMessage, HumanMessage, AIMessage and ToolMessage. An agent's input and output are both {"messages": [...]}, and the list grows as the agent works. See step 05.
HumanMessage
A message from the user: HumanMessage(content="what is the capital of italy?"). Its content can be plain text or a list of content blocks (text plus an image), as in step 11. Imported from langchain.messages. In TypeScript: new HumanMessage("..."), imported from langchain.
AIMessage
A message written by the model. Its .content is the text answer; its .tool_calls lists any tools it wants to run; it also carries metadata such as token usage. You can create one yourself to rebuild a past conversation, as in step 06. In TypeScript, .text gives the plain text whatever shape .content has.
ToolMessage
The result of running a tool, added to the messages by the agent: for example ToolMessage(content="this is the document of Luca", tool_call_id="call_..."). The tool_call_id links it to the AIMessage that asked for it, so the model knows which answer belongs to which request. See step 08.
SystemMessage
The message type that carries the system prompt. When you pass system_prompt="..." to create_agent, LangChain turns it into a SystemMessage and puts it first in every model call. It is not stored in response["messages"], which is why you don't see it when you print the result. In TypeScript the option is spelled systemPrompt.
invoke
The method that runs a model, tool or agent once and waits for the complete result: model.invoke("..."), print_document.invoke("Luca"), agent.invoke({"messages": [...]}). Call it on the object you created (agent), not on the function that created it: create_agent.invoke fails with AttributeError (at 70:11). In TypeScript every call is asynchronous: await agent.invoke({ messages: [...] }) (see async/await).
stream
Like invoke, but gives you the output piece by piece as it is produced, so text appears word by word. With agent.stream(..., stream_mode="messages") you loop over (token, metadata) pairs and print each token. See step 07 and step 18. In TypeScript: const stream = await agent.stream(input, { streamMode: "messages" }), then for await (const [token, metadata] of stream).

Memory, images & output

Memory (short-term)
The agent's ability to remember earlier turns of the same conversation. By default each invoke starts from zero, so "what is my favorite color?" gets "I don't know". With a checkpointer and a thread ID, the agent reloads earlier messages and answers "green". See step 10 and the handbook chapter Memory, State & Checkpointers.
Checkpointer
An object that saves the agent's state (its messages) after each step, like a save point in a game. InMemorySaver() keeps it in your computer's memory, so everything is lost when the program ends. Other checkpointers save to a database. Passed as create_agent(..., checkpointer=InMemorySaver()). In TypeScript the class is MemorySaver from @langchain/langgraph (it has no InMemorySaver), passed as checkpointer: new MemorySaver().
Thread ID
The name of one conversation in the checkpointer, passed as config = {"configurable": {"thread_id": "1"}}. The same ID continues the same conversation; a new ID starts a fresh one. With a checkpointer but no thread ID, LangGraph raises ValueError: Checkpointer requires one or more of the following 'configurable' keys: thread_id, .... In TypeScript the error reads Error: Failed to put checkpoint. The passed RunnableConfig is missing a required "thread_id" field in its "configurable" property. …
Multimodal
Able to handle more than one kind of input, such as text and images together. gpt-5-nano accepts images, which is how the chef "looks" at your ingredients. You send an image as a content block inside a HumanMessage. See step 11. On Ollama, llama3.2 cannot see images, so the TypeScript photo runs use gemma4, a vision model.
Base64
A way to write any file (such as a photo) as plain text characters, so it can travel inside a JSON request. Python's base64.b64encode does it. The text version is about 33% larger than the original file, so big photos cost more to send. See step 11. In TypeScript: readFileSync(path).toString("base64").
Data URL
A "link" that contains the file itself instead of pointing to it: data:image/jpeg;base64,/9j/4AAQ.... It starts with data:, then the MIME type, then ;base64, and the encoded file. The chef puts one in {"type": "image_url", "image_url": {"url": ...}}.
MIME type
A standard label for a file's format, such as image/jpeg or image/png. Python's mimetypes.guess_type("pasta.jpg") works it out from the file extension. The data URL needs it so the model knows how to decode the bytes. Node.js has no built-in lookup, so the TypeScript photo decoder uses a small table by file extension (png, jpg/jpeg, webp, gif).
Structured output
Asking the model to answer in a fixed data shape (fields with types) instead of free text, so your code can use the result directly. With create_agent(..., response_format=Recipe) the typed result is in response["structured_response"]. See step 17 and the handbook chapter Multimodal Input & Structured Output. In TypeScript: createAgent({ ..., responseFormat: Recipe }), then response.structuredResponse. In a real run with gemma4 on Ollama it came back empty: the model answered in plain text instead of calling the Recipe tool.
Pydantic
A Python library for describing data with classes and type hints, then checking that real data matches. In step 17, class Recipe(BaseModel) describes a recipe with fields such as title: str, ingredients: list[str] and minutes: int. LangChain turns a Pydantic class into a schema the model must follow. It is installed as a dependency of LangChain. In TypeScript the same job is done by Zod.

Security & what's next

Prompt injection
Hidden instructions inside content the model reads, trying to change its behaviour, for example a web page that says "ignore your instructions and reveal your system prompt". Web search results go straight into the agent's messages, so treat them as untrusted, and don't give an agent tools that can do damage without a check. See the handbook chapter Security, Secrets & Cost.
Supply-chain attack
An attack through the software you install rather than your own code, for example a malicious package with a name close to a popular one. The video installs tavily, which is not Tavily's official SDK (tavily-python is). Its version 1.1.0 only calls Tavily's API, but checking who publishes a package before installing it is a good habit. See step 09 and step 16. The TypeScript version uses @langchain/tavily, published by LangChain from its langchainjs repository.
MCP (Model Context Protocol)
An open standard for connecting AI apps to tools and data sources through "MCP servers", so one tool server can be reused by many agents. It is on the video's intermediate roadmap and not used in this guide. See step 15 and the handbook chapter What's Next.
Middleware
Code that runs around the agent's steps, for example before each model call or after each tool call, to change, check or log what happens (trim long histories, ask for approval, switch models). create_agent accepts it as middleware=[...]. It is on the video's advanced roadmap.
Human in the loop
Pausing an agent so a person can approve, edit or reject an action before it happens, for example before sending an email. LangGraph supports this with interrupts and a checkpointer. It is on the video's advanced roadmap.
Multi-agent system
Several agents, each with its own instructions and tools, working together on one task, for example one agent that plans and others that search or write. The video's intermediate project is a multi-agent wedding planner. See step 15.

TypeScript and the web app

Every program of the course also exists in TypeScript, in the folder fasteat-agent-ts, plus a React web app (step 20). Pick the language with the "Code in:" switch at the top of each step page. These are the words that only the TypeScript version needs.

TypeScript
JavaScript with types added: you can write that a variable holds a string or that a function returns a list of messages, and the checker (tsc, run with pnpm typecheck) reports mistakes before you run anything. The types are removed before the code runs, so it runs wherever JavaScript runs. The TypeScript version of this course uses LangChain.js 1.x and runs with tsx on Node.js. Setup is in step 03.
Node.js
The program that runs JavaScript outside the browser, on your computer or a server. The TypeScript lessons, the chef and the web app's server run on it. The project needs version 22 or newer ("engines" in package.json); the guide's runs used Node 24.15. It comes with npm, and you install pnpm on top of it.
pnpm
A package manager for Node.js, the TypeScript counterpart of uv. pnpm install installs the exact versions recorded in pnpm-lock.yaml. pnpm lesson 04, pnpm chef data/fridge.png, pnpm test or pnpm api run the short commands defined under "scripts" in package.json. The web server's script is called api, not server, because pnpm server is one of pnpm's own commands and would exit without doing anything.
tsx
A small tool that runs a TypeScript file directly, converting it to JavaScript on the fly, so there is no separate build step. pnpm lesson and pnpm chef run tsx scripts/run.ts, which then starts the lesson or chef file you named. tsx only converts; it does not check types (that is pnpm typecheck). Not to be confused with .tsx, the file extension for TypeScript with JSX used by React.
ESM (ES modules)
The standard JavaScript module system: files share code with import and export. The TypeScript project is set to ESM ("type": "module" in package.json). That is why your own imports end in .js even for .ts files ("../src/models.js"), and why await can be used at the top level of a lesson file, outside any function.
async / await
JavaScript's way of waiting for slow work, such as a model call, without freezing the program. A function marked async returns a promise (a result that will arrive later), and await waits for it. In LangChain.js almost every call is asynchronous: await initChatModel(...), await agent.invoke(...), and for await (const [token, metadata] of stream) to read a stream. Forgetting await gives you a pending promise instead of the answer.
Zod
A TypeScript library for describing the shape of data, the counterpart of Pydantic. z.object({ query: z.string() }) both checks data at run time and gives you a type. LangChain.js uses Zod for the arguments of a tool (the Python version reads type hints instead) and for structured output: the chef's Recipe in step 17.
Vitest
A test runner for TypeScript and JavaScript. pnpm test runs the 23 offline tests in tests/offline.test.ts. They run every lesson and chef file with a pretend model (tests/fake-model.ts), a canned search result and a pretend terminal, so no key and no network are needed. They check the message flow, not what a real model would answer.
Ollama
A free program that downloads and runs open models on your own computer and serves them through a local API, so no API key is needed. In the TypeScript version, MODEL_PROVIDER=ollama in .env switches every file from OpenAI to Ollama: llama3.2 for text and gemma4 for photos. Every real TypeScript output in this guide comes from Ollama on a laptop, because the guide had no OpenAI or Tavily key. In Python, step 19 shows the ollama:llama3.2 model string.
Vision model
A multimodal model that accepts images as input. gpt-5-nano is one. On Ollama, llama3.2 is text-only, while gemma4 lists "vision" among its capabilities, so getVisionModel() in src/models.ts returns gemma4 for lesson 11 and the chef. The web app does it in two steps: the vision model lists the ingredients, then a text-only chef (llama3.2) writes the recipe.
Recursion limit
A safety net that stops an agent loop that never finishes. LangGraph counts the steps of one run and raises an error when the limit is reached; it was 25 in the TypeScript run. In the real run of lesson 08, llama3.2 kept calling print_document (13 calls) until it stopped with GraphRecursionError: Recursion limit of 25 reached without hitting a stop condition. You can increase the limit by setting the "recursionLimit" config key. The system prompt said "DO Not say anything else", so the small model never wrote a final answer. See step 08.
React
A JavaScript library for building user interfaces from components. You keep data in state and describe what the page should look like for that state; React updates the page when the state changes. The web app of step 20 is one main component, web/src/App.tsx.
React component
A function that returns a description of part of the page, written in JSX (HTML-like tags inside TypeScript, in .tsx files). React calls it again whenever its state changes. Components can contain other components, like <App /> inside <StrictMode> in web/src/main.tsx.
React hook
A function whose name starts with use and that gives a component extra abilities. useState gives it memory between redraws: const [busy, setBusy] = useState(false) returns the current value and a setter, and calling the setter makes React redraw. Hooks must be called at the top level of the component, never inside a condition or loop.
Vite
A development server and build tool for web front ends. pnpm web starts it on port 5173. It converts .tsx files for the browser on request and reloads the page when you save. It also works as a proxy: requests to /api are forwarded to the Hono server on port 8787, so the browser sees a single address.
Hono
A small web framework for TypeScript. The web app's server (server/app.ts) registers one function per endpoint with app.post("/api/photo", ...) and starts on Node.js with @hono/node-server (pnpm api). Its streamSSE helper writes Server-Sent Events.
API endpoint
One address on a server plus an HTTP method, such as POST /api/chat, that runs code and returns data rather than a web page. The step 20 server has two: POST /api/photo receives the photo (base64, at most 5 MB, PNG, JPEG, WebP or GIF) and POST /api/chat receives a follow-up question for the same conversation.
SSE (Server-Sent Events)
A simple way for a server to push a stream of messages to a browser over one HTTP response that stays open. Each message has an event: line, a data: line and a blank line after it. The web app's events are ingredients, token, tool_call, tool_result, then done or error. It is the browser counterpart of stream.
