Streaming Responses

agent.stream with stream_mode="messages" to print tokens as they arrive.

▶ Watch this part (31:45)

Goal

"There's one thing that is bothering me that every time I need to wait for these results" (31:23). Long answers like the one about Rome take several seconds, and with invoke you see nothing until the very end. In this step you switch to agent.stream(...), which hands you the answer piece by piece while the model is still writing, and you print each piece the moment it arrives.

The chef project uses invoke, but the chat version in step 18 streams every answer with exactly this loop. It's the difference between staring at a frozen terminal and watching the reply being typed.

invoke vs stream

"Stream works like invoke but it's actually giving us token by token instead of giving us the whole thing, and you can choose what to pick depending on your application" (34:27). Both send the same request to the model and the model generates the answer at the same speed. The only difference is when you get to see it.

New to streaming? Where the pieces come from

A model writes its answer one token at a time, each new token chosen after the previous ones. OpenAI can send each piece over the network as soon as it exists, instead of collecting the whole answer first.

To stream means to receive and use those pieces as they arrive. In LangChain each piece is an AIMessageChunk: a small, partial AIMessage whose content holds just that bit of text (often a word or part of a word; the presenter calls them tokens). Glue all the chunks together and you get the same text invoke would have returned.

from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain.agents import create_agent
from langchain.messages import HumanMessage, AIMessage

load_dotenv()

# 0 to 1 from least creative to most creative
# model = init_chat_model(model="gpt-5-nano",temperature=1.0)

agent = create_agent(model="gpt-5-nano")


for token, metadata in agent.stream(
    {"messages": [HumanMessage(content="what is the capital of italy?"),
                  AIMessage(content="Rome (Italian: Roma)."),
                  HumanMessage(content="tell me more about it")]},
                  stream_mode="messages"
):
    if token.content:
        print(token.content, end="", flush=True)
import "dotenv/config";
import { AIMessage, createAgent, HumanMessage } from "langchain";
import { MODEL_ID } from "../src/models.js";

const agent = createAgent({ model: MODEL_ID });

const stream = await agent.stream(
  {
    messages: [
      new HumanMessage("what is the capital of italy?"),
      new AIMessage("Rome (Italian: Roma)."),
      new HumanMessage("tell me more about it"),
    ],
  },
  { streamMode: "messages" },
);

for await (const [token, metadata] of stream) {
  if (token.text) {
    process.stdout.write(token.text);
  }
}

New to for await and array destructuring? Reading line 18

A normal for (const fruit of ["apple", "pear"]) loop runs its block once per item. for await (const x of stream) does the same for items that arrive over time: it waits for the next piece, runs the block, then waits again, until the stream ends.

Each item here is an array of two values, [chunk, metadata]. Writing const [token, metadata] in the loop header gives both values a name in one go. That is called destructuring; the names are your choice, and their order matches the order in the array.

Like Python's agent.stream, the stream does not build a list first. Each piece is produced while the model is still writing, which is what makes the output live.

New to for loops and tuple unpacking? Reading line 14

A for loop repeats its indented block once for every item something produces:

for fruit in ["apple", "pear"]:
    print(fruit)        # runs twice: apple, then pear

A tuple is a fixed group of values in parentheses, like ("Rome", {"step": 1}). If every item is a pair, you can give both parts a name right in the loop header. That is called unpacking:

for word, number in [("one", 1), ("two", 2)]:
    print(word, number) # one 1, then two 2

Line 14 does the same: each item from agent.stream(..., stream_mode="messages") is a pair (message chunk, metadata). The presenter calls the first one token. The names are your choice; the number of names must match the number of values in each item.

One special thing about agent.stream: it doesn't make a list first. Each item is produced only when the loop asks for the next one, while the model is still writing. That's what makes the output live.

New to process.stdout.write? Printing without a line break

console.log("Rome") always adds a line break after its text. For streamed pieces you want them side by side, so the file uses process.stdout.write(text), which writes exactly the text you give it and nothing more. The pieces already contain their own spaces, like " capital".

There is no flush option to remember here. If you use console.log(token.text) by mistake, you get one piece per line.

New to print's options? end and flush

By default, print("Rome") adds a line break at the end: it's really print("Rome", end="\n"). When printing chunks, you want them side by side, so you pass end="" (nothing at the end). The chunks already contain their own spaces, like " capital".

Python also buffers output: it collects printed text in memory and writes it to the screen in batches, usually when a line ends. With end="" no line ends, so the text could sit in the buffer. flush=True forces Python to write it out immediately, which is what makes streaming visible.

What you should see: the answer about Rome appears in the terminal a few words at a time, all on flowing lines, instead of all at once after a pause. The final text is similar to step 6's (the wording varies from run to run). When it ends, your terminal prompt may appear right after the last word, because nothing printed a final line break; add a plain print()console.log() after the loop if that bothers you.

Other stream modes

The video only uses "messages". For orientation, here are two more modes the agent supports. In TypeScript the option is called streamMode and takes the same three values. You don't need them for this course; they're shown so the word "mode" makes sense.

stream_modeEach item is…Good for
"messages"a pair (chunk, metadata), many per answerShowing text live, as in this step and step 18
"updates" (the agent's default)a dictionary with what one step just added, e.g. {"model": {"messages": [AIMessage(...)]}}Following progress step by step: "model answered", "tool ran"
"values"the whole state after each step: {"messages": [...all so far...]}Debugging: seeing the full message list grow

Common mistakes:

  • Forgetting { streamMode: "messages" }: the default mode yields one object per finished step, not [chunk, metadata] pairs, so const [token, metadata] on line 18 cannot split them and the loop fails with a TypeError.
  • Forgetting await on line 7: stream is then a Promise, not a stream, and the loop fails with a TypeError. The editor usually warns you first.
  • Using console.log(token.text): every piece lands on its own line. Use process.stdout.write.
  • Printing token instead of token.text: you see whole AIMessageChunk objects instead of text.
  • Later, once your agent has tools: "messages" mode also yields the tool messages, so this loop would print tool results too. Step 18 prints only AIMessageChunk text to avoid that.

Common mistakes:

  • Forgetting stream_mode="messages": the default mode yields one-key dictionaries such as {"model": {...}}, and the loop crashes with ValueError: not enough values to unpack (expected 2, got 1).
  • for token in agent.stream(..., stream_mode="messages") (one name): no error, but token is now the whole pair, and token.content raises AttributeError: 'tuple' object has no attribute 'content'.
  • Missing comma between the messages dictionary and stream_mode=...: SyntaxError.
  • Forgetting the colon after ) on line 19, or not indenting lines 20–21: SyntaxError / IndentationError.
  • Printing token instead of token.content: you see AIMessageChunk(content=..., ...) objects instead of text.
  • Later, once your agent has tools: "messages" mode also yields the tool messages, so this loop would print tool results too. Step 18 prints only AIMessageChunk text to avoid that.
Recap
  • agent.stream(...) runs the same agent as invoke but hands you results while they are being produced.
  • With stream_mode="messages" each item is a pair (chunk, metadata); for token, metadata in ... unpacks it.
  • if token.content: skips empty chunks; print(..., end="", flush=True) shows the text live on one line.
  • Stream when a person is watching; invoke when your code needs the full result.
  • In TypeScript: const stream = await agent.stream(input, { streamMode: "messages" }), then for await (const [token, metadata] of stream) and process.stdout.write(token.text).
