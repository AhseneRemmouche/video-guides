Project Setup with uv

Python 3.12, a uv project, a virtual environment, .env keys for OpenAI and Tavily, and .gitignore.

▶ Watch this part (08:33)

Goal

Prepare everything the lessons need: a project folder, Python 3.12, a project managed by uv, a virtual environment, a secret .env file with your OpenAI and Tavily keys, a .gitignore that keeps those keys out of Git, some credit on your OpenAI account, and LangChain installed. This is the part of the video from 08:33 to 15:51.

Take your time here. Nearly every error in later steps ("module not found", "missing credentials") traces back to one detail of this setup.

New to the terminal? What it is and how to open it in VS Code

The terminal is a window where you type commands instead of clicking. Each command is a program name followed by words that tell it what to do, for example python --version. You press Enter to run it, and its output appears below.

The presenter uses the terminal built into VS Code. Open it with Terminal → New Terminal or Ctrl+`. On Windows it starts PowerShell; on macOS it is usually zsh, on Linux bash. Most commands on this page are identical everywhere; where they differ, both versions are given.

The terminal always works "inside" one folder, shown in the prompt (for example PS D:\…\Beginner>). Commands that create files create them in that folder. If you open your project folder in VS Code first, the terminal starts there automatically.

  3. Install uv if you do not have it (09:10)

    The presenter prefers uv to pip because uv "takes care of a lot of the syncing between the packages". The command in the video:

    pip install uv

    Line by line

    Line(s)CodeWhat it does & why
    1pip install uvpip = the installer, install = the action, uv = the package name. Downloads uv from PyPI (the public Python package index) and installs it into your global Python, which puts a uv command on your PATH. Run uv --version again afterwards to confirm.

    uv's own documentation also offers standalone installers that do not need pip. Either works:

    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
    curl -LsSf https://astral.sh/uv/install.sh | sh

    Both download uv's official install script and run it. After a standalone install, close and reopen the terminal so it finds the new uv command.

    New to uv? Why use it instead of plain pip

    uv is a single, very fast tool that replaces several older ones. With pip alone you would create a virtual environment with python -m venv, install packages with pip install, and keep a requirements.txt up to date by hand. uv does all of it:

    • uv init creates a project with a pyproject.toml file that lists your dependencies.
    • uv venv creates the virtual environment, and can even download the Python version you ask for.
    • uv add installs a package and records it in pyproject.toml and pins exact versions in a lockfile, uv.lock.
    • uv sync makes the virtual environment match the lockfile exactly, which is how a teammate gets the same setup in seconds.

    That last point is what the presenter loves most (15:23): "when we are passing the project to someone else, they can simply uv sync everything".

  4. Turn the folder into a uv project (09:34) 
    uv init

    Line by line

    Line(s)CodeWhat it does & why
    1uv initinit = initialise. Creates a new Python project in the current folder. It names the project after the folder (lowercased, so beginner) and writes these files: main.py (a tiny starter program), pyproject.toml (project description and dependency list), README.md, .python-version (which Python to use) and .gitignore.     Tip: if your default Python is newer than 3.12, you can run uv init --python 3.12 instead. Then .python-version says 3.12 and pyproject.toml says requires-python = ">=3.12", matching the venv you create next.

  5. Create the virtual environment with Python 3.12 (09:58) 
    uv venv --python 3.12

    Line by line

    Line(s)CodeWhat it does & why
    1uv venvCreates a virtual environment in a folder called .venv inside your project. It is a private copy of Python plus an empty place for packages, used only by this project.
    1--python 3.12Asks for Python 3.12 specifically. If 3.12 is not on your computer, uv downloads it. The presenter picks 3.12 rather than the newest version "to be a little bit safer": brand-new Python versions sometimes lack ready-made builds of popular packages for a while. "You can pick whatever version you have" as long as it is at least 3.12, because the finished project requires it.

    uv answers with three lines, ending in the activation command for your system, for example on Windows:

    Using CPython 3.12.12
Creating virtual environment at: .venv
Activate with: .venv\Scripts\activate
    New to virtual environments? What they are and why every project needs one

    When you pip install something without a virtual environment, it goes into the one global Python on your computer. Project A might need version 1 of a library and project B version 2; globally you can only have one. Sooner or later something breaks.

    A virtual environment ("venv") is a folder (.venv) holding a Python interpreter and its own set of packages. Each project gets its own, so projects can never break each other. You can delete .venv at any time and recreate it with uv sync; it is never committed to Git.

    Activating the venv changes your terminal session so that the commands python and pip point into .venv instead of the global Python.

  6. Activate the virtual environment (10:21)

    Use the line for your system:

    .venv\Scripts\activate
    source .venv/bin/activate

    Line by line

    Line(s)CodeWhat it does & why
    1 (Windows).venv\Scripts\activateRuns the activation script that uv put in .venv\Scripts. On Windows, Python venvs keep their programs in a Scripts folder and paths use backslashes. PowerShell picks the activate.ps1 version automatically.
    1 (macOS/Linux)source .venv/bin/activateOn macOS and Linux the folder is bin and paths use forward slashes. source runs the script inside your current shell; without it, the changes would happen in a throw-away sub-shell and disappear immediately.

    When it works, the prompt starts with the environment name in brackets. The presenter's shows (Beginner) (10:21: "We are in beginner"), because uv names the environment after the folder. To leave the venv later, type deactivate.

    Windows: "running scripts is disabled on this system"? PowerShell blocks scripts by default on some machines. Allow scripts for your user account once, then activate again:

    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

    Set-ExecutionPolicy changes the rule, -Scope CurrentUser applies it only to you (no admin rights needed), and RemoteSigned allows scripts created on your machine (like the venv's activate script) while still requiring a signature for scripts downloaded from the internet.

    Every time you open a new terminal, activate again. Alternative: uv run python main.py runs a command inside the project's venv without activating it.

  7. Create the .env file for your secret keys (10:21–11:54)

    In VS Code's Explorer, create a new file named exactly .env in the project root (next to main.py). Put two variables in it. The values below are placeholders: replace them with your real keys in actions 9 and 10, with no spaces around = and no quotes needed.

    OPENAI_API_KEY=your-openai-key-goes-here
TAVILY_API_KEY=your-tavily-key-goes-here

    Line by line

    Line(s)CodeWhat it does & why
    1OPENAI_API_KEY=…Your OpenAI API key. The name must be exactly this: LangChain's OpenAI integration (and OpenAI's own package) look for an environment variable called OPENAI_API_KEY. As the presenter says (11:07), LangChain "will automatically come to our env file and check the OpenAI key" once your code loads the file with load_dotenv() (step 04). Required from step 04 on.
    2TAVILY_API_KEY=…The key for Tavily, the web search service used in step 09 and the chef. The presenter adds it now and says "you can add it later on". Tavily's client reads this exact name.
    New to .env files? Environment variables in two minutes

    An environment variable is a named value that a running program can read from its surroundings, for example OPENAI_API_KEY. Keeping secrets in environment variables, rather than typing them into your code, means the code can be shared without the secret.

    An .env file is a plain text file with one NAME=value per line. Python does not read it on its own. The python-dotenv package provides load_dotenv(), which reads the file and turns each line into an environment variable for your running program. That is the first thing every lesson file does.

    The file name starts with a dot. On macOS and Linux that makes it "hidden" in file browsers; VS Code still shows it.

  8. Make Git ignore the .env file (10:45)

    Open the .gitignore that uv init created and add a line with .env. The presenter does this right after creating .env; VS Code then shows the ignored entries greyed out ("Now we see both our greys"), which is how VS Code marks files Git ignores. Here is the .gitignore of the presenter's finished project (the chef repository):

    .env
__pycache__/

    Line by line

    Line(s)CodeWhat it does & why
    1.envTells Git never to track the file named .env. Without this line, git add . would include your keys and git push would publish them on GitHub. This is the most important line in the file.
    2__pycache__/Ignores the __pycache__ folders Python creates to cache compiled files (you will see one appear after your first run). They are rebuilt automatically and only clutter the repository. The trailing / means "folders with this name".

    The .gitignore that uv init writes today is longer: it already lists __pycache__/, a few build folders and .venv. Keep those lines and just add .env. Even if .venv is missing from your .gitignore, uv puts a tiny .gitignore containing * inside .venv itself, so Git skips it anyway; listing .venv explicitly is still a good habit.

    New to Git and .gitignore? Why it matters for secrets

    Git records snapshots (commits) of your project's files; GitHub stores them online. Anything committed stays in the history, even if you delete the file later. A .gitignore file lists names Git should pretend do not exist. Add secrets to it before your first commit.

  9. Get an OpenAI API key and add credit (12:17–14:13)

    If you already have a key, paste it into .env. Otherwise, as in the video:

    1. Go to the OpenAI developer dashboard (platform.openai.com) and create an account or sign in.
    2. Open API keys and click Create new secret key. Give it a name; the presenter uses "langchain beginner".
    3. Copy the key right away. It is long and starts with sk-. The dashboard shows it only once; if you lose it, create a new one.
    4. Paste it into .env after OPENAI_API_KEY= and save.
    5. Open Billing and choose Add credit to balance. The presenter adds $5 and says the course will not use more than that, because they deliberately use low-cost models such as gpt-5-nano for teaching. API usage is billed separately from a ChatGPT subscription.

    Keep your key secret. In the video the presenter shows their key on screen for teaching and says they will delete it right after recording ("don't waste your time and try to copy this"). Do not imitate that. Anyone with your key can spend your credit: as the presenter warns, "you can lose a lot of money". Never paste a key into code, chat messages, screenshots or a commit. The presenter's good-practice tip (13:26): create a separate key per project, so if one leaks you revoke just that one and the others keep working.

  12. Add LangChain, then sync and lock (14:39–15:23) 
    uv add langchain
uv sync
uv lock

    Line by line

    Line(s)CodeWhat it does & why
    1uv add langchainadd does three things in one go: writes "langchain>=…" into the dependencies list of pyproject.toml; resolves exact versions of LangChain and everything it needs (including langchain-core and langgraph) and writes them to uv.lock; and installs them into .venv. "Just like that we have everything we need."
    2uv syncMakes .venv match uv.lock exactly: installs what is missing and removes what is not listed. Right after uv add nothing changes, but this is the command a teammate (or you on another computer) runs after cloning the project.
    3uv lockRe-creates uv.lock from pyproject.toml without installing. Useful after editing pyproject.toml by hand. The presenter first says "sync and then lock" and corrects to "lock"; after uv add, both are already up to date, so these two lines are harmless checks.

    You will add more packages the same way in later steps: uv add langchain-openai in step 04 (OpenAI integration) and the Tavily package in step 09. If from dotenv import load_dotenv fails in step 04 with ModuleNotFoundError: No module named 'dotenv', run uv add python-dotenv: that is the real package behind load_dotenv.

13.12Tells uv which Python version to use for this project when it creates a venv (for example during uv sync on a fresh clone). Written by uv init. Without it, uv picks any installed Python that satisfies requires-python.

And uv.lock? It is a long, generated file listing every package (including dependencies of dependencies) with its exact version and a checksum, so installs are identical everywhere. You never edit it; you commit it. In this guide's checks it pinned langchain 1.3.12, langchain-core 1.4.9, langgraph 1.2.9, langchain-openai 1.3.4 and openai 2.45.0.

What you should see

  • uv --version prints a version number.
  • Your terminal prompt starts with (Beginner) (or your folder name).
  • python main.py prints Hello from beginner!.
  • In VS Code's Explorer, .env and .venv appear greyed out (ignored by Git).
  • pyproject.toml lists langchain under dependencies, and a uv.lock file exists.

Common mistakes

  • Forgot to activate the venv. Symptom: later, ModuleNotFoundError for a package you just added, because python is the global one. Fix: activate (look for the name in brackets) or use uv run python …. The presenter hits this too in the chef project (81:41).
  • Running commands in the wrong folder. uv init in your home folder creates the project there. Check the path in the prompt first.
  • File named env or .env.txt. It must be exactly .env. Windows Notepad likes to add .txt; create the file in VS Code instead.
  • Spaces or quotes in .env. Write OPENAI_API_KEY=sk-…, one per line, no spaces around =.
  • Typo in the variable name. OPENAI_KEY or OPEN_AI_API_KEY will not be found. It must be OPENAI_API_KEY.
  • Committing .env. Add it to .gitignore before the first commit. See below if it already happened.
  • No credit on the OpenAI account. A valid key still fails with a quota or billing error until credit is added.

Rare Windows issue, seen while checking this guide: if an environment variable named SSLKEYLOGFILE is set on your machine, importing langchain_openai can crash with OPENSSL_Uplink … no OPENSSL_Applink. Remove that variable and open a new terminal.

Recap
  • python --version, pip --version, uv --version check your tools; pip install uv installs uv.
  • uv init creates the project files; uv venv --python 3.12 creates .venv; activate it with .venv\Scripts\activate (Windows) or source .venv/bin/activate (macOS/Linux).
  • .env holds OPENAI_API_KEY and TAVILY_API_KEY; .gitignore keeps it out of Git.
  • Create an OpenAI secret key (one per project), keep it private, and add credit ($5 in the video).
  • uv add installs and records packages; uv.lock pins exact versions; teammates run uv sync.
