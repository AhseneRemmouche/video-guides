Use the official Tavily package: tavily-python

The PyPI package called tavily (the one installed in the video, version 1.1.0, "Simple API TAVILY") is published by an individual, not by Tavily. Tavily's official SDK is tavily-python (published by Tavily AI, source at github.com/tavily-ai/tavily-python). Both are imported the same way, from tavily import TavilyClient, so tools.py works unchanged with either.

The tavily 1.1.0 code was read while checking this guide: it only sends your key and query to https://api.tavily.com, so that version isn't harmful. But installing look-alike packages is exactly how supply-chain attacks work: a future version of an unofficial package could do anything with your key. Prefer:

uv add tavily-python

If you already ran uv add tavily, remove it first with uv remove tavily, so two packages don't fight over the same tavily import name. Step 16 makes this change in the project.

New to how a module runs when it's imported? Why line 14 runs only once

When Python executes from tools import web_search, it runs the whole file tools.py from top to bottom, once: the imports, basicConfig, load_dotenv(), TavilyClient() and the def (which only defines the function, it doesn't call it). Then it hands you the name web_search. If another file imports tools again, Python reuses the already-loaded module instead of running it twice.

That's why code at the top level of a module (outside any function) is "setup" code: it runs once, at import time. The body of web_search runs only when someone calls it, which here is the agent, as many times as the model asks.

JavaScript modules behave the same way: the first import of chef/tools.ts runs the file once, including line 8 that creates TavilySearch; later imports reuse it. The function inside tool(…) runs once per search.

New to logging? What it is and why it beats print in real projects

A log is a running diary your program writes about itself: "started", "loaded the photo", "searching for X", "error talking to the API". print() can do that too, so why bother?

  • Every line gets context for free: the time, and how important it is (the level). With times, you can see that the third search took 8 seconds.
  • Levels let you turn detail up or down without editing code: show only warnings and errors in production, everything while debugging. With print you'd have to delete or comment out lines.
  • Logs can go anywhere: the terminal, a file, or a cloud monitoring service. The presenter's point at 98:19: on a cloud server or with monitoring tools, you read the logs, and plain print output may not reach those tools.
  • Libraries log too. Packages like httpx (which the OpenAI SDK uses for its HTTP requests) write their own log lines, and your configuration decides whether you see them. That's how the presenter "can also see the requests" at 100:24.

Rule of thumb: print for the program's actual output (here: the recipe), logging for messages about the program.

The format string, piece by piece

format="%(asctime)s | %(levelname)s | %(message)s" is a template for every log line. Each %(name)s is a placeholder: name is a field of the log record and the final s means "insert it as text". Everything else (the spaces and |) is printed as-is.

Levels: what level=logging.INFO means

Every log message has a level. basicConfig(level=logging.INFO) sets a threshold: messages at INFO or above are shown, DEBUG messages are hidden. Without level=... the default threshold is WARNING, and none of the logging.info lines would appear.

The TypeScript logger: src/logger.ts

Node has no built-in module like Python's logging. The project uses a tiny file that prints lines in the same format, time | LEVEL | message. It has no levels to filter: log.info and log.warning always print.

// A tiny logger that prints "time | LEVEL | message", like the course's
// logging.basicConfig(format="%(asctime)s | %(levelname)s | %(message)s").
function stamp() {
  const now = new Date();
  const pad = (n: number, width = 2) => String(n).padStart(width, "0");
  const date = `${now.getFullYear()}-${pad(now.getMonth() + 1)}-${pad(now.getDate())}`;
  const time = `${pad(now.getHours())}:${pad(now.getMinutes())}:${pad(now.getSeconds())},${pad(now.getMilliseconds(), 3)}`;
  return `${date} ${time}`;
}

export const log = {
  info: (message: string) => console.error(`${stamp()} | INFO | ${message}`),
  warning: (message: string) => console.error(`${stamp()} | WARNING | ${message}`),
};

New to the agent loop? Why the chef can search more than once

agent.invoke doesn't make one call to the model. It runs the agent loop from step 8:

  1. Send all messages so far (system prompt, your photo message, any earlier tool results) plus the tool descriptions to the model.
  2. If the model answers with a tool call ("call web_search with query X"), run the tool, add its result as a ToolMessage, and go back to 1.
  3. If the model answers with plain text, stop. That's the final answer.

The model decides how many searches it needs. In the presenter's run it searched several times ("oyster sauce", "garlic fried...") before writing the recipe. Each round trip costs time, model tokens and a Tavily search credit.

# 🌟 Chef's Signature Creamy Chicken & Vegetable Skillet 🌟

This recipe balances the savory depth of soy sauce and chicken with the freshness of lime and the creaminess of yogurt and milk.

**Yields:** 2-3 servings
**Prep time:** 15 minutes
**Cook time:** 30 minutes

### 🔪 Ingredients You Have:
*   **Chicken:** About 1 lb, cut into bite-sized pieces
*   **Onions:** 1 medium, chopped
*   **Carrots:** 2-3, sliced or diced
*   **Spinach:** 5-6 oz, fresh
*   **Tomatoes:** 2 medium, chopped
*   **Milk:** 1/2 cup
*   **Yogurt:** 1/2 cup (plain, preferably Greek for thickness)
*   **Eggs:** 2 (for a quick topping/binding, optional)
*   **Cheese:** 1/2 cup, shredded (cheddar, mozzarella, or whatever you have)
*   **Soy Sauce:** 3-4 tablespoons (adjust to taste)
*   **Butter:** 2 tablespoons
*   **Lime:** Juice of 1/2 lime
*   **Garlic/Ginger (Chef's Note):** If you had these, they would be perfect, but we will rely on the onion and lime for aromatic depth!

### 👨‍🍳 Instructions:

**1. Sear the Chicken:**
*   In a large skillet or pan, melt the **butter** over medium-high heat.
*   Add the **chicken** pieces and cook until golden brown and cooked through. Remove the chicken from the skillet and set it aside, leaving the flavorful bits in the pan.

**2. Sauté the Aromatics & Vegetables:**
*   Reduce the heat to medium. Add the chopped **onions** and **carrots** to the same skillet. Sauté for 5-7 minutes until the onions are soft and the carrots begin to soften.
*   Add the chopped **tomatoes** and cook for another 3-4 minutes until they start to break down slightly.

**3. Build the Sauce Base:**
*   Return the cooked **chicken** to the skillet.
*   Pour in the **milk** and **soy sauce**. Stir well, scraping up any browned bits from the bottom of the pan. Let this simmer gently for 5 minutes to allow the flavors to meld.

**4. Cream and Finish:**
*   Reduce the heat to low. Stir in the **yogurt** until the sauce turns a creamy, light orange/tan color. *Do not let it boil vigorously once the yogurt is added, or it may curdle.*
*   Stir in the **spinach** until it wilts completely into the sauce (this happens quickly).
*   Squeeze the **lime juice** over the mixture and stir. Taste and add more soy sauce or lime juice as needed for balance.

**5. The Grand Finale (Cheese & Eggs):**
*   Sprinkle the shredded **cheese** over the top of the skillet. Cover the pan for 2-3 minutes until the cheese is melted and bubbly.
*   **Optional Egg Topping:** While the cheese is melting, quickly fry the **eggs** in a separate small pan (sunny-side up or over easy). Place one or two perfectly cooked eggs on top of the skillet just before serving.

### 🍽️ Chef's Serving Suggestion:
Serve this rich, vibrant skillet mixture immediately. It is magnificent served over a bed of fluffy rice or with crusty bread to soak up every last drop of the creamy sauce!

Enjoy this culinary masterpiece! Let me know if you'd like a recipe for a different style of dish!

Common mistakes

  • OPENAI_API_KEY is missing. Add it to your .env file (or set MODEL_PROVIDER=ollama).: lines 9–12 of chef/main.ts stopped the program. Add the key, or switch to Ollama.
  • Image not found: … or Not an image file: …: the path after pnpm chef is wrong or not a PNG, JPEG, WebP or GIF. Paths are relative to the project folder.
  • The recipe says the model could not search: there is no TAVILY_API_KEY in .env. That is expected; add a key to get real search results.
  • A very slow run on Ollama: gemma4 reads a photo and writes up to 2048 tokens; on a small GPU this can take several minutes. Close other programs that use memory.
  • Error mentioning langchain_openai right after "creating our agent...": run uv add langchain-openai (89:15 in the video).
  • openai.OpenAIError: Missing credentials: .env isn't loaded or the key name is misspelled. Check the file is called .env, sits next to main.py, and contains OPENAI_API_KEY=....
  • Tavily complains about a missing or invalid key when the first search runs: check TAVILY_API_KEY in .env.
  • ModuleNotFoundError: No module named 'tools' (or prompt, photo_decoder): you ran python main.py from another folder, or a file name is misspelled (tool.py, prompts.py).
  • Nothing seems to happen after "choosing our image...": the file dialog opened behind other windows. Look in the taskbar.
  • Nothing seems to happen after "choosing our image...": you gave no path, and the program is waiting at Image path: for you to type one.
  • No log lines at all: level=logging.INFO is missing (the default level, WARNING, hides INFO), or basicConfig was already called elsewhere with different settings.
  • Changing CHEF_PROMPT has no effect: that's the line 52 bug from step 13, not you. Step 16 fixes it.
  • Windows only, rare: a crash mentioning OPENSSL_Uplink / no OPENSSL_Applink when importing langchain_openai happens if the environment variable SSLKEYLOGFILE is set. Remove that variable.

Web results go straight into the model's context

Every search result becomes part of what the model reads. A web page could contain text written to manipulate AI models ("ignore your instructions and..."), which is called prompt injection. For a recipe app the risk is small, but keep it in mind when you build agents that can take actions. Searching also helps against hallucination: the recipe is based on real pages instead of only the model's memory.
