Web Search with Tavily

Give the agent internet access with a Tavily search tool, and see the difference without it.

▶ Watch this part (47:22)

Goal

In step 08 you built a tiny tool that returned a fixed sentence. That proved the mechanics, but as the presenter says at 47:22, "this is not really what tools are for". In this step you give the agent a real superpower: searching the internet. You'll write a web_search tool that calls Tavily, a search API built for AI agents, and then ask the agent for "the latest news of the day".

This is the exact tool the personal chef project uses later (step 14) to look up recipes, so it's worth understanding every line.

Where the code comes from. The lesson files of steps 4–11 are not in the presenter's GitHub repo. Code transcribed from the video (frames at 52:30–54:00), run against the repo's locked versions (langchain 1.3.12, langgraph 1.2.9, langchain-openai 1.3.4) with an offline test harness that replaced the model and the Tavily search with fakes.

Why a model needs a search tool

An LLM learns from a huge pile of text collected up to a certain date, called its training cutoff. After that date it learns nothing new. It has no browser and no internet connection of its own (47:46: "LLMs don't have really access to the internet"). Ask it about today's news and it can only say "I don't know", or worse, guess and invent something that sounds right (a hallucination).

New to search APIs? What Tavily is and why not just "Google it"

A search API is a web search engine you call from code instead of a browser. You send a query string, it sends back results as data.

Tavily is a search API designed for AI agents (47:46–48:33). Instead of a page of blue links with ads, it returns a clean list of results, each with a title, a URL and a short extract of the page text. That's exactly what a model needs: text it can read and cite.

Why not scrape Google yourself? Search pages are made for humans, change often, block bots, and are full of HTML you'd have to clean up. A search API does that heavy lifting for you, which is what the presenter means by "we don't have to do a lot of heavy lifting".

Tavily has a free plan. At the time of writing it gives 1,000 credits per month; the presenter says "more than a 1,000 credits just for free" and notes it is not a sponsor (48:09).

Set up Tavily

  1. Create a Tavily account

    Sign up on Tavily's website (48:33). The free plan is enough for this whole course.

  2. Create an API key

    In the dashboard, open API Keys and create a new key. The presenter names it "langchain beginner" and also sets a usage limit "just in case" (48:55). A limit is a good habit: if your code ever loops by mistake, it can't burn through all your credits.

  3. Put the key in your .env file

    Open the .env file you created in step 03 (Project setup). It already has a line for Tavily. Paste your key there:

    OPENAI_API_KEY=your-openai-key-here
TAVILY_API_KEY=your-tavily-key-here

    The name must be exactly TAVILY_API_KEY, because that's the name the Tavily client looks for. The presenter deletes the key shown on screen after recording and says "create your own. Don't try to copy this. It's not going to work" (48:55–49:17).

  4. Install the Tavily package

    In the terminal, with your virtual environment active, the presenter runs (49:41):

    uv add tavily

    Please read the callout right below before you run it. We recommend a slightly different command.

Use the official package: uv add tavily-python

The video installs a package named tavily, and the presenter's repo lists tavily>=1.1.0 as a dependency. We checked the Python Package Index (PyPI) while writing this guide:

  • The PyPI package tavily (version 1.1.0) is described as "Simple API TAVILY" and is published by an individual, not by Tavily.
  • Tavily's official Python SDK is tavily-python, published by Tavily AI (source code at github.com/tavily-ai/tavily-python; version 0.8.5 when we checked).
  • Both are imported the same way: from tavily import TavilyClient. So the code on this page works unchanged with either one.
  • We read the source of the installed tavily 1.1.0. It only sends your requests to https://api.tavily.com with your key, so it is not harmful in that version.

Why it still matters: a package with a name close to a famous one can change owner or behaviour in a later release, and it receives your API key. Installing look-alike packages is a common way supply-chain attacks happen. The safe habit is to install the package the service itself documents.

Recommendation: run uv add tavily-python instead. If you already ran uv add tavily, run uv remove tavily first, then uv add tavily-python. Step 16 makes the same switch in the chef project.

New to package names? Why "tavily" and "tavily-python" are different things

When you run uv add something, uv downloads a package called something from PyPI, the public store of Python packages. Anyone can publish a package there under any free name.

Inside the package is one or more modules, the names you use after import. The package name and the module name are chosen separately. For example, the package python-dotenv gives you the module dotenv, and the package tavily-python gives you the module tavily.

So import tavily working does not tell you which package you installed. Check the service's own documentation for the exact install command, and look at pyproject.toml to see what you actually depend on.

Write the search tool

  1. Open tools.py

    Keep working in the tools.py file from step 08. The presenter deletes the old print_document tool ("it was hard to make it work because it's such a simple tool", 49:17) and the strict system prompt, which isn't needed anymore (52:12).

  2. Replace the file's contents with the code below. It creates a Tavily client, wraps its search method in a tool, and asks the agent for the latest news.
  3. Run it with python tools.py and watch the "we are doing some research on ..." lines appear.
from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain.tools import tool
from langchain.messages import HumanMessage
from tavily import TavilyClient
from typing import Dict, Any

load_dotenv()

tavily_client = TavilyClient()

@tool
def web_search(query: str) -> Dict[str, Any]:
    """tool for searching the web for information"""
    print(f"we are doing some research on {query}")
    return tavily_client.search(query)


agent = create_agent(model="gpt-5-nano",
                     tools=[web_search])

response = agent.invoke(
    {"messages": [HumanMessage(content="give me the lastest news of the day")]}
)

print("this is the AI last response: ")
print(response["messages"][-1].content)

print("--------------- this is the details -----------------")
print(response["messages"])

New to type hints like Dict[str, Any]? What they mean

A type hint is a label that says what kind of value a variable, parameter or return value should be. Python itself doesn't enforce them: the program runs the same with or without them.

  • query: str – the parameter query should be a string (text).
  • -> Dict[str, Any] – the function returns a dictionary. The part in square brackets says the keys are strings and the values can be anything.

So why bother? Two reasons. Editors like VS Code use them to warn you about mistakes and to autocomplete. And LangChain's @tool reads the parameter hints to tell the model what arguments the tool takes. Without query: str, the model wouldn't know it should send text.

Since Python 3.9 you can also write the built-in dict[str, Any] (lowercase) without importing Dict. Both mean the same thing.

New to the agent loop? Why the agent searched several times

An agent is a model in a loop. Each turn of the loop, the model looks at all the messages so far and decides: "Do I have enough to answer, or do I need a tool?"

For "the latest news of the day" the first search may return only a few headlines. The model may then decide to search again with different words to cover more ground. Each search is a new tool call, a new run of your function, a new print line, and new credits used. The loop stops when the model writes a normal answer with no tool call.

You don't write this loop yourself; create_agent builds it for you on top of LangGraph. The concept page How an Agent Thinks walks through it message by message.

What a search result looks like

tavily_client.search(query) returns a dictionary. The exact fields depend on Tavily's API version and options, but the core shape looks like this (shortened, values made up):

{
    "query": "top headlines today",
    "answer": None,
    "images": [],
    "results": [
        {
            "title": "World news: what happened today",
            "url": "https://news.example.com/today",
            "content": "A short extract of the page text ...",
            "score": 0.87,
            "raw_content": None,
        },
        # ... more results (5 by default)
    ],
    "response_time": 1.2,
}

What you should see

  • One or more lines like we are doing some research on latest news today, printed while the agent works (your queries will differ).
  • Then this is the AI last response: followed by a summary of current headlines.
  • Then the long "details" list: a HumanMessage, one or more AIMessages with empty content and filled tool_calls, a ToolMessage full of JSON per search, and a final AIMessage with the answer.
  • The run takes noticeably longer than in step 08, because each search is a real network request.

Credits: what each run costs

Every call to tavily_client.search uses credits from your monthly allowance. Because the agent decides how many searches to run, one question can use several credits. Around 55:54 the presenter looks at Tavily's usage and sees the searches from the run counted there. With 1,000 free credits a month (at the time of writing) you have plenty for learning and personal projects, which is the presenter's point at 56:16.

Two habits keep you in control: set a usage limit on the key (as the presenter did), and keep the print line in your tool so you always see how many searches happen.

Common mistakes

  • Key in the wrong variable name. The client looks for TAVILY_API_KEY exactly. A name like TAVILY_KEY or TAVILLY_API_KEY won't be found, so the client has no key and searches fail or get limited (the exact error depends on the package and version).
  • load_dotenv() after TavilyClient(). The client reads the key when it's created, so loading .env later is too late. Keep line 8 above line 10.
  • ModuleNotFoundError: No module named 'tavily'. The package isn't installed in the active virtual environment. Activate it and run uv add tavily-python.
  • Passing tools=[web_search()]. The parentheses call the function immediately (without a query, so it fails). Pass the tool itself: tools=[web_search].
  • Forgetting the old tool. If you leave print_document in the list but delete its code, Python raises a NameError. The presenter removes both (52:12).
  • Trusting every result. Web pages can be wrong or even contain instructions aimed at the model (prompt injection). For news, ask the agent to cite URLs so you can check them.

Recap
  • Models only know what they learned before their training cutoff; a search tool lets an agent fetch current information.
  • Tavily is a search API for agents. Put your key in .env as TAVILY_API_KEY; TavilyClient() reads it from the environment.
  • Install the official SDK with uv add tavily-python; the video's uv add tavily installs a different, unofficial package with the same import.
  • web_search(query: str) plus a clear docstring is all the model needs to use the tool; the returned dict becomes a JSON ToolMessage.
  • The agent may search several times for one question; each search costs credits, and the print line shows you each one.
  • Without the tool, the same model says it can't get real-time news: that's the difference between a model and an agent with tools.
