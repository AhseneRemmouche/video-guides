Conversation History & the Model Shortcut

Send Human/AI/Human messages so the agent understands follow-ups; pass the model as a string.

▶ Watch this part (28:21)

Goal

A real chat is more than one question. In this step you send the agent a short conversation: a question, the AI's earlier answer, and a follow-up that only makes sense with that history ("tell me more about it"). You'll see why the model needs the whole history every time. Then you'll delete the separate model object and give create_agent just the model's name as a string, a shortcut you'll use for the rest of the course.

This matters for the project: the personal chef must remember what was in your fridge photo when you ask a follow-up. Step 10 automates that with memory, but it works exactly the way you'll build it by hand here.

The idea: the model only knows what you send it

The presenter introduces this at 28:21: "the agent can see multiple things. We can tell it actually there has been a conversation". They simulate one, Human → AI → Human, and add: "This is basically what happens when you talk to ChatGPT" (29:33). And the key sentence: "If the AI did not have this previous conversation, it will not know that it needs to talk to me more about [Rome]" (29:55).

New to how chat models "remember"? They don't: you resend the history

A chat model has no memory between calls. Each call is independent: the model reads the messages you send in that call, writes an answer, and forgets everything. This is called being stateless.

So how does ChatGPT follow a conversation? The app keeps the history and sends the whole conversation again with every new question. The model re-reads it all each time, which is why longer chats use more tokens (and cost more).

There is also a limit to how much the model can read at once, called the context window. Very long conversations eventually have to be shortened. The handbook chapter on memory and state covers that; for now your conversation is three short messages.

New to AIMessage? Writing the AI's lines yourself

In step 5 the agent created an AIMessage as its reply. Here you create one yourself: AIMessage(content="Rome (Italian: Roma)."). It tells the model "earlier in this chat, you said this". The model can't tell whether it really said it; it trusts the history you send.

That's powerful (you can replay a saved chat, or show the model an example of the style you want) and also a responsibility: if you put words in the AI's mouth, it will build on them. The presenter copied the content from the agent's real answer in step 5, so the history is honest.

Step by step

  1. Import AIMessage

    Change line 4 to from langchain.messages import HumanMessage, AIMessage. A comma-separated list imports several names from the same module in one line.

  2. Turn the single message into a conversation

    Inside the list, after the first HumanMessage, add a comma, then AIMessage(content="Rome (Italian: Roma)."), another comma, and HumanMessage(content="tell me more about it") (28:47–29:33). Put each message on its own line so the conversation is easy to read.

  3. Run it with python models_agents.py. The presenter's run (30:17) printed a long answer: "Quick facts, location, center of Italy…".
  4. Remove the model object

    Comment out the model = init_chat_model(...) line (put # in front) and change the agent line to agent = create_agent(model="gpt-5-nano") (30:39). Run again: it works exactly the same (31:00).

The complete file

Code transcribed from the video (frames at 30:50), run against the repo's locked versions (langchain 1.3.12).

from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain.agents import create_agent
from langchain.messages import HumanMessage, AIMessage

load_dotenv()

# 0 to 1 from least creative to most creative
# model = init_chat_model(model="gpt-5-nano",temperature=1.0)

agent = create_agent(model="gpt-5-nano")

response = agent.invoke(
    {"messages": [HumanMessage(content="what is the capital of italy?"),
                  AIMessage(content="Rome (Italian: Roma)."),
                  HumanMessage(content="tell me more about it")]}
)

print(response["messages"][-1].content)

The model shortcut: just say its name

"I don't even need to create a model to create an agent" (30:17). When you pass a string, create_agent hands it to init_chat_model, which infers the provider from how the name starts. You can also be explicit with "provider:model".

New to providers? One code style, many model companies

A provider is the company (or local program) that runs the model: OpenAI, Anthropic, Google, a local Ollama install, and so on. Each has its own API, but LangChain hides the differences behind the same chat-model interface, so agent.invoke(...) works the same whichever you pick.

The presenter mentions this at 31:23: "we can use multiple things like Gemini. We can also use Claude. You can use any provider that you like". To switch, you install that provider's LangChain package (for example langchain-anthropic), put its API key in .env, and change the model string. Step 19 does exactly that for the chef project.

When should you still build the model yourself with init_chat_model? When you want settings other than the defaults (such as temperature for a model that supports it). The string shortcut always uses defaults.

You writeWhat you getUse it when
create_agent(model="gpt-5-nano")Provider inferred from the name; default settingsQuick experiments; the rest of this course
create_agent(model="openai:gpt-5-nano")Provider stated explicitly; default settingsNames without a well-known prefix, or for clarity
create_agent(model=init_chat_model(...))A model object with your own settingsYou need options such as temperature or timeouts

Common mistakes:

  • Missing comma between messages: SyntaxError: invalid syntax. Perhaps you forgot a comma? Every item in a list except the last needs a comma after it.
  • Brackets in the wrong order at the end: the list closes with ] before the dictionary closes with }, and the call closes with ) last. VS Code highlights matching pairs when you click next to one.
  • Forgot to import AIMessage: NameError: name 'AIMessage' is not defined.
  • A typo in the model name: "gpt5-nano" gives ValueError: Unable to infer model provider for model='gpt5-nano'. A name with the right prefix but a wrong model (for example "gpt-5-nanoo") passes this check and only fails when OpenAI answers that the model does not exist.
  • Wrong message order, for example putting the follow-up first: the model reads the chat in list order and gets confused.
Recap
  • Chat models are stateless: they only know the messages you send in this call.
  • To continue a conversation, send the history: HumanMessage, AIMessage, HumanMessage, in order.
  • The agent returns your messages plus its new reply; [-1] still gets the answer.
  • create_agent(model="gpt-5-nano") builds the model for you; the provider is inferred from the name, or stated with "openai:gpt-5-nano".
