Switch to React 19 APIs

Make the code React 19-only: use(), the context as provider, a <title> that follows the city, and root error logging.

Extension · built and browser-tested

Extension: not in the video. This step builds on steps 25–28. The code was type-checked, linted (0 problems), built and run in headless Chrome against the production build with mocked OpenWeather answers. These scenarios were checked: normal load, a map click, the theme saved across a reload, an empty city search, and One Call failing on every card.

What that proves: the app behaves exactly as after step 28. The browser tab now names the city, and each card error is logged once. What it does not prove: anything about real OpenWeather data (the answers were fake).

Goal

The project already installs React 19.2.0, but its code is written in a way React 18 would also understand. In this step you switch it to the React 19 way of doing things, so the code only works on React 19 or later. There are four small changes:

  1. Read the theme with use() It replaces useContext().
  2. Render the context as its own provider <ThemeContext value={…}> replaces <ThemeContext.Provider value={…}>.
  3. Render a title from a component The browser tab then says "Weather in Tokyo"; React 19 moves the <title> into the page's <head> for you.
  4. Log render errors in one place The new onCaughtError and onUncaughtError options of createRoot do it, and the error boundary stops logging a second copy.

You also raise the minimum React version in package.json to 19.2.0, so nobody installs an older version by accident.

Was the app not already React 19? Version vs. features

Two different things are called "using React 19":

  • Installing it. The repo's package.json asks for "react": "^19.1.1" and the lockfile installs 19.2.0. Also, react-leaflet 5 only accepts React 19 (its peerDependencies say "react": "^19.0.0"), so this project could never have been installed with React 18 anyway.
  • Writing code that uses its new features. The video's code only uses APIs that already existed in React 18: useState, useEffect, useContext, Context.Provider, lazy, Suspense, class error boundaries. That's why it reads like a React 18 app.

This step is about the second meaning. Nothing gets faster or looks different in the app; the code becomes shorter and uses today's recommended forms, which is what you'll see in the current React documentation.

Changes 1 and 2: the theme context

In React 18 you read a context with the useContext hook and provided it with <ThemeContext.Provider>. React 19 adds a shorter form for both.

import { createContext, use } from "react"

export type Theme = "light" | "dark"

type ThemeContextType = {
  theme: Theme
  toggleTheme: () => void
}

// Kept in its own file: React Fast Refresh works best when component files only export components.
export const ThemeContext = createContext<ThemeContextType | undefined>(undefined)

export const useTheme = () => {
  // React 19: use() reads a context like useContext, and unlike other hooks it may also be called inside if/loops
  const context = use(ThemeContext)
  if (!context) throw new Error("useTheme must be used within a ThemeProvider")
  return context
}

import { useEffect, useState, type ReactNode } from "react"
import { ThemeContext, type Theme } from "../hooks/useTheme"

type Props = {
  children: ReactNode
}

const STORAGE_KEY = "weather-theme"

// 1. the choice saved last time, 2. the operating system setting, 3. dark
function getInitialTheme(): Theme {
  try {
    const saved = localStorage.getItem(STORAGE_KEY)
    if (saved === "light" || saved === "dark") return saved
  } catch {
    // storage can be blocked (private mode, browser settings): fall through
  }
  if (window.matchMedia?.("(prefers-color-scheme: light)").matches) return "light"
  return "dark"
}

export default function ThemeProvider({ children }: Props) {
  const [theme, setTheme] = useState<Theme>(getInitialTheme)

  const toggleTheme = () => {
    setTheme((prev) => (prev === "dark" ? "light" : "dark"))
  }

  useEffect(() => {
    document.documentElement.classList.toggle("dark", theme === "dark")
    try {
      localStorage.setItem(STORAGE_KEY, theme)
    } catch {
      // not saved, but the app still works
    }
  }, [theme])

  // React 19: the context itself is the provider (<ThemeContext.Provider> is no longer needed)
  return <ThemeContext value={{ theme, toggleTheme }}>{children}</ThemeContext>
}

Change 3: the tab title follows the city

Until now the browser tab said weather-project, the name Vite gave the project in step 2. In React 18 you would change it with document.title = … inside a useEffect. In React 19 you can render a <title> element anywhere in your components, and React moves it into the document's <head>.

Change 4: log render errors once, in one place

In step 26 the error boundary logged each error itself, in componentDidCatch. React 19 already logs every error an error boundary catches, so each card error appeared twice in the console. React 19 also adds two options to createRoot to control that logging:

  • onCaughtError runs when an error boundary catches an error (a card failed but shows its "Try again" message).
  • onUncaughtError runs when no boundary catches it (React then removes the whole app from the page, as you saw in step 26).
import { StrictMode } from "react"
import { createRoot } from "react-dom/client"
import "./index.css"
import App from "./App.tsx"
import { QueryClient, QueryClientProvider } from "@tanstack/react-query"
import ThemeProvider from "./components/ThemeProvider.tsx"

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      retry: 1, // one quick retry instead of three: a wrong key or missing subscription won't fix itself
      staleTime: 5 * 60 * 1000, // weather data stays fresh for 5 minutes: switching back to a city reuses it
    },
  },
})

// React 19 root error options: one place to log render errors (or send them to an error-tracking service)
createRoot(document.getElementById("root")!, {
  onCaughtError: (error, info) => console.error("Caught by an error boundary:", error, info.componentStack),
  onUncaughtError: (error, info) => console.error("Uncaught render error:", error, info.componentStack),
}).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <ThemeProvider>
        <App />
      </ThemeProvider>
    </QueryClientProvider>
  </StrictMode>
)

import { Component, type ReactNode } from "react"
import { QueryErrorResetBoundary } from "@tanstack/react-query"
import Card from "./cards/Card"

type BoundaryProps = {
  title: string
  children: ReactNode
  onReset: () => void
}

type BoundaryState = { error: Error | null }

// React only offers error boundaries as class components.
// No componentDidCatch: React 19 already logs every caught error once (see onCaughtError in main.tsx).
class ErrorBoundary extends Component<BoundaryProps, BoundaryState> {
  state: BoundaryState = { error: null }

  static getDerivedStateFromError(error: Error): BoundaryState {
    return { error }
  }

  retry = () => {
    this.props.onReset() // lets TanStack Query fetch again instead of re-throwing the cached error
    this.setState({ error: null })
  }

  render() {
    if (!this.state.error) return this.props.children
    return (
      <Card title={this.props.title} childrenClassName="flex flex-col gap-4">
        <p role="alert" className="text-red-500">
          {this.state.error.message}
        </p>
        <button
          onClick={this.retry}
          className="self-start rounded-md border px-3 py-1 hover:bg-muted"
        >
          Try again
        </button>
      </Card>
    )
  }
}

// One boundary per card: if one request fails, the rest of the dashboard keeps working.
export default function WeatherErrorBoundary({ title, children }: { title: string; children: ReactNode }) {
  return (
    <QueryErrorResetBoundary>
      {({ reset }) => (
        <ErrorBoundary title={title} onReset={reset}>
          {children}
        </ErrorBoundary>
      )}
    </QueryErrorResetBoundary>
  )
}

React 19 features we did not use (and why)

"React 19 only" doesn't mean using every new API. These exist, but this app has no place where they help:

FeatureWhat it's forWhy not here
use(promise)Read a promise's result while rendering, with Suspense showing a fallback meanwhile.TanStack Query's useSuspenseQuery already does this and adds caching and retries. Promises passed to use must be created outside the component (or cached), which TanStack handles for you.
Actions, useActionState, useFormStatusForms that send data, with pending and error state handled for you.The app has no forms and never sends data; it only reads weather.
useOptimisticShow a change immediately while a save is still running.Nothing is saved to a server.
ref as a normal propPass ref to your own components without forwardRef.No component here needs a ref. The shadcn components in src/components/ui/ are already the React 19 versions: they take React.ComponentProps<…> and none of them uses forwardRef.
<Activity>, useEffectEvent (19.2)Keep hidden parts of the page alive; read the latest props inside an effect without restarting it.The side panel is just moved off-screen with CSS, and no effect here needs it.

Common mistakes

  • Writing <ThemeContext> without value: every useTheme() then gets undefined and throws "useTheme must be used within a ThemeProvider".
  • Calling use outside a component or hook, for example in a plain helper function or an event handler: it only works while React is rendering, just like other hooks. (It's only the if/loop rule that is relaxed.)
  • Leaving @types/react at version 18 in another project you upgrade: the TypeScript descriptions then don't match React 19, and the new forms show up as type errors even though the code runs. Upgrade the @types packages together with React.
  • Splitting the title into pieces (<title>Weather in {location}</title>): <title> should receive a single string. Build the string first, as on line 51.
  • Keeping componentDidCatch logging and adding onCaughtError: every error is printed twice again.
Recap
  • The project was already installing React 19 (and react-leaflet 5 requires it); this step makes the code React 19-only too, and sets the minimum to 19.2.0.
  • use(ThemeContext) replaces useContext; <ThemeContext value> replaces .Provider.
  • A <title> rendered in App goes into the <head>, so the tab names the city.
  • createRoot(…, { onCaughtError, onUncaughtError }) is the single place that logs render errors; the boundary no longer logs them a second time.
  • Forms, actions, optimistic updates and use(promise) are React 19 features too, but this read-only dashboard has no use for them.
