Side Panel: Air Pollution

A side panel with air quality data from the Air Pollution API.

▶ Watch this part (03:31:04)

Goal

So far the whole app has been one column of cards. In this step the presenter adds a side panel on the right edge of the screen. It shows air quality data for the same place the dashboard shows: one big AQI number and one small card per pollutant. Each card has a slider showing how high the value is, the scale under it, and five tags (Good, Fair, Moderate, Poor, Very Poor) with the current one highlighted in colour.

The data comes from a second, free OpenWeather endpoint: the Air Pollution API. You add one fetch function, one Zod schema and one component file, src/components/SidePanel.tsx. At the end of the chapter the panel also learns to open and close, which step 23 uses to turn it into a drawer on small screens.

What the presenter explains

At 3:31:13 the presenter explains why: "The free tier of open weather only comes with so much stuff. And one of the other free APIs we could use without paying anything is the air pollution API." The OpenWeather documentation lists the pollutants and a table of value ranges for each one, so the plan (3:31:35) is "a card for each one of these pollutants", each with "some sort of slider in it to show how low or high the value is. And then something saying whether it's in the good range, fair range, moderate range, and so forth." The slider comes from shadcn/ui.

The presenter then explains how side panels usually behave (3:32:20): at large screen sizes the dashboard and the panel are visible side by side, but "at small enough screen sizes, we need to make it collapse. And when the user optionally opens it up, it opens over the dashboard content." For now it is built as an overlay that always shows, "just so it's easy for us to see as we develop it". Step 23 adds the real responsive behaviour.

Some decisions the presenter explains along the way:

  • Position fixed (3:33:06): "we want it to always be in the same spot in the screen no matter what." fixed top-0 right-0 h-screen pins it to the right edge, full height.
  • A very high z-index (3:34:35): the Leaflet map uses z-index values around 1000, so the panel gets z-1001 to sit above the map and the legend.
  • Suspense inside the panel, not around it (3:35:20): "I don't want the entire side panel to disappear. I just want the inner content of it to be suspended." So SidePanel is the frame, and an inner AirPollution component calls useSuspenseQuery.
  • Spreading props (3:40:10): when a component only passes props through, the presenter writes {...props} "so if we decide to add more in the future, we don't have to be explicit about it."
  • The schema was generated with ChatGPT (3:37:55), "AI in general is really good at generating schemas like this", and it was wrong in one field, which the presenter found through the Zod error (3:46:58, see below).
  • The ranges table was generated with ChatGPT too (3:57:09), and the presenter reads it through: "I'm not just going to blindly trust it… I don't just want to be a certified vibe coder here."
  • The slider maximum (3:59:01–4:03:10): the "Very Poor" range has no upper limit, so the presenter uses the start of Very Poor as the maximum, or the value itself if it is even higher.
New to the Air Pollution API and the AQI? What the numbers mean

OpenWeather's Air Pollution API takes a latitude and longitude and returns, for that point, a list with one entry (current data). Each entry has:

  • main.aqi: OpenWeather's air quality index, a whole number from 1 (Good) to 5 (Very Poor). This is OpenWeather's own five-step scale. It is not the 0–500 "US AQI" you may know from weather apps, so don't compare the two numbers directly.
  • components: the concentration of eight substances in micrograms per cubic metre (µg/m³, the unit shown in the OpenWeather table on screen at 4:03:10): co (carbon monoxide), no (nitrogen monoxide), no2 (nitrogen dioxide), o3 (ozone), so2 (sulphur dioxide), pm2_5 and pm10 (fine and coarse particles), nh3 (ammonia).

The OpenWeather page shows a table that maps value ranges to the five quality names for six of them (SO2, NO2, PM10, PM2.5, O3, CO). For NH3 and NO it only says they "do not affect the AQI calculation" and gives a minimum and maximum. That matters later (see the warning about the ranges table).

New to position fixed and z-index? How a panel floats over the page

Normally elements are laid out one after another ("in the flow"). position: fixed (Tailwind fixed) takes an element out of the flow and pins it to the browser window: top-0 right-0 means "touch the top and right edges", and it stays there while the page scrolls. Because it is out of the flow, it does not push other content aside; it lies on top of it.

Which element is on top is decided by z-index: a higher number wins (among positioned elements in the same stacking context). Leaflet gives its panes and controls values in the hundreds and around 1000, which is why the panel uses z-1001 and why the tooltip in step 21 needs z-2000. In Tailwind v4 you can write any number after z-, such as z-1001, without square brackets.

New to Object.entries and immediately invoked functions? Two JavaScript tools used here

Object.entries(obj) turns an object into an array of [key, value] pairs, so you can .map over it. Object.entries({ co: 230, no: 0.1 }) gives [["co", 230], ["no", 0.1]]. In .map(([key, value]) => …) the square brackets are array destructuring: they name the two items of each pair. Object.keys(obj) gives only the keys.

An immediately invoked function (IIFE) is a function that is called the moment it is defined: const x = (() => { …; return something })(). The first parentheses hold the arrow function, the final () calls it. The presenter uses it (4:08:10) because the logic needs a loop or a switch, which can't be written inside a plain expression, and the result should still be a const.

New to lifting state? Why the open/closed flag lives in App

A piece of state should live in the closest component that all its users share. The panel's open/closed flag is read by the panel (to slide in or out) and changed by a hamburger button that lives in App (and in step 23 also in MobileHeader). So the presenter puts useState in App and passes both the value and the setter down as props (4:22:11): "the rest of our dashboard… is going to have to know whether or not our side panel is open."

The fetch function

This is the new function at the end of src/api.ts (lines 23–35 of the repo file; the whole file is shown in step 14):

export async function getAirPollution({
  lat,
  lon,
}: {
  lat: number
  lon: number
}) {
  const res = await fetch(
    `http://api.openweathermap.org/data/2.5/air_pollution?lat=${lat}&lon=${lon}&appid=${API_KEY}`
  )
  const data = await res.json()
  return AirPollutionSchema.parse(data)
}

Two problems carried into the final code

  • http://, not https://. On localhost this works. Once the app is deployed on an HTTPS site, browsers block plain-HTTP requests from it (mixed content), and the side panel would stay on its skeleton or fail. The One Call URL in the same file already uses https. Step 25 switches every URL to https://.
  • No res.ok check. An error response (wrong key, for example) is handed to Zod, which reports a confusing "expected number, received undefined" instead of the real reason. Step 25 adds the check.

The complete component

This is the final file from the repo. It already contains the tooltips (step 21), the skeleton fallback (step 22) and the responsive classes (step 23); the explanations below say which line came from which step.

import { getAirPollution } from "@/api"
import type { Coords } from "@/types"
import { useSuspenseQuery } from "@tanstack/react-query"
import { Suspense, type Dispatch, type SetStateAction } from "react"
import Card from "./cards/Card"
import { Slider } from "./ui/slider"
import clsx from "clsx"
import { Tooltip, TooltipContent, TooltipTrigger } from "./ui/tooltip"
import Information from "/src/assets/information.svg?react"
import Chevron from "/src/assets/ChevronLeft.svg?react"
import SidePanelSkeleton from "./skeletons/SidePanelSkeleton"

type Props = {
  coords: Coords
  isSidePanelOpen: boolean
  setIsSidePanelOpen: Dispatch<SetStateAction<boolean>>
}

export default function SidePanel(props: Props) {
  const { isSidePanelOpen, setIsSidePanelOpen } = props
  return (
    <div
      className={clsx(
        "fixed top-0 right-0 h-screen w-(--sidebar-width) shadow-md bg-sidebar z-1001 py-8 px-4 overflow-y-scroll transition-transform duration-300 lg:translate-x-0!",
        isSidePanelOpen ? "translate-x-0" : "translate-x-full"
      )}
    >
      <button onClick={() => setIsSidePanelOpen(false)}>
        <Chevron className="size-8 -ml-2 lg:hidden" />
      </button>
      <Suspense fallback={<SidePanelSkeleton />}>
        <AirPollution {...props} />
      </Suspense>
    </div>
  )
}

function AirPollution({ coords }: Props) {
  const { data } = useSuspenseQuery({
    queryKey: ["pollution", coords],
    queryFn: () => getAirPollution(coords),
  })

  return (
    <div className="flex flex-col gap-4">
      <h1 className="text-2xl font-semibold">Air Pollution</h1>
      <h1 className="text-5xl font-semibold">{data.list[0].main.aqi}</h1>
      <div className="flex items-center gap-2">
        <h1 className="text-2xl font-semibold">AQI</h1>
        <Tooltip>
          <TooltipTrigger>
            <Information className="size-4" />
          </TooltipTrigger>
          <TooltipContent className="z-2000">
            <p className="max-w-xs">
              {" "}
              Air Quality Index. Possible values: 1, 2, 3, 4, 5. Where 1 = Good,
              2 = Fair, 3 = Moderate, 4 = Poor, 5 = Very Poor.
            </p>
          </TooltipContent>
        </Tooltip>
      </div>
      {Object.entries(data.list[0].components).map(([key, value]) => {
        const pollutant =
          airQualityRanges[key.toUpperCase() as keyof typeof airQualityRanges]

        const max = Math.max(pollutant["Very Poor"].min, value)

        const currentLevel = (() => {
          for (const [level, range] of Object.entries(pollutant)) {
            if (
              value >= range.min &&
              (range.max === null || value <= range.max)
            )
              return level
          }
          return "Very Poor"
        })()

        const qualityColor = (() => {
          switch (currentLevel) {
            case "Good":
              return "bg-green-500"
            case "Fair":
              return "bg-yellow-500"
            case "Moderate":
              return "bg-orange-500"
            case "Poor":
              return "bg-red-500"
            case "Very Poor":
              return "bg-purple-500"
            default:
              return "bg-zinc-500"
          }
        })()

        return (
          <Card
            key={key}
            childrenClassName="flex flex-col gap-3"
            className="hover:scale-105 transition-transform duration-300 from-sidebar-accent to-sidebar-accent/60 gap-0!"
          >
            <div className="flex justify-between">
              <div className="flex items-center gap-2">
                <span className="text-lg font-bold capitalize">{key}</span>
                <Tooltip>
                  <TooltipTrigger>
                    <Information className="size-4" />
                  </TooltipTrigger>
                  <TooltipContent className="z-2000">
                    <p className="max-w-xs">
                      Concentration of{" "}
                      {pollutantNameMapping[key.toUpperCase() as Pollutant]}
                    </p>
                  </TooltipContent>
                </Tooltip>
              </div>
              <span className="text-lg font-semibold">{value}</span>
            </div>
            <Slider min={0} max={max} value={[value]} disabled />
            <div className="flex justify-between text-xs">
              <p>0</p>
              <p>{max}</p>
            </div>
            <div className="flex justify-between">
              {Object.keys(pollutant).map((quality) => (
                <span
                  className={clsx(
                    "px-2 py-1 rounded-md text-xs font-medium",
                    quality === currentLevel
                      ? qualityColor
                      : "bg-muted text-muted-foreground"
                  )}
                >
                  {quality}
                </span>
              ))}
            </div>
          </Card>
        )
      })}
    </div>
  )
}

Common mistakes

  • Blank page with ZodError … "path": ["coord"]: the generated schema uses a tuple; use z.object({ lat: z.number(), lon: z.number() }).
  • The panel is hidden behind the map: z-index too low. Leaflet uses values around 1000; use z-1001.
  • "Element implicitly has an 'any' type because expression of type 'string' can't be used to index type 'AirQualityRanges'" (TS7053, checked with the locked TypeScript): you indexed the table with key directly. Add toUpperCase() and the as keyof typeof airQualityRanges assertion.
  • "'range.max' is possibly 'null'" (TS18047): add the range.max === null || check.
  • Every tag is grey: forgot .toUpperCase(), so pollutant is undefined, or currentLevel spelled differently from the keys ("Very Poor" with a space).
  • React warning "Each child in a list should have a unique "key" prop" in the console: the tag <span> on line 127 has no key. It is harmless here but easy to fix: <span key={quality} …>.
  • The slider can be dragged: missing disabled.
  • Typing gap-0 without !: the gap above the content stays, because both classes have the same specificity and the card's own gap-4 wins.

Two details in the ranges table worth knowing

  • The NO and NH3 levels are not from OpenWeather. The OpenWeather table on screen at 4:03:10 gives level ranges for SO2, NO2, PM10, PM2.5, O3 and CO only. For NH3 and NO it says "Other parameters that do not affect the AQI calculation" and lists only a value range (NH3 0.1–200, NO 0.1–100). The NO ranges in the code (0/20/40/60/80) and the NH3 ranges (a copy of NO2's) were made up by the AI. So the "Good" tag on those two cards has no official meaning. If you want to be strict, show only the value and slider for them.
  • Boundaries. OpenWeather writes the ranges as [0; 20): 20 belongs to the next level. The loop checks value <= range.max and stops at the first match, so a value of exactly 20 counts as Good instead of Fair. It only matters for values that land exactly on a boundary.

Accessibility notes (not covered in the video)

The panel uses <h1> three times for visual sizes; a page should normally have one h1, with h2/h3 below it, and the size set with classes. The chevron <button> contains only an icon, so a screen reader announces just "button"; add aria-label="Close side panel". A closed panel is only moved off screen, so keyboard users can still tab into it; the HTML inert attribute on the closed panel prevents that. See the handbook chapter on responsive and accessible interfaces.

Recap
  • The Air Pollution API gives OpenWeather's 1–5 aqi plus eight concentrations; getAirPollution fetches it and AirPollutionSchema validates it (with coord as an object, not a tuple).
  • SidePanel is a fixed frame with z-1001; Suspense wraps only the inner AirPollution, which calls useSuspenseQuery with key ["pollution", coords].
  • Object.entries builds one Card per pollutant; max, currentLevel and qualityColor turn a number into a slider position and a coloured tag.
  • isSidePanelOpen lives in App; translate-x-0/translate-x-full plus transition-transform slide the panel.
  • Carried-over issues: http:// URL, no res.ok check, the 0,0 request, invented NO/NH3 levels, a missing key. Steps 25 and 26 fix the first three.
