Map Legend

A colour legend for each weather layer.

▶ Watch this part (02:50:49)

Goal

The weather layers are colourful, but what does a colour mean? "If I go to the pressure map, I really have no idea what this pressure map even means" (at 2:50:50). In this step you add a legend: a small translucent box in the top-right corner of the map with the layer's name, a colour bar, and the lowest and highest values with their unit. It changes whenever the Map Type dropdown changes.

You'll learn three useful front-end skills: turning data into a CSS linear-gradient, placing one element on top of another with absolute/relative positioning, and getting it above Leaflet's map with z-index.

What the presenter explains

The colours come from OpenWeather's docs (2:51:12–2:51:34). The Weather maps 1.0 page links to "Map styles legend: Default styles for weather layers", which lists, for each layer, which value gets which colour. "It's essentially just giving us the color spectrums that we can use for each different map type."

The data was converted with ChatGPT (2:51:56): "I'm too lazy to do this on my own. So, I'm going to take all of these numbers … plug them into chat GBT, and ask it to make me one big record." The result is the mapTypeData object at the bottom of the file.

A record keyed by layer name (2:52:19): "the key for each thing is just a string, which is the map type. And then the value is just another object" with a title, a unit and the colour stops.

Gradient positions are percentages (2:54:12–2:56:57): CSS needs each colour at a position between 0 % and 100 %. The presenter divides each stop's value by the highest value: for clouds, 50 / 100 × 100 = 50 %.

Position over the map (2:57:45–2:58:30): the legend is absolute top-4 right-4, and the map and legend are wrapped in a div with relative "so whenever we position our map legend absolutely, it positioned itself relative to the parent." z-1000 puts it above the map.

New to absolute and relative? Placing one box on top of another

Normally elements are laid out one after another. position: absolute (Tailwind absolute) takes an element out of that flow and places it with top, right, bottom, left, measured from its nearest positioned ancestor: the closest parent with a position other than the default.

That's what relative on the wrapper is for. It doesn't move the wrapper at all; it just says "measure from here". Without it, top-4 right-4 would be measured from the whole page, and the legend would float in the page's top-right corner instead of the map's.

Tailwind's spacing scale is 0.25 rem per step, so top-4 = 1 rem = 16 px with the default font size.

The complete file: MapLegend.tsx

type Props = {
  mapType: string
}

export default function MapLegend({ mapType }: Props) {
  const data = mapTypeData[mapType]

  const maxValue = data.stops[data.stops.length - 1].value

  const gradientStops = data.stops
    .map((stop) => `${stop.color} ${(stop.value / maxValue) * 100}%`)
    .join(", ")

  return (
    <div className="absolute top-4 right-4 z-1000 w-48 xs:w-96 rounded-xl shadow-lg p-4 bg-background/50 border border-accent/70 flex flex-col gap-4">
      <h3 className="text-sm font-semibold text-foreground">{data.title}</h3>
      <div
        className="w-full h-6 rounded-xl border border-accent/70"
        style={{
          background: `linear-gradient(to right, ${gradientStops})`,
        }}
      />
      <div className="flex justify-between text-xs text-foreground">
        <span>
          {data.stops[0].value} {data.unit}
        </span>
        <span>
          {data.stops[data.stops.length - 1].value} {data.unit}
        </span>
      </div>
    </div>
  )
}

New to linear-gradient? Colour stops and positions

CSS linear-gradient(direction, colour position, colour position, …) paints a smooth blend. to right means it runs from the left edge (0 %) to the right edge (100 %). Each colour stop says "at this position, be exactly this colour"; between two stops the browser blends.

background: linear-gradient(to right, blue 0%, yellow 50%, red 100%);

Colours can be semi-transparent: rgba(255, 255, 255, 0.5) is white at 50 % opacity. That's how the clouds bar fades from invisible to solid white. Positions can be any number, even below 0 % or above 100 %; such stops lie outside the visible bar, which matters below.

When value ÷ max isn't enough

The formula assumes the scale starts at 0. Two layers don't: temperature starts at −65 and pressure at 94 000. Working the repo's formula through for them (computed from the code, not a browser test):

LayerPositions from value / max × 100What the bar shows
temp_new−65 → −216.7 %, −30 → −100 %, 0 → 0 %, 30 → 100 %Only 0 to 30 °C. All the purples and blues for −65 to −10 °C lie to the left of the visible bar, yet the label still says "−65 °C". You can see it in the video at 3:04:09: the temperature bar starts at cyan, not purple.
pressure_new94 000 → 87.0 %, 100 000 → 92.6 %, 108 000 → 100 %The first 87 % of the bar is one flat blue; all nine colours are squeezed into the last 13 %.
clouds, rain, windstart at 0 or 1Correct (wind starts at 1, so it's off by half a percent, which you can't see).

The fix is to measure from the first stop instead of from 0. Two lines in MapLegend.tsx (a suggested change, not in the video or the repo):

const minValue = data.stops[0].value
const maxValue = data.stops[data.stops.length - 1].value

const gradientStops = data.stops
  .map((stop) => `${stop.color} ${((stop.value - minValue) / (maxValue - minValue)) * 100}%`)
  .join(", ")

With it, temperature runs from 0 % (−65) to 100 % (30) with −30 at 36.8 % and 0 at 68.4 %, and pressure from 0 % to 100 % with 100 000 Pa at 42.9 %. For clouds nothing changes, since the minimum is 0.

New to z-index? Why the legend needs z-1000

When positioned elements overlap, z-index decides which one is on top: higher numbers win; with equal numbers, the one later in the HTML wins.

Leaflet's stylesheet gives its own parts large numbers (from leaflet.css): the map's panes are at z-index: 400 (tiles, markers and popups live inside them) and the corner controls (zoom buttons, attribution) at z-index: 1000. An absolutely positioned legend with no z-index would be painted under the map pane. z-1000 puts it above the map; because the legend comes after the map in the HTML, it also wins any tie with the controls.

That's also why the dropdown lists use z-1001 (step 16): they must open above both the map and the legend. In step 20 the side panel uses the same trick.

What you should see. A translucent box in the map's top-right corner. With Clouds selected: "Clouds (%)", a bar fading from transparent to white (hard to see against a dark map, as the presenter notes at 3:02:40), "0 %" and "100 %". Pressure gives a blue-to-red bar labelled 94000 Pa … 108000 Pa, Temperature a cyan-to-orange bar labelled −65 °C … 30 °C. The legend doesn't move when you drag the map.
Common mistakes.
  • Legend in the page corner, not the map corner: relative is missing on the wrapper, or the legend is outside it.
  • Legend invisible: no z-1000 (it's under the map), or the bar has no height (h-6).
  • Bar is empty: one bad stop (a typo in an rgba(…) colour, a missing %) makes the whole background value invalid, and the browser ignores it silently. Inspect the bar in DevTools: an invalid declaration is shown crossed out with a warning icon.
  • Page goes blank after adding a new layer to the dropdown: mapTypeData[mapType] returns undefined for a key that isn't in the record, and data.stops then throws. TypeScript doesn't warn because Record<string, …> promises a value for every string. Add the entry to mapTypeData whenever you add a type.
  • Using a Tailwind class for the gradient (bg-[linear-gradient(...)] built from a variable): Tailwind can't see runtime strings, so the class doesn't exist. Use style, as the repo does.
Video vs repo. The video's legend box is w-96 with gap-3; the repo has w-48 xs:w-96 and gap-4 (responsive tweaks from step 23). The wrapper in App.tsx is just relative in the video and gets height and grid classes later. The data and the gradient code are the same.
Recap
  • The legend data (title, unit, colour stops per layer) comes from OpenWeather's "Default styles for weather layers".
  • mapTypeData[mapType] picks the entry; map + join turn the stops into a CSS gradient string.
  • Runtime values go in style; Tailwind classes handle everything that's fixed.
  • relative on the parent + absolute top-4 right-4 on the child pins the legend to the map's corner; z-1000 lifts it above Leaflet.
  • value / max only works for scales starting at 0; subtract the minimum for temperature and pressure.
