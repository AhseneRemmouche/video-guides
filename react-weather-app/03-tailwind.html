New to Tailwind? Styling with class names instead of CSS files

With plain CSS you invent a class name (.weather-card), write its rules in a .css file, and attach the class to an element. With Tailwind you use many small ready-made classes directly on the element, each doing one thing: p-4 (padding), rounded-xl (rounded corners), bg-red-500 (a red background). These are called utility classes.

"You can write styles in line like this instead of having to have dedicated CSS files" (06:45). "Instead of just spamming CSS files and random classes everywhere and getting messy, we'll be using it throughout this entire video" (07:07).

Tailwind only puts into the final CSS the classes it actually finds in your files, so the stylesheet stays small even though thousands of classes are available. Prefixes such as md: (from a certain screen width, a breakpoint) and dark: (in dark mode) come later, in steps 23 and 24.

New to CSS units? px, rem and why Tailwind counts in steps

px (pixels) is a fixed size. rem means "times the root font size", which browsers set to 16 px unless the user changes it. Because Tailwind's spacing is in rem, a user who enlarges the default font size in their browser settings gets proportionally larger spacing too, which helps readability.

Tailwind's spacing scale counts in steps of 0.25rem (4 px): p-1 = 4 px, p-4 = 16 px, w-32 = 128 px. Using the scale instead of random values keeps spacing consistent across the whole dashboard. When you really need an exact value, Tailwind accepts arbitrary values in square brackets, such as w-[180px], which the finished dropdowns use.

      "@": path.resolve(__dirname, "./src"),

Common mistakes

  • Following a Tailwind v3 tutorial. npx tailwindcss init fails with v4 (the command no longer exists there), and @tailwind base; lines do nothing useful. Use the Vite guide for v4, as above.
  • Forgetting @import "tailwindcss"; or putting it below other rules. No error appears: the classes simply have no effect and there is no red square.
  • Forgetting the () in tailwindcss(), or importing from "tailwindcss" instead of "@tailwindcss/vite" in the config. The styles do not appear, or Vite prints an error about the plugin.
  • Writing class= instead of className=. It often still renders, but React warns in the console ("Invalid DOM property `class`"). Use className.
  • Building class names from pieces, like "bg-" + color + "-500". Tailwind scans the source text and never sees the full name, so the CSS is not generated. Always write complete class names, for example color === "red" ? "bg-red-500" : "bg-blue-500".
  • Typos in a class name (bg-red500) fail silently. The Tailwind CSS IntelliSense extension for VS Code autocompletes and previews classes; the presenter's hover tooltip comes from it.
Recap
  • Tailwind v4 with Vite = npm install tailwindcss @tailwindcss/vite, tailwindcss() in the plugins list, and @import "tailwindcss"; at the top of index.css.
  • No tailwind.config.js is needed; Tailwind finds your class names automatically.
  • Utility classes like size-32 and bg-red-500 style elements directly in className.
  • Only complete class names written in your files are generated.
