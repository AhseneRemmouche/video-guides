Skeleton Loaders and Suspense

useSuspenseQuery, Suspense boundaries and skeleton placeholders.

▶ Watch this part (03:04:43)

Goal

Click somewhere on the map and the cards keep showing the old place's weather for a moment, then suddenly jump to the new data. "There's not really any sort of visual indication that we're fetching new data" (at 3:04:56). In this step every dashboard card gets a skeleton: a grey, pulsing copy of the card with the same shape, shown while its data loads. React's <Suspense> decides when to show it, and a short fade-in makes the real content appear smoothly.

This is also where the choice made back in step 8 pays off: the cards use useSuspenseQuery instead of useQuery, and that's what lets Suspense do the loading logic for you.

What the presenter explains

Skeletons instead of spinners (3:05:18): a skeleton loader "should generally match the shape that your data will be in. And it looks way cleaner than doing a loading spinner." The presenter shows shadcn's Skeleton component as an example.

Why the cards use useSuspenseQuery (3:05:42): "If you have a component that uses use suspense query, you can wrap that entire component in the built-in suspense component in React, which will allow you to have a fallback component, meaning the component that is rendered while we're waiting on the data to fetch."

Separate skeleton components (3:06:50): "The easiest way to do this … without completely muddying the components that we already have, would be to create brand new skeleton components that mimic the real ones": copy the card's JSX, then replace every piece that uses data with a Skeleton.

Same size as the real card (3:10:39–3:12:58, 3:16:43): measure each element in DevTools and divide the pixels by 4 to get the Tailwind size. "If the sizes are way off … you're going to see a weird readjusting of sizes and a weird flickering on the page." The presenter checks that both cards are 420 px tall.

No more isLoading checks (3:14:04): "without using suspense, what you'd probably have to do … is you would pull out something like is pending or is loading … and then in your JSX you would conditionally say … render a loading spinner otherwise render the actual content." Suspense removes that code from the cards.

All or nothing (3:14:50–3:15:58): with only the Current Weather card wrapped, nothing changed: the skeleton never appeared. Only after wrapping all four cards did the skeletons show. "It's an all or nothing kind of thing, at least in this particular use case."

Fade in (3:27:22–3:30:49): a fade-in keyframe animation on the card's content, so data doesn't just "flash in".

New to Suspense? What "suspending" means

<Suspense fallback={…}> is a React component that marks a boundary. If any component inside it isn't ready to render yet (it "suspends"), React shows the fallback in place of the boundary's whole content. When everything inside is ready, React swaps the real content back in.

A component suspends by telling React "I'm waiting for this promise". You never write that yourself here: useSuspenseQuery does it when the data for its query key isn't in the cache yet. React looks for the nearest <Suspense> above the waiting component, so where you put boundaries decides what gets replaced by what.

The handbook chapter TanStack Query in Depth and the concept page How Data Flows Through the App go further.

useQuery vs useSuspenseQuery

Both hooks come from TanStack Query, take the same query key and query function, and share the same cache. They differ in what the component sees while data is missing:

  const { data } = useSuspenseQuery({
    queryKey: ["weather", coords],

New to useSuspenseQuery? Three rules worth knowing
  • It needs a <Suspense> above it. Otherwise React has nowhere to show a fallback.
  • data is always defined. TypeScript knows it too, so data?.daily in DailyForecast.tsx (line 22) could be data.daily; the ?. is harmless.
  • Errors are thrown. If the request fails (after TanStack's retries), the hook throws the error during render. React then looks for the nearest error boundary, just as it looks for the nearest Suspense for loading. This app has none yet; see "No error boundary yet" below.

New to Array.from({ length })? Looping a fixed number of times in JSX

JSX has no for loop; you render lists with array.map(...). To repeat something n times you need an array of length n first:

Array.from({ length: 3 })             // [undefined, undefined, undefined]
Array.from({ length: 3 }).map((_, i) => i)   // [0, 1, 2]

new Array(3).map(...) does not work: it creates "holes" that map skips. Array.from fills real slots.

Why each card has its own boundary

  • Matching shapes. A boundary has one fallback. With one <Suspense> around all four cards, the whole area would turn into a single fallback, and you'd need a combined skeleton for the full grid.
  • Smallest possible replacement. Only the part that's waiting is swapped out. The map, the dropdowns and the grid stay where they are.
  • Every suspending component needs a boundary above it. That's the "all or nothing" the presenter ran into (3:14:50): with only Current Weather wrapped, the other three cards also suspended on the same query but had no boundary of their own, and the skeleton never appeared; instead the old cards stayed until the new data arrived. The presenter's explanation in the video is about the cards sharing cached data; the practical rule is the same either way: wrap every component that calls useSuspenseQuery.
  • Room to grow. If the cards ever use different queries, each one will appear as soon as its own data is ready.

VS Code's hover shows what it compiles to: animation: fade-in 0.6s ease-out-forwards;. ease-out-forwards isn't a CSS keyword, so the browser treats the whole animation declaration as invalid and drops it. There's no error message anywhere. The fix is ease-out_forwards (two separate words). The presenter then tried 0.6s and settled on 1s (3:30:49).

New to CSS keyframe animations? @keyframes and the animation shorthand

@keyframes name { from { … } to { … } } defines the steps of an animation once. An element then runs it with animation: name duration timing-function fill-mode:

  • duration: 1s.
  • timing function: ease-out starts fast and slows down at the end.
  • fill mode: forwards keeps the last frame (opacity 1) after the animation ends.

Tailwind has a few built-in animations (animate-pulse, animate-spin, …) but no fade-in, hence the custom one ("There's no built-in fade animation in Tailwind to my knowledge", 3:27:22). Tailwind v4 also lets you register it as a theme variable (--animate-fade-in) to get a short class like animate-fade-in; the arbitrary value works without that.

What you should see. On first load and after every map click or new city, each card briefly shows its grey pulsing skeleton (often only a fraction of a second on a fast connection), then the real content fades in over one second. The cards don't change size during the swap. Going back to a place you've already seen shows the cached data at once, without skeletons. To slow things down for a better look, use DevTools → Network → "Slow 4G".
Common mistakes.
  • Skeleton never shows: one of the four cards isn't wrapped in <Suspense>, or a card still uses useQuery (which never suspends).
  • fallback={CurrentSkeleton} (without the angle brackets): that passes the function, not an element, and React warns that functions are not valid as a React child. Write fallback={<CurrentSkeleton />}.
  • The whole page flashes: the boundary is too high (for example around the whole grid or the whole App), so the map disappears too.
  • Cards jump in height: skeleton sizes don't match; measure again in DevTools.
  • "Each child in a list should have a unique key prop" in the console: the key={index} is missing on a mapped div.
  • No fade: a typo in the arbitrary value (see above), or the @keyframes name doesn't match the name in the class.

No error boundary yet

Suspense handles waiting. Nothing in the app handles failing. When the One Call request fails (invalid key, missing One Call subscription, network down), TanStack Query retries it (three times by default, with increasing delays), and then useSuspenseQuery throws the error. React looks for an error boundary above the card, finds none, and removes the whole app from the page: a blank screen (verified with a mocked 401 response).

Video vs repo. In the video the cards are still one column, so the Suspense elements sit directly in a flex flex-col list; the repo wraps each in a grid cell div (step 23). The skeletons' 2xl: classes and Card's className prop, optional title and 2xl:flex-1 were added later. SideCardSkeleton and SidePanelSkeleton in the same folder belong to step 22.
Recap
  • useSuspenseQuery suspends while data is missing; the nearest <Suspense fallback> shows the fallback instead.

  • Lists in skeletons map over Array.from({ length: n }) with key={index}.
