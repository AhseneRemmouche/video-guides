Maps on the Web: Leaflet, Tiles & Layers

Coordinates, zoom levels, tile servers, overlays and how react-leaflet wraps Leaflet.

The map is the biggest thing on the dashboard. In step 11 the presenter added a Leaflet map with react-leaflet. In step 15 they made it follow the dropdown, in step 16 they laid OpenWeather's weather tiles over it, in step 17 they swapped the base map for a MapTiler style, and in step 18 they added a legend. This chapter explains the ideas underneath: how positions are written, how a round Earth becomes a flat square, why maps are cut into tiles, how layers stack, how react-leaflet wraps an older non-React library, and two production details: the broken marker image and attribution.

Why this matters for your project. Two of the bugs found in testing live in Map.tsx: a click listener added on every render, and a default marker that shows as a broken image in the production build. Both come from the gap between Leaflet's imperative style and React's way of thinking. Knowing how tiles and layers work also lets you add your own overlays, change the zoom sensibly and credit the map data correctly.

Library facts below were read from the installed leaflet 1.9.4, react-leaflet 5.0.0-rc.2 and @maptiler/leaflet-maptilersdk 4.1.1. Tile numbers were computed with the standard formula and are marked as such.

Latitude and longitude

Every position on Earth is two angles, in degrees. Latitude says how far north or south of the equator you are: from -90 (South Pole) to 90 (North Pole). Longitude says how far east or west of the line through Greenwich, London: from -180 to 180. Tokyo is about latitude 35.68, longitude 139.69: a bit more than a third of the way to the North Pole, and well to the east.

The point 0, 0 is in the Atlantic Ocean, in the Gulf of Guinea, south of Ghana. That is why the committed app "flickers to the middle of the ocean" before showing Tokyo (the presenter notices it around 2:28:00): it requests weather for lat: 0, lon: 0 while the city is still being looked up (see chapter 6).

The project translates between the two spellings when the user clicks: const { lat, lng } = e.latlng then onMapClick(lat, lng), and App.tsx stores it as { lat, lon }. Mixing up the order is the classic map bug: your marker lands in the wrong hemisphere, or in Antarctica.

From a globe to a square: Web Mercator

A screen is flat, so the globe must be projected. Almost every web map, including Leaflet's default, uses Web Mercator (code name EPSG:3857; Leaflet's map options default to crs: EPSG3857). It turns the whole world into one square. Two side effects you will notice:

  • Areas far from the equator look much bigger than they are (Greenland looks as large as Africa).
  • The poles cannot be shown. Leaflet's projection stops at latitude ±85.0511287798 (MAX_LATITUDE in the source), the value that makes the world exactly square.

You rarely compute this yourself; Leaflet converts between [lat, lng] and screen pixels for you. But it explains the next idea: since the world is a square, it can be cut into smaller squares.

Zoom levels and tiles

Downloading one huge picture of the world would be impossible. Instead, map servers cut the square world into tiles: small images, 256 × 256 pixels in Leaflet by default (tileSize: 256). At zoom 0 the whole world is one tile. Each zoom level doubles the width and height, so zoom z has 2z × 2z tiles. The browser only downloads the handful of tiles that cover the visible area.

A tile is named by three numbers: zoom z, column x (from the left, starting at 0) and row y (from the top). That is what the {z}/{x}/{y} placeholders in a tile URL mean. Leaflet fills them in for every tile it needs. The weather overlay in Map.tsx uses exactly this pattern:

<TileLayer
  opacity={0.7}
  url={`https://tile.openweathermap.org/map/${mapType}/{z}/{x}/{y}.png?appid=${API_KEY}`}
/>

Base map, overlays and opacity

A web map is a stack of transparent sheets. The bottom sheet is the base map (land, sea, borders, labels). Above it you can put overlays: weather tiles, markers, shapes. In this app the stack is:

  1. MapTiler base map, added by MapTileLayer with the style "basic-dark". It is a vector map: the SDK downloads map data and draws it in the browser, instead of downloading finished pictures.
  2. OpenWeather weather tiles (clouds_new, precipitation_new, pressure_new, wind_new, temp_new): PNG images with transparent areas. At 2:49:43 the presenter finds the white clouds "kind of harsh" and adds opacity={0.7}, so the base map shows through.
  3. The marker at the selected coordinates.
  4. Controls and the legend: Leaflet's zoom buttons and attribution, plus the project's MapLegend, an ordinary absolutely positioned div with z-1000 so it floats above Leaflet's panes.

Leaflet is imperative; React is declarative

Leaflet was written before React became popular. You use it by giving commands to a map object: map.panTo(...), map.on("click", ...), layer.addTo(map), map.removeLayer(layer). That style is called imperative. React is declarative: you describe what the screen should look like for the current state, and React works out the changes.

react-leaflet bridges the two. <MapContainer> creates one Leaflet map object when it first appears and puts it in a React context. Child components such as <TileLayer> and <Marker> read the map from that context and call Leaflet's commands for you when their props change. Your own children can get the same map object with the useMap() hook, which in the installed source is literally return useLeafletContext().map.

One rule surprises everyone: MapContainer's center and zoom are only read once. In react-leaflet/lib/MapContainer.js, map.setView(center, zoom) runs inside the callback that creates the map, and never again. Changing the center prop later does nothing. That is why, in step 15, the map did not follow the dropdown. The presenter first forced a brand-new map with a changing key (which caused flicker, 2:28:23), then switched to calling map.panTo from a child component: the imperative way.

Imperative calls need effects and cleanup

MapTileLayer in the repo does this correctly: it adds the MapTiler layer inside useEffect and removes it in the cleanup function. MapClick does not. It calls Leaflet straight in the render body:

  const map = useMap()
  map.panTo([coords.lat, coords.lon])

  map.on("click", (e) => {
    const { lat, lng } = e.latlng
    onMapClick(lat, lng)
  })

Every render adds another click listener and none is ever removed, so after many renders one click runs the handler many times. (This was reasoned from the code and Leaflet's API, not counted in the browser.) The fix in step 25 uses react-leaflet's useMapEvents, whose installed source calls map.on(handlers) inside useEffect and map.off(handlers) in the cleanup, and moves panTo into an effect that runs only when the coordinates change:

  const map = useMapEvents({
    click(e) {
      onMapClick(e.latlng.lat, e.latlng.lng)
    },
  })

  // pan only when the coordinates change, not on every render
  useEffect(() => {
    map.panTo([coords.lat, coords.lon])
  }, [map, coords.lat, coords.lon])

A small detail: because the { click } object is new on every render, useMapEvents removes the old listener and adds the new one each time. That is fine: there is always exactly one.

The broken marker in production builds

In the browser test, the committed app showed a perfect blue pin with npm run dev but a broken image (alt text "Marker") in the production build:

Here is the chain of cause and effect, each link checked in the installed packages:

  1. Leaflet's default icon does not import its images. Its CSS has a rule .leaflet-default-icon-path whose background is url(images/marker-icon.png). At run time _detectIconPath reads that background URL and keeps everything before marker-icon.png as the folder for the images.
  2. Vite inlines small assets as data: URLs in production builds. The default limit (assetsInlineLimit) is 4096 bytes, and Leaflet's marker-icon.png is 1,466 bytes. So in the built CSS the background is a long data:image/png;base64,... string, which no longer ends in marker-icon.png.
  3. The path detection fails, Leaflet falls back to looking for a <link href$="leaflet.css"> (there is none: Vite bundles all CSS into one hashed file), and builds an image URL that does not exist.

The dev server does not inline the CSS images the same way, which is why it only breaks after npm run build. The reliable fix is to stop relying on detection: import the three images so Vite handles them, and hand Leaflet an explicit icon. From ext25/src/components/Map.tsx:

import markerIconUrl from "leaflet/dist/images/marker-icon.png"
import markerIcon2xUrl from "leaflet/dist/images/marker-icon-2x.png"
import markerShadowUrl from "leaflet/dist/images/marker-shadow.png"

const markerIcon = L.icon({
  iconUrl: markerIconUrl,
  iconRetinaUrl: markerIcon2xUrl,
  shadowUrl: markerShadowUrl,
  iconSize: [25, 41],
  iconAnchor: [12, 41],
  shadowSize: [41, 41],
})
// ...
<Marker position={[lat, lon]} icon={markerIcon} />

The sizes are Leaflet's own defaults for Icon.Default. iconAnchor: [12, 41] says "the tip of the pin is 12 px from the left and 41 px from the top", so the point, not the middle of the image, sits on the coordinates.

Attribution: crediting the map data

Map data and tiles are created by someone, and their licences usually require a visible credit. Leaflet shows an attribution box in the bottom-right corner by default (attributionControl: true in the map options). Layers add their own text to it. In this project:

  • The MapTiler SDK layer adds the credit itself. Its installed source calls attributionControl.addAttribution(...) with links to "© MapTiler" and "© OpenStreetMap contributors". Our test screenshots show the line Leaflet | © MapTiler © OpenStreetMap contributors.
  • The OpenWeather <TileLayer> has no attribution prop, so OpenWeather is not credited on the map. Check OpenWeather's terms for what they require, and if a credit is needed, add it with the prop:
<TileLayer
  opacity={0.7}
  attribution='Weather data &copy; <a href="https://openweathermap.org/">OpenWeather</a>'
  url={`https://tile.openweathermap.org/map/${mapType}/{z}/{x}/{y}.png?appid=${API_KEY}`}
/>

Two rules of thumb. Never hide the attribution control with CSS to "clean up" the design; it is often a licence condition, not decoration. And if you ever point a TileLayer at OpenStreetMap's own tile servers (many react-leaflet examples do), read the OpenStreetMap Foundation's tile usage policy first: those servers are a shared community resource with rules for apps.

The base map follows the theme

The repo hard-codes the dark MapTiler style "basic-dark", so the map stays dark in light mode. Step 27 picks the style from the theme using the SDK's constants (MapStyle.BASIC.DARK is "basic-v2-dark", MapStyle.BASIC.LIGHT is "basic-v2-light"); the browser test confirmed the style request switched when toggling. Constants are safer than typed strings because a typo becomes a TypeScript error instead of a blank map.

Common misconceptions
  • "Changing center on MapContainer moves the map." It is read once. Use map.panTo / setView in an effect, as step 25 does.
  • "Coordinates are always [lat, lon]." Leaflet yes; GeoJSON is [lon, lat], and Leaflet calls it lng, not lon.
  • "A higher zoom just enlarges the picture." Each zoom level is a new set of tiles with more detail, and four times as many of them.
  • "Overlays replace the base map." They are stacked on top; use transparent tiles or opacity.
  • "If the marker works in dev, it works in production." Not for Leaflet's default icon with Vite. Test npm run build + npm run preview.
  • "Attribution is optional decoration." It is usually required by the data licence.
Recap
  • Latitude is north/south (-90 to 90), longitude east/west (-180 to 180). Leaflet uses [lat, lng].
  • Web maps use Web Mercator (EPSG:3857): the world becomes a square, clipped at about ±85°.
  • Zoom z = 2z × 2z tiles of 256 px, addressed by {z}/{x}/{y}.
  • The map is a stack: MapTiler base, OpenWeather overlay at opacity 0.7, marker, controls and legend.
  • react-leaflet shares one Leaflet map via context; get it with useMap. center/zoom are initial values only. Put direct Leaflet calls in effects with cleanup (useMapEvents).
  • Pass an explicit L.icon with imported images, or the default marker breaks after vite build.
  • Keep the attribution visible and credit every data source you use.
