Side Panel Skeletons

Loading placeholders for the side panel.

▶ Watch this part (04:28:37)

Goal

Every dashboard card already shows a skeleton (a grey, pulsing placeholder in the shape of the real content) while its data loads (step 19). The side panel doesn't: "If I click somewhere, the entire panel just blanks out before it reappears" (4:28:53). In this step the presenter builds two small components, SideCardSkeleton (one fake pollutant card) and SidePanelSkeleton (the whole panel content), and plugs the second into the <Suspense> that has been waiting inside SidePanel since step 20.

What the presenter explains

"Making skeleton loaders now is super super easy because we've done it a couple of times" (4:29:15). The recipe is the same as in step 19: copy the JSX of the real component, delete what isn't needed (the key, the tooltip), and replace "everywhere that we were consuming some sort of API data" with a shadcn <Skeleton> of the same size (4:30:00).

The sizes are measured in the browser's dev tools and converted to Tailwind classes by dividing pixels by 4 (4:30:23–4:32:43): the name with its icon is about 46 px wide and 28 px tall, rounded to w-12 h-7 (48 × 28 px); the slider is "hardcoded to be 6 pixels tall", so w-full h-1.5; the scale numbers are about 8 × 16 px, so w-2 h-4; the tags are about 24 px tall and 40–70 px wide, so w-15 h-6.

Then the presenter notices (4:33:04): the Suspense wraps the whole AirPollution component, so the fallback must imitate the whole panel content, not one card. Hence the second component, which keeps the real headings ("Air Pollution", "AQI"), shows a 48 px block where the AQI number goes, and renders SideCardSkeleton eight times. Finally the skeleton blocks were invisible because they had the same colour as the card, fixed with bg-sidebar (4:37:14).

New to Tailwind's spacing scale? Why divide by 4

In Tailwind v4 most size utilities (w-*, h-*, size-*, p-*, gap-*) are a multiple of one base unit, --spacing: 0.25rem. With the default root font size of 16 px, 0.25rem is 4 px. So h-7 = 7 × 4 = 28 px, h-1.5 = 6 px, w-15 = 60 px, size-12 = 48 × 48 px. That is why the presenter divides every measured pixel value by 4. Tailwind v4 accepts any number here (w-15 exists even though v3 had no such class). w-full is 100% of the parent and size-* sets width and height together.

New to Array.from({ length })? Making a list without data

To render something n times you need an array with n items to .map over. Array.from({ length: 8 }) creates [undefined, undefined, …] with 8 items. In .map((_, index) => …) the first parameter (the item, always undefined) is named _ by convention to say "unused"; index (0 to 7) is used as the React key. Using the index as a key is fine here because the list never reorders.

Step by step

  1. Create src/components/skeletons/SideCardSkeleton.tsx

    With the tsrfc snippet (an editor shortcut from the "ES7+ React" snippets extension that writes a typed function component). Paste the <Card> JSX from SidePanel, remove key and the tooltip, replace data with <Skeleton> (4:29:15–4:32:43).

  2. Create src/components/skeletons/SidePanelSkeleton.tsx

    Paste the JSX of AirPollution, delete the logic and tooltip, map eight SideCardSkeletons, replace the AQI number with <Skeleton className="size-12" /> (4:33:04–4:36:27).

  3. Use it as the fallback

    In SidePanel.tsx: <Suspense fallback={<SidePanelSkeleton />}> and import it (4:36:50).

  4. Make the blocks visible

    Add bg-sidebar to every Skeleton in SideCardSkeleton (4:37:14). Step 24 turns this into dark:bg-sidebar.

Common mistakes

  • Skeleton invisible in dark mode: add dark:bg-sidebar (or bg-sidebar if you are still in the video's state before step 24).
  • The panel jumps in size when data arrives: the skeleton's classes differ from the real card's. Copy childrenClassName and className exactly.
  • Fallback on the wrong Suspense: if you wrap <SidePanel> in App instead, the whole panel (with its close button) disappears while loading. The Suspense belongs inside SidePanel, around AirPollution.
  • Lint errors: npm run lint reports two errors per file, checked with the locked ESLint: 
    src/components/skeletons/SideCardSkeleton.tsx
  4:14  error  The `{}` ("empty object") type allows any non-nullish value, including literals like `0` and `""`  @typescript-eslint/no-empty-object-type
  6:42  error  Unexpected empty object pattern  no-empty-pattern
    The same two appear in SidePanelSkeleton.tsx (and in the other skeletons and LightDarkToggle). The app still builds; lint is a separate check. Fix: delete type Props = {} and write export default function SideCardSkeleton() {. Step 25 does this for all files.

The repo matches the video, except that the bg-sidebar classes became dark:bg-sidebar in step 24. The shadcn skeleton.tsx itself was also edited in step 24 (from bg-accent to dark:bg-accent bg-foreground/25).

Recap
  • SideCardSkeleton = the real side card's JSX with every piece of data replaced by a Skeleton of the measured size (pixels ÷ 4 = Tailwind number).
  • SidePanelSkeleton imitates all of AirPollution: real headings, a size-12 block for the AQI and eight card skeletons.
  • It is the fallback of the Suspense inside SidePanel, so the frame and close button stay visible.
  • Placeholders need contrast: dark:bg-sidebar makes them visible on the dark cards.
  • The empty Props pattern causes lint errors; step 25 removes it.
