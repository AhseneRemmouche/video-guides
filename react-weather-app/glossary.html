Glossary

Every technical term in this guide, explained for beginners.

Every technical word used in this guide, explained in plain language. Step pages link here the first time a term appears, so you can always come back. Terms are grouped by topic. Most entries give an example from the weather dashboard and link to the step where the idea first shows up. Some also point to a handbook chapter that goes deeper.

Two maps to start with

Before the individual words, here is how they fit together. The first map shows where each piece of the project lives while you work on it. The second shows the layers of the app, from the language you write in to the tools that ship it.

Tools & command line

Terminal (command line)
A text window where you type commands instead of clicking. In VS Code, open it with Ctrl+`. Commands in this guide such as npm install or npm run dev are typed there and run with Enter. Make sure the terminal is in the project folder (the one with package.json) before you run them. First used in step 02.
Node.js
A program that runs JavaScript outside the browser, on your computer. You don't write Node code in this project, but every tool you use (npm, Vite, TypeScript, ESLint) is a JavaScript program that needs Node to run. The code in this guide was verified with Node 24.15. Install it from nodejs.org before step 02.
npm
The package manager that comes with Node. It downloads packages into node_modules/ (npm install zod), and runs the scripts listed in package.json (npm run dev, npm run build, npm run lint). First used in step 02; more in handbook chapter 3.
npx
Runs a package's command without installing it into your project first. The presenter uses it to add shadcn components: npx shadcn@latest add select downloads the shadcn tool, runs it once, and the tool copies the component file into src/components/ui/. See step 12.
Package (library)
Code someone else wrote and published so you can reuse it, for example @tanstack/react-query or leaflet. A name that starts with @something/ belongs to an organisation's "scope". You install packages with npm and bring them into a file with import.
package.json
The project's ID card. It lists the project name, the dependencies and dev dependencies with allowed version ranges ("zod": "^4.1.12" means "4.1.12 or a newer 4.x"), and the scripts: dev runs vite, build runs tsc -b && vite build, lint runs eslint .. Created in step 02.
Lockfile (package-lock.json)
A file npm writes that records the exact version of every installed package, including the packages your packages need. With it, npm ci installs exactly the same versions on any machine. The repo's lockfile pins, for example, react 19.2.0 and zod 4.1.12; this guide was tested against those. Commit it to Git; never edit it by hand.
Dependency
A package your app needs while it runs in the browser, listed under "dependencies" in package.json. Examples here: react, @tanstack/react-query, zod, leaflet, react-leaflet. npm install name adds one.
Dev dependency
A package you only need while developing or building, not inside the finished app, listed under "devDependencies". Examples: typescript, vite, eslint, vite-plugin-svgr, and the @types/... packages that teach TypeScript about JavaScript libraries. Added with npm install -D name.
Vite
The build tool of this project (version 7.1.11). It does two jobs: while you work it runs a fast dev server, and for release it builds a small set of optimised files. Plugins in vite.config.ts add React support, Tailwind and svgr, and an alias makes @/ mean src/. The project is created with npm create vite@latest in step 02.
Dev server
A small local web server started by npm run dev, usually at http://localhost:5173. It serves your source files to the browser, translating TypeScript and JSX on the fly, and reloads changes instantly (HMR). It only runs on your computer. Restart it after editing .env, because environment variables are read once at start-up.
Build (production build)
Turning your source code into the files a real website serves. npm run build first type-checks everything (tsc -b), then vite build writes plain JavaScript, CSS and assets into dist/. npm run preview serves that folder so you can test it. The build can behave differently from the dev server: the broken map marker of step 25 only shows up there. More in step 28.
Bundle
The JavaScript file (or files) a build produces by joining your code and all the libraries it imports. As committed, this app becomes one file of about 2,006 kB (559 kB compressed), which makes Vite warn about chunks larger than 500 kB. Step 28 splits the map into its own chunk with lazy loading.
HMR (Hot Module Replacement)
A dev-server feature: when you save a file, only that module is swapped in the open browser tab, often keeping the current state. That's why the presenter's dashboard updates the moment they save. It only exists in development. The lint rule "only-export-components" exists to keep HMR working, see lint.

JavaScript & TypeScript

JavaScript
The programming language browsers run. Everything in this app ends up as JavaScript, even though you write TypeScript. Handbook: chapter 1.
TypeScript
JavaScript plus types. You describe what shape your values have, and the TypeScript compiler (tsc) checks your code before it runs, catching mistakes like a misspelled property. Files end in .ts, or .tsx when they contain JSX. Types are removed during the build, so the browser only sees JavaScript. The project uses TypeScript 5.9.3, chosen in step 02.
Type
A description of what a value may be. number, string and boolean are built in; you can name your own with type. In src/types.ts: type Coords = { lat: number; lon: number }. Every component also declares a Props type for the props it accepts. A union such as type Theme = "light" | "dark" allows only those two strings.
Interface
Another TypeScript way to name an object's shape: interface Coords { lat: number; lon: number } means the same as the type version. This project uses type everywhere; for objects the two are interchangeable, so pick one style and stay with it.
Generic
A type with a slot you fill in with angle brackets. useState<Coords>(...) tells React the state holds Coords; Dispatch<SetStateAction<string>> is "a setter for a string state", the type of setLocation passed to the dropdown. createContext<ThemeContextType | undefined> in the ThemeProvider is another example.
Type inference
TypeScript working out a type on its own so you don't have to write it. useState("Tokyo") is inferred as a string state. Zod uses this heavily: weatherSchema.parse(data) returns a value whose type is inferred from the schema, so data.current.temp is known to be a number in every card. See step 07.
Module
A file that shares code with others through export and import. Each file in src/ is a module with its own scope: a variable in api.ts is invisible elsewhere unless it is exported. "type": "module" in package.json switches this modern system on.
Import
Bringing something from another module or package into the current file. import { useQuery } from "@tanstack/react-query" takes a named export; import Card from "./Card" takes the default export. Vite also lets you import non-code files: import "./index.css", or import Hamburger from "/src/assets/hamburger.svg?react" with svgr.
Export
Making something in a module available to other files. export async function getWeather(...) is a named export; export default function CurrentWeather(...) is the one default export of a file.
Arrow function
A short way to write a function: (lat, lon) => { ... }. Used all over React code, for example queryFn: () => getGeocode(location) or onClick={() => setIsSidePanelOpen(true)}. Without curly braces the expression after the arrow is returned automatically.
Destructuring
Unpacking values from an object or array into variables. const { data } = useSuspenseQuery(...) takes the data property; const [location, setLocation] = useState("Tokyo") takes the two items of the array useState returns; function CurrentWeather({ coords }: Props) unpacks the props. { data: geocodeData } also renames while unpacking.
Template literal
A string in backticks that can contain ${...} placeholders. api.ts builds every URL this way, inserting lat, lon and the key. Values are inserted as-is, which is why step 25 wraps the city in encodeURIComponent before it goes into a query string.
Optional chaining (?.)
Reads a property only if the thing before ?. exists; otherwise the whole expression is undefined instead of crashing. geocodeData?.[0] is safe while the data is still loading. But it only protects the step it is written on: in geocodeData?.[0].lat, an empty array gives [0] = undefined, and .lat then throws TypeError: Cannot read properties of undefined (reading 'lat'). That crash is fixed in step 25.
Nullish coalescing (??)
"Use the left value, unless it is null or undefined, then use the right one." geocodeData?.[0].lat ?? 0 means "latitude, or 0 if we don't have it yet". Handy, but here the fallback 0 is a real place (in the Atlantic, off West Africa), so the app asks for weather there first. See How Data Flows.
Promise
An object standing for a value that will arrive later, such as the answer to a network request. It ends up either fulfilled (with the value) or rejected (with an error). fetch returns a promise, and so do the functions in api.ts. TanStack Query takes the promise from your query function and tracks it for you.
async / await
A readable way to work with promises. Inside a function marked async, await pauses until the promise settles: const res = await fetch(url), then const data = await res.json(). An async function always returns a promise. If an awaited promise rejects, the error is thrown at that line. Introduced in step 05.
fetch
The browser's built-in function for HTTP requests. fetch(url) resolves to a response object; res.json() reads its body as JSON. Important detail: fetch only rejects when the network fails. A 401 or 404 answer still resolves normally, with res.ok set to false, so your code must check it. The repo doesn't, which leads to the confusing errors fixed in step 25.
JSON
JavaScript Object Notation, the text format APIs answer in: {"lat": 35.68, "lon": 139.69}. res.json() turns that text into JavaScript objects and arrays. The app then checks the result with a Zod schema, because JSON from the network has no TypeScript types.

React

React
A JavaScript library for building user interfaces out of components. You describe what the screen should look like for the current data, and React updates the page when the data changes. This app uses React 19.2.0. Handbook: chapter 2.
Component
A function whose name starts with a capital letter and that returns JSX. The dashboard is built from components: App, Card, CurrentWeather, HourlyForecast, DailyForecast, AdditionalInfo, Map, SidePanel, LocationDropdown and more. You use one like a tag: <CurrentWeather coords={coords} />. The reusable Card of step 08 is a good first example.
JSX
HTML-like syntax inside JavaScript: <h1 className="text-2xl">Location: </h1>. Curly braces put JavaScript values inside it: {Math.round(data.current.temp)}°F. It uses className instead of class. The build turns JSX into normal function calls.
Props
The inputs a component receives from its parent, written like HTML attributes. App passes coords to every card, and location plus setLocation to LocationDropdown. Props flow down only; a child changes the parent's data by calling a function it was given, like setLocation. The special prop children is whatever you put between the opening and closing tags, as in Card.
State
Data a component remembers between renders, and whose change makes React draw again. App keeps four pieces: location (the city), coordinates (the last map click), mapType and isSidePanelOpen. Data from the server is not kept in useState here; TanStack Query's cache holds it.
Hook
A function whose name starts with use and which plugs a component into a React feature: useState, useEffect, useContext, or library hooks like useQuery, useSuspenseQuery and react-leaflet's useMap. Rules: call hooks only at the top level of a component or another hook, never inside conditions or loops, so React sees them in the same order on every render.
useState
The hook that gives a component a piece of state. const [location, setLocation] = useState("Tokyo") returns the current value and a setter. Calling setLocation("London") stores the new value and schedules a re-render. The setter can also take a function of the previous value: setTheme((prev) => prev === "dark" ? "light" : "dark").
useEffect
Runs code after React has updated the page, for work outside React: changing the <html> class for the theme, or adding the MapTiler layer to the Leaflet map. The second argument ([theme], [map]) lists the values that make it run again. The function it returns is the cleanup, run before the next effect and when the component disappears. Step 25 moves the map's panTo into an effect.
useContext
Reads the value of a context from the nearest provider above. The app's useTheme hook wraps useContext(ThemeContext) and throws a clear error if it is used outside the ThemeProvider. See step 24.
Context
A way to share a value with many components without passing it as props through every level. createContext makes one; the theme (theme and toggleTheme) lives in ThemeContext, so the toggle and the map can both reach it. Built in step 24.
Provider
A component that makes a value available to everything inside it. main.tsx wraps the app twice: QueryClientProvider hands the TanStack Query client (and its cache) to every useQuery, and ThemeProvider hands out the theme. Anything outside a provider can't see its value. First used in step 04.
Key (React key prop)
A special prop that tells React which item is which. In lists, {locations.map((city) => <SelectItem key={city} ...>)} gives each item a stable identity. Changing a component's key makes React throw it away and build a fresh one; the presenter first uses that trick to re-centre the map in step 15, then switches to panTo. Not the same thing as a query key.
Rendering (re-render)
React calling your component function to find out what the screen should show, then updating only the parts of the page that changed. A component re-renders when its state changes, when its parent re-renders, or when a context or query it uses changes. Rendering should only calculate; side effects (like adding a map listener) belong in useEffect. How Data Flows follows one re-render step by step.
Strict Mode
<StrictMode> in main.tsx turns on extra development checks. In dev it renders components twice and runs effects twice (set up, clean up, set up) to expose code with side effects in the wrong place. It does nothing in the production build. If you see a console.log printed twice in dev, this is why.

Styling & UI

Tailwind CSS
A CSS framework where you style elements with many small classes directly in the JSX, instead of writing separate CSS rules. This project uses Tailwind 4.1.15 with its Vite plugin; version 4 is configured in CSS (@import "tailwindcss"; and @theme in src/index.css), not in a JavaScript config file. Installed in step 03; handbook chapter 4.
Utility class
A Tailwind class that does one small thing: flex (flex layout), gap-4 (1rem gap), text-2xl (bigger text), font-semibold, rounded-xl, p-8 (padding). Prefixes apply them conditionally: md:grid-cols-2 from a breakpoint up, dark: in dark mode, hover: on hover.
Breakpoint
A screen width from which different styles apply. Tailwind's defaults are sm 640px, md 768px, lg 1024px, xl 1280px and 2xl 1536px; this project adds xs at 500px in index.css (--breakpoint-xs: 500px). So 2xl:grid-cols-4 only takes effect on wide screens. Used throughout step 23.
Dark variant (dark:)
Tailwind classes that only apply in dark mode, such as dark:bg-zinc-900. Here the line @custom-variant dark (&:is(.dark *)); in index.css says "dark mode = inside an element with the class dark". The ThemeProvider adds or removes that class on <html>. See step 24.
shadcn/ui
A collection of ready-made React components (Select, Tooltip, Switch, Slider, Skeleton...) that you copy into your own project instead of installing as a package. npx shadcn@latest add select writes src/components/ui/select.tsx, which you can then edit. components.json stores its settings (style "new-york", base colour zinc, aliases @/components and @/lib/utils). Set up in step 12.
Radix UI
A library of unstyled, accessible building blocks (keyboard support, focus handling, screen-reader labels). shadcn's components are Radix underneath with Tailwind styles on top: the location dropdown uses @radix-ui/react-select and the pollutant tips use @radix-ui/react-tooltip.
Lucide icons (lucide-react)
An icon set delivered as React components. shadcn's select.tsx imports CheckIcon, ChevronDownIcon and ChevronUpIcon from it for the dropdown arrows and the tick next to the chosen city. It came along when shadcn was set up.
SVG
Scalable Vector Graphics: images described as shapes in XML text, so they stay sharp at any size and can be recoloured with CSS. The app's own icons (wind, sunrise, hamburger menu, information "i"...) are SVG files in src/assets/. The diagrams in this guide are SVG too.
svgr (vite-plugin-svgr)
A Vite plugin that turns an SVG file into a React component when you add ?react to the import: import Hamburger from "/src/assets/hamburger.svg?react", then <Hamburger className="size-6" />. Because it becomes real SVG in the page, Tailwind classes can size and colour it. The line in vite-env.d.ts tells TypeScript about these imports. Added in step 09.

Web & APIs

API
Application Programming Interface: a documented way for one program to ask another for something. Here it means web APIs, URLs on OpenWeather's servers that answer with JSON. The app calls three: Geocoding (city → coordinates), One Call 3.0 (weather) and Air Pollution. Handbook: chapter 5.
API key
A secret string that identifies you to an API, so the provider can apply your plan and limits. OpenWeather expects it as appid=... in the URL; MapTiler as apiKey. Keep it out of Git (put it in .env), but know that a key used by browser code is visible to anyone who opens the site's JavaScript; see VITE_ variables and step 28. This guide never shows the keys visible in the video.
Query string
The part of a URL after ?, made of name=value pairs joined by &. In .../onecall?lat=35.68&lon=139.69&units=imperial&exclude=minutely,alerts&appid=... it carries the coordinates, the unit system, the parts of the answer to leave out, and the key. Special characters (like the space in "New York") must be encoded.
HTTP status code
A three-digit number at the start of every HTTP response. 200 means OK; 401 means "unauthorised" (missing or wrong key, or no access to that API); 404 means not found; 429 means too many requests; 5xx means the server failed. res.ok is true for 200–299. OpenWeather answers a bad key with 401 and a JSON body containing a message, which step 25 shows to the user.
HTTPS
HTTP with encryption: nobody between the browser and the server can read or change the data. URLs start with https://. The repo calls One Call over HTTPS but the geocoding and air-pollution APIs over plain http://; step 25 switches all three to HTTPS.
Mixed content
An https:// page loading something over plain http://. Browsers block such requests, because they would undo the page's encryption. On http://localhost during development the problem is invisible; once the site is deployed on HTTPS, the repo's geocoding and air-pollution calls would be blocked. Fixed in step 25.
CORS
Cross-Origin Resource Sharing. By default a web page may only read responses from its own origin (scheme + domain + port). A different server, like api.openweathermap.org, has to allow it with special response headers. OpenWeather's APIs do, which is why the app can call them straight from the browser. If an API you try doesn't, the browser console shows a CORS error and you need your own server in between. Handbook: chapter 5.
Environment variable
A named setting that lives outside the code, so each machine can supply its own value. Vite reads them from a .env file in the project root at start-up: VITE_API_KEY=.... Change .env → restart the dev server. Add .env to .gitignore (the repo's .gitignore only covers *.local, so step 28 adds it) and commit a .env.example with placeholders instead. First used in step 05.
VITE_ variables and import.meta.env
Vite only exposes environment variables whose names start with VITE_ to your code, as import.meta.env.VITE_API_KEY. At build time the value is pasted into the JavaScript as plain text. A test build with VITE_API_KEY=TESTKEY contained "TESTKEY" twice in dist/assets/*.js. So a VITE_ variable keeps the key out of Git, but not out of the deployed site. Details in step 28.

Data fetching & validation

TanStack Query (React Query)
A library (version 5.90.5) that fetches, caches and refreshes server data for React. You give it a query key and a query function; it gives back data, isLoading, error and more, and stores the result in a shared cache. It handles loading, retries, de-duplication and background updates you would otherwise write by hand with useState and useEffect. Installed in step 04; handbook chapter 6.
Query key
An array that names a piece of data in the cache: ["geocode", location], ["weather", coords], ["pollution", coords]. Same key → same cache entry; a new key → a new entry and a new fetch. Objects in a key are compared by content, so { lat: 35.68, lon: 139.69 } matches even if it is a new object. All four weather cards use ["weather", coords], so they share one request. See step 06 and How Data Flows.
Query function (queryFn)
The function TanStack Query calls to get the data. It must return a promise and throw on failure. Here it is always a small arrow calling api.ts: queryFn: () => getWeather({ lat: coords.lat, lon: coords.lon }). Everything it needs should also be in the query key, otherwise the cache can't tell the requests apart.
Cache (query cache)
TanStack Query's memory of past results, keyed by query key and owned by the QueryClient created in main.tsx. Any component asking for a key that is already cached gets the data immediately. Unused entries are removed after 5 minutes by default (gcTime). That's why switching back to a city you've seen is instant.
Stale time (staleTime)
How long cached data counts as fresh. The default is 0: data is "stale" at once, so TanStack Query refetches it in the background whenever a component using it mounts or the window regains focus, while still showing the cached version. Step 26 sets staleTime: 5 * 60 * 1000 (5 minutes), since weather doesn't change every second.
Retry
Trying a failed query again. TanStack Query's default for queries is 3 retries with growing pauses (about 1, 2 and 4 seconds). Useful for a flaky network, useless for a wrong key: with an invalid key the repo app made 28 requests in 20 seconds before giving up. Step 26 sets retry: 1.
Suspense
A React component that shows a fallback while something inside it isn't ready: <Suspense fallback={<CurrentSkeleton />}><CurrentWeather ... /></Suspense>. When CurrentWeather waits for data, React shows the skeleton in its place, then swaps in the real card. Each card has its own boundary, so cards appear independently. Also used for lazy loading. See step 19.
useSuspenseQuery
The Suspense version of useQuery. Instead of returning isLoading, it pauses ("suspends") the component until the data is there, so data is never undefined and the card code needs no loading checks. Errors are thrown to the nearest error boundary. The four weather cards and the air-pollution panel use it; App's geocode query uses plain useQuery. See step 19.
Error boundary
A component that catches errors thrown while rendering the components inside it and shows a fallback instead of crashing. Without one, any error unmounts the whole app and leaves a blank page, which is what the repo does when an API call fails. React only offers error boundaries as class components. Step 26 adds WeatherErrorBoundary around every card, combined with TanStack Query's QueryErrorResetBoundary so "Try again" really refetches.
Skeleton (loader)
A grey, gently pulsing placeholder in the shape of the content that's coming. It feels faster than a spinner and keeps the layout from jumping. The app has one per card (CurrentSkeleton, HourlySkeleton, DailySkeleton, AdditionalInfoSkeleton) and for the side panel, built from shadcn's Skeleton. Built in step 19 and step 22.
Zod
A library (version 4.1.12) for describing data with schemas and checking real data against them at run time. TypeScript types vanish when the code runs, so they can't check what an API really sends; Zod can, and it also gives you the TypeScript type for free. Added in step 07; handbook chapter 7.
Schema
A description of the shape data must have, written with Zod: z.object({ lat: z.number(), lon: z.number(), ... }). The app has three in src/schemas/: weatherSchema, GeocodeSchema (an array of places) and AirPollutionSchema. A field marked .optional() may be missing. The repo's GeocodeSchema requires local_names, which OpenWeather leaves out for many places; step 25 makes it optional.
Validation
Checking that data matches what you expect before using it. schema.parse(data) returns the data, typed, if it matches, and throws a ZodError listing every mismatch if not, for example "path": ["lat"] ... expected number, received undefined. That message is what you get when an error response (which has no lat) is validated as weather, so check res.ok first, as step 25 does.

Maps

Leaflet
A JavaScript library (1.9.4) for interactive maps: zooming, panning, tile layers, markers and click events. It works directly with the page's DOM, outside React, which is why the app reaches it through react-leaflet and useMap(). Its stylesheet must be imported (import "leaflet/dist/leaflet.css") or the tiles scatter. Added in step 11; handbook chapter 8.
react-leaflet
React components around Leaflet: <MapContainer>, <TileLayer>, <Marker>, and hooks such as useMap() and useMapEvents(). The project uses version 5.0.0-rc.2, a release candidate (a test version before the final release). MapContainer only reads its center once, so moving the map later needs map.panTo(...); see step 15.
Tile layer
Web maps are drawn from small square images (tiles, usually 256×256 px), fetched by URL for each zoom level and position: .../{z}/{x}/{y}.png. The app stacks two: a base map from MapTiler, and an OpenWeather weather layer (clouds, precipitation, wind...) at 70% opacity chosen with the map-type dropdown. See step 16.
Marker
The pin that shows a position on the map: <Marker position={[lat, lon]} />. Leaflet's default pin image breaks in the production build (Vite inlines the small PNGs, and Leaflet then builds a wrong image URL), so the deployed site shows a broken image. Step 25 imports the images and passes an explicit L.icon.
Latitude and longitude
The two numbers that locate any point on Earth. Latitude (lat) runs from −90 (south pole) to 90 (north pole); longitude (lon, or lng in Leaflet's click event) from −180 to 180 east or west of Greenwich. Tokyo is about 35.68, 139.69. The point 0, 0 lies in the Gulf of Guinea, in the ocean; the repo briefly asks for its weather on every load (see How Data Flows).
Geocoding
Turning a place name into coordinates. getGeocode("Tokyo") calls OpenWeather's Geocoding API with q=Tokyo&limit=1 and gets back an array with one place (name, lat, lon, country...). An unknown name returns an empty array, which the repo doesn't handle (blank page). Added in step 14.
MapTiler
A map provider offering styled base maps. The app adds it with @maptiler/leaflet-maptilersdk (4.1.1): new MaptilerLayer({ style, apiKey }). It needs its own key. The repo hard-codes a real key in Map.tsx line 58; this guide replaces it with "YOUR_MAPTILER_KEY". Since any browser key is public, restrict it to your site's address in the MapTiler dashboard. Added in step 17.
OpenWeather
The weather service whose APIs feed the whole dashboard: Geocoding, One Call 3.0, Air Pollution, weather map tiles and the weather icons (openweathermap.org/img/wn/...). You sign up and get an API key in step 05. New keys can take a while to start working. Check OpenWeather's site for current plans and limits.
One Call API 3.0
OpenWeather's API that returns current conditions, hourly forecast (48 hours) and daily forecast (8 days) for one coordinate in a single response. The app requests it with units=imperial (°F and mph, fixed) and exclude=minutely,alerts. It needs a separate "One Call by Call" subscription on your OpenWeather account; without it every weather card fails with a 401. Used from step 05.
Air quality (Air Pollution API)
OpenWeather's Air Pollution API returns, for a coordinate, an overall index and the concentrations of pollutants in μg/m³: CO, NO, NO₂, O₃, SO₂, PM2.5, PM10 and NH₃. The side panel shows each one with a slider and a Good-to-Very-Poor rating. See step 20.
AQI (Air Quality Index)
One number summing up air quality. OpenWeather's scale goes from 1 (Good) to 5 (Very Poor), found at data.list[0].main.aqi; it is the big number at the top of the side panel. Other agencies use different scales (the US one goes to 500), so don't compare numbers across sources.

Quality & shipping

Responsive design
One layout that adapts to any screen width, from phone to wide monitor, instead of separate sites. Here the cards go from one column on phones to two at md and a four-column dashboard at 2xl, and the side panel becomes a slide-in drawer below lg. See step 23; handbook chapter 9.
Mobile-first
Writing the phone layout as the default and adding classes for larger screens. In Tailwind, a class without prefix applies everywhere and md: means "from 768px up". So grid-cols-1 md:grid-cols-2 reads "one column, two from tablets on".
CSS Grid
A layout system for rows and columns. The dashboard's card area is a grid: grid grid-cols-1 md:grid-cols-2 2xl:grid-cols-4 2xl:grid-rows-4 gap-4, with col-span-*, row-span-* and order-* on each card to place it.
Flexbox
A layout system for one direction at a time: a row (flex) or a column (flex flex-col). Used for the header, inside cards and in the side panel, with helpers like items-center, justify-between, gap-4 and ml-auto (push to the right).
Accessibility (a11y)
Making the app usable for everyone, including keyboard and screen-reader users. Examples here: Radix components support the keyboard, images need meaningful alt text, error messages in the extensions carry role="alert" so they are announced, and text needs enough contrast in both themes. Handbook: chapter 9.
localStorage
A small key-value store in the browser that survives page reloads, per website. localStorage.setItem("weather-theme", "dark") saves; getItem reads it back. The repo forgets the theme on reload; step 27 saves it under the key "weather-theme".
prefers-color-scheme
A CSS media feature that tells a page whether the operating system is set to light or dark mode. From JavaScript: window.matchMedia("(prefers-color-scheme: light)").matches is true when the system is set to light. The repo always starts dark; step 27 starts with the system setting when nothing is saved yet.
Lint (linting)
Automatic checks for mistakes and risky patterns that are still valid code. npm run lint on the repo reports 15 errors: 14 for empty {} props types in the toggle and the six skeleton files, and 1 "only-export-components" in ThemeProvider.tsx (a file that exports a component should export only components, so HMR works). Steps 25 and 27 bring it to zero.
ESLint
The linter used here (version 9.38), configured in eslint.config.js with TypeScript rules, the React Hooks rules (which check the hook rules and effect dependencies) and the React Refresh rule. The build passes even with lint errors, so run npm run lint yourself. Handbook: chapter 3.
Code splitting
Breaking the bundle into several files so the browser downloads only what it needs first. In step 28 the main file drops from 2,005.92 kB to 623.35 kB (177.48 kB compressed), and the map code goes into its own 1,383.59 kB chunk that loads next.
Lazy loading
Loading code only when it's about to be used. const Map = lazy(() => import("./components/Map")) tells Vite to put Map (with Leaflet and MapTiler) in a separate file, and React loads it the first time the map renders, showing a Suspense fallback meanwhile. See step 28.
