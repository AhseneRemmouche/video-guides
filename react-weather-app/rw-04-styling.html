Styling with Tailwind CSS & shadcn/ui

Utility classes, responsive prefixes, dark variant, design tokens and copy-in components.

What you will learn

The weather dashboard has almost no hand-written CSS. Nearly every visual decision is a class name in a className string, generated by Tailwind CSS v4, plus a few ready-made components from shadcn/ui. This chapter explains how that works, so a line like

        <div className="grid grid-cols-1 2xl:flex-1 2xl:min-h-0 md:grid-cols-2 2xl:grid-cols-4 2xl:grid-rows-4 gap-4">

reads as a clear description instead of noise. You will learn:

  • what a utility class is and what CSS Tailwind generates for it;
  • the spacing scale, arbitrary values and CSS-variable shortcuts;
  • variants: hover, state, breakpoints and the dark variant;
  • mobile-first responsive design, including the project's custom xs breakpoint;
  • design tokens in index.css and how light/dark themes swap them;
  • combining classes safely with clsx and cn;
  • what shadcn/ui is (and isn't), and how it uses Radix.
Why this matters for your project. The responsive layout (step 23, about an hour of the video), the theme switch (step 24) and the dropdowns that must appear above the map (step 13) are all styling problems solved with these tools. When something looks wrong, the fix is almost always one class.

Utility classes: one class, one job

In traditional CSS you invent a class name (.weather-card) and write its rules in a separate file. With utility classes, each class does one small thing, and you combine many of them directly in the markup. Tailwind provides thousands of these classes, and only generates CSS for the ones you actually use. Here is the project's Card frame:

        "p-4 rounded-xl bg-linear-to-br from-card to-card/60 shadow-md flex flex-col gap-4 2xl:h-full border dark:border-none",

Each class maps to a small CSS rule. We built the project and looked at the generated stylesheet:

.hidden{display:none}
.grid-cols-1{grid-template-columns:repeat(1,minmax(0,1fr))}
.h-120{height:calc(var(--spacing)*120)}
.size-6{width:calc(var(--spacing)*6);height:calc(var(--spacing)*6)}
.z-1001{z-index:1001}
.order-2{order:2}

How Tailwind v4 is wired in

Two pieces, both added in step 3: the @tailwindcss/vite plugin in vite.config.ts, and one line at the top of src/index.css, @import "tailwindcss";. There is no tailwind.config.js: Tailwind v4 is configured in CSS (components.json even records "config": ""). The plugin scans your source files for strings that look like class names and generates only those rules; the whole stylesheet for this app is 51 kB before compression.

The scan reads your files as plain text, so class names must appear whole. SidePanel.tsx does this correctly: its switch returns complete strings like "bg-green-500" and "bg-red-500". If it built them as `bg-${color}-500`, Tailwind would never see bg-green-500 in the source and the colour would be missing.

The spacing scale

Size utilities use one base unit, --spacing, which is 0.25rem (4 px at the default font size). p-4 is 4 × 0.25rem = 1rem = 16 px. gap-8 is 2rem. h-120 on the map container is 120 × 0.25rem = 30rem (480 px). In v4 any number works, not just a fixed list, because the CSS is calc(var(--spacing)*N).

Class in the projectCSS it means
p-8, pt-4, px-2 py-1padding 2rem; padding-top 1rem; padding left/right 0.5rem, top/bottom 0.25rem
gap-4space between flex or grid children, 1rem
size-6width and height 1.5rem (icons)
text-2xl, font-semiboldfont size from the type scale, weight 600
rounded-xlborder-radius from the theme (--radius-xl)
ml-autopush an item to the far side of a flex row (the theme toggle)

Arbitrary values and escape hatches

When the scale has no fitting value, square brackets accept any CSS value, with underscores standing for spaces:

ClassWhereGenerated CSS (verified)
xs:w-[180px]dropdown triggerswidth:180px (inside the xs media query)
lg:w-[calc(100dvw-var(--sidebar-width))]main column in App.tsxwidth:calc(100dvw - var(--sidebar-width))
w-(--sidebar-width)side panelwidth:var(--sidebar-width) — v4 shorthand for "use this CSS variable"
animate-[fade-in_1s_ease-out_forwards]Card.tsxruns the @keyframes fade-in defined in index.css
lg:translate-x-0!side panelthe trailing ! adds !important, so on large screens the panel stays visible whatever the open/closed class says

100dvw is "100% of the dynamic viewport width"; the presenter explains the calc at about 4:43:38. --sidebar-width: 23rem is a plain CSS variable declared in :root, used both for the panel's width and for the space the main column leaves for it.

Variants: classes that apply under conditions

A prefix followed by a colon is a variant: the class applies only when its condition is true. The project uses several kinds:

VariantConditionExample
hover:mouse over the elementhover:scale-105 on pollutant cards
focus-visible:focused by keyboardthe focus ring in shadcn's switch.tsx
data-[state=checked]:element has data-state="checked"Radix sets this on the switch; Tailwind styles it
disabled:disabled form controldisabled:opacity-50
md:, 2xl:, xs:screen at least that widelayout changes in App.tsx
dark:inside an element with class darkdark:border-none on cards

Variants stack: dark:data-[state=unchecked]:bg-input/80 in switch.tsx means "in dark mode, when unchecked". The /80 suffix sets 80% opacity on the colour.

Responsive design, mobile first

A breakpoint variant like md: compiles to a @media (min-width: ...) rule. "Min-width" is the key: it means this width and wider. So you write the phone layout with no prefix, then add prefixes for what changes as the screen grows. This is mobile-first design, and the presenter states the rule at about 4:50:06 in step 23: default styles target the smallest screens, and breakpoints are added "as soon as you want to start getting bigger".

Tailwind's default breakpoints are defined in rem. The project adds its own xs at 500 px in index.css (the presenter adds it at about 5:19:02):

@theme inline {
  --breakpoint-xs: 500px;

In the built CSS, only the breakpoints the app uses appear: @media(min-width:500px), @media(min-width:48rem), @media(min-width:64rem) and @media(min-width:96rem) (verified). sm and xl are not used.

Now the grid line from the start of the chapter reads naturally: one column by default, two from md, four from 2xl, where the grid also gets four rows and fills the screen height. The order-* classes reorder the cards: hourly and daily swap places at 2xl (order-3 2xl:order-4 and order-4 2xl:order-3), while the HTML order stays the same.

Our phone-width (390 px) test of the committed repo showed the single-column layout working; see the screenshots in step 23. Chapter 9 goes deeper into grid, flexbox and accessibility.

Dark mode and design tokens

By default Tailwind's dark: follows the operating system setting. The project wants a toggle instead, so index.css redefines the variant:

@custom-variant dark (&:is(.dark *));

Read it as: "dark:X applies to an element (&) that is inside something with class dark". The built CSS confirms it: .dark\:border-none:is(.dark *){...border-style:none}. ThemeProvider's effect adds or removes dark on the <html> element (chapter 2), so every element on the page switches at once.

Most colours don't even need dark:. They use design tokens: named CSS variables whose values change with the theme. index.css sets them up in three layers:

:root {
  --card: oklch(0.97 0 0);                /* light value */
}
@theme inline {
  --color-card: var(--card);              /* makes bg-card, from-card... exist */
}
.dark {
  --card: oklch(0.21 0.006 285.885);      /* dark value */
}

The colour values use oklch(), a modern CSS colour format (lightness, chroma, hue) that shadcn uses for its zinc palette. You rarely edit them by hand; to change the look, change a token once and every component that uses it follows. Two more details from index.css:

  • .dark svg { filter: invert(1); } turns the black icon SVGs white in dark mode. It applies to every SVG inside .dark, so any colourful SVG you add later will be inverted too.
  • :root also keeps the Vite template's color: rgba(255, 255, 255, 0.87); background-color: #242424;. They are overridden by the body rule (bg-background text-foreground), but are leftovers you can delete.

Combining classes: clsx and cn

Components often need a base class list plus some classes from props or conditions. The project uses two helpers:

  • clsx joins strings and skips falsy values: clsx("px-2", isActive ? "bg-green-500" : "bg-muted").
  • cn (in src/lib/utils.ts, created by shadcn) runs clsx and then tailwind-merge, which removes earlier classes that conflict with later ones.
clsx("size-8", "size-14")                   // "size-8 size-14"
cn("size-8", "size-14")                     // "size-14"
cn("px-2 py-1 bg-muted", "bg-green-500")    // "px-2 py-1 bg-green-500"
clsx("p-4 rounded-xl", undefined, false && "hidden", "shadow-md")
                                            // "p-4 rounded-xl shadow-md"

Why it matters: when an element has two conflicting classes, the one later in the generated stylesheet wins, not the one later in your string. WeatherIcon.tsx uses clsx("size-8", className) and CurrentWeather passes "size-14". The result is "size-8 size-14". It works only because Tailwind happens to emit .size-14 after .size-8 (verified in the built CSS). Pass a smaller size and the override would silently fail. Using cn instead of clsx for overridable classes removes the guesswork. The shadcn components already do this: SelectContent has z-50 by default, and cn lets the project's className="z-1001" replace it.

shadcn/ui: components you own

shadcn/ui is not a package you install and import from node_modules. It is a collection of component source files that a CLI copies into your project, where you can read and edit them. The project has five: src/components/ui/select.tsx, skeleton.tsx, slider.tsx, switch.tsx and tooltip.tsx, added with commands like npx shadcn@latest add select (step 12, step 21).

components.json tells the CLI how your project is set up, so the copied files fit:

SettingMeaning
"style": "new-york"Which visual variant of the components to copy.
"tailwind": { "css": "src/index.css", "baseColor": "zinc", "cssVariables": true }Where to write the tokens, which grey palette to use, and to style with CSS variables (the tokens above).
"aliases": { "components": "@/components", "utils": "@/lib/utils", ... }Import paths to write into the copied files — why the @/ alias had to exist first (chapter 3).
"iconLibrary": "lucide"Copied components use lucide-react icons (the select's chevrons). The app's own icons are SVG files through svgr.

Radix renders open menus and tooltips in a "portal" at the end of <body>, positioned above the page. Leaflet's panes and controls use z-indexes up to 1000 (from leaflet.css), so the project raises its floating pieces: SelectContent className="z-1001", the side panel z-1001, tooltips z-2000, and the legend z-1000. If a dropdown opens behind the map, this is the fix.

New to CSS? The three ideas Tailwind assumes
  • The box model: every element is a box with content, padding (inside the border), border and margin (outside). p-* and m-* set padding and margin.
  • Flexbox and grid: flex lays children out in a row (or a column with flex-col); grid places them in rows and columns (grid-cols-2). gap-* spaces them. See flexbox and grid.
  • The cascade: when two rules set the same property with equal specificity, the later one in the stylesheet wins. This is why cn exists.
Pitfalls
  • Building class names with template literals (`text-${size}`): Tailwind can't see them, so no CSS is generated. Map to complete strings instead.
  • Expecting the last class in the string to win: stylesheet order decides. Use cn for overrides.
  • Thinking md: means "on medium screens only": it means "medium and up". To target only small screens, use the unprefixed class plus an override (e.g. flex xs:hidden, as MobileHeader does).
  • dark: doing nothing: check the dark class is on <html> and that @custom-variant dark is in your CSS.
  • Dropdown hidden behind the map: raise its z-index above Leaflet's 1000.
  • Treating shadcn as a library to upgrade: copied files don't update themselves; re-run the CLI or edit them yourself.
Recap
  • Utility classes each set one thing; Tailwind v4 generates CSS only for classes found whole in your source.
  • Sizes come from --spacing (0.25rem); brackets and (--var) give arbitrary values; ! makes a class important.
  • Variants (hover:, data-[...]:, md:, dark:) apply classes conditionally and can be stacked.
  • Breakpoints are min-width: write the phone layout first, add prefixes as the screen grows; the project adds xs = 500 px with @theme.
  • Dark mode = .dark on <html> + a custom variant + tokens that the .dark rule redefines.
  • cn = clsx + tailwind-merge for safe overrides; shadcn copies Radix-based components into src/components/ui for you to own.
