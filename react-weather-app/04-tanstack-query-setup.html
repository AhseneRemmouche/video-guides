Installing TanStack Query

Add TanStack Query and wrap the app in a QueryClientProvider.

▶ Watch this part (07:35)

Goal

Install TanStack Query and connect it to the whole app with a QueryClient and a QueryClientProvider in main.tsx. This chapter runs from 07:30 to 09:22. Nothing changes on screen yet: you are laying the pipes that every weather card will use from step 06 on.

"Now that we have Tailwind added, for the data fetching part we're going to add TanStack Query, which some people still call React Query, into our project" (07:30). The presenter has two separate videos about it and assumes "at least a foundational understanding", so this page fills in the basics.

New to TanStack Query? What problem it solves

Fetching data in React by hand means writing, for every request: a state variable for the data, one for "is it loading?", one for the error, a useEffect that starts the request, and code to avoid showing old answers when the input changes. Then you notice that two components need the same data and fetch it twice.

TanStack Query (formerly React Query; the package is still @tanstack/react-query) does all of that for you. You give it two things: a name for the data (a query key, such as ["weather", coords]) and a function that fetches it (a query function). It gives back data, isLoading, error and more, and it keeps the answer in a cache. If four cards ask for the same key, there is only one request.

By default it also retries a failed request (3 times), refetches when you come back to the browser tab, and keeps unused data for 5 minutes. You will see these defaults matter in steps 25 and 26.

New to context and providers? How a value reaches every component

Normally data travels down the component tree through props: a parent passes it to its child, which passes it to its child, and so on. For something that almost every component needs (the query cache, the current theme), passing it by hand through every level would be tedious.

Context is React's way to make a value available to a whole subtree. A provider component puts the value in; any component below it, however deep, can read it with a hook. QueryClientProvider puts the client in, and useQuery reads it (internally it calls useQueryClient()). That is why the provider must be above every component that uses a query. You will build your own context and provider for the theme in step 24.

The finished main.tsx

The repository's final version adds one more provider. Lines 6 and 13–15 come from step 24 (light and dark mode); everything else is exactly what you typed above.

import { StrictMode } from "react"
import { createRoot } from "react-dom/client"
import "./index.css"
import App from "./App.tsx"
import { QueryClient, QueryClientProvider } from "@tanstack/react-query"
import ThemeProvider from "./components/ThemeProvider.tsx"

const queryClient = new QueryClient()

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <ThemeProvider>
        <App />
      </ThemeProvider>
    </QueryClientProvider>
  </StrictMode>
)

What you should see

  • @tanstack/react-query appears under dependencies in package.json.
  • The page looks exactly as before (the red square). No errors in the terminal or in the browser console (F12 → Console).

Common mistakes

  • No QueryClient set, use QueryClientProvider to set one in the console later, with a blank page. A component calls useQuery but is not inside <QueryClientProvider>, or the provider was added in a different file than the one index.html loads. Wrap <App /> in main.tsx.
  • Forgetting the client prop (<QueryClientProvider> alone). TypeScript underlines it in red: the prop is required.
  • Writing client="queryClient" with quotes. That passes the text, not the object. Use curly braces.
  • Creating the client inside App. It seems to work, but the cache is replaced on every render. Keep it at the top of main.tsx.
  • Installing react-query (the old v3 package) or copying v3/v4 examples. In v5, useQuery takes one object (useQuery({ queryKey, queryFn })), not separate arguments.

Optional, not in the video: TanStack's devtools show every query, its key, its state and the cached data in a panel at the bottom of the page. Install @tanstack/react-query-devtools as a dev dependency and add <ReactQueryDevtools /> (imported from that package) inside the provider, next to <App />. It is left out of the production build automatically. Very handy when a card does not update in later steps.

Recap
  • npm i @tanstack/react-query installs TanStack Query v5.
  • new QueryClient() creates the cache once, at the top level of main.tsx, outside any component.
  • <QueryClientProvider client={queryClient}> around <App /> shares it through context with every component.
  • The finished file adds ThemeProvider inside it in step 24.
