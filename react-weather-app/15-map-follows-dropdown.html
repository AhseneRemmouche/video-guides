Interactive Map: Following the Dropdown

Make the map move when the city changes: the key trick, then panTo.

▶ Watch this part (02:26:15)

Goal

After step 14 the dropdown updates every card, but "nothing happens with the map. … The map just stays exactly where it was" (2:26:06). In this short step you make the map follow the selected city. The presenter tries two approaches on camera, and both are worth understanding:

  1. The key trick (2:27:14): give MapContainer a key made from the coordinates, so React throws the map away and builds a new one whenever they change. It works, but the map flickers "to the middle of the ocean" first.
  2. panTo from a prop (2:28:23): pass the coordinates to MapClick and move the existing map with map.panTo. Smooth for map clicks; for the dropdown a flicker remains, and the presenter correctly traces it to the 0, 0 fallback from step 14.

The second version is what the repo ships. At the end you'll see the complete final Map.tsx and what is still worth improving (done in step 25).

What the presenter explains

The presenter's first guess (2:26:52): "because this map container is kind of just a generic wrapper around the vanilla JavaScript library of Leaflet, it might not consider this center right here changing to be a valid enough reason to trigger a rerender". So they force one: "If the key of a component changes, React is 100% going to rerender the component" (2:27:14). The map now moves, "however, I'm sure you're noticing this little problem here. This flickering thing. Anytime we go somewhere, it flickers to looks like the middle of the ocean first" (2:27:37–2:28:00). They blame the key approach, since it rebuilds the whole component every time.

Second idea (2:28:23): remove the key, pass coords to MapClick, and call map.panTo directly in its body. Their reasoning (2:29:32): MapClick re-renders when its props change, and "this map should only ever rerender when the coordinates change", so running panTo in the body is fine and "makes it less complicated than having to do something like a useEffect, which I generally caution against" (2:29:56). Map clicks now glide without flicker. But picking Manila from the dropdown still flickers (2:30:18), and here the presenter finds the real cause (2:30:40): while the geocode request is "still in flight", the geocode data is undefined, "so basically for a split second we fall back to 0 0 for our coordinates". They decide to address it later with Suspense and skeleton loaders (2:31:26).

New to how react-leaflet updates the map? Created once, then left alone

React re-rendering a component and Leaflet moving a map are two different things. When coords change, Map does re-render and MapContainer receives the new center. But in react-leaflet 5, MapContainer creates the Leaflet map once, in a callback that runs when its div first appears, and calls map.setView(center, zoom) there and nowhere else. Later values of center and zoom are simply not read. This is deliberate: otherwise every re-render would yank the map back while the user is dragging it.

So the presenter's guess is close but not exact: the re-render happens; it just doesn't move the map. Moving an existing map is done by calling Leaflet methods on it: map.panTo(latlng) (animated move, same zoom), map.setView(latlng, zoom) (jump, optionally changing zoom) or map.flyTo(latlng, zoom) (animated zoom-out-and-in).

Approach 1: the key trick

New to key as a reset button?

In step 13, key told React which list item is which. It has a second use: React treats an element with a different key as a different component. When the key changes, React unmounts the old one (running its cleanup, discarding its state) and mounts a brand-new one from scratch. That is a full reset, not just a re-render.

It is a legitimate tool, for example to reset a form when you switch to another user. But it is expensive for something like a map: the old Leaflet map is destroyed (react-leaflet calls map.remove()), a new one is created, and all tiles are requested again.

Where the "middle of the ocean" really comes from

Latitude 0, longitude 0 is in the Gulf of Guinea, off the coast of West Africa: open ocean. The map shows it because App computes coords = 0, 0 while the geocode request for the new city is in flight (geocodeData?.[0].lat ?? 0, step 14). This was verified in the browser test of the final app, which also showed the cards requesting the weather for 0, 0 on every load. At 2:28:00 the presenter attributes the flicker to the key approach; the key only makes it more dramatic (a rebuilt map instead of a pan). At 2:30:40 they identify the fallback correctly, but the fallback stays in the final code. Step 25 removes it: no coordinates yet means no map move and no weather request.

Approach 2: panTo from a prop

Instead of rebuilding the map, keep the one Leaflet map and tell it to move. MapClick already has the map (from useMap()); it just needs the coordinates.

export default function Map({ coords, onMapClick }: Props) {
  const { lat, lon } = coords
  return (
    <MapContainer
      center={[lat, lon]}
      zoom={5}
      style={{ width: "700px", height: "500px" }}
    >
      <MapClick onMapClick={onMapClick} coords={coords} />
      <TileLayer
        attribution='&copy; <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a> contributors'
        url="https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png"
      />
      <Marker position={[lat, lon]} />
    </MapContainer>
  )
}

function MapClick({
  onMapClick,
  coords,
}: {
  onMapClick: (lat: number, lon: number) => void
  coords: Coords
}) {
  const map = useMap()
  map.panTo([coords.lat, coords.lon])

  map.on("click", (e) => {
    const { lat, lng } = e.latlng
    onMapClick(lat, lng)
  })

  return null
}

New to side effects in render? Why useEffect exists

React expects the body of a component to be pure: given the same props and state, compute JSX and do nothing else. Moving a map, adding an event listener, or sending a request are side effects: they change something outside React. React may render a component more often than you expect: when a parent re-renders for an unrelated reason, or twice in a row in development under Strict Mode.

useEffect(fn, deps) is the place for side effects that should follow a change: React runs fn after rendering, only when a value in deps changed, and runs its returned cleanup before the next run or on unmount. The presenter is right that effects are overused (many things people put in effects are really derived values), but synchronising an outside system like a Leaflet map with React state is exactly what they are for.

The presenter's assumption is that MapClick "should only ever rerender when the coordinates change". That holds today, but not for long: from step 16 the map-type dropdown re-renders App, Map and MapClick without changing coords, and later the side panel and theme toggle do too. Each such render calls panTo again (harmless if you haven't moved the map, but it pulls the map back to the marker if you dragged it away) and adds one more click listener. This is reasoned from the code, not measured in the browser test.

About line 58

In the original repo, line 58 contains a real MapTiler API key written directly in the code. It has been replaced here with "YOUR_MAPTILER_KEY". Never commit keys to a public repository; step 28 explains what to do instead (environment variables, and origin restrictions in the MapTiler dashboard).

import { MapContainer, Marker, TileLayer, useMap } from "react-leaflet"
import "leaflet/dist/leaflet.css"
import type { Coords } from "../types"
import { useEffect } from "react"
import { MaptilerLayer } from "@maptiler/leaflet-maptilersdk"

const API_KEY = import.meta.env.VITE_API_KEY

type Props = {
  coords: Coords
  onMapClick: (lat: number, lon: number) => void
  mapType: string
}

export default function Map({ coords, onMapClick, mapType }: Props) {
  const { lat, lon } = coords
  return (
    <MapContainer
      center={[lat, lon]}
      zoom={5}
      style={{ width: "100%", height: "100%" }}
    >
      <MapClick onMapClick={onMapClick} coords={coords} />
      <MapTileLayer />
      <TileLayer
        opacity={0.7}
        url={`https://tile.openweathermap.org/map/${mapType}/{z}/{x}/{y}.png?appid=${API_KEY}`}
      />
      <Marker position={[lat, lon]} />
    </MapContainer>
  )
}

function MapClick({
  onMapClick,
  coords,
}: {
  onMapClick: (lat: number, lon: number) => void
  coords: Coords
}) {
  const map = useMap()
  map.panTo([coords.lat, coords.lon])

  map.on("click", (e) => {
    const { lat, lng } = e.latlng
    onMapClick(lat, lng)
  })

  return null
}

function MapTileLayer() {
  const map = useMap()

  useEffect(() => {
    const tileLayer = new MaptilerLayer({
      style: "basic-dark",
      apiKey: "YOUR_MAPTILER_KEY",
    })
    tileLayer.addTo(map)

    return () => {
      map.removeLayer(tileLayer)
    }
  }, [map])

  return null
}

For comparison, this is how step 25 rewrites MapClick (excerpt from the fixed file): one listener managed by react-leaflet, and a pan only when the numbers change.

  // useMapEvents registers the click listener once and removes it on unmount
  const map = useMapEvents({
    click(e) {
      onMapClick(e.latlng.lat, e.latlng.lng)
    },
  })

  // pan only when the coordinates change, not on every render
  useEffect(() => {
    map.panTo([coords.lat, coords.lon])
  }, [map, coords.lat, coords.lon])

What you should see

  • With the key version: the map jumps to each city you pick, but flashes to open ocean first and resets the zoom.
  • With the panTo version: clicking the map glides smoothly to the click, keeping your zoom.
  • Picking a city from the dropdown glides to it too, with a brief detour towards 0, 0 while the city is geocoded (most visible the first time you pick a city; cached cities are instant).

Common mistakes

  • Using coords.longitude (the presenter's first attempt at 2:29:10): TypeScript reports "Property 'longitude' does not exist on type 'Coords'". It's lon.
  • Keeping both the key and panTo: the key still rebuilds the map on every change, so you keep the flash and gain nothing.
  • Calling panTo inside the click handler and in the body: two pans per click. Let the state drive the pan.
  • Forgetting to pass coords to MapClick: "Cannot read properties of undefined (reading 'lat')" from the panTo line.
  • Expecting center to move the map: it is only read when the map is created (react-leaflet's design, not a bug).

Leaflet's camera methods (panTo, setView, flyTo) and react-leaflet's hooks are covered in Maps on the Web; effects and keys in React Fundamentals.

Recap
  • MapContainer reads center only when it creates the Leaflet map; later changes don't move it.
  • Version 1 (2:27:14): key={`${coords.lat},${coords.lon}`} rebuilds the map on every change: it works, but flashes and reloads all tiles.
  • The "middle of the ocean" is latitude 0, longitude 0: the geocode fallback from step 14, verified in the browser test; the presenter traces it at 2:30:40, and it stays in the final code until step 25.
  • Version 2 (2:29:30, the repo's version): pass coords to MapClick and call map.panTo; clicks only report via onMapClick.
  • panTo and map.on in the render body run on every render; step 25 moves them into useEffect and useMapEvents.
  • The final Map.tsx shown here has its hard-coded MapTiler key replaced with "YOUR_MAPTILER_KEY".
