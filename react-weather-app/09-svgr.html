SVG Icons with svgr

Import SVG files as React components with vite-plugin-svgr.

▶ Watch this part (01:27:51)

Goal

The Additional Weather Info card from step 08 is plain text, which looks bland next to the cards with weather icons (1:26:34). In this step (1:27:51–1:33:05) you give each of its six rows a small icon. The icons are SVG files, and a Vite plugin called vite-plugin-svgr lets you import each file as a React component:

import Cloud from "/src/assets/cloud.svg?react"

<Cloud className="size-8" />

You'll add the plugin to vite.config.ts, teach TypeScript about the special ?react imports with one line in src/vite-env.d.ts, and render the icons from the rows array. The same technique is used later for the hamburger menu, the sun/moon of the theme switch and the side panel icons.

New to SVG? What it is and why it suits icons

SVG (Scalable Vector Graphics) is an image format written as text: shapes like <path d="M12 3V4…"/> inside an <svg> tag. Because it describes shapes instead of pixels, it stays sharp at any size, and the files are tiny.

There are two ways to show an SVG on a page: as a picture (<img src="cloud.svg">), or inline, with the <svg> markup placed directly in the HTML. Inline SVGs can be styled with CSS classes like any element. svgr automates the inline way: it converts an SVG file into a React component that renders that markup.

1. Register the plugin in vite.config.ts

New to Vite plugins? What the plugins array does

Vite itself only knows how to serve and bundle plain JavaScript, CSS and static files. Plugins teach it more: react() handles JSX and fast refresh, tailwindcss() generates the Tailwind CSS (step 03), and now svgr() turns *.svg?react imports into components. Each plugin is a function you call; the array lists them in order. After editing vite.config.ts, Vite restarts the dev server by itself; if it doesn't, stop it with Ctrl+C and run npm run dev again.

Try the video's version: vite.config.ts at 1:28:30

import { defineConfig } from "vite"
import react from "@vitejs/plugin-react"
import tailwindcss from "@tailwindcss/vite"
import svgr from "vite-plugin-svgr"

// https://vite.dev/config/
export default defineConfig({
  plugins: [react(), tailwindcss(), svgr()],
})

2. Tell TypeScript about ?react imports

After writing the imports, every line is underlined in red (1:30:28). TypeScript resolves imports by itself and has no idea what /src/assets/sunrise.svg?react is. Removing the reference line from this project and running tsc shows exactly that error:

src/components/cards/AdditionalInfo.tsx(4,21): error TS2307: Cannot find module '/src/assets/sunrise.svg?react' or its corresponding type declarations.

The plugin ships a type declaration that fixes this; you just have to point TypeScript at it.

/// <reference types="vite-plugin-svgr/client" />

Line by line

Line(s)CodeWhat it does & why
1/// <reference types="vite-plugin-svgr/client" />A triple-slash directive: a special comment that tells TypeScript to load the type file client.d.ts from the vite-plugin-svgr package. That file says: any module named "*.svg?react" has a default export that is a React function component accepting all normal <svg> props (className, style, onClick…) plus optional title/desc. Now Cloud is typed and <Cloud className="size-8" /> is accepted.
New to .d.ts files? And why the file must be inside src/

A .d.ts file contains only type information, no code that runs. It's where you describe things TypeScript can't see by itself, like special import paths. (The name vite-env.d.ts is a convention from Vite's templates; see vite-env.)

TypeScript only reads the files listed in the "include" setting of tsconfig.app.json, which in this project is ["src"]. A vite-env.d.ts at the project root is simply ignored by that config, so the errors stay. That's why moving the file into src/ fixed it in the video (1:31:12).

3. Import and render the icons

Each icon is imported with an absolute path that starts at the project root. In Vite, a path beginning with / means "from the project root", so /src/assets/cloud.svg?react works from any file. Relative paths (../../assets/cloud.svg?react) or, after step 12, @/assets/cloud.svg?react would work too.

Common mistakes

  • Importing without ?react: you get the file's URL as a string, not a component, and <Cloud /> fails.
  • Forgetting svgr() in the plugins array: the package is installed but nothing converts the files.
  • vite-env.d.ts at the project root: TypeScript ignores it (the app config only includes src). Move it into src/.
  • Lowercase component names such as <icon />: React renders an unknown HTML tag called "icon" instead of your component.
  • Copy-paste slips in the import list: in the video all six lines first pointed to sunrise.svg (1:29:14) before the file names were changed; make sure each name points to its own file.
  • Giant icons: the downloaded SVGs declare width="800px" height="800px". Without a size class like size-8 they render at that size.
Recap
  • npm install --save-dev vite-plugin-svgr and svgr() in the Vite plugins array.
  • Import an SVG as a component with the ?react suffix: import Cloud from "/src/assets/cloud.svg?react".
  • /// <reference types="vite-plugin-svgr/client" /> in src/vite-env.d.ts gives those imports a type; the file must be inside src/.
  • svgr components accept normal <svg> props, so className="size-8" sizes them.
  • Components can be stored in data (Icon: Cloud) and rendered from a map as <Icon />.
  • The icons are black files; invert (video) or .dark svg { filter: invert(1) } (repo, step 24) makes them readable in dark mode.
