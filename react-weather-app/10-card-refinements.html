New to inline styles in React? The double curly braces

In HTML you write style="transform: rotate(184deg)", a string. In React the style prop takes a JavaScript object instead, with camelCase property names (backgroundColor, not background-color).

That's where the double braces come from: the outer { } means "a JavaScript expression follows" (like any JSX value), and the inner { } is the object itself: style={{ transform: "rotate(184deg)" }}.

Tailwind classes can't be used here because the angle is only known at run time, from the API; Tailwind generates its CSS ahead of time from class names it finds in your files. For values computed from data, an inline style is the right tool.

New to CSS rotate()? How the angle turns the arrow

transform: rotate(Xdeg) turns an element clockwise around its centre by X degrees, without moving anything around it. An arrow that points up at 0° points right at 90°, down at 180° and left at 270°. The compass works the same way (0° = north, 90° = east…), so an up arrow rotated by a compass bearing points in that compass direction.

function FormatComponent({ value, number }: { value: string; number: number }) {
  if (value === "sunrise" || value === "sunset")
    return new Date(number * 1000).toLocaleTimeString(undefined, {
      hour: "numeric",
      minute: "2-digit",
      hour12: true,
    })

  if (value === "wind_deg")
    return (
      <UpArrow
        className="size-8"
        style={{ transform: `rotate(${number}deg)` }}
      />
    )

  return number
}

Checking the arrow against the API

The presenter doesn't trust the arrow blindly (1:35:24): open DevTools (F12), go to the Network tab, refresh the page, click the One Call request (its name starts with onecall), open Response, and look at current.wind_deg. In the video it says 184, and the arrow points just past straight down: they agree.

Good to know: which way does the wind blow? (Not covered in the video.) OpenWeather documents wind_deg as a meteorological direction, the convention weather services use: the direction the wind is coming from. 184° means a wind from just west of south, blowing towards the north. The presenter's arrow (rotated by exactly wind_deg) therefore points to where the wind comes from, which is how the number is defined, but the opposite of "the direction the wind is going". If you prefer the arrow to show where the wind blows to, rotate by number + 180. Either is fine; just label it so users know which one they're looking at. Also consider giving the arrow a text alternative for screen readers, e.g. role="img" and aria-label={`${number}°`}; svgr passes such props to the <svg>.

Common mistakes

  • A giant arrow: no size class; add className="size-8".
  • A string instead of an object: style="transform: rotate(…)" is HTML syntax. In React, TypeScript reports that a string isn't assignable to the style type; use style={{ transform: … }}.
  • Forgetting the unit: `rotate(${number})` without deg is invalid CSS and the browser silently ignores it, so the arrow always points up.
  • Normal quotes instead of backticks: "rotate(${number}deg)" keeps the literal text ${number}; only backticks insert the value.
  • A typo in "wind_deg": the branch never matches and you keep seeing the number.
Recap
  • FormatComponent now has three outcomes: a time (sunrise/sunset), a rotated arrow (wind_deg), or the plain number.
  • React's style prop takes an object; values computed from data (like an angle) belong there, not in Tailwind classes.
  • rotate(Xdeg) turns an up arrow clockwise, so the angle equals the compass direction it points to.
  • Always size svgr icons; downloaded SVG files often declare a large fixed size.
  • Check what the UI shows against the raw response in the Network tab.
  • All four cards now share one query and one Card frame; next, the map makes the location changeable.
