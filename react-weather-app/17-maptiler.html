Custom Base Map with MapTiler

Replace the default tiles with a MapTiler style.

▶ Watch this part (02:44:52)

Goal

The base map from step 11 is OpenStreetMap's standard style: light greens and blues that "just does not blend in with the rest of our app at all" (at 2:45:03), which is dark and uses shadcn's zinc greys. In this step you swap it for a dark base map from MapTiler, using MapTiler's Leaflet plugin. You'll also soften the weather layer with opacity.

Along the way you meet a pattern you'll use whenever React has to drive a plain JavaScript library: a small component that renders nothing and does its work in useEffect, with a cleanup function that undoes it.

About the API key in Map.tsx. The official repo has a real MapTiler key typed directly into Map.tsx (line 58). This guide replaces it with "YOUR_MAPTILER_KEY". Don't copy keys from the video or the repo: create your own (below), and preferably keep it in .env as shown in "A safer way to pass the key".

What the presenter explains

Why MapTiler (2:45:03): "This map right here is just the default map from Open Street Map. But if you want to get a fancier looking one or one that matches our theme a little bit more, we can use a service called Maptiler." The presenter browses MapTiler's styles and picks a dark one that "definitely matches kind of this color scheme".

An SDK, not just a URL (2:45:26): "To add a map like this, we'll first have to install the SDK for map tyler", the Leaflet extension @maptiler/leaflet-maptilersdk. Background the video doesn't go into: MapTiler's styles are vector maps (drawn in the browser from map data by the MapLibre engine inside the SDK, not downloaded as finished pictures), which is why a plain TileLayer URL isn't enough.

Use useMap and useEffect (2:46:12–2:47:00): like MapClick, the new MapTileLayer component is "purely for functionality not for actually rendering JSX", so it returns null. "I generally caution against using use effects. But when interfacing with straight JavaScript … or interfacing with external libraries, it's generally okay."

The style (2:47:24): basic-dark "looks really similar … but is actually quite a bit more lightweight … and will be a little bit faster".

An API key (2:47:46): "Just like Open Weather, Map Tyler wants you to use an API key." The presenter says it's free and needs no payment information, only an account (their words at the time of recording; check MapTiler's current plans yourself).

Always clean up (2:48:54): "working with use effects, especially that involve external libraries, it's almost always a smart idea to have a cleanup".

Soften the weather (2:49:43): on the dark map, the white clouds look "kind of harsh", so the weather TileLayer gets opacity={0.7}.

Step by step

  1. Create a MapTiler account Log in (2:48:09). In the menu, open API keys and copy your key (or create one with New key). The key page itself says: "we are highly recommending using one key per web application and set allowed HTTP origins to prevent stealing of the key" (visible at 2:48:09). More on that below.
  2. Install the Leaflet extension Run this in the project folder (2:45:50): 
    npm i @maptiler/leaflet-maptilersdk

    npm i is short for npm install: it downloads the package into node_modules and adds it to dependencies in package.json. The @maptiler/ part is the publisher's scope. This project's lockfile has version 4.1.1.

  3. Write MapTileLayer Put it at the bottom of src/components/Map.tsx (2:46:12–2:48:54): get the map with useMap(), create a MaptilerLayer inside useEffect, add it with addTo(map), and return a cleanup that calls map.removeLayer. Import useEffect from react and MaptilerLayer from the package.
  4. Replace the OpenStreetMap <TileLayer> Swap the one with attribution for <MapTileLayer /> (2:49:18). Save: the map turns dark.
  5. Add opacity={0.7} It goes on the OpenWeather <TileLayer> (2:49:43).

New to useEffect and cleanup? Running code after React renders

useEffect(setup, dependencies) tells React: "after you've put this component on the screen, run setup". If setup returns a function, React keeps it as the cleanup and runs it:

  • before running setup again (when a value in the dependency array changed), and
  • when the component is removed from the page (unmounted).

Effects are meant for talking to things outside React: timers, the browser, or a library like Leaflet that keeps its own state. Leaflet doesn't know about React's renders; if you add a layer, Leaflet keeps it until you remove it. The cleanup is that "remove it".

The dependency array [map] means "run again only if map changes". The map object stays the same for the life of the MapContainer, so in practice the layer is added once and removed once.

The complete file: Map.tsx

The final file from the repo, with the MapTiler key replaced by "YOUR_MAPTILER_KEY" on line 58.

import { MapContainer, Marker, TileLayer, useMap } from "react-leaflet"
import "leaflet/dist/leaflet.css"
import type { Coords } from "../types"
import { useEffect } from "react"
import { MaptilerLayer } from "@maptiler/leaflet-maptilersdk"

const API_KEY = import.meta.env.VITE_API_KEY

type Props = {
  coords: Coords
  onMapClick: (lat: number, lon: number) => void
  mapType: string
}

export default function Map({ coords, onMapClick, mapType }: Props) {
  const { lat, lon } = coords
  return (
    <MapContainer
      center={[lat, lon]}
      zoom={5}
      style={{ width: "100%", height: "100%" }}
    >
      <MapClick onMapClick={onMapClick} coords={coords} />
      <MapTileLayer />
      <TileLayer
        opacity={0.7}
        url={`https://tile.openweathermap.org/map/${mapType}/{z}/{x}/{y}.png?appid=${API_KEY}`}
      />
      <Marker position={[lat, lon]} />
    </MapContainer>
  )
}

function MapClick({
  onMapClick,
  coords,
}: {
  onMapClick: (lat: number, lon: number) => void
  coords: Coords
}) {
  const map = useMap()
  map.panTo([coords.lat, coords.lon])

  map.on("click", (e) => {
    const { lat, lng } = e.latlng
    onMapClick(lat, lng)
  })

  return null
}

function MapTileLayer() {
  const map = useMap()

  useEffect(() => {
    const tileLayer = new MaptilerLayer({
      style: "basic-dark",
      apiKey: "YOUR_MAPTILER_KEY",
    })
    tileLayer.addTo(map)

    return () => {
      map.removeLayer(tileLayer)
    }
  }, [map])

  return null
}

New to useMap? How a React component reaches the Leaflet map

MapContainer creates one Leaflet map and shares it with everything inside it through React context. useMap() reads that context. That's why MapClick and MapTileLayer must be rendered inside <MapContainer>.

react-leaflet has ready-made components for Leaflet's own layers (TileLayer, Marker, …). For a third-party layer like MaptilerLayer there is no component, so you write the small "null component" yourself. That's a common react-leaflet pattern, and the same shape works for any plugin.

A safer way to pass the key

Putting the key in .env keeps it out of your Git history. This is how step 25 does it (verified, extract of code/ext25/src/components/Map.tsx):

const MAPTILER_KEY = import.meta.env.VITE_MAPTILER_KEY
…
  useEffect(() => {
    if (!MAPTILER_KEY) return // no key: keep the weather layer only
    const tileLayer = new MaptilerLayer({
      style: "basic-dark",
      apiKey: MAPTILER_KEY,
    })
    tileLayer.addTo(map)

    return () => {
      map.removeLayer(tileLayer)
    }
  }, [map])
VITE_API_KEY=your-openweather-key
VITE_MAPTILER_KEY=your-maptiler-key
  1. Add the line to .env It goes in the project root, next to VITE_API_KEY. The VITE_ prefix is required: Vite only exposes environment variables with that prefix to browser code.
  2. Restart npm run dev. Vite reads .env when it starts.
  3. Make sure .env is ignored by Git. This project's .gitignore covers *.local (so .env.local) but not .env itself. Add a line .env, or name your file .env.local. Step 28 adds both.
  4. Restrict the key to your site. In MapTiler Cloud, open the key and add the allowed HTTP origins: your deployed domain, plus localhost while you develop. Requests from other websites using your key are then refused.
New to restricting API keys? Why a "public" key can still be safe enough

Some keys are meant to be used from the browser, where anyone can read them: map keys are the classic example. The provider protects you in a different way: you tell it which websites (origins, like https://myweather.example) are allowed to use the key. The browser adds the page's origin to every request automatically, and a normal web page can't fake it, so another site that copies your key gets refused.

This doesn't stop someone from calling the API with a script that sends a fake origin, so keep an eye on your usage in the dashboard. Keys that must stay secret (like a paid OpenWeather key) need a small server in between. See API key and the handbook chapter HTTP, REST APIs & API Keys.

After saving, the map is dark grey with light labels, with the MapTiler logo in the bottom-left corner and "Leaflet | © MapTiler © OpenStreetMap contributors" in the bottom-right (the SDK adds these credits itself, frame at 2:50:15). Common mistakes.
  • Map area stays empty or grey: the key is missing or wrong. Check the Console and Network tab for failed api.maptiler.com requests. With the .env version, check the variable name and restart the dev server.
  • "useMap" error ("No context provided…"): <MapTileLayer /> is rendered outside <MapContainer>.
  • Both maps at once: you added <MapTileLayer /> but kept the OpenStreetMap <TileLayer>. Remove the old one.
  • Origin restriction too strict: after restricting the key, localhost stops working unless it's in the allowed list too.
  • Committing the key: if a real key ever reached GitHub, deleting the line isn't enough (it stays in history). Create a new key in the dashboard and delete the old one.

Recap
  • MapTiler styles are added with @maptiler/leaflet-maptilersdk's MaptilerLayer, not a TileLayer URL.
  • A component that returns null can still use hooks: useMap gets the map, useEffect adds the layer.
  • The cleanup map.removeLayer(tileLayer) undoes the effect; StrictMode tests it in development.
  • Put every value the effect uses in the dependency array ([map]); ESLint warns if you don't.
  • opacity={0.7} on the weather layer keeps the dark map readable.
  • Never hard-code keys: use VITE_MAPTILER_KEY in an ignored .env, and restrict the key to your origins.
