Goal

The next feature is a dropdown of popular cities above the map (step 13). A good dropdown is surprisingly hard to build: it must open and close, work with the keyboard, scroll long lists, stay on screen, and be readable by screen readers. Instead of writing all that, the presenter uses shadcn/ui, a collection of ready-made components that are copied into your project as source files.

This step is mostly setup. You add a path alias (@/ = src/) to TypeScript and Vite, run shadcn init (which writes components.json, src/lib/utils.ts and theme variables in index.css), repair the colours that change as a result, and finally add the Select component. No new feature is visible yet; the payoff comes on the next page.

New to shadcn/ui? A component library you copy, not install

Most UI libraries are npm packages: you install them, import their components, and their code lives hidden in node_modules. shadcn/ui works differently. Its command-line tool copies the component's source code into your project (here src/components/ui/select.tsx). From then on it is your file: you can read it, change its classes, or delete parts.

The heavy lifting inside those files is done by Radix UI primitives (installed from npm), which handle behaviour and accessibility: focus, keyboard navigation, ARIA attributes, positioning. shadcn adds the look with Tailwind classes and icons from lucide-react.

The presenter's summary (2:00:25): "a component library that allows you to install components as needed, not some library where we install 10 GB of packages". And their reason: "I think it's important to not reinvent the wheel, especially if you want to keep things consistent" (2:01:11).

The path alias: @/ means src/

shadcn's files import each other with paths like @/lib/utils. The @ is not an npm scope here; it is an alias you define. It must be taught to two different tools, which is why there are three config edits.

New to path aliases? Why two tools need to know

Relative imports like ../../lib/utils depend on where the importing file sits, and break when you move files. An alias gives a fixed starting point: @/lib/utils always means src/lib/utils, from any folder.

But an alias is only a convention, so every tool that reads imports must be told about it:

  • TypeScript (your editor and tsc -b in npm run build) reads compilerOptions.paths in the tsconfig files, so it can find the file and check types.
  • Vite (the dev server and the bundler) reads resolve.alias in vite.config.ts, so it can actually load the file in the browser and in the build.

If only TypeScript knows, the editor is happy but the page fails with "Failed to resolve import". If only Vite knows, the page works but the editor shows red squiggles and npm run build stops at the type-check.

Why the app turned white, and the fix

After restarting the dev server, "all the styling suddenly looks pretty bad. These cards have a bunch of dark text now. And now the background of our app is white" (2:04:38). init rewrote src/index.css with two sets of colour variables: a light set on :root and a dark set on .dark, plus a line that makes Tailwind's dark: variant depend on a dark class. The page body now uses --background and --foreground, and without the dark class those are the light values.

New to CSS variables and design tokens?

A CSS variable (custom property) is a named value: --card: oklch(…) defines it, var(--card) reads it. If the same variable is defined in two places, the more specific or later rule wins for elements it matches. shadcn uses this for theming: :root (the whole page) defines the light colours, .dark redefines the same names with dark colours. Put class="dark" on an ancestor and every element inside reads the dark values.

Tailwind v4 turns those variables into utilities through @theme inline { --color-card: var(--card); … } in index.css: that is what makes bg-card, text-card-foreground and so on exist. Names like "card" or "popover" describe a role, not a colour; that is what "design token" means. Change the token once and every card follows.

Common mistakes

  • "Validating import alias" fails in init: the paths block is missing from the root tsconfig.json (not only tsconfig.app.json).
  • Failed to resolve import "@/lib/utils" in the browser: the resolve.alias block is missing in vite.config.ts, or Vite was not restarted after editing it.
  • Cannot find module 'path' or Cannot find name '__dirname' in vite.config.ts: you skipped npm install -D @types/node.
  • JSON error after editing tsconfig.app.json: a missing comma before "baseUrl", or the block pasted outside compilerOptions.
  • Everything white after init: expected. Add class="dark" to <body> and use token classes like bg-card instead of fixed colours.
  • Running shadcn add from the wrong folder: run it in the project root, where components.json is.

For more on Tailwind v4's CSS-first config, tokens and how shadcn fits in, read Styling with Tailwind CSS & shadcn/ui.

Recap
  • shadcn/ui copies component source into src/components/ui; Radix provides behaviour and accessibility, Tailwind the look.
  • The @/ alias must be added to the tsconfig files (for TypeScript) and to vite.config.ts (for Vite), plus @types/node for path.
  • npx shadcn@latest init (base colour Zinc) writes components.json, src/lib/utils.ts and the theme variables in index.css.
  • cn() = twMerge(clsx(...)): join classes, then let later ones win.
  • Colours are now tokens (bg-card) with light values on :root and dark values on .dark; the video hard-codes <body class="dark"> until step 24.
  • npx shadcn@latest add select creates select.tsx; its main pieces are Select, SelectTrigger, SelectValue, SelectContent and SelectItem.
