Location Dropdown

A dropdown of cities that sets the location state.

▶ Watch this part (02:09:20)

Goal

Clicking the map works for "somewhere over there", but people usually think in city names. In this short step you build a location dropdown with twelve popular cities, using the shadcn Select from step 12. You paste shadcn's usage example, fix a layering problem (the list opens behind the map), and replace the example's items with a list rendered from an array.

At the end of this step the dropdown opens and you can pick a city, but picking does nothing yet: the dropdown keeps its choice to itself, and the weather API needs coordinates, not names. Step 14 solves both.

What the presenter explains

The presenter copies the usage example from the shadcn Select page (2:09:08), creates a dropdowns folder "because we're going to have I think two dropdowns in this app, not just one" (the second one, for map layers, comes in step 16), and pastes the example into LocationDropdown.tsx. The editor offers to import the parts from @radix-ui/react-select, but they must come from your own ../ui/select file (2:09:53).

They name the parts (2:10:16): "this select trigger component right here is essentially just the button that triggers the dropdown to open and close and select content is the dropdown itself", all wrapped in Select. Rendered above the map, the open list is "getting cut off quite a bit by the map" (2:11:01): "sometimes the maps that you use have a z-index of around a thousand". The fix is a class on SelectContent, with an honest caveat: "I generally like to stay away from spamming z-indexes everywhere. But sometimes you got to do what you got to do" (2:11:25).

Finally, the example's Light/Dark/System items are replaced with a list of popular cities that the presenter asked ChatGPT for (2:11:47), rendered with locations.map, using each city name as both the key and the value "because these should always be unique" (2:12:10).

New to z-index and stacking? Why the list hid behind the map

When elements overlap, the browser draws them in layers. z-index sets the layer for positioned elements: higher numbers are drawn on top. Elements compete only inside the same stacking context (a group created, for example, by an element with a transform or with both position and a z-index).

Here, Leaflet's CSS gives its map pane z-index: 400 and the corners holding the zoom buttons and attribution z-index: 1000. The map's outer div doesn't create its own stacking context, so those numbers compete directly with the rest of the page. shadcn's list uses z-50 (50) and is rendered in a portal at the end of <body>, so it competes in the same page-wide context. 50 < 400: the map wins and covers the list.

z-1001 is the smallest round number above Leaflet's highest layer (1000). A value like z-[9999] would also work; the point is to beat 1000.

Render a list of cities

The example's three items are replaced by twelve cities. Instead of writing twelve <SelectItem> lines by hand, the presenter keeps the cities in an array and turns each one into an item with .map().

New to rendering lists? map() and the key prop

array.map(fn) builds a new array by calling fn on every element. In JSX, an array of elements renders as those elements in order, so {locations.map((city) => <SelectItem …>{city}</SelectItem>)} turns 12 strings into 12 items.

React needs a key on each element of such a list: a string that is unique among its siblings and stable between renders. React uses it to match old and new items when the list changes, instead of guessing by position. Without it you get the console warning "Each child in a list should have a unique "key" prop" (the presenter saw that warning for another list at 2:23:20). City names are unique, so they make good keys. Avoid the array index as a key when items can be reordered or removed.

The key is for React only; your component never receives it as a prop. That's why the city also goes into value, which Radix does use. Step 15 uses a key in a very different way: changing it on purpose to force React to rebuild a component.

The "Theme" placeholder: a harmless copy-paste slip

placeholder="Theme" comes from shadcn's example (a theme picker) and survives into the final repo. Right now, in this step, you can actually see it: nothing is selected yet, so the button says "Theme" (on screen in the video from 2:11:25). From step 14 on, the dropdown always has a value ("Tokyo" at start), so the placeholder never shows. Still, a placeholder is read by screen readers and shown whenever the value is empty, so give it a meaningful text such as "Choose a city". Step 25 makes that change.

The final file in the repo

This is LocationDropdown.tsx as committed in the repo. It contains changes made later in the video, marked in the table, so you can see where this component ends up.

import type { Dispatch, SetStateAction } from "react"
import {
  Select,
  SelectContent,
  SelectItem,
  SelectTrigger,
  SelectValue,
} from "../ui/select"

type Props = {
  location: string
  setLocation: Dispatch<SetStateAction<string>>
}

export default function LocationDropdown({ location, setLocation }: Props) {
  return (
    <Select value={location} onValueChange={(value) => setLocation(value)}>
      <SelectTrigger className="w-full xs:w-[180px]">
        <SelectValue placeholder="Theme" />
      </SelectTrigger>
      <SelectContent className="z-1001">
        {location === "custom" && (
          <SelectItem value="custom">Custom</SelectItem>
        )}
        {locations.map((city) => (
          <SelectItem key={city} value={city}>
            {city}
          </SelectItem>
        ))}
      </SelectContent>
    </Select>
  )
}

const locations = [
  "Bangkok",
  "Tokyo",
  "Seoul",
  "Dubai",
  "Manila",
  "London",
  "New York",
  "Paris",
  "Berlin",
  "Madrid",
  "Rome",
  "Lisbon",
]

What you should see

  • A 180 px button reading "Theme" at the top left, above the map.
  • Clicking it opens a list of twelve cities drawn over the map, with a check mark next to the selected one after you pick.
  • Keyboard works for free: Tab to the button, Enter or Space to open, arrow keys to move, Enter to choose, Esc to close.
  • Choosing a city changes only the button text. The map and the cards do not move yet.

Common mistakes

  • Accepting the editor's auto-import from @radix-ui/react-select: you get the unstyled primitive (or "has no exported member SelectContent"). Import from ../ui/select.
  • List hidden behind the map: forgot className="z-1001" on SelectContent (not on SelectTrigger: the trigger is not covered, the list is).
  • Warning "Each child in a list should have a unique "key" prop": missing key={city} on SelectItem.
  • An item with value="": Radix reserves the empty string for "no selection" (to show the placeholder) and throws an error for an item with an empty value.
  • Expecting the cards to change: not yet. The dropdown is uncontrolled and the API needs coordinates; step 14 connects it.
Recap
  • LocationDropdown in src/components/dropdowns is built from shadcn's usage example, imported from ../ui/select.
  • SelectTrigger is the button, SelectValue its text, SelectContent the list (in a portal), SelectItem each option.
  • Leaflet's layers go up to z-index 1000; z-1001 on SelectContent lets the list open over the map.
  • Cities live in a locations array; locations.map renders one SelectItem each, with the name as key and value.
  • The placeholder "Theme" is a leftover from the example (fixed in step 25); the dropdown becomes controlled by App in step 14.
