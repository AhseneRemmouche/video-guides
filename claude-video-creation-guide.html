Tutorial walkthrough

Create animated videos with Claude

A no-render-engine way to make explainer videos: Claude writes a self-contained HTML + JavaScript canvas animation (with procedural sound) inside an Artifact, driven by ready-made styles from the AI Style Atlas. Two workflows — with and without an AI voiceover — each with the exact prompts and examples.

Built from the video “Claude Makes a New Kind of Video — Full Tutorial” (watched via Gemini). Each step links to its moment in the video.

The idea in one line

Instead of a text-to-video model, Claude writes plain JavaScript that draws every frame onto an HTML <canvas> with requestAnimationFrame(), and synthesizes sound effects with the Web Audio API — all inside one Artifact. No installs, no render farm, fully editable in chat.

Three tools, all free to start: the AI Style Atlas (prompt library), Claude (the canvas/player), and Google AI Studio (optional TTS voiceover).

How it works ▶ 00:34

Each “style” in the Style Atlas is really a big prompt: it contains a base JavaScript render engine (a draw(t) loop on a canvas), a Web Audio sound kit, and style-specific drawing code. You paste that prompt into Claude with your topic; Claude adapts the drawing math to your subject and returns a playable video Artifact. Because Claude gets the actual code (not a screenshot to imitate), the look stays consistent.

What you'll need

AI Style Atlas

Free library by Futurepedia — 86 animation styles (Glassmorphism UI, Flat-Vector Science, 16-Bit Pixel, Chalkboard, Manim-style math…), each with reference code + a sound kit.

Claude

Claude (Opus or Sonnet) with Artifacts — it writes the HTML/JS and shows the interactive player. ChatGPT also works, slightly lower fidelity.

Google AI Studio

aistudio.google.com — only for Workflow B, to synthesize the AI voiceover with Gemini TTS and export an MP3.

Model/UI names below are what the video shows and can change over time — if a label differs in your account, match by meaning (e.g. the TTS model, the “With voiceover” toggle). Nothing here runs on your machine; you drive each tool yourself.

Workflow A — a video without voiceover

Fastest path: pick a style, type a topic, paste into Claude, approve. Good for silent explainers and social clips.

1

Pick a style on the AI Style Atlas ▶ 03:42

Browse the Atlas and open a style card. Each card has a 15-second sample preview and a “Style clip” option.

Example

The presenter picks Glassmorphism UI (#46, “Dimensional”).

2

Configure the generator & copy the prompt ▶ 04:10

  1. Toggle No voiceover.
  2. In “Your topic or script (optional)”, type your topic.
  3. Leave Storyboard first checked if you want Claude to plan scene beats before building.
  4. Click the blue Copy prompt button — it copies the system instructions + base render engine + sound kit + your topic.
Example topic
how noise cancelling headphones work
3

Paste the prompt into Claude ▶ 04:53

Open a new Claude chat, paste, and send. The prompt is long (it includes full reference code + the audio synth kit), so Claude attaches it as a text file automatically. With “Storyboard first” on, Claude returns a storyboard Artifact: scene beats (Hook, Outside noise, The ear cup, Mix listening…) with preview cards and sound-effect notes.

4

Approve & generate the video ▶ 05:04

If you got a storyboard, reply with one word to build the full video:

Example reply
approved

Claude writes the full HTML5/JS app and opens an interactive player Artifact — smooth 60 FPS motion graphics with synthesized sound effects.

Workflow B — a video with an AI voiceover

Here you make the voiceover first, get a word-level transcript, and let the Atlas sync the animation to each spoken word.

1

Generate the voiceover in Google AI Studio ▶ 07:40

  1. Open aistudio.google.com → Playground. In the model panel, choose the Audio tab → the Gemini Flash TTS model.
  2. Create a new speech/dialogue block.
  3. In Speaker settings → Voice, preview voices (Birdi, Lura, Aida…) and pick one — the presenter uses Fola.
  4. Set Style → Narration (“commanding, rich vocal modulation, dramatic pauses”).
  5. Optional: insert expression tags like <breath>, <laugh>, <cheer>.
  6. Paste your script, click Run, then download the .mp3.
Example script
Stars begin as huge, cold clouds of gas and dust. Gravity slowly
pulls the cloud together, and as it collapses, it spins faster and
heats up. When the center reaches about ten million degrees, hydrogen
atoms start fusing into helium, releasing enormous energy. That's the
moment it ignites. A new star is born, and it can shine for billions
of years.
2

Get a word-level SRT transcript ▶ 08:53

Drag the generated MP3 into Claude (desktop / Claude Code) and ask for a word-level SRT so motion events can land on individual words.

Exact prompt
give me a word-level srt transcript for this I can copy paste

Claude transcribes it and returns an SRT code block with one entry per word. Click Copy code.

Example output (shape)
00:00:00,000 --> 00:00:00,520
Stars

00:00:00,520 --> 00:00:00,820
begin

00:00:00,820 --> 00:00:01,040
as
...
Key rule

Ask for word-level (per-word timestamps), not line-level — that's what lets the animation hit each word. Use word-level for short clips (<30s); for longer videos use line-level to avoid hitting prompt/token limits.

3

Build the synced prompt on the Atlas ▶ 09:29

  1. Open the Atlas and pick a style — the presenter uses Flat-Vector Science (#1).
  2. Toggle With voiceover.
  3. In “Your topic or script”, type a short topic.
  4. In “Voiceover timing: paste your SRT or word timestamps”, paste the copied SRT.
  5. Uncheck Storyboard first to go straight to the final render.
  6. Click Copy prompt.
Example topic
How stars are born
4

Build the video & load the audio ▶ 09:49

Open a new Claude chat, paste the prompt, send. Claude renders the animation synced to the word timestamps. Then add the voice:

  • Click Load voiceover in the player (lower right), or
  • Drag-and-drop the .mp3 onto the canvas (“Drop the voiceover audio”).

The result plays with synchronized motion, on-screen word callouts, synthesized SFX, and your AI voiceover.

Gotcha (handy)

You don't need the audio during prompt-building — you can attach/drag it into the finished player any time after the render.

Refine it, and save a style for reuse

Iterate in chat — just describe the change ▶ around 05:35 / 07:15:

Example edit requests
change the color palette to pastel
make the elements move 20% slower
adjust the line weight to be thinner

Save a custom look as a Skill ▶ 07:22: once you like a style, ask Claude to turn it into a reusable Skill so you can call it later without the Atlas.

Example prompt
turn this style into a reusable skill — create a folder with
SKILL.md and style.js so I can call this look directly next time

Tips & gotchas

  • Why full-code prompts work: sending the actual reference JavaScript (not a screenshot) lets Claude modify the existing draw/math calls, so the style stays consistent across Opus and Sonnet.
  • Other LLMs: the same prompts work in ChatGPT (GPT-4o / o1), though the presenter finds Claude's native Artifact canvas slightly higher quality.
  • Storyboard toggle: keep it on to review scene beats before the full build; turn it off to render immediately.
  • Word vs line SRT: word-level for tight sync on short clips; line-level for longer videos to stay within token limits.
  • Audio is late-bindable: load the voiceover into the player after rendering — no need to include it in the prompt.

Export to MP4 ▶ 05:08

The output is a self-contained HTML canvas/JS app in an Artifact, with player controls: Play/Pause, timeline scrubber, sound on/off, loop, and Load voiceover. To get an MP4 for editing or upload, record the canvas:

  • Use a screen recorder (OBS, or your OS capture) on the playing Artifact, or
  • Ask Claude to add a canvas recorder (the MediaRecorder API on canvas.captureStream()) so the player can save a .webm you then convert to MP4 with ffmpeg.
Example: convert a recorded clip
ffmpeg -i recording.webm -c:v libx264 -pix_fmt yuv420p out.mp4
