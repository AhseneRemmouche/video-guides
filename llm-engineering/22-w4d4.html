What an Inference Endpoint is

Up to now you have called models that someone else hosts: OpenAI, Anthropic, Google. An open-source model is different — the weights are yours to download, but something has to run them on a GPU. A HuggingFace Inference Endpoint is HuggingFace running that model on a GPU box for you, privately, and handing you a web URL to call it. You click Deploy → Inference Endpoints on the model's page, choose a cloud (AWS, Azure or Google Cloud) and a machine (this model needs a GPU — at least an Nvidia L4 with 24 GB), and click Create. A few minutes later you have your own private copy of the model answering requests.

New to "inference endpoint"? What it is and why it matters

Inference just means running a trained model to get an answer (as opposed to training it). An endpoint is a URL you send requests to. So an inference endpoint is "a web address where a running model waits to answer you". HuggingFace Inference Endpoints are the managed version: you pick a model and a GPU, they start the server, and you get a private URL plus a token. You are renting a dedicated GPU by the hour — in the video, about $0.80 per hour — so you turn it on for an experiment and pause or delete it the moment you are done. This is also a genuine way to put an open-source model into production.

New to CodeQwen and open-source code models? What they are

CodeQwen (the code variant of Alibaba's Qwen) is an open-source model fine-tuned for programming. The instructor finds it at the top of the Big Code Models Leaderboard, a HuggingFace Space that ranks open models on code tasks such as Python and C++. The chat version is the one to pick, because you can talk to it (“convert this Python to fast C++”) the same way you talk to GPT, rather than only completing code. Other open code models exist — Code Llama, DeepSeek Coder, Code Gemma — and trying them is an exercise the instructor sets. The important idea: an open-source model is one whose weights anyone can download and run, so you choose where it runs.

Hosted vs local: where does the model actually run?

An open-source model can run in three places. Locally on your own machine (via Ollama, or HuggingFace Transformers if you have a GPU) — free, but limited by your hardware. In a notebook in the cloud such as Google Colab — has a GPU, but the model is trapped in that notebook. Or on a hosted endpoint such as a HuggingFace Inference Endpoint — a dedicated GPU in the cloud that you call over the web from anywhere, including your own box. The instructor chooses the endpoint precisely because he wants to compile and run the resulting C++ on his own machine, inside the same UI as GPT and Claude, while the heavy model work happens on a rented GPU.

The lifecycle (and the part that costs money)

An endpoint is not free and it is not instant. After you create it you wait about five minutes for it to start — the instructor says “go and get a coffee” — because the GPU has to boot and load the model. That wait is the cold start. While it is running it bills by the hour whether you use it or not, so the golden rule is: pause or delete the endpoint when you finish. The instructor notes he had spent $3.64 on his CodeQwen endpoint by the time he was done.

Common mistakes.
  • Leaving the endpoint running. It charges by the hour (about $0.80 in the video) whether or not you send requests. Go to the Inference Endpoints page and pause or delete it the instant you stop. This is the easiest way to run up a surprise bill in the whole course.
  • Calling it too soon. Right after you click Create the endpoint is still starting (cold start, ~5 minutes). Calls will fail until its status is Running.
  • Picking a CPU box. A 7B model needs a GPU; the page recommends at least an Nvidia L4 with 24 GB. A CPU box will be unusable or crash on anything but trivial inputs.
  • Expecting a clean answer. CodeQwen ignored the “no explanation” instruction and wrapped its C++ in chatter. You post-process it — strip everything before and after the C++ fences.
  • Using the video's endpoint address. CODE_QWEN_URL must be the URL of your endpoint, copied from its page. Ed's addresses stopped working long ago.

import "dotenv/config";
import { InferenceClient } from "@huggingface/inference";

const systemMessage =
  "You are an assistant that reimplements Python code in high performance C++ for an M1 Mac. " +
  "Respond only with C++ code; use comments sparingly and do not provide any explanation other than occasional comments. " +
  "The C++ response needs to produce an identical output in the fastest possible time. " +
  "Keep implementations of random number generators identical so that results match exactly.";

function userPromptFor(python: string): string {
  return (
    "Rewrite this Python code in C++ with the fastest possible implementation that produces identical output in the least time. " +
    "Respond only with C++ code; do not explain your work other than a few comments. " +
    "Pay attention to number types to ensure no int overflows. Remember to #include all necessary C++ packages such as iomanip.\n\n" +
    python
  );
}

function messagesFor(python: string): { role: string; content: string }[] {
  return [
    { role: "system", content: systemMessage },
    { role: "user", content: userPromptFor(python) },
  ];
}

// tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True) gives this text for
// CodeQwen (the ChatML format print(text) shows in the video), so TypeScript can build it by hand
function applyChatTemplate(messages: { role: string; content?: unknown }[]): string {
  return messages.map((m) => `<|im_start|>${m.role}\n${m.content}<|im_end|>\n`).join("") + "<|im_start|>assistant\n";
}

import time

def calculate(iterations, param1, param2):

const systemMessage =
  "You are an assistant that reimplements Python code in high performance C++ for an M1 Mac. " +
  "Respond only with C++ code; use comments sparingly and do not provide any explanation other than occasional comments. " +
  "The C++ response needs to produce an identical output in the fastest possible time. " +

function userPromptFor(python: string): string {
  return (
    "Rewrite this Python code in C++ with the fastest possible implementation that produces identical output in the least time. " +
    "Respond only with C++ code; do not explain your work other than a few comments. " +
    "Pay attention to number types to ensure no int overflows. Remember to #include all necessary C++ packages such as iomanip.\n\n" +
    python
  );
}

function messagesFor(python: string): OpenAI.Chat.ChatCompletionMessageParam[] {
  return [
    { role: "system", content: systemMessage },
    { role: "user", content: userPromptFor(python) },
  ];
}

// write to a file called optimized.cpp
function writeOutput(cpp: string): void {
  const code = cpp.replaceAll("```cpp", "").replaceAll("```", "");
  writeFileSync("optimized.cpp", code);
}

// Gradio wants the whole reply so far on every step, so each yield is cumulative
async function* streamGpt(python: string): AsyncGenerator<string> {
  const stream = await openai.chat.completions.create({
    model: OPENAI_MODEL,
    reasoning_effort: "low",
    messages: messagesFor(python),
    stream: true,
  });
  let reply = "";
  for await (const chunk of stream) {
    reply += chunk.choices[0]?.delta?.content ?? "";
    yield reply.replaceAll("```cpp\n", "").replaceAll("```", "");
  }
}

async function* streamClaude(python: string): AsyncGenerator<string> {
  const stream = claude.messages.stream({
    model: CLAUDE_MODEL,
    max_tokens: 2000,
    system: systemMessage,
    messages: [{ role: "user", content: userPromptFor(python) }],
  });
  let reply = "";
  for await (const event of stream) {
    if (event.type === "content_block_delta" && event.delta.type === "text_delta") {
      reply += event.delta.text;
      yield reply.replaceAll("```cpp\n", "").replaceAll("```", "");
    }
  }
}

// tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True) gives this text for
// CodeQwen (the ChatML format print(text) shows in the video), so TypeScript can build it by hand
function applyChatTemplate(messages: { role: string; content?: unknown }[]): string {
  return messages.map((m) => `<|im_start|>${m.role}\n${m.content}<|im_end|>\n`).join("") + "<|im_start|>assistant\n";
}

// stream_code_qwen: template the messages, stream tokens from the endpoint, yield the text so far
async function* streamCodeQwen(python: string): AsyncGenerator<string> {
  const text = applyChatTemplate(messagesFor(python));
  const stream = hf.textGenerationStream({ endpointUrl: CODE_QWEN_URL, inputs: text, parameters: { max_new_tokens: 3000 } });
  let result = "";
  for await (const r of stream) {
    result += r.token.text;
    yield result;
  }
}

async function* optimize(python: string, model: string): AsyncGenerator<string> {
  let result: AsyncGenerator<string>;
  if (model === "GPT") result = streamGpt(python);
  else if (model === "Claude") result = streamClaude(python);
  else if (model === "CodeQwen") result = streamCodeQwen(python);
  else throw new Error("Unknown model");
  for await (const streamSoFar of result) yield streamSoFar;
}

// execute_python: run the code and hand back what it printed
function executePython(code: string): string {
  return execFileSync("python", ["-c", code], { encoding: "utf8" });
}

// execute_cpp: save, compile with speed flags, run, return the output (or the compiler's complaint)
function executeCpp(code: string): string {
  writeOutput(code);
  try {
    execFileSync("clang++", ["-Ofast", "-std=c++17", "-march=native", "-o", "optimized", "optimized.cpp"], { encoding: "utf8", stdio: "pipe" });
    return execFileSync("./optimized", { encoding: "utf8" }); // on Windows: "optimized.exe"
  } catch (e) {
    return `An error occurred:\n${(e as { stderr?: string }).stderr ?? String(e)}`;
  }
}

A short recap with no code. You can code against frontier and open-source models, choose a model using leaderboards and arenas, and deploy an open model on an endpoint. Video vs repo.
  • The whole mechanism differs. The video deploys CodeQwen on a Hugging Face Inference Endpoint and calls it with InferenceClient plus AutoTokenizer.apply_chat_template. The current repository drops all of that and reaches open-source models through OpenAI-compatible addresses (Ollama on your own machine, Groq and OpenRouter in the cloud), with the same client.chat.completions.create(...) call as the frontier models.
  • Models. The video compares GPT-4o, Claude 3.5 Sonnet and CodeQwen 1.5 7B Chat; the repository's dropdown lists current frontier models plus qwen2.5-coder, deepseek-coder-v2, gpt-oss and qwen3-coder.
  • Simpler UI. The repository's Day 4 screen has no Run buttons: one port(model, python) function returns the whole C++ at once (no streaming), and a separate cell compiles and runs it.

The "Runs today" tabs keep the video's method and change only what no longer works: model ids, endpoint addresses, the M1-only compiler flags, the misnamed function and where Gradio 6 expects the CSS.

What you should see. With a running endpoint (video method) or a reachable open-source client (repo method), choosing an open-source model in the dropdown and pressing Convert streams C++ into the right-hand box, usually wrapped in a little explanation you then delete. On the easy pi program the compiled C++ runs in a fraction of a second and prints the same value as the Python. On the hard subarray program, expect the open-source model to produce plausible-looking C++ whose answer does not match — in the video CodeQwen changed the random-number logic, so the numbers diverged.
Recap
  • Day 4 runs an open-source code model on the same Python → C++ task as the frontier models, to compare them.
  • A HuggingFace Inference Endpoint is a dedicated GPU in HuggingFace's cloud that you spin up, giving you a private URL to call any open model — the instructor picks CodeQwen 7B from the Big Code Models Leaderboard.
  • The video calls it with InferenceClient(url, token).text_generation(text, stream=True, ...), after apply_chat_template turns the messages into one prompt string.
  • An endpoint costs money by the hour (~$0.80), takes about five minutes to cold-start, and must be paused or deleted when you finish.
  • Results: CodeQwen passed the easy pi test but stumbled on the hard one; the frontier models passed both. A 7B model versus trillion-parameter ones is not a fair fight — yet open-source did well.
  • Video vs repo: today's repository reaches open-source models through OpenAI-compatible addresses (Ollama, Groq, OpenRouter) rather than InferenceClient; same goal, simpler plumbing.
  • In TypeScript, @huggingface/inference's textGenerationStream calls the same endpoint; the chat template is a few lines of string building.
  • The model-calling code was not run live here; the speed and quality results are the instructor's.
