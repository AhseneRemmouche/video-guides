What an Inference Endpoint is

Up to now you have called models that someone else hosts: OpenAI, Anthropic, Google. An open-source model is different — the weights are yours to download, but something has to run them on a GPU. A HuggingFace Inference Endpoint is HuggingFace running that model on a GPU box for you, privately, and handing you a web URL to call it. You click Deploy → Inference Endpoints on the model's page, choose a cloud (AWS, Azure or Google Cloud) and a machine (this model needs a GPU — at least an Nvidia L4 with 24 GB), and click Create. A few minutes later you have your own private copy of the model answering requests.

New to "inference endpoint"? What it is and why it matters

Inference just means running a trained model to get an answer (as opposed to training it). An endpoint is a URL you send requests to. So an inference endpoint is "a web address where a running model waits to answer you". HuggingFace Inference Endpoints are the managed version: you pick a model and a GPU, they start the server, and you get a private URL plus a token. You are renting a dedicated GPU by the hour — in the video, about $0.80 per hour — so you turn it on for an experiment and pause or delete it the moment you are done. This is also a genuine way to put an open-source model into production.

New to CodeQwen and open-source code models? What they are

CodeQwen (the code variant of Alibaba's Qwen) is an open-source model fine-tuned for programming. The instructor finds it at the top of the Big Code Models Leaderboard, a HuggingFace Space that ranks open models on code tasks such as Python and C++. The chat version is the one to pick, because you can talk to it (“convert this Python to fast C++”) the same way you talk to GPT, rather than only completing code. Other open code models exist — Code Llama, DeepSeek Coder, Code Gemma — and trying them is an exercise the instructor sets. The important idea: an open-source model is one whose weights anyone can download and run, so you choose where it runs.

Hosted vs local: where does the model actually run?

An open-source model can run in three places. Locally on your own machine (via Ollama, or HuggingFace Transformers if you have a GPU) — free, but limited by your hardware. In a notebook in the cloud such as Google Colab — has a GPU, but the model is trapped in that notebook. Or on a hosted endpoint such as a HuggingFace Inference Endpoint — a dedicated GPU in the cloud that you call over the web from anywhere, including your own box. The instructor chooses the endpoint precisely because he wants to compile and run the resulting C++ on his own machine, inside the same UI as GPT and Claude, while the heavy model work happens on a rented GPU.

The lifecycle (and the part that costs money)

An endpoint is not free and it is not instant. After you create it you wait about five minutes for it to start — the instructor says “go and get a coffee” — because the GPU has to boot and load the model. That wait is the cold start. While it is running it bills by the hour whether you use it or not, so the golden rule is: pause or delete the endpoint when you finish. The instructor notes he had spent $3.64 on his CodeQwen endpoint by the time he was done.

Common mistakes.
  • Leaving the endpoint running. It charges by the hour (about $0.80 in the video) whether or not you send requests. Go to the Inference Endpoints page and pause or delete it the instant you stop. This is the easiest way to run up a surprise bill in the whole course.
  • Calling it too soon. Right after you click Create the endpoint is still starting (cold start, ~5 minutes). Calls will fail until its status is Running.
  • Picking a CPU box. A 7B model needs a GPU; the page recommends at least an Nvidia L4 with 24 GB. A CPU box will be unusable or crash on anything but trivial inputs.
  • Expecting a clean answer. CodeQwen ignored the “no explanation” instruction and wrapped its C++ in chatter. You post-process it — strip everything before and after the C++ fences.

Calling the endpoint: the video's method

In the video the call is only a few lines. You log in to HuggingFace, load the model's tokenizer with AutoTokenizer.from_pretrained(...), turn your usual messages list into one text string with tokenizer.apply_chat_template(...), then create an InferenceClient pointed at your endpoint URL and token and call text_generation(...). Streaming is optional but lets you watch the C++ appear token by token, exactly like the GPT and Claude streams from Day 3.

from huggingface_hub import login, InferenceClient
from transformers import AutoTokenizer

login(hf_token)
CODE_QWEN = "Qwen/CodeQwen1.5-7B-Chat"
CODE_QWEN_URL = "https://your-endpoint.endpoints.huggingface.cloud"

# turn the messages list into the exact prompt text CodeQwen was trained on
tokenizer = AutoTokenizer.from_pretrained(CODE_QWEN)
text = tokenizer.apply_chat_template(
    messages_for(python), tokenize=False, add_generation_prompt=True)

# the whole remote call: point the client at your endpoint, stream back tokens
client = InferenceClient(CODE_QWEN_URL, token=hf_token)
stream = client.text_generation(text, stream=True, max_new_tokens=3000)
for chunk in stream:
    print(chunk, end="")

def port(model, python):
    client = clients[model]
    openai_reasoning_models = {"gpt-4o-mini-sol"} if model in openai_reasoning_models else None
    response = client.chat.completions.create(model=model, messages=messages_for(python))

In TypeScript

There is no official TypeScript port of this particular day, and that is fine, because the endpoint idea travels almost unchanged. An Inference Endpoint is just a URL that accepts a POST request, so from Node you can call it with plain fetch: send the prompt text in the request body, include your HuggingFace token in an Authorization header, and read the generated text out of the JSON response. That is the same round trip the Python InferenceClient makes under the hood — the client is a convenience wrapper over exactly this HTTP call.

// Illustrative only - not from the course repo, and not run here.
const res = await fetch(ENDPOINT_URL, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${HF_TOKEN}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    inputs: text,                      // the chat-templated prompt
    parameters: { max_new_tokens: 3000 },
  }),
});
const data = await res.json();
console.log(data[0].generated_text);   // the generated C++

The one Python-only piece is apply_chat_template, which formats the prompt the exact way CodeQwen expects. In TypeScript you would either hard-code that template string or let a hosted chat API apply it for you; everything else is an ordinary HTTP request.
