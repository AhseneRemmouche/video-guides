Week 3 · Day 5 — Meeting Minutes from Audio

Combine a frontier model and an open-source model: transcribe a recording with Whisper, then write tidy markdown meeting minutes with Llama - plus a synthetic test-data generator.

Companion to Ed Donner's course · uv setup · Python + TypeScript/React · code verified against the repo

This is the final day of Week 3, and it is a proper project. You will build a small business tool that takes an audio recording of a meeting and produces tidy written minutes — a summary, who was there, the key discussion points, the takeaways, and a list of action items with the person responsible for each. The instructor frames it as a feature you find in many real products, and it is a lovely way to finish the week because it stitches together everything you have learned.

The clever part is that it uses two different kinds of model, one after the other. First a frontier model — OpenAI's Whisper — listens to the audio and writes down what was said (this is called speech-to-text, or transcription). Then an open-source model — Llama 3.1 8B, running on your own GPU — reads that transcript and writes the minutes. One model turns sound into text; the other turns text into a neat document. Neither could do the whole job as well alone, so you combine them.

The concepts the instructor introduces

Three ideas carry the day.

Speech-to-text (transcription). Whisper is OpenAI's audio model: you hand it a sound file and it hands back the words. It is the mirror image of text-to-speech, which you met in Week 2 (there you turned text into speech; here you turn speech into text). You call it with openai.audio.transcriptions.create and the model name whisper-1.

Combining a frontier model with an open-source model. This is the headline pattern of the whole week. The frontier model (Whisper) is reached over the internet through an API — someone else runs it, you pay per use, and you need no special hardware. The open-source model (Llama 3.1) is one whose weights you download and run on your own GPU. Using both in one program lets each do what it is best at: Whisper has excellent audio understanding, and an open-source Llama is cheap to run, private, and fully under your control for the text work.

A system prompt for structured output. To make Llama produce a tidy document rather than a loose paragraph, you set a system prompt that spells out exactly which sections you want: summary, key discussion points, takeaways, and action items with owners, all in markdown. The system prompt is where you define the shape of the answer; the user prompt then supplies the actual transcript.

New to Whisper and speech-to-text? What it is and why it matters

Speech-to-text (also called transcription or automatic speech recognition) is the task of turning spoken audio into written words. Whisper is OpenAI's model for this, named whisper-1 in the API. You open an audio file and pass it to openai.audio.transcriptions.create(...); with response_format="text" you get back a plain string of the transcript.

It handles common formats such as MP3 and WAV. In this project the input is a short extract of a real Denver City Council meeting (from a public dataset called MeetingBank), trimmed to roughly ten minutes so the demo runs quickly. Whisper does the hard job of understanding messy, overlapping speech; your code then only has to deal with text.

New to combining frontier and open-source models? Why use two

A frontier model is one of the big, paid models you reach over the internet through an API, like OpenAI's. You never download it; you just send a request and get an answer. An open-source model is one whose weights are published, so you can download it and run it yourself — here, Llama 3.1 8B through the HuggingFace Transformers library on a GPU.

Why mix them? Because they have different strengths. Whisper's audio quality is hard to match, and you only pay for the few seconds of transcription. Once you have text, an open-source model can do the writing for free on hardware you control, which is cheaper at scale and keeps the meeting content private. Picking the right tool for each step — rather than forcing one model to do everything — is a core skill the course is building toward.

New to using a system prompt for structured output? What it is and why it matters

The system prompt is the first message you send a chat model. It sets the model's job and the rules before the real request arrives. When you need the answer in a particular shape, the system prompt is where you describe that shape.

Here the system message says: "You are an assistant that produces minutes of meetings from transcripts, with summary, key discussion points, takeaways and action items with owners, in markdown." Because you named the exact sections and the format (markdown), the model reliably returns a document you could paste straight into a wiki. This is a softer cousin of the JSON mode you saw in Week 1: instead of forcing valid JSON, you guide the model to a consistent layout with clear instructions.

The full program

# Reconstructed to match the course's Google Colab notebook for this day.
# Standard HuggingFace code; runs on a GPU (e.g. Colab T4). Not executed here (no GPU).
#
# Week 3 - Day 5: Meeting Minutes - combine a frontier model with an open-source model.
#   1) Transcribe an audio recording with OpenAI Whisper (audio -> text).
#   2) Feed that transcript to an open-source LLM (Llama 3.1 8B, 4-bit quantized) with
#      a system prompt, and stream back meeting minutes in markdown (summary, key
#      discussion points, takeaways, action items with owners).
# The sample input is a short extract of a Denver City Council meeting (MeetingBank).
#
# Colab setup (run once in a cell):
#   !pip install -q openai transformers accelerate bitsandbytes
#   from huggingface_hub import login
#   from google.colab import userdata
#   login(userdata.get("HF_TOKEN"), add_to_git_credential=True)
# In Colab you typically mount Google Drive for the audio file:
#   from google.colab import drive
#   drive.mount("/content/drive")

import os

import torch
from openai import OpenAI
from transformers import (
    AutoModelForCausalLM,
    AutoTokenizer,
    BitsAndBytesConfig,
    TextStreamer,
)

AUDIO_MODEL = "whisper-1"
LLAMA = "meta-llama/Meta-Llama-3.1-8B-Instruct"

# Path to the audio file. In Colab this comes off the mounted Drive, e.g.
# "/content/drive/MyDrive/llms/denver_extract.mp3".
AUDIO_FILENAME = "denver_extract.mp3"


def transcribe(audio_filename):
    # Frontier step: OpenAI Whisper turns the audio into text.
    # In Colab the key is passed explicitly (from a Colab secret) rather than relied
    # upon in the environment; OpenAI() also reads OPENAI_API_KEY if it is set.
    openai = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
    with open(audio_filename, "rb") as audio_file:
        transcription = openai.audio.transcriptions.create(
            model=AUDIO_MODEL,
            file=audio_file,
            response_format="text",
        )
    return transcription


def build_messages(transcription):
    system_message = (
        "You are an assistant that produces minutes of meetings from transcripts, "
        "with summary, key discussion points, takeaways and action items with owners, "
        "in markdown."
    )
    user_prompt = (
        "Below is an extract transcript of a Denver council meeting. Please write "
        "minutes in markdown, including a summary with attendees, location and date; "
        "discussion points; takeaways; and action items with owners.\n"
        f"{transcription}"
    )
    return [
        {"role": "system", "content": system_message},
        {"role": "user", "content": user_prompt},
    ]


def summarize(messages):
    # Open-source step: Llama 3.1 8B, 4-bit quantized, writes the minutes.
    quant_config = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_use_double_quant=True,
        bnb_4bit_compute_dtype=torch.bfloat16,
        bnb_4bit_quant_type="nf4",
    )

    tokenizer = AutoTokenizer.from_pretrained(LLAMA)
    tokenizer.pad_token = tokenizer.eos_token
    inputs = tokenizer.apply_chat_template(
        messages, return_tensors="pt", add_generation_prompt=True
    ).to("cuda")

    streamer = TextStreamer(tokenizer)
    model = AutoModelForCausalLM.from_pretrained(
        LLAMA, device_map="auto", quantization_config=quant_config
    )

    # A hefty response, so allow many more new tokens than the earlier joke demos.
    outputs = model.generate(inputs, max_new_tokens=2000, streamer=streamer)

    # Decode the full output to a string (in Colab this is shown with display(Markdown(...))).
    response = tokenizer.decode(outputs[0])
    return response


def main():
    transcription = transcribe(AUDIO_FILENAME)
    print("=== Transcript ===")
    print(transcription)

    messages = build_messages(transcription)

    print("\n=== Meeting minutes ===")
    response = summarize(messages)
    print(response)


if __name__ == "__main__":
    main()

What you should see

First the transcript prints — a long block of plain text of what was said at the meeting. For the Denver extract it is mostly a debate about recognising Indigenous Peoples' Day:

=== Transcript ===
Thank you, Councilman. We have a proclamation this evening,
proclamation 1127, recognizing Indigenous Peoples' Day ...

Then, after Llama loads, the minutes stream out as markdown, with the sections you asked for:

=== Meeting minutes ===
# Minutes - Denver City Council
## Summary
Attendees: Council members ...  Location: Denver  Date: October 9
## Key discussion points
- Proclamation 1127 recognizing Indigenous Peoples' Day ...
## Takeaways
- The proclamation was adopted ...
## Action items
- Councilman Lopez: transmit a copy to the Denver American Indian Commission
- Clerk: attest and affix the city seal

The exact wording differs every run; what matters is that the four sections are there and each action has an owner.

Common mistakes
  • Audio format or length. Give Whisper a format it accepts (MP3 and WAV are safe) and a reasonable length. The course uses a short extract of about ten minutes on purpose — a very long recording is slower, costs more, and can hit the API's file-size limit. Trim long audio into chunks.
  • Wrong file path. In Colab the audio lives on the mounted Drive. If you forget drive.mount("/content/drive") or mistype the path, open(...) fails with a file-not-found error before Whisper is ever called.
  • GPU memory. An 8B model will not fit on a small GPU at full size — that is the whole reason for 4-bit quantization. If you drop the quantization_config, or forget to select a GPU runtime in Colab, you can hit an out-of-memory error. The quantized model keeps the quality high while fitting in the T4's memory.
  • No key or not logged in. The Whisper call needs a valid OpenAI key, and loading Llama needs you to be logged in to HuggingFace (Llama is a gated model). Missing either stops the matching half of the pipeline.

In TypeScript

Days 2 and 3 of this week ship a full TypeScript port, but this project stays Python-primary, and it is worth being honest about why. The frontier half travels well: you can transcribe audio in transformers.js with a small Whisper model (whisper-tiny or whisper-base) running in Node or the browser, or simply call the OpenAI API from the openai JavaScript SDK exactly as you would in Python. Either gives you the transcript.

The summarising half is where TypeScript cannot match the Python version. Loading an 8-billion-parameter Llama with 4-bit bitsandbytes quantization is GPU-and-Python only — there is no TypeScript equivalent of that step. On the TypeScript side you have two realistic choices: run a small open-source model through transformers.js (far smaller than 8B, so the minutes will be weaker), or send the transcript to a hosted service such as HuggingFace's Inference API or any chat API and let a big model do the writing there. So the honest summary is: transcription ports cleanly, but the full on-device Llama step stays in Python on a GPU.

Take it further: a synthetic test-data generator

The instructor sets two challenges. The easy one is to wrap this tool in a Gradio web page, so you type a filename and press a button to get the minutes. The harder, end-of-week challenge is a different product built on the same open-source half: a synthetic test-data generator. You describe the kind of dataset you want — product descriptions, job postings, sample customer records — and the model invents a diverse set of realistic examples you can use to test your own business software.

The point worth noticing is that only the prompt changes. The machinery is identical: load a quantized open-source model, feed it a system prompt that defines the output, and stream back the result. Swap "write meeting minutes from this transcript" for "invent diverse test data of this kind", and the very same code becomes a completely different, genuinely useful tool.
