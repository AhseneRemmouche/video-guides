What is a notebook, and how do cells run?

Almost all the course code lives in Jupyter notebooks. A notebook (also called a "lab") is a document made of cells. A cell holds either text or a piece of Python code. You click a code cell and press Shift+Enter to run just that cell; its output appears right underneath it. This lets you experiment one small step at a time instead of running a whole file at once.

The important rule: run the cells from the top down, in order. Later cells depend on names (variables and functions) defined in earlier ones. If you skip the imports cell at the top and run a cell lower down, Python has never heard of those names and you get a NameError. The instructor says the most common fix for a NameError is simply "did you run every cell from the top?".

New to notebooks? What they are and why data scientists love them

A plain Python script runs start to finish and then stops. A notebook keeps a live Python session running in the background (called the kernel). Each time you run a cell, that same session remembers everything from the cells you ran before — your variables stay alive. That is why you can load a web page in one cell, inspect it in the next, and call a model in a third, tweaking each step without starting over. The trade-off is that cell order matters: if you run cells out of order the session can hold stale values. When in doubt, use the menu's Restart Kernel and Run All Cells to get a clean, top-to-bottom run.

Step 1: Build the environment with uv

An environment is an isolated copy of Python plus a fixed set of packages, kept separate from the rest of your computer so versions never clash. Ed's repository ships everything needed to build one with uv, a fast project manager from Astral. Instead of installing packages by hand, uv reads two files already in the repo — pyproject.toml (what the project needs) and uv.lock (the exact pinned versions) — and recreates the identical setup for you with a single command.

  1. Install uv Open a terminal (a plain PowerShell on Windows, Terminal on Mac) and install uv. On Windows: 
    powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
    On Mac or Linux: 
    curl -LsSf https://astral.sh/uv/install.sh | sh
    irm (Invoke-RestMethod) downloads the install script and iex (Invoke-Expression) runs it; on Mac, curl downloads the script (-LsSf follows redirects quietly and fails on error) and sh runs it. Close and reopen the terminal afterwards so the new uv command is found.
  2. Clone the repo Download Ed's code and step into it: 
    git clone https://github.com/ed-donner/llm_engineering
cd llm_engineering
    git clone makes a local copy of the repository; cd ("change directory") moves you inside the new llm_engineering folder, which the instructor calls the project root. On Windows you may first need to install git (accept every default); on Mac git is already there.
  3. Build the environment From the project root, run one command: 
    uv sync
    uv sync reads pyproject.toml and uv.lock, downloads Python 3.12 if your machine does not have it, creates a private .venv folder, and installs every package at the exact pinned version. Because the versions are locked, every student ends up with an identical, reproducible setup.
  4. Open the notebook Launch JupyterLab inside that environment: 
    uv run jupyter lab
    uv run runs a command inside the project's .venv without you having to "activate" anything. This opens JupyterLab in your browser; open week1/day1.ipynb. If you prefer Cursor or VS Code, open the notebook there instead and go to the next step.
  5. Select the Kernel If you opened the notebook in Cursor/VS Code, click Select Kernel at the top right, choose Python Environments…, and pick the one that looks like .venv (Python 3.12.x). It is usually marked "Recommended" with a star. You must do this for every notebook.
New to uv? What it is and why this course uses it

uv is a fast package and project manager for Python. Older projects used several separate tools to make an environment and install packages; uv does it all in one, and much faster. The key commands: uv sync builds the .venv and installs exactly what the lock file pins (so your setup matches everyone else's); uv run <command> runs something inside that environment without a separate "activate" step; uv add <package> adds a new dependency and updates the lock file. You never edit the .venv folder by hand — uv manages it for you.

Step 2: Store your OpenAI API key in a .env file

To call OpenAI's models from code you need an API key — a long secret string that identifies and bills your account. You create one on the OpenAI platform under Dashboard → API keys → Create new secret key, then copy it immediately (you only get to see it once). OpenAI keys start with sk-proj-.

About cost. The API is pay-per-request, separate from any ChatGPT subscription. OpenAI asks for a small minimum top-up (the instructor mentions $5). The course spends only a fraction of a cent per call because it uses the cheap gpt-4o-mini model. Keep auto-recharge off. If you would rather not pay at all, you can use the free local Ollama option shown below for most exercises.

Keys must never be written into your code or committed to git. The course stores them in an environment variable loaded from a file named exactly .env, which git is told to ignore.

  1. Create the file In the project root, create a file named exactly .env. On Mac you can run nano .env; on Windows use Notepad and, in Save as, set Save as type to All Files so it is not saved as .env.txt.
  2. Add the key Put one line in it, with no spaces around the =: 
    OPENAI_API_KEY=sk-proj-your-real-key-here
  3. Watch the gotchas The filename must be exactly .env — not keys.env, not .env.txt. On Mac it is hidden; list it with ls -a. Make sure no stray spaces or "smart" long dashes crept into the key when you pasted it.
What is an API key, and why hide it in .env?

An API key is like a password for a service you call from code. Anyone who has your key can spend money on your account, so it is a secret. Hard-coding it into a notebook is dangerous: the moment you push that notebook to GitHub, the key is public. The .env file keeps the secret in one place outside your code. Your program reads it at run time, and because .env is listed in .gitignore, it never gets committed. This "keys in the environment, not in the code" habit is standard practice everywhere, not just this course.

In Python, the library python-dotenv (imported as dotenv) reads that file for you with load_dotenv(). In the TypeScript port, the dotenv package does the same job — import "dotenv/config" loads .env into process.env as soon as the program starts.

Step 3: One tiny call to a frontier model

With the key in place, the notebook makes its first call to the OpenAI API. It uses the official client library, builds a short list of messages, and calls the chat completions endpoint. The model's reply comes back from the first choice's message content. That single pattern — build messages, call the endpoint, read the reply — is used again and again throughout the course. The act of the model producing a reply is called inference.

Honest note on what was tested. The code on this page that calls OpenAI (and Ollama) was not run live here, because that needs a paid key or a running Ollama server. It is shown exactly as the course presents it. The scraping part was run offline (in both languages) and behaves as described below; the TypeScript project was also type-checked and built with Vite.

Step 4: Run a model locally with Ollama (free)

Before paying for anything, the very first thing the instructor does is run an LLM on your own machine using Ollama. Ollama downloads and runs open-source models (such as Meta's Llama) directly on your computer, for free. In the video he builds a working "Spanish tutor" in minutes this way.

  1. Install Download Ollama from ollama.com and install it (Setup.exe on Windows, the installer on Mac).
  2. Run a model In a terminal, pull and chat with a small model: 
    ollama run llama3.2
    The first run downloads the model's roughly 2 billion parameters, so it may take a few minutes. A blinking cursor means the model is running locally and ready to chat. On a small machine use ollama run llama3.2:1b.
  3. Check the server Ollama also runs a background server at http://localhost:11434; visiting that address in a browser shows "Ollama is running". If it is not running, start it with ollama serve.

The reason this matters for the project: Ollama exposes an OpenAI-compatible endpoint at http://localhost:11434/v1. That means the same summarizer code can talk to a free local model simply by pointing the client at that address instead of OpenAI's cloud (the course does this on Day 2).

Frontier model vs open-source model — what's the difference?

A frontier model is one of the biggest, most capable models of the moment (GPT, Claude, Gemini). They are closed-source and run only on the provider's servers, so you reach them over an API and pay per request. An open-source model (like Llama) has published weights you can download and run yourself, for free, with a tool like Ollama. The instructor notes a local Llama model might be around 2 billion parameters while a top frontier model is rumoured to be thousands of times larger — so the cloud reply is usually richer, but the local one costs nothing and keeps your data on your machine.

Step 5: The project — a website summarizer

Now the main event. We will build a program that takes a URL, scrapes the page's text, asks a model to summarize it, and displays the result as formatted markdown. This is a classic use of summarization, one of the most common and useful things LLMs do. Below is the complete file in both languages, exactly as verified. Use the switch to flip between the Python version (which uses the Website class) and the TypeScript port (which imports a shared scraper).

# Day 1 - Website Summarizer (the version shown in the video)
# A tiny "Reader's Digest of the internet": give it a URL, get back a short summary.

import os
import requests
from bs4 import BeautifulSoup
from dotenv import load_dotenv
from openai import OpenAI
from IPython.display import Markdown, display

# Load the OPENAI_API_KEY from your .env file into the environment
load_dotenv(override=True)
api_key = os.getenv("OPENAI_API_KEY")

if not api_key:
    print("No API key was found - check your .env file")
elif not api_key.startswith("sk-proj-"):
    print("An API key was found, but it doesn't start sk-proj- - please check it")
else:
    print("API key found and looks good so far!")

# Create the OpenAI client. With no arguments it reads OPENAI_API_KEY from the environment.
openai = OpenAI()

MODEL = "gpt-4o-mini"

# Some websites refuse a request that has no User-Agent header, so we send a normal browser one
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 "
                  "(KHTML, like Gecko) Chrome/117.0.0.0 Safari/537.36"
}


class Website:
    """A utility class to represent a website that we have scraped."""

    def __init__(self, url):
        self.url = url
        response = requests.get(url, headers=headers)
        soup = BeautifulSoup(response.content, "html.parser")
        self.title = soup.title.string if soup.title else "No title found"
        for irrelevant in soup.body(["script", "style", "img", "input"]):
            irrelevant.decompose()
        self.text = soup.body.get_text(separator="\n", strip=True)


# A system prompt tells the model what role to play and how to behave
system_prompt = """You are an assistant that analyzes the contents of a website \
and provides a short summary, ignoring text that might be navigation related. \
Respond in markdown."""


# A user prompt is the actual request. We build it from the scraped page.
def user_prompt_for(website):
    user_prompt = f"You are looking at a website titled {website.title}\n"
    user_prompt += "The contents of this website is as follows; \
please provide a short summary of this website in markdown. \
If it includes news or announcements, then summarize these too.\n\n"
    user_prompt += website.text
    return user_prompt


# The OpenAI API expects a list of messages, each with a role and content
def messages_for(website):
    return [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_prompt_for(website)},
    ]


def summarize(url):
    website = Website(url)
    response = openai.chat.completions.create(
        model=MODEL,
        messages=messages_for(website),
    )
    return response.choices[0].message.content


def display_summary(url):
    summary = summarize(url)
    display(Markdown(summary))


display_summary("https://edwarddonner.com")

What is web scraping?

Web scraping means fetching a web page with code and pulling useful data out of its HTML. In Python, two libraries do the work: requests downloads the page (like a browser asking the server for it), and BeautifulSoup parses the returned HTML into a tree you can search. In the TypeScript port, the built-in fetch downloads the page and node-html-parser parses the returned HTML into a tree you can search — it plays the role BeautifulSoup plays in Python. We ask it for the <title>, delete the parts that are not readable content, and read the remaining text. A limitation shown in the course: this simple approach only sees the HTML the server sends. Pages that build themselves with JavaScript in the browser (like React apps) come back nearly empty, and some sites return a 403 error. Those need a browser-automation tool such as Selenium or Playwright instead.

The shared scraper (TypeScript)

The TypeScript summarizer above does not scrape the page itself; it imports a small shared module, scrape.ts. Splitting it out keeps the scraping logic in one place (Day 5's brochure project reuses it) and makes it testable offline — this is the part that was actually run and verified. It mirrors the Python Website class: strip the noise tags, keep the body text, and also collect the page's links.

// Shared website scraping, the TypeScript counterpart of the Python `Website` class.
// `parseWebsite` works on an HTML string (offline, testable); `fetchWebsite` adds the network fetch.
import { parse } from "node-html-parser";

// Some websites refuse a request that has no User-Agent header, so we send a normal browser one
export const headers = {
  "User-Agent":
    "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 " +
    "(KHTML, like Gecko) Chrome/117.0.0.0 Safari/537.36",
};

/** A scraped website: its title, its visible text, and the links it contains. */
export interface Website {
  url: string;
  title: string;
  text: string;
  links: string[];
}

// The tags whose content is noise for a summary (scripts, styles, images, form inputs).
const IRRELEVANT = ["script", "style", "img", "input"];

/** Parse an HTML string into a Website. Mirrors BeautifulSoup: strip noise tags, keep body text + links. */
export function parseWebsite(html: string, url: string): Website {
  const root = parse(html);

  const titleEl = root.querySelector("title");
  const title = titleEl ? titleEl.text.trim() : "No title found";

  const body = root.querySelector("body") ?? root;
  for (const tag of IRRELEVANT) {
    for (const el of body.querySelectorAll(tag)) el.remove();
  }
  const text = body.structuredText.trim();

  const links = root
    .querySelectorAll("a")
    .map((a) => a.getAttribute("href"))
    .filter((href): href is string => Boolean(href));

  return { url, title, text, links };
}

/** Fetch a URL and parse it. Uses the global fetch (Node 18+). */
export async function fetchWebsite(url: string): Promise<Website> {
  const response = await fetch(url, { headers });
  const html = await response.text();
  return parseWebsite(html, url);
}

/** Webpage Title + Contents, the string fed to the brochure model (Website.get_contents in Python). */
export function getContents(site: Website): string {
  return `Webpage Title:\n${site.title}\nWebpage Contents:\n${site.text}\n\n`;
}

System prompt vs user prompt — what's the difference?

A chat model takes its instructions as a list of messages, each with a role. The system prompt sets the overall context: who the model is, what task it does, what tone to use. It is like a job description. The user prompt is the actual request for this turn — the conversation starter the model must reply to. In this project the system prompt is fixed ("you summarize websites, ignore navigation, respond in markdown") while the user prompt changes for every page because it contains that page's text. A plain prompt is just any text you send a model.

from bs4 import BeautifulSoup
import requests


# Standard headers to fetch a website
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/117.0.0.0 Safari/537.36"
}


def fetch_website_contents(url):
    """
    Return the title and contents of the website at the given url;
    truncate to 2,000 characters as a sensible limit
    """
    response = requests.get(url, headers=headers)
    soup = BeautifulSoup(response.content, "html.parser")
    title = soup.title.string if soup.title else "No title found"
    if soup.body:
        for irrelevant in soup.body(["script", "style", "img", "input"]):
            irrelevant.decompose()
        text = soup.body.get_text(separator="\n", strip=True)
    else:
        text = ""
    return (title + "\n\n" + text)[:2_000]


def fetch_website_links(url):
    """
    Return the links on the webiste at the given url
    I realize this is inefficient as we're parsing twice! This is to keep the code in the lab simple.
    Feel free to use a class and optimize it!
    """
    response = requests.get(url, headers=headers)
    soup = BeautifulSoup(response.content, "html.parser")
    links = [link.get("href") for link in soup.find_all("a")]
    return [link for link in links if link]

Common mistakes.
  • Forgot to select the kernel. In Cursor/VS Code you must do it for every notebook, or nothing runs.
  • Ran cells out of order. A NameError almost always means you skipped a cell above — run from the top.
  • Wrong .env name. keys.env or .env.txt will not be found; it must be exactly .env in the project root.
  • Mangled key. A leading/trailing space, or a "smart" long dash pasted from a notes app, breaks the key — that is what the startsWith("sk-proj-") check catches.
  • Ran a command outside uv. Use uv run … so the command sees the project's .venv; running bare jupyter or python may use a different environment with the packages missing.
  • Expecting every site to work. JavaScript-rendered pages (e.g. openai.com) come back nearly empty, and some sites return 403. That is a limit of simple scraping, not a bug in your code.
Recap
  • A notebook runs code one cell at a time; run cells top to bottom or you will hit a NameError.
  • You built the environment with uv: install uv, git clone, uv sync (creates the .venv with Python 3.12), then uv run jupyter lab or select the .venv kernel.
  • Your OpenAI key lives in a file named exactly .env and starts with sk-proj-; it is loaded from the environment and never committed to git.
  • Calling a model is always: build a messages list (system + user), call the chat completions endpoint, and read the first choice's message content — the same pattern in Python and TypeScript.
  • Ollama runs open-source models locally for free and offers an OpenAI-compatible endpoint, so the same code works against it.
  • The project scrapes a page, summarizes it, and shows the markdown. Python uses requests + BeautifulSoup and the Website class; the TypeScript port uses fetch + node-html-parser and a shared scrape.ts; a React app in week1-ts/ wraps the same summarizer behind a Hono API.
