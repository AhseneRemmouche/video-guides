Week 2 · Day 1 — Multiple APIs, Streaming and Adversarial Chat

Call OpenAI, Anthropic Claude and Google Gemini from one notebook, stream their replies token by token, and make two models hold a conversation with each other.

Welcome to Week 2. Last week you called one provider, OpenAI, over its API. Today you widen your reach: from a single notebook you will call three different model makers — OpenAI's GPT, Anthropic's Claude and Google's Gemini — ask each one to tell a joke, stream a reply back word by word, and then, for fun, let two models argue with each other in an adversarial conversation. The instructor's goal for the day is simple: add Anthropic's and Google's APIs to the OpenAI skills you already have, and get a feel for the small differences between them.

As on every day, the lab is shown in both languages. The course is taught in Python; this guide also ships a verified TypeScript port. Use the Code in: switch at the top of the page (or the Python | TypeScript tabs on the code card) to pick a language — the whole page follows your choice. The two programs do the same things in the same order, so you can read either one.

There is one idea worth holding onto before we start. All three providers do the same job — you send a list of messages, they send back a reply — but each exposes it through a slightly different door. OpenAI and Gemini share one shape; Anthropic's native library has its own. The clever part is that you rarely need three different libraries: because Google's and several others' servers speak OpenAI's protocol, one OpenAI client can talk to all of them just by changing a web address.

The concepts the instructor introduces

Three ideas carry the day. First, many providers, one skill: you already know the chat completions call shape; Gemini and Claude accept almost the same thing, and where they differ it is in small, nameable ways. Second, streaming: instead of waiting for a whole answer, you receive it in little pieces as it is generated — the "typewriter" effect from the chat apps. Third, the conversation as a list of messages: a chat with history is just a growing list of role-tagged messages, and once you see that, you can make two models talk to each other by feeding each one the other's replies.

New to the Anthropic (Claude) API? What it is and how it differs

Anthropic make the Claude family of models, and they ship their own client library — the anthropic package in Python, @anthropic-ai/sdk in Node. It does the same job as OpenAI's, but its call looks a little different, and the differences are worth memorising because they trip people up:

  • The call is client.messages.create(...), not chat.completions.create(...).
  • The system prompt is passed as a top-level system= argument, not as the first item in the messages list.
  • max_tokens (a cap on how long the reply may be) is optional for OpenAI but required for Claude — leave it out and the call fails.
  • The reply is a list of content blocks, so you read the text from response.content[0].text rather than response.choices[0].message.content.

In this lesson Ed uses each provider's own library. There is also a short-cut you will meet later: Anthropic and Google both run servers that "speak OpenAI", so you can reach them with the ordinary OpenAI client (see the next primer).

New to OpenAI-compatible endpoints? The base_url trick

An endpoint is the web address a request is sent to. The OpenAI client normally sends to OpenAI's address, but you can override it with base_url (Python) or baseURL (TypeScript). Several providers — Google (Gemini), DeepSeek, Groq, and your own local Ollama — expose an OpenAI-compatible endpoint: a server that accepts the exact same request shape. So you create the same OpenAI(...) client, hand it that provider's address and API key, and every call you already know works unchanged. One library, many model makers. The only thing that changes is the base_url and the model name.

New to streaming? What it is and why it matters

By default a chat call waits until the model has finished, then hands you the whole reply at once. With streaming you instead receive the answer in small pieces, called chunks, as they are generated, and you loop over them. With OpenAI you add stream=True (Python) / stream: true (TypeScript) and read each chunk's new text from delta.content. Claude's native library is slightly different: there is no extra argument — instead you call a stream method and read from its text stream. Either way you keep adding the pieces to a running string, which is what produces the typewriter effect. It does not make the model faster; it just lets the reader start reading sooner.

What is an adversarial conversation? A two-model chat

A chat with memory is really just a list of messages that grows over time: a system prompt, then alternating user and assistant turns. An adversarial conversation uses that same list to let two models talk to each other instead of a human talking to one model. One model is told to be argumentative, the other to be polite. Each turn, you take the whole transcript so far and hand it to one model as its history, collect its reply, add it to the transcript, and repeat with the other model. Nothing magic is happening — it is the conversation history being replayed and extended, which is also a nice reminder that models are stateless: they remember nothing between calls, so you resend the entire history every time.

// Video 2 in TypeScript: three providers, then streaming (run: npx tsx day1_streaming.ts)
import "dotenv/config";
import OpenAI from "openai";
import Anthropic from "@anthropic-ai/sdk";
import { GoogleGenAI } from "@google/genai";

const openai = new OpenAI();     // reads OPENAI_API_KEY
const claude = new Anthropic();  // reads ANTHROPIC_API_KEY
const gemini = new GoogleGenAI({ apiKey: process.env.GOOGLE_API_KEY });

const systemMessage = "You are an assistant that is great at telling jokes";
const userPrompt = "Tell a light-hearted joke for an audience of Data Scientists";
const prompts: OpenAI.Chat.ChatCompletionMessageParam[] = [
  { role: "system", content: systemMessage },
  { role: "user", content: userPrompt },
];

// GPT
const completion = await openai.chat.completions.create({
  model: "gpt-6-luna",
  reasoning_effort: "none",
  messages: prompts,
});
console.log(completion.choices[0].message.content);

// Claude: system is a top-level field and max_tokens is required (the SDK no longer takes temperature)
const message = await claude.messages.create({
  model: "claude-sonnet-4-6",
  max_tokens: 200,
  system: systemMessage,
  messages: [{ role: "user", content: userPrompt }],
});
const first = message.content[0];
console.log(first.type === "text" ? first.text : "");

// Claude, streamed: print each piece of text the moment it arrives
const claudeStream = claude.messages.stream({
  model: "claude-sonnet-4-6",
  max_tokens: 200,
  system: systemMessage,
  messages: [{ role: "user", content: userPrompt }],
});
claudeStream.on("text", (text) => process.stdout.write(text));
await claudeStream.finalMessage();
console.log();

// Gemini: the system message goes in config.systemInstruction
const response = await gemini.models.generateContent({
  model: "gemini-3.1-flash-lite",
  contents: userPrompt,
  config: { systemInstruction: systemMessage },
});
console.log(response.text);

// GPT, streamed, on a serious question
const stream = await openai.chat.completions.create({
  model: "gpt-6-luna",
  reasoning_effort: "none",
  messages: [
    { role: "system", content: "You are a helpful assistant" },
    { role: "user", content: "How do I decide if a business problem is suitable for an LLM solution?" },
  ],
  stream: true,
});
let reply = "";
for await (const chunk of stream) {
  const piece = chunk.choices[0]?.delta?.content ?? "";
  reply += piece;
  process.stdout.write(piece);
}

# Let's make a conversation between GPT-4o-mini and Claude-3-haiku

gpt_model = "gpt-4o-mini"
claude_model = "claude-3-haiku-20240307"

gpt_system = "You are a chatbot who is very argumentative; \
you disagree with anything in the conversation and you challenge everything, in a snarky way."

claude_system = "You are a very polite, courteous chatbot. You try to agree with \
everything the other person says, or find common ground. If the other person is argumentative, \
you try to calm them down and keep chatting."

gpt_messages = ["Hi there"]
claude_messages = ["Hi"]

def call_gpt():
    messages = [{"role": "system", "content": gpt_system}]
    for gpt, claude in zip(gpt_messages, claude_messages):
        messages.append({"role": "assistant", "content": gpt})
        messages.append({"role": "user", "content": claude})
    completion = openai.chat.completions.create(
        model=gpt_model,
        messages=messages
    )
    return completion.choices[0].message.content

call_gpt()

def call_claude():
    messages = []
    for gpt, claude_message in zip(gpt_messages, claude_messages):
        messages.append({"role": "user", "content": gpt})
        messages.append({"role": "assistant", "content": claude_message})
    messages.append({"role": "user", "content": gpt_messages[-1]})
    message = claude.messages.create(
        model=claude_model,
        system=claude_system,
        messages=messages,
        max_tokens=500
    )
    return message.content[0].text

call_claude()

call_gpt()

gpt_messages = ["Hi there"]
claude_messages = ["Hi"]

print(f"GPT:\n{gpt_messages[0]}\n")
print(f"Claude:\n{claude_messages[0]}\n")

for i in range(5):
    gpt_next = call_gpt()
    print(f"GPT:\n{gpt_next}\n")
    gpt_messages.append(gpt_next)
    
    claude_next = call_claude()
    print(f"Claude:\n{claude_next}\n")
    claude_messages.append(claude_next)

import "dotenv/config";
import OpenAI from "openai";
import Anthropic from "@anthropic-ai/sdk";

const openai = new OpenAI();
const claude = new Anthropic();

const gptModel = "gpt-6-luna";
const claudeModel = "claude-haiku-4-5";

const gptSystem = "You are a chatbot who is very argumentative; " +
  "you disagree with anything in the conversation and you challenge everything, in a snarky way.";
const claudeSystem = "You are a very polite, courteous chatbot. You try to agree with " +
  "everything the other person says, or find common ground. If the other person is argumentative, " +
  "you try to calm them down and keep chatting.";

const gptMessages = ["Hi there"];
const claudeMessages = ["Hi"];

// GPT sees its own lines as "assistant" and Claude's as "user"
async function callGpt(): Promise<string> {
  const messages: OpenAI.Chat.ChatCompletionMessageParam[] = [{ role: "system", content: gptSystem }];
  for (let i = 0; i < Math.min(gptMessages.length, claudeMessages.length); i++) {
    messages.push({ role: "assistant", content: gptMessages[i] });
    messages.push({ role: "user", content: claudeMessages[i] });
  }
  const completion = await openai.chat.completions.create({ model: gptModel, reasoning_effort: "none", messages });
  return completion.choices[0].message.content ?? "";
}

// Claude sees it the other way round, and gets GPT's latest line last
async function callClaude(): Promise<string> {
  const messages: Anthropic.MessageParam[] = [];
  for (let i = 0; i < Math.min(gptMessages.length, claudeMessages.length); i++) {
    messages.push({ role: "user", content: gptMessages[i] });
    messages.push({ role: "assistant", content: claudeMessages[i] });
  }
  messages.push({ role: "user", content: gptMessages[gptMessages.length - 1] });
  const message = await claude.messages.create({ model: claudeModel, system: claudeSystem, messages, max_tokens: 500 });
  const first = message.content[0];
  return first.type === "text" ? first.text : "";
}

console.log(`GPT:\n${gptMessages[0]}\n`);
console.log(`Claude:\n${claudeMessages[0]}\n`);
for (let i = 0; i < 5; i++) {
  const gptNext = await callGpt();
  console.log(`GPT:\n${gptNext}\n`);
  gptMessages.push(gptNext);

  const claudeNext = await callClaude();
  console.log(`Claude:\n${claudeNext}\n`);
  claudeMessages.push(claudeNext);
}

Common mistakes
  • Missing ANTHROPIC_API_KEY. The Claude cells need it. In Python you get an authentication error; the TypeScript port is kinder and prints "(Skipping Claude - ANTHROPIC_API_KEY not set)". Add the key to .env, save, and (in a notebook) re-run the cell that loads it (or restart the kernel).
  • Forgetting max_tokens for Claude's native SDK. Claude's own library requires a reply-length cap. Leave max_tokens out of messages.create(...) and the call errors before it reaches the model.
  • Reading the Claude reply the OpenAI way. With the native SDK the text is at content[0].text (a list of blocks), not choices[0].message.content. Mixing the two up gives an undefined or an attribute error.
  • Editing .env without reloading. After changing a key you must save the file and re-run the load cell (or restart the script); otherwise the old value is still in memory.
  • Forgetting await (TypeScript). Every call is asynchronous; drop an await and you pass around a pending Promise instead of the text.
