There is one idea worth holding onto before we start. All three providers do the same job — you send a list of messages, they send back a reply — but each exposes it through a slightly different door. OpenAI and Gemini share one shape; Anthropic's native library has its own. The clever part is that you rarely need three different libraries: because Google's and several others' servers speak OpenAI's protocol, one OpenAI client can talk to all of them just by changing a web address.

The concepts the instructor introduces

Three ideas carry the day. First, many providers, one skill: you already know the chat completions call shape; Gemini and Claude accept almost the same thing, and where they differ it is in small, nameable ways. Second, streaming: instead of waiting for a whole answer, you receive it in little pieces as it is generated — the "typewriter" effect from the chat apps. Third, the conversation as a list of messages: a chat with history is just a growing list of role-tagged messages, and once you see that, you can make two models talk to each other by feeding each one the other's replies.

New to the Anthropic (Claude) API? What it is and how it differs

Anthropic make the Claude family of models, and they ship their own client library — the anthropic package in Python, @anthropic-ai/sdk in Node. It does the same job as OpenAI's, but its call looks a little different, and the differences are worth memorising because they trip people up:

  • The call is client.messages.create(...), not chat.completions.create(...).
  • The system prompt is passed as a top-level system= argument, not as the first item in the messages list.
  • max_tokens (a cap on how long the reply may be) is optional for OpenAI but required for Claude — leave it out and the call fails.
  • The reply is a list of content blocks, so you read the text from response.content[0].text rather than response.choices[0].message.content.

There is also a short-cut you will use a lot in this lab: Anthropic and Google both run servers that "speak OpenAI", so you can skip the native library and reach them with the ordinary OpenAI client (see the next primer). The native library is still useful to know, because some features are only on it.

New to OpenAI-compatible endpoints? The base_url trick

An endpoint is the web address a request is sent to. The OpenAI client normally sends to OpenAI's address, but you can override it with base_url (Python) or baseURL (TypeScript). Several providers — Google (Gemini), DeepSeek, Groq, and your own local Ollama — expose an OpenAI-compatible endpoint: a server that accepts the exact same request shape. So you create the same OpenAI(...) client, hand it that provider's address and API key, and every call you already know works unchanged. One library, many model makers. The only thing that changes is the base_url and the model name.

New to streaming? What it is and why it matters

By default a chat call waits until the model has finished, then hands you the whole reply at once. With streaming you instead receive the answer in small pieces, called chunks, as they are generated, and you loop over them. With OpenAI you add stream=True (Python) / stream: true (TypeScript) and read each chunk's new text from delta.content. Claude's native library is slightly different: there is no extra argument — instead you call a stream method and read from its text stream. Either way you keep adding the pieces to a running string, which is what produces the typewriter effect. It does not make the model faster; it just lets the reader start reading sooner.

What is an adversarial conversation? A two-model chat

A chat with memory is really just a list of messages that grows over time: a system prompt, then alternating user and assistant turns. An adversarial conversation uses that same list to let two models talk to each other instead of a human talking to one model. One model is told to be argumentative, the other to be polite. Each turn, you take the whole transcript so far and hand it to one model as its history, collect its reply, add it to the transcript, and repeat with the other model. Nothing magic is happening — it is the conversation history being replayed and extended, which is also a nice reminder that models are stateless: they remember nothing between calls, so you resend the entire history every time.

// Day 1 - Multiple APIs (TypeScript port of day1.py)
//   1) OpenAI via the openai client library
//   2) Anthropic Claude via the native @anthropic-ai/sdk
//   3) Google Gemini via the OpenAI-compatible base URL (the library's whole trick:
//      swap baseURL + apiKey and the same client talks to another provider)
//   4) a streaming helper
//   5) a short adversarial conversation between two models (argumentative GPT vs polite Claude)
//
// Run with: npm run day1   (needs OPENAI_API_KEY; ANTHROPIC_API_KEY / GOOGLE_API_KEY are optional)
import "dotenv/config";
import { pathToFileURL } from "node:url";
import OpenAI from "openai";
import Anthropic from "@anthropic-ai/sdk";

const GPT_MODEL = "gpt-4o-mini";
const CLAUDE_MODEL = "claude-3-5-sonnet-20240620";
const CLAUDE_HAIKU = "claude-3-haiku-20240307";
const GEMINI_MODEL = "gemini-2.0-flash";
const GEMINI_BASE_URL = "https://generativelanguage.googleapis.com/v1beta/openai/";

// --- clients (built lazily so the module imports fine with no keys) ------------
function openaiClient(): OpenAI {
  return new OpenAI(); // reads OPENAI_API_KEY
}

function anthropicClient(): Anthropic {
  return new Anthropic(); // reads ANTHROPIC_API_KEY
}

function geminiClient(): OpenAI {
  return new OpenAI({ baseURL: GEMINI_BASE_URL, apiKey: process.env.GOOGLE_API_KEY });
}

// --- 1. OpenAI ----------------------------------------------------------------
async function askOpenAI(prompt: string): Promise<string> {
  const openai = openaiClient();
  const response = await openai.chat.completions.create({
    model: GPT_MODEL,
    messages: [{ role: "user", content: prompt }],
  });
  return response.choices[0]?.message.content ?? "";
}

// --- 2. Anthropic Claude (native SDK) -----------------------------------------
// The native SDK differs from OpenAI's shape: max_tokens is required and the reply
// comes back as an array of content blocks, so we pull the text out of the text blocks.
async function askClaude(prompt: string): Promise<string> {
  const anthropic = anthropicClient();
  const response = await anthropic.messages.create({
    model: CLAUDE_MODEL,
    max_tokens: 500,
    messages: [{ role: "user", content: prompt }],
  });
  return response.content
    .map((block) => (block.type === "text" ? block.text : ""))
    .join("");
}

// --- 3. Google Gemini via the OpenAI-compatible endpoint ----------------------
async function askGemini(prompt: string): Promise<string> {
  const gemini = geminiClient();
  const response = await gemini.chat.completions.create({
    model: GEMINI_MODEL,
    messages: [{ role: "user", content: prompt }],
  });
  return response.choices[0]?.message.content ?? "";
}

// --- 4. A streaming helper ----------------------------------------------------
// Streams an OpenAI completion, writing deltas to stdout as they arrive, and
// returns the full text once the stream ends.
async function streamOpenAI(prompt: string): Promise<string> {
  const openai = openaiClient();
  const stream = await openai.chat.completions.create({
    model: GPT_MODEL,
    messages: [{ role: "user", content: prompt }],
    stream: true,
  });
  let full = "";
  for await (const chunk of stream) {
    const delta = chunk.choices[0]?.delta.content ?? "";
    full += delta;
    process.stdout.write(delta);
  }
  process.stdout.write("\n");
  return full;
}

// --- 5. Adversarial two-model conversation ------------------------------------
// GPT is instructed to be argumentative; Claude to be polite. Each turn we rebuild
// the running transcript from each model's point of view (its own replies are the
// assistant turns, the other model's replies are the user turns).
const gptSystem =
  "You are a chatbot who is very argumentative; you disagree with anything in the " +
  "conversation and you challenge everything, in a snarky way.";
const claudeSystem =
  "You are a very polite, courteous chatbot. You try to agree with everything the other " +
  "person says, or find common ground. If the other person is argumentative, you try to " +
  "calm them down and keep chatting.";

async function callGpt(gptMessages: string[], claudeMessages: string[]): Promise<string> {
  const openai = openaiClient();
  const messages: OpenAI.Chat.ChatCompletionMessageParam[] = [
    { role: "system", content: gptSystem },
  ];
  for (let i = 0; i < gptMessages.length; i++) {
    messages.push({ role: "assistant", content: gptMessages[i]! });
    if (claudeMessages[i] !== undefined) messages.push({ role: "user", content: claudeMessages[i]! });
  }
  const response = await openai.chat.completions.create({ model: GPT_MODEL, messages });
  return response.choices[0]?.message.content ?? "";
}

async function callClaude(gptMessages: string[], claudeMessages: string[]): Promise<string> {
  const anthropic = anthropicClient();
  // Claude's native SDK keeps the system prompt as a top-level field, not a message.
  const messages: Anthropic.MessageParam[] = [];
  for (let i = 0; i < gptMessages.length; i++) {
    messages.push({ role: "user", content: gptMessages[i]! });
    if (claudeMessages[i] !== undefined) messages.push({ role: "assistant", content: claudeMessages[i]! });
  }
  const response = await anthropic.messages.create({
    model: CLAUDE_HAIKU,
    max_tokens: 500,
    system: claudeSystem,
    messages,
  });
  return response.content.map((b) => (b.type === "text" ? b.text : "")).join("");
}

async function adversarialLoop(rounds = 3): Promise<void> {
  const gptMessages = ["Hi there"];
  const claudeMessages = ["Hi"];
  console.log(`GPT:\n${gptMessages[0]}\n`);
  console.log(`Claude:\n${claudeMessages[0]}\n`);
  for (let i = 0; i < rounds; i++) {
    const gptNext = await callGpt(gptMessages, claudeMessages);
    console.log(`GPT:\n${gptNext}\n`);
    gptMessages.push(gptNext);

    const claudeNext = await callClaude(gptMessages, claudeMessages);
    console.log(`Claude:\n${claudeNext}\n`);
    claudeMessages.push(claudeNext);
  }
}

// --- entry point --------------------------------------------------------------
async function main(): Promise<void> {
  if (!process.env.OPENAI_API_KEY) {
    console.log("OPENAI_API_KEY not set - this demo needs it. See .env.example.");
    return;
  }
  const joke = "Tell a joke for a student on the journey to becoming an expert in LLM Engineering";

  console.log("=== OpenAI ===");
  console.log(await askOpenAI(joke));

  if (process.env.ANTHROPIC_API_KEY) {
    console.log("\n=== Claude ===");
    console.log(await askClaude(joke));
  } else {
    console.log("\n(Skipping Claude - ANTHROPIC_API_KEY not set)");
  }

  if (process.env.GOOGLE_API_KEY) {
    console.log("\n=== Gemini ===");
    console.log(await askGemini(joke));
  } else {
    console.log("\n(Skipping Gemini - GOOGLE_API_KEY not set)");
  }

  console.log("\n=== Streaming ===");
  await streamOpenAI("Describe the color blue to someone who has never seen, in one sentence.");

  if (process.env.ANTHROPIC_API_KEY) {
    console.log("\n=== Adversarial conversation (GPT vs Claude) ===");
    await adversarialLoop(3);
  } else {
    console.log("\n(Skipping adversarial loop - needs ANTHROPIC_API_KEY)");
  }
}

if (import.meta.url === pathToFileURL(process.argv[1] ?? "").href) {

  });
}

Python note — one library or two?

The Python notebook reaches Claude two ways. The joke, puzzle and adversarial cells use the OpenAI-compatible client (anthropic = OpenAI(base_url=...)), so the call looks exactly like an OpenAI call. The dedicated "client library" cell (lines 176-185) uses Anthropic's own from anthropic import Anthropic package, which is where messages.create, max_tokens and response.content[0].text appear. Both reach the same model; the native library is the one you need when you want Claude-only features.

TypeScript note — async/await and the native Claude SDK

Every network call here is async, so each one is written with await; forget an await and you would pass around an unresolved Promise instead of the text. Unlike the Python notebook, the port always uses Claude's native @anthropic-ai/sdk — which is why you see max_tokens, the top-level system, and the content-block mapping in every Claude function.

Common mistakes
  • Missing ANTHROPIC_API_KEY. The Claude cells need it. In Python you get an authentication error; the TypeScript port is kinder and prints "(Skipping Claude - ANTHROPIC_API_KEY not set)". Add the key to .env, save, and (in a notebook) re-run load_dotenv(override=True).
  • Forgetting max_tokens for Claude's native SDK. Claude's own library requires a reply-length cap. Leave max_tokens out of messages.create(...) and the call errors before it reaches the model. (Through the OpenAI-compatible client it is optional, which is why the main Python cells can omit it.)
  • Reading the Claude reply the OpenAI way. With the native SDK the text is at content[0].text (a list of blocks), not choices[0].message.content. Mixing the two up gives an undefined or an attribute error.
  • Editing .env without reloading. After changing a key you must save the file and re-run the load cell (or restart the script); otherwise the old value is still in memory.
  • Forgetting await (TypeScript). Every call is asynchronous; drop an await and you pass around a pending Promise instead of the text.

Streaming is a Day 1 topic even though the current notebook dropped its streaming cells. For completeness, the plain-text OpenAI version the video shows looks like this (standard, and consistent with the code above):

stream = openai.chat.completions.create(model="gpt-4o-mini", messages=tell_a_joke, stream=True)

The end="" stops Python adding a line break after each piece, so the words flow. Claude's native library streams differently — you call its stream method and loop over its text stream rather than adding a stream=True argument.

Recap
  • From one notebook you called three providers: OpenAI, Anthropic's Claude and Google's Gemini.
  • The OpenAI-compatible trick lets one OpenAI client reach Gemini, Claude, DeepSeek, Groq and local Ollama — you only change base_url and the model name.
  • Claude's native Anthropic library differs in four ways: messages.create, a top-level system=, a required max_tokens, and a reply read from content[0].text.
  • Streaming delivers a reply in chunks you loop over (delta.content with OpenAI; a stream method with Claude's native SDK), giving the typewriter effect.
  • An adversarial conversation makes two models talk by relabelling one shared transcript — your own lines as assistant, the other model's as user — proving again that models are stateless and the message list is the memory.
  • Python and TypeScript do the same work; the Python notebook reaches Claude mostly through the OpenAI-compatible client, while the TypeScript port always uses the native Anthropic SDK.
  • The API-calling code was not run live; the TypeScript project type-checks and builds.
