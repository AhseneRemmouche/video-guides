This is the finale of Week 2, and the instructor promises it is "really, really good fun." All week you built an airline assistant: it chats, it keeps a conversation going, and on Day 4 you gave it a tool that looks up ticket prices in a database. Today you make it multimodal — it will also draw pictures and speak its answers out loud. Along the way you meet the word that dominates the rest of the course: the agent.

The plan has three parts. First you write a function called artist that turns a city name into a picture, using an image model (the video uses OpenAI's DALL-E 3). Then you write a function called talker that turns text into an audio clip, using a text-to-speech model (the video uses tts-1). Finally you fold both of those into the airline assistant so that, when a customer asks about a city, the assistant speaks its reply and shows a travel poster of that city. Each of those functions is a small, specialised worker — a first, concrete taste of what an agent is.

As on every day, the lab is shown in both languages. The course is in Python; this guide ships a line-for-line TypeScript port. Use the Code in: switch at the top of the page (or the Python | TypeScript tabs on the code card) to choose; the whole page follows your choice.

The concepts the instructor introduces

Three ideas carry the day. Multimodal: a system that handles more than one kind of data — here text in and out, plus generated images and generated speech. Image and audio generation: the same openai client you already use can also make pictures (openai.images.generate) and sound (openai.audio.speech.create). And the agent: a small, autonomous, task-specific piece of software. The instructor is careful that "agent" is an umbrella term, but today's version is simple — each helper function (price lookup, artist, talker) is a focused specialist, and the main chat function orchestrates them.

New to "multimodal"? What it means and why it matters

Multimodal describes a model or an app that works with more than one mode of data — text, images, audio, sometimes video — instead of only text. A plain chatbot is single-mode: text in, text out. Today's assistant is multimodal because it takes a text question and gives back three things at once: written text, spoken audio and a picture.

The instructor makes an honest aside: strictly speaking an image model and a speech model are not "large language models". But people now use "LLM" loosely for all the models behind modern generative AI, so image and audio generation have become part of the LLM engineer's toolkit. You call them through the very same client object, which is why it feels seamless.

New to image generation and DALL-E? What they are and why they matter

Image generation means asking a model to create a brand-new picture from a text description (a "prompt"). You do not pick from stock photos; the model paints something that has never existed. DALL-E is OpenAI's family of image models; the video uses DALL-E 3, its most capable version at the time. (DALL-E 2 is an older, slightly cheaper option that makes less impressive images.)

You call it with openai.images.generate(...), passing the model name, a text prompt, a size such as 1024x1024, and n=1 for one image. The picture comes back as base64 text (a way of writing binary data as plain letters and numbers), which your code then decodes into real image bytes.

New to text-to-speech? What it is and why it matters

Text-to-speech (TTS) turns written words into spoken audio. You hand the model a string of text and a voice name, and it returns an audio clip of that text read aloud. The video uses the tts-1 model and the voice onyx; there are several other voices (the instructor also tries alloy) that you can swap in by changing one word.

You call it with openai.audio.speech.create(...). The reply is raw audio bytes (an MP3), which you can play right away or save to a file. It is the mirror image of image generation: same client, different method, binary data back.

What is an "agent"? A gentle first look

An agent is a software worker that is usually autonomous (it acts on its own), goal-oriented (it is trying to achieve something) and task-specific (it is good at one job). Agents are often combined into an agent framework, an environment where several of them cooperate — sometimes with memory, sometimes with one model planning the work for others, often by calling tools.

Today you build a tiny version. The artist function is a specialist that only makes pictures; the talker function is a specialist that only makes speech; the price tool is a specialist that only reads the database. The chat function stitches them together to answer one customer. The instructor stresses this is a small example of the idea; full autonomous agents come back in a big way later in the course.

// combined agent: the Day 4 tool-call loop, then draw the destination and speak the reply.
// Everything is guarded so the module compiles and imports without an API key.
import "dotenv/config";
import { writeFile } from "node:fs/promises";
import { pathToFileURL } from "node:url";
import OpenAI from "openai";
import { getTicketPrice, tools, SYSTEM_MESSAGE } from "./day4_tools.js";

export const IMAGE_MODEL = "dall-e-3";
export const TTS_MODEL = "tts-1";
export const CHAT_MODEL = "gpt-4o-mini";

// Generate an image and return the raw PNG bytes (b64 decoded).
export async function artist(openai: OpenAI, city: string): Promise<Buffer> {
  const response = await openai.images.generate({
    model: IMAGE_MODEL,
    prompt:
      `An image representing a vacation in ${city}, showing tourist spots and everything ` +
      `unique about ${city}, in a vibrant pop-art style`,
    size: "1024x1024",
    n: 1,
    response_format: "b64_json",
  });
  const b64 = response.data?.[0]?.b64_json;
  if (!b64) throw new Error("No image returned");
  return Buffer.from(b64, "base64");
}

// Turn text into speech and return the raw audio bytes (MP3).
export async function talker(openai: OpenAI, message: string): Promise<Buffer> {
  const response = await openai.audio.speech.create({
    model: TTS_MODEL,
    voice: "onyx", // try alloy or coral too
    input: message,
  });
  return Buffer.from(await response.arrayBuffer());
}

// The combined agent: run the airline tool-call loop, then (optionally) draw + speak.
export async function multimodalChat(
  openai: OpenAI,
  message: string,
): Promise<{ reply: string; image: Buffer | null; audio: Buffer }> {
  // Detect which city the tools looked at so we know what to draw, without re-running them.
  const messages: OpenAI.Chat.ChatCompletionMessageParam[] = [
    { role: "system", content: SYSTEM_MESSAGE },
    { role: "user", content: message },
  ];
  let response = await openai.chat.completions.create({ model: CHAT_MODEL, messages, tools });
  const cities: string[] = [];

  while (response.choices[0]?.finish_reason === "tool_calls") {
    const responseMessage = response.choices[0].message;
    messages.push(responseMessage);
    for (const toolCall of responseMessage.tool_calls ?? []) {
      if (toolCall.type === "function" && toolCall.function.name === "get_ticket_price") {
        const args = JSON.parse(toolCall.function.arguments) as { destination_city: string };
        cities.push(args.destination_city);
        messages.push({
          role: "tool",
          content: getTicketPrice(args.destination_city),
          tool_call_id: toolCall.id,
        });
      }
    }
    response = await openai.chat.completions.create({ model: CHAT_MODEL, messages, tools });
  }

  const reply = response.choices[0]?.message.content ?? "";
  const audio = await talker(openai, reply);
  const image = cities.length > 0 ? await artist(openai, cities[0]!) : null;
  return { reply, image, audio };
}

async function main(): Promise<void> {
  if (!process.env.OPENAI_API_KEY) {
    console.log("OPENAI_API_KEY not set - skipping the live DALL-E / TTS calls. See .env.example.");
    console.log(`Would use image model '${IMAGE_MODEL}' and TTS model '${TTS_MODEL}'.`);
    // The Day 4 tool still works offline via its own guard.
    return;
  }
  const openai = new OpenAI();
  const { reply, image, audio } = await multimodalChat(openai, "How much is a ticket to Tokyo?");
  console.log("Assistant:", reply);
  await writeFile("day5-reply.mp3", audio);
  console.log("Wrote day5-reply.mp3");
  if (image) {
    await writeFile("day5-city.png", image);
    console.log("Wrote day5-city.png");
  }
}

if (import.meta.url === pathToFileURL(process.argv[1] ?? "").href) {
  main().catch((err) => {
    console.error(err);
    process.exitCode = 1;
  });
}

Common mistakes and things to watch
  • Images cost real money. Up to now the course has cost fractions of a cent. Each DALL-E 3 image is about $0.04 in the video (the repo's note for its newer image model says roughly 3 cents). That is small, but not nothing — do not generate images in a tight loop, and remember n=1.
  • Forgetting to decode the base64. The image does not arrive as a picture; it arrives as a long base64 string. If you pass that string straight to the image library it will fail. You must call base64.b64decode(...) (Python) or Buffer.from(b64, "base64") (TypeScript) first, then wrap the bytes.
  • Audio is bytes too. talker returns raw audio bytes, not a sound you can "print". Play it through the audio component, or write it to a .mp3 file, to hear it.
  • Using the plain chat UI. gr.ChatInterface cannot show an image or play audio. The lab switches to gr.Blocks precisely so it can lay out the extra panels.

Build it step by step

Beyond reading the finished file, here is how to build today's assistant from the Day 4 starting point. Track A is Python with uv; Track B is the TypeScript script.

Track A — Python + uv. Start from the Day 4 notebook, which already has the assistant and its price tool.

  1. In the llm_engineering folder, make sure the imaging and audio packages are present (the repo's lock file includes them): 
    uv add pillow pydub
    Pillow opens the generated image; pydub helps play audio in the notebook.
  2. Open week2/day5.ipynb and run every cell from the top so the FlightAI assistant and get_ticket_price are defined and the price database is loaded.
  3. Add the image imports and the artist function (the code above), then run artist("New York City") and display(...) to see your first generated picture.
  4. Add the talker function and test it with a short line of text to hear a voice.
  5. Replace the chat function with the multimodal chat(history) and the handle_tool_calls_and_return_cities helper, so replies are spoken and cities are drawn.
  6. Add the gr.Blocks UI cell and run ui.launch(...). Type a question and watch the three panels fill: transcript, image, audio.

Track B — Node + TypeScript. The verified script reuses the Day 4 tool file.

  1. In the TypeScript project (week2-ts/ or the code/ts/w2 folder), install once: 
    npm install
    This pulls in openai, dotenv, typescript and tsx.
  2. Make sure day4_tools.ts is present — day5_multimodal.ts imports getTicketPrice, tools and SYSTEM_MESSAGE from it.

    It asks the agent a sample question and writes day5-reply.mp3 and day5-city.png next to the script.

Recap
  • Today's assistant is multimodal: one text question produces a written reply, spoken audio, and a generated picture.
  • artist(city) calls openai.images.generate (DALL-E 3 in the video) and decodes the returned base64 text into an image.
  • talker(text) calls openai.audio.speech.create (tts-1 in the video) and returns audio bytes you play or save.
  • The combined chat runs the Day 4 tool-call loop, remembers the looked-up city, then speaks the reply and draws that city — a tiny agent framework of three focused specialists.
  • A custom gr.Blocks screen replaces the plain chat UI so it can show the image panel and an autoplaying audio player.
  • Images cost real money (about $0.04 each in the video); the image and audio come back as encoded bytes that must be decoded before use.
  • The video uses dall-e-3 / tts-1 (shown in the TypeScript tab); the repo's Python file shows the newer gpt-image-1-mini / gpt-4o-mini-tts.
  • The image, audio and API code was not run live here; the TypeScript project type-checks and builds and runs offline via its no-key guard.
