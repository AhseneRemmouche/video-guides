Week 2 · Day 5 — Multimodal: Images and Audio

Add an image tool with DALL-E 3 and a voice with text-to-speech, and combine tools into a single multimodal agent.

Companion to Ed Donner's course · uv setup · Python + TypeScript/React · code verified against the repo

This is the finale of Week 2, and the instructor promises it is "really, really good fun." All week you built an airline assistant: it chats, it keeps a conversation going, and on Day 4 you gave it a tool that looks up ticket prices. Today you make it multimodal — it will also draw pictures and speak its answers out loud. Along the way you meet the word that dominates the rest of the course: the agent.

The plan has three parts. First you write a function called artist that turns a city name into a picture, using an image model (the video uses OpenAI's DALL-E 3). Then you write a function called talker that turns text into an audio clip, using a text-to-speech model (the video uses tts-1). Finally you fold both of those into the airline assistant so that, when a customer asks about a city, the assistant speaks its reply and shows a travel poster of that city. Each of those functions is a small, specialised worker — a first, concrete taste of what an agent is.

As on every day, the lab is shown in both languages. The course is in Python; this guide ships a line-for-line TypeScript port. Use the Code in: switch at the top of the page (or the Python | TypeScript tabs on the code card) to choose; the whole page follows your choice.

The concepts the instructor introduces

Three ideas carry the day. Multimodal: a system that handles more than one kind of data — here text in and out, plus generated images and generated speech. Image and audio generation: the same openai client you already use can also make pictures (openai.images.generate) and sound (openai.audio.speech.create). And the agent: a small, autonomous, task-specific piece of software. The instructor is careful that "agent" is an umbrella term, but today's version is simple — each helper function (price lookup, artist, talker) is a focused specialist, and the main chat function orchestrates them.

New to "multimodal"? What it means and why it matters

Multimodal describes a model or an app that works with more than one mode of data — text, images, audio, sometimes video — instead of only text. A plain chatbot is single-mode: text in, text out. Today's assistant is multimodal because it takes a text question and gives back three things at once: written text, spoken audio and a picture.

The instructor makes an honest aside: strictly speaking an image model and a speech model are not "large language models". But people now use "LLM" loosely for all the models behind modern generative AI, so image and audio generation have become part of the LLM engineer's toolkit. You call them through the very same client object, which is why it feels seamless.

New to image generation and DALL-E? What they are and why they matter

Image generation means asking a model to create a brand-new picture from a text description (a "prompt"). You do not pick from stock photos; the model paints something that has never existed. DALL-E is OpenAI's family of image models; the video uses DALL-E 3, its most capable version at the time. (DALL-E 2 is an older, slightly cheaper option that makes less impressive images.)

You call it with openai.images.generate(...), passing the model name, a text prompt, a size such as 1024x1024, and n=1 for one image. The picture comes back as base64 text (a way of writing binary data as plain letters and numbers), which your code then decodes into real image bytes.

New to text-to-speech? What it is and why it matters

Text-to-speech (TTS) turns written words into spoken audio. You hand the model a string of text and a voice name, and it returns an audio clip of that text read aloud. The video uses the tts-1 model and the voice onyx; there are several other voices (the instructor also tries alloy) that you can swap in by changing one word.

You call it with openai.audio.speech.create(...). The reply is raw audio bytes (an MP3), which you can play right away or save to a file. It is the mirror image of image generation: same client, different method, binary data back.

What is an "agent"? A gentle first look

An agent is a software worker that is usually autonomous (it acts on its own), goal-oriented (it is trying to achieve something) and task-specific (it is good at one job). Agents are often combined into an agent framework, an environment where several of them cooperate — sometimes with memory, sometimes with one model planning the work for others, often by calling tools.

Today you build a tiny version. The artist function is a specialist that only makes pictures; the talker function is a specialist that only makes speech; the price tool is a specialist that only looks up prices. The chat function stitches them together to answer one customer. The instructor stresses this is a small example of the idea; full autonomous agents come back in a big way later in the course.

// Video 19 in TypeScript: an artist and a talker (run: npx tsx day5_artist_talker.ts)
import "dotenv/config";
import { writeFile } from "node:fs/promises";
import OpenAI from "openai";

const openai = new OpenAI(); // reads OPENAI_API_KEY

// Make a pop-art picture of a city (GPT image models always answer in base64)
async function artist(city: string): Promise<Buffer> {
  const imageResponse = await openai.images.generate({
    model: "gpt-image-1-mini",
    prompt: `An image representing a vacation in ${city}, showing tourist spots and everything unique about ${city}, in a vibrant pop-art style`,
    size: "1024x1024",
    n: 1,
  });
  const imageBase64 = imageResponse.data?.[0]?.b64_json;
  if (!imageBase64) throw new Error("No image returned");
  return Buffer.from(imageBase64, "base64");
}

// Turn text into speech. Node has no built-in audio player, so the MP3 bytes are returned and saved
async function talker(message: string): Promise<Buffer> {
  const response = await openai.audio.speech.create({
    model: "tts-1",
    voice: "onyx", // alloy onyx
    input: message,
  });
  return Buffer.from(await response.arrayBuffer());
}

await writeFile("new_york.png", await artist("New York City"));
await writeFile("hi_there.mp3", await talker("Well, hi there"));
console.log("Wrote new_york.png and hi_there.mp3 - open them to see and hear the results");

def chat(message, history):
    image = None
    conversation = [{"role": "system", "content": system_message}]
    for human, assistant in history:
        conversation.append({"role": "user", "content": human})
        conversation.append({"role": "assistant", "content": assistant})
    conversation.append({"role": "user", "content": message})
    response = openai.chat.completions.create(model=MODEL, messages=conversation, tools=tools)

    if response.choices[0].finish_reason=="tool_calls":
        message = tool_call = response.choices[0].message
        response, city = handle_tool_call(message)
        conversation.append(message)
        conversation.append(response)
        image = artist(city)
        response = openai.chat.completions.create(model=MODEL, messages=conversation)

    reply = response.choices[0].message.content
    talker(reply)
    return reply, image

// The Gradio screen has no TypeScript twin: this script answers one question and saves the picture and the speech.
import "dotenv/config";
import { writeFile } from "node:fs/promises";
import OpenAI from "openai";

const openai = new OpenAI();
const MODEL = "gpt-6-luna";

const systemMessage = "You are a helpful assistant for an Airline called FlightAI. " +
  "Give short, courteous answers, no more than 1 sentence. " +
  "Always be accurate. If you don't know the answer, say so.";

type Turn = { role: "user" | "assistant"; content: string };

// --- Day 4: the price tool -------------------------------------------------
const ticketPrices: Record<string, string> = { london: "$799", paris: "$899", tokyo: "$1400", berlin: "$499" };

function getTicketPrice(destinationCity: string): string {
  console.log(`Tool get_ticket_price called for ${destinationCity}`);
  return ticketPrices[destinationCity.toLowerCase()] ?? "Unknown";
}

const tools: OpenAI.Chat.ChatCompletionTool[] = [{
  type: "function",
  function: {
    name: "get_ticket_price",
    description: "Get the price of a return ticket to the destination city. Call this whenever you need to know the ticket price, " +
      "for example when a customer asks 'How much is a ticket to this city'",
    parameters: {
      type: "object",
      properties: {
        destination_city: { type: "string", description: "The city that the customer wants to travel to" },
      },
      required: ["destination_city"],
      additionalProperties: false,
    },
  },
}];

function handleToolCall(message: OpenAI.Chat.ChatCompletionMessage): [OpenAI.Chat.ChatCompletionToolMessageParam, string] {
  const toolCall = message.tool_calls![0];
  if (toolCall.type !== "function") throw new Error("Unexpected tool call");
  const city = (JSON.parse(toolCall.function.arguments) as { destination_city: string }).destination_city;
  const price = getTicketPrice(city);
  return [{ role: "tool", content: JSON.stringify({ destination_city: city, price }), tool_call_id: toolCall.id }, city];
}

// --- Video 19: the two specialists -------------------------------------------
async function artist(city: string): Promise<Buffer> {
  const imageResponse = await openai.images.generate({
    model: "gpt-image-1-mini",
    prompt: `An image representing a vacation in ${city}, showing tourist spots and everything unique about ${city}, in a vibrant pop-art style`,
    size: "1024x1024",
    n: 1,
  });
  const imageBase64 = imageResponse.data?.[0]?.b64_json;
  if (!imageBase64) throw new Error("No image returned");
  return Buffer.from(imageBase64, "base64");
}

async function talker(message: string): Promise<Buffer> {
  const response = await openai.audio.speech.create({ model: "tts-1", voice: "onyx", input: message });
  return Buffer.from(await response.arrayBuffer());
}

// --- Video 20: the chat that uses all three ----------------------------------
async function chat(message: string, history: Turn[]): Promise<{ reply: string; image: Buffer | null; audio: Buffer }> {
  let image: Buffer | null = null;
  const conversation: OpenAI.Chat.ChatCompletionMessageParam[] = [{ role: "system", content: systemMessage }];
  for (const turn of history) conversation.push({ role: turn.role, content: turn.content });
  conversation.push({ role: "user", content: message });
  let response = await openai.chat.completions.create({ model: MODEL, reasoning_effort: "none", messages: conversation, tools });

  if (response.choices[0].finish_reason === "tool_calls") {
    const toolRequest = response.choices[0].message;
    const [toolResponse, city] = handleToolCall(toolRequest);
    conversation.push(toolRequest);
    conversation.push(toolResponse);
    image = await artist(city);  // the one extra line: draw the city the model asked about
    response = await openai.chat.completions.create({ model: MODEL, reasoning_effort: "none", messages: conversation });
  }

  const reply = response.choices[0].message.content ?? "";
  const audio = await talker(reply);  // and speak every reply
  return { reply, image, audio };
}

const { reply, image, audio } = await chat("How much is a return ticket to London?", []);
console.log("Assistant:", reply);
await writeFile("reply.mp3", audio);
if (image) await writeFile("city.png", image);
console.log("Wrote reply.mp3" + (image ? " and city.png" : ""));

Common mistakes and things to watch
  • Images cost real money. Up to now the course has cost fractions of a cent. Each DALL-E 3 image is about $0.04 in the video (the repo's note for its newer image model says roughly 3 cents). That is small, but not nothing — do not generate images in a tight loop, and remember n=1.
  • Forgetting to decode the base64. The image does not arrive as a picture; it arrives as a long base64 string. If you pass that string straight to the image library it will fail. You must call base64.b64decode(...) (Python) or Buffer.from(b64, "base64") (TypeScript) first, then wrap the bytes.
  • Audio needs a player. The speech arrives as MP3 bytes. In the video pydub decodes and plays them, which needs ffmpeg installed; on Windows pydub's playback can also fail with a permission error. Today's repository sidesteps both by returning the bytes to a gr.Audio(autoplay=True) player; the TypeScript port writes them to a .mp3 file.
  • Using the plain chat UI. gr.ChatInterface cannot show an image or play audio. The lab switches to gr.Blocks precisely so it can lay out the extra panels.
  • Retired models. dall-e-3 no longer works (and GPT image models reject response_format); use the Runs today tab.
  • Not run live here. The image, audio and API code in this guide was not executed (that needs a paid key). The "As in the video" code matches the recording; the "Runs today" and TypeScript code was checked against the current libraries with a type checker.
Video vs repo

Recap
  • Today's assistant is multimodal: one text question produces a written reply, spoken audio, and a generated picture.
  • artist(city) calls openai.images.generate (DALL-E 3 in the video, gpt-image-1-mini today) and decodes the returned base64 text into an image.
  • talker(text) calls openai.audio.speech.create (tts-1) and gets MP3 bytes, which the video plays with pydub.
  • The combined chat runs the Day 4 tool round trip, keeps the looked-up city, then speaks the reply and draws that city — a tiny agent framework of three focused specialists.
  • A custom gr.Blocks screen replaces the plain chat UI so it can show the image panel next to the chat.
  • Images cost real money (about $0.04 each in the video); the image and audio come back as encoded bytes that must be decoded before use.
  • dall-e-3 is retired: the "Runs today" tabs use gpt-image-1-mini, current chat models, and Gradio's dictionary-shaped chat history.
