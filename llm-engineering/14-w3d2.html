What a pipeline is

The instructor explains that there are two levels at which you can use the transformers library. The high level is pipelines: packaged, ready-to-use tasks for everyday inference (running a trained model to turn an input into an output). The low level is working directly with tokenizers and models — which you need when you care about exactly how text is tokenised, which model and parameters you use, or when you want to train or fine-tune your own model. Today is entirely about the easy, high level. Tokenizers and models come next lesson.

New to "a pipeline"? What it is and why it matters

A pipeline bundles together everything needed to run one kind of task: it takes your raw input, prepares it for the model (tokenising text, resizing an image), runs the model, and turns the model's raw numbers back into a friendly answer. You do not see any of those steps — you just call it. The shape is always the same two lines:

pipe = pipeline("task-name")   # 1. build the pipeline for a task
result = pipe(your_input)      # 2. call it with your input

If you do not name a model, the pipeline downloads a sensible default model for that task from the hub the first time you run it. You can pass model="org/name" to pick a specific one.

New to the transformers library? The heart of HuggingFace

The transformers library (installed with pip install transformers) is HuggingFace's Python package for running and training transformer models. It is the single most-used piece of the HuggingFace ecosystem: it knows how to download a model from the hub, load it, and run it. For tasks that generate images it has a sibling library, diffusers, and a companion datasets library gives access to ready-made datasets. The instructor installs all three in Colab with one command: !pip install -q transformers datasets diffusers (the leading ! runs a shell command inside a notebook cell; -q keeps it quiet).

New to transformers.js? The same idea in JavaScript

transformers.js is HuggingFace's official JavaScript library (installed as @huggingface/transformers). It mirrors the Python API — you still call pipeline(task) and then call the result with your input — but it runs small models in-process using ONNX weights (on the CPU via WebAssembly), so it works in a plain Node program or even in the browser, with no GPU and no server. Because it runs the .onnx builds, you usually name an explicit Xenova/* model that ships those weights. Two differences to remember: every call is async (you await it, because the model downloads on first use), and it is best for the smaller models — the giant ones still want Python and a GPU.

The seven everyday tasks

The instructor rattles through a family of common machine-learning tasks, each one a pipeline. Here is the task zoo you will build today, with the string you pass to pipeline(...).

What each task does (quick tour)
  • sentiment-analysis — reads a sentence and says POSITIVE or NEGATIVE with a confidence score. A classic classification task.
  • ner (named entity recognition) — tags the words in a sentence as the kinds of thing they name: PER (person), LOC (location), ORG (organisation), and so on.
  • question-answering — you give it a context passage and a question; it finds the answer inside the context.
  • summarization — turns a long block of text into a short one.
  • translation — translates between two languages; the task string names the pair, e.g. translation_en_to_fr.
  • zero-shot-classification — sorts text into labels you supply, with no task-specific training examples. You pass the candidate labels at call time.
  • text-generation — continues a prompt, the way a small language model would. The instructor notes a tiny default model rambles; a bigger model reads better.
  • image / audio — image generation uses the diffusers sibling library (Stable Diffusion); audio uses a text-to-speech pipeline (Microsoft's SpeechT5). Shown briefly at the end.

# Reconstructed to match the course's Google Colab notebook for this day.
# Standard HuggingFace code; runs on a GPU (e.g. Colab T4). Not executed here (no GPU).
#
# Week 3 - Day 2: HuggingFace Transformers "pipelines" - the high-level API.
# A pipeline wraps a model + tokenizer so an everyday inference task is two lines:
#   pipe = pipeline("task-name")
#   result = pipe(input)
# When no model is named, the pipeline downloads a sensible default for that task
# from the HuggingFace hub on first use.
#
# Colab setup (run once in a cell before this script):
#   !pip install -q transformers datasets diffusers
# and sign in so gated/large models can download:
#   from huggingface_hub import login
#   from google.colab import userdata
#   login(userdata.get("HF_TOKEN"), add_to_git_credential=True)

import torch
from transformers import pipeline

# Use the GPU when we have one; pipelines take device=0 (cuda:0) or device="cuda".
device = "cuda" if torch.cuda.is_available() else "cpu"


def sentiment_analysis():
    # Positive / negative classification of a sentence.
    classifier = pipeline("sentiment-analysis", device=device)
    result = classifier("I am super excited to be on the way to LLM mastery!")
    print("Sentiment:", result)
    # -> [{'label': 'POSITIVE', 'score': 0.999...}]


def named_entity_recognition():
    # Tag the words in a sentence as persons, locations, organizations, etc.
    ner = pipeline("ner", grouped_entities=True, device=device)
    result = ner("Barack Obama was the 44th president of the United States.")
    print("NER:", result)
    # -> [{'entity_group': 'PER', 'word': 'Barack Obama', ...},
    #     {'entity_group': 'LOC', 'word': 'United States', ...}]


def question_answering():
    # Answer a question given a context passage to look the answer up in.
    qa = pipeline("question-answering", device=device)
    result = qa(
        question="Who was the 44th president of the United States?",
        context="Barack Obama was the 44th president of the United States.",
    )
    print("Question answering:", result)
    # -> {'answer': 'Barack Obama', 'score': ..., 'start': ..., 'end': ...}


def summarization():
    # Turn a block of text into a short summary.
    summarizer = pipeline("summarization", device=device)
    text = (
        "The HuggingFace transformers library is an incredibly versatile and powerful tool "
        "for natural language processing (NLP). It allows users to perform a wide range of "
        "tasks such as text classification, named entity recognition, and question answering, "
        "among others. It's an extremely popular library that's widely used by the open-source "
        "data science community. It lowers the barrier to entry into the field by providing "
        "Data Scientists with a productive, convenient way to work with transformer models."
    )
    summary = summarizer(text, max_length=50, min_length=25, do_sample=False)
    print("Summary:", summary[0]["summary_text"])


def translation():
    # Translate English to French.
    translator = pipeline("translation_en_to_fr", device=device)
    result = translator(
        "The Data Scientists were truly amazed by the power and simplicity of the "
        "HuggingFace pipeline API."
    )
    print("Translation:", result[0]["translation_text"])


def zero_shot_classification():
    # Classify text against labels we supply, with no task-specific training.
    classifier = pipeline("zero-shot-classification", device=device)
    result = classifier(
        "HuggingFace's Transformers library is amazing!",
        candidate_labels=["technology", "sports", "politics"],
    )
    print("Zero-shot classification:", result)
    # -> {'labels': ['technology', ...], 'scores': [0.95, ...]}


def text_generation():
    # Continue a prompt with a (small, default) language model.
    generator = pipeline("text-generation", device=device)
    result = generator(
        "If there's one thing I want you to remember about using HuggingFace pipelines, it's"
    )
    print("Text generation:", result[0]["generated_text"])

# These move from transformers to its sibling library, diffusers (for images), and
# use a few more parameters, but are still only a handful of lines. The course runs
# these on the GPU too.

def main():
    sentiment_analysis()
    named_entity_recognition()
    question_answering()
    summarization()
    translation()
    zero_shot_classification()
    text_generation()

// Week 3 - Day 2: HuggingFace pipelines, the transformers.js way.
//
// The Python course uses `from transformers import pipeline`; transformers.js is the
// real JS equivalent: `import { pipeline } from "@huggingface/transformers"`. The API
// is the same shape - call pipeline(task) to get a pipe, then call the pipe with input -
// except it is async (the model downloads on first use) and it runs small ONNX models
// in-process (WASM on CPU), so we name explicit Xenova/* models the library supports.
//
// Run with: npm run day2
// NOTE: the first run downloads each model (tens of MB) from the HuggingFace hub and
// caches it under node_modules/.cache; there is no network use until then.
import "dotenv/config";
import { pathToFileURL } from "node:url";
import { pipeline } from "@huggingface/transformers";

// Small models transformers.js ships ONNX weights for.
const SENTIMENT_MODEL = "Xenova/distilbert-base-uncased-finetuned-sst-2-english";
const SUMMARIZATION_MODEL = "Xenova/distilbart-cnn-6-6";
const QA_MODEL = "Xenova/distilbert-base-cased-distilled-squad";
const ZERO_SHOT_MODEL = "Xenova/nli-deberta-v3-xsmall";

// --- sentiment analysis -------------------------------------------------------
export async function sentimentAnalysis(text: string) {
  const classifier = await pipeline("sentiment-analysis", SENTIMENT_MODEL);
  const result = await classifier(text);
  return result; // [{ label: "POSITIVE", score: 0.99... }]
}

// --- summarization ------------------------------------------------------------
export async function summarize(text: string) {
  const summarizer = await pipeline("summarization", SUMMARIZATION_MODEL);
  // transformers.js types the options as a full GenerationConfig; we only need a couple
  // of fields, so cast the partial options object.
  const options = { max_new_tokens: 60 } as Record<string, unknown>;
  const result = (await summarizer(text, options as any)) as Array<{ summary_text: string }>;
  return result[0]?.summary_text ?? "";
}

// --- question answering -------------------------------------------------------
export async function questionAnswering(question: string, context: string) {
  const qa = await pipeline("question-answering", QA_MODEL);
  const result = await qa(question, context);
  return result; // { answer, score }
}

// --- zero-shot classification -------------------------------------------------
export async function zeroShotClassification(text: string, labels: string[]) {
  const classifier = await pipeline("zero-shot-classification", ZERO_SHOT_MODEL);
  const result = await classifier(text, labels);
  return result; // { labels, scores }
}

async function main(): Promise<void> {
  console.log("=== sentiment-analysis ===");
  console.log(await sentimentAnalysis("I am super excited to be on the way to LLM mastery!"));

  console.log("\n=== summarization ===");
  console.log(
    await summarize(
      "The HuggingFace transformers library is an incredibly versatile and powerful tool " +
        "for natural language processing. It lets you perform a wide range of tasks such as " +
        "text classification, named entity recognition, question answering and summarization. " +
        "It is widely used by the open-source data science community and lowers the barrier to " +
        "entry into the field.",
    ),
  );

  console.log("\n=== question-answering ===");
  console.log(
    await questionAnswering(
      "Who was the 44th president of the United States?",
      "Barack Obama was the 44th president of the United States.",
    ),
  );

  console.log("\n=== zero-shot-classification ===");
  console.log(
    await zeroShotClassification("HuggingFace's Transformers library is amazing!", [
      "technology",
      "sports",
      "politics",
    ]),
  );
}

// Only run when invoked directly (so the file is safe to import for its helpers).
if (import.meta.url === pathToFileURL(process.argv[1] ?? "").href) {
  main().catch((err) => {
    console.error(err);
    process.exitCode = 1;
  });
}

Python vs TypeScript — where the code runs

The two programs read almost identically, but they live in different worlds. Python's transformers leans on a GPU and the unnamed default models; transformers.js runs small named models on the CPU, right inside Node or a browser tab.

Common surprises. The first call for each task downloads a model, so it is slow and needs a network — later calls are fast and offline. On Python you will see a one-time "no model was supplied, defaulted to …" message (harmless) and a nudge that a GPU is available but unused if you leave off device. On a CPU the big Python models are painfully slow; that is why Week 3 uses a Colab GPU, and why the TypeScript side sticks to small models.

A note on the hub and the hosted alternative

Everything today downloads a model and runs it on your machine (your Colab GPU, or your CPU for transformers.js). HuggingFace also offers a hosted Inference API — the same models behind a web call, so you run nothing locally — which is handy when you have no GPU and do not want a multi-megabyte download. The pipelines in this lesson are the run-it-yourself route; the Inference API is the call-a-server route to the same catalogue.

  • If you name no model, the pipeline downloads a sensible default for that task on first use; you can pass model= to choose one.
  • Today's tasks: sentiment-analysis, ner, question-answering, summarization, translation, zero-shot-classification, text-generation, plus image generation (via diffusers) and text-to-speech, noted briefly.
  • transformers.js (@huggingface/transformers) mirrors the API in JavaScript — same task strings, but async and running small Xenova/* ONNX models on the CPU in Node or the browser.
  • The first call downloads the model (slow, needs network) and then caches it; Python wants a GPU for the bigger models, which is why Week 3 runs on Colab.
