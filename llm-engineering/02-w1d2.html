What the Chat Completions API is

An LLM does one simple thing: you give it a conversation, and it predicts what should come next. The Chat Completions API wraps exactly that idea. You send a list of messages — each with a role (system, user or assistant) and some text — and the model replies with the most likely next message. That is all "chat completion" means: here is a conversation, please complete it.

OpenAI invented this API shape, but it became so popular that almost every provider now offers the same thing. That is why learning it once pays off everywhere. In the video, Ed Donner calls it "the simplest way to call an LLM."

New to APIs? What an API endpoint is and why it matters

An API (Application Programming Interface) is a way for your program to ask another program to do something. When that other program lives on the internet, you reach it at an endpoint: a web address (URL) that accepts requests and sends back answers. OpenAI's chat endpoint is https://api.openai.com/v1/chat/completions. You send it a request (which model you want, and the messages); it sends back the model's reply. This request-and-response style over the web is called a REST API, and almost everything today is built on it.

  • Cloud APIs: your code calls a model in the cloud and you pay per request, as on Day 1. LangChain is a layer on top of these APIs, and Amazon Bedrock, Google Vertex AI and Azure ML are managed cloud services that offer many models behind one interface.

// Video 18 in TypeScript: call a local Ollama model by hand, then with the ollama package
// (run: npx tsx day2_ollama.ts; needs Ollama running and `ollama pull llama3.2` done once)
import ollama from "ollama";

// Constants
const OLLAMA_API = "http://localhost:11434/api/chat";
const HEADERS = { "Content-Type": "application/json" };
const MODEL = "llama3.2";

// Create a messages list using the same format that we used for OpenAI
const messages = [
  { role: "user", content: "Describe some of the business applications of Generative AI" },
];

const payload = {
  model: MODEL,
  messages: messages,
  stream: false,
};

// A plain HTTP POST to the Ollama server on your own machine
const response = await fetch(OLLAMA_API, { method: "POST", headers: HEADERS, body: JSON.stringify(payload) });
const data = (await response.json()) as { message: { content: string } };
console.log(data.message.content);

// The same call through the ollama package
const reply = await ollama.chat({ model: MODEL, messages: messages });
console.log(reply.message.content);

What is Ollama, and what is a local model?

Ollama is a free tool that runs open-source models directly on your computer. You download a model once with ollama pull, and Ollama serves it at http://localhost:11434. A "local model" means the model's weights live on your machine and all the thinking (inference) happens there — nothing is sent to the cloud. The upside is it is free and private; the downside is a laptop-sized model is far weaker than a frontier model like GPT. Under the hood Ollama uses optimized C++ so these models run acceptably without a giant server.

What does a client library (openai, ollama) actually do?

It is a client library — a thin wrapper around the exact HTTP call you saw in part 1. It builds the headers, turns your arguments into JSON, sends the POST, and unpacks the JSON reply into an object. That is it. As the course stresses: it is open-source and lightweight, and "some people think it contains OpenAI model code — it doesn't!" The model runs on OpenAI's servers; the library just carries messages to and from it. The Python and JavaScript editions are the same idea in two languages.

Common mistakes.
  • Ollama not running. A "connection refused" error means the server is not up. Open a terminal, run ollama serve, and check that http://localhost:11434 says "Ollama is running".
  • Model not downloaded. Asking for llama3.2 before pulling it gives a "model not found" error. Run ollama pull llama3.2 (or ollama run llama3.2 once, as in Video 2 of Day 1).
  • Wrong path. The native chat endpoint is /api/chat; /v1 is the OpenAI-compatible one, which expects a different request and reply shape.
  • Reading the reply the OpenAI way. Ollama's native reply has no choices list: the text is in ['message']['content'].
  • Forgetting "stream": False. Without it Ollama streams many small JSON lines, and response.json() fails.
  • Too big a model. llama3.2 (about 2 GB) suits most laptops; llama3.2:1b is smaller still. Large models are very slow without a strong GPU.

So the current repository reaches Ollama through its OpenAI-compatible endpoint instead of the ollama package. The diagrams below show that version.
What is an OpenAI-compatible endpoint?

Because OpenAI's Chat Completions API became the standard, other providers built endpoints that accept the same request shape and return the same response shape. These are called OpenAI-compatible endpoints. The benefit: you keep the one client library you already know and only change two things — the base URL (which server) and the key (which account). OpenAI even designed its library to allow this. So "OpenAI" appearing in your code does not mean an OpenAI model is running — the base URL decides that.

Your homework

This is the exercise Ed sets at the end of Video 18: take the Day 1 website summarizer and make it call your local Ollama model instead of OpenAI. Only one function changes: summarize calls ollama.chat(model=MODEL, messages=messages) and reads response['message']['content']. The scraping, the system prompt and the user prompt stay exactly the same. You end up with a summarizer that is free, keeps your data on your own computer and works offline; a small local model writes rougher summaries than a frontier model. Try it yourself first. Here is the course's solution (week1/solutions/day2 SOLUTION.ipynb, as it was when the video was recorded), with a TypeScript port:

# imports

import requests
from bs4 import BeautifulSoup
from IPython.display import Markdown, display
import ollama

# Constants

MODEL = "llama3.2"

# A class to represent a Webpage

class Website:
    """
    A utility class to represent a Website that we have scraped
    """
    url: str
    title: str
    text: str

    def __init__(self, url):
        """
        Create this Website object from the given url using the BeautifulSoup library
        """
        self.url = url
        response = requests.get(url)
        soup = BeautifulSoup(response.content, 'html.parser')
        self.title = soup.title.string if soup.title else "No title found"
        for irrelevant in soup.body(["script", "style", "img", "input"]):
            irrelevant.decompose()
        self.text = soup.body.get_text(separator="\n", strip=True)

# Let's try one out

ed = Website("https://edwarddonner.com")
print(ed.title)
print(ed.text)

# Define our system prompt - you can experiment with this later, changing the last sentence to 'Respond in markdown in Spanish."

system_prompt = "You are an assistant that analyzes the contents of a website \
and provides a short summary, ignoring text that might be navigation related. \
Respond in markdown."

# A function that writes a User Prompt that asks for summaries of websites:

def user_prompt_for(website):
    user_prompt = f"You are looking at a website titled {website.title}"
    user_prompt += "The contents of this website is as follows; \
please provide a short summary of this website in markdown. \
If it includes news or announcements, then summarize these too.\n\n"
    user_prompt += website.text
    return user_prompt

# See how this function creates exactly the format above

def messages_for(website):
    return [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_prompt_for(website)}
    ]

# And now: call the Ollama function instead of OpenAI

def summarize(url):
    website = Website(url)
    messages = messages_for(website)
    response = ollama.chat(model=MODEL, messages=messages)
    return response['message']['content']

summarize("https://edwarddonner.com")

# A function to display this nicely in the Jupyter output, using markdown

def display_summary(url):
    summary = summarize(url)
    display(Markdown(summary))

display_summary("https://edwarddonner.com")

display_summary("https://cnn.com")

display_summary("https://anthropic.com")
// The Day 2 exercise, solved in TypeScript: the Day 1 summarizer on a local Ollama model
// (run: npx tsx day2_solution.ts; needs Ollama running and llama3.2 pulled)
import ollama from "ollama";
import { parse } from "node-html-parser";

const MODEL = "llama3.2";

// A class to represent a Webpage (as on Day 1)
class Website {
  title = "No title found";
  text = "";
  private constructor(public url: string) {}
  static async create(url: string): Promise<Website> {
    const site = new Website(url);
    const root = parse(await (await fetch(url)).text());
    const title = root.querySelector("title");
    if (title) site.title = title.text.trim();
    const body = root.querySelector("body");
    if (body) {
      for (const el of body.querySelectorAll("script, style, img, input")) el.remove();
      site.text = body.structuredText.trim();
    }
    return site;
  }
}

const systemPrompt =
  "You are an assistant that analyzes the contents of a website " +
  "and provides a short summary, ignoring text that might be navigation related. " +
  "Respond in markdown.";

function userPromptFor(website: Website): string {
  let userPrompt = `You are looking at a website titled ${website.title}`;
  userPrompt +=
    "\nThe contents of this website is as follows; " +
    "please provide a short summary of this website in markdown. " +
    "If it includes news or announcements, then summarize these too.\n\n";
  return userPrompt + website.text;
}

function messagesFor(website: Website) {
  return [
    { role: "system", content: systemPrompt },
    { role: "user", content: userPromptFor(website) },
  ];
}

// And now: call the Ollama function instead of OpenAI
async function summarize(url: string): Promise<string> {
  const website = await Website.create(url);
  const response = await ollama.chat({ model: MODEL, messages: messagesFor(website) });
  return response.message.content;
}

console.log(await summarize("https://edwarddonner.com"));

The Website class, prompts and messages_for are the Day 1 code; only the imports, the MODEL constant and summarize are new. If a page has no <body> the class fails, as on Day 1 (the "Runs today" version on the Day 1 page adds the check).

Recap
  • The Chat Completions API means: send a list of messages, get the predicted next message back.
  • At bottom it is one HTTP POST: a JSON body with model and messages, and a JSON reply. To a cloud provider you add a Bearer key header; to Ollama on your own machine you need none. Python sends it with requests.post; TypeScript sends it with fetch.
  • Client libraries (openai, ollama; Python and JavaScript editions) are thin wrappers around that POST. They hold no model code; the model runs on the provider's servers, or in Ollama on your computer.
  • Other providers copied the API shape (OpenAI-compatible endpoints), so the same client reaches Google Gemini or a local Ollama model by changing only the base URL and the key; the current repository's Day 2 notebook uses that route.
  • Ollama runs open-source models like llama3.2 on your own machine — free and private, but less powerful than a frontier model.
  • In the video Ed calls Llama 3.2 with a hand-made POST to http://localhost:11434/api/chat and then with the ollama package's ollama.chat(...); both read ['message']['content'].
