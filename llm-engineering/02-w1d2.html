What the Chat Completions API is

An LLM does one simple thing: you give it a conversation, and it predicts what should come next. The Chat Completions API wraps exactly that idea. You send a list of messages — each with a role (system, user or assistant) and some text — and the model replies with the most likely next message. That is all "chat completion" means: here is a conversation, please complete it.

OpenAI invented this API shape, but it became so popular that almost every provider now offers the same thing. That is why learning it once pays off everywhere. In the video, Ed Donner calls it "the simplest way to call an LLM."

New to APIs? What an API endpoint is and why it matters

An API (Application Programming Interface) is a way for your program to ask another program to do something. When that other program lives on the internet, you reach it at an endpoint: a web address (URL) that accepts requests and sends back answers. OpenAI's chat endpoint is https://api.openai.com/v1/chat/completions. You send it a request (which model you want, and the messages); it sends back the model's reply. This request-and-response style over the web is called a REST API, and almost everything today is built on it.

# Day 2 - The Chat Completions API, three ways
# 1) the raw HTTP endpoint, 2) the openai client library, 3) OpenAI-compatible
#    endpoints for other providers (Google Gemini and a local Ollama model).

import os
import requests
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv(override=True)
api_key = os.getenv("OPENAI_API_KEY")

# --- 1. Calling the raw HTTP endpoint directly ---------------------------------
# This is all the openai library does under the hood: an HTTPS POST with a JSON body.
headers = {"Authorization": f"Bearer {api_key}", "Content-Type": "application/json"}

payload = {
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "Tell me a fun fact"}],
}

response = requests.post(
    "https://api.openai.com/v1/chat/completions",
    headers=headers,
    json=payload,
)
print(response.json()["choices"][0]["message"]["content"])

# --- 2. The same call with the openai client library --------------------------
# The library is a thin wrapper around the call above - no model code lives in it.
openai = OpenAI()
response = openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Tell me a fun fact"}],
)
print(response.choices[0].message.content)

# --- 3. OpenAI-compatible endpoints -------------------------------------------
# Other providers copied OpenAI's endpoint shape, so the same client library works
# if you change base_url and api_key.

# Google Gemini (optional - needs GOOGLE_API_KEY in your .env)
GEMINI_BASE_URL = "https://generativelanguage.googleapis.com/v1beta/openai/"
google_api_key = os.getenv("GOOGLE_API_KEY")
if google_api_key:
    gemini = OpenAI(base_url=GEMINI_BASE_URL, api_key=google_api_key)
    response = gemini.chat.completions.create(
        model="gemini-2.0-flash",
        messages=[{"role": "user", "content": "Tell me a fun fact"}],
    )
    print(response.choices[0].message.content)

# Ollama, running on your own machine (free, no API key - the key is ignored)
# First run `ollama pull llama3.2` in a terminal.
OLLAMA_BASE_URL = "http://localhost:11434/v1"
ollama = OpenAI(base_url=OLLAMA_BASE_URL, api_key="ollama")
response = ollama.chat.completions.create(
    model="llama3.2",
    messages=[{"role": "user", "content": "Tell me a fun fact"}],
)
print(response.choices[0].message.content)

What does the openai library actually do?

It is a client library — a thin wrapper around the exact HTTP call you saw in part 1. It builds the headers, turns your arguments into JSON, sends the POST, and unpacks the JSON reply into an object. That is it. As the course stresses: it is open-source and lightweight, and "some people think it contains OpenAI model code — it doesn't!" The model runs on OpenAI's servers; the library just carries messages to and from it. The Python and JavaScript editions are the same idea in two languages.

What is an OpenAI-compatible endpoint?

Because OpenAI's Chat Completions API became the standard, other providers built endpoints that accept the same request shape and return the same response shape. These are called OpenAI-compatible endpoints. The benefit: you keep the one client library you already know and only change two things — the base URL (which server) and the key (which account). OpenAI even designed its library to allow this. So "OpenAI" appearing in your code does not mean an OpenAI model is running — the base URL decides that.

What is Ollama, and what is a local model?

Ollama is a free tool that runs open-source models directly on your computer. You download a model once with ollama pull, and Ollama serves it at http://localhost:11434. A "local model" means the model's weights live on your machine and all the thinking (inference) happens there — nothing is sent to the cloud. The upside is it is free and private; the downside is a laptop-sized model is far weaker than a frontier model like GPT. Under the hood Ollama uses optimized C++ so these models run acceptably without a giant server.

What you should see. Each of the three calls prints a short fun fact. The OpenAI and Gemini answers come back in a second or two; the first Ollama answer may be slower while the model loads into memory. The three replies will differ in wording — and will differ again every time you run them — because the models generate fresh text each call. (We did not run these calls on our machine, so we do not print a specific fact here; the exact wording depends on the model and the moment.)
Common mistakes.
  • Ollama not running. If the Ollama calls fail to connect, the server is not up. Open a terminal and run ollama serve, then check http://localhost:11434 says "Ollama is running".
  • Model not downloaded. Asking for llama3.2 before ollama pull llama3.2 gives a "model not found" error. Pull it first.
  • Wrong base URL. Forgetting the /v1 on http://localhost:11434/v1, or dropping the trailing /openai/ on the Gemini URL, sends your request to the wrong path and it fails. Copy the URLs exactly. In Python the option is base_url; in TypeScript it is baseURL — a common typo when switching languages.
  • Forgetting the dummy key. Ollama ignores the key, but the client library still requires one. Leave it out and you get an error about a missing API key. Any non-empty string works; the course uses "ollama".
  • Key not loaded. If OpenAI returns a 401, your .env was not loaded or the key is wrong. In Python re-run the cell after load_dotenv(override=True); in TypeScript make sure import "dotenv/config" is at the very top. Check the key starts with sk-proj-.
Video vs repo. Ed keeps the GitHub repo ahead of the recorded videos, so the model names differ. This guide shows the video's names because that is what you see on screen:
  • OpenAI model: the video uses gpt-4o-mini; the current repo uses gpt-6-luna with an extra reasoning_effort="none" argument.
  • Gemini model: the video era uses gemini-2.0-flash; the current repo uses gemini-3.1-flash-lite.
Treat a model name as a value you can swap. AI companies retire older models every few months, so if one stops working, pick a current model from that same company's line-up — the rest of the code does not change. The repo also pulls an optional second local model, deepseek-r1:1.5b (a distilled DeepSeek); try it the same way if you like, with ollama pull deepseek-r1:1.5b.

# Day 1 - Website Summarizer (the version shown in the video)
# A tiny "Reader's Digest of the internet": give it a URL, get back a short summary.

import os
import requests
from bs4 import BeautifulSoup
from dotenv import load_dotenv
from openai import OpenAI
from IPython.display import Markdown, display

# Load the OPENAI_API_KEY from your .env file into the environment
load_dotenv(override=True)
api_key = os.getenv("OPENAI_API_KEY")

if not api_key:
    print("No API key was found - check your .env file")
elif not api_key.startswith("sk-proj-"):
    print("An API key was found, but it doesn't start sk-proj- - please check it")
else:
    print("API key found and looks good so far!")

# Create the OpenAI client. With no arguments it reads OPENAI_API_KEY from the environment.
openai = OpenAI()

MODEL = "gpt-4o-mini"

# Some websites refuse a request that has no User-Agent header, so we send a normal browser one
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 "
                  "(KHTML, like Gecko) Chrome/117.0.0.0 Safari/537.36"
}


class Website:
    """A utility class to represent a website that we have scraped."""

    def __init__(self, url):
        self.url = url
        response = requests.get(url, headers=headers)
        soup = BeautifulSoup(response.content, "html.parser")
        self.title = soup.title.string if soup.title else "No title found"
        for irrelevant in soup.body(["script", "style", "img", "input"]):
            irrelevant.decompose()
        self.text = soup.body.get_text(separator="\n", strip=True)


# A system prompt tells the model what role to play and how to behave
system_prompt = """You are an assistant that analyzes the contents of a website \
and provides a short summary, ignoring text that might be navigation related. \
Respond in markdown."""


# A user prompt is the actual request. We build it from the scraped page.
def user_prompt_for(website):
    user_prompt = f"You are looking at a website titled {website.title}\n"
    user_prompt += "The contents of this website is as follows; \
please provide a short summary of this website in markdown. \
If it includes news or announcements, then summarize these too.\n\n"
    user_prompt += website.text
    return user_prompt


# The OpenAI API expects a list of messages, each with a role and content
def messages_for(website):
    return [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_prompt_for(website)},
    ]


def summarize(url):
    website = Website(url)
    response = openai.chat.completions.create(
        model=MODEL,
        messages=messages_for(website),
    )
    return response.choices[0].message.content


def display_summary(url):
    summary = summarize(url)
    display(Markdown(summary))


display_summary("https://edwarddonner.com")

// A tiny "Reader's Digest of the internet": give it a URL, get back a short summary.
import "dotenv/config";
import OpenAI from "openai";
import { fetchWebsite, type Website } from "./scrape.js";

// Check the key the same way the notebook does
const apiKey = process.env.OPENAI_API_KEY;
if (!apiKey) {
  console.log("No API key was found - check your .env file");
} else if (!apiKey.startsWith("sk-proj-")) {
  console.log("An API key was found, but it doesn't start sk-proj- - please check it");
} else {
  console.log("API key found and looks good so far!");
}

const MODEL = "gpt-4o-mini";

// A system prompt tells the model what role to play and how to behave
const systemPrompt =
  "You are an assistant that analyzes the contents of a website and provides a short " +
  "summary, ignoring text that might be navigation related. Respond in markdown.";

// A user prompt is the actual request. We build it from the scraped page.
function userPromptFor(site: Website): string {
  let prompt = `You are looking at a website titled ${site.title}\n`;
  prompt +=
    "The contents of this website is as follows; please provide a short summary of this " +
    "website in markdown. If it includes news or announcements, then summarize these too.\n\n";
  prompt += site.text;
  return prompt;
}

// The OpenAI API expects a list of messages, each with a role and content
function messagesFor(site: Website): OpenAI.ChatCompletionMessageParam[] {
  return [
    { role: "system", content: systemPrompt },
    { role: "user", content: userPromptFor(site) },
  ];
}

export async function summarize(url: string): Promise<string> {
  const openai = new OpenAI(); // reads OPENAI_API_KEY from the environment
  const site = await fetchWebsite(url);
  const response = await openai.chat.completions.create({
    model: MODEL,
    messages: messagesFor(site),
  });
  return response.choices[0]?.message.content ?? "";
}

// Shared website scraping, the TypeScript counterpart of the Python `Website` class.
// `parseWebsite` works on an HTML string (offline, testable); `fetchWebsite` adds the network fetch.
import { parse } from "node-html-parser";

// Some websites refuse a request that has no User-Agent header, so we send a normal browser one
export const headers = {
  "User-Agent":
    "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 " +
    "(KHTML, like Gecko) Chrome/117.0.0.0 Safari/537.36",
};

/** A scraped website: its title, its visible text, and the links it contains. */
export interface Website {
  url: string;
  title: string;
  text: string;
  links: string[];
}

// The tags whose content is noise for a summary (scripts, styles, images, form inputs).
const IRRELEVANT = ["script", "style", "img", "input"];

/** Parse an HTML string into a Website. Mirrors BeautifulSoup: strip noise tags, keep body text + links. */
export function parseWebsite(html: string, url: string): Website {
  const root = parse(html);

  const titleEl = root.querySelector("title");
  const title = titleEl ? titleEl.text.trim() : "No title found";

  const body = root.querySelector("body") ?? root;
  for (const tag of IRRELEVANT) {
    for (const el of body.querySelectorAll(tag)) el.remove();
  }
  const text = body.structuredText.trim();

  const links = root
    .querySelectorAll("a")
    .map((a) => a.getAttribute("href"))
    .filter((href): href is string => Boolean(href));

  return { url, title, text, links };
}

/** Fetch a URL and parse it. Uses the global fetch (Node 18+). */
export async function fetchWebsite(url: string): Promise<Website> {
  const response = await fetch(url, { headers });
  const html = await response.text();
  return parseWebsite(html, url);
}

/** Webpage Title + Contents, the string fed to the brochure model (Website.get_contents in Python). */
export function getContents(site: Website): string {
  return `Webpage Title:\n${site.title}\nWebpage Contents:\n${site.text}\n\n`;
}
Recap
  • The Chat Completions API means: send a list of messages, get the predicted next message back.
  • At bottom it is one HTTPS POST — headers with a Bearer key, a JSON body with model and messages — and a JSON reply you read from choices[0].message.content. Python sends it with requests.post; TypeScript sends it with fetch.
  • The openai client library (Python and JavaScript editions) is a thin wrapper around that POST. It holds no model code; the model runs on the provider's servers.
  • Other providers copied the API shape (OpenAI-compatible endpoints), so the same client reaches Google Gemini or a local Ollama model by changing only the base URL and the key.
  • Ollama runs open-source models like llama3.2 on your own machine — free and private, but less powerful than a frontier model.
