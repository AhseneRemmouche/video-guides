Week 4 · Project Build — The Code Optimizer, Step by Step

Build the Python-to-C++ code optimizer from scratch: a Gradio app in Python + uv, and a two-pane React app (paste Python, get optimized C++) with a Hono API in Node + TypeScript.

Build it yourself · Python + uv (Gradio) and React + Node + TypeScript

The five day-pages explain Week 4 one idea at a time. This page is different: it is a hands-on build. You will put the whole week's project together, in order, so that at the end you can paste a slow piece of Python, pick a model, and watch fast C++ stream back from a frontier model such as GPT-4o or Claude. This is the course's code-generation project: a model rewrites your Python as high-performance C++ that produces identical output in a fraction of the time.

As in the rest of the guide you build it in two stacks and pick whichever world you live in:

  • Track A is the course's own stack: uv-managed Python with a Gradio web UI. This is the code shown on the Day 3 page. The API-calling code is shown exactly as in the course; it was not run live in this guide.
  • Track B is the guide's extra port: React on the front end with a small Node server, written in TypeScript. The server is a tiny Hono API with one streaming endpoint. The finished code lives in the week4-ts/ folder, and the steps below match those files exactly. It type-checks and the web app builds; the model calls were not run live.

Both tracks do the same three things: send the Python plus a short instruction to a model, stream the C++ answer back token by token, and show it beside the original. Only the wrapper differs — a Gradio page in Python, a React two-pane page in TypeScript. Pick one track and follow it top to bottom; you do not need both.

Build it step by step

Run it locally (Python + uv)

The runnable Week 4 project lives in the week4-py/ folder and runs fully locally against Ollama, with no paid API keys. Install Ollama first, then:

ollama pull llama3.2
cd week4-py
UV_NATIVE_TLS=1 uv sync
uv run python src/optimize.py

It generates C++ from sample Python using local Ollama; actually compiling and timing that C++ needs a C++ compiler, so that step is only described in compile_note.py.

Track A - Python + uv (Gradio)

This track builds the optimizer as a Python script with a small Gradio web page on top. The full, explained code is on the Day 3 page; here we only list what to create and run, not re-explain every line. Each step tells you what to type and what you should see.

New to Gradio? What it is and why this track uses it Gradio is a Python library that turns a plain function into a web page with input and output boxes, with almost no front-end code. You give it a function that takes some text and returns (or streams) some text, and it draws a browser UI around it. The course uses it so you can paste Python on the left and watch C++ appear on the right without writing any HTML or JavaScript. Because the function can yield partial results, Gradio shows the C++ growing live as the model writes it.
  1. Create the project Make a fresh folder and let uv manage it. uv is the fast Python package manager the course uses instead of Anaconda: 
    uv init llm-week4
cd llm-week4
    You can also just work inside the course repo you cloned in Week 1; either way the commands below are the same.
  2. Add the libraries Add the two model SDKs, Gradio and the env loader. uv add installs each one and records it in pyproject.toml: 
    uv add openai anthropic gradio python-dotenv
    openai talks to GPT-4o, anthropic talks to Claude, gradio draws the web page, and python-dotenv loads your keys from a .env file.
  3. Set your API keys Create a .env file in the project root with the key(s) for the model(s) you want. The Anthropic key is optional if you only use GPT-4o: 
    OPENAI_API_KEY=sk-proj-...
ANTHROPIC_API_KEY=sk-ant-...
    .env is git-ignored; never commit it. Day 3's code checks that the keys exist and prints the first few characters so you can confirm they loaded.
  4. Write the prompts In your script, write the system and user prompts that tell the model exactly what to do. These are the real prompts from the lab: 
    system_prompt = """
Your task is to convert Python code into high performance C++ code.
Respond only with C++ code. Do not provide any explanation other than occasional comments.
The C++ response needs to produce an identical output in the fastest possible time.
"""
    The matching user_prompt_for(python) wraps the pasted Python in a fenced block and names the compile command, so the model tunes the C++ for it.
  5. Write the streaming optimize function Add the function the UI calls (it is shown as port(...) in the Day 3 notebook). It builds the two messages, calls the chosen model with stream=True, and yields the C++ as it arrives, stripping any stray ```cpp fences. Streaming is what makes the output grow live: 
    def optimize(python, model):
    stream = client.chat.completions.create(
        model=model,
        messages=messages_for(python),
        stream=True,
    )
    reply = ""
    for chunk in stream:
        reply += chunk.choices[0].delta.content or ""
        yield reply.replace("```cpp", "").replace("```", "")
    The full version, with the GPT and Claude clients wired up, is on the Day 3 page.
  6. Build the Gradio UI Wrap the function in a Gradio interface with a model dropdown, a Python input box and a C++ output box: 
    import gradio as gr

with gr.Blocks() as ui:
    with gr.Row():
        python = gr.Textbox(label="Python code", lines=12)
        cpp = gr.Textbox(label="C++ code", lines=12)
    model = gr.Dropdown(["GPT", "Claude"], label="Model", value="GPT")
    go = gr.Button("Optimize")
    go.click(optimize, inputs=[python, model], outputs=[cpp])

ui.launch()
    This is the two-box layout the course shows: Python on the left, C++ on the right, a dropdown to pick the model.
  7. Run it Start the app from inside the uv project: 
    uv run python app.py
    uv run runs the script inside the project's virtual environment without you activating it. Gradio prints a local URL (something like http://127.0.0.1:7860); open it, paste some slow Python, pick a model, and click Optimize.
  8. (Optional) Compile and time the C++ To prove the speedup, write the C++ to main.cpp, compile it with an optimising C++ compiler and time both versions. The lab uses clang++ with aggressive flags (for example -std=c++17 -Ofast -mcpu=native) and runs it through Python's subprocess. You need a C++ compiler installed for this step; it is not needed just to see the generated code.
What you should see. The script first prints that your API key(s) loaded. The Gradio page opens in the browser with two code boxes and a model dropdown. When you click Optimize, C++ streams into the right-hand box a few lines at a time. If you run the optional compile step, the C++ prints the same result as the Python but in a much shorter execution time.
Common mistakes. Forgetting the .env file (or putting it in the wrong folder) means the key check fails and the model call errors. Picking Claude without an ANTHROPIC_API_KEY set gives an authentication error — set that key or stick to GPT-4o. The optional compile step fails with a "command not found" error if no C++ compiler is installed; that does not stop you from generating and reading the C++.
Video vs repo. The current repo's day3.py adds a reasoning_effort parameter to the model call and uses newer model ids; the video-era code did not have it. The guide shows the video's simpler shape. Treat the model name as a value you may need to swap, since AI companies retire models. The big "13,000x speedup" headline is from Ed's experiment in the course video — attribute it to the course; we did not measure it here.

Track B - React + Node + TypeScript

This track rebuilds the optimizer as a small web app: a React two-pane page talks to a Node server written in TypeScript, and the server streams the C++ back from the model over one HTTP endpoint. The scripts run with tsx, the server is built with Hono, and the page is bundled by Vite. These are the real files in week4-ts/; the steps below match them exactly.

  1. Scaffold the project You need Node (version 18 or newer) first; check with node --version. Create the web app with Vite's React + TypeScript template, which brings in React, Vite and TypeScript: 
    npm create vite@latest week4-ts -- --template react-ts
cd week4-ts
    This project keeps its Vite app under a web/ folder and adds server/ and src/ beside it, all in one package (run npm init if you are assembling the folder by hand, and set "type": "module").
  2. Add the runtime libraries Add the two model SDKs, the server and the env loader. npm add installs them and records them in package.json: 
    npm add openai @anthropic-ai/sdk hono @hono/node-server dotenv
    openai talks to GPT-4o, @anthropic-ai/sdk is Anthropic's native SDK for Claude, hono + @hono/node-server are the web server, and dotenv loads the .env.
  3. Add the dev tool Add tsx so you can run a .ts file directly (React, Vite and TypeScript already came with the scaffold): 
    npm add -D tsx
    -D marks it as a development-only dependency.
  4. Create the core module Create src/optimize.ts. It exports optimizePython(python, model), an async generator that yields C++ chunks: for "gpt-4o" it calls openai.chat.completions.create({ ..., stream: true }) and yields each delta.content; for "claude" it uses anthropic.messages.stream(...) and yields each text delta. It holds the same system and user prompts as the Python lab, and a MissingKeyError so a missing key becomes a clear message. The full file is embedded on the Day 3 page.
  5. Create the Hono API Create server/index.ts. It builds a Hono app with one route, POST /api/optimize, that reads { python, model }, returns a 400 JSON error if the body or the needed key is missing, then uses Hono's streamText to loop over optimizePython(...) and write each chunk straight to the response. It also serves the built React app. Copy it from the Day 3 page and it listens on http://localhost:8788.
  6. Build the two-pane React UI Create web/src/App.tsx: a Python textarea on the left, a read-only C++ textarea on the right, a model dropdown (GPT-4o / Claude 3.5 Sonnet) and an Optimize button. The button fetches /api/optimize and reads the streamed response with a reader, appending each decoded chunk to the C++ box so it fills live. The full component is on the Day 3 page.
  7. Check the package scripts The commands above are wired in package.json. These are the real scripts in week4-ts/: 
    {
  "scripts": {
    "optimize": "tsx src/optimize.ts",
    "api": "tsx server/index.ts",
    "web": "vite --config web/vite.config.ts",
    "typecheck": "tsc --noEmit -p tsconfig.json",
    "build": "tsc --noEmit -p tsconfig.json && vite build --config web/vite.config.ts"
  }
}
    optimize runs the core module once from the command line, api starts the Hono server, web starts the Vite dev server, and build type-checks then bundles the app.
  8. Run the app You need two terminals: one for the API, one for the web server. In the first: 
    npm run api
    In the second: 
    npm run web
    Then open http://localhost:5173. Vite proxies /api to the server on port 8788, so the browser can call it. Paste some slow Python, pick a model, and click Optimize.
What you should see. npm run api prints LLM Engineering Week 4 API on http://localhost:8788. The page at http://localhost:5173 shows the two code panes, the model dropdown and the Optimize button. When you click it, C++ streams into the right-hand pane chunk by chunk. If a key is missing you get a clear red error instead of a crash.
Common mistakes. Starting only npm run web but not npm run api makes every request fail — both must be running. Forgetting the .env file, or the key for the model you picked, returns the 400 "key is not set" error. Editing .env while the server is running: restart npm run api so it reloads the keys.
Video vs repo. The real week4-ts/ project pins the video-era model ids (gpt-4o and claude-3-5-sonnet-20240620) for reproducible results. Because every OpenAI-compatible endpoint uses the same call shape, adding another provider later is just a new base URL and key, exactly as in Weeks 1 and 2.

What you built

In whichever track you chose, you now have the full Week 4 project: paste slow Python, pick a model, and get high-performance C++ streamed back. Track A runs the course's own stack — a uv-managed Python script wrapped in a Gradio page. Track B rebuilds the same optimizer as a React two-pane app with a Hono API, matching the real week4-ts/ files. The core move is identical in both: build the system and user prompts, call GPT-4o or Claude with streaming on, and show the C++ as it arrives. Only the wrapper around that function changed.

Recap
  • You built Week 4's code optimizer in two stacks: Python + uv with a Gradio UI (Track A) and React + Node + TypeScript with a Hono API (Track B).
  • Each track followed the same four stages: set up, add libraries, create files, run.
  • Track A: uv add openai anthropic gradio python-dotenv, set the keys in .env, write the system/user prompts and a streaming optimize(python, model) function, wrap it in a gr.Blocks UI with a model dropdown, and run uv run python app.py (optionally compile and time the C++ with clang++).
  • Track B matches the real week4-ts/ project: the Vite react-ts scaffold, npm add openai @anthropic-ai/sdk hono @hono/node-server dotenv and npm add -D tsx, then src/optimize.ts (streaming optimizePython), server/index.ts (Hono POST /api/optimize) and web/src/App.tsx (the two-pane UI), run with npm run api + npm run web.
  • The full line-by-line explanation of both the Python and TypeScript code is on the Day 3 page; the open-source code models and evaluation follow on Day 4.
