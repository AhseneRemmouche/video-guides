Week 4 · Project Build — The Code Optimizer, Step by Step

Build the Python-to-C++ code optimizer from scratch, in one of two tabs: a streaming Python + uv script that runs free on Ollama, or a two-pane React app (paste Python, get optimized C++) with a Hono API in Node + TypeScript. Every step shows its full code and why you do it.

Build it yourself · Python + uv or React + Node + TypeScript

The five day-pages explain Week 4 one idea at a time. This page is different: it is a hands-on build. You will put the whole week's project together, in order, so that at the end you can paste a slow piece of Python, pick a model, and watch fast C++ stream back from a frontier model such as GPT-4o or Claude. This is the course's code-generation project: a model rewrites your Python as high-performance C++ that produces identical output in a fraction of the time.

You can build it in either of two stacks. Choose one with the tabs in Build it step by step; each tab is complete on its own:

  • Python + uv: the guide's verified week4-py/ project, a streaming terminal script that sends slow Python to a model and prints the C++ as it arrives. It runs free against a local Ollama model, and the same code works with GPT-4o by changing three lines of .env.
  • React + Node + TypeScript: the guide's week4-ts/ project, the course's two-box UI rebuilt as a React page (Python on the left, C++ streaming in on the right, a GPT-4o / Claude dropdown) with a small Hono API that streams the answer.

Both do the same three things: send the Python plus an instruction to a model, stream the C++ answer back token by token, and clean off any stray markdown fences. Only the wrapper differs.

Build it step by step

Pick your stack with the tabs below. Each tab is a complete build from an empty folder in Visual Studio Code (no Jupyter notebook): every step shows the exact code to type or paste, and a Why that explains the reason for the step. The VS Code steps set up the editor, the Python environment or Node project, and one-key run and debug (F5). You never need another page to finish.

  10. Start src/optimize.py: settings and the client.

    Create src/optimize.py and add:

    """Week 4: Python -> C++ code optimizer, running against a local Ollama model.

This mirrors Ed Donner's LLM Engineering Week 4 "code optimizer": feed a slow
piece of Python to a model and ask it to rewrite it as fast C++. In the course
the C++ is then compiled and timed against the Python to measure a real speedup.
Here we only *generate* the C++ (see compile_note.py for why the compile+time
step is skipped on this machine).
"""

import os
import re
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv(override=True)

MODEL = os.getenv("OPTIMIZE_MODEL", "llama3.2:latest")
BASE_URL = os.getenv("OPENAI_BASE_URL", "http://localhost:11434/v1")
API_KEY = os.getenv("OPENAI_API_KEY", "ollama")

# Local Ollama speaks the OpenAI API at /v1. The api_key just has to be non-empty.
client = OpenAI(base_url=BASE_URL, api_key=API_KEY)

    load_dotenv(override=True) copies .env into the environment, and override=True makes the file win over an old value already set on your computer. Each setting uses os.getenv(name, default), so the script still runs against local Ollama even without a .env. One client is created at the top and reused by every call.

  11. Add the instruction and a deliberately slow sample. 
    SYSTEM_PROMPT = "Rewrite this Python in C++ for maximum speed; reply with only the C++ code."

# A deliberately slow sample: an O(n) Python loop summing numbers.
SAMPLE_PYTHON = """\
def sum_to(n):
    total = 0
    for i in range(1, n + 1):
        total += i
    return total

print(sum_to(100_000_000))
"""

    The system prompt is the whole job description: rewrite in C++, aim for speed, and reply with code only, so the answer can be saved straight to a file. The sample is a plain loop over 100 million numbers: slow in Python, trivial for compiled C++, which makes the speedup easy to see.

  12. Add strip_fences(): clean the model's answer. 
    def strip_fences(text: str) -> str:
    """Remove a leading ```cpp / ``` fence and a trailing ``` fence."""
    text = re.sub(r"^\s*```(?:cpp|c\+\+)?\s*\n", "", text)
    text = re.sub(r"\n?```\s*$", "", text)
    return text.strip()

    Even when told "only code", models usually wrap their answer in a ```cpp markdown fence. A C++ compiler would choke on those lines, so two regular expressions remove a leading fence (with or without the cpp/c++ tag) and a trailing one.

  13. Add optimize(): the streaming call. 
    def optimize(python_code: str, model: str = MODEL) -> str:
    """Stream a C++ rewrite of `python_code` from the local model and return it."""
    stream = client.chat.completions.create(
        model=model,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": python_code},
        ],
        stream=True,
    )
    chunks = []
    for chunk in stream:
        piece = chunk.choices[0].delta.content or ""
        print(piece, end="", flush=True)
        chunks.append(piece)
    print()
    return strip_fences("".join(chunks))

    This is the heart of the project. The messages are the instruction (system) and the Python to port (user). stream=True makes the API send the reply in small chunks; printing each delta.content with flush=True shows the C++ growing live, which is what the course's Gradio box shows. or "" handles chunks that carry no text (such as the final one). The pieces are joined and cleaned at the end so the caller gets compilable C++.

  14. Add the entry point. 
    if __name__ == "__main__":
    print(f"Model: {MODEL}  (via {BASE_URL})")

    print(SAMPLE_PYTHON)
    print("--- Streaming C++ from the model ---")

    The if __name__ == "__main__": guard runs the demo only when you start the file directly, so another script (or a Gradio UI) can import optimize() without triggering it. Printing the raw stream and then the cleaned C++ lets you see exactly what strip_fences() removed.

  15. Check your finished src/optimize.py against the complete file. 
    """Week 4: Python -> C++ code optimizer, running against a local Ollama model.

This mirrors Ed Donner's LLM Engineering Week 4 "code optimizer": feed a slow
piece of Python to a model and ask it to rewrite it as fast C++. In the course
the C++ is then compiled and timed against the Python to measure a real speedup.
Here we only *generate* the C++ (see compile_note.py for why the compile+time
step is skipped on this machine).
"""

import os
import re
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv(override=True)

MODEL = os.getenv("OPTIMIZE_MODEL", "llama3.2:latest")
BASE_URL = os.getenv("OPENAI_BASE_URL", "http://localhost:11434/v1")
API_KEY = os.getenv("OPENAI_API_KEY", "ollama")

# Local Ollama speaks the OpenAI API at /v1. The api_key just has to be non-empty.
client = OpenAI(base_url=BASE_URL, api_key=API_KEY)

SYSTEM_PROMPT = "Rewrite this Python in C++ for maximum speed; reply with only the C++ code."

# A deliberately slow sample: an O(n) Python loop summing numbers.
SAMPLE_PYTHON = """\
def sum_to(n):
    total = 0
    for i in range(1, n + 1):
        total += i
    return total

print(sum_to(100_000_000))
"""


def strip_fences(text: str) -> str:
    """Remove a leading ```cpp / ``` fence and a trailing ``` fence."""
    text = re.sub(r"^\s*```(?:cpp|c\+\+)?\s*\n", "", text)
    text = re.sub(r"\n?```\s*$", "", text)
    return text.strip()


def optimize(python_code: str, model: str = MODEL) -> str:
    """Stream a C++ rewrite of `python_code` from the local model and return it."""
    stream = client.chat.completions.create(
        model=model,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": python_code},
        ],
        stream=True,
    )
    chunks = []
    for chunk in stream:
        piece = chunk.choices[0].delta.content or ""
        print(piece, end="", flush=True)
        chunks.append(piece)
    print()
    return strip_fences("".join(chunks))


if __name__ == "__main__":
    print(f"Model: {MODEL}  (via {BASE_URL})")
    print("--- Python to optimize ---")
    print(SAMPLE_PYTHON)
    print("--- Streaming C++ from the model ---")
    cpp = optimize(SAMPLE_PYTHON)
    print("\n--- Cleaned C++ ---")
    print(cpp)

    Building it in parts helps you understand it; comparing with the complete file catches the small slips (an indent, a missing bracket in a regex) that would stop it running.

    • "isDefault": true makes Run the optimizer the default build task. Why: Ctrl+Shift+B (macOS Cmd+Shift+B) then runs uv run python src/optimize.py; the compiler check, ollama list and uv sync are in Terminal → Run Task….
    • "type": "debugpy" uses the Python Debugger with the interpreter you selected, so the .venv packages. Why: the debugger needs a real Python to start; uv run is a terminal command it cannot pause.
    • "cwd": "${workspaceFolder}" starts the program in the project folder. Why: when a debugger is attached, load_dotenv() (line 15) can look for .env starting from the current folder instead of the script's folder, so it finds your settings only if the program starts next to .env.
    • "envFile" loads .env into the debugged program. Why: the model, base URL and key are then set however the program is started; line 15 reads the same file with override=True, so the two never disagree.

  19. Add src/compile_note.py: check for a compiler. 
    """Explain the compile + time step that the course does but this machine can't.

In Ed Donner's Week 4, after the model generates C++ it is compiled and timed
against the Python to show a real speedup. That requires a C++ compiler
(g++ or clang++), which is NOT installed on this machine, so optimize.py only
generates the C++. This script prints the exact commands a reader would run
once a compiler is available.
"""

import shutil

COMPILERS = ["g++", "clang++"]


def main() -> None:
    print("=== Compile + time step (skipped here) ===\n")

    found = {name: shutil.which(name) for name in COMPILERS}
    available = {k: v for k, v in found.items() if v}

    if available:
        for name, path in available.items():
            print(f"Found {name}: {path}")
        print("\nA compiler is available, so you COULD compile and time the C++.")
    else:
        print("No C++ compiler found (checked: " + ", ".join(COMPILERS) + ").")
        print("That is why optimize.py only GENERATES C++ and does not compile or time it.")

    print("\nTo compile and run the generated C++ (save optimize.py output as optimized.cpp):\n")
    print("  # With g++ (install via MSYS2/MinGW-w64 on Windows, apt/brew elsewhere):")
    print("  g++ -O3 -std=c++17 -o optimized optimized.cpp")
    print("  ./optimized          # (Windows: optimized.exe)\n")
    print("  # Or with clang++:")
    print("  clang++ -O3 -std=c++17 -o optimized optimized.cpp")
    print("  ./optimized\n")
    print("Time both versions to compare, e.g. Python:")
    print("  python -c \"import time; ...\"   vs   the compiled C++ binary.")
    print("\nThe course typically sees large speedups (often 100x+) with GPT-4o/Claude-grade C++.")


if __name__ == "__main__":
    main()

  20. (Optional) Compile and time the C++.

    Save the cleaned C++ from step 17 as optimized.cpp, then, with a compiler installed:

    g++ -O3 -std=c++17 -o optimized optimized.cpp     # or: clang++ -O3 -std=c++17 -o optimized optimized.cpp

    Time it against the Python version (for example with time on macOS/Linux or Measure-Command in PowerShell). Both must print the same number.

  14. Add optimizePython(): stream from either model. 
    // --- the core: stream a C++ port of the given Python -------------------------
// Yields chunks of C++ as they arrive, mirroring the Gradio `yield` loop.
export async function* optimizePython(python: string, model: Model): AsyncGenerator<string> {
  if (!hasKeyFor(model)) throw new MissingKeyError(model);

  if (model === "gpt-4o") {
    const openai = new OpenAI(); // reads OPENAI_API_KEY
    const stream = await openai.chat.completions.create({
      model: GPT_MODEL,
      messages: [
        { role: "system", content: SYSTEM_PROMPT },
        { role: "user", content: userPromptFor(python) },
      ],
      stream: true,
    });
    for await (const chunk of stream) {
      const delta = chunk.choices[0]?.delta.content ?? "";
      if (delta) yield delta;
    }
  } else {
    const anthropic = new Anthropic(); // reads ANTHROPIC_API_KEY
    const stream = anthropic.messages.stream({
      model: CLAUDE_MODEL,
      max_tokens: 2000,
      system: SYSTEM_PROMPT,
      messages: [{ role: "user", content: userPromptFor(python) }],
    });
    for await (const event of stream) {
      if (
        event.type === "content_block_delta" &&
        event.delta.type === "text_delta"
      ) {
        yield event.delta.text;
      }
    }
  }
}

    It is an async generator (async function*): it yields each piece of C++ as it arrives, which is the TypeScript form of the Python for chunk in stream loop, and lets the server pass pieces on without waiting for the end. The two branches exist because the SDKs differ: OpenAI sends choices[0].delta.content, while Anthropic sends typed events, of which only content_block_delta / text_delta carry text. Anthropic also takes the system prompt as a separate system field and requires max_tokens.

  let out = "";
  for await (const chunk of optimizePython(python, model)) out += chunk;
  return stripCodeFences(out);
}

}

app.post("/api/optimize", async (c) => {
  const body = (await c.req.json().catch(() => ({}))) as {
    python?: unknown;
    model?: unknown;
  };

  const python = typeof body.python === "string" ? body.python : "";
  const model = parseModel(body.model);
  if (!python.trim()) return c.json({ error: "Body must include non-empty 'python'" }, 400);
  if (!model) return c.json({ error: "Body must include model 'gpt-4o' or 'claude'" }, 400);

  // Fail fast with a 400 when the key for the chosen model is missing, before streaming starts.
  const needsOpenAI = model === "gpt-4o";
  if (needsOpenAI && !process.env.OPENAI_API_KEY)
    return c.json({ error: "OPENAI_API_KEY is not set on the server" }, 400);
  if (!needsOpenAI && !process.env.ANTHROPIC_API_KEY)
    return c.json({ error: "ANTHROPIC_API_KEY is not set on the server" }, 400);

  return streamText(c, async (stream) => {
    try {
      for await (const chunk of optimizePython(python, model)) {
        await stream.write(chunk);
      }
    } catch (err) {
      // The stream has already started (200), so surface the error inline as a comment.
      const message = err instanceof MissingKeyError ? err.message : String(err);
      await stream.write(`\n// error: ${message}\n`);
    }
  });
});

  24. Build the two-pane UI: web/src/App.tsx. 
    // Week 4 code optimiser: the React replacement for the Gradio two-box UI (Day 3 / Day 4).
// Python on the left, generated C++ on the right, a model dropdown and an Optimize button.
// The C++ streams in from the Hono /api/optimize endpoint as the model produces it.
import { useState } from "react";

type Model = "gpt-4o" | "claude";

const SAMPLE_PYTHON = `import time

def calculate(iterations, param1, param2):
    result = 1.0
    for i in range(1, iterations+1):
        j = i * param1 - param2
        result -= (1/j)
        j = i * param1 + param2
        result += (1/j)
    return result

start_time = time.time()
result = calculate(100_000_000, 4, 1) * 4
end_time = time.time()

print(f"Result: {result:.12f}")
print(f"Execution Time: {(end_time - start_time):.6f} seconds")
`;

export function App() {
  const [python, setPython] = useState(SAMPLE_PYTHON);
  const [cpp, setCpp] = useState("");
  const [model, setModel] = useState<Model>("gpt-4o");
  const [busy, setBusy] = useState(false);
  const [error, setError] = useState("");

  async function optimize() {
    if (!python.trim() || busy) return;
    setBusy(true);
    setError("");
    setCpp("");

    try {
      const res = await fetch("/api/optimize", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ python, model }),
      });
      if (!res.ok) {
        const data = await res.json().catch(() => ({}));
        setError(data.error ?? "Request failed");
        return;
      }
      const reader = res.body?.getReader();
      const decoder = new TextDecoder();
      let text = "";
      while (reader) {
        const { value, done } = await reader.read();
        if (done) break;
        text += decoder.decode(value, { stream: true });
        setCpp(text);
      }
    } catch (e) {
      setError(String(e));
    } finally {
      setBusy(false);
    }
  }

  return (
    <main className="wrap">
      <header>
        <h1>LLM Engineering - Week 4</h1>
        <p className="sub">
          Rewrite slow Python as high-performance C++. Paste Python, pick a model, hit Optimize.
        </p>
      </header>

      <div className="toolbar">
        <label>
          Model
          <select value={model} onChange={(e) => setModel(e.target.value as Model)} disabled={busy}>
            <option value="gpt-4o">GPT-4o</option>
            <option value="claude">Claude 3.5 Sonnet</option>
          </select>
        </label>
        <button onClick={optimize} disabled={busy || !python.trim()}>
          {busy ? "Optimizing..." : "Optimize"}
        </button>
      </div>

      {error && <div className="error">{error}</div>}

      <div className="panes">
        <section className="pane">
          <div className="pane-head">Python</div>
          <textarea
            className="code"
            value={python}
            onChange={(e) => setPython(e.target.value)}
            spellCheck={false}
            placeholder="Paste the Python you want to speed up..."
          />
        </section>
        <section className="pane">
          <div className="pane-head">C++</div>
          <textarea
            className="code"
            value={cpp}
            readOnly
            spellCheck={false}
            placeholder="The generated C++ will stream in here."
          />
        </section>
      </div>
    </main>
  );
}
    • Lines 8–25, the sample. The same pi example as the CLI, pre-filled in the left pane. Why: you can click Optimize straight away without hunting for slow Python.
    • Lines 28–32, state. The Python, the C++, the chosen model, a busy flag and an error. Why: when any of these change, React redraws the page.
    • Lines 34–65, optimize(). Posts { python, model }; on an error status it shows the JSON message, otherwise it reads the body with getReader() and appends each decoded chunk to the C++ pane. Why: res.json() or res.text() would wait for the whole answer; reading the stream piece by piece is what makes the pane fill live. { stream: true } keeps a character that is split across two chunks intact.
    • Lines 67–114, the markup. Model dropdown, Optimize button, error box, and two textareas, the right one read-only. Why: it is the course's Gradio layout (Python left, C++ right, a model picker) in React.

    The page only knows the URL /api/optimize; it never sees a key or a model SDK, so it stays small and safe to serve to anyone.
