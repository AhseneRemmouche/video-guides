Build it yourself · Python + uv (training) and a React demo UI

The five day-pages explain Week 6 one idea at a time. This page is different: it is a hands-on build. You will put the whole week's project together, in order, so that at the end you have a model that reads a product description and estimates what the product costs - plus a small app to try it. This is the course's product pricer: you curate a large dataset of real products and prices, measure how well simple methods and off-the-shelf frontier models do, and then fine-tune a frontier model on your own examples so it learns to price items from their descriptions.

The data work and the training are Python jobs (pandas, scikit-learn and the fine-tuning API), managed with uv. The finished model is reached over the network with an API key, so the app that uses it can be written in anything. That makes this week's two tabs two stages, not two copies of the same program. New to fine-tuning? What it is and why this week uses it Most of the course prompts a general model: you send instructions and examples in each request. Fine-tuning is different - you give a provider a file of input/output examples and it trains a private copy of the model on them, returning a new model id. From then on the model has your examples baked in, so your prompts can be shorter and the answers more consistent for your narrow task. Here the task is pricing: each example is a product description (the input) paired with its real price (the wanted output). It is not always worth it - a big part of the week is measuring whether it beat the simpler methods.

  9. Write src/make_data.py: the product dataset.

    Create src/make_data.py with this complete file:

    """Generate a small synthetic product-pricing dataset.

This stands in for Ed Donner's Week 6 Amazon "items_full" dataset, which is far
too large to reproduce offline. Each row is a templated product "description"
mentioning a category, a brand and a size, and a price that is a (noisy)
function of those three features. We write train/test CSVs to data/.
"""

import os
import random

import numpy as np
import pandas as pd

HERE = os.path.dirname(os.path.abspath(__file__))
DATA_DIR = os.path.join(os.path.dirname(HERE), "data")

SEED = 42

# Each category has a base price. Brands and sizes are multipliers/addends.
CATEGORIES = {
    "laptop": 900.0,
    "headphones": 120.0,
    "coffee maker": 80.0,
    "office chair": 180.0,
    "backpack": 45.0,
    "smartphone": 650.0,
    "monitor": 220.0,
    "blender": 60.0,
}

# Brand quality multiplier (premium brands cost more).
BRANDS = {
    "Acme": 0.8,
    "Globex": 1.0,
    "Initech": 1.15,
    "Umbrella": 1.4,
    "Stark": 1.8,
}

# Size adds a flat amount (bigger/pro variants cost more).
SIZES = {
    "mini": -20.0,
    "standard": 0.0,
    "large": 40.0,
    "pro": 120.0,
}

TEMPLATES = [
    "{brand} {size} {category} in excellent condition, barely used.",
    "Brand new {brand} {category} ({size} model) with full warranty.",
    "{size} {category} by {brand}. Great value, ships fast.",
    "Refurbished {brand} {category}, {size} edition, works perfectly.",
    "{brand} {category} {size} - a reliable everyday choice for home or office.",
]


def make_row(rng: random.Random):
    category = rng.choice(list(CATEGORIES))
    brand = rng.choice(list(BRANDS))
    size = rng.choice(list(SIZES))
    template = rng.choice(TEMPLATES)

    description = template.format(brand=brand, size=size, category=category)

    base = CATEGORIES[category]
    price = base * BRANDS[brand] + SIZES[size]
    # Multiplicative + additive noise so the relationship is learnable but not exact.
    price *= rng.uniform(0.9, 1.1)
    price += rng.gauss(0, 8)
    price = max(5.0, round(price, 2))

    return {
        "description": description,
        "category": category,
        "brand": brand,
        "size": size,
        "price": price,
    }


def main():
    rng = random.Random(SEED)
    np.random.seed(SEED)

    n = 300
    rows = [make_row(rng) for _ in range(n)]
    df = pd.DataFrame(rows)

    # Shuffle and split 80/20 train/test.
    df = df.sample(frac=1.0, random_state=SEED).reset_index(drop=True)
    split = int(len(df) * 0.8)
    train_df = df.iloc[:split].reset_index(drop=True)
    test_df = df.iloc[split:].reset_index(drop=True)

    os.makedirs(DATA_DIR, exist_ok=True)
    train_path = os.path.join(DATA_DIR, "train.csv")
    test_path = os.path.join(DATA_DIR, "test.csv")
    train_df.to_csv(train_path, index=False)
    test_df.to_csv(test_path, index=False)

    print("Synthetic product dataset generated.")
    print(f"  total rows : {len(df)}")
    print(f"  train rows : {len(train_df)}  -> {train_path}")
    print(f"  test rows  : {len(test_df)}  -> {test_path}")
    print(f"  price range: ${df['price'].min():.2f} - ${df['price'].max():.2f}")
    print(f"  mean price : ${df['price'].mean():.2f}")
    print()
    print("Sample rows:")
    print(train_df.head(3).to_string(index=False))


if __name__ == "__main__":
    main()
    • Lines 15–18, paths and seed. DATA_DIR is worked out from the file's own location, so the script writes to week6-py/data/ whichever folder you run it from. Why: a fixed SEED makes every run produce the same dataset, so your numbers can be compared with the ones on this page.
    • Lines 20–55, the price recipe. Each category has a base price, each brand a multiplier and each size a flat add-on; five sentence templates turn them into descriptions. Why: the price really depends on words in the text, so a model that reads the description can learn it, just as with real product listings.
    • Lines 58–79, make_row(). Picks a category, brand, size and template, builds the description and computes the price with random noise on top. Why: without noise the price would be an exact formula; the noise makes it learnable but not perfectly predictable, like real prices.
    • Lines 82–110, main(). Makes 300 rows, shuffles them, keeps 80% for training and 20% for testing, and writes train.csv and test.csv. Why: every model is scored on test items it never saw while training; scoring on training items would make any model look better than it is.

    The course curates a large real dataset of Amazon products (Days 1 and 2). That is far too big to download for a first build, so this script makes a small dataset with the same shape: a text description and a price. Every later script reads these two CSV files, so they all work on exactly the same items.

    """Traditional ML baselines for the synthetic product pricer.

Mirrors Ed Donner's Week 6 "day 3" baselines:
  - a constant predictor (always predict the training mean),
  - a CountVectorizer + LinearRegression over the description text,
  - a RandomForestRegressor over the same bag-of-words features.

Each model is scored on the held-out test set with Average Absolute Error
(mean |predicted - actual| in dollars), the same spirit as the course's metric.
Results are printed as a small leaderboard and also saved to data/baseline_preds.csv
so frontier_eval.py can print the local LLM number next to these.
"""

import os

import numpy as np
import pandas as pd
from sklearn.ensemble import RandomForestRegressor
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.linear_model import LinearRegression

HERE = os.path.dirname(os.path.abspath(__file__))
DATA_DIR = os.path.join(os.path.dirname(HERE), "data")

SEED = 42


def average_absolute_error(y_true, y_pred):
    return float(np.mean(np.abs(np.asarray(y_pred) - np.asarray(y_true))))


def load_data():
    train = pd.read_csv(os.path.join(DATA_DIR, "train.csv"))
    test = pd.read_csv(os.path.join(DATA_DIR, "test.csv"))
    return train, test

    average_absolute_error is the score used everywhere this week: the average of how many dollars each guess was off. It is easy to explain ("on average we are $35 out") and the same function scores every model, so the comparison is fair. load_data() reads the two CSV files from step 11.

  13. Add the first baseline: always guess the average price. 
    def main():
    train, test = load_data()
    print(f"Loaded {len(train)} train / {len(test)} test items\n")

    y_train = train["price"].to_numpy()
    y_test = test["price"].to_numpy()

    results = []  # (name, avg_abs_error)

    # --- Baseline 1: constant (mean) predictor -------------------------------
    mean_price = float(np.mean(y_train))
    const_pred = np.full(len(test), mean_price)
    results.append(("Constant (mean) predictor", average_absolute_error(y_test, const_pred)))

    The silliest possible model predicts the training mean for every item. Any model worth using must beat it by a lot. It gives you a floor, so you can tell whether the later numbers are actually good or only look good.

  14. Add the two text models: bag-of-words with linear regression and a random forest. 
        # --- Baseline 2: CountVectorizer + LinearRegression ----------------------
    np.random.seed(SEED)
    vectorizer = CountVectorizer(max_features=2000, stop_words="english")
    X_train = vectorizer.fit_transform(train["description"])
    X_test = vectorizer.transform(test["description"])

    lin = LinearRegression()
    lin.fit(X_train, y_train)
    lin_pred = np.maximum(lin.predict(X_test), 0)
    results.append(("CountVectorizer + LinearRegression", average_absolute_error(y_test, lin_pred)))

    # --- Baseline 3: RandomForestRegressor -----------------------------------
    rf = RandomForestRegressor(n_estimators=200, random_state=SEED, n_jobs=-1)
    rf.fit(X_train, y_train)
    rf_pred = np.maximum(rf.predict(X_test), 0)
    results.append(("RandomForestRegressor (bag-of-words)", average_absolute_error(y_test, rf_pred)))

    A CountVectorizer turns each description into word counts (bag-of-words): it learns the vocabulary from the training text only (fit_transform) and reuses it for the test text (transform). A linear regression then gives each word a dollar weight; a random forest can also learn combinations such as "Stark" together with "laptop". np.maximum(..., 0) stops a model predicting a negative price.

    """Traditional ML baselines for the synthetic product pricer.

Mirrors Ed Donner's Week 6 "day 3" baselines:
  - a constant predictor (always predict the training mean),
  - a CountVectorizer + LinearRegression over the description text,
  - a RandomForestRegressor over the same bag-of-words features.

Each model is scored on the held-out test set with Average Absolute Error
(mean |predicted - actual| in dollars), the same spirit as the course's metric.
Results are printed as a small leaderboard and also saved to data/baseline_preds.csv
so frontier_eval.py can print the local LLM number next to these.
"""

import os

import numpy as np
import pandas as pd
from sklearn.ensemble import RandomForestRegressor
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.linear_model import LinearRegression

HERE = os.path.dirname(os.path.abspath(__file__))
DATA_DIR = os.path.join(os.path.dirname(HERE), "data")

SEED = 42


def average_absolute_error(y_true, y_pred):
    return float(np.mean(np.abs(np.asarray(y_pred) - np.asarray(y_true))))


def load_data():
    train = pd.read_csv(os.path.join(DATA_DIR, "train.csv"))
    test = pd.read_csv(os.path.join(DATA_DIR, "test.csv"))
    return train, test


def main():
    train, test = load_data()
    print(f"Loaded {len(train)} train / {len(test)} test items\n")

    y_train = train["price"].to_numpy()
    y_test = test["price"].to_numpy()

    results = []  # (name, avg_abs_error)

    # --- Baseline 1: constant (mean) predictor -------------------------------
    mean_price = float(np.mean(y_train))
    const_pred = np.full(len(test), mean_price)
    results.append(("Constant (mean) predictor", average_absolute_error(y_test, const_pred)))

    # --- Baseline 2: CountVectorizer + LinearRegression ----------------------
    np.random.seed(SEED)
    vectorizer = CountVectorizer(max_features=2000, stop_words="english")
    X_train = vectorizer.fit_transform(train["description"])
    X_test = vectorizer.transform(test["description"])

    lin = LinearRegression()
    lin.fit(X_train, y_train)
    lin_pred = np.maximum(lin.predict(X_test), 0)
    results.append(("CountVectorizer + LinearRegression", average_absolute_error(y_test, lin_pred)))

    # --- Baseline 3: RandomForestRegressor -----------------------------------
    rf = RandomForestRegressor(n_estimators=200, random_state=SEED, n_jobs=-1)
    rf.fit(X_train, y_train)
    rf_pred = np.maximum(rf.predict(X_test), 0)
    results.append(("RandomForestRegressor (bag-of-words)", average_absolute_error(y_test, rf_pred)))

    # --- Leaderboard ---------------------------------------------------------
    results.sort(key=lambda r: r[1])
    print("Baseline leaderboard (Average Absolute Error, lower is better):")
    print("-" * 56)
    for name, err in results:
        print(f"  ${err:8.2f}   {name}")
    print("-" * 56)
    print(f"  (training mean price = ${mean_price:.2f})")

    # Persist test predictions + errors so frontier_eval can line up with these.
    out = pd.DataFrame(
        {
            "description": test["description"],
            "actual": y_test,
            "const_pred": const_pred,
            "linreg_pred": lin_pred,
            "rf_pred": rf_pred,
        }
    )
    out_path = os.path.join(DATA_DIR, "baseline_preds.csv")
    out.to_csv(out_path, index=False)

    summary = pd.DataFrame(results, columns=["model", "avg_abs_error"])
    summary.to_csv(os.path.join(DATA_DIR, "baseline_scores.csv"), index=False)
    print(f"\nSaved per-item predictions -> {out_path}")

def parse_price(text: str) -> float:
    """Pull the first number out of the model's reply."""
    if text is None:
        return 0.0
    cleaned = text.replace(",", "").replace("$", "")
    match = re.search(r"\d+(?:\.\d+)?", cleaned)

def llm_price(description: str) -> float:

// Pull the first number out of a reply like "The price is $19.99" or "$1,234.50".
// Strips currency symbols and thousands separators; returns NaN if there is no number.
export function parsePrice(text: string): number {
  // Remove commas used as thousands separators (1,234.50 -> 1234.50).
  const cleaned = text.replace(/,/g, "");
  // First run of digits with an optional decimal part.
  const match = cleaned.match(/-?\d+(?:\.\d+)?/);

  14. Add estimatePrice(): the model call. 
    // --- the core: estimate a price for a product description --------------------
export async function estimatePrice(description: string): Promise<number> {
  if (!process.env.OPENAI_API_KEY) throw new MissingKeyError();

  const openai = new OpenAI(); // reads OPENAI_API_KEY
  const completion = await openai.chat.completions.create({
    model: priceModel(),
    messages: [
      { role: "system", content: SYSTEM_PROMPT },
      { role: "user", content: userPromptFor(description) },
    ],
    // Low ceiling: we only want a number back, not an essay.
    max_tokens: 12,
    temperature: 0,
  });

  const reply = completion.choices[0]?.message.content ?? "";
  return parsePrice(reply);
}

    It checks the key first, then sends the system prompt and the description to the chat completions API. max_tokens: 12 is enough for a price and nothing else, and temperature: 0 makes the same description give the same price each time. Creating the client inside the function means importing this file never fails just because the key is missing.

    // The API behind the React product-pricer page (Week 6, served over HTTP).
//   POST /api/price  {description}  -> {price}
// Reads OPENAI_API_KEY from the environment; with the key missing it returns a
// clear 400 JSON error instead of crashing.
import "dotenv/config";
import { Hono } from "hono";
import { serve } from "@hono/node-server";
import { serveStatic } from "@hono/node-server/serve-static";
import { estimatePrice, priceModel } from "../src/price.js";

const app = new Hono();

app.post("/api/price", async (c) => {
  const body = (await c.req.json().catch(() => ({}))) as { description?: unknown };
  const description = typeof body.description === "string" ? body.description : "";
  if (!description.trim())
    return c.json({ error: "Body must include non-empty 'description'" }, 400);

  // Fail fast with a 400 when the key is missing, before we try to call OpenAI.
  if (!process.env.OPENAI_API_KEY)
    return c.json({ error: "OPENAI_API_KEY is not set on the server" }, 400);

  try {
    const price = await estimatePrice(description);
    if (!Number.isFinite(price))
      return c.json({ error: "Could not parse a price from the model reply" }, 502);
    return c.json({ price, model: priceModel() });
  } catch (err) {
    return c.json({ error: String(err) }, 500);
  }
});

// Serve the built React app (run `npm run build` first).
app.use("/*", serveStatic({ root: "./web/dist" }));

const port = Number(process.env.PORT ?? 8788);
serve({ fetch: app.fetch, port });
console.log(`LLM Engineering Week 6 API on http://localhost:${port}`);
    • Lines 13–17, read and check the body. Anything that is not a non-empty description string gets a 400. Why: anything can be sent to a server, so the input is checked before it reaches the model.
    • Lines 19–21, the key check. Why: with no key you get a clear JSON error ("OPENAI_API_KEY is not set on the server") instead of a crash.
    • Lines 23–30, call the model. Returns { price, model }, a 502 if no number could be read from the reply, or a 500 on any other error. Why: returning the model name lets you confirm the page really used your fine-tuned id.
    • Lines 33–38, static files and the port. Why: after npm run build one server delivers both the page and the API, on port 8788 unless PORT is set.

    // Week 6 product pricer: paste a product description, get an estimated price.
// The React front end posts the description to the Hono /api/price endpoint and
// shows the returned dollar amount, big.
import { useState } from "react";

const SAMPLE_DESCRIPTION =
  "Quadcast USB condenser microphone with tap-to-mute sensor, built-in " +
  "anti-vibration shock mount, and RGB lighting. Ideal for streaming, " +
  "podcasting, and gaming.";

function formatPrice(value: number): string {
  return value.toLocaleString("en-US", {
    style: "currency",
    currency: "USD",
    minimumFractionDigits: 2,
    maximumFractionDigits: 2,
  });
}

export function App() {
  const [description, setDescription] = useState(SAMPLE_DESCRIPTION);
  const [price, setPrice] = useState<number | null>(null);
  const [busy, setBusy] = useState(false);
  const [error, setError] = useState("");

  async function estimate() {
    if (!description.trim() || busy) return;
    setBusy(true);
    setError("");
    setPrice(null);

    try {
      const res = await fetch("/api/price", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ description }),
      });
      const data = await res.json().catch(() => ({}));
      if (!res.ok) {
        setError(data.error ?? "Request failed");
        return;
      }
      setPrice(typeof data.price === "number" ? data.price : null);
    } catch (e) {
      setError(String(e));
    } finally {
      setBusy(false);
    }
  }

  return (
    <main className="wrap">
      <header>
        <h1>LLM Engineering - Week 6</h1>
        <p className="sub">
          The product pricer. Describe an item and a fine-tuned model estimates
          what it costs.
        </p>
      </header>

      <section className="card">
        <label className="field">
          Product description
          <textarea
            value={description}
            onChange={(e) => setDescription(e.target.value)}
            spellCheck={false}
            rows={6}
            placeholder="Describe the product you want a price for..."
          />
        </label>

        <button onClick={estimate} disabled={busy || !description.trim()}>
          {busy ? "Estimating..." : "Estimate price"}
        </button>

        {error && <div className="error">{error}</div>}

        {price !== null && (
          <div className="result">
            <div className="result-label">Estimated price</div>
            <div className="result-price">{formatPrice(price)}</div>
          </div>
        )}
      </section>
    </main>
  );
}
