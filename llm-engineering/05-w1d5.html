Week 1 · Day 5 — The Business Brochure Project

Combine two LLM calls into a workflow: one picks the relevant links on a company site, the next writes a streamed markdown brochure - a first taste of agentic design.

Companion to Ed Donner's course · uv setup · Python + TypeScript/React · code verified against the repo

This is the finale of Week 1. All week you summarised a single web page with one call to the OpenAI API. Today you build a small commercial tool on top of that idea: give it a company name and the address of their website, and it writes a marketing brochure you could hand to a prospective client, an investor, or someone you want to hire. The trick is that the tool makes two calls to the model instead of one, and chaining those calls together is your first taste of what the course calls agentic design.

As on the other days, the lab is shown in both languages. The original course is in Python; this guide also ships a line-for-line TypeScript port. Use the Code in: switch at the top of the page (or the Python | TypeScript tabs on each code card) to pick a language; the whole page follows your choice. The two programs do exactly the same thing in the same order, so you can read either one.

The business challenge, in the instructor's words, is to "create a product that builds a brochure for a company." A brochure should not be built from the home page alone. Real information lives on the About, Careers and Company pages. So the job splits naturally into two steps. Step one: look at every link on the landing page and decide which ones are worth reading. Step two: fetch those pages, hand all the text to the model, and ask it to write the brochure. Step one is surprisingly hard to do with ordinary code (which link is "relevant"? how do you turn /about into a full address?), but it is exactly the kind of nuanced judgement a frontier model is good at. So we hand that judgement to the model too.

The concepts the instructor introduces

Four ideas carry the day. One-shot prompting: when you ask the model for step one, you include a single worked example of the answer you want. Zero examples is "zero-shot", one example is "one-shot", several examples is "multi-shot". JSON mode: you ask OpenAI to guarantee the reply is a valid JSON object, so your code can read it with a parser instead of guessing where the data is inside a paragraph of prose. Streaming: instead of waiting for the whole brochure and then showing it, you let the words flow back a few at a time, the way the chat apps do. And tone through the system prompt: changing a single sentence in the system prompt turns a formal brochure into a funny one, without touching any other code.

New to one-shot and multi-shot prompting? What they are and why they matter

A prompt is the text you send the model. "Shots" means worked examples you put inside that text to show the model the shape of answer you want.

  • Zero-shot: just the instruction, no example. "Pick the relevant links and reply in JSON."
  • One-shot: the instruction plus one example answer. That is what today's first call does — it shows one tiny JSON object with an about page and a careers page.
  • Multi-shot: the instruction plus several examples. More examples usually make the reply more reliable and more consistent, because the model has more evidence of exactly what you mean.

The instructor's end-of-day challenge is to upgrade step one to multi-shot by adding a second and third example. You do not change any code to do it — you only add more examples to the prompt text.

New to JSON mode (structured output)? What it is and why it matters

JSON is a plain-text way to write data: objects in { }, lists in [ ], keys and string values in quotes. A model normally replies in free prose, which is hard for code to read reliably. Passing response_format={"type": "json_object"} (Python) or response_format: { type: "json_object" } (TypeScript) switches on JSON mode: OpenAI then guarantees the reply is one valid JSON object, so json.loads(...) / JSON.parse(...) always works.

Two things to remember. First, you must also say "respond in JSON" in your prompt — OpenAI's own documentation says JSON mode only works if the prompt mentions JSON too. Second, this is the simple version; the course later teaches a stricter technique called structured outputs that forces an exact shape, used in the Week 8 agent project. Note too that this option is an OpenAI feature; other providers such as Claude do not offer this exact parameter.

New to streaming? What it is and why it matters

By default a chat call waits until the model has finished, then hands you the whole answer at once. With streaming you instead receive the answer in small pieces, called chunks, as they are generated. You add stream=True (Python) or stream: true (TypeScript) to the call; the result is no longer a finished response but something you loop over. Each chunk carries a little bit of new text in delta.content. You keep adding those pieces to a running string, which produces the familiar "typewriter" effect. It does not make the model faster — it just lets the reader start reading sooner.

What does "agentic" mean here? A gentle first look

An agentic program is one that breaks a big task into smaller steps and uses the model more than once, often letting the output of one call decide what the next call does. Today's tool is a tiny, "toy" example: call one decides which pages to read, and that decision shapes the text that call two turns into a brochure. The instructor is explicit that this is only a flavour of the idea — real agent frameworks come back in a big way in Week 8, with a preview in Week 2. You are not building an autonomous agent today; you are seeing the seed of one.

# Day 5 - The company brochure (the version shown in the video)
# Two LLM calls: first pick the relevant links on a site, then write a brochure
# from those pages. This is a first taste of an "agentic" multi-step workflow.

import os
import json
import requests
from bs4 import BeautifulSoup
from dotenv import load_dotenv
from openai import OpenAI
from IPython.display import Markdown, display, update_display

load_dotenv(override=True)
openai = OpenAI()
MODEL = "gpt-4o-mini"

headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 "
                  "(KHTML, like Gecko) Chrome/117.0.0.0 Safari/537.36"
}


class Website:
    """A scraped website: its title, text, and the links it contains."""

    def __init__(self, url):
        self.url = url
        response = requests.get(url, headers=headers)
        self.body = response.content
        soup = BeautifulSoup(self.body, "html.parser")
        self.title = soup.title.string if soup.title else "No title found"
        if soup.body:
            for irrelevant in soup.body(["script", "style", "img", "input"]):
                irrelevant.decompose()
            self.text = soup.body.get_text(separator="\n", strip=True)
        else:
            self.text = ""
        links = [link.get("href") for link in soup.find_all("a")]
        self.links = [link for link in links if link]

    def get_contents(self):
        return f"Webpage Title:\n{self.title}\nWebpage Contents:\n{self.text}\n\n"


# --- Step 1: ask the model which links matter, answering in strict JSON ---------
link_system_prompt = """You are provided with a list of links found on a webpage. \
You are able to decide which of the links would be most relevant to include in a \
brochure about the company, such as links to an About page, or a Company page, or \
Careers/Jobs pages.
You should respond in JSON as in this example:
{
    "links": [
        {"type": "about page", "url": "https://full.url/goes/here/about"},
        {"type": "careers page", "url": "https://another.full.url/careers"}
    ]
}"""


def get_links_user_prompt(website):
    user_prompt = f"Here is the list of links on the website of {website.url} - "
    user_prompt += "please decide which of these are relevant web links for a brochure \
about the company, respond with the full https URL in JSON format. \
Do not include Terms of Service, Privacy, email links.\n"
    user_prompt += "Links (some might be relative links):\n"
    user_prompt += "\n".join(website.links)
    return user_prompt


def get_links(url):
    website = Website(url)
    response = openai.chat.completions.create(
        model=MODEL,
        messages=[
            {"role": "system", "content": link_system_prompt},
            {"role": "user", "content": get_links_user_prompt(website)},
        ],
        response_format={"type": "json_object"},
    )
    result = response.choices[0].message.content
    return json.loads(result)


# --- Step 2: gather those pages and write the brochure --------------------------
def get_all_details(url):
    result = "Landing page:\n"
    result += Website(url).get_contents()
    links = get_links(url)
    for link in links["links"]:
        result += f"\n\n{link['type']}\n"
        result += Website(link["url"]).get_contents()
    return result


brochure_system_prompt = """You are an assistant that analyzes the contents of \
several relevant pages from a company website and creates a short brochure about \
the company for prospective customers, investors and recruits. Respond in markdown. \
Include details of company culture, customers and careers/jobs if you have the information."""


def get_brochure_user_prompt(company_name, url):
    user_prompt = f"You are looking at a company called: {company_name}\n"
    user_prompt += "Here are the contents of its landing page and other relevant pages; \
use this information to build a short brochure of the company in markdown.\n"
    user_prompt += get_all_details(url)
    user_prompt = user_prompt[:5_000]  # keep within a sensible token budget
    return user_prompt


def stream_brochure(company_name, url):
    stream = openai.chat.completions.create(
        model=MODEL,
        messages=[
            {"role": "system", "content": brochure_system_prompt},
            {"role": "user", "content": get_brochure_user_prompt(company_name, url)},
        ],
        stream=True,
    )
    response = ""
    display_handle = display(Markdown(""), display_id=True)
    for chunk in stream:
        response += chunk.choices[0].delta.content or ""
        update_display(Markdown(response), display_id=display_handle.display_id)


stream_brochure("HuggingFace", "https://huggingface.co")

// Two LLM calls: first pick the relevant links on a site, then write a brochure
// from those pages. This is a first taste of an "agentic" multi-step workflow.
import "dotenv/config";
import OpenAI from "openai";
import { fetchWebsite, getContents } from "./scrape.js";

const openai = new OpenAI();
const MODEL = "gpt-4o-mini";

interface RelevantLink {
  type: string;
  url: string;
}
interface RelevantLinks {
  links: RelevantLink[];
}

// --- Step 1: ask the model which links matter, answering in strict JSON --------
const linkSystemPrompt = `You are provided with a list of links found on a webpage. \
You are able to decide which of the links would be most relevant to include in a \
brochure about the company, such as links to an About page, or a Company page, or \
Careers/Jobs pages.
You should respond in JSON as in this example:
{
    "links": [
        {"type": "about page", "url": "https://full.url/goes/here/about"},
        {"type": "careers page", "url": "https://another.full.url/careers"}
    ]
}`;

function getLinksUserPrompt(url: string, links: string[]): string {
  let prompt = `Here is the list of links on the website of ${url} - `;
  prompt +=
    "please decide which of these are relevant web links for a brochure about the company, " +
    "respond with the full https URL in JSON format. " +
    "Do not include Terms of Service, Privacy, email links.\n";
  prompt += "Links (some might be relative links):\n";
  prompt += links.join("\n");
  return prompt;
}

async function getLinks(url: string): Promise<RelevantLinks> {
  const site = await fetchWebsite(url);
  const response = await openai.chat.completions.create({
    model: MODEL,
    messages: [
      { role: "system", content: linkSystemPrompt },
      { role: "user", content: getLinksUserPrompt(site.url, site.links) },
    ],
    response_format: { type: "json_object" },
  });
  return JSON.parse(response.choices[0]?.message.content ?? "{}") as RelevantLinks;
}

// --- Step 2: gather those pages and write the brochure -------------------------
async function getAllDetails(url: string): Promise<string> {
  let result = "Landing page:\n";
  result += getContents(await fetchWebsite(url));
  const { links } = await getLinks(url);
  for (const link of links) {
    result += `\n\n${link.type}\n`;
    result += getContents(await fetchWebsite(link.url));
  }
  return result;
}

const brochureSystemPrompt =
  "You are an assistant that analyzes the contents of several relevant pages from a company " +
  "website and creates a short brochure about the company for prospective customers, investors " +
  "and recruits. Respond in markdown. Include details of company culture, customers and " +
  "careers/jobs if you have the information.";

async function getBrochureUserPrompt(companyName: string, url: string): Promise<string> {
  let prompt = `You are looking at a company called: ${companyName}\n`;
  prompt +=
    "Here are the contents of its landing page and other relevant pages; " +
    "use this information to build a short brochure of the company in markdown.\n";
  prompt += await getAllDetails(url);
  return prompt.slice(0, 5_000); // keep within a sensible token budget
}

export async function streamBrochure(companyName: string, url: string): Promise<void> {
  const stream = await openai.chat.completions.create({
    model: MODEL,
    messages: [
      { role: "system", content: brochureSystemPrompt },
      { role: "user", content: await getBrochureUserPrompt(companyName, url) },
    ],
    stream: true,
  });
  for await (const chunk of stream) {
    process.stdout.write(chunk.choices[0]?.delta.content ?? "");
  }
  process.stdout.write("\n");
}

const url = process.argv[3] ?? "https://huggingface.co";

// Shared website scraping, the TypeScript counterpart of the Python `Website` class.
// `parseWebsite` works on an HTML string (offline, testable); `fetchWebsite` adds the network fetch.
import { parse } from "node-html-parser";

// Some websites refuse a request that has no User-Agent header, so we send a normal browser one
export const headers = {
  "User-Agent":
    "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 " +
    "(KHTML, like Gecko) Chrome/117.0.0.0 Safari/537.36",
};

/** A scraped website: its title, its visible text, and the links it contains. */
export interface Website {
  url: string;
  title: string;
  text: string;
  links: string[];
}

// The tags whose content is noise for a summary (scripts, styles, images, form inputs).
const IRRELEVANT = ["script", "style", "img", "input"];

/** Parse an HTML string into a Website. Mirrors BeautifulSoup: strip noise tags, keep body text + links. */
export function parseWebsite(html: string, url: string): Website {
  const root = parse(html);

  const titleEl = root.querySelector("title");
  const title = titleEl ? titleEl.text.trim() : "No title found";

  const body = root.querySelector("body") ?? root;
  for (const tag of IRRELEVANT) {
    for (const el of body.querySelectorAll(tag)) el.remove();
  }
  const text = body.structuredText.trim();

  const links = root
    .querySelectorAll("a")
    .map((a) => a.getAttribute("href"))
    .filter((href): href is string => Boolean(href));

  return { url, title, text, links };
}

/** Fetch a URL and parse it. Uses the global fetch (Node 18+). */
export async function fetchWebsite(url: string): Promise<Website> {
  const response = await fetch(url, { headers });
  const html = await response.text();
  return parseWebsite(html, url);
}

/** Webpage Title + Contents, the string fed to the brochure model (Website.get_contents in Python). */
export function getContents(site: Website): string {
  return `Webpage Title:\n${site.title}\nWebpage Contents:\n${site.text}\n\n`;
}

Making it live: streaming

The first working version of step two simply collected the whole reply and showed it in one go. To get the typewriter effect you make one change: turn streaming on and loop over the result. In Python, if you only wanted plain text, the loop can be as short as this:

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")

The end="" stops Python adding a line break after each piece, so the text flows. The notebook code is a little longer only because it re-renders Markdown nicely instead of printing raw text. The TypeScript script already does the plain-text version: it writes each chunk straight to the terminal with process.stdout.write(...), which is why its loop is so short.

Changing the tone with one line

Because the system prompt sets not just the task but the voice, you can get a completely different brochure by swapping that one string for a humorous variant and re-running. In Python:

brochure_system_prompt = """You are an assistant that analyzes the contents of \
several relevant pages from a company website and creates a short, humorous, \
entertaining, jokey brochure about the company for prospective customers, \
investors and recruits. Respond in markdown. \
Include details of company culture, customers and careers/jobs if you have the information."""

In TypeScript it is the same single-string change to brochureSystemPrompt. Nothing else changes. The instructor suggests going further for practice: make it snarky, or ask for the brochure in Spanish. This is the quickest possible lesson in how much the system prompt shapes the result.

What you should see

Step one prints a small JSON object, something like:

{
  "links": [
    {"type": "about page", "url": "https://anthropic.com/company"},
    {"type": "careers page", "url": "https://anthropic.com/careers"}
  ]
}

Then, when you run the brochure maker, a Markdown brochure types itself out line by line — headings, bullet points and a closing line — built from several of the company's pages, not just the home page. In the notebook it is rendered as formatted Markdown; in the TypeScript script it is the same text printed to the terminal. Run it again and you get a slightly different brochure each time.

Common mistakes
  • Prose instead of JSON. If you forget the response_format JSON setting (or forget to mention JSON in the prompt), the model may reply with a paragraph, and json.loads / JSON.parse then throws. Both the parameter and the word "JSON" in the prompt are needed.
  • Relative vs absolute URLs. Many links on a page look like /about, not https://site.com/about. A relative link cannot be fetched on its own, which is exactly why the prompt asks the model to return the full https URL.
  • Forgetting the 5,000-character cap. The [:5_000] / .slice(0, 5_000) truncation is there on purpose. Removing it on a large site can overflow the context window or run up a bigger bill than you meant.
  • Forgetting await (TypeScript). The scraping and model calls are asynchronous; leave off an await and you pass a pending Promise instead of the value, which makes the text come out as [object Promise].
Video vs repo
  • Model name. The video uses gpt-4o-mini, which is what you see on screen and what this guide shows. The current repo has moved on to gpt-6-luna with an extra reasoning_effort="none" argument. Model names get retired over time, so treat the model id as a value you may need to swap for whatever is current when you run it.
  • Scraper. The video defines the Website class inline (shown in the Python tab). The repo has refactored the identical logic into a separate scraper.py with functions fetch_website_contents(url) and fetch_website_links(url). The TypeScript port follows the repo's shape, keeping its scraper in the shared scrape.ts from Day 1. Same behaviour either way.
  • Character cap. On screen the instructor mentions a 20,000-character guard while the typed code uses 5,000. Either way it is just a safety cap; the number is yours to choose.
Recap
  • The project turns a company's website into a Markdown brochure using two model calls.
  • Call 1 asks which links matter and replies in strict JSON, using JSON mode (the response_format json_object setting) and one-shot prompting (one worked example in the prompt).
  • Call 2 fetches those pages, joins the text (capped at 5,000 characters), and writes the brochure; turning streaming on makes it appear with the typewriter effect.
  • Changing one line of the system prompt changes the tone — formal, humorous, or another language — with no other code changes.
  • The Python and TypeScript versions do the same work step for step; the TypeScript port reuses the shared scrape.ts from Day 1, and a small React app in week1-ts/ wraps it in a UI.
  • Chaining the two calls is a first, toy taste of agentic design, revisited in Week 2 and built out fully in Week 8.
  • The API-calling code (both languages) is shown as in the course and was not run live; the TypeScript project type-checks and builds, and the shared scraper was run offline.
