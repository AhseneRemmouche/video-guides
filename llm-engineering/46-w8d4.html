Week 8 · Day 4 — Agents That Collaborate

The agent framework: a planning agent coordinates a scanner agent (finds deals), the ensemble pricer, and a messaging agent - each doing one job and handing off to the next.

Companion to Ed Donner's course · uv setup · Python + TypeScript/React · code verified against the repo

This is the day everything from Week 8 clicks into place. Over the last three days you built the pieces of "The Price is Right": a scanner that reads deal feeds, an ensemble pricer that estimates what a product is really worth, and the specialist on Modal. Today you add a messaging agent that sends a push notification, and wire everything into a single agentic system: a planning agent that runs the whole show by calling each worker in turn. Each agent does exactly one job and then hands its result to the next. That handoff pattern of small, specialised, collaborating agents is the big idea of the day.

The instructor is emphatic that none of this is magic. There are off-the-shelf agent frameworks (LangChain, Hugging Face agents, Gradio, and others), but he deliberately avoids them. By now you know how to call a model directly, so you can connect a few models and a little Python yourself and see exactly what information flows between the agents. The whole "framework" turns out to be a handful of plain classes that call one another.

What an agent system is, and the five hallmarks

In the video the instructor lists five hallmarks of agentic AI. A solution is agentic when it does some mix of these: it breaks a big task into smaller steps; it uses tools (function calling and structured outputs) so the model does more than chat; it has an environment the agents share (for example a common memory and a way to call each other); it often has a planning agent that decides what to do in what order; and, most distinctively, it has autonomy — some existence that runs behind the scenes rather than only while a human is chatting with it. No single one is required, but the more boxes you tick, the more clearly "agentic" the system is.

New to multi-agent systems? What they are and why they matter

A single agent is a program that uses a model to do a job. A multi-agent system is several such programs, each responsible for one narrow task, that cooperate to solve a problem none of them could do alone. Today's system has four workers: one finds candidate deals, one prices them, one picks the best, and one sends the alert. Splitting the work this way keeps each piece simple to write, test and reason about — the same reason we split ordinary code into small functions. The difference is that some of these "functions" are whole language models.

The four agents and their one job each

The planning agent is the coordinator. In this course it is not a model at all — it is a short piece of Python, because the workflow is simple and the order is fixed: scan, then price, then pick the best, then maybe alert. The instructor points out you could make the planner itself a model that decides the order (a nice challenge), but you do not have to; a planner can be plain code or even a JSON config.

The scanner agent (built on Day 3's work) reads RSS deal feeds, asks a frontier model to pull out a pithy description and a price for each item, and returns a short list of candidate deals. It is given the shared memory so it can skip anything already surfaced. The ensemble pricer agent estimates what each product is really worth by calling three underlying models (the fine-tuned specialist on Modal, a RAG frontier model, and a random-forest model) and blending their answers. The messaging agent is the simplest: given the best opportunity, it sends a push notification (via Pushover) so the deal lands on your phone.

New to specialised agents and handoff? What they are and why they matter

A specialised agent is one that does a single, well-defined job and nothing else. The scanner only finds deals; it does not price them. The pricer only estimates value; it does not decide whether to alert you. A handoff is the moment one agent finishes and passes its output to the next: the scanner hands a list of deals to the planner, which hands each description to the pricer, which hands a price back, and so on. Because each agent has a narrow contract (clear input, clear output), you can test, replace or upgrade any one of them without touching the others.

New to planning and orchestration? What they are and why they matter

Orchestration means arranging separate pieces so they run in the right order with the right data passed between them — like a conductor cueing each section of an orchestra. The planning agent is that conductor here. It knows which agent to call first, what to feed the next one, and when to stop. Keeping the orchestration in one place means the workers stay dumb and simple: they just do their job when asked. If you later want a different workflow, you change the planner, not the agents.

Autonomy: the one that really distinguishes an agent

The instructor singles out autonomy as the hallmark that most separates an agent from an ordinary chat app. The airline chatbot and the RAG Q&A from earlier weeks had memory, but they only existed while a human was typing into them. An autonomous agent has a presence beyond a single conversation: a process running behind the scenes, doing its job without a person prompting each step. Today's system is almost there — you still kick off a run by hand — and tomorrow (Day 5) you make it truly autonomous by having it run on a schedule with a Gradio dashboard on top.

New to autonomous operation? What it is and why it matters

An autonomous program runs on its own, triggered by a timer or an event rather than by a person clicking a button. A deal scanner that wakes up every few minutes, checks the feeds, and messages you only when it finds something good is autonomous: most of the time nothing happens and no human is involved. This is powerful but also where the warnings below come from — an unattended process that calls paid models needs guard-rails so it cannot spend money or loop forever without anyone watching.

import os
from twilio.rest import Client
from agents.deals import Opportunity
import http.client
import urllib
from agents.agent import Agent


DO_TEXT = False
DO_PUSH = True

class MessagingAgent(Agent):

    name = "Messaging Agent"
    color = Agent.WHITE

    def __init__(self):
        """
        Set up this object to either do push notifications via Pushover,
        or SMS via Twilio,
        whichever is specified in the constants
        """
        self.log(f"Messaging Agent is initializing")
        if DO_TEXT:
            account_sid = os.getenv('TWILIO_ACCOUNT_SID', 'your-sid-if-not-using-env')
            auth_token = os.getenv('TWILIO_AUTH_TOKEN', 'your-auth-if-not-using-env')
            self.me_from = os.getenv('TWILIO_FROM', 'your-phone-number-if-not-using-env')
            self.me_to = os.getenv('MY_PHONE_NUMBER', 'your-phone-number-if-not-using-env')
            self.client = Client(account_sid, auth_token)
            self.log("Messaging Agent has initialized Twilio")
        if DO_PUSH:
            self.pushover_user = os.getenv('PUSHOVER_USER', 'your-pushover-user-if-not-using-env')
            self.pushover_token = os.getenv('PUSHOVER_TOKEN', 'your-pushover-user-if-not-using-env')
            self.log("Messaging Agent has initialized Pushover")

    def message(self, text):
        """
        Send an SMS message using the Twilio API
        """
        self.log("Messaging Agent is sending a text message")
        message = self.client.messages.create(
          from_=self.me_from,
          body=text,
          to=self.me_to
        )

    def push(self, text):
        """
        Send a Push Notification using the Pushover API
        """
        self.log("Messaging Agent is sending a push notification")
        conn = http.client.HTTPSConnection("api.pushover.net:443")
        conn.request("POST", "/1/messages.json",
          urllib.parse.urlencode({
            "token": self.pushover_token,
            "user": self.pushover_user,
            "message": text,
            "sound": "cashregister"
          }), { "Content-type": "application/x-www-form-urlencoded" })
        conn.getresponse()

    def alert(self, opportunity: Opportunity):
        """
        Make an alert about the specified Opportunity
        """
        text = f"Deal Alert! Price=${opportunity.deal.price:.2f}, "
        text += f"Estimate=${opportunity.estimate:.2f}, "
        text += f"Discount=${opportunity.discount:.2f} :"
        text += opportunity.deal.product_description[:10]+'... '
        text += opportunity.deal.url
        if DO_TEXT:
            self.message(text)
        if DO_PUSH:
            self.push(text)
        self.log("Messaging Agent has completed")

from typing import Optional, List
from agents.agent import Agent
from agents.deals import ScrapedDeal, DealSelection, Deal, Opportunity
from agents.scanner_agent import ScannerAgent
from agents.ensemble_agent import EnsembleAgent
from agents.messaging_agent import MessagingAgent


class PlanningAgent(Agent):

    name = "Planning Agent"
    color = Agent.GREEN
    DEAL_THRESHOLD = 50

    def __init__(self, collection):
        """
        Create instances of the 3 Agents that this planner coordinates across
        """
        self.log("Planning Agent is initializing")
        self.scanner = ScannerAgent()
        self.ensemble = EnsembleAgent(collection)
        self.messenger = MessagingAgent()
        self.log("Planning Agent is ready")

    def run(self, deal: Deal) -> Opportunity:
        """
        Run the workflow for a particular deal
        :param deal: the deal, summarized from an RSS scrape
        :returns: an opportunity including the discount
        """
        self.log("Planning Agent is pricing up a potential deal")
        estimate = self.ensemble.price(deal.product_description)
        discount = estimate - deal.price
        self.log(f"Planning Agent has processed a deal with discount ${discount:.2f}")
        return Opportunity(deal=deal, estimate=estimate, discount=discount)

    def plan(self, memory: List[str] = []) -> Optional[Opportunity]:
        """
        Run the full workflow:
        1. Use the ScannerAgent to find deals from RSS feeds
        2. Use the EnsembleAgent to estimate them
        3. Use the MessagingAgent to send a notification of deals
        :param memory: a list of URLs that have been surfaced in the past
        :return: an Opportunity if one was surfaced, otherwise None
        """
        self.log("Planning Agent is kicking off a run")
        selection = self.scanner.scan(memory=memory)
        if selection:
            opportunities = [self.run(deal) for deal in selection.deals[:5]]
            opportunities.sort(key=lambda opp: opp.discount, reverse=True)
            best = opportunities[0]
            self.log(f"Planning Agent has identified the best deal has discount ${best.discount:.2f}")
            if best.discount > self.DEAL_THRESHOLD:
                self.messenger.alert(best)
            self.log("Planning Agent has completed a run")
            return best if best.discount > self.DEAL_THRESHOLD else None
        return None

import logging

class Agent:
    """
    An abstract superclass for Agents
    Used to log messages in a way that can identify each Agent
    """

    # Foreground colors
    RED = '\033[31m'
    GREEN = '\033[32m'
    YELLOW = '\033[33m'
    BLUE = '\033[34m'
    MAGENTA = '\033[35m'
    CYAN = '\033[36m'
    WHITE = '\033[37m'
    
    # Background color
    BG_BLACK = '\033[40m'
    
    # Reset code to return to default color
    RESET = '\033[0m'

    name: str = ""
    color: str = '\033[37m'

    def log(self, message):
        """
        Log this as an info message, identifying the agent
        """
        color_code = self.BG_BLACK + self.color
        message = f"[{self.name}] {message}"
        logging.info(color_code + message + self.RESET)

def init_logging():
    root = logging.getLogger()
    root.setLevel(logging.INFO)
    
    handler = logging.StreamHandler(sys.stdout)
    handler.setLevel(logging.INFO)
    formatter = logging.Formatter(
        "[%(asctime)s] [Agents] [%(levelname)s] %(message)s",
        datefmt="%Y-%m-%d %H:%M:%S %z",
    )
    handler.setFormatter(formatter)
    root.addHandler(handler)

class DealAgentFramework:

    DB = "products_vectorstore"
    MEMORY_FILENAME = "memory.json"

    def __init__(self):
        init_logging()
        self.log("Initializing Agent Framework")
        load_dotenv()
        client = chromadb.PersistentClient(path=self.DB)
        self.memory = self.read_memory()
        self.collection = client.get_or_create_collection('products')
        self.planner = PlanningAgent(self.collection)
        self.log("Agent Framework is ready")

    def read_memory(self) -> List[Opportunity]:
        if os.path.exists(self.MEMORY_FILENAME):
            with open(self.MEMORY_FILENAME, "r") as file:
                data = json.load(file)
            opportunities = [Opportunity(**item) for item in data]
            return opportunities
        return []

    def write_memory(self) -> None:
        data = [opportunity.dict() for opportunity in self.memory]
        with open(self.MEMORY_FILENAME, "w") as file:
            json.dump(data, file, indent=2)

    def log(self, message: str):
        text = BG_BLUE + WHITE + "[Agent Framework] " + message + RESET
        logging.info(text)

    def run(self) -> Optional[Opportunity]:
        logging.info("Kicking off Planning Agent")
        result = self.planner.plan(memory=self.memory)
        logging.info(f"Planning Agent has completed and returned: {result}")
        if result:
            self.memory.append(result)
            self.write_memory()
        return result

    @classmethod
    def get_plot_data(cls, max_datapoints=10000):
        client = chromadb.PersistentClient(path=cls.DB)
        collection = client.get_or_create_collection('products')
        result = collection.get(include=['embeddings', 'documents', 'metadatas'], limit=max_datapoints)
        vectors = np.array(result['embeddings'])
        documents = result['documents']
        categories = [metadata['category'] for metadata in result['metadatas']]
        colors = [COLORS[CATEGORIES.index(c)] for c in categories]
        tsne = TSNE(n_components=3, random_state=42, n_jobs=-1)
        reduced_vectors = tsne.fit_transform(vectors)
        return documents, reduced_vectors, colors

What you should see

When the real framework runs from the command line, the log fills with each agent announcing itself in its own colour: the agent framework initialises, the planning agent starts, the scanner becomes ready, then the ensemble's three models (the Modal specialist, the RAG frontier model, the random forest) load and report ready, the messenger is ready, and the framework prints that it is ready. In the video the instructor gets an alert about a refurbished laptop estimated near $925 and offered at $560.

Common mistakes and real risks of agent systems
  • Agents failing silently. If one agent returns nothing (the scanner finds no new deals, a model times out), the pipeline can quietly produce no alert. That is sometimes correct, but without good logging you cannot tell "nothing good today" from "something broke". This is exactly why every agent logs in its own colour.
  • The cost of many model calls. One run can call several models many times — the ensemble alone calls three models per deal, across several deals. Those paid calls add up fast. Keep an eye on how many calls a single run makes before you let it run often.
  • Repeat alerts. Without memory the planner would surface the same deal on every run. The framework saves each surfaced opportunity in memory.json and the scanner skips those URLs; delete the file if you want to start fresh.
  • Hard-coded numbers. The instructor flags the hard-coded $50 threshold and the "top 5" count as things to turn into named, configurable values before you call this production code.

Recap
  • An agentic system breaks a task into steps, uses tools, shares an environment, often has a planner, and ideally runs autonomously.
  • Today's system has four specialised agents: a scanner (finds deals), an ensemble pricer (estimates value), a planner (coordinates and picks the best), and a messaging agent (sends the alert).
  • Each agent does one job and hands its output to the next; the planner runs them in a fixed order: scan, price, select, alert.
  • The planner is plain Python because the order is fixed; making it an LLM that uses function calling is the suggested challenge (today's repository does exactly that).
  • Deal selection keeps only the single best opportunity and alerts only when the discount beats a threshold, so most runs correctly send nothing.
  • The framework is just deal_agent_framework.py: logging, the Chroma collection, a JSON memory, and a run() that calls the planner. Run it from the command line.
  • Watch the risks: silent failures, the cost of many model calls, and runaway loops — logging, thresholds and stop conditions are the guard-rails. True autonomy comes on Day 5.
