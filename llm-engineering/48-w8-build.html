Week 8 · Project Build — The Deal-Hunting System, Step by Step

Build the autonomous deal hunter from an empty folder, one tab per stack: the scan, price, rank and alert agent loop in Python + uv, and a React + Node + TypeScript dashboard that shows the deals. Every step shows its full code and why you do it.

Build it yourself · Python + uv (agents) and a React dashboard demo

This is the Week 8 project - the finale of the whole course. By the end of it you will have an autonomous system that, with no one watching, scans online deal feeds, works out what each item is really worth, and pings your phone the moment it finds something priced well below its true value. It is called "The Price is Right", and it is a real agentic AI system: several specialised agents that each do one job and hand work to each other.

You can build it in either of two stacks; choose one with the tabs in Build it step by step. Each tab is complete on its own:

  • Python + uv: the agent pipeline itself, scan → price → rank → alert, runnable on your own computer against a free local Ollama model. The course's full system adds live RSS feeds, a fine-tuned pricer on Modal, an ensemble and phone alerts; the tab says exactly where each of those plugs in.
  • React + Node + TypeScript: a dashboard that shows found deals as cards and highlights the biggest discount, served by a tiny Hono API. It runs on clearly-labelled sample deals with no keys, because the agents themselves are Python.

Build the deal-hunting agents in Python with uv

This is the guide's runnable version of the week, the verified week8-py/ project. It keeps the course's agent logic, scan → price → rank → alert, and runs it end to end against a local Ollama model with no paid keys.   11. Add the system prompt and the number parser. 
    SYSTEM = "You estimate the fair retail price of a product in US dollars. Reply with just a number, no words, no dollar sign."


def get_price(text: str) -> float:
    """Pull the first number out of a model reply."""
    text = text.replace("$", "").replace(",", "")
    match = re.search(r"[-+]?\d*\.\d+|\d+", text)
    return float(match.group()) if match else 0.0

    The system prompt asks for "just a number", but models still add words or a $ sometimes, so get_price() strips $ and commas and takes the first number. If there is none it returns 0, so one odd reply cannot crash the loop.

  12. Add estimate_price(): one description in, one price out. 
    def estimate_price(description: str) -> float:
    """Ask the local model for a fair price. Short prompt, parse a number."""
    user = f"How much does this cost?\n\n{description}\n\nPrice in dollars:"
    response = client.chat.completions.create(
        model=MODEL,
        messages=[
            {"role": "system", "content": SYSTEM},
            {"role": "user", "content": user},
        ],
        temperature=0.0,
        max_tokens=20,
    )
    reply = response.choices[0].message.content or ""
    return get_price(reply)

    This one function is the pricer agent's whole interface, which is the point: the planner does not care whether a price comes from a local model, a fine-tuned model on Modal or the course's ensemble, as long as this function returns a number. Temperature 0 makes the same item get the same estimate each time.

  18. Add the planning loop: scan, then price every deal. 
    def plan() -> list[Opportunity]:
    """Scan -> price -> rank -> alert over the sample deals."""
    print("[planning_agent] Scanning for deals (sample data stands in for RSS scanner)...")
    deals = scan_for_deals()
    print(f"[planning_agent] Got {len(deals)} deals. Pricing each via local Ollama...\n")

    opportunities: list[Opportunity] = []
    for i, deal in enumerate(deals, 1):
        print(f"  ({i}/{len(deals)}) pricing: {deal.title} ...")
        estimate = estimate_price(deal.description)
        discount = estimate - deal.actual_price
        opportunities.append(Opportunity(deal=deal, estimate=estimate, discount=discount))
        print(f"      actual=${deal.actual_price:.2f}  estimate=${estimate:.2f}  discount=${discount:.2f}")

    opportunities.sort(key=lambda o: o.discount, reverse=True)

    This is the planning agent's job: call the scanner, ask the pricer about each deal, and compute discount = estimate − price. A big positive discount means the item sells for much less than it seems to be worth. Sorting puts the best bargain first.

    print("[planning_agent] Scanning for deals (sample data stands in for RSS scanner)...")

// The discount as a percentage of the estimated fair price (0 when estimate <= 0).
export function discountPercent(deal: Deal): number {
  if (deal.estimate <= 0) return 0;
  return Math.round((deal.discount / deal.estimate) * 100);
}

  22. Build the dashboard: web/src/App.tsx. 
    // Week 8 "The Price is Right" dashboard: the deals the agent pipeline found, each
// with its actual price, the pricer agent's estimated fair price, and the discount.
// The biggest discount is highlighted. "Scan for deals" calls GET /api/deals to
// re-scan. All data is clearly-labelled SAMPLE data - no live scanning here.
//
// The dashboard loads pre-ranked sample deals on first render (so it is useful even
// as a static build), and the shared sample set is imported from src/deals.ts - the
// same module the Hono API serves - so the two can never drift apart.
import { useState } from "react";
import {
  type Deal,
  sampleDeals,
  rankByDiscount,
  discountPercent,
} from "../../src/deals";

const usd = (n: number) => `$${n.toLocaleString("en-US")}`;

const INITIAL_DEALS = rankByDiscount(sampleDeals());

export function App() {
  const [deals, setDeals] = useState<Deal[]>(INITIAL_DEALS);
  const [busy, setBusy] = useState(false);
  const [error, setError] = useState("");

  async function scan() {
    if (busy) return;
    setBusy(true);
    setError("");
    try {
      const res = await fetch("/api/deals");
      if (!res.ok) {
        const data = await res.json().catch(() => ({}));
        setError(data.error ?? "Request failed");
        return;
      }
      const data = (await res.json()) as { deals: Deal[] };
      setDeals(data.deals);
    } catch (e) {
      setError(String(e));
    } finally {
      setBusy(false);
    }
  }

  // The single best discount drives the "top deal" highlight.
  const bestDiscount = deals.reduce((max, d) => Math.max(max, d.discount), 0);

  return (
    <main className="wrap">
      <header>
        <h1>The Price is Right - Week 8</h1>
        <p className="sub">
          An autonomous multi-agent deal hunter. A Planning agent coordinates a Scanner
          (RSS deal feeds), an Ensemble pricer (frontier + fine-tuned + RAG models), and a
          Messaging agent to surface products priced well below their estimated value.
        </p>
        <p className="note">
          Demo dashboard - shows <strong>sample data</strong>, not a live scan. The real
          agent pipeline is Python.
        </p>
      </header>

      <div className="toolbar">
        <button onClick={scan} disabled={busy}>
          {busy ? "Scanning..." : "Scan for deals"}
        </button>
        <span className="count">
          {deals.length} deals - ranked by discount
        </span>
      </div>

      {error && <div className="error">{error}</div>}

      <div className="cards">
        {deals.map((deal) => {
          const top = deal.discount === bestDiscount && bestDiscount > 0;
          const pct = discountPercent(deal);
          return (
            <article className={top ? "card top" : "card"} key={deal.url}>
              {top && <div className="badge">Biggest discount</div>}
              <h2 className="title">
                <a href={deal.url} target="_blank" rel="noreferrer">
                  {deal.title}
                </a>
              </h2>
              <div className="prices">
                <div className="price">
                  <span className="label">Price</span>
                  <span className="value">{usd(deal.price)}</span>
                </div>
                <div className="price">
                  <span className="label">Estimate</span>
                  <span className="value est">{usd(deal.estimate)}</span>
                </div>
                <div className="price">
                  <span className="label">Discount</span>
                  <span className="value save">
                    {usd(deal.discount)}
                    <small>{pct}%</small>
                  </span>
                </div>
              </div>
              <div className="bar" aria-hidden="true">
                <div
                  className="bar-fill"
                  style={{ width: `${Math.min(pct, 100)}%` }}
                />
              </div>
            </article>
          );
        })}
      </div>
    </main>
  );
}
    • Lines 9–19, imports and INITIAL_DEALS. The page imports the same deals.ts the server uses. Why: the cards show up on first render, even as a static build with no server, and the two sides can never drift apart.
    • Lines 21–44, state and scan(). Calls GET /api/deals and replaces the cards, or shows an error. Why: finally always clears the busy flag, so the button never stays stuck on "Scanning...".
    • Lines 46–47, bestDiscount. Why: working out the top deal from the data (not from its position in the list) keeps the badge right even if the order changes.
    • Lines 49–115, the markup. A header with a "sample data" note, the toolbar, and one card per deal with price, estimate, discount and a bar; line 77 marks the top card. Why: the note makes it impossible to mistake sample deals for a live scan.

    This is the "watch the agents" screen from the course, reduced to the essentials: each deal's price against its estimated worth, with the best bargain impossible to miss.
