Week 8 · Project Build — The Deal-Hunting System, Step by Step

Build the autonomous deal-hunting system in Python + uv - the agent framework, ensemble pricer and notifications - and a React dashboard demo (Node + TypeScript) that shows the deals it finds.

Build it yourself · Python + uv (agents) and a React dashboard demo

This is the Week 8 project - the finale of the whole course. By the end of it you will have an autonomous system that, with no one watching, scans online deal feeds, works out what each item is really worth, and pings your phone the moment it finds something priced well below its true value. It is called "The Price is Right", and it is a real agentic AI system: several specialised agents that each do one job and hand work to each other.

There are two tracks on this page. Track A is the real system, and it is all Python (managed by uv): the agents, the pricing models, the scheduler and the push notifications. Track B is a small React dashboard so you can watch the deals the system finds in a browser. The dashboard is a demo that shows clearly-labelled sample deals; in a full build you would feed it the deals coming out of the Python pipeline. The complete, line-by-line code for the Python side lives on the day pages - this page is the build guide that ties it all together.

Build it step by step

Run it locally (Python + uv)

The runnable Week 8 project lives in the week8-py/ folder and runs fully locally against Ollama, with no paid API keys. Install Ollama first, then:

ollama pull llama3.2
cd week8-py
UV_NATIVE_TLS=1 uv sync
uv run python src/planning_agent.py

The scan to price to rank to alert loop runs against local Ollama on sample deals; the real Modal pricer, live RSS feeds and Pushover alerts (modal_note.py) are not run.

Do Track A first if you want the real system - it needs paid API keys, a deployed pricing model and signup for a couple of free services, so it takes real setup. Track B is self-contained and runs on sample data with nothing but Node, so you can build and open it straight away.

Track A - Python + uv (the agent system)

This track builds the real deal hunter. Every step says what to type and what you should see. The full, explained code for each file is on the day pages - here we only list the moves in order. The system was not run on this machine: it needs a paid OpenAI key, a model deployed to a GPU service, and signups for Hugging Face, Modal and Pushover. The Python shown is the course's own code.

This track needs keys and a deployed model. Track A talks to paid and external services: OpenAI (and optionally Anthropic) for the frontier model, Hugging Face for the fine-tuned weights, Modal to serve the fine-tuned pricer on a GPU, and Pushover to send the phone alert. Put every key in a .env file in the project root and never commit it. None of this was run here - the steps and code come straight from the course.
  1. Get the project and add the libraries Use the course repo (or uv init price-is-right for an empty project), then add every library the week needs with uv: 
    uv add openai anthropic modal chromadb sentence-transformers gradio python-dotenv requests
    openai and anthropic are the frontier-model clients; modal deploys and calls the fine-tuned pricer; chromadb is the vector store for retrieval; sentence-transformers turns product text into vectors; gradio builds the control panel UI; python-dotenv loads your keys from .env; and requests is what the messaging agent uses to send the push notification to Pushover. uv run <cmd> runs any command inside the project's environment without "activating" anything.
  2. Deploy the fine-tuned pricer to Modal This is from Day 2. Your Week 7 fine-tuned model is wrapped in pricer_service.py and deployed to Modal, which runs it on a GPU behind a callable function. Sign in once (uv run modal setup), then deploy: 
    uv run modal deploy -m pricer_service
    Modal prints a deployed-app URL. From then on any Python can call it with modal.Cls.from_name("pricer-service", "Pricer") and get a price back - the model stays warm on Modal's servers, not on your machine. The full service code and the line-by-line walk-through are on Day 2.
  3. Build the ensemble pricer Also Day 2. One model is never quite enough, so you blend three into an ensemble: a frontier model with retrieval, your fine-tuned model on Modal, and a small neural-network regression model. Each one estimates a price and you take a weighted average: 
    def ensemble(item):
    price1 = get_price(gpt_5__1_rag(item))   # frontier + RAG
    price2 = specialist(item)                # fine-tuned, on Modal
    price3 = deep_neural_network(item)       # regression model
    return price1 * 0.8 + price2 * 0.1 + price3 * 0.1
    The frontier-plus-retrieval estimate carries most of the weight (0.8); the other two nudge it. The full EnsembleAgent and how each weight was chosen are on Day 2.
  4. Build the RAG pricer This is Day 3. The strongest single estimate comes from giving a frontier model context: you store thousands of past products as vectors in Chroma, and for a new item you retrieve the five most similar ones and show the model their prices before asking for its estimate: 
    def find_similars(item):
    vec = vector(item)
    results = collection.query(query_embeddings=vec.astype(float).tolist(), n_results=5)
    documents = results['documents'][0][:]
    prices = [m['price'] for m in results['metadatas'][0][:]]
    return documents, prices
    Those similar items and their prices become the context the model reasons from. The full retrieval pipeline and the FrontierAgent that wraps it are on Day 3.
  5. Write the scanner, planning and messaging agents This is Day 4 - the heart of the system. Three more agents join the pricer, each a small class with one job. The scanner agent reads RSS deal feeds and returns a clean, typed list of items. The planning agent drives the loop: scan, price each item with the ensemble, compare price to estimate, and pick the best bargain. The messaging agent sends the alert. The planner exposes the three jobs to the model as tools: 
    tools = [{"type": "function", "function": scan_function},
         {"type": "function", "function": estimate_function},
         {"type": "function", "function": notify_function}]
    The model then calls scan, then estimate for each item, then notify once for the single best deal. The full framework - every agent class and how they hand work to each other - is on Day 4.
  6. Wire up push notifications Still Day 4. The messaging agent sends the alert through Pushover, a free service that delivers a push notification to your phone. You create a free account, put PUSHOVER_USER and PUSHOVER_TOKEN in .env, and the agent posts the message to Pushover's API with requests: 
    payload = {"user": pushover_user, "token": pushover_token, "message": message}
requests.post("https://api.pushover.net/1/messages.json", data=payload)
    That one HTTP call is the whole "alert me" feature. Setup and the full MessengerAgent are on Day 4.
  7. Assemble the dashboard, scheduler and alerts This is Day 5. Everything comes together in price_is_right.py, a gradio app that runs the planning agent on a schedule, shows every deal it has surfaced in a live table, and fires a push when a good one appears. The app holds the running list of opportunities and refreshes the table as new deals arrive: 
    agent_framework = DealAgentFramework()
agent_framework.init_agents_as_needed()
    The complete app, the schedule and the memory of past deals are on Day 5.
  8. Run it With the pricer deployed, the keys in .env and Pushover connected, start the whole system from the command line: 
    uv run price_is_right.py
    A browser opens with the control panel. The agents start scanning; as deals appear, each one shows its price, the ensemble's estimate and the discount, and your phone buzzes when a genuine bargain is found. The full run and what to expect are on Day 5.

Track B - React dashboard (Node + TypeScript)

This track is a small, self-contained dashboard that shows found deals as cards, highlights the biggest discount, and has a Scan for deals button. It is built with Vite + React for the page and Hono for a tiny API, all in TypeScript. It runs on sample data - no keys, no network, no agents - so you can build and open it on its own. The real, verified project is in week8-ts/; the steps below match those files exactly.

  1. Scaffold the project Make the React front end with the Vite react-ts template, then turn the root folder into a Node package for the server and shared code. Using npm: 
    npm create vite@latest web -- --template react-ts
npm init -y
    web/ holds the React app; the root package.json holds the server, the shared src/ code and the scripts that run everything.
  2. Add the server libraries The API is built with Hono and run on Node: 
    npm add hono @hono/node-server dotenv
    hono is the tiny web framework that defines the routes; @hono/node-server runs a Hono app on Node and can also serve the built React files; dotenv loads a .env file (the demo needs no keys, but it keeps the shape of a real build).
  3. Add the TypeScript runner You run the .ts files directly with tsx, so no separate compile step is needed in development: 
    npm add -D tsx
    -D saves it as a dev dependency (a tool you use while building, not shipped to users). tsx runs TypeScript as-is, which is how the api script starts the server.
  4. Create the deal model Make src/deals.ts. This is the shared heart of the demo: the Deal type, some clearly-labelled sample deals, and the pure helpers that rank and measure them. It has no models, no network and no Node APIs, so both the server and the browser can import it: 
    export interface Deal {
  title: string;
  url: string;
  price: number;     // what it is selling for
  estimate: number;  // the pricer's fair value
  discount: number;  // estimate - price (bigger is better)
}

export function rankByDiscount(deals: Deal[]): Deal[] {
  return [...deals].sort((a, b) => b.discount - a.discount);
}
    sampleDeals() returns about six hand-written stand-ins (a Sony headphone, an LG TV, and so on) for what the Scanner and pricer agents would surface at runtime. The full file is in week8-ts/src/deals.ts.
  5. Create the API Make server/index.ts. It is a Hono app with one route, GET /api/deals, that returns the sample deals ranked by discount. In a real build this is where the Python pipeline's deals would come from; here it serves the sample data: 
    app.get("/api/deals", (c) => {
  const deals = rankByDiscount(sampleDeals()).map((deal) => ({
    ...deal,
    discountPercent: discountPercent(deal),
  }));
  return c.json({ sample: true, count: deals.length, deals });
});
    The sample: true flag is honest about what the data is. The full server, including serving the built React app, is in week8-ts/server/index.ts.
  6. Build the dashboard Make web/src/App.tsx. It loads the pre-ranked sample deals on first render (so it works even as a static build), draws one card per deal with its price, estimate and discount, highlights the single biggest discount, and re-scans when you click the button: 
    const [deals, setDeals] = useState<Deal[]>(INITIAL_DEALS);

async function scan() {
  const res = await fetch("/api/deals");
  const data = (await res.json()) as { deals: Deal[] };
  setDeals(data.deals);
}

// the single best discount drives the "top deal" highlight
const bestDiscount = deals.reduce((max, d) => Math.max(max, d.discount), 0);
    Each card marked top (its discount equals bestDiscount) gets a "Biggest discount" badge. The full component is in week8-ts/web/src/App.tsx.
  7. Check the run scripts The root package.json defines the scripts that run everything. These are the real scripts from week8-ts/: 
    "scripts": {
  "deals": "tsx src/deals.cli.ts",
  "api": "tsx server/index.ts",
  "web": "vite --config web/vite.config.ts",
  "typecheck": "tsc --noEmit -p tsconfig.json",
  "build": "tsc --noEmit -p tsconfig.json && vite build --config web/vite.config.ts"
}
    api starts the Hono server with tsx; web starts the Vite dev server for the React page; deals prints the ranked sample deals in the terminal; typecheck and build check and bundle the whole project.
  8. Run it Start the API and the web page in two terminals: 
    npm run api
npm run web
    npm run api prints the port it is listening on; npm run web opens the dashboard. Click Scan for deals and the cards refresh from GET /api/deals. Everything you see is sample data - a real build would feed these cards from the Python agent pipeline.
What you should see. In Track A, a browser control panel that fills with priced deals and a push notification on your phone when a real bargain appears. In Track B, a page of deal cards with the biggest discount highlighted, refreshing when you press Scan for deals. The React dashboard was type-checked and built successfully; the Python agent system is shown exactly as in the course and was not run live here.

Across eight weeks you went from calling a hosted model in a single line of code to orchestrating a team of agents and a fine-tuned model of your own.

Run it with npm run api and npm run web. It uses sample data; a real build feeds it from the agent pipeline.
