Glossary

Every technical term in this guide, explained for beginners.

Plain-language definitions of every technical word used in this guide. Each entry ends with where the idea shows up in Socialix, the app we build.

Web and Next.js

Next.js
A framework for building websites and web apps with React. It gives you routing (which file answers which URL), server code and a build step in one project, so you do not have to wire those pieces together yourself. In this app: Socialix runs on Next.js 16.4.2; the video starts from a Next.js boilerplate instead of writing the setup by hand.
App Router
The way modern Next.js maps folders to pages. A folder inside src/app becomes a URL, and a page.tsx file in it is the page shown there; a layout.tsx wraps all pages below it. In this app: src/app/dashboard/posts/page.tsx is the page at /dashboard/posts, and src/app/dashboard/layout.tsx adds the sidebar to every dashboard page.
React
A JavaScript library for building user interfaces out of small reusable pieces called components. A component is a function that returns what should appear on screen, and React updates the screen when the data changes. In this app: every page and widget, from the sign-in form to the office picture, is a React 19 component.
Server Component
A React component that runs only on the server. It can read the database or secret settings directly, and only the finished HTML is sent to the browser, so its code never reaches the visitor. In the Next.js App Router, every component is a server component unless its file says otherwise. In this app: the overview, calendar and analytics pages are server components that query Postgres directly.
Client Component
A React component that also runs in the browser, so it can react to clicks, keep state and use hooks such as useEffect. You mark one by putting "use client" at the very top of the file. In this app: the chat workspace, the live office, the sidebar and the sign-in page are client components.
Server Action
A function that runs on the server but can be called straight from a form or button in the browser, without writing a separate API URL. Next.js turns the call into a network request for you. Files full of them start with "use server". In this app: src/app/dashboard/actions.ts holds the server actions for campaigns, posts (approve, cancel, delete) and settings.
Route Handler
A file named route.ts inside the app folder that answers HTTP requests at that URL, like a small API endpoint. It exports functions named after HTTP methods such as GET or POST. In this app: POST /api/agents/[agent]/chat starts an agent run and GET /api/agents/state returns the latest chat and task state for the page to poll.
TypeScript
JavaScript with types added. You can say that a value is a string or a list of posts, and the TypeScript checker warns you before the code runs when something does not fit. The types are removed when the code is built, so browsers still run plain JavaScript. In this app: every source file is TypeScript (.ts or .tsx), checked with pnpm typecheck.
Tailwind CSS
A CSS framework where you style elements with many small class names, such as p-4 for padding or text-sm for small text, instead of writing separate CSS rules. It keeps the styles next to the markup they affect. In this app: Tailwind 4 styles the whole dashboard, set up in src/app/globals.css.
shadcn/ui
A collection of ready-made React components (buttons, dialogs, cards and so on) built with Tailwind. Instead of installing it as a package, you copy each component's source into your own project, so you can change it freely. In this app: the video's boilerplate includes shadcn/ui; Socialix writes its few UI pieces by hand in src/components/ui.tsx.
Boilerplate
A starter project that already contains the usual setup, so you begin from working code rather than an empty folder. It saves time but brings along choices made by someone else. In this app: the video starts from the create-fastnextjs-app boilerplate (Tailwind, shadcn/ui, Drizzle); Socialix was set up by hand.
Node.js
A program that runs JavaScript outside the browser, on your computer or a server. Web servers, build tools and scripts written in JavaScript all need it. In this app: Socialix needs Node 22 or newer; Node runs the Next.js server, the scripts and the MCP server.
pnpm
A package manager for Node.js, like npm but faster and more careful with disk space. It installs the libraries listed in package.json and runs the project's scripts, for example pnpm dev. In this app: all commands use pnpm, such as pnpm db:setup, pnpm build and pnpm start.
Dashboard
A page or set of pages that gives an overview of a system and lets you control it, usually with a sidebar, summary numbers and lists. It is the control room of an app. In this app: everything after sign-in lives under /dashboard: overview, AI Agent, posts, calendar, analytics, accounts and settings.
SVG
Scalable Vector Graphics: a way to describe a picture with shapes (rectangles, circles, lines, text) written as code. It stays sharp at any size and can be changed with code, which makes it good for diagrams and simple animations. In this app: the office with the five agents at their desks is drawn as SVG in src/components/office.tsx.
Polling
Asking a server for news again and again at a fixed interval, instead of the server pushing updates. It is simple and robust, at the cost of some extra requests. In this app: the AI Agent page calls GET /api/agents/state every 5 seconds, and every 1.5 seconds while an agent is busy.
useEffect
A React hook that runs code after a component appears on screen or after some values change, for example to start a timer or scroll a box. If the function you give it returns something, React treats that returned value as a cleanup function to call later. In this app: Bug 3 came from a useEffect that accidentally returned the result of scrollIntoView(); adding braces fixed it.
Promise
A JavaScript object that stands for a result that will arrive later, such as a network response. You wait for it with await or .then(), and handle failure with .catch(). In this app: Chrome 155 started returning a Promise from scrollIntoView(), which React then tried to call as a cleanup function (Bug 3); a failed poll is now caught with .catch(() => null).
Hydration
The step where React, running in the browser, takes over HTML that the server already sent and attaches click handlers and state to it. Until hydration finishes, the page is visible but not yet interactive. A JavaScript error while the page starts up in the browser can make Next.js show an error screen instead of the page. In this app: the AI Agent page's client components come alive this way, and the Bug 3 crash showed up as "This page couldn't load".
Markdown
A simple text format where **bold**, # Heading and - item become formatted text. AI models often answer in Markdown because it is easy to write and read. In this app: agent replies are shown with the small Markdown renderer in src/components/markdown.tsx, and the project docs are Markdown files.

Data and storage

PostgreSQL (Postgres)
A popular open-source database that stores data in tables with rows and columns and is queried with SQL. It is reliable and runs anywhere from a laptop to the cloud. In this app: Socialix stores campaigns, messages, tasks, research, posts, settings and usage in a local Postgres; the autopilot has its own Postgres too.
Docker
A tool that runs software in containers: small isolated packages that include everything the program needs. It lets you start a database with one command without installing it on your system. In this app: the local Postgres runs in a Docker container named wsa-pg.
ORM
Object-Relational Mapper: a library that lets you work with database tables through code in your own language instead of writing raw SQL strings. It usually also gives you types for your rows. In this app: Drizzle is the ORM.
Drizzle ORM
A lightweight TypeScript ORM. You describe tables in TypeScript, and Drizzle gives you typed queries such as db.select().from(posts). In this app: drizzle-orm 0.45.4 defines the tables in src/lib/db/schema.ts and runs every query; the video also uses Drizzle.
Schema
A description of the shape of data. A database schema lists the tables and their columns; a validation schema (like a Zod schema) lists the fields an object must have. In this app: src/lib/db/schema.ts is the database schema with seven tables, and each agent tool has a Zod schema for its input.

Settings and security

.env file
A plain text file of NAME=value lines that holds settings and secrets for an app. It stays on your machine and is never committed to Git; a .env.example file shows the names without real values. In this app: Socialix's .env holds only the dashboard login and session secret, and the other secrets are read from the autopilot's .env.
API key
A long secret string that identifies you to an online service, such as an AI provider, and lets it bill your account. Anyone who has it can use your account, so keep it in a .env file and never show or commit it. In this app: the Anthropic API key is read in place from the autopilot's .env; the guide never prints it.
Session cookie
A small piece of data the server stores in your browser after you sign in. The browser sends it back with every request, so the server knows you are still signed in. In this app: signing in sets a cookie containing a signed JWT, checked on the dashboard pages.
JWT (JSON Web Token)
A compact text token that carries a few facts (for example "signed in as the owner, valid until Friday") plus a signature. The server checks the signature with its secret key, so nobody can change the facts without being noticed. In this app: src/lib/auth.ts creates and checks the login JWT with the jose library, signed with HS256.
httpOnly
A cookie flag that hides the cookie from JavaScript running in the page. The browser still sends it to the server, but scripts cannot read it, which protects it from being stolen by injected code. In this app: the session cookie (socialix_session) is httpOnly; the campaign cookie is not, because it only holds a campaign id.
OAuth
A standard way to let one app act on your account in another service without giving it your password. You approve access on the service's own page, and the app receives an access token. In this app: the social networks are connected inside the autopilot; Socialix never handles those logins.
Access token
A secret string an app sends to an API to prove it may act for a user. Tokens usually expire and must be refreshed. In this app: the social network tokens live only in the autopilot, which refreshes them; Facebook's token was expired at test time.
TLS
Transport Layer Security: the encryption behind https://. It keeps traffic private and proves the server is who it claims to be, using certificates. Some antivirus programs inspect TLS traffic with their own certificate, which Node.js does not trust by default. In this app: Norton intercepts TLS on the owner's PC, so Node is started with NODE_OPTIONS=--use-system-ca.

AI and agents

LLM (large language model)
An AI model trained on huge amounts of text that predicts the next words of a reply. It can answer questions, write and summarize, and, with tools, take actions. In this app: every agent is an LLM (Claude) with its own instructions and tools.
Claude
A family of LLMs made by Anthropic. Bigger models such as Sonnet and Opus are smarter; smaller ones such as Haiku are faster and cheaper. In this app: claude-sonnet-5-5 powers the Master, Research and Creator agents, and claude-haiku-5-5 the Scheduler and Analytics agents.
Claude Code
Anthropic's AI coding assistant that works in your terminal or editor. You describe what you want in plain words, and it reads files, writes code and runs commands for you. In this app: the video builds its app by prompting Claude Code, and Socialix was built with Claude Code too.
Anthropic API
The web service your code calls to use Claude models. You send a list of messages (and optionally tools) with your API key, and get the model's reply back. The official @anthropic-ai/sdk package wraps these calls for JavaScript. In this app: src/lib/ai/runner.ts calls the API through @anthropic-ai/sdk 0.135.0.
Model
One specific trained AI, named by an id such as claude-haiku-5-5. Different models trade off quality, speed and price. In this app: the settings MODEL_SMART and MODEL_FAST choose which model each agent uses.
Prompt
The text you give an AI model to tell it what you want. Clear, complete prompts with the needed context get better results. In this app: the owner's chat messages are prompts, and so are the instructions the Master Agent writes for each team member.
System prompt
Standing instructions sent to the model with every request, separate from the conversation. It sets the role, the rules and the background facts. In this app: systemPrompt() in src/lib/ai/agents.ts builds each agent's system prompt from its role and the campaign brief.
Token
The small unit of text a model reads and writes; one token is roughly three or four characters of English. Providers count input and output tokens and charge for them. This is a different thing from an access token. In this app: every model call's input and output tokens are stored in the usage table and shown on the analytics page.
Usage
A record of how much of a paid service you consumed, here model calls, tokens and web searches. Tracking it shows which part of an app costs the most. In this app: the usage table gets one row per model call, and the analytics page sums it per agent (Research used about 97,000 input tokens in the verified run).
Tool use
A way for a model to ask your code to do something. You describe tools (name, purpose, input schema); the model replies with a tool_use block naming a tool and its input; your code runs it and sends back a tool_result. In this app: tools such as assign_task, save_draft and schedule_post are how the agents act.
Server tool
A tool that runs on Anthropic's side instead of in your code. You only switch it on in the request; Anthropic runs it and puts the results into the reply. In this app: the Research Agent's web search (web_search_20250305) is a server tool; all other tools run in Socialix.
Web search tool
A server tool that lets Claude search the web and read results while it answers, citing its sources. You can cap how many searches one request may make. In this app: the Research Agent may search up to 5 times per request; the verified run used 4 searches.
pause_turn
A stop reason the API returns when a long server-tool turn (such as several web searches) was paused before finishing. Your code sends the conversation back so the model can continue where it stopped. In this app: runAgent() in runner.ts calls the model again when it sees pause_turn.
Zod
A TypeScript library for describing the shape of data and checking that real data matches. A Zod schema both validates input while the program runs and gives you a TypeScript type. In this app: each tool's input is a Zod 4 schema; invalid input from the model gets an "Invalid input: ..." reply.
JSON Schema
A standard JSON format for describing what a JSON object must look like: its fields, their types and which are required. Many APIs use it to describe expected input. In this app: z.toJSONSchema() turns each Zod schema into the JSON Schema Claude sees for that tool.
Agent
An AI model given a goal, instructions and tools, which decides by itself which steps to take and keeps going until the job is done. It differs from a single question-and-answer chat because it acts in a loop. In this app: there are five agents: Master, Research, Creator, Scheduler and Analytics.
Agent loop
The repeating cycle that makes an agent work: call the model, run any tools it asks for, send the results back, and call again until it says it is finished. A limit on rounds stops it from running forever. In this app: runAgent() loops up to 16 model calls and stops on end_turn.
Multi-agent system
Several specialised agents working together, each with its own instructions and tools, usually coordinated by one of them. Splitting the work keeps each agent focused and lets cheaper models handle simple jobs. In this app: the Master Agent coordinates a team of four specialists.
Master Agent
The coordinating agent in a team. It reads the owner's request, breaks it into tasks and hands each task to the right specialist. In this app: the Master Agent uses assign_task and list_tasks, for example sending research to Research, writing to Creator and timing to Scheduler.
Sub-agent
A specialist agent that receives a task from the Master Agent and reports a result back. It does not see the Master's conversation, so the instructions it receives must be complete. In this app: Research, Creator, Scheduler and Analytics are sub-agents; each task is saved as an agent_tasks row.
OpenAI Agents SDK
OpenAI's library for building agents with tools and hand-offs on top of OpenAI's models. It runs the agent loop for you. In this app: the video uses it; Socialix instead writes its own small loop on the Anthropic SDK.

Background work

Background job
Work that runs after the web request has already answered, so the user is not left waiting. Long tasks such as AI agent runs or publishing are typical background jobs. In this app: startChat() saves the message, answers at once and runs the agent in the background; a Set refuses a second message to a busy agent.
Inngest
A hosted service for background jobs and scheduled functions. Your app sends it events, and it calls your functions reliably, with retries and timing. In this app: the video uses Inngest (with a check every 15 minutes); Socialix runs agents in-process and leaves publishing to the autopilot's worker.
Publish queue
A list of posts waiting to be published, each with a time when it should go out. A separate process takes items off the queue when they are due. In this app: approving a post adds a PublishJob row (status QUEUED, nextRunAt in UTC) to the autopilot's queue.
Worker
A long-running process that does queued background work, separate from the web server. It wakes up, picks up due jobs, runs them and records the result. In this app: the autopilot's worker (npm run worker) publishes queued posts with its own token refresh, retries and audit log.

Publishing and social media

Campaign
A planned set of social posts around one goal, product or topic, with a target audience, a tone and usually a link. In this app: you create a campaign first; its brief goes into every agent's system prompt and every post belongs to it.
Approval
A human check before something goes live. Keeping a person in the loop catches AI mistakes before the public sees them. In this app: scheduled posts wait with status awaiting_approval until the owner clicks Approve on the posts page.
Auto-publish
A setting that skips the manual approval step and hands posts straight to publishing. It is faster but riskier. In this app: the autoPublish setting is off by default; in list_connections the platform capability is named canAutoPublish so the agents do not confuse the two (Bug 2).
Character limit
The maximum length a social network accepts for one post. Text over the limit is refused or cut off. In this app: save_draft counts the full post (body, hashtags and link) and refuses drafts over the limit, for example 280 for X and 3000 for LinkedIn.
Hashtag
A word or phrase starting with # that groups posts on the same topic and helps people find them. In this app: the Creator saves hashtags separately from the body; they are added after it and count toward the character limit.
UTC
Coordinated Universal Time, the world's reference clock with no time zone offset or daylight saving. Storing times in UTC avoids mix-ups between places. In this app: the autopilot's nextRunAt is stored in UTC; the verified run scheduled posts at 14:00 and 18:00 UTC.
ISO 8601
A standard way to write dates and times as text, such as 2026-10-18T14:00:00+00:00. The part at the end gives the offset from UTC, so the moment is unambiguous. In this app: schedule_post requires an ISO 8601 time with an offset and refuses times in the past.
WordPress
The most widely used system for running websites and blogs. It stores posts and pages and offers a REST API to read them. In this app: the owner's site is a WordPress site, and the Research Agent can read its recent posts with wordpress_recent_posts.
REST API
A web API where each URL stands for a kind of data and HTTP methods such as GET and POST read or change it, usually exchanging JSON. In this app: wordpress_recent_posts calls WordPress's /wp-json/wp/v2/posts; the owner's site answered HTTP 403 because of bot protection.
Autopilot (WordPress Social Autopilot)
A separate app the owner already runs for social publishing. It keeps the connected social accounts and their tokens, its own Postgres database and dashboard (port 3000), and a worker that publishes queued posts. In this app: Socialix hands approved posts to the autopilot through the MCP server and reads the Anthropic key, database URL and site URL from its .env.
MCP (Model Context Protocol)
An open standard for connecting AI apps to tools and data. A program called an MCP server offers named tools, and any MCP client can list and call them in the same way. In this app: Socialix talks to the autopilot only through MCP, using @modelcontextprotocol/sdk.
MCP server
A program that offers tools through MCP. The client starts or connects to it, asks which tools exist and calls them with arguments. In this app: mcp/social-publisher/server.ts offers list_connections, publish_post, get_post_status, cancel_post and list_recent_posts.
stdio
Standard input and output: the text streams every program has for reading input and writing output. An MCP client can start a server as a child process and exchange messages through these streams, without any network port. In this app: the app spawns node --import tsx mcp/social-publisher/server.ts once and talks to it over stdio.

Tools and services in the video

InsForge
A hosted backend service that provides sign-in and a Postgres database, set up through its command-line tool or MCP. It saves you from running your own auth and database. In this app: the video uses InsForge for auth and data; Socialix uses a single-owner login and a local Postgres instead.
Sandbox
An isolated environment where code or an agent can act without touching your real computer or data. If something goes wrong, only the sandbox is affected. In this app: the video gives each agent a cloud desktop sandbox; Socialix agents only call narrow, checked tools.
E2B
A service that provides cloud sandboxes, including full virtual desktops, that AI agents can control. In this app: the video gives each agent an E2B desktop; Socialix uses Claude's web search tool instead.
ImageKit
A service for storing, transforming and delivering images, with AI features to generate and edit them. In this app: the video uses ImageKit for post images; Socialix does not generate images and lets a post carry an optional public image URL.
Blotato
A service that publishes posts to many social networks (Instagram, YouTube, TikTok, LinkedIn, X and more) through one API and an MCP server. In this app: the video publishes through Blotato; Socialix publishes through the owner's autopilot and its own MCP server.
Pull request
A request to merge a set of code changes into a project, usually on GitHub. Teammates or tools review the changes and comment before they are accepted. In this app: the video's code changes go through pull requests that CodeRabbit reviews.
CodeRabbit
An AI service that reviews pull requests and comments on likely bugs and improvements. In this app: the video uses CodeRabbit; Socialix relies on pnpm typecheck, pnpm build and a browser test.

Testing and operations

Type check
Running the TypeScript checker over the whole project without building it, to catch type errors such as a missing field or a wrong argument. It is quick and catches many mistakes early. In this app: pnpm typecheck checks the project before a build.
Production build
Compiling and optimising an app for real use, as opposed to the development server that rebuilds on every change. A build also catches many errors that development mode lets through. In this app: pnpm build creates the production build and pnpm start serves it on port 3100.
Playwright
A library that controls a real browser from code: it opens pages, clicks, types and checks what appears. It is used for automated browser tests. In this app: scripts/e2e_test.py uses Playwright for Python to run 23 checks.
End-to-end (E2E) test
A test that uses the whole app the way a person would, from the browser through the server to the database, instead of testing one function alone. It catches problems that only appear when the parts work together. In this app: the E2E test signs in, chats with agents and runs a full post lifecycle; 23 of 23 checks pass.
Port
A number that tells a computer which program should receive network traffic; a web server listens on one port. Only one program can use a port at a time. In this app: Socialix uses port 3100 and the autopilot's dashboard uses 3000; EADDRINUSE :3100 means a server is already running there.
