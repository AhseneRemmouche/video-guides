How our Socialix is set up

We did not use the boilerplate. Our project contains only the files it needs, written with Claude Code, and its settings are split between two files. The folder layout also differs: our code lives under src/.

The steps

  1. Check the tools: node --version (22 or later), pnpm --version (install with npm install -g pnpm) and docker --version.
  2. Start the database the autopilot already uses: docker start wsa-pg, then docker ps --filter name=wsa-pg should show Up.
  3. Create the project folder (ours is C:\MLSCampus\social-media-ai-agent) with the files on this page, then run pnpm install in it.
  4. Create your settings file: Copy-Item .env.example .env, then open .env and check AUTOPILOT_DIR and APP_LOGIN_EMAIL.
  5. Later, in step 06, pnpm db:setup creates the database and fills in the login. Then pnpm dev starts the app at http://localhost:3100.

New to .env files? Settings that stay out of the code

An .env file is a plain text file of NAME=value lines. Programs read it at start-up so that settings (and secrets such as an API key) are not written inside the code. .env is never committed to git; .env.example is a template that lists the names with safe sample values.

The two .env files, and why secrets stay in the autopilot

The video keeps every key in its own .env. We have two:

  • Our .env holds only harmless settings plus the dashboard login: where the autopilot lives, our database name, the login email and password, the session secret and the model names.
  • The autopilot's .env already holds the Anthropic key, the database address with its password, and the WordPress site address. Our app reads it in place and never copies it.

Why: one copy of each secret is safer than two. If the Anthropic key changes, you change it in one place. And a mistake in our project (sharing the folder, committing .env) cannot leak the Claude key or the database password, because they are not in it.

src/lib/env.ts

This module reads both files and exposes a single config object.

import fs from "node:fs";
import path from "node:path";

/**
 * Settings for the whole app. Two sources:
 * 1. this project's .env (non-secret settings + the dashboard login), and
 * 2. the WordPress Social Autopilot's .env (Anthropic key, database URL, site URL), read in place so the
 *    secrets are never copied into this project.
 * Values are never logged.
 */

function parseEnvFile(file: string): Record<string, string> {
  if (!fs.existsSync(file)) return {};
  const out: Record<string, string> = {};
  for (const line of fs.readFileSync(file, "utf8").split(/\r?\n/)) {
    const m = /^([A-Z0-9_]+)=(.*)$/.exec(line.trim());
    if (!m) continue;
    let v = m[2]!.trim();
    if ((v.startsWith('"') && v.endsWith('"')) || (v.startsWith("'") && v.endsWith("'"))) v = v.slice(1, -1);
    out[m[1]!] = v;
  }
  return out;
}

const own = { ...parseEnvFile(path.join(process.cwd(), ".env")), ...process.env } as Record<string, string | undefined>;
const autopilotDir = own.AUTOPILOT_DIR ?? "C:/MLSCampus/wordpress-social-autopilot";
const autopilot = parseEnvFile(path.join(autopilotDir, ".env"));

function required(name: string, value: string | undefined, where: string): string {
  if (!value) throw new Error(`Missing ${name} (expected in ${where})`);
  return value;
}

/** The autopilot's database URL, pointed at another database on the same server. */
function withDatabase(url: string, db: string): string {
  const u = new URL(url);
  u.pathname = `/${db}`;
  u.searchParams.delete("schema");
  return u.toString();
}

export const config = {
  autopilotDir,
  get anthropicApiKey() {
    return required("ANTHROPIC_API_KEY", autopilot.ANTHROPIC_API_KEY, `${autopilotDir}/.env`);
  },
  /** The autopilot's own database (connected accounts, publish queue). */
  get autopilotDatabaseUrl() {
    const u = new URL(required("DATABASE_URL", autopilot.DATABASE_URL, `${autopilotDir}/.env`));
    u.searchParams.delete("schema"); // a Prisma-only parameter
    return u.toString();
  },
  /** This app's database: same server and login, its own database name. */
  get appDatabaseUrl() {
    return withDatabase(this.autopilotDatabaseUrl, own.APP_DATABASE_NAME ?? "social_media_ai_agent");
  },
  appDatabaseName: own.APP_DATABASE_NAME ?? "social_media_ai_agent",
  wordpressSiteUrl: autopilot.WORDPRESS_SITE_URL ?? "",
  loginEmail: own.APP_LOGIN_EMAIL ?? "owner@example.com",
  get loginPassword() {
    return required("APP_LOGIN_PASSWORD", own.APP_LOGIN_PASSWORD, ".env (run pnpm db:setup)");
  },
  get sessionSecret() {
    return required("SESSION_SECRET", own.SESSION_SECRET, ".env (run pnpm db:setup)");
  },
  modelSmart: own.MODEL_SMART ?? "claude-sonnet-5-5",
  modelFast: own.MODEL_FAST ?? "claude-haiku-5-5",
};

New to Tailwind? Utility classes instead of CSS files

With Tailwind CSS you style elements with short class names right in the markup: rounded-xl bg-white p-2 shadow-sm means rounded corners, white background, small padding, small shadow. At build time Tailwind scans your files and writes CSS only for the classes you used. Tailwind 4 is configured in CSS (the @theme block below) instead of a tailwind.config.js file.

Video vs our app.
  • The video generates the project with create-fastnextjs-app (shadcn, Drizzle Kit, Inngest); we write a small project by hand with pnpm.
  • The video's code sits in app/, db/ and lib/ at the root; ours is under src/ and imported with @/.
  • The video runs on port 3000; we use 3100 because the autopilot's dashboard uses 3000.
  • The video keeps all keys in one .env; we keep only the login there and read the Claude key and database address from the autopilot's .env.
  • The video's quick-helper agent is a Claude Code convenience for the developer, not part of the app. Our project does not include it; add it to your own project if you like.
What you should see
  • pnpm install ends without errors and creates node_modules.
  • pnpm typecheck prints nothing (no errors).
  • After step 06's pnpm db:setup, pnpm dev prints a local address with port 3100, and opening http://localhost:3100 lands on the sign-in page.
Common mistakes
  • Backslashes in AUTOPILOT_DIR. Write C:/MLSCampus/... with forward slashes.
  • Pasting the Anthropic key into our .env. It is not read from there. Keep it in the autopilot's .env only.
  • "Missing ANTHROPIC_API_KEY (expected in .../.env)": AUTOPILOT_DIR points to the wrong folder, or the key line is missing in the autopilot's file.
  • "Missing SESSION_SECRET": you have not run pnpm db:setup yet.
  • Editing .env while pnpm dev runs. Settings are read at start-up; stop the server (Ctrl+C) and start it again.
  • EADDRINUSE :3100: a Socialix server is already running. Use it, or stop the old one first.
  • Certificate errors when calling Claude on a PC with Norton or similar antivirus: start Node with $env:NODE_OPTIONS = "--use-system-ca" first.
  • Running commands outside the project folder. pnpm looks for package.json in the current folder.
Recap
  • The video generates its project with npx create-fastnextjs-app, picks shadcn, Postgres + Drizzle and Inngest, then installs Claude Code in VS Code and adds a Haiku helper agent.
  • Our Socialix is a small hand-written Next.js 16 project under src/, installed with pnpm, running on port 3100.
  • tsconfig.json sets strict TypeScript and the @/ shortcut; next.config.ts keeps pg and the MCP SDK out of the bundle; PostCSS + globals.css set up Tailwind 4 and our colours.
  • src/lib/env.ts reads our .env and the autopilot's .env into one config; secrets stay in the autopilot and are checked only when used.
