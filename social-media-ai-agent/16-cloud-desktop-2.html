What our app does: Research to Creator, through the database

Socialix's agents don't share a conversation. The Master Agent passes instructions to each team member (step 13), and anything bigger travels through the database. The Research Agent saves findings with save_research (step 15). The Creator Agent reads them with list_research, writes posts, and saves each one with save_draft. The Scheduler Agent then finds those drafts with list_drafts (step 18).

The Creator tools

These lines are from src/lib/ai/tools.ts; the complete file is on step 15.

const CHAR_LIMITS: Record<Platform, number> = { LINKEDIN: 3000, FACEBOOK: 500, INSTAGRAM: 2200, X: 280, TIKTOK: 2200, YOUTUBE: 5000 };

// ---------- Creator ----------

const listResearch = tool(
  "list_research",
  "List the research findings saved for this campaign, newest first.",
  z.object({ limit: z.number().int().min(1).max(20).default(10) }),
  async ({ limit }, ctx) => {
    const rows = await db.query.research.findMany({ where: eq(schema.research.campaignId, ctx.campaignId), orderBy: desc(schema.research.createdAt), limit });
    return rows.length ? rows.map(({ title, summary, sources }) => ({ title, summary, sources })) : "No research saved yet.";
  },
);

const saveDraft = tool(
  "save_draft",
  "Save a finished post as a draft for one platform.",
  z.object({
    platform: z.enum(PLATFORMS),
    title: z.string().describe("A short working title"),
    body: z.string().describe("The post text, ready to publish, without hashtags"),
    hashtags: z.array(z.string()).default([]).describe("Hashtags, each starting with #"),
    imageUrl: z.string().url().optional().describe("A real public image URL (required for Instagram and TikTok)"),
  }),
  async ({ platform, title, body, hashtags, imageUrl }, ctx) => {
    const campaign = await db.query.campaigns.findFirst({ where: eq(schema.campaigns.id, ctx.campaignId) });
    // The autopilot appends the link and the hashtags; count them so the post is never cut when published.
    const total = (hashtags.length ? `${body}\n\n${hashtags.join(" ")}` : body).length + (campaign?.link ? campaign.link.length + 1 : 0);
    if (total > CHAR_LIMITS[platform]) {
      return `Not saved: with hashtags and the link it is ${total} characters, but ${platform} allows ${CHAR_LIMITS[platform]}. Shorten it by at least ${total - CHAR_LIMITS[platform]} characters and call save_draft again.`;
    }
    const [row] = await db
      .insert(schema.posts)
      .values({ campaignId: ctx.campaignId, platform, title, body, hashtags, imageUrl: imageUrl ?? null, link: campaign?.link ?? "" })
      .returning({ id: schema.posts.id });
    const media = (platform === "INSTAGRAM" || platform === "TIKTOK") && !imageUrl ? ` Note: ${platform} needs an image before it can be published.` : "";
    return `Saved draft ${row!.id} for ${platform} (${total}/${CHAR_LIMITS[platform]} characters).${media}`;
  },
);

Lesson: Bug 1, the over-long X drafts

In an early version, save_draft did not check the length. During testing the Creator Agent saved four X drafts that were too long. The system prompt already said "X 280", but a model counting characters in its head is not reliable, and the hashtags and link added at publishing time made it worse. A post like that would be cut or refused by the network.

The fix was to stop trusting and start measuring: save_draft now counts the full published length (line 104) and refuses to save anything over the limit (lines 105-107). The Creator's prompt in src/lib/ai/agents.ts (line 95) also tells it to count hashtags and the link, and "If save_draft says a post is too long, shorten it and save again; only saved drafts count."

Tracking usage on every call

A team of agents makes many Claude calls for one request. To see what that costs, the agent loop records every call. In src/lib/ai/runner.ts (complete file on step 14), line 54 calls recordUsage right after each messages.create. Lines 23-26 (explained on step 15) store the agent, the model, the input and output tokens from msg.usage, and the number of web searches. The table is defined in src/lib/db/schema.ts:

/** Claude usage per agent call, so the dashboard can show what the team costs. */
export const usage = pgTable("usage", {
  id: id(),
  agent: text("agent").$type<AgentRole>().notNull(),
  model: text("model").notNull(),
  inputTokens: integer("input_tokens").notNull().default(0),
  outputTokens: integer("output_tokens").notNull().default(0),
  webSearches: integer("web_searches").notNull().default(0),
  createdAt: createdAt(),
});

Video vs our app. In the video this chapter adds a whole toolbox: research through the E2B desktop browser, copy generation, image generation with Gemini, ImageKit transforms and file storage, with results saved in InsForge. Socialix keeps the Creator to two tools, list_research and save_draft, and has no image generation (step 17). What it adds that the video doesn't show is a hard length check per network, and usage tracking for every Claude call so you can see what each agent costs.
What you should see
  • Ask the Creator Agent for an X post about your campaign. In our browser test it replied in about 8 seconds and the draft was measured at 262/280 characters.
  • The new draft appears on the Posts page under drafts, with its hashtags shown separately.
  • After a full Master run, the Analytics page lists each agent with its calls, tokens and searches, as in the table above (your numbers will differ).
Common mistakes
  • Counting only the body. The published post also contains the hashtags and the link. This is exactly how Bug 1 happened.
  • Putting hashtags inside the body. They are then counted and published twice. The schema description and the Creator prompt both say to keep them in the hashtags list.
  • Asking the Creator to write before any research exists. list_research answers "No research saved yet." Run the Research Agent first, or ask the Master Agent, which orders the tasks.
  • Reading the usage table as money. It stores tokens and searches, not prices. Multiply by the current prices of each model yourself if you need a cost.
Recap
  • The video adds research and creator toolboxes (E2B browser, Gemini images, ImageKit transforms) and saves outputs in the database.
  • In Socialix, research travels Research → research table → Creator via save_research and list_research.
  • save_draft measures body + blank line + hashtags + link against CHAR_LIMITS and refuses with "Not saved ... Shorten it by at least N characters" when it doesn't fit.
  • Bug 1 (four over-long X drafts) is why the check lives in code, not only in the prompt.
  • Every Claude call writes a usage row; the Analytics page sums them per agent.
