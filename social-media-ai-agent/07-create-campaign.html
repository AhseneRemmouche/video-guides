How our app creates a campaign

Three files work together: a form component with the fields, the page that shows it, and the server action that saves it. A fourth, src/lib/campaign.ts, answers "which campaign is open right now?" for every dashboard page.

New to server actions and FormData? What they are and why they matter

Normally a form needs an API endpoint: the browser sends the data, server code reads it, saves it and answers. A Next.js server action skips the endpoint you would write yourself. You write an async function in a file marked "use server" and pass it to <form action={…}>. When the form is submitted, Next.js sends the fields to the server and calls your function with them.

The fields arrive as a FormData object. formData.get("niche") returns the value of the input whose name is niche. A ticked checkbox sends the text "on"; an unticked one sends nothing at all.

src/app/dashboard/actions.ts

All server actions of the dashboard live in this one file. This page uses the first three. The rest are explained on the pages where their buttons appear; they are listed in the table so you know what is there.

"use server";

import { cookies } from "next/headers";
import { redirect } from "next/navigation";
import { revalidatePath } from "next/cache";
import { eq } from "drizzle-orm";
import { db, schema } from "@/lib/db";
import { PLATFORMS, type Platform } from "@/lib/db/schema";
import { destroySession, requireSession } from "@/lib/auth";
import { CAMPAIGN_COOKIE } from "@/lib/campaign";
import { cancelPost, handOffPost, setAutoPublish, syncStatuses } from "@/lib/publishing";

const str = (f: FormData, k: string) => String(f.get(k) ?? "").trim();

export async function createCampaign(formData: FormData) {
  await requireSession();
  const platforms = PLATFORMS.filter((p) => formData.get(`platform_${p}`) === "on");
  const [row] = await db
    .insert(schema.campaigns)
    .values({
      name: str(formData, "name") || "My campaign",
      niche: str(formData, "niche") || "general",
      audience: str(formData, "audience"),
      goal: str(formData, "goal"),
      tone: str(formData, "tone") || "friendly and clear",
      link: str(formData, "link"),
      platforms,
    })
    .returning({ id: schema.campaigns.id });
  (await cookies()).set(CAMPAIGN_COOKIE, row!.id, { path: "/", sameSite: "lax", maxAge: 365 * 24 * 3600 });
  redirect("/dashboard");
}

export async function updateCampaign(formData: FormData) {
  await requireSession();
  const id = str(formData, "id");
  const platforms = PLATFORMS.filter((p) => formData.get(`platform_${p}`) === "on");
  await db
    .update(schema.campaigns)
    .set({ name: str(formData, "name"), niche: str(formData, "niche"), audience: str(formData, "audience"), goal: str(formData, "goal"), tone: str(formData, "tone"), link: str(formData, "link"), platforms })
    .where(eq(schema.campaigns.id, id));
  revalidatePath("/dashboard", "layout");
}

export async function switchCampaign(formData: FormData) {
  await requireSession();
  (await cookies()).set(CAMPAIGN_COOKIE, str(formData, "id"), { path: "/", sameSite: "lax", maxAge: 365 * 24 * 3600 });
  revalidatePath("/dashboard", "layout");
}

export async function approvePost(formData: FormData) {
  await requireSession();
  await handOffPost(str(formData, "id"));
  revalidatePath("/dashboard", "layout");
}

export async function cancelPostAction(formData: FormData) {
  await requireSession();
  await cancelPost(str(formData, "id"));
  revalidatePath("/dashboard", "layout");
}

export async function deletePost(formData: FormData) {
  await requireSession();
  const id = str(formData, "id");
  const post = await db.query.posts.findFirst({ where: eq(schema.posts.id, id) });
  if (post && post.status !== "queued") await db.delete(schema.posts).where(eq(schema.posts.id, id));
  revalidatePath("/dashboard", "layout");
}

export async function createManualPost(formData: FormData) {
  await requireSession();
  const platform = str(formData, "platform") as Platform;
  if (!PLATFORMS.includes(platform)) return;
  const campaign = await db.query.campaigns.findFirst({ where: eq(schema.campaigns.id, str(formData, "campaignId")) });
  if (!campaign) return;
  const when = str(formData, "scheduledAt");
  await db.insert(schema.posts).values({
    campaignId: campaign.id,
    platform,
    title: str(formData, "title") || "Untitled post",
    body: str(formData, "body"),
    hashtags: str(formData, "hashtags").split(/[\s,]+/).filter((h) => h.startsWith("#")),
    imageUrl: str(formData, "imageUrl") || null,
    link: campaign.link,
    scheduledAt: when ? new Date(when) : null,
    status: when ? "awaiting_approval" : "draft",
  });
  revalidatePath("/dashboard", "layout");
}

export async function setAutoPublishAction(formData: FormData) {
  await requireSession();
  await setAutoPublish(formData.get("autoPublish") === "on");
  revalidatePath("/dashboard", "layout");
}

export async function refreshStatuses() {
  await requireSession();
  await syncStatuses();
  revalidatePath("/dashboard", "layout");
}

export async function signOut() {
  await destroySession();
  redirect("/signin");
}

New to cookie options? What path, sameSite and maxAge mean

When the server sets a cookie it can add rules. path: "/" sends the cookie with requests to every page of the site, not only the page that set it. sameSite: "lax" tells the browser not to send it along when another website posts a form to ours, which blocks a whole family of tricks (cross-site request forgery). maxAge is the lifetime in seconds: 365 * 24 * 3600 is one year. Without maxAge the cookie would disappear when the browser closes.

Two more options appear on the session cookie in step 06: httpOnly (JavaScript cannot read it) and secure (sent over HTTPS only). The campaign cookie skips them because it only remembers which campaign is open.

src/lib/campaign.ts

Every dashboard page needs the open campaign. This file has the two helpers they use.

import { cookies } from "next/headers";
import { desc, eq } from "drizzle-orm";
import { db, schema } from "@/lib/db";

export const CAMPAIGN_COOKIE = "socialix_campaign";

export async function listCampaigns() {
  return db.query.campaigns.findMany({ orderBy: desc(schema.campaigns.createdAt) });
}

/** The campaign chosen in the sidebar (cookie), or the newest one. */
export async function getCurrentCampaign() {
  const id = (await cookies()).get(CAMPAIGN_COOKIE)?.value;
  if (id) {
    const c = await db.query.campaigns.findFirst({ where: eq(schema.campaigns.id, id) });
    if (c) return c;
  }
  return (await db.query.campaigns.findFirst({ orderBy: desc(schema.campaigns.createdAt) })) ?? null;
}

export type Campaign = NonNullable<Awaited<ReturnType<typeof getCurrentCampaign>>>;

Common mistakes
  • Input name and action key do not match. If the form says name="niche" and the action reads "topic", the value is silently empty and the fallback "general" is saved. Keep the names identical.
  • Forgetting requireSession() in a new action. Anyone who finds the endpoint could then create or change data without signing in. Every action in actions.ts starts with it, except signOut.
  • Adding a field in one place only. A new brief field must be added to schema.ts, the SQL in db-setup.ts, CampaignFields, and both createCampaign and updateCampaign.
  • Expecting unticked checkboxes in the data. They are not sent at all, which is why the code tests === "on" for each platform instead of reading a list.
  • Calling redirect() inside try. redirect works by throwing a special error. A surrounding try/catch would swallow it and the page would not move. Our actions call it last, outside any try.
Video vs our app
  • Form: the video builds a two-step wizard (name and icon, then office picture) with icon upload to InsForge storage. Ours is one form with the brief the agents read: name, niche, audience, goal, tone, link, platforms.
  • Uploads: the video raises serverActions.bodySizeLimit to 3 MB for icon uploads. We upload nothing, so our next.config.ts needs no such setting.
  • Office: the video stores the chosen office picture per campaign. We draw one SVG office in code (step 10).
  • Owner: the video stores the user id with each campaign. With a single owner, our campaigns have no user column.
  • Open campaign: ours is remembered in the socialix_campaign cookie and switched from the sidebar (next page).
Recap
  • A campaign is the brief every agent reads; posts, tasks and research belong to one.
  • CampaignFields holds the inputs and is shared by the new-campaign and Settings pages.
  • createCampaign checks the session, turns ticked boxes into a platform list, inserts the row, stores its id in a cookie and redirects.
  • getCurrentCampaign uses the cookie, then the newest campaign, then null, which sends a new owner to the form.
  • actions.ts holds every dashboard action; the others appear on later pages.
