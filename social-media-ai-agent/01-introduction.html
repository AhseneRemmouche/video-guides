New to AI agents? What they are and why they matter

A large language model (LLM) such as Claude reads text and writes text. On its own it cannot search the web, save a file or schedule a post. An agent is an LLM plus a set of tools (small functions your program offers it) plus a loop: the model decides which tool to call, your program runs it and sends back the result, and the model continues until the job is done.

In Socialix, "save this draft" and "schedule this post" are tools. The model chooses when to use them; our code decides what they are allowed to do. That split is what keeps an AI app safe.

New to multi-agent teams? Why split the work across several agents

A multi-agent app gives each agent one job and a short list of tools. A master agent talks to you, breaks your request into tasks and hands each task to a sub-agent. Small, focused agents are easier to instruct, cheaper (simple jobs can use a smaller model) and easier to debug: when a post is too long, you know it was the Creator.

How our version differs from the video

We kept the app and the agent team, and swapped the outside services. The main reasons: the owner already runs a "WordPress Social Autopilot" that holds their connected social accounts and publishes posts reliably, and we wanted no extra paid cloud accounts. Step 03 explains each swap in detail.

Video vs our app. Our Socialix also adds one safety rule the video does not have: auto-publish is off by default, so every post the agents schedule waits for you to press Approve. And our app never sees the social media passwords or tokens; those stay inside the autopilot.

What you need

  • Windows with Node.js 22 or later and pnpm.
  • Docker Desktop, which runs the Postgres database.
  • The WordPress Social Autopilot installed, with your social accounts connected, and an API key for Claude in its settings file.
  • Basic comfort with a terminal (PowerShell) and a code editor. Everything else is explained as we go.
What you should see by the end of the guide: a dashboard at http://localhost:3100 where you type a request such as "Research 2 trending topics about AI tools for small businesses this week, then write one LinkedIn post and one X post about the best one, and schedule them for tomorrow at good times." In our test run the Master Agent sent the work to Research, then Creator, then Scheduler, and ended with a LinkedIn post and an X post for the next day, both awaiting approval.
Common mistakes
  • Signing up for Blotato, InsForge, Inngest, E2B or ImageKit to follow our code. Our version does not use them; you only need the services listed above.
  • Expecting the agents to post straight away. With auto-publish off (the default), posts wait on the Posts page until you press Approve.
  • Copying the video's OpenAI code into our project. The agent code in this guide is written for Claude and will not work with OpenAI keys.
