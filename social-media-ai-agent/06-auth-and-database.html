Auth & Database Setup

Single-owner sign-in with a signed cookie, and the Postgres tables with Drizzle ORM.

▶ Watch this part (00:25:17)

Every dashboard needs two things before it can hold real work: a way to keep strangers out (authentication) and a place to store data that survives a restart (a database). In this chapter the video sets up both with one hosted service, InsForge. Socialix has a single owner, so it uses a much smaller design: one email and password from the .env file, a signed session cookie, and a local Postgres database reached through Drizzle ORM. You will read all five files that do this.

How our app signs the owner in

New to session cookies and JWTs? What they are and why they matter

A web server forgets you between requests. After you sign in, it gives your browser a small piece of text, a cookie, which the browser sends back with every request. If the cookie proves "this is the owner", the server lets you in.

The proof must be impossible to fake. We use a JWT (JSON Web Token): a short JSON message such as {"sub": "owner@example.com", "exp": …} plus a signature made with a secret only the server knows (SESSION_SECRET). If anyone changes one character, the signature no longer matches and the server rejects the token.

The cookie is httpOnly: JavaScript in the page cannot read it, so a script injected into the page cannot steal the session.

src/lib/auth.ts

All login logic lives in one small file. It reads the login and the secret from config (the settings object from src/lib/env.ts, shown on the Project Setup page).

import crypto from "node:crypto";
import { cookies } from "next/headers";
import { redirect } from "next/navigation";
import { SignJWT, jwtVerify } from "jose";
import { config } from "@/lib/env";

/** Single-owner login: email + password from .env, a signed session cookie for 7 days. */

const COOKIE = "socialix_session";
const key = () => new TextEncoder().encode(config.sessionSecret);

function same(a: string, b: string): boolean {
  const x = Buffer.from(a);
  const y = Buffer.from(b);
  return x.length === y.length && crypto.timingSafeEqual(x, y);
}

export function checkLogin(email: string, password: string): boolean {
  return same(email.trim().toLowerCase(), config.loginEmail.toLowerCase()) && same(password, config.loginPassword);
}

export async function createSession(): Promise<void> {
  const token = await new SignJWT({ sub: config.loginEmail }).setProtectedHeader({ alg: "HS256" }).setIssuedAt().setExpirationTime("7d").sign(key());
  (await cookies()).set(COOKIE, token, { httpOnly: true, sameSite: "lax", secure: process.env.NODE_ENV === "production", path: "/", maxAge: 7 * 24 * 3600 });
}

export async function destroySession(): Promise<void> {
  (await cookies()).delete(COOKIE);
}

export async function getSession(): Promise<string | null> {
  const token = (await cookies()).get(COOKIE)?.value;
  if (!token) return null;
  try {
    const { payload } = await jwtVerify(token, key());
    return typeof payload.sub === "string" ? payload.sub : null;
  } catch {
    return null;
  }
}

/** For pages and server actions: the owner's email, or a redirect to the sign-in page. */
export async function requireSession(): Promise<string> {
  const who = await getSession();
  if (!who) redirect("/signin");
  return who;
}

src/app/signin/page.tsx

The sign-in page is a server component with an inline server action. There is no client-side JavaScript in it: the browser posts a normal form.

import { redirect } from "next/navigation";
import { checkLogin, createSession, getSession } from "@/lib/auth";
import { Logo } from "@/components/logo";

async function signIn(formData: FormData) {
  "use server";
  const email = String(formData.get("email") ?? "");
  const password = String(formData.get("password") ?? "");
  if (!checkLogin(email, password)) redirect("/signin?error=1");
  await createSession();
  redirect("/dashboard");
}

export default async function SignInPage({ searchParams }: { searchParams: Promise<{ error?: string }> }) {
  if (await getSession()) redirect("/dashboard");
  const { error } = await searchParams;
  return (

        <p className="mt-1 text-sm text-gray-500">Sign in to brief your AI team.</p>
        {error && <p className="mt-4 rounded-xl bg-red-50 px-3 py-2 text-sm text-red-700">Wrong email or password.</p>}
        <label className="mt-6 block text-sm font-medium">
          Email
          <input name="email" type="email" required autoComplete="username" className="mt-1 w-full rounded-xl border border-gray-200 px-3 py-2 outline-none focus:border-brand-500" />
        </label>
        <label className="mt-4 block text-sm font-medium">
          Password
          <input name="password" type="password" required autoComplete="current-password" className="mt-1 w-full rounded-xl border border-gray-200 px-3 py-2 outline-none focus:border-brand-500" />
        </label>
        <button className="mt-6 w-full rounded-xl bg-brand-600 py-2.5 font-medium text-white hover:bg-brand-700">Sign in</button>
        <p className="mt-4 text-xs text-gray-400">The login is set in this project&apos;s .env file (APP_LOGIN_EMAIL, APP_LOGIN_PASSWORD).</p>

How our app stores data

New to ORMs and Drizzle? What they are and why they matter

A database speaks SQL: select * from posts where campaign_id = '…'. An ORM (object-relational mapper) lets you write that in TypeScript instead: db.query.posts.findMany({ where: eq(schema.posts.campaignId, id) }). The big win is types. Drizzle knows every table and column from schema.ts, so a typo in a column name is a type error, and the rows you get back have the right types.

A schema is the description of the tables: names, columns, types, defaults and links between tables.

src/lib/db/schema.ts

Socialix has seven tables. Unlike the video, there is no users table: the one owner is in .env.

import { integer, jsonb, pgTable, text, timestamp } from "drizzle-orm/pg-core";

/** This app's own tables. The social accounts and the publish queue live in the autopilot's database. */

export const AGENTS = ["master", "research", "creator", "scheduler", "analytics"] as const;
export type AgentRole = (typeof AGENTS)[number];

export const PLATFORMS = ["LINKEDIN", "FACEBOOK", "INSTAGRAM", "X", "TIKTOK", "YOUTUBE"] as const;
export type Platform = (typeof PLATFORMS)[number];

const id = () =>
  text("id")
    .primaryKey()
    .$defaultFn(() => crypto.randomUUID());
const createdAt = () => timestamp("created_at", { withTimezone: true }).notNull().defaultNow();

export const campaigns = pgTable("campaigns", {
  id: id(),
  name: text("name").notNull(),
  niche: text("niche").notNull(),
  audience: text("audience").notNull().default(""),
  goal: text("goal").notNull().default(""),
  tone: text("tone").notNull().default("friendly and clear"),
  link: text("link").notNull().default(""), // the URL posts point back to
  platforms: text("platforms").array().notNull().default([]),
  createdAt: createdAt(),
});

/** Chat history, one thread per agent per campaign. */
export const agentMessages = pgTable("agent_messages", {
  id: id(),
  campaignId: text("campaign_id")
    .notNull()
    .references(() => campaigns.id, { onDelete: "cascade" }),
  agent: text("agent").$type<AgentRole>().notNull(),
  role: text("role").$type<"user" | "assistant">().notNull(),
  content: text("content").notNull(),
  createdAt: createdAt(),
});

export type TaskStatus = "queued" | "running" | "done" | "failed";

/** Work the Master Agent hands to a team member. */
export const agentTasks = pgTable("agent_tasks", {
  id: id(),
  campaignId: text("campaign_id")
    .notNull()
    .references(() => campaigns.id, { onDelete: "cascade" }),
  agent: text("agent").$type<AgentRole>().notNull(),
  title: text("title").notNull(),
  instructions: text("instructions").notNull().default(""),
  status: text("status").$type<TaskStatus>().notNull().default("queued"),
  result: text("result").notNull().default(""),
  createdAt: createdAt(),
  updatedAt: timestamp("updated_at", { withTimezone: true }).notNull().defaultNow(),
});

/** Findings saved by the Research Agent. */
export const research = pgTable("research", {
  id: id(),
  campaignId: text("campaign_id")
    .notNull()
    .references(() => campaigns.id, { onDelete: "cascade" }),
  title: text("title").notNull(),
  summary: text("summary").notNull(),
  sources: jsonb("sources").$type<{ title: string; url: string }[]>().notNull().default([]),
  createdAt: createdAt(),
});

export type PostStatus = "draft" | "awaiting_approval" | "queued" | "published" | "failed" | "cancelled";

/** Posts written by the Creator Agent and scheduled by the Scheduler Agent. */
export const posts = pgTable("posts", {
  id: id(),
  campaignId: text("campaign_id")
    .notNull()
    .references(() => campaigns.id, { onDelete: "cascade" }),
  platform: text("platform").$type<Platform>().notNull(),
  title: text("title").notNull(),
  body: text("body").notNull(),
  hashtags: text("hashtags").array().notNull().default([]),
  link: text("link").notNull().default(""),
  imageUrl: text("image_url"),
  status: text("status").$type<PostStatus>().notNull().default("draft"),
  scheduledAt: timestamp("scheduled_at", { withTimezone: true }),
  /** id of the content row in the autopilot's database once handed over for publishing */
  autopilotContentId: text("autopilot_content_id"),
  externalUrl: text("external_url"),
  error: text("error"),
  createdAt: createdAt(),
  updatedAt: timestamp("updated_at", { withTimezone: true }).notNull().defaultNow(),
});

export const settings = pgTable("settings", {
  key: text("key").primaryKey(),
  value: jsonb("value").notNull(),
});

/** Claude usage per agent call, so the dashboard can show what the team costs. */
export const usage = pgTable("usage", {
  id: id(),
  agent: text("agent").$type<AgentRole>().notNull(),
  model: text("model").notNull(),
  inputTokens: integer("input_tokens").notNull().default(0),
  outputTokens: integer("output_tokens").notNull().default(0),
  webSearches: integer("web_searches").notNull().default(0),
  createdAt: createdAt(),
});

// One pool per process, reused across hot reloads in development.
const g = globalThis as unknown as { __appPool?: pg.Pool };
const pool = g.__appPool ?? new pg.Pool({ connectionString: config.appDatabaseUrl, max: 5 });
if (process.env.NODE_ENV !== "production") g.__appPool = pool;

export const db = drizzle(pool, { schema });
export { schema };

scripts/db-setup.ts

The video creates tables with drizzle-kit push. We do not install drizzle-kit. One script, run with pnpm db:setup, creates the database, the tables and the dashboard login. It is safe to run again.

// Creates this app's database (next to the autopilot's: same server and login), its tables, and the
// dashboard login in .env if missing. Safe to run again. Prints no secrets.
import crypto from "node:crypto";
import fs from "node:fs";
import pg from "pg";
import { config } from "../src/lib/env";

const TABLES = `
create table if not exists campaigns (
  id text primary key, name text not null, niche text not null, audience text not null default '',
  goal text not null default '', tone text not null default 'friendly and clear', link text not null default '',
  platforms text[] not null default '{}', created_at timestamptz not null default now());
create table if not exists agent_messages (
  id text primary key, campaign_id text not null references campaigns(id) on delete cascade,
  agent text not null, role text not null, content text not null, created_at timestamptz not null default now());
create table if not exists agent_tasks (
  id text primary key, campaign_id text not null references campaigns(id) on delete cascade,
  agent text not null, title text not null, instructions text not null default '', status text not null default 'queued',
  result text not null default '', created_at timestamptz not null default now(), updated_at timestamptz not null default now());
create table if not exists research (
  id text primary key, campaign_id text not null references campaigns(id) on delete cascade,
  title text not null, summary text not null, sources jsonb not null default '[]', created_at timestamptz not null default now());
create table if not exists posts (
  id text primary key, campaign_id text not null references campaigns(id) on delete cascade,
  platform text not null, title text not null, body text not null, hashtags text[] not null default '{}',
  link text not null default '', image_url text, status text not null default 'draft', scheduled_at timestamptz,
  autopilot_content_id text, external_url text, error text,
  created_at timestamptz not null default now(), updated_at timestamptz not null default now());
create table if not exists settings (key text primary key, value jsonb not null);
create table if not exists usage (
  id text primary key, agent text not null, model text not null, input_tokens integer not null default 0,
  output_tokens integer not null default 0, web_searches integer not null default 0, created_at timestamptz not null default now());
insert into settings (key, value) values ('autoPublish', 'false') on conflict do nothing;
`;

async function main() {
  // 1. The database itself
  const admin = new pg.Client({ connectionString: config.autopilotDatabaseUrl });
  await admin.connect();
  const exists = await admin.query("select 1 from pg_database where datname = $1", [config.appDatabaseName]);
  if (exists.rowCount === 0) {
    await admin.query(`create database "${config.appDatabaseName.replace(/"/g, "")}"`);
    console.log(`created database ${config.appDatabaseName}`);
  } else console.log(`database ${config.appDatabaseName} already exists`);
  await admin.end();

  // 2. Tables
  const c = new pg.Client({ connectionString: config.appDatabaseUrl });
  await c.connect();
  await c.query(TABLES);
  await c.end();
  console.log("tables ready");

  // 3. Dashboard login, generated once. Read it from .env; it is not printed.
  const envFile = ".env";
  let text = fs.existsSync(envFile) ? fs.readFileSync(envFile, "utf8") : fs.readFileSync(".env.example", "utf8");
  const setIfEmpty = (key: string, value: string) => {
    const re = new RegExp(`^${key}=(.*)$`, "m");
    const m = re.exec(text);
    if (m && m[1]!.trim()) return;
    text = m ? text.replace(re, `${key}=${value}`) : `${text.trimEnd()}\n${key}=${value}\n`;
    console.log(`generated ${key} in .env`);
  };
  setIfEmpty("APP_LOGIN_PASSWORD", crypto.randomBytes(12).toString("base64url"));
  setIfEmpty("SESSION_SECRET", crypto.randomBytes(32).toString("base64url"));
  fs.writeFileSync(envFile, text);
}

main().catch((e) => {
  console.error("db setup failed:", e instanceof Error ? e.message : e);
  process.exit(1);
});

Common mistakes
  • Database not running. db setup failed: … ECONNREFUSED … 5433. Start Docker Desktop, then docker start wsa-pg.
  • Skipped pnpm db:setup. Signing in fails with Missing SESSION_SECRET (expected in .env (run pnpm db:setup)) or the same for APP_LOGIN_PASSWORD. Run the script.
  • Wrong AUTOPILOT_DIR. Missing DATABASE_URL (expected in …/.env): the path in our .env does not point to the autopilot's folder.
  • Changing SESSION_SECRET. Every existing cookie stops verifying, so you are signed out. That is also the quick way to sign out every browser at once.
  • Adding a column only in schema.ts. Drizzle then queries a column the database does not have and Postgres answers "column … does not exist". Add it to the SQL in db-setup.ts too (for an existing table, with alter table … add column …, because create table if not exists skips tables that exist).
Video vs our app
  • Auth: the video uses InsForge sign-in (Google, GitHub, email) for any number of users and saves each user in a users table. Socialix has one owner: email and password in .env, checked in constant time, and a 7-day HS256 JWT in an httpOnly cookie.
  • Database: the video uses InsForge's hosted Postgres. We use the Postgres server that already runs for the WordPress Social Autopilot (Docker container wsa-pg), with our own database social_media_ai_agent.
  • Tables: the video runs drizzle-kit push and browses with Drizzle Studio. We create tables with plain SQL in scripts/db-setup.ts and use Drizzle ORM 0.45.4 only for queries.
  • Setup: the video lets Claude Code configure InsForge through its CLI. Ours is one command, pnpm db:setup, which also generates the login.
Recap
  • The video sets up InsForge for auth and a hosted database, pushes a users table and adds Google sign-in through one Claude Code prompt.
  • Socialix signs in one owner: checkLogin compares in constant time, createSession sets a signed 7-day cookie, requireSession guards pages.
  • Seven tables live in schema.ts; four of them belong to a campaign and are deleted with it.
  • db/index.ts keeps one connection pool, even across hot reloads.
  • pnpm db:setup creates the database, the tables and the login, and never prints a secret.
