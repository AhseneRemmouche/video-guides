Dashboard Layout

The sidebar, campaign picker and page shell shared by every dashboard page.

▶ Watch this part (00:43:32)

Every page of the dashboard shares the same frame: a sidebar with the logo, the campaign picker and the menu, and a content area on the right. In Next.js you build that frame once, in a layout, and every page inside the folder is rendered inside it. This chapter builds that shell. You will read the layout, the sidebar, the logo and the small set of shared UI pieces (ui.tsx) that later pages use for cards, headers and badges.

New to layouts in the App Router? What they are and why they matter

In the Next.js App Router, folders are URLs: src/app/dashboard/posts/page.tsx is the page at /dashboard/posts. A layout.tsx file in a folder wraps every page in that folder and its sub-folders. It receives the page as the children prop and decides where to put it.

When you move between pages in the same layout, Next.js keeps the layout on screen and swaps only children. That is why the sidebar does not flash on every click.

How our app builds the shell

src/app/dashboard/layout.tsx

The layout is a server component. It checks the session, loads the campaigns, builds the campaign picker and the footer, and hands them to the sidebar.

import Link from "next/link";
import { LogOut, Plus } from "lucide-react";
import { requireSession } from "@/lib/auth";
import { getCurrentCampaign, listCampaigns } from "@/lib/campaign";
import { MobileNav, Sidebar } from "@/components/sidebar";
import { signOut, switchCampaign } from "./actions";

export const dynamic = "force-dynamic";

export default async function DashboardLayout({ children }: { children: React.ReactNode }) {
  const owner = await requireSession();
  const [current, all] = await Promise.all([getCurrentCampaign(), listCampaigns()]);

  const picker = (
    <div className="rounded-2xl border border-gray-100 bg-gray-50 p-3">
      <p className="text-xs font-semibold uppercase tracking-wide text-gray-400">Campaign</p>
      {current ? (
        <form action={switchCampaign} className="mt-1">
          <select name="id" defaultValue={current.id} className="w-full bg-transparent text-sm font-semibold outline-none">
            {all.map((c) => (
              <option key={c.id} value={c.id}>
                {c.name}
              </option>
            ))}
          </select>
          <div className="mt-2 flex gap-2">
            <button className="rounded-lg bg-white px-2 py-1 text-xs text-gray-600 shadow-sm">Switch</button>
            <Link href="/dashboard/campaigns/new" className="flex items-center gap-1 rounded-lg bg-white px-2 py-1 text-xs text-gray-600 shadow-sm">
              <Plus size={12} /> New
            </Link>
          </div>
        </form>
      ) : (
        <Link href="/dashboard/campaigns/new" className="mt-1 block text-sm font-semibold text-brand-600">
          Create your first campaign
        </Link>
      )}
    </div>
  );

  const footer = (
    <form action={signOut} className="flex items-center justify-between rounded-xl px-3 py-2 text-sm text-gray-500">
      <span className="truncate">{owner}</span>
      <button title="Sign out" className="rounded-lg p-1 hover:bg-gray-100">
        <LogOut size={16} />
      </button>
    </form>
  );

  return (
    <div className="flex min-h-screen">
      <Sidebar campaignPicker={picker} footer={footer} />
      <div className="min-w-0 flex-1">
        <MobileNav />
        <main className="mx-auto max-w-7xl p-4 md:p-8">{children}</main>
      </div>
    </div>
  );
}

New to server and client components? Why the sidebar is split this way

A server component runs only on the server. It can await the database and read cookies, and it sends finished HTML. A client component (a file starting with "use client") also runs in the browser, so it can use hooks such as usePathname and react to clicks.

The sidebar must know the current URL to highlight the active link, so it is a client component. But the campaign list comes from the database, which only the server can reach. The solution: the server layout builds the picker and passes it in as a prop. A client component may receive server-rendered JSX as props and simply place it.

src/components/sidebar.tsx

"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";
import { BarChart3, Bot, CalendarDays, FileText, LayoutGrid, Link2, Settings } from "lucide-react";
import { Logo } from "./logo";

const NAV = [
  { href: "/dashboard", label: "Overview", icon: LayoutGrid },
  { href: "/dashboard/ai-agent", label: "AI Agent", icon: Bot },
  { href: "/dashboard/posts", label: "Posts", icon: FileText },
  { href: "/dashboard/calendar", label: "Calendar", icon: CalendarDays },
  { href: "/dashboard/analytics", label: "Analytics", icon: BarChart3 },
  { href: "/dashboard/accounts", label: "Accounts", icon: Link2 },
];

export function Sidebar({ campaignPicker, footer }: { campaignPicker: React.ReactNode; footer: React.ReactNode }) {
  const path = usePathname();
  const item = (href: string, label: string, Icon: typeof LayoutGrid) => {
    const active = href === "/dashboard" ? path === href : path.startsWith(href);
    return (
      <Link key={href} href={href} className={`flex items-center gap-3 rounded-xl px-3 py-2 text-sm font-medium transition ${active ? "bg-brand-600 text-white shadow-md shadow-indigo-200" : "text-gray-600 hover:bg-gray-100"}`}>
        <Icon size={18} />
        {label}
      </Link>
    );
  };
  return (
    <aside className="sticky top-0 hidden h-screen w-64 shrink-0 flex-col gap-4 border-r border-gray-100 bg-white p-4 md:flex">
      <Logo />
      {campaignPicker}
      <nav className="flex flex-col gap-1">
        <p className="px-3 pt-2 text-xs font-semibold uppercase tracking-wide text-gray-400">Menu</p>
        {NAV.map((n) => item(n.href, n.label, n.icon))}
      </nav>
      <div className="mt-auto flex flex-col gap-1">
        {item("/dashboard/settings", "Settings", Settings)}
        {footer}
      </div>
    </aside>
  );
}

export function MobileNav() {
  const path = usePathname();
  return (
    <nav className="flex gap-1 overflow-x-auto border-b border-gray-100 bg-white px-3 py-2 md:hidden">
      {[...NAV, { href: "/dashboard/settings", label: "Settings", icon: Settings }].map(({ href, label }) => {
        const active = href === "/dashboard" ? path === href : path.startsWith(href);
        return (
          <Link key={href} href={href} className={`whitespace-nowrap rounded-lg px-3 py-1.5 text-sm ${active ? "bg-brand-600 text-white" : "text-gray-600"}`}>
            {label}
          </Link>
        );
      })}
    </nav>
  );
}

A handful of tiny building blocks used by almost every page. Writing them once keeps the pages short and the look consistent.

import type { Platform, PostStatus } from "@/lib/db/schema";

export const PLATFORM_LABEL: Record<Platform, string> = {
  LINKEDIN: "LinkedIn",
  FACEBOOK: "Facebook",
  INSTAGRAM: "Instagram",
  X: "X",
  TIKTOK: "TikTok",
  YOUTUBE: "YouTube",
};

const PLATFORM_STYLE: Record<Platform, string> = {
  LINKEDIN: "bg-[#0a66c2] text-white",
  FACEBOOK: "bg-[#1877f2] text-white",
  INSTAGRAM: "bg-gradient-to-br from-[#f58529] via-[#dd2a7b] to-[#8134af] text-white",
  X: "bg-black text-white",
  TIKTOK: "bg-[#111] text-white",
  YOUTUBE: "bg-[#ff0000] text-white",
};

const PLATFORM_LETTER: Record<Platform, string> = { LINKEDIN: "in", FACEBOOK: "f", INSTAGRAM: "IG", X: "X", TIKTOK: "TT", YOUTUBE: "▶" };

export function PlatformBadge({ platform, size = "md" }: { platform: Platform; size?: "sm" | "md" }) {
  const s = size === "sm" ? "size-6 text-[10px]" : "size-8 text-xs";
  return (
    <span title={PLATFORM_LABEL[platform]} className={`inline-grid shrink-0 place-items-center rounded-lg font-bold ${s} ${PLATFORM_STYLE[platform]}`}>
      {PLATFORM_LETTER[platform]}
    </span>
  );
}

const STATUS_STYLE: Record<PostStatus, string> = {
  draft: "bg-gray-100 text-gray-700",
  awaiting_approval: "bg-amber-100 text-amber-800",
  queued: "bg-sky-100 text-sky-800",
  published: "bg-emerald-100 text-emerald-800",
  failed: "bg-red-100 text-red-700",
  cancelled: "bg-gray-100 text-gray-500",
};
const STATUS_LABEL: Record<PostStatus, string> = {
  draft: "Draft",
  awaiting_approval: "Awaiting approval",
  queued: "Queued",
  published: "Published",
  failed: "Failed",
  cancelled: "Cancelled",
};

export function StatusBadge({ status }: { status: PostStatus }) {
  return <span className={`inline-block max-w-full truncate rounded-full px-2 py-0.5 text-xs font-medium ${STATUS_STYLE[status]}`}>{STATUS_LABEL[status]}</span>;
}

export function Card({ children, className = "" }: { children: React.ReactNode; className?: string }) {
  return <section className={`rounded-3xl bg-white p-5 shadow-sm shadow-gray-200/60 ${className}`}>{children}</section>;
}

export function PageHeader({ title, subtitle, children }: { title: string; subtitle?: string; children?: React.ReactNode }) {
  return (
    <div className="mb-6 flex flex-wrap items-end justify-between gap-3">
      <div>
        <h1 className="text-2xl font-semibold tracking-tight">{title}</h1>
        {subtitle && <p className="text-sm text-gray-500">{subtitle}</p>}
      </div>
      {children}
    </div>
  );
}

export function formatWhen(d: Date | null): string {
  if (!d) return "Not scheduled";
  return d.toLocaleString("en-US", { weekday: "short", month: "short", day: "numeric", hour: "numeric", minute: "2-digit" });
}

What you should see. On a wide window, every dashboard page has the white sidebar on the left: the Socialix logo, the CAMPAIGN box with a drop-down, Switch and + New, the six menu items with the current one in blue, Settings at the bottom and your email with a sign-out icon. Make the window narrow and the sidebar disappears; a row of links appears above the page instead.
Common mistakes
  • Using usePathname without "use client". Next.js stops with an error saying the hook only works in a client component. Keep the directive at the very top of sidebar.tsx.
  • Querying the database inside the sidebar. A client component cannot import @/lib/db (it would try to bundle the database driver for the browser). Load data in the layout and pass it down, as we do with campaignPicker.
  • Overview always highlighted. If you use startsWith for every item, Overview matches every page. Keep the exact-match case for /dashboard.
  • Expecting the drop-down to switch by itself. Choosing a campaign in the list changes nothing until you click Switch, because the form is only sent then.
  • Removing force-dynamic. Pages could then be served from a cache made at build time, showing an old campaign list.
Video vs our app
  • Collapse: the video's sidebar is icon-only by default and expands (shortcut ⌘ B). Ours always shows icons with labels; Logo already has a compact option if you want to add collapsing.
  • Header: the video adds a header with search, notifications, Create post and an avatar. We have none; each page has a PageHeader with its title, subtitle and page-specific buttons (the Overview's is Brief the team).
  • Campaign switcher: the video uses a custom drop-down menu. Ours is a native <select> with a Switch button and a + New link: no client JavaScript, and it works with the keyboard out of the box.
  • Phones: we add a MobileNav row of links for small screens.
  • Placeholders: the video shows "coming soon" pages at this point. In our finished app every menu item already leads to a real page.
Recap
  • dashboard/layout.tsx wraps every dashboard page: it guards sign-in, loads campaigns and builds the picker and footer.
  • sidebar.tsx is a client component because it needs usePathname for the active link; it receives server-built pieces as props.
  • One NAV list drives both the desktop sidebar and the phone menu.
  • logo.tsx is the gradient sparkle mark plus the name.
  • ui.tsx holds the shared badges, Card, PageHeader and formatWhen used across the app.
