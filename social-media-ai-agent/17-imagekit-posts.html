ImageKit to Create Posts

AI images with ImageKit in the video; in our app, image URLs for Instagram and TikTok posts.

▶ Watch this part (02:07:27)

Instagram and TikTok are visual networks: a post there needs an image. This step looks at how images get into posts. The video adds AI image editing with ImageKit and a full "Create Post" page. Our app takes a much smaller route: a post can carry the address of an image that already exists on the web, and the publishing path refuses an Instagram or TikTok post that has none. Socialix does not generate images.

New to URL-based image transforms? How ImageKit-style URLs work

You upload an image once. Instead of saving a new file for every size or effect, you ask for a variant by changing the URL. The service reads the parameters, builds that version, caches it and returns it. For ImageKit the parameters go after ?tr=, for example width and height:

https://ik.imagekit.io/<your_id>/photo.jpg               original
https://ik.imagekit.io/<your_id>/photo.jpg?tr=w-400,h-300  400 x 300 version

That is why the video's cropped image "updated to the URL only": the edit is a new address, and the original file is unchanged.

What our app does

Socialix has no ImageKit, no Gemini, no upload and no image editor. Images enter a post in one way only: as a public image URL, typed by the owner or given to the Creator Agent. It is stored in the image_url column of the posts table (imageUrl: text("image_url"), line 83 of src/lib/db/schema.ts), and it is optional.

The server action that receives the form, from src/app/dashboard/actions.ts:

export async function createManualPost(formData: FormData) {
  await requireSession();
  const platform = str(formData, "platform") as Platform;
  if (!PLATFORMS.includes(platform)) return;
  const campaign = await db.query.campaigns.findFirst({ where: eq(schema.campaigns.id, str(formData, "campaignId")) });
  if (!campaign) return;
  const when = str(formData, "scheduledAt");
  await db.insert(schema.posts).values({
    campaignId: campaign.id,
    platform,
    title: str(formData, "title") || "Untitled post",
    body: str(formData, "body"),
    hashtags: str(formData, "hashtags").split(/[\s,]+/).filter((h) => h.startsWith("#")),
    imageUrl: str(formData, "imageUrl") || null,
    link: campaign.link,
    scheduledAt: when ? new Date(when) : null,
    status: when ? "awaiting_approval" : "draft",
  });
  revalidatePath("/dashboard", "layout");
}

Images and the agents

The Creator Agent's save_draft tool (step 16) has an optional imageUrl field, described as "A real public image URL (required for Instagram and TikTok)". If it saves an Instagram or TikTok draft without one, the tool still saves it but adds (line 112 of tools.ts): "Note: INSTAGRAM needs an image before it can be published." The Creator's instructions (src/lib/ai/agents.ts, line 97) say to use an image URL "only if the owner or the research provides a real public image URL, otherwise say the post needs an image", so it doesn't make one up. The Scheduler's list_drafts tool reports hasImage for each draft.

The refusal at publishing time

The last safety net is in our MCP server (step 18), in mcp/social-publisher/server.ts:

  INSTAGRAM: { canAutoPublish: true, requiresMedia: true, charLimit: 2200 },
  TIKTOK: { canAutoPublish: true, requiresMedia: true, charLimit: 2200 },
  async ({ platform, title, body, hashtags, link, imageUrl, scheduledAt }) => {
    const caps = CAPABILITIES[platform];
    if (!caps.canAutoPublish) return fail(`${platform} cannot be published automatically by the autopilot (manual posting only).`);
    if (caps.requiresMedia && !imageUrl) return fail(`${platform} needs an imageUrl.`);

Adding image generation later (not built, not tested)

This section is a design idea only. None of it exists in Socialix and none of it has been tested.

Claude models write text; they don't produce image files. To let the Creator Agent attach images you would add a separate image service and give the agent a tool that returns a public URL. One possible shape:

  1. Pick an image service: an image-generation model (the video uses Gemini), or a transform service such as ImageKit for editing images the owner uploads.
  2. Store the result somewhere public (ImageKit's media library, S3 or similar), because Instagram and TikTok fetch the image from its URL.
  3. Add a client tool for the Creator, for example generate_image, built with the same tool() helper as the others. It would call the service, upload the file and return the public URL as text.
  4. Let the Creator pass that URL to save_draft's existing imageUrl field. Nothing after that needs to change: the posts table, the hand-off and the MCP server already carry the URL.
  5. Keep the owner's approval step: a generated image should be looked at before it is published.
Video vs our app. The video builds a Create Post page with image upload, an ImageKit-powered editor (AI edits, background change, generative fill, crop, adjustments, text), Gemini image generation for the Creator Agent, live platform previews, and editing or unscheduling of scheduled posts. Socialix has none of that: posts carry an optional public image URL, entered in a simple form or passed to save_draft, and Instagram and TikTok posts without one are refused by our MCP server. The upside is fewer services and keys; the downside is that you must host your images yourself.
What you should see
  • Create a manual LinkedIn post with an image URL: its card on the Posts page shows the picture above the text.
  • Ask the Creator Agent for an Instagram post without giving an image: the draft is saved, and the reply mentions that the post needs an image.
  • Approve an Instagram post that has no image: it moves to the Failed tab with the error "INSTAGRAM needs an imageUrl.".
Common mistakes
  • Using a link to a web page instead of to an image file. The URL must open the image itself (often ending in .jpg, .png or .webp), not a page that contains it.
  • Using a private or local address such as a file on your PC or localhost. The social network has to download the image from the internet.
  • Expecting the manual form to check the length. Only the Creator's save_draft tool measures posts against the character limits; the manual form saves what you type.
  • Trying to publish to YouTube from Socialix. The autopilot posts to YouTube manually only, so publish_post refuses it whatever image you give.
Recap
  • The video uses ImageKit (URL-based transforms, storage) and Gemini to generate and edit images, with a rich Create Post page and image editor.
  • Socialix generates no images. A post has an optional imageUrl, set in the "Create a post yourself" form or by the Creator's save_draft.
  • save_draft warns when an Instagram or TikTok draft has no image; the MCP publish_post tool refuses it, and the post is marked failed with the reason.
  • Image generation could be added later as one more tool that returns a public URL; that design is not built or tested.
