# Socialix: an AI social media team

> Step-by-step setup and usage: see [docs/](docs/README.md).

A Next.js dashboard where a team of Claude agents plans, writes and schedules social media posts. It
is built after the video "Build Social Media AI Agent Team Using Claude Code & Next.js", with three
changes:

- **Claude instead of OpenAI.** The agents run on the Anthropic API.
- **Your autopilot instead of Blotato.** Posts are published through the
  [WordPress Social Autopilot](../wordpress-social-autopilot), via an MCP server in this project.
- **No extra cloud services.** It uses your local Postgres instead of InsForge, and an in-process task
  runner instead of Inngest. There is no E2B sandbox.

## The team

| Agent | Model | Tools |
|---|---|---|
| Master | `claude-sonnet-5-5` | `assign_task` (runs a team member and waits for the result), `list_tasks` |
| Research | `claude-sonnet-5-5` | Anthropic web search, `save_research`, `wordpress_recent_posts` (read-only WordPress REST) |
| Creator | `claude-sonnet-5-5` | `list_research`, `save_draft` |
| Scheduler | `claude-haiku-5-5` | `list_connections` (MCP), `list_drafts`, `schedule_post` |
| Analytics | `claude-haiku-5-5` | `post_overview` (refreshes statuses through MCP) |

Brief the Master Agent on the **AI Agent** page. It splits the request into tasks, which you can watch
on the task board while the desks in the office light up.

## How publishing works

```
Scheduler Agent ──schedule_post──► post "awaiting approval" (this app's database)
You press Approve (or auto-publish is on)
      │
      ▼
Social Publisher MCP server (mcp/social-publisher/server.ts, stdio)
      │  publish_post: WordPressPost + APPROVED GeneratedContent + QUEUED PublishJob
      ▼
WordPress Social Autopilot database ──► its worker (npm run worker) publishes at the scheduled time
                                         with its own publishers, token refresh, retries and audit log
```

Socialix never reads the social access tokens. They stay encrypted in the autopilot's database and are
used only by its worker. The MCP tools are:

- `list_connections`
- `publish_post`
- `get_post_status`
- `cancel_post`
- `list_recent_posts`

**Nothing is posted until you approve it**, unless you turn on auto-publish in Settings. Approved
posts go out only while the autopilot's worker is running.

## Setup

Prerequisites:

- Node 22 or later and pnpm.
- The autopilot's database running. That is the Docker container `wsa-pg`, started with
  `docker start wsa-pg`.

```
pnpm install
cp .env.example .env      # only non-secret settings; set APP_LOGIN_EMAIL
pnpm db:setup             # creates the social_media_ai_agent database and the tables, and generates the login in .env
pnpm mcp:check            # lists the MCP tools and your connected accounts (posts nothing)
pnpm build && pnpm start  # http://localhost:3100 (the autopilot uses 3000); or pnpm dev
```

To publish approved posts, also run the autopilot's worker:

```
cd ../wordpress-social-autopilot
npm run worker
```

### Where the secrets come from

This project's `.env` holds no API keys. These come from `AUTOPILOT_DIR/.env` and are read in place:

- `ANTHROPIC_API_KEY`
- `DATABASE_URL`, whose server and login are reused for this app's own database
- `WORDPRESS_SITE_URL`

The only secrets here are the dashboard login and the session key, both generated by `pnpm db:setup`.

On Windows behind an antivirus that inspects TLS, start Node with `NODE_OPTIONS=--use-system-ca`.

## Not included, compared with the video

- **Image generation:** Claude does not make images. Instagram and TikTok posts need an image URL,
  which you add yourself or take from your WordPress posts.
- **The E2B sandbox browser:** the Research Agent uses Anthropic's web search instead.
- **Engagement analytics** (likes, reach): the autopilot does not read post metrics yet.
- **Multi-user accounts:** this is a single-owner dashboard.
