Set Up and Run the App

From an empty machine to a running dashboard and publishing worker, with every command explained.

This chapter takes you from a machine with nothing installed to a running Socialix dashboard and a publishing worker. Every command is explained word by word. It follows the project's own documentation (docs/01-setup.md and docs/02-start-and-stop.md), written for PowerShell on Windows, which is what the owner uses.

Why this matters for your project. Socialix is not one program. It is a Next.js server, a Postgres database in Docker, an MCP server the app starts by itself, and the WordPress Social Autopilot with its worker. If one of them is missing, the symptom often shows up somewhere else ("agents fail", "posts stay queued"). Knowing what runs where makes those problems easy to find.

One-time setup

Step 1: start the database

docker start wsa-pg
docker ps --filter name=wsa-pg
Line(s)CodeWhat it does & why
1docker start wsa-pgdocker start starts an existing, stopped container; wsa-pg is its name (the autopilot's Postgres). It does not create a container; the autopilot's setup did that.
2docker ps --filter name=wsa-pgdocker ps lists running containers; --filter name=wsa-pg shows only ours. The STATUS column should say Up.

Step 2: install Socialix

cd C:\MLSCampus\social-media-ai-agent
pnpm install

cd moves into the project folder. pnpm install reads package.json and downloads the exact versions listed there (Next.js 16.4.2, React 19.3.1, the Anthropic SDK 0.135.0, the MCP SDK 1.32.1 and the rest) into node_modules.

Step 3: create the settings file

Copy-Item .env.example .env
notepad .env

Copy-Item is PowerShell's copy command; the second line opens the copy in Notepad. This is the template you are copying:

# Socialix settings. Secrets are NOT stored here: the Anthropic key, the database password and
# the social-media tokens stay in the WordPress Social Autopilot project and are read from there.

# Folder of the WordPress Social Autopilot project (its .env supplies ANTHROPIC_API_KEY,
# DATABASE_URL, WORDPRESS_SITE_URL; its database holds the connected social accounts).
AUTOPILOT_DIR=C:/MLSCampus/wordpress-social-autopilot

# This app's own database name, created next to the autopilot's database on the same server.
APP_DATABASE_NAME=social_media_ai_agent

# Login for this dashboard (single owner). Generated by `pnpm db:setup` if empty.
APP_LOGIN_EMAIL=owner@example.com
APP_LOGIN_PASSWORD=
SESSION_SECRET=

# Claude models (defaults shown).
MODEL_SMART=claude-sonnet-5-5
MODEL_FAST=claude-haiku-5-5

Step 4: create the database, tables and login

pnpm db:setup

This runs tsx scripts/db-setup.ts (step 6). It connects with the autopilot's database URL, creates the social_media_ai_agent database if it is missing, creates the seven tables with create table if not exists, inserts autoPublish = false, and fills APP_LOGIN_PASSWORD and SESSION_SECRET in .env with random values if they are empty. It never prints them. Running it again is safe; it never deletes data. You should see:

created database social_media_ai_agent      (or: already exists)
tables ready
generated APP_LOGIN_PASSWORD in .env        (only if you left it empty)
generated SESSION_SECRET in .env

Step 5: check the publishing connection

$env:NODE_OPTIONS = "--use-system-ca"
pnpm mcp:check
Line(s)CodeWhat it does & why
1$env:NODE_OPTIONS = "--use-system-ca"Sets an environment variable for this PowerShell window only. Node reads NODE_OPTIONS at start-up; --use-system-ca makes it trust the certificates Windows trusts (see the primer below).
2pnpm mcp:checkRuns scripts/mcp-check.ts: starts the MCP server, lists its tools and your accounts, and checks that an Instagram post without an image is refused. It posts nothing.
New to TLS inspection? Why NODE_OPTIONS=--use-system-ca is needed on the owner's PC

Secure connections (TLS, the "s" in https) prove who the server is with a certificate signed by a trusted authority. Some antivirus programs, Norton on the owner's PC, look inside secure connections: they put their own certificate in the middle, which Windows trusts because the antivirus installed it. Node.js, by default, uses its own list of authorities and does not know the antivirus certificate, so calls to Claude fail with "self-signed certificate in certificate chain". --use-system-ca tells Node to use the Windows list instead. Set it before every pnpm start, pnpm mcp:check and npm run worker.

Step 6: build

pnpm build

next build type-checks and compiles every page into an optimized production build. It ends with a list of pages and no errors. Rebuild after every code change: pnpm start serves the last build, not your latest edits.

Every day: start and stop

Open two PowerShell windows.

docker start wsa-pg
cd C:\MLSCampus\social-media-ai-agent
$env:NODE_OPTIONS = "--use-system-ca"
pnpm start

Wait for Ready, then open http://localhost:3100 and sign in with APP_LOGIN_EMAIL and APP_LOGIN_PASSWORD from .env. pnpm start runs next start -p 3100: -p 3100 picks the port, so Socialix does not clash with the autopilot's dashboard on 3000.

cd C:\MLSCampus\wordpress-social-autopilot
$env:NODE_OPTIONS = "--use-system-ca"
npm run worker

The worker is what publishes. You only need it when approved posts should go out. While it is stopped, approved posts wait safely in the queue; when it starts, late posts are sent right away. The autopilot uses npm, not pnpm, because that is how that project is set up.

To use the autopilot's own dashboard as well (to reconnect an account, for example), run npm run dev in a third window in the autopilot folder and open http://localhost:3000.

Stop: press Ctrl+C in each window. To also stop the database and free memory: docker stop wsa-pg.

What you should see. docker ps shows wsa-pg as Up; pnpm mcp:check lists five tools and six networks; pnpm build ends without errors; pnpm start prints Ready; http://localhost:3100 shows the sign-in page, then the dashboard.
Pitfalls.
  • ECONNREFUSED ... 5433: the database is not running. Start Docker Desktop, then docker start wsa-pg.
  • EADDRINUSE ... 3100: Socialix is already running, maybe in another window. Use that one, or stop it: Get-NetTCPConnection -LocalPort 3100 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess }.
  • "self-signed certificate in certificate chain": NODE_OPTIONS was not set in this window. It does not carry over to new windows.
  • Agents fail with 401 or authentication_error: the key in the autopilot's .env is missing or wrong. "credit balance is too low": add credit in the Anthropic console.
  • Pages look old after a code change: run pnpm build again before pnpm start.
  • The app stopped by itself: usually low memory on the owner's PC. Close other apps and start again; the data is in the database, so nothing is lost.
  • Changed .env but nothing happened: settings are read when the server starts. Restart it.
Recap
  • Setup: docker start wsa-pg, pnpm install, copy .env.example to .env, pnpm db:setup, pnpm mcp:check, pnpm build.
  • Daily: window 1 runs Socialix on port 3100, window 2 runs the autopilot worker that publishes.
  • Our .env holds no API keys; the key, database URL and site URL are read from the autopilot's .env.
  • On a PC with TLS inspection, set NODE_OPTIONS=--use-system-ca in every window.
