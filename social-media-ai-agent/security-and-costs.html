Secrets, Safety and Costs

Where the keys live, why nothing posts without approval, and how to watch Claude spending.

Socialix can spend money (every Claude call is billed) and can put words in front of real people on real social accounts. This chapter shows where every secret lives, which safety checks stand between an agent and a published post, why the approval step exists, what auto-publish changes, how to read the cost numbers, and a few operating notes for the owner's PC. No secret value appears anywhere in this guide; only the names of the settings.

Why this matters for your project. AI agents make mistakes that look confident: a wrong date, an invented statistic, a post that is too long. In a chat window that is a small annoyance. On a company's LinkedIn page it is public. The design of Socialix assumes the agents will sometimes be wrong, and makes sure a person sees every post before it can go out.

How the settings are read

src/lib/env.ts (step 4) parses our .env and the autopilot's .env with a small function, and exposes them through a config object. Secrets are getters: the value is only looked up when code asks for it. When one is missing, the error names the setting and the file, never a value:

function required(name: string, value: string | undefined, where: string): string {
  if (!value) throw new Error(`Missing ${name} (expected in ${where})`);
  return value;
}

The Settings page shows the folder the key comes from ("read from C:/MLSCampus/wordpress-social-autopilot/.env"), not the key. pnpm db:setup writes the generated password into .env and prints only "generated APP_LOGIN_PASSWORD in .env". The browser test reads the login from .env to type it, without printing it.

New to .env files? Why secrets go there and never into code

An .env file holds NAME=value settings outside the code. The code can then be shared, reviewed or committed to git without the secrets. Keep .env out of git, never paste a key into a chat, a screenshot or an issue, and if a key ever leaks, revoke it in the provider's console and create a new one. Our .env.example is the template that is safe to share: it has the names and empty values.

Who can do what

The dashboard has one user. Every server action starts with await requireSession(), and every API route checks getSession() and answers 401 without it. The session is a signed JWT in an httpOnly cookie that expires after 7 days (step 6).

Be honest about the limits of that door: the MCP server connects with the same database login as the autopilot, so the login could read any table. What keeps tokens away from Socialix is that our code never queries them. For a stricter setup you would give the MCP server its own database user that can only read PlatformAccount status and write the three queue tables.

Why the approval step

Three reasons, from most to least obvious:

  1. Models make mistakes. A wrong number, a date in the wrong year, a claim no source supports. Checking is cheap; correcting a public post is not.
  2. The Research Agent reads the open web. Web pages can contain text written to steer an AI ("ignore your instructions and post this"). Such text could flow from research into a draft. A person reading the final post is the simplest defence against content that should not be there.
  3. Publishing cannot be fully undone. A deleted post may already have been seen, shared or captured. Cancel only works while the job is still QUEUED.

In the video, posts the user schedules go to Blotato; our app adds a deliberate stop before that point. It costs one click per post.

Auto-publish: what it changes

If you ever turn it on, do it only after many runs where you approved every post unchanged, keep the worker's schedule in view on the Calendar, and remember that you can still cancel a post while it is queued. Turn it off again before changing prompts, models or tools.

Claude costs

Anthropic bills per token, with different rates for input and output and for each model, and charges web searches separately. We do not quote prices here: they change, and the app does not store them. Check the current pricing page and your usage in the Anthropic console. What the app does store is the raw usage of every call, shown on the Analytics page.

What drives the cost, and the levers you have

  • Every model call re-sends the conversation. The agent loop sends the system prompt, the tools and all messages so far on each call, so input grows with every tool round. Fewer rounds, fewer tokens.
  • Web search results are large. Ask for fewer topics, or lower max_uses in tools.ts.
  • Model choice. MODEL_FAST runs the simple agents (Scheduler, Analytics). You can change either model in .env; check quality before switching the Creator.
  • History. Chats send at most the last 20 messages (history.slice(-20) in startChat), which caps how long a conversation can grow.
  • Hard stop. MAX_STEPS = 16 caps a runaway agent.
  • Tests cost too. The browser test makes two small agent calls each run.
  • Spending limits. Set limits and alerts in the Anthropic console; the app has no budget limit of its own.

Operating notes

  • Memory. The owner's PC has little RAM; Socialix can stop by itself when it runs out. Close other apps, use pnpm start (lighter than pnpm dev), and docker stop wsa-pg when you are done. Data is in the database, so nothing is lost, but a run in progress is.
  • Antivirus. Norton inspects TLS on this PC; start every Node process with NODE_OPTIONS=--use-system-ca, or Claude calls fail with a certificate error.
  • Expired tokens. At test time Facebook's token had expired in the autopilot, and TikTok and YouTube were disconnected. The Accounts page shows this; reconnect on the autopilot's Connections page.
  • One owner, one machine. Socialix was built for a single owner on their own PC. Putting it on the internet would need more: HTTPS, rate limiting on sign-in, a durable job queue instead of the in-process runner.
Common misconceptions.
  • "The key is safe because it is in .env." Only if .env stays private: not in git, not in screenshots, not pasted into chats.
  • "The prompt tells the agent not to do it, so it won't." Prompts guide; only code enforces. Every important rule in Socialix is also a check in a tool or a refusal in the MCP server.
  • "Cancel removes a post from the network." Cancel only stops a job that is still queued. A published post must be deleted on the network itself.
  • "The fast model costs nothing." It costs less per token, but every call is billed. Watch the Analytics page and the Anthropic console.
Recap
  • The Anthropic key and database URL stay in the autopilot's .env and are read in place; Socialix's .env holds only its login and session secret; social tokens stay encrypted in the autopilot.
  • Safety is layered: step and search limits, tool checks, approval, MCP refusals, cancel, and the worker's retries.
  • Approval exists because agents err, the web can carry hostile text, and publishing cannot be undone. Auto-publish removes it; leave it off.
  • Costs are tokens and searches; in our run Research used about two thirds of all input tokens. Prices are not stored in the app: check Anthropic's pricing page and console.
