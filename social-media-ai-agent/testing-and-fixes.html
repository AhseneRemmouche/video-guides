Testing and the Bugs We Fixed

The browser test, what it checks, and the real bugs found while building (over-long drafts, a Chrome 155 crash).

The video checks its work by clicking through the app and letting CodeRabbit review each pull request. We check Socialix with three things: a type check (pnpm typecheck), a production build (pnpm build) and a browser test with 23 checks that drives the real app, calls real Claude agents, and hands one harmless post to the real autopilot. This chapter explains that test line by line, what each check proves, and the four real bugs we found while building.

Why this matters for your project. An app that can publish to real social accounts needs tests that prove the dangerous parts work and that the test itself cannot publish anything. Our test is built around that rule: its one post is scheduled a year ahead and cancelled at once.

What an end-to-end test is

New to end-to-end tests and Playwright? What they are

An end-to-end test uses the app the way a person does: it opens pages in a real browser, types, clicks, and checks what appears. It tests everything together (pages, server actions, database, agents, MCP server), which unit tests of single functions cannot. The price: it is slower, and it needs the whole system running.

Playwright is a library that controls a browser from code. Our test uses its Python version (playwright.sync_api) with headless Chromium, a browser with no window.

The test script: scripts/e2e_test.py

"""End-to-end test of Socialix in headless Chromium. Publishes nothing: the one post handed to the
autopilot is scheduled a year ahead and cancelled straight away (the autopilot worker must be stopped).
Reads the login from the app's .env without printing it. Usage: python scripts/e2e_test.py <out_dir>"""
import json, os, pathlib, re, subprocess, sys, time
from playwright.sync_api import sync_playwright

APP = pathlib.Path("C:/MLSCampus/social-media-ai-agent")
env = dict(re.findall(r"^([A-Z_]+)=(.*)$", (APP / ".env").read_text(encoding="utf-8"), re.M))
out = pathlib.Path(sys.argv[1]); out.mkdir(parents=True, exist_ok=True)
BASE = "http://localhost:3100"
TITLE = "SOCIALIX E2E TEST - not for publishing"
results = []

def check(name, ok, detail=""):
    results.append((name, bool(ok), detail))
    print(("PASS " if ok else "FAIL ") + name + (f"  ({detail})" if detail else ""), flush=True)

def verify():
    r = subprocess.run("pnpm exec tsx scripts/verify-post.ts \"%s\"" % TITLE, cwd=APP, shell=True, capture_output=True, text=True,
                       env={**os.environ, "NODE_OPTIONS": "--use-system-ca"}, timeout=120)
    line = [l for l in r.stdout.splitlines() if l.startswith("{")]
    return json.loads(line[-1]) if line else {"error": r.stderr[-400:]}

def card(page):
    return page.locator("section", has_text=TITLE).first

def ask(page, campaign, agent, text, timeout=300):
    page.goto(BASE + "/dashboard/ai-agent"); page.wait_for_load_state("networkidle")
    page.locator("button", has_text=agent.capitalize() + " Agent").first.click()
    before = page.evaluate(f"fetch('/api/agents/state?campaignId={campaign}&agent={agent}').then(r => r.json())")
    n = sum(1 for m in before["messages"] if m["role"] == "assistant")
    page.fill("input[placeholder^='Tell the']", text)
    page.click("button[aria-label=Send]")
    start = time.time()
    while time.time() - start < timeout:
        time.sleep(4)
        st = page.evaluate(f"fetch('/api/agents/state?campaignId={campaign}&agent={agent}').then(r => r.json())")
        replies = [m for m in st["messages"] if m["role"] == "assistant"]
        if not st["thinking"] and len(replies) > n:
            return replies[-1]["content"], time.time() - start
    return None, time.time() - start

with sync_playwright() as p:
    b = p.chromium.launch()
    page = b.new_page(viewport={"width": 1440, "height": 1000})
    errors = []
    page.on("console", lambda m: errors.append(m.text) if m.type == "error" else None)
    page.on("response", lambda r: errors.append(f"HTTP {r.status} {r.url}") if r.status >= 500 else None)

    # --- Authentication
    page.goto(BASE + "/dashboard"); page.wait_for_load_state("networkidle")
    check("signed-out visitor is sent to the sign-in page", "/signin" in page.url, page.url)
    page.fill("input[name=email]", env["APP_LOGIN_EMAIL"]); page.fill("input[name=password]", "wrong-password")
    page.click("button:has-text('Sign in')"); page.wait_for_url("**/signin?error=*", timeout=15000)
    check("wrong password is refused", page.get_by_text("Wrong email or password").count() > 0, page.url)
    page.fill("input[name=email]", env["APP_LOGIN_EMAIL"]); page.fill("input[name=password]", env["APP_LOGIN_PASSWORD"])
    page.click("button:has-text('Sign in')"); page.wait_for_url("**/dashboard**", timeout=15000)
    check("correct login opens the dashboard", "/dashboard" in page.url, page.url)
    # A fresh browser has no campaign cookie (the app falls back to the newest campaign), so read the id
    # from the AI Agent page's own state request.
    with page.expect_request(lambda r: "/api/agents/state?campaignId=" in r.url, timeout=15000) as req:
        page.goto(BASE + "/dashboard/ai-agent")
    campaign = re.search(r"campaignId=([^&]+)", req.value.url).group(1)
    check("a campaign is selected", bool(campaign))

    # --- Every page renders
    expected = {"": "Overview", "ai-agent": "AI Agents", "posts": "Posts", "calendar": "Calendar", "analytics": "Analytics",
                "accounts": "Accounts", "settings": "Settings", "campaigns/new": "campaign"}
    for path, heading in expected.items():
        resp = page.goto(f"{BASE}/dashboard/{path}"); page.wait_for_load_state("networkidle")
        body = page.inner_text("body")
        check(f"page /dashboard/{path} loads", resp.status == 200 and heading.lower() in body.lower() and "Application error" not in body, f"HTTP {resp.status}")
    page.goto(BASE + "/dashboard/accounts"); page.wait_for_load_state("networkidle")
    check("accounts page reads connections through MCP", "LinkedIn" in page.inner_text("body") and "connected" in page.inner_text("body").lower())
    page.goto(BASE + "/dashboard/calendar?week=1"); page.wait_for_load_state("networkidle")
    check("calendar moves to next week", "posts" in page.inner_text("body"))

    # --- Post lifecycle: create -> approve (queued in autopilot) -> cancel -> delete
    page.goto(BASE + "/dashboard/posts"); page.wait_for_load_state("networkidle")
    page.select_option("select[name=platform]", "LINKEDIN")
    page.fill("input[name=title]", TITLE)
    page.fill("textarea[name=body]", "Automated test post. It is scheduled a year ahead and cancelled immediately.")
    page.fill("input[name=hashtags]", "#test")
    page.fill("input[name=scheduledAt]", "2027-10-16T10:00")
    page.click("form:has(textarea[name=body]) button:has-text('Save')"); page.wait_for_load_state("networkidle"); page.wait_for_timeout(1000)
    check("manual post is created as awaiting approval", card(page).count() and "Awaiting approval" in card(page).inner_text())
    page.screenshot(path=str(out / "e2e-created.png"), full_page=True)

    card(page).locator("button", has_text="Approve").click(); page.wait_for_load_state("networkidle"); page.wait_for_timeout(2500)
    page.reload(); page.wait_for_load_state("networkidle")
    check("approve hands the post to the autopilot (queued)", "Queued" in card(page).inner_text())
    v = verify()
    check("autopilot has the post queued for 2027", v.get("handedOff") and v.get("autopilot") and "QUEUED" in v["autopilot"] and "2027-10-16" in v["autopilot"], (v.get("autopilot") or str(v))[:200])

    card(page).locator("button", has_text="Cancel").click(); page.wait_for_load_state("networkidle"); page.wait_for_timeout(2500)
    page.reload(); page.wait_for_load_state("networkidle")
    check("cancel marks the post cancelled", "Cancelled" in card(page).inner_text())
    v = verify()
    check("autopilot job is no longer queued", v.get("autopilot") and "QUEUED" not in v["autopilot"], (v.get("autopilot") or str(v))[:200])

    card(page).locator("button", has_text="Delete").click(); page.wait_for_load_state("networkidle"); page.wait_for_timeout(1500)
    page.reload(); page.wait_for_load_state("networkidle")
    check("delete removes the post", card(page).count() == 0 and not verify().get("found"))

    # --- Agents (real Claude calls)
    reply, secs = ask(page, campaign, "analytics", "Give me a two-sentence status report on this campaign's posts.")
    check("Analytics Agent answers", bool(reply), f"{secs:.0f}s: {(reply or '')[:160]!r}")
    reply, secs = ask(page, campaign, "creator",
                      "Write one X post (no research needed) inviting small business owners to try one AI tool this week. Title it 'E2E creator test'. Save it as a draft.")
    page.goto(BASE + "/dashboard/posts?tab=drafts"); page.wait_for_load_state("networkidle")
    draft = page.locator("section", has_text="E2E creator test").first
    check("Creator Agent saves a draft within the X limit", bool(reply) and draft.count() > 0, f"{secs:.0f}s: {(reply or '')[:200]!r}")
    page.screenshot(path=str(out / "e2e-creator-draft.png"), full_page=True)
    if draft.count():
        draft.locator("button", has_text="Delete").click(); page.wait_for_load_state("networkidle")

    check("no server errors or console errors", not errors, "; ".join(errors[:5]))
    b.close()

passed = sum(ok for _, ok, _ in results)
print(f"\n{passed}/{len(results)} checks passed")

The helper: scripts/verify-post.ts

// Test helper: prints a post's status in this app and, if it was handed off, in the autopilot (via MCP).
// Run: pnpm exec tsx scripts/verify-post.ts "<post title>"
import { desc, eq } from "drizzle-orm";
import { db, schema } from "../src/lib/db";
import { callSocialTool } from "../src/lib/mcp/social";

const title = process.argv[2] ?? "";
const post = await db.query.posts.findFirst({ where: eq(schema.posts.title, title), orderBy: desc(schema.posts.createdAt) });
if (!post) {
  console.log(JSON.stringify({ found: false }));
  process.exit(0);
}
const autopilot = post.autopilotContentId ? (await callSocialTool("get_post_status", { contentId: post.autopilotContentId })).text : null;
console.log(JSON.stringify({ found: true, status: post.status, scheduledAt: post.scheduledAt, handedOff: Boolean(post.autopilotContentId), autopilot }));
process.exit(0);
Line(s)CodeWhat it does & why
3–5importsDrizzle helpers, our database, and the MCP client.
7–8process.argv[2], findFirst(... orderBy: desc(createdAt))The title passed on the command line, and the newest post with that title.
9–12{ found: false }No such post: print that and stop. The delete check relies on it.
13callSocialTool("get_post_status", ...)Only if the post was handed over: ask the autopilot through MCP. The answer is the JSON text from get_post_status (status, attempts, last error, next run time).
14–15console.log(JSON.stringify({...})), process.exit(0)One JSON line for the Python side, then exit (the MCP child process would otherwise keep the script alive).

Why does the post test use 10:00 on the form but expect 14:00Z in the autopilot? The form's datetime-local value has no time zone, so the server reads it as its own local time; on the owner's machine at test time, 10:00 local was 14:00 UTC.

Two lessons from writing the test

  1. Wait for redirects. After clicking "Sign in", the page navigates. A check that runs before the navigation has finished still sees /signin. page.wait_for_url("**/dashboard**") waits until the redirect has happened (and fails clearly after 15 seconds if it never does).
  2. Don't depend on state the test browser doesn't have. A fresh browser has no campaign cookie, because the app only sets it when the owner picks or creates a campaign; until then it shows the newest campaign. So the campaign id cannot be read from a cookie. The fix is to watch the app's own network request, which already carries the id. (The session cookie is httpOnly and invisible to page scripts anyway; the campaign cookie is not.)

The four bugs we found and fixed

Bug 1: the Creator saved X drafts that were too long

What happened. In an early run, the Creator Agent saved four X drafts that were longer than X allows once hashtags and the link were added. Cause: nothing in the code checked the full length; the limit was only an instruction, and models are not reliable at counting characters. Fix: save_draft now counts the full published length (body + blank line + hashtags + campaign link + 1) and refuses: "Not saved: ... Shorten it by at least N characters and call save_draft again." The model shortens and retries. Details on step 16.

Bug 2: the Master Agent saw a contradiction that was not there

What happened. list_connections first returned a field called autoPublish: true, meaning "this network can be published automatically". The Master Agent confused it with the app's own auto-publish setting (which was off) and reported a contradiction to the owner. Fix: the field was renamed canAutoPublish. Lesson: tool output is read by a model; names must not collide with other concepts in its instructions. Details on step 13.

Bug 3: "This page couldn't load" in Chrome 155

What happened. In Chrome 155 the AI Agent page crashed with "TypeError: i is not a function", and Next.js showed "This page couldn't load". Our test passed. Cause: the chat scrolled with useEffect(() => ref.current?.scrollIntoView()). An arrow function without braces returns its expression. In Chrome 155, scrollIntoView() returns a Promise, so the effect returned a Promise, and React treats whatever an effect returns as its cleanup function. When React later called that "cleanup", it crashed. Our older Playwright Chromium returned undefined, so the test never saw it. Fix: braces, and scrolling only the chat box with box.scrollTo({ top: box.scrollHeight }); a failed poll is now also caught (.catch(() => null)). Details on step 11.

Bug 4: the agents did not face their monitors

What happened. In the office picture, the agents first sat at the side of their desks instead of in front of their monitors. Fix: in office.tsx they were moved in front of the desk, seen from behind, so they look at the screen. Details on step 10.

Pitfalls.
  • A green test is not proof for every browser. Bug 3 passed our test and crashed in Chrome 155. Test in the browser your users have, too.
  • Never run the test with the worker on. The test cancels its post immediately, but the documented rule is to stop npm run worker first.
  • The agent checks cost money. Checks 21 and 22 make real, small Claude calls.
  • Prompts are not limits. Bug 1 showed that a rule in a prompt is a wish; a check in a tool is a guarantee.
Recap
  • We check with pnpm typecheck, pnpm build and a 23-check Playwright test; all 23 passed.
  • The test covers sign-in, every page, the full post lifecycle against the real autopilot, two real agents, and console or server errors.
  • It cannot publish: a post a year ahead, cancelled at once, with the worker stopped.
  • Four bugs: over-long drafts (tool now counts and refuses), a confusing field name (renamed canAutoPublish), a Promise returned from an effect (braces and scrollTo), and agents facing the wrong way.
