CodeRabbit Setup

AI code review with CodeRabbit in the video, and the checks we run instead: typecheck, build, browser test.

▶ Watch this part (00:21:24)

Before the video writes any real feature, it connects an AI code reviewer called CodeRabbit to the project's GitHub repository. From then on, every chapter ends the same way: push the work to a new branch, open a pull request, let CodeRabbit read the changes, then merge. This page explains what CodeRabbit is and how the video connects it. Then it shows the three checks we run on our own app, Socialix, instead: a type check, a production build and a 23-check browser test.

Why does a project need checks at all? When Claude Code writes most of the code, you did not type every line yourself. Something has to look at the result before you trust it. In the video that is CodeRabbit, a second AI that reads each change. For us it is a set of automatic tests that run the code and fail loudly when something is wrong.

New to pull requests? What they are and why they matter

Git keeps the history of your code. A branch is a separate line of work. You can change files on it without touching the main version (the main branch). When the work is ready, you ask to merge your branch into main. On GitHub that request is called a pull request (PR for short).

A pull request page shows every changed line. People (or bots like CodeRabbit) can comment on it before anyone clicks Merge. That is the moment to catch mistakes, because after the merge the change is part of the main code.

Connecting CodeRabbit to GitHub (22:46 to 24:43)

The presenter does this in three parts. Only the steps below are shown in the video.

  1. Create a repository on GitHub (22:46). On github.com he creates a new private repository named social-media-ai-agent. GitHub then shows its "Quick setup" page with the commands to connect a local folder.
  2. Push the code (23:10). He copies the git remote add origin … line into a terminal in VS Code. Then, in VS Code's Source Control panel, he clicks + to stage all changes, types a commit message, clicks Commit and then Publish Branch. Because it is the first push, everything lands on main.
  3. Sign in to CodeRabbit (23:58). He signs in at CodeRabbit with his GitHub account.
  4. Add the repository (24:20). In the CodeRabbit app, under Connected repositories, he clicks Add Repositories. CodeRabbit sends him to GitHub's page for its installed GitHub App.
  5. Give access to one repository. GitHub lists what CodeRabbit asks for (see the diagram below). Under Repository access he chooses Only select repositories, picks social-media-ai-agent and clicks Save.
  6. Check it worked (24:43). Back in CodeRabbit, social-media-ai-agent now appears in the list of connected repositories.

The commands behind the buttons

The video clicks buttons in VS Code. Each button runs a normal Git command. Here are the same steps typed in a terminal, so you know what happens. This is the standard Git workflow, not something CodeRabbit needs. Replace <you> with your GitHub user name.

git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/<you>/social-media-ai-agent.git
git push -u origin main

# at the end of a chapter
git switch -c dashboard-layout
git add .
git commit -m "Add dashboard layout"
git push -u origin dashboard-layout

When you open a pull request, CodeRabbit starts within seconds. Its Change Stack page first says "Preparing your Change Stack" and fills in when the review is done. If you leave the PR description empty, CodeRabbit writes one for you (59:53).
Common mistakes with CodeRabbit
  • Pushing straight to main every time. CodeRabbit reviews pull requests. With no PR there is no review. The video creates a new branch for every chapter for this reason.
  • Not merging before starting the next branch. The presenter stresses this at 36:47. If you do not merge, the next branch starts from an old main without your last chapter.
  • Repository not selected. If you picked "Only select repositories" but forgot to tick the new repo, nothing happens on your PRs. Go back to the GitHub App settings and add it.
  • Committing .env. Check that .env is in .gitignore before the first git add .. A key pushed to GitHub must be treated as leaked and replaced.

How our app checks its code instead

Socialix lives in a local folder and is not reviewed by CodeRabbit. We check every change with three commands. Each one catches a different kind of problem, and each is cheaper and faster than the next.

New to type checking and builds? What they are and why they matter

TypeScript adds types to JavaScript: "this value is a string", "this function returns a Date". The TypeScript compiler, tsc, reads all files and complains when the types do not fit, for example when you pass a number where a string is expected or misspell a property name. The flag --noEmit means "only check, do not write any output files".

A production build (next build) is what Next.js does before it can serve the app quickly. It compiles every page, checks that server-only code is not sent to the browser, and stops with an error if any page cannot be built.

The browser test

The real safety net is scripts/e2e_test.py, an end-to-end test. It is written in Python with Playwright, a library that drives a real Chromium browser: it opens pages, types into fields and clicks buttons, then checks what appears. It runs against the app on http://localhost:3100, so start the server first.

"""End-to-end test of Socialix in headless Chromium. Publishes nothing: the one post handed to the
autopilot is scheduled a year ahead and cancelled straight away (the autopilot worker must be stopped).
Reads the login from the app's .env without printing it. Usage: python scripts/e2e_test.py <out_dir>"""
import json, os, pathlib, re, subprocess, sys, time
from playwright.sync_api import sync_playwright

APP = pathlib.Path("C:/MLSCampus/social-media-ai-agent")
env = dict(re.findall(r"^([A-Z_]+)=(.*)$", (APP / ".env").read_text(encoding="utf-8"), re.M))
out = pathlib.Path(sys.argv[1]); out.mkdir(parents=True, exist_ok=True)
BASE = "http://localhost:3100"
TITLE = "SOCIALIX E2E TEST - not for publishing"
results = []

def check(name, ok, detail=""):
    results.append((name, bool(ok), detail))
    print(("PASS " if ok else "FAIL ") + name + (f"  ({detail})" if detail else ""), flush=True)

def verify():
    r = subprocess.run("pnpm exec tsx scripts/verify-post.ts \"%s\"" % TITLE, cwd=APP, shell=True, capture_output=True, text=True,
                       env={**os.environ, "NODE_OPTIONS": "--use-system-ca"}, timeout=120)
    line = [l for l in r.stdout.splitlines() if l.startswith("{")]
    return json.loads(line[-1]) if line else {"error": r.stderr[-400:]}

def card(page):
    return page.locator("section", has_text=TITLE).first

def ask(page, campaign, agent, text, timeout=300):
    page.goto(BASE + "/dashboard/ai-agent"); page.wait_for_load_state("networkidle")
    page.locator("button", has_text=agent.capitalize() + " Agent").first.click()
    before = page.evaluate(f"fetch('/api/agents/state?campaignId={campaign}&agent={agent}').then(r => r.json())")
    n = sum(1 for m in before["messages"] if m["role"] == "assistant")
    page.fill("input[placeholder^='Tell the']", text)
    page.click("button[aria-label=Send]")
    start = time.time()
    while time.time() - start < timeout:
        time.sleep(4)
        st = page.evaluate(f"fetch('/api/agents/state?campaignId={campaign}&agent={agent}').then(r => r.json())")
        replies = [m for m in st["messages"] if m["role"] == "assistant"]
        if not st["thinking"] and len(replies) > n:
            return replies[-1]["content"], time.time() - start
    return None, time.time() - start

with sync_playwright() as p:
    b = p.chromium.launch()
    page = b.new_page(viewport={"width": 1440, "height": 1000})
    errors = []
    page.on("console", lambda m: errors.append(m.text) if m.type == "error" else None)
    page.on("response", lambda r: errors.append(f"HTTP {r.status} {r.url}") if r.status >= 500 else None)

    # --- Authentication
    page.goto(BASE + "/dashboard"); page.wait_for_load_state("networkidle")
    check("signed-out visitor is sent to the sign-in page", "/signin" in page.url, page.url)
    page.fill("input[name=email]", env["APP_LOGIN_EMAIL"]); page.fill("input[name=password]", "wrong-password")
    page.click("button:has-text('Sign in')"); page.wait_for_url("**/signin?error=*", timeout=15000)
    check("wrong password is refused", page.get_by_text("Wrong email or password").count() > 0, page.url)
    page.fill("input[name=email]", env["APP_LOGIN_EMAIL"]); page.fill("input[name=password]", env["APP_LOGIN_PASSWORD"])
    page.click("button:has-text('Sign in')"); page.wait_for_url("**/dashboard**", timeout=15000)
    check("correct login opens the dashboard", "/dashboard" in page.url, page.url)
    # A fresh browser has no campaign cookie (the app falls back to the newest campaign), so read the id
    # from the AI Agent page's own state request.
    with page.expect_request(lambda r: "/api/agents/state?campaignId=" in r.url, timeout=15000) as req:
        page.goto(BASE + "/dashboard/ai-agent")
    campaign = re.search(r"campaignId=([^&]+)", req.value.url).group(1)
    check("a campaign is selected", bool(campaign))

    # --- Every page renders
    expected = {"": "Overview", "ai-agent": "AI Agents", "posts": "Posts", "calendar": "Calendar", "analytics": "Analytics",
                "accounts": "Accounts", "settings": "Settings", "campaigns/new": "campaign"}
    for path, heading in expected.items():
        resp = page.goto(f"{BASE}/dashboard/{path}"); page.wait_for_load_state("networkidle")
        body = page.inner_text("body")
        check(f"page /dashboard/{path} loads", resp.status == 200 and heading.lower() in body.lower() and "Application error" not in body, f"HTTP {resp.status}")
    page.goto(BASE + "/dashboard/accounts"); page.wait_for_load_state("networkidle")
    check("accounts page reads connections through MCP", "LinkedIn" in page.inner_text("body") and "connected" in page.inner_text("body").lower())
    page.goto(BASE + "/dashboard/calendar?week=1"); page.wait_for_load_state("networkidle")
    check("calendar moves to next week", "posts" in page.inner_text("body"))

    # --- Post lifecycle: create -> approve (queued in autopilot) -> cancel -> delete
    page.goto(BASE + "/dashboard/posts"); page.wait_for_load_state("networkidle")
    page.select_option("select[name=platform]", "LINKEDIN")
    page.fill("input[name=title]", TITLE)
    page.fill("textarea[name=body]", "Automated test post. It is scheduled a year ahead and cancelled immediately.")
    page.fill("input[name=hashtags]", "#test")
    page.fill("input[name=scheduledAt]", "2027-10-16T10:00")
    page.click("form:has(textarea[name=body]) button:has-text('Save')"); page.wait_for_load_state("networkidle"); page.wait_for_timeout(1000)
    check("manual post is created as awaiting approval", card(page).count() and "Awaiting approval" in card(page).inner_text())
    page.screenshot(path=str(out / "e2e-created.png"), full_page=True)

    card(page).locator("button", has_text="Approve").click(); page.wait_for_load_state("networkidle"); page.wait_for_timeout(2500)
    page.reload(); page.wait_for_load_state("networkidle")
    check("approve hands the post to the autopilot (queued)", "Queued" in card(page).inner_text())
    v = verify()
    check("autopilot has the post queued for 2027", v.get("handedOff") and v.get("autopilot") and "QUEUED" in v["autopilot"] and "2027-10-16" in v["autopilot"], (v.get("autopilot") or str(v))[:200])

    card(page).locator("button", has_text="Cancel").click(); page.wait_for_load_state("networkidle"); page.wait_for_timeout(2500)
    page.reload(); page.wait_for_load_state("networkidle")
    check("cancel marks the post cancelled", "Cancelled" in card(page).inner_text())
    v = verify()
    check("autopilot job is no longer queued", v.get("autopilot") and "QUEUED" not in v["autopilot"], (v.get("autopilot") or str(v))[:200])

    card(page).locator("button", has_text="Delete").click(); page.wait_for_load_state("networkidle"); page.wait_for_timeout(1500)
    page.reload(); page.wait_for_load_state("networkidle")
    check("delete removes the post", card(page).count() == 0 and not verify().get("found"))

    # --- Agents (real Claude calls)
    reply, secs = ask(page, campaign, "analytics", "Give me a two-sentence status report on this campaign's posts.")
    check("Analytics Agent answers", bool(reply), f"{secs:.0f}s: {(reply or '')[:160]!r}")
    reply, secs = ask(page, campaign, "creator",
                      "Write one X post (no research needed) inviting small business owners to try one AI tool this week. Title it 'E2E creator test'. Save it as a draft.")
    page.goto(BASE + "/dashboard/posts?tab=drafts"); page.wait_for_load_state("networkidle")
    draft = page.locator("section", has_text="E2E creator test").first
    check("Creator Agent saves a draft within the X limit", bool(reply) and draft.count() > 0, f"{secs:.0f}s: {(reply or '')[:200]!r}")
    page.screenshot(path=str(out / "e2e-creator-draft.png"), full_page=True)
    if draft.count():
        draft.locator("button", has_text="Delete").click(); page.wait_for_load_state("networkidle")

    check("no server errors or console errors", not errors, "; ".join(errors[:5]))
    b.close()

passed = sum(ok for _, ok, _ in results)
print(f"\n{passed}/{len(results)} checks passed")

Running it

  1. Install Playwright for Python once: pip install playwright, then playwright install chromium.
  2. Stop the autopilot's worker, so the test post (scheduled for 2027 anyway) cannot be picked up.
  3. Start Socialix: pnpm build then pnpm start (port 3100).
  4. In another terminal, in the project folder: python scripts/e2e_test.py test-output. Screenshots go into test-output.
What you should see. One PASS line per check, then 23/23 checks passed. In our run the Analytics Agent answered in 4 seconds and the Creator Agent saved an X draft of 262/280 characters in 8 seconds. The lifecycle part put the post in the autopilot's queue as QUEUED for 2027-10-16 14:00 UTC, then cancel set it to FAILED with "Cancelled from Socialix" (the autopilot has no "cancelled" status), and delete removed it.
Common mistakes with our checks
  • Server not running. Every page check fails with a connection error. Start pnpm start first. If it says EADDRINUSE :3100, a server is already running on that port.
  • Old build. You changed code but did not run pnpm build again, so the test checks yesterday's app.
  • Wrong APP path. Line 7 points to the owner's folder. On another machine the script cannot find .env and stops with FileNotFoundError.
  • Playwright browsers not installed. Playwright then says the Chromium executable does not exist. Run playwright install chromium.
  • Autopilot worker left running. The test post is scheduled for 2027 and cancelled at once, but stopping the worker is the rule the script states, so nothing can ever be published by a test.

Adding CodeRabbit to your own copy

Nothing stops you from using both. If you put your copy of the project on GitHub, follow the six steps from the video above: create the repository, push, sign in to CodeRabbit, Add Repositories, select only this repository, and check it is listed. Then work in branches and open a pull request for each change. Keep running pnpm typecheck, pnpm build and the browser test before you push: CodeRabbit reads your code, but it does not click through your app.

Video vs our app
  • Review: the video uses CodeRabbit on GitHub pull requests after each chapter. Socialix is not reviewed by CodeRabbit.
  • Checks: we run pnpm typecheck, pnpm build and the 23-check Playwright test (scripts/e2e_test.py), which the video does not have.
  • What each catches: an AI reviewer is good at spotting risky code and explaining changes. A browser test proves the app actually works end to end, including real Claude and MCP calls. They complement each other.
Recap
  • CodeRabbit is an AI reviewer that runs on every GitHub pull request once you install its GitHub App on the repository.
  • The video connects it in six steps and then ends every chapter with branch, commit, publish, pull request, review, merge.
  • Pick "Only select repositories" so it can only reach the project it reviews; keep .env out of Git.
  • Socialix is checked with pnpm typecheck (tsc --noEmit), pnpm build and scripts/e2e_test.py.
  • The browser test has 23 checks in five groups and passes 23/23; it still missed one bug that only a newer Chrome showed.
