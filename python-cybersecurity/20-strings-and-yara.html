Readable strings and an introduction to YARA

Pulling strings out of a binary to find IOCs, then writing YARA rules that recognise them.

▶ Watch this part (03:44:36)

Even a compiled binary is full of readable text: the addresses it contacts, the file paths it touches, the messages it prints. Pulling those strings out is one of the fastest ways to understand a sample. This step extracts strings and highlights indicators of compromise (IOCs), then introduces YARA, the industry-standard way to describe malware with simple pattern rules.

We analyse the harmless sample. Both scripts here read suspect.bin, the inert file built in Step 17. It carries realistic malicious-looking strings but no runnable code, so it is perfectly safe to scan and gives the detection tools something real to find.

What this step does

The presenter shows that strings alone often reveal a sample's purpose (at 3:44:36). Our first script, 17_strings.py, extracts readable ASCII and UTF-16 text and matches it against patterns for URLs, IP addresses, crypto wallets and ransom wording. The second, 18_yara_rules.py, writes three small YARA rules and scans the file with them, reporting which rules matched and exactly where.

New to IOCs? What they are

An indicator of compromise is a concrete, shareable artefact that points to malicious activity: a command-and-control (C2) URL, an IP address, a file hash, a Bitcoin address, a distinctive string. IOCs matter because they are portable: once you extract one from a sample, you can search for it across your network, block it at a firewall, or hand it to colleagues. Strings are often where the first IOCs come from.

Part 1: extracting strings and IOCs

Strings come in two common flavours on Windows: plain ASCII (one byte per character) and UTF-16 (two bytes per character, with a zero byte between). Our extractor finds both, then runs a set of regular-expression patterns over the raw bytes to pick out the interesting ones.

  1. From code/malware/, make sure suspect.bin exists (run python make_sample.py from Step 17 if not).
  2. Run python 17_strings.py. With no argument it defaults to suspect.bin; you can pass any file path instead.
"""Extracting readable strings and spotting indicators of compromise (IOCs).

Even a compiled binary contains readable text: URLs it contacts, file paths it
touches, messages it prints. Pulling those strings out is one of the fastest ways
to understand a sample. This extracts both ASCII and UTF-16 strings and highlights
ones that look like IOCs (URLs, IPs, crypto addresses, ransom wording).

Usage:  python 17_strings.py <path-to-any-file>   (defaults to suspect.bin)
"""
import os
import re
import sys

MIN_LEN = 4
# Patterns that commonly matter in an investigation.
IOC_PATTERNS = {
    "URL": re.compile(rb"https?://[^\s\"'<>\x00]{4,}"),
    "Onion/C2": re.compile(rb"[a-z0-9]+\.onion[^\s\"'<>\x00]*"),
    "IPv4": re.compile(rb"\b(?:\d{1,3}\.){3}\d{1,3}\b"),
    "Bitcoin": re.compile(rb"\b[13][a-km-zA-HJ-NP-Z1-9]{25,34}\b"),
    "Telegram": re.compile(rb"api\.telegram\.org[^\s\"'<>\x00]*"),
    "Ransom wording": re.compile(rb"(?i)(encrypted|ransom|bitcoin|decrypt)"),
}


def extract_strings(data: bytes):
    # ASCII runs of printable characters.
    ascii_re = re.compile(rb"[\x20-\x7e]{%d,}" % MIN_LEN)
    found = [m.group().decode("latin-1") for m in ascii_re.finditer(data)]
    # UTF-16LE strings (common on Windows): printable byte then a zero byte.
    utf16_re = re.compile(rb"(?:[\x20-\x7e]\x00){%d,}" % MIN_LEN)
    found += [m.group().decode("utf-16-le", "replace") for m in utf16_re.finditer(data)]
    return found


def main(path: str):
    with open(path, "rb") as f:
        data = f.read()
    strings = extract_strings(data)
    print(f"{len(strings)} readable string(s) in {os.path.basename(path)}. First 12:\n")
    for s in strings[:12]:
        print("   ", s)

    print("\nIndicators of compromise found:")
    any_hit = False
    for label, pattern in IOC_PATTERNS.items():
        for match in set(pattern.findall(data)):
            any_hit = True
            print(f"  [{label}] {match.decode('latin-1')}")
    if not any_hit:
        print("  none")


if __name__ == "__main__":
    default = os.path.join(os.path.dirname(__file__), "suspect.bin")
    main(sys.argv[1] if len(sys.argv) > 1 else default)

Why match on raw bytes with regular expressions?

Patterns like a URL or an IP address have a predictable shape, and regular expressions describe shapes concisely. Running them over the raw bytes (rather than over decoded text) means a pattern can match no matter how the string was stored, and it avoids errors from bytes that are not valid text. The trade-off is that patterns can over-match, so human review of the hits still matters.

Part 2: writing and running YARA rules

Extracting strings by hand works for one file. To recognise the same threat across thousands of files, analysts write YARA rules and share them. A rule names some patterns and a condition over them; YARA scans a file and tells you which rules matched, and where.

New to YARA? What a rule looks like

A YARA rule has three parts: an optional meta: block for notes, a strings: block listing the patterns (each named with a $), and a condition: block of boolean logic over those patterns, for example 2 of them or $a and $b. Modifiers tune matching: nocase ignores letter case, ascii matches plain bytes, and wide also matches the UTF-16 form. YARA is widely used to label malware families and to hunt for known threats.

  1. Install the Python binding once: pip install yara-python. We ran yara-python 4.5.4 (the module is imported as yara).
  2. From code/malware/, run python 18_yara_rules.py to scan suspect.bin with the three built-in rules.
"""Writing and running YARA rules.

YARA is the industry standard for describing malware with simple pattern rules.
A rule lists strings (text or bytes) and a condition; YARA scans a file and tells
you which rules matched. Analysts share rules to recognise known families.

This defines three small rules and scans a file with them.
Usage:  python 18_yara_rules.py <path-to-file>   (defaults to suspect.bin)
"""
import os
import sys
import yara

# A rule has: a name, a strings: section (the $-prefixed patterns) and a
# condition: (boolean logic over those patterns). 'nocase' = case-insensitive,
# 'wide' = match UTF-16 too, 'ascii' = match plain bytes.
RULES_SOURCE = r"""
rule Ransomware_Indicators {
    meta:
        description = "Wording and APIs typical of ransomware"
    strings:
        $a = "have been encrypted" nocase wide ascii
        $b = ".locked" ascii wide
        $c = "vssadmin delete shadows" nocase ascii wide
    condition:
        2 of them
}

rule Stealer_Indicators {
    meta:
        description = "Browser-credential theft and chat-app exfiltration"
    strings:
        $login = "Login Data" ascii wide
        $tg = "api.telegram.org" ascii wide
        $cookie = "cookies" nocase ascii wide
    condition:
        $login and ($tg or $cookie)
}

rule Backdoor_Indicators {
    strings:
        $cmd = "cmd.exe /c" nocase ascii wide
        $onion = ".onion" ascii wide
    condition:
        any of them
}
"""


def main(path: str):
    rules = yara.compile(source=RULES_SOURCE)      # compile once, reuse for many files
    matches = rules.match(path)
    print(f"Scanning {os.path.basename(path)} with {len(RULES_SOURCE.split('rule ')) - 1} rules\n")
    if not matches:
        print("No rules matched (file looks clean to these rules).")
        return
    for m in matches:
        print(f"  MATCH: {m.rule}")
        for s in m.strings:
            # Each matched string reports where it was found.
            for inst in s.instances:
                text = inst.matched_data.decode("latin-1", "replace")
                print(f"     {s.identifier} at offset {inst.offset}: {text!r}")


if __name__ == "__main__":
    default = os.path.join(os.path.dirname(__file__), "suspect.bin")
    main(sys.argv[1] if len(sys.argv) > 1 else default)

Common mistakes.
  • No module named 'yara' means the binding is missing. Install yara-python (not a package literally called "yara") into the same environment.
  • Writing a rule with a single common word in the condition. It will match everywhere and tell you nothing; require a combination, as the ransomware and stealer rules do.
  • Forgetting wide on a rule meant to catch Windows UTF-16 strings, so it silently misses them.
  • Treating a match as a conviction. YARA says "this pattern is present", which is a strong lead, but a human still confirms the finding in context.
Recap
  • Strings reveal URLs, paths and messages; filtering them for IOCs gives you artefacts to search and block.
  • Our sample yields 18 strings and six IOCs, including an onion C2 URL and a Bitcoin address.
  • A YARA rule is named patterns plus a condition; it reports matches with exact byte offsets.
  • All three rules match the deliberately-loaded sample; good rules require combinations, and humans confirm matches.
