HTTP status codes and what they tell an analyst

Reading 200, 401, 403, 404 and 500 and turning them into meaning for a scanner.

▶ Watch this part (01:46:20)

Every HTTP reply opens with a three-digit status code: the server's one-number summary of what happened. To an analyst those numbers are a map. A 200 says "this exists and I gave it to you"; a 401 says "this exists but it is protected"; a 404 says "nothing here"; a 500 says "I broke trying". This step reads codes back from the lab and learns what each one tells you.

Authorization first. The script requests several paths on the practice lab at 127.0.0.1, including one crafted to trigger an error. Probing paths and forcing errors on a system you do not own is an attack. Keep it on the lab and within the Rules of engagement.

What the status code tells you

The presenter walks through the families of codes (at 1:47:40): the 2xx group means success, 3xx means "go somewhere else", 4xx means "you got it wrong", and 5xx means "the server got it wrong". For someone mapping an authorized target, the interesting split inside 4xx and 5xx is what gives the game away. A GET that returns 200 found something real. A 401 or 403 means the path exists but is guarded — which is itself a discovery. A 404 means keep looking. And a 500 means you made the app do something it could not handle, which is often the first sign of a deeper flaw.

The script also reads two response headers to guess the server's technology. That technique is fingerprinting, and we give it its own treatment in Step 15; here we stay focused on the status codes themselves.

New to status codes? The short version

A status code is a number the server sends to say how the request went. The ones you meet most: 200 OK, 301/302 redirect, 401 unauthorized, 403 forbidden, 404 not found, 500 internal server error. You do not have to memorise them all — the first digit tells you the category, and a small lookup table (like the one in this script) covers the handful you see every day.

Why does a security analyst care about 401 vs 404?

Both are "you did not get the page", but they mean opposite things. A 404 says the path does not exist — a dead end. A 401 or 403 says the path does exist but is protected — you have just confirmed a real, guarded resource worth noting. Telling these apart is how content discovery turns a list of guesses into a map of the site.

Reading codes from the lab

The script defines a small lookup table, a describe() helper that requests a path and prints its code's meaning, and a fingerprint() helper for Step 15. It then asks the lab for four paths chosen to return four different codes.

  1. Make sure lab_server.py is running in Terminal 1 (Step 11).
  2. In Terminal 2, from code/requests/, run python 11_status_and_fingerprint.py.
  3. Match each path to the code it returned, using the table below.
"""HTTP status codes and simple server fingerprinting.

Status codes are the server's one-number summary of what happened. Fingerprinting
means reading response headers to guess the technology behind a site - useful for
an analyst mapping an authorized target. Start lab_server.py first.
"""
import requests

BASE = "http://127.0.0.1:8099"

# A short map so a tool can print human-friendly meanings.
MEANING = {
    200: "OK - the request succeeded",
    401: "Unauthorized - credentials needed or wrong",
    403: "Forbidden - the server refuses, even with credentials",
    404: "Not Found - no such resource",
    500: "Server Error - the app crashed handling the request",
}


def describe(path):
    resp = requests.get(BASE + path)
    code = resp.status_code
    print(f"{path:12} -> {code}  {MEANING.get(code, 'other')}")
    return resp


def fingerprint(resp):
    print("\nTechnology clues from headers:")
    for header in ("Server", "X-Powered-By"):
        value = resp.headers.get(header)
        if value:
            print(f"  {header}: {value}")


if __name__ == "__main__":
    describe("/")             # 200
    describe("/admin")        # 200 (a 'secret' path that exists)
    describe("/missing")      # 404
    home = describe("/product?id=1'")  # 500 from the fake SQL error
    fingerprint(home)

Why is a 500 the one that excites an analyst?

A 500 means the application hit an error it did not handle. You made it fail with input it did not expect — here, a single quote. That tells you the input reached somewhere sensitive (in the lab, a pretend SQL query) without being cleaned. Real 500s often leak stack traces, file paths or database messages, each a clue to the next step. For a defender, an unexpected 500 is equally a signal: something is being fed input it was never designed for.

What you should see. With the lab running, 11_status_and_fingerprint.py prints the four paths and their codes: 
/            -> 200  OK - the request succeeded
/admin       -> 200  OK - the request succeeded
/missing     -> 404  Not Found - no such resource
/product?id=1' -> 500  Server Error - the app crashed handling the request
The home page and the hidden /admin both return 200; /missing returns 404; and the single quote in /product?id=1' forces a 500. (The script then prints two "Technology clues" header lines — those belong to fingerprinting in Step 15.)
Common mistakes.
  • Treating 200 as "safe" and everything else as "failed". For an analyst 401, 403 and 500 are discoveries, not failures. Read the number, do not just check for 200.
  • Letting requests raise on error codes. By default requests does not raise for 4xx/5xx — you read resp.status_code yourself. Only resp.raise_for_status() would turn them into exceptions, which here you do not want.
  • Forgetting the quote is one character. It is id=1', a single quote appended. Dropping it gives a normal 200 and no error to see.
  • Lab not running. A missing server gives a ConnectionError rather than any status code. Start lab_server.py first.
Recap
  • The status code is the server's verdict; the first digit gives the family (2xx success, 4xx your error, 5xx server error).
  • 200 means found, 401/403 means guarded-but-real, 404 means nothing there, 500 means you broke something — the richest lead.
  • resp.status_code holds the number; a small lookup dict turns it into a readable meaning.
  • Defenders read the same codes in their logs, so a trail of 404s ending in a 500 looks like probing.
  • The technology clues this script also prints are fingerprinting — the subject of Step 15.
