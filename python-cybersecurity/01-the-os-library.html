The os library: Python's bridge to the operating system

Why almost every Python security tool leans on the os module, and your first calls into it.

▶ Watch this part (00:00:00)

Almost every security tool has to touch the real machine it runs on: read the folder it was launched from, create a place to save reports, look at files, or check how the computer is configured. Python's os module is the bridge that makes all of that possible. This first step gets you comfortable with it, because the next nine steps build on it.

The code on this page is our own, runnable version of what the course demonstrates for the os library. It only ever reads your machine and prints what it finds, so it is completely safe to run.

What the os module is for

The operating system is the software that manages your files, folders and running programs. Your Python script cannot reach those things directly; it asks the operating system to do it. The os module is the set of functions that carries those requests across. Early in the course (at 01:10) the presenter frames it the same way: before you can scan a website or inspect a file, your tool has to know where it is and what is around it.

Two more ideas matter from the start. First, different operating systems disagree about small things, such as the character between folder names (a backslash on Windows, a forward slash on Linux and macOS). Code that copes with those differences is called cross-platform, and the os module gives us helpers to stay that way. Second, the folder your program treats as "here" while it runs is its working directory; most tools write their output relative to it (at 02:40).

What this script does

  1. Opens a terminal in a folder of your choice and runs python 01_os_basics.py.
  2. Prints the working directory, so you can see exactly where the script thinks it is.
  3. Prints which operating system it is on, two different ways.
  4. Builds a file path the safe, cross-platform way with os.path.join.
  5. Lists the first few entries in the current folder.
New to the terminal? What it is and why we use it

A terminal is a text window where you type a command and press Enter instead of clicking. You launch every script in this guide by typing python followed by the file name. The folder you are "in" when you launch it becomes the script's working directory, which is why the first thing this script prints is that folder.

New to import? Bringing a library into your file

An import line loads code someone else already wrote so you can use it. import os makes the operating-system helpers available under the name os, and import platform loads a small standard library that reports things like the OS name. Both ship with Python, so there is nothing to install with pip.

The code

"""os library basics for security tooling.

The os module is Python's bridge to the operating system: it lets a script read
the current folder, create directories, walk the file system and run system
commands. Security tools lean on it constantly because an automated scanner or
analyzer has to touch real files and folders, not just values inside the program.

Run it with:  python 01_os_basics.py
Everything here only touches a throwaway folder it creates itself.
"""
import os
import platform

# Where am I running right now?
print("Current working directory:", os.getcwd())

# Which operating system is this? Tools branch on this to stay cross-platform.
print("Operating system:", platform.system())      # 'Windows', 'Linux' or 'Darwin'
print("os.name:", os.name)                          # 'nt' on Windows, 'posix' elsewhere

# The path separator differs per OS ('\\' on Windows, '/' on Linux/macOS).
# os.path.join builds a correct path without hard-coding the separator.
report_dir = os.path.join(os.getcwd(), "scan_reports")
print("A safe path built with os.path.join:", report_dir)

# List what is in the current folder (first five entries).
entries = os.listdir(".")
print("First entries in this folder:", entries[:5])

Why cross-platform care matters in security tools

You will often write a tool on one operating system and run it on another (your laptop is Windows, the server you analyse is Linux). If you hard-code "folder\\file" it will be wrong on Linux, and "folder/file" can be wrong on older Windows tooling. os.path.join and os.pathsep always pick the right character, so the same code runs everywhere.

What you should see. On a Windows machine the output looks like this (your folder path will be your own): 
Operating system: Windows
os.name: nt
A safe path built with os.path.join: ...\code\out\scan_reports
First entries in this folder: ['01_os_basics.txt']
The first line it prints is Current working directory: followed by the folder you ran it from. On Linux or macOS the two OS lines would read Linux / posix (or Darwin / posix) and the path separators would be forward slashes.
Common mistakes.
  • Expecting the script's folder. os.getcwd() is the folder you launched from, which can differ from where 01_os_basics.py is saved. Run it from the folder you actually want to work in.
  • Building paths by hand. Writing os.getcwd() + "/scan_reports" may work on your machine and break on another. Use os.path.join.
  • Confusing the two OS checks. platform.system() gives 'Windows'/'Linux'/'Darwin'; os.name gives 'nt'/'posix'. Pick the one that matches the comparison you are writing.
  • Forgetting the import. Leaving out import platform raises NameError: name 'platform' is not defined.
Recap
  • The os module is Python's bridge to the operating system; security tools rely on it to touch real files and folders.
  • os.getcwd() tells you the working directory — the folder output is written relative to.
  • platform.system() and os.name report the operating system so tools can branch per platform.
  • os.path.join keeps paths cross-platform by choosing the right separator for you.
  • os.listdir(".") lists what is in the current folder, the starting point for any scanner.
