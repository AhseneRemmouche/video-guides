Glossary

Every technical term in this guide, explained for beginners.

Every technical term used in this guide, in plain language. Terms are grouped by topic. Each page links here the first time it uses a term.

Operating system and Python

Operating system (OS)
The software that runs your computer and manages its files, memory and programs. Windows, macOS, Linux and Android are operating systems.
os module
Python's built-in library for talking to the operating system: reading the current folder, creating directories, reading environment variables and running system commands. It is the foundation most security tools build on.
Terminal (command line)
A text window where you type commands instead of clicking. You run the scripts in this guide from a terminal.
Working directory
The folder a program treats as "here" while it runs — the folder you were in when you launched it. os.getcwd() returns it.
PATH (system variable)
A list of folders the operating system searches when you type a command name like python. Reading it shows which tools are installed and where.
Environment variable
A named value the operating system hands to programs when they start — the user name, the home folder, or secrets like API keys. Reading secrets from the environment keeps them out of your source code.
pip
Python's package installer. pip install requests downloads and installs a library so you can import it.
Virtual environment (venv)
A private, per-project copy of Python and its installed packages, so one project's libraries do not clash with another's.
Standard output (stdout)
The default place a program's text goes — normally your terminal. print() writes there.
Cross-platform
Code that runs unchanged on Windows, macOS and Linux. Using os.path.join and os.pathsep instead of hard-coded slashes keeps tools cross-platform.

The web and HTTP

HTTP
HyperText Transfer Protocol — the request-and-response language browsers and tools use to talk to web servers.
HTTPS
HTTP wrapped in encryption (TLS), so no one between you and the server can read or change the traffic.
HTTP method
The verb of a request that says what you want to do: GET to fetch, POST to send data, and others such as PUT and DELETE.
GET request
An HTTP request that asks the server for a resource. Any data it carries is in the URL as query parameters.
POST request
An HTTP request that sends data to the server in the request body — used by login forms, for example.
Request
The message a client sends to a server: a method, a URL, headers and an optional body.
Response
What the server sends back: a status code, headers and a body (often HTML or JSON).
Status code
A three-digit number summarising the result of a request — 200 OK, 404 Not Found, 500 Server Error, and so on.
Header
A name-and-value line of metadata attached to a request or response — who the client is, what content type is returned, which security rules apply.
Query parameter
A value passed in a URL after ?, like ?q=hello. Parameters are a common place user input enters an application.
User-Agent
A header that names the client software making the request. Tools can set it to look like a normal browser; servers and defenders log it.
URL
The address of a web resource, e.g. http://127.0.0.1:8099/login — scheme, host, port and path.
requests (library)
The standard Python library for sending HTTP requests and reading responses. Almost every web-security script uses it.
TLS
Transport Layer Security — the encryption that turns HTTP into HTTPS and proves a server's identity with a certificate.
Cookie
A small value a server asks the browser to store and send back on later requests, often to remember a login session.
Session
A server's memory of one logged-in user across several requests, usually tracked by a cookie.

Web vulnerabilities and testing

Vulnerability
A weakness in software that an attacker could misuse to do something they should not be able to do.
Cross-site scripting (XSS)
A flaw where an application includes attacker-supplied input in a page without escaping it, so the browser runs it as code. The fix is output encoding.
Reflected XSS
XSS where the input you send in a request is immediately echoed back in the response, like a search term shown on the results page.
SQL injection (SQLi)
A flaw where user input is pasted into a database query, letting an attacker change what the query does. The fix is parameterised queries.
Injection
Any flaw where untrusted input is treated as part of a command or query instead of as plain data.
Payload
The specific input a tester sends to check for or demonstrate a vulnerability. In this guide, payloads are harmless markers, never live exploits.
Output encoding
Converting characters like < and > into safe forms before putting user input into a page, so the browser shows them as text instead of running them. The main defence against XSS.
Parameterised query
A database query where values are passed separately from the SQL text, so input can never change the query's structure. The main defence against SQL injection.
Security header
An HTTP response header that tells the browser to enforce a protection, such as blocking framing or restricting where scripts may load from.
Content-Security-Policy (CSP)
A security header that lists where a page may load scripts, styles and other resources from — a strong defence against XSS.
HTTP Strict-Transport-Security (HSTS)
A security header that forces browsers to use HTTPS for a site, blocking downgrade attacks.
Content discovery
Probing a site for paths and files that are reachable but not linked, such as /admin or /.env, usually with a wordlist.
Wordlist
A list of candidate names a tool tries one by one — for paths, usernames or passwords. Using one against a system you do not own is an attack.
Fingerprinting
Working out what technology a target runs (web server, framework, version) by reading clues such as response headers.
CVE
Common Vulnerabilities and Exposures — a public, uniquely numbered record of a known security flaw, e.g. CVE-2021-41773.
NVD
The U.S. National Vulnerability Database, a free source of CVE records with severity scores and a JSON API.
CVSS
Common Vulnerability Scoring System — a 0–10 score and severity label (Low to Critical) describing how serious a CVE is.

Malware analysis

Malware
Software written to harm or abuse a system — viruses, ransomware, stealers, backdoors and more.
Infostealer
Malware that collects sensitive data (saved passwords, cookies, files) and sends it to the attacker. This guide teaches how it works only to defend against it.
Ransomware
Malware that encrypts a victim's files and demands payment to restore them.
Stealer
Short for infostealer: malware focused on stealing credentials and other secrets.
Backdoor
Malware that gives an attacker hidden remote access to a machine, often taking commands from a server they control.
Static analysis
Examining a file without running it — reading its headers, imports and strings. Safer than running the sample.
Dynamic analysis
Running a sample in a controlled, isolated environment to watch what it does. Powerful but risky; needs a sandbox.
Sandbox
An isolated environment (often a disposable virtual machine) where suspicious code can run without touching the real system or network.
PE file
Portable Executable — the file format of Windows .exe and .dll files. It has headers that describe the program before it runs.
Section
A named region inside a PE file, such as .text (code) or .data (data). Each has a size and other properties.
Entropy
A 0–8 measure of how random a chunk of data looks. Very high entropy in a code section often means it is compressed or encrypted (packed).
Import table
The list, stored in a PE file, of external functions it plans to call and which DLLs provide them — a preview of what the program can do.
DLL
Dynamic-Link Library — a Windows file of shared functions that programs import and call, such as KERNEL32.dll.
API call
A program's use of a function provided by the operating system or a library, such as CreateRemoteThread. Which APIs a binary imports hints at its behaviour.
Indicator of compromise (IOC)
A concrete clue that a file or system is malicious — a known bad URL, IP address, file hash or distinctive string.
Command-and-control (C2)
The server an attacker uses to send commands to and receive data from malware they have planted.
YARA
A tool and language for describing malware with pattern rules, so files can be scanned and matched against known families.
YARA rule
One named pattern: a set of strings or bytes and a condition that decides when a file matches.
Hash
A fixed-length fingerprint of data produced by a one-way function. Two identical files share a hash; a tiny change gives a completely different one.
MD5
An old, fast hashing function. Fine as a non-security identifier or marker, but broken for proving integrity — use SHA-256 for that.
Packing
Compressing or encrypting a program so its real code is hidden until it runs — common in malware to dodge simple scanners. Shows up as high entropy.

Browser automation

Playwright
A library that drives a real browser (Chromium, Firefox or WebKit) from code, so a script sees pages exactly as a user would after JavaScript runs.
Headless browser
A real browser running without a visible window — fast and scriptable, ideal for automation and servers.
DOM
Document Object Model — the live, in-memory tree of elements a browser builds from a page. Checking the DOM confirms whether injected input became real HTML.
Single-page app (SPA)
A site that builds its pages with JavaScript in the browser. Simple HTTP tools see an empty shell, so a real browser is needed to test it.
Selector
A short expression that points at elements on a page, such as input[name=username].
Locator
Playwright's object representing elements matched by a selector, which you then read or act on.
Brute-force attack
Trying many passwords (or other values) against a login until one works. Doing this against a system you do not own is illegal.
Rate limiting
Capping how many requests or attempts a client may make in a time window — a core defence against brute force and abuse.
Account lockout
Temporarily disabling a login after too many failed attempts, so guessing becomes impractical.
Multi-factor authentication (MFA)
Requiring a second proof of identity beyond a password, such as a code or hardware key, so a stolen password alone is not enough.
CAPTCHA
A challenge meant to be easy for humans and hard for scripts, used to slow automated attempts.

Ethics and the law

Authorization
Explicit, documented permission from the owner to test a specific system. Without it, security testing is illegal — no matter how good your intentions.
Scope
The exact systems, addresses and actions an authorization covers. Anything outside the scope is off-limits.
Penetration test
An authorized, scoped engagement where testers simulate attacks to find weaknesses before real attackers do.
Responsible disclosure
Reporting a vulnerability privately to the owner and giving them time to fix it before any public mention.
Capture the Flag (CTF)
A legal security game with challenges built for hacking practice — a safe place to use everything in this guide.
Red team
The offensive side of security: authorized testers who emulate attackers.
Blue team
The defensive side: the people who detect, analyse and stop attacks. Most of this guide is blue-team work.
Cybersecurity
The practice of protecting systems, networks and data from attack, misuse and failure.
Ethical hacking
Using attacker techniques legally and with permission, to improve security rather than to harm.
