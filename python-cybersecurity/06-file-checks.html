Checking that files exist and reading their size

Using os.path to test for a file and measure it before acting on it.

▶ Watch this part (00:32:54)

Before a tool reads or analyses a file, it should ask a few quick questions: is the file actually there? Is it a file and not a folder? How big is it? What is its name, and which folder is it in? Python answers all of these through os.path, and this step shows the five checks you will reach for most. They are the same calls at the end of the 03_files.py script you ran in the previous step.

These checks are the start of safe, defensive tooling: a malware analyser that opens a file it has not confirmed exists, or reads a zero-byte sample as if it had content, will crash or give nonsense. A one-line check first avoids both.

The idea: ask os.path before you act

The os module includes a sub-module, os.path, full of small functions that answer questions about a path without opening the file (at 18:40 in the course). Because they only inspect, they are cheap and safe to call. The five below are the ones a beginner uses constantly.

CallAnswersReturns for scan.txt

os.path.isfile(p)Is it a file (not a folder)?True
os.path.getsize(p)How many bytes is it?64

Trying the checks yourself

  1. Run 03_files.py from Step 05 so that toolkit_output/reports/scan.txt exists.
  2. Read the last five lines it prints — those are exactly the os.path checks covered here.
  3. Point the same calls at a path that does not exist and watch os.path.exists return False instead of crashing.
  4. Add a line to the file by hand, re-run, and see os.path.getsize report a larger byte count.

The five checks

Here are the same calls from 03_files.py (lines 31–35), shown on their own so you can see them without the rest of the script:

report_path = os.path.join("toolkit_output", "reports", "scan.txt")

print("Exists:", os.path.exists(report_path))
print("Is a file:", os.path.isfile(report_path))
print("Size in bytes:", os.path.getsize(report_path))
print("Just the file name:", os.path.basename(report_path))
print("Just the folder:", os.path.dirname(report_path))

Line by line

Line(s)CodeWhat it does & why
31os.path.exists(report_path)Returns True if something (a file or a folder) is at that path, False if nothing is. The first thing to check before reading, so you fail politely instead of crashing with FileNotFoundError.
32os.path.isfile(report_path)Returns True only for a real file. A path can exist but be a folder, so this distinguishes the two before you try to open it.
33os.path.getsize(report_path)Returns the size in bytes. Here 64. A size of 0 means an empty file — often a sign something went wrong upstream.
34os.path.basename(report_path)Returns just the last part of the path, scan.txt, dropping every folder. Handy for naming output or printing a tidy label.
35os.path.dirname(report_path)Returns the folder part only, without the file name — the mirror image of basename.
What is a byte, and why does size matter?

A byte is the basic unit of digital storage; one byte usually holds one plain English character. So a 64-byte text file is roughly 64 characters including the invisible newlines. In security work, size is a quick signal: an empty (0-byte) sample has nothing to analyse, and an unexpectedly huge file might be a decompression trap, so tools check size before loading a file into memory.

Path, file name, and folder: three views of one string

A full path like toolkit_output/reports/scan.txt contains both a folder part and a file name. os.path.dirname gives you the folder (toolkit_output/reports) and os.path.basename gives you the file name (scan.txt). Splitting a path this way is far safer than searching for slashes yourself, and it stays cross-platform.

What you should see. Running the end of 03_files.py against the scan.txt it just wrote prints: 
Exists: True
Is a file: True
Size in bytes: 64
Just the file name: scan.txt

Exists and Is a file are both True, the size is exactly 64 bytes, and the path splits cleanly into the file name scan.txt and its reports folder.
Common mistakes.
  • Treating exists as "is a file". os.path.exists is also True for folders. Follow it with os.path.isfile when you specifically need a file.
  • Opening without checking. Calling open on a missing path raises FileNotFoundError. Check exists first and fail with a clear message.
  • Ignoring a zero-byte file. getsize can return 0; analysing an empty file wastes work or crashes. Test getsize(p) > 0 before reading.
  • Splitting paths by hand. Searching for "/" or "\\" to find the file name breaks across operating systems. Use basename and dirname.
Recap
  • os.path.exists says whether anything is at a path; os.path.isfile confirms it is a file, not a folder.
  • os.path.getsize returns the size in bytes (64 for our scan.txt); a 0 means empty.
  • os.path.basename and os.path.dirname split a path into its file name and its folder, cross-platform.
  • Running these cheap checks before opening a file is the first habit of a safe, defensive tool.
