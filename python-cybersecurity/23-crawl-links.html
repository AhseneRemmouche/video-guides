First script: open a browser and crawl a site's links

Opening a page in a headless browser and mapping its internal and external links.

▶ Watch this part (04:43:27)

Now that we can open a page with a real browser, let us do something useful with it: read every link on the page and sort the links into those that stay on the same site and those that point elsewhere. Mapping a site's links is the first, gentlest step of reconnaissance — it shows you the pages, login areas and admin corners that make up a target's attack surface.

Authorization first. Crawling and reconnaissance are only legal on a system you own or have explicit, written permission to test. In this guide we only ever crawl the local practice lab on 127.0.0.1. Before pointing any crawler at a real site, re-read the rules of engagement on the Rules of engagement page. Same code, different target, completely different legal meaning.

What crawling links tells a tester

Every page on a site is reachable through links, so collecting the links is how you discover what else exists. The presenter describes this (at 4:38:20) as drawing a map before you explore: you want to know which links are internal (part of the same site, and therefore in scope if the site is your target) and which are external (pointing at other people's sites, which are not in your scope). Keeping those two apart is both a practical and an ethical habit — you never want to wander off your authorized target by following an external link.

To decide "same site or not", we compare the host part of each link's URL against the host of our base URL. A link like /login has no host of its own; it is relative. We turn it into a full absolute URL first (so /login becomes http://127.0.0.1:8099/login), then read its host. That is what urljoin and urlparse from Python's standard library do for us.

New to internal vs external links? Why it matters here

An internal link stays on the same host (same domain and port) — it leads to another page of the same site. An external link leaves for a different host, like example.com. For a tester with permission to test one site, internal links are the pages you may look at; external links belong to someone else and are out of scope. Sorting them automatically keeps you honest and saves time.

New to urljoin and urlparse? What they do

Both come from Python's built-in urllib.parse module — no install needed. urljoin(base, href) combines a base URL with a possibly-relative link to produce one absolute URL, following the same rules a browser uses. urlparse(url) breaks a URL into its parts; we use its .netloc (the host, including port) to compare where two links point.

Run it

  1. Make sure the lab is still running in its own terminal: 
    python lab_server.py
  2. Save the script below as 21_crawl_links.py next to it.
  3. Run it in a second terminal: 
    python 21_crawl_links.py
"""Extract every link on a page and sort them into internal vs external.

Mapping a site's links is the first step of reconnaissance on an authorized
target: it shows the attack surface (pages, login forms, admin areas). This reads
every <a href> the browser rendered and classifies each link by its host.
Start lab_server.py first.
"""
from urllib.parse import urljoin, urlparse
from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8099"
base_host = urlparse(BASE).netloc

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto(BASE + "/")

    # get_attribute across all matches: one call returns a list of href values.
    hrefs = page.locator("a").evaluate_all(
        "els => els.map(e => e.getAttribute('href'))"
    )

    internal, external = [], []
    for href in hrefs:
        if not href:
            continue
        absolute = urljoin(BASE, href)        # turn '/login' into a full URL
        if urlparse(absolute).netloc == base_host:
            internal.append(absolute)
        else:
            external.append(absolute)

    print("Internal links (same site):")
    for link in sorted(set(internal)):
        print("  ", link)
    print("\nExternal links (other sites):")
    for link in sorted(set(external)):
        print("  ", link)

    browser.close()

Internal links (same site):

   http://127.0.0.1:8099/search?q=hi

   https://example.com
The relative links /login and /search?q=hi were turned into full lab URLs and kept as internal, while https://example.com was correctly put aside as external.
Common mistakes.
  • Forgot to start the lab. No server on 127.0.0.1:8099 means page.goto fails to connect. Start lab_server.py first.
  • Forgot playwright install. If the Chromium binary was never downloaded, launching the browser errors out. Run python -m playwright install chromium once.
  • Treating relative links as external. If you skip urljoin and read the host of /login directly, its host is empty and it looks external. Always build the absolute URL first.
  • Crawling the wrong target. Changing BASE to a site you do not own turns a harmless exercise into unauthorized scanning. Keep it on your lab unless you have written permission.
Recap
  • Collecting links maps a site's attack surface — the first step of authorized reconnaissance.
  • page.locator("a").evaluate_all(...) reads every link's href in one efficient call.
  • urljoin makes relative links absolute; urlparse(...).netloc gives the host used to classify them.
  • Splitting internal from external links keeps your testing inside the scope you are allowed to touch.
  • Only ever crawl your own lab or a target with written permission — see the Rules of engagement page.
