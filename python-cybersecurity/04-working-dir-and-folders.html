The working directory and creating folders

getcwd, mkdir, makedirs and the safe, re-runnable pattern for building output folders.

▶ Watch this part (00:11:13)

A security tool almost always begins by building a tidy place to put its output: one folder for reports, one for logs, one for samples. Doing that by hand is easy; doing it so the tool can be run twice without crashing is the part beginners miss. This step shows the safe, re-runnable pattern for creating folders with the os module.

This is our own, runnable version of the folder-handling the course walks through. It only creates a throwaway toolkit_output folder next to where you run it.

The idea: a tool needs a tidy home

When the presenter builds the toolkit's output structure (at 11:20) the point is organisation: results should not pile up in one messy folder. But there is a trap. The simple command that makes a folder, os.mkdir, fails with an error the second time, because the folder is already there. A real tool is run many times, so it must notice what already exists and leave it alone. That "check, then act" habit is the whole lesson here.

What this script does

  1. Reads the working directory and uses it as the base for everything.
  2. Builds the path toolkit_output with os.path.join (never by gluing strings).
  3. Creates that top folder with os.mkdir, but only after checking it does not already exist.
  4. Creates three sub-folders (reports, logs, samples) with os.makedirs(..., exist_ok=True).
  5. Lists the contents of toolkit_output to confirm the result.
New to folders vs files? The quick version

A folder (also called a directory) is a container; a file holds actual content such as text. This step only makes folders — empty containers. The next step fills one of them with a file. Folders can be nested inside folders, which is how toolkit_output/reports is a folder named reports living inside toolkit_output.

What is an exception, and what is FileExistsError?

When Python cannot do what you asked, it raises an exception: it stops and reports an error instead of returning a value. os.mkdir on a folder that already exists raises FileExistsError. You can either avoid it (check os.path.exists first, as this script does) or pass exist_ok=True to os.makedirs so it quietly does nothing when the folder is already there.

The code

"""Creating folders safely: getcwd, mkdir, makedirs and existence checks.

A security tool usually starts by building a tidy output structure (a folder for
reports, one for logs, one for samples). Doing that blindly crashes the second
time you run it, because the folder already exists. This shows the safe pattern.
"""
import os

# 1. The current working directory is the folder the script was launched from.
base = os.getcwd()
print("Working directory:", base)

# 2. Build the path for a new folder. Never concatenate strings with '/' by hand.
target = os.path.join(base, "toolkit_output")

# 3. os.mkdir makes ONE folder and raises FileExistsError if it is already there.
#    So we check first with os.path.exists. This is the safe, re-runnable pattern.
if not os.path.exists(target):
    os.mkdir(target)
    print("Created:", target)
else:
    print("Already exists, leaving it alone:", target)

# 4. os.makedirs makes a whole chain of nested folders at once.
#    exist_ok=True means "do nothing if it already exists" (no crash on re-run).
for sub in ("reports", "logs", "samples"):
    path = os.path.join(target, sub)
    os.makedirs(path, exist_ok=True)
    print("Ready:", path)

# 5. Confirm what we built.
print("Contents of toolkit_output:", os.listdir(target))

mkdir vs makedirs: which should I reach for?

Use os.mkdir when you need exactly one folder and its parent already exists. Use os.makedirs when the path has several levels that might not exist yet (for example toolkit_output/reports/2026), because it creates the whole chain in one call. Add exist_ok=True to makedirs whenever the tool might run more than once.

What you should see. On the first run (your paths will be your own, shortened here): 
Working directory: ...\code\out
Created: ...\toolkit_output
Ready: ...\toolkit_output\reports
Ready: ...\toolkit_output\logs
Ready: ...\toolkit_output\samples
Contents of toolkit_output: ['logs', 'reports', 'samples']
Run it a second time and the second line changes to Already exists, leaving it alone: — the sub-folder lines and the final listing stay the same, and nothing is lost. Note the final list comes back sorted as ['logs', 'reports', 'samples']; the order the operating system returns is not guaranteed to match the order you created them.
Common mistakes.
  • Calling os.mkdir twice. Running a tool that uses bare os.mkdir a second time raises FileExistsError. Either guard it with os.path.exists or switch to os.makedirs(..., exist_ok=True).
  • Using os.mkdir for a deep path. os.mkdir("a/b/c") fails if a or b do not exist. os.makedirs creates the missing parents.
  • Assuming an order from listdir. The returned list is not sorted by creation time. Sort it yourself if order matters.
  • Running from the wrong folder. The output lands relative to the working directory, so launch the script from where you want toolkit_output to appear.
Recap
  • os.mkdir makes one folder and raises FileExistsError if it is already there; its parent must exist.
  • Guarding os.mkdir with os.path.exists makes the step safe to repeat.
  • os.makedirs(path, exist_ok=True) creates a whole chain of folders and never crashes on a re-run.
  • Build every path with os.path.join, and confirm the result with os.listdir.
