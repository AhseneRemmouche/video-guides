Project: a one-click security-project scaffolder

Tying the os module together into a script that builds a whole toolkit layout at once.

▶ Watch this part (00:58:15)

This is the capstone of the os module. Everything you learned so far, joining paths, making folders safely, writing files, reading the environment, comes together in one small tool: run it once and it builds a clean, professional folder layout for a new security project, drops starter files in the right places, and writes a README. Run it again and nothing breaks, because it only fills in what is missing.

What the presenter explains

Real tools are not one giant file; they are organised into folders by responsibility (at 58:40). The course settles on a layout a scanner would actually use: a core folder for shared logic, a modules folder with one file per check, and a reports folder for output. Instead of creating this by hand every time, we describe the layout as data, a dictionary, and let Python build it (at 1:02:00).

The quality that makes the tool safe to re-run is idempotence (at 1:06:00): doing the same thing twice leaves the same result. Two os features deliver it. os.makedirs(path, exist_ok=True) creates a folder and quietly does nothing if it already exists, and an os.path.exists check before every file write means the tool never clobbers work you have already done. The presenter finishes by walking the finished tree with os.walk (at 1:10:00) to print what was built.

Do this

  1. Create os/06_project_scaffolder.py in your project.
  2. Run it in your terminal: python os/06_project_scaffolder.py. It creates a my_scanner folder inside your current working directory.
  3. Look at the printed tree, then open the my_scanner folder and confirm the files are there.
  4. Run the exact same command a second time. Nothing changes and nothing errors. That is the idempotence in action.
  5. Edit one of the starter files (add a line to core/http_client.py), run again, and confirm your edit survives: the tool skips files that already exist.

The full file

This is our own, runnable version of the scaffolder the video builds. It uses only functions from the earlier os steps.

"""Project: a one-click security-project scaffolder.

This ties the whole os module together. Run it once and it builds a clean,
professional folder layout for a new security tool, drops starter files in the
right places, and writes a README. Running it again is safe: it never overwrites
existing files, it only fills in what is missing.

The layout separates concerns the way real tools do:
  core/     - shared logic (HTTP client, logging)
  modules/  - one file per check (headers, status, discovery)
  reports/  - output goes here
  README.md - what the tool is
"""
import os

# A dict maps each folder to the starter files it should contain.
LAYOUT = {
    "core": ["__init__.py", "http_client.py", "logger.py"],
    "modules": ["__init__.py", "security_headers.py", "status_check.py"],
    "reports": [".gitkeep"],
}

STARTER = {
    "http_client.py": "import requests\n\n# shared request session goes here\n",
    "logger.py": "# simple logging helpers\n",
    "security_headers.py": "# check a site's security headers\n",
    "status_check.py": "# interpret HTTP status codes\n",
}


def scaffold(project_name: str) -> str:
    root = os.path.join(os.getcwd(), project_name)
    os.makedirs(root, exist_ok=True)

    for folder, files in LAYOUT.items():
        folder_path = os.path.join(root, folder)
        os.makedirs(folder_path, exist_ok=True)
        for file_name in files:
            file_path = os.path.join(folder_path, file_name)
            if not os.path.exists(file_path):            # never clobber existing work
                with open(file_path, "w", encoding="utf-8") as f:
                    f.write(STARTER.get(file_name, ""))

    readme = os.path.join(root, "README.md")
    if not os.path.exists(readme):
        with open(readme, "w", encoding="utf-8") as f:
            f.write(f"# {project_name}\n\nA security toolkit scaffolded with Python.\n")

    return root


if __name__ == "__main__":
    created = scaffold("my_scanner")
    print("Project ready at:", created)
    for current, dirs, files in os.walk(created):
        depth = current.replace(created, "").count(os.sep)
        print("  " * depth + os.path.basename(current) + os.sep)
        for name in files:
            print("  " * (depth + 1) + name)

What does "idempotent" mean?

An operation is idempotent when running it once and running it many times give the same end state. Pressing an elevator button is idempotent; adding a coin to a jar is not. This scaffolder is idempotent because makedirs(exist_ok=True) and the os.path.exists checks mean a second run creates nothing new and changes nothing. That property is what lets you re-run a setup tool without fear.

Why describe the layout as a dictionary?

The code that creates folders and files never mentions specific names; it loops over the LAYOUT dictionary. That separation means adding a new folder or file is a one-line data change, not a logic change. It is the same idea as configuration driving behaviour, and it keeps the building logic short and reusable.

What is os.walk and why use it here?

os.walk visits a folder and everything beneath it, handing you each directory along with the sub-directories and files it contains. It saves you from writing your own recursion. Here it is used only to print a tidy tree of what was built, but the same call is how real tools scan a project or a target folder.

What you should see. The run prints the created path and a tree of the result:

Your path before my_scanner will match wherever you ran the command. Running it again prints the same tree and changes nothing on disk.
Common mistakes.
  • Expecting the project in a specific place. It is created in your current working directory; cd to where you want it before running, or the folder appears wherever your terminal happens to be.
  • Removing exist_ok=True from makedirs. The second run then raises FileExistsError and the tool is no longer safe to re-run.
  • Dropping the os.path.exists check before writing. Every run would overwrite your files with the blank starter content, erasing your work.
  • Building paths by gluing strings with + and a slash. Use os.path.join so the result is correct on Windows and Unix alike.
Recap
  • The scaffolder describes its folder layout as a dictionary and builds it with a loop, so structure changes are data changes.
  • os.makedirs(exist_ok=True) and an os.path.exists guard make the tool idempotent: safe to run again and again.
  • os.path.join keeps every path cross-platform; os.walk prints the finished tree.
  • This capstone imports nothing new, it recombines the os skills from Steps 04, 05 and the environment steps into one useful tool.
