Case study: how infostealers abuse the system (and how defenders spot them)

The video's browser-data-to-Telegram example, reframed as a threat model with detection and defences.

▶ Watch this part (00:03:49)

At 03:49 the course shows a short script that copies a browser's saved logins and cookies and sends them to a Telegram bot. That pattern is a real class of malware called an infostealer, and building a working one is exactly the kind of thing this guide will not do. But the knowledge behind it is genuinely useful to a defender: if you know what a stealer takes and where it looks, you can protect it and detect the theft. So this step keeps the lesson and drops the weapon.

What we will not do. We do not read, copy, decrypt or send anyone's browser data. The script on this page only checks whether folders exist on your own machine and prints advice. Run it only on a computer you own. See Rules of engagement.

How an infostealer works (so you can stop it)

Stealers are one of the most common kinds of malware today because the payoff is high and the targets are predictable. The pattern is almost always the same four moves:

  1. Locate. Browsers keep saved passwords, cookies and autofill data in fixed, well-known folders. The malware does not have to search — it knows exactly where to go, using the same environment variables (like LOCALAPPDATA) you met in the os module.
  2. Copy. It reads those files. Some data is encrypted with a key that is itself stored on the same machine, which is why local malware can often undo it.
  3. Exfiltrate. It sends the loot somewhere the attacker can collect it. Chat APIs such as Telegram or Discord are popular because they look like ordinary web traffic and need no server of the attacker's own — this is a simple form of command-and-control.
  4. Hide. It tries to look boring and delete its traces.

The defender's version of the same script

Here is a safe tool that uses the "locate" knowledge for good. It builds the same folder paths a stealer would target and reports whether they exist on your machine — nothing more. It never opens or transmits a single byte of their contents. Treat it as a reminder of what lives on your disk and needs protecting.

"""Defensive awareness: where browsers keep sensitive data, and why that matters.

The video shows an attacker's "infostealer" pattern: a script that copies a
browser's saved logins and cookies and ships them to a Telegram bot. We do NOT
reproduce that tool. Instead this script does the defender's version of the same
knowledge: it LOCATES the sensitive browser files on THIS machine (read-only,
your own data) and reports whether they exist, so you understand what a stealer
targets and can protect it.

It never opens, copies, decrypts or transmits anything. It only checks paths.
Use it only on a machine you own.
"""
import os

# These are the well-known locations infostealers look for. Knowing them is how a
# defender reasons about what to encrypt, monitor and lock down.
def browser_data_locations() -> dict[str, str]:
    local = os.environ.get("LOCALAPPDATA", "")
    roaming = os.environ.get("APPDATA", "")
    home = os.environ.get("USERPROFILE") or os.environ.get("HOME") or ""
    return {
        "Chrome profile":  os.path.join(local, "Google", "Chrome", "User Data", "Default"),
        "Edge profile":    os.path.join(local, "Microsoft", "Edge", "User Data", "Default"),
        "Firefox profiles": os.path.join(roaming, "Mozilla", "Firefox", "Profiles"),
        "Linux Chrome":    os.path.join(home, ".config", "google-chrome", "Default"),
    }


def main():
    print("Sensitive browser data locations on this machine (read-only check):\n")
    for name, path in browser_data_locations().items():
        present = "FOUND" if os.path.isdir(path) else "not present"
        print(f"  [{present:>11}] {name}")
        print(f"               {path}")
    print(
        "\nDefensive takeaways:\n"
        "  - Saved passwords and cookies live in predictable folders.\n"
        "  - Protect them with full-disk encryption and OS account separation.\n"
        "  - Detect theft by alerting on unusual reads of these paths and on\n"
        "    outbound traffic to chat APIs (Telegram, Discord) from odd processes.\n"
        "  - Prefer a password manager + hardware MFA so a stolen cookie is not enough."
    )


if __name__ == "__main__":
    main()

New to environment variables like LOCALAPPDATA? What they are

An environment variable is a value the operating system hands every program when it starts. LOCALAPPDATA points at your per-user app-data folder (on Windows, something like C:\Users\you\AppData\Local). Because every Windows machine exposes it, both legitimate apps and malware use it to find user data without guessing your user name.

Why is reading paths safe but reading the files would not be?

Checking whether a folder exists touches only its name in the file system — like reading a label on a drawer. Opening the password database inside would be reading the drawer's contents. This tool deliberately stops at the label.

What you should see. On a typical Windows machine with Chrome, Edge and Firefox installed, each profile shows FOUND and the Linux path shows not present: 
Sensitive browser data locations on this machine (read-only check):

  [      FOUND] Chrome profile
               C:\Users\<you>\AppData\Local\Google\Chrome\User Data\Default
  [      FOUND] Edge profile
               C:\Users\<you>\AppData\Local\Microsoft\Edge\User Data\Default
  [      FOUND] Firefox profiles
               C:\Users\<you>\AppData\Roaming\Mozilla\Firefox\Profiles
  [not present] Linux Chrome
               C:\Users\<you>\.config\google-chrome\Default
The exact paths depend on your user name and which browsers you use.
Common mistakes. Running this expecting it to "show my passwords" — it does not, and that is the point. Also: thinking the folders being present is itself a problem. It is normal; the goal is to protect them, which is what the next section covers.

How to actually defend against stealers

DefenceWhy it helps
Full-disk encryption (BitLocker, FileVault, LUKS)If the disk is stolen offline, the profile files are unreadable.
Multi-factor authentication + a password managerA stolen password or cookie alone is not enough to log in as you.
Separate OS user accountsOne compromised app cannot read another user's profile.
Endpoint monitoring / egress alertsUnusual reads of browser profiles, or traffic to a chat API from an odd process, is a detection signal — exactly the "exfiltrate" step above.
Keep software patchedMany stealers arrive through a separate exploit or a trojanised download; patching and careful downloads cut off the delivery.
Recap
  • An infostealer locates browser files in fixed folders, copies them, and exfiltrates them over ordinary-looking traffic.
  • We used the "locate" knowledge to build a read-only awareness tool — never a stealer.
  • The same os/environment-variable skills power both offence and defence; the difference is intent and permission.
  • Encryption, MFA, account separation and egress monitoring break the chain.
