Creating and writing files programmatically

Writing, appending and reading report and log files the way a tool generates output.

▶ Watch this part (00:18:45)

A report, a log, a list of findings — to a security tool these are all just text files it writes to disk. Once you can create a file, add to it, and read it back, your tool can leave a permanent record instead of printing to the screen and forgetting. This step covers writing files programmatically with Python's built-in open, using the folders you built in the previous step.

This is our own, runnable version of the file-handling the course demonstrates. It writes a small scan.txt into toolkit_output/reports and reads it back.

The idea: writing is just opening with the right mode

Python opens a file with one function, open, and you tell it what you intend to do with a short mode letter (at 15:10 in the course). Three modes matter now: "w" to write (which creates the file, or empties it if it exists), "a" to append (add to the end without erasing), and "r" to read. Getting the mode wrong is the classic beginner bug: open a growing log with "w" and you wipe it every run.

What this script does

  1. Builds the path to a reports folder and makes sure it exists (os.makedirs(..., exist_ok=True)).
  2. Writes two lines into a new scan.txt with mode "w".
  3. Appends two more lines with mode "a", so the first two survive.
  4. Reads the whole file back and prints it to the standard output.
  5. Inspects the file with os.path: does it exist, is it a file, how big is it, and what are its name and folder.
New to the with block and file handles?

When you open a file you get back a handle: an object you call .write() or .read() on. A handle must be closed afterwards, or data can be left unwritten. Writing with open(...) as f: hands you the handle as f and closes it automatically when the indented block ends — even if an error happens inside. It is the safe, standard way to work with files.

Why encoding="utf-8"?

Text on disk is really bytes, and the encoding is the rule for turning characters into bytes. UTF-8 is the modern standard that handles every language and symbol. Stating encoding="utf-8" makes your tool behave the same on every machine, instead of relying on the operating system's default, which differs between Windows and Linux.

The code

"""Creating and writing files programmatically, then checking them.

Reports, logs and found-credential lists are all just text files a tool writes.
This shows how to write a file, append to it, read it back, and inspect it with
os.path (does it exist? how big is it?).
"""
import os

workdir = os.path.join(os.getcwd(), "toolkit_output", "reports")
os.makedirs(workdir, exist_ok=True)

report_path = os.path.join(workdir, "scan.txt")

# open(..., "w") creates the file (or empties it) and gives us a handle to write.
# The 'with' block closes the file for us even if an error happens.
with open(report_path, "w", encoding="utf-8") as f:
    f.write("Target: example.com\n")
    f.write("Scan started\n")

# open(..., "a") appends instead of overwriting: good for a growing log.
with open(report_path, "a", encoding="utf-8") as f:
    f.write("Port 80 open\n")
    f.write("Port 443 open\n")

# Read the whole file back as one string.
with open(report_path, "r", encoding="utf-8") as f:
    print("--- report contents ---")
    print(f.read())

# Inspect the file with os.path.
print("Exists:", os.path.exists(report_path))
print("Is a file:", os.path.isfile(report_path))
print("Size in bytes:", os.path.getsize(report_path))
print("Just the file name:", os.path.basename(report_path))
print("Just the folder:", os.path.dirname(report_path))

What does \n actually do?

\n is the newline character written as two visible characters in source code. When the file is saved, it becomes an invisible line break. That is why each f.write(...) ends with \n: so the next piece of text starts on a fresh line rather than being stuck onto the previous one.

What you should see. The script prints the file it just wrote, then the os.path facts about it: 
--- report contents ---
Target: example.com
Scan started
Port 80 open
Port 443 open

Exists: True
Is a file: True
Size in bytes: 64
Just the file name: scan.txt
Just the folder: ...\toolkit_output\reports
All four lines are present, which proves the append did not overwrite the write. The size is exactly 64 bytes. The folder line ends in toolkit_output\reports on Windows (forward slashes on Linux and macOS).
Common mistakes.
  • Using "w" for a log. Opening a log file with "w" empties it every run. Use "a" to keep adding.
  • Forgetting \n. Without newlines all your writes land on one long line.
  • Not closing the file. Writing without a with block and forgetting f.close() can leave the last bytes unwritten. The with block avoids this.
  • Writing into a missing folder. If reports does not exist, open(..., "w") raises FileNotFoundError. That is why line 10 calls os.makedirs first.
  • Omitting the encoding. Leaving out encoding="utf-8" can produce different bytes on different machines; always state it.
Recap
  • open(path, "w") creates or empties a file; "a" appends to the end; "r" reads it.
  • A with open(...) as f: block closes the file for you, even if an error happens inside.
  • End each written line with \n, and always pass encoding="utf-8".
  • Make sure the target folder exists first with os.makedirs(..., exist_ok=True).
  • os.path.exists, isfile, getsize, basename and dirname let a tool inspect a file after writing it.
