What Is AI? From Machine Learning to LLMs

The big picture: AI, machine learning, deep learning, generative AI and where LLMs fit.

In Part 1 you built a chatbot that answers questions from your own PDFs, sees images, listens and speaks. You called an LLM with one line of code, openai("gpt-5-mini"), and it simply worked. This chapter steps back and answers the question underneath all of that: what is this "AI" thing you have been calling?

You will learn how the words artificial intelligence, machine learning, deep learning, generative AI and large language model relate to each other, how a machine "learns" from examples, what a neural network and a transformer are (without any maths), what these systems are good and bad at, and where each AI component in this project fits.

Why this matters for your chatbot. When the bot gives a wrong answer, you need a mental model to know why. Is it missing information (fix: better retrieval)? Is it guessing (fix: tell it to say "I don't know")? Is it the wrong kind of model for the job (fix: pick another one)? Every later chapter builds on the vocabulary introduced here.

The nested circles: AI, ML, deep learning, generative AI

People often use "AI", "machine learning" and "LLM" as if they meant the same thing. They do not. The easiest way to remember the difference is a set of circles, each one inside the previous one.

Artificial intelligence (AI)The broad goal of making computers do things we would call "intelligent": recognising, deciding, planning, conversing. It includes old-fashioned hand-written rules.A chess program from the 1990s; a thermostat with "if temperature < 19 then heat" rules.

New to "parameters"? What they are and why they matter

A model is, at heart, a very large mathematical function. It takes numbers in and gives numbers out. The parameters (also called weights) are the adjustable numbers inside that function. Think of them as millions or billions of tiny volume knobs.

Training is the process of turning those knobs, a tiny amount at a time, until the function's outputs are good. When people say a model "has 8 billion parameters", they mean it has 8 billion knobs. More knobs generally means the model can capture more patterns, but it also needs more memory and computing power to run.

When a company "releases the weights" of a model, it publishes those knob settings, so anyone can run the model on their own hardware. That idea comes back in chapter 3.

How machine learning learns from data

Traditional programming and machine learning are two different ways to get a computer to do something.

  • Traditional programming: you write the rules. Rules + data → answers. Example: "if the subject contains FREE MONEY, mark it as spam."
  • Machine learning: you supply examples with the right answers, and the computer works out the rules. Data + answers → rules (a model). You then use those learned rules on new data.

A worked example: a spam filter

Imagine you want to sort emails into "spam" and "not spam".

  1. Collect labelled examples. You gather 100,000 old emails. Each already has a label because users clicked "Report spam" or did not. This labelled collection is the training data.
  2. Turn emails into numbers. Computers only do arithmetic, so each email is turned into numbers: how often certain words appear, whether there are links, who sent it, and so on. These numbers are called features.
  3. Train. The model starts with random parameters, so its first guesses are useless. It guesses "spam" or "not spam" for an email, compares the guess with the real label, measures how wrong it was (the loss), and nudges its parameters so that next time it would be slightly less wrong. Repeat that for every email, many times over. This is training.
  4. Test. You keep some labelled emails aside that the model never saw during training. If it classifies those correctly, it has learned general patterns rather than memorising.
  5. Use it. Now a brand-new email arrives. The trained model looks at it and outputs, say, "97% likely spam". Running a trained model on new input is called inference.

Key point: your chatbot never trains anything. When you upload a PDF in step 12, the model does not learn it. The text is stored in a database and handed to the model at question time. That is what RAG means, and it is why the bot can use documents uploaded five seconds ago.

There are a few main styles of machine learning you will hear about:

  • Supervised learning: learn from examples with correct answers (the spam filter).
  • Unsupervised learning: find structure in data without answers, for example grouping similar customers.
  • Self-supervised learning: create the "answers" automatically from the data itself. LLMs are trained this way: hide the next word of a sentence and ask the model to guess it. The real next word is the answer, so no human labelling is needed. That is why LLMs can learn from so much text.
  • Reinforcement learning: learn by trial and error from rewards. A version of this, using human preferences, is used to make chat models helpful (see chapter 2).

Neural networks, intuitively

A neural network is a kind of model loosely inspired by brain cells, but it is really just layers of simple arithmetic.

  • Each neuron takes some numbers in, multiplies each by a weight, adds them up, and passes the result through a simple "squash" function. That is all one neuron does.
  • Neurons are arranged in layers. The first layer receives the input numbers (pixels, or numbers representing words). Each next layer receives the outputs of the previous layer.
  • With many layers ("deep" learning), early layers tend to pick up simple patterns and later layers combine them into more abstract ones. In an image model, early layers might react to edges, middle layers to shapes like eyes or wheels, and late layers to "cat" or "car". Nobody programs these patterns; they emerge during training.
New to vectors? Why everything becomes a list of numbers

Neural networks only work with numbers, so every input (a word, an image, a sound) must first be turned into a list of numbers. A list of numbers is called a vector. For example, a pixel might be [255, 128, 0] (red, green, blue).

Language models turn each piece of text into a vector too. The clever part is that, after training, pieces of text with similar meanings end up with similar vectors. You already used this in step 10: an embedding is exactly such a vector (1,536 numbers for text-embedding-3-small), and similar meanings give vectors that point in similar directions.

The transformer and attention, at a high level

Almost every modern LLM is built on an architecture called the transformer, introduced by Google researchers in the 2017 paper "Attention Is All You Need". You do not need the maths to use LLMs well, but the core idea is worth knowing.

Language is full of words whose meaning depends on other words, sometimes far away. Read these two sentences:

  • "The bank raised its interest rates."
  • "We had a picnic on the river bank."

To understand "bank", you must look at "interest rates" or "river". The transformer's key trick, attention, does exactly that: for every word, the model computes how much it should "pay attention" to every other word in the text, and blends in information from the most relevant ones. It does this in many layers, and in many parallel "heads" that each focus on different kinds of relationships (grammar, who-did-what, topic, and so on).

Two practical consequences follow from this design:

  • It trains efficiently. Older language models read text one word at a time, in order. Transformers can process all positions of a training text in parallel, which made it practical to train on enormous amounts of text with modern chips.
  • Long inputs cost more. Because every piece of text can attend to every other piece, longer inputs need more computation and memory. That is one reason models have a maximum context window and why providers charge per token. Chapter 2 explains both.

Common misconception: "the model looks things up in a database of everything it read." It does not. After training, the original texts are gone. What remains are the parameters, which encode patterns and a lot of compressed knowledge, imperfectly. That is why a model can be confidently wrong, and why we give it real documents through RAG.

What generative AI and LLMs are

A generative model produces new content. An LLM is a generative model for text, and its job sounds almost too simple: given some text, predict what comes next, one small piece (a token) at a time. It repeats this, adding each new piece to the text, until it decides to stop.

Because it was trained on a vast amount of human writing (books, websites, code, conversations), "predicting what comes next" well requires picking up grammar, facts, styles, reasoning patterns and even programming languages. A raw model trained like this is then further trained to follow instructions and hold conversations politely; that is what turns it into a chat assistant. Chapter 2 covers these training stages.

When you write in step 5:

const result = streamText({
  model: openai("gpt-4.1-mini"),
  messages: convertToModelMessages(messages),
});

you are asking OpenAI's servers to run inference: take the conversation so far and keep predicting the next token, sending each one back to you as it is produced (that is streaming).

Multimodal models

Early LLMs only read and wrote text. Many current models are multimodal: they accept, and sometimes produce, more than one kind of data, such as images, audio or PDFs. Internally, an image is cut into small patches that are turned into vectors, much like words are, so the same transformer can "attend" across text and pictures together.

You used multimodal models in Part 1 without much ceremony:

  • Step 18: users attach an image to a question, and the chat model looks at it.
  • Step 21: a vision-capable model reads text out of images and scanned PDFs (a form of OCR) so they can be indexed.
  • Step 19 and step 20: separate audio models turn speech into text and text into speech (STT/TTS).

What AI is good at, and what it is bad at

These are general tendencies of today's LLMs, not hard rules. Models improve quickly, so test your own use case.

Usually good atUsually weak at
Summarising, rewriting, translating and changing the tone of text.Exact facts it has not been given, especially niche or recent ones. It may invent them (a hallucination).
Answering questions when the relevant text is in the prompt (this is why RAG works).Precise arithmetic and counting over long inputs. Hand that to a real calculator tool, as the agent in step 22 does.
Extracting structured data from messy text (names, dates, amounts).Knowing what happened after its training data was collected (its knowledge cutoff).
Writing and explaining code; drafting first versions.Being consistent: the same question can produce different answers.
Classifying and routing (for example "is this a billing or a technical question?").Knowing when it does not know. It rarely says so unless instructed to.
Understanding images, charts and screenshots (multimodal models).Resisting instructions hidden in untrusted content (prompt injection; see chapter 13).

Pitfalls for beginners

  • Treating fluent text as correct text. LLMs are trained to sound plausible. Plausible and true are different things. Always ground answers in real data (RAG, tools) when correctness matters.
  • Thinking the model "remembers" your users. Each request is independent. The model only "remembers" a conversation because your app sends the whole history every time (chapter 2).
  • Using AI where a plain if statement would do. Rules are cheaper, faster and fully predictable. Use a model where the input is messy human language or images.

Recap
  • AI ⊃ machine learning ⊃ deep learning ⊃ generative AI ⊃ LLMs.
  • Machine learning learns rules from examples. Training adjusts parameters; inference uses the frozen model. Your app only ever does inference.
  • Neural networks are layers of simple arithmetic whose weights are tuned during training.
  • Transformers use attention so every token can draw on every other token; this powers modern LLMs (2017 paper).
  • An LLM generates text by repeatedly predicting the next token. Multimodal models also handle images and other inputs.
  • LLMs are great with language, weak on unseen facts and exact computation; ground them with RAG and tools.
  • This project combines several specialised models: chat, embeddings, vision, STT and TTS.
