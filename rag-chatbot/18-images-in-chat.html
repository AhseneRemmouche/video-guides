Images in the Chat

Attach images to a question and let the model see them.

Extension · code type-checked against the repo

About steps 18–21. These are not in the video. They extend the finished project from step 16. All of their code was type-checked (tsc --noEmit) and production-built (next build) against the GitHub repo's exact package versions (Next.js 15.5.3, ai 5.0.47, @ai-sdk/openai 2.0.32 and the repo's AI Elements). They haven't been run against live OpenAI, Clerk or Neon accounts, so test them with your own keys.

Goal

Let users attach images to a question, for example "What does this error screenshot mean?" or "Which policy applies to this receipt?". The model sees the image and can still search the knowledge base.

New to multimodal models? What it means for a model to "see" an image

An LLM started out as a text-only machine: text in, text out. A multimodal model (also called a vision model) accepts more than one kind of input in the same message, such as text and images.

Behind the scenes, the image is cut into small square tiles and each tile is turned into numbers the model can process, a bit like how words are turned into tokens. That is why images cost input tokens too: a big, detailed picture costs more than a small one.

For you as a developer, the important part is simple: you put the image in the message next to the text, and the model answers using both. You don't train anything and you don't call a separate "image API".

Read the diagram from left to right: the user picks an image, a small helper converts it into a format the server can read, the chat sends it together with the text, the route handler passes it on, and the vision model looks at it.

Three things to know first

  1. The prompt box already supports attachments

    The repo's src/components/ai-elements/prompt-input.tsx already exports PromptInputAttachments, PromptInputAttachment, PromptInputActionMenu and PromptInputActionAddAttachments, and PromptInput accepts accept, multiple, maxFiles, maxFileSize and onError. You don't need to install anything.

    Remember that AI Elements components are copied into your project as source files (that's how shadcn-style components work). So "the component supports it" means the code is already sitting in that file and you can open it to read exactly what each prop does.

  2. The model can already see images

    The AI SDK's convertToModelMessages turns a message's file parts into image inputs for the model. Both gpt-4.1-mini (the video) and gpt-5-mini (the repo) accept images. The route handler barely changes.

  3. There is one catch: blob: URLs

    In this version of AI Elements, each attachment gets a blob: URL from URL.createObjectURL. That URL only exists inside your browser tab, so the server can't read it. Before sending, you convert each attachment to a data: URL, which carries the file's bytes as base64. Newer AI Elements releases do this for you. This version doesn't.

New to blob: and data: URLs? Why one works on the server and the other doesn't

Both are ways to point at a file using a URL, but they work very differently (see also blob and data URLs in the glossary).

  • blob: URL – a short nickname like blob:http://localhost:3000/4f1c…. The actual file bytes stay in your browser's memory, and the nickname only means something inside the tab that created it. If you send that string to the server, the server has nothing to look up. It's like giving someone your locker number at a gym they've never been to.
  • data: URL – the file itself, written inside the URL as text. It looks like data:image/png;base64,iVBORw0KGgo…. Anyone who receives the string has the whole file. It's like handing over the contents of the locker.

The trade-off: a data: URL is long (it contains the whole file), but it can travel anywhere. A blob: URL is short but useless outside the tab.

// illustrative only
"blob:http://localhost:3000/4f1c2a9e-..."   // pointer, browser tab only
"data:image/png;base64,iVBORw0KGgoAAAANS..." // the bytes themselves
New to base64? How binary files become text

An image is binary data: a long list of bytes, each a number from 0 to 255. Many of those bytes aren't printable characters, so you can't safely put them inside JSON or a URL.

Base64 rewrites any bytes using only 64 safe characters: A–Z, a–z, 0–9, + and / (plus = for padding at the end). Every 3 bytes become 4 characters. That's why a base64 file is about 33% bigger (4 ÷ 3 ≈ 1.33) than the original, which is the reason the page mentions it next to the 4 MB limit.

Tiny example: the text Hi! is the bytes 72, 105, 33, and in base64 it becomes SGkh.

Step by step

  1. Create the blob → data URL helper

    For each attachment: fetch the blob: URL (this works for local blobs), read it with a FileReader as a data URL, free the blob with URL.revokeObjectURL, and return the part with its new URL. Parts that already have a non-blob URL pass through unchanged.

    Create a new file at src/lib/to-data-url.ts (the lib folder already holds your other helpers such as embeddings.ts):

    import type { FileUIPart } from "ai";

// PromptInput gives attachments temporary blob: URLs that only exist in this
// browser tab. The server can't read those, so turn each one into a data: URL
// (the file's bytes, base64-encoded) before sending the message.
export async function toDataUrlParts(
  files: FileUIPart[],
): Promise<FileUIPart[]> {
  return Promise.all(
    files.map(async (file) => {
      if (!file.url.startsWith("blob:")) return file;

      const blob = await fetch(file.url).then((res) => res.blob());
      const dataUrl = await new Promise<string>((resolve, reject) => {
        const reader = new FileReader();
        reader.onloadend = () => resolve(reader.result as string);
        reader.onerror = () => reject(reader.error);
        reader.readAsDataURL(blob);
      });

      URL.revokeObjectURL(file.url);
      return { ...file, url: dataUrl };
    }),
  );
}

    New to FileReader? Reading a file inside the browser

    Web pages aren't allowed to read files on your disk freely. When a user chooses a file (with a file picker or drag-and-drop), the page gets a File or Blob object, and FileReader is the browser tool for reading its contents.

    • readAsDataURL(blob) – gives a data: URL string (used here).
    • readAsText(blob) – gives plain text, for .txt or .csv files.
    • readAsArrayBuffer(blob) – gives raw bytes.

    It is event-based: you call a readAs… method, and later the browser calls your onload/onloadend/onerror function. That's why the helper wraps it in a Promise.

    New to Promise.all? Waiting for several async jobs at once

    A Promise is a placeholder for a value that will arrive later. Promise.all([p1, p2, p3]) takes a list of Promises and gives back one Promise that:

    • resolves with an array of all the results, in the same order as the input, once every Promise has finished;
    • rejects as soon as any one of them fails.
    // illustrative only
const [a, b] = await Promise.all([slowDouble(1), slowDouble(2)]);
// a = 2, b = 4 — both ran at the same time

    The alternative, a for loop with await inside, would convert the images one after another. With four images, Promise.all is faster, and the order of the attachments is preserved either way.

    PropValueWhy
    acceptimage/png,image/jpeg,image/webp,image/gifThese are the image formats OpenAI accepts. A broad image/* would let through formats like HEIC that the API rejects.
    multipletrueAllows several images per question.

    maxFileSize4 * 1024 * 10244 MB per file. Base64 makes the payload about 33% larger.
    onErrorsets inputErrorShows "Too many files", "exceeds maximum size" and similar messages.

    Why 4 * 1024 * 1024? Sizes are measured in bytes. 1 kilobyte (KB) is 1,024 bytes and 1 megabyte (MB) is 1,024 KB, so 4 MB = 4 × 1,024 × 1,024 = 4,194,304 bytes. Writing the multiplication is clearer than the raw number. The values in accept are MIME types: standard labels like image/png that say what kind of file something is (category / format).

    Typing quirk: PromptInput's props combine the normal form onError (a DOM event) with its own file-error callback, so TypeScript sees the argument as either type. The if ("code" in err) check narrows it to the file-error object.

  3. Show attachment thumbnails and an "Add images" menu

    Inside PromptInputBody, put <PromptInputAttachments> above the textarea. It renders one PromptInputAttachment per file, each with a remove (×) button that appears on hover. In PromptInputTools, the placeholder the video left empty, add a PromptInputActionMenu. Its trigger is a + button, and its menu item opens the file picker. You can also drag and drop images onto the prompt box.

  4. Update handleSubmit
    • Allow sending when there is text or files. An image on its own is a valid question.
    • Convert the files with toDataUrlParts. The function is now async.
    • Call sendMessage({ text, files }), or sendMessage({ files }) if there is no text. This avoids sending an empty text part.
    • Clear the attachments. This version of PromptInput doesn't clear them after submit and doesn't expose a clear function outside its context. Incrementing a key (formKey) remounts the component with an empty attachment list.
    New to the key trick? Why changing a key clears a component's state

    You know key from lists: React uses it to tell items apart. But a key works on any component, and it has a powerful side effect.

    React keeps a component's internal state (here, PromptInput's list of attachments) as long as the component stays "the same one" between renders. When its key changes, React decides it is a different component: it throws the old one away, with all its state, and mounts (creates) a fresh one, which starts empty.

    // illustrative only
<PromptInput key={0} />   // first render: attachments [img1]
<PromptInput key={1} />   // key changed: brand-new PromptInput, attachments []

    That's why setFormKey((key) => key + 1) after sending empties the attachment tray, even though you can't reach inside PromptInput to clear it. The textarea's text isn't lost by surprise: it lives in your input state, which you clear yourself with setInput("").

  5. Render image parts in the conversation

    Add a case "file" to the parts switch. If part.mediaType starts with image/, render an <img> inside the same Message/MessageContent wrapper so it lines up with the user's bubble. A plain <img> is used because Next's <Image> can't optimise in-memory data: URLs. The biome-ignore comment tells the repo's linter this is deliberate.

    A linter is a tool that reads your code and warns about likely problems or style issues. The repo uses Biome, which normally warns "use Next's <Image> instead of <img>". The comment switches off that one rule for that one line and records the reason.

  6. Tell the model what to do with images

    In src/app/api/chat/route.ts, append one sentence to the end of the system prompt. Nothing else in the route changes:

    Base your answers on the search results when available. Give concise answers that correctly answer what the user is asking for. Do not flood them with all the information from the search results.
If the user attaches images, look at them carefully and use what you see together with the knowledge base.`,

    The first line is the end of the existing system prompt; only the second line is new. The prompt is a template literal (a string between backticks), so it can span several lines, and the closing `, stays at the very end. Be careful not to delete that backtick, or the whole file stops compiling.

// src/app/chat/page.tsx
"use client";

import { Fragment, useState } from "react";
import { useChat } from "@ai-sdk/react";
import {
  Conversation,
  ConversationContent,
  ConversationScrollButton,
} from "@/components/ai-elements/conversation";
import { Message, MessageContent } from "@/components/ai-elements/message";
import {
  PromptInput,
  PromptInputActionAddAttachments,
  PromptInputActionMenu,
  PromptInputActionMenuContent,
  PromptInputActionMenuTrigger,
  PromptInputAttachment,
  PromptInputAttachments,
  PromptInputBody,
  type PromptInputMessage,
  PromptInputSubmit,
  PromptInputTextarea,
  PromptInputToolbar,
  PromptInputTools,
} from "@/components/ai-elements/prompt-input";
import { Response } from "@/components/ai-elements/response";
import { Loader } from "@/components/ai-elements/loader";
import { toDataUrlParts } from "@/lib/to-data-url";

export default function RAGChatBot() {
  const [input, setInput] = useState("");
  const [formKey, setFormKey] = useState(0);
  const [inputError, setInputError] = useState<string | null>(null);
  const { messages, sendMessage, status } = useChat();

  const handleSubmit = async (message: PromptInputMessage) => {
    const text = message.text?.trim() ?? "";
    const hasFiles = Boolean(message.files?.length);
    if (!text && !hasFiles) {
      return;
    }

    const files = hasFiles
      ? await toDataUrlParts(message.files ?? [])
      : undefined;

    if (text) {
      sendMessage({ text, files });
    } else if (files) {
      sendMessage({ files });
    }

    setInput("");
    setInputError(null);
    setFormKey((key) => key + 1); // remount PromptInput to clear its attachments
  };

  return (
    <div className="max-w-4xl mx-auto p-6 relative size-full h-[calc(100vh-4rem)]">
      <div className="flex flex-col h-full">
        <Conversation className="h-full">
          <ConversationContent>
            {messages.map((message) => (
              <div key={message.id}>
                {message.parts.map((part, i) => {
                  switch (part.type) {
                    case "text":
                      return (
                        <Fragment key={`${message.id}-${i}`}>
                          <Message from={message.role}>
                            <MessageContent>
                              <Response>{part.text}</Response>
                            </MessageContent>
                          </Message>
                        </Fragment>
                      );
                    case "file":
                      if (!part.mediaType.startsWith("image/")) {
                        return null;
                      }
                      return (
                        <Fragment key={`${message.id}-${i}`}>
                          <Message from={message.role}>
                            <MessageContent>
                              {/* biome-ignore lint/performance/noImgElement: data: URLs can't go through next/image optimisation */}
                              <img
                                src={part.url}
                                alt={part.filename ?? "Attached image"}
                                className="max-h-64 rounded-md"
                              />
                            </MessageContent>
                          </Message>
                        </Fragment>
                      );
                    default:
                      return null;
                  }
                })}
              </div>
            ))}
            {(status === "submitted" || status === "streaming") && <Loader />}
          </ConversationContent>
          <ConversationScrollButton />
        </Conversation>

        {inputError && (
          <p className="mt-2 text-sm text-destructive">{inputError}</p>
        )}

        <PromptInput
          key={formKey}
          onSubmit={handleSubmit}
          className="mt-4"
          accept="image/png,image/jpeg,image/webp,image/gif"
          multiple
          maxFiles={4}
          maxFileSize={4 * 1024 * 1024}
          onError={(err) => {
            // PromptInput reuses the form's onError prop for file errors
            if ("code" in err) setInputError(err.message);
          }}
        >
          <PromptInputBody>
            <PromptInputAttachments>
              {(attachment) => <PromptInputAttachment data={attachment} />}
            </PromptInputAttachments>
            <PromptInputTextarea
              value={input}
              onChange={(e) => setInput(e.target.value)}
            />
          </PromptInputBody>
          <PromptInputToolbar>
            <PromptInputTools>
              <PromptInputActionMenu>
                <PromptInputActionMenuTrigger />
                <PromptInputActionMenuContent>
                  <PromptInputActionAddAttachments label="Add images" />
                </PromptInputActionMenuContent>
              </PromptInputActionMenu>
            </PromptInputTools>
            <PromptInputSubmit disabled={!input && !status} status={status} />
          </PromptInputToolbar>
        </PromptInput>
      </div>
    </div>
  );
}

Save both files. The dev server (npm run dev) reloads automatically. Open http://localhost:3000/chat and sign in.

  1. Attach an image: click + → Add images, or drag one onto the prompt box. A 56 px thumbnail appears above the textarea.
  2. Ask about it, for example "What's in this picture?". Your message shows the image and the answer describes it.
  3. Combine it with the knowledge base: upload a photo of a receipt and ask "Can I expense this?". The model reads the receipt and calls searchKnowledgeBase to find the expense policy.
  4. Check the limits: try a fifth image or a file over 4 MB. A red message appears above the prompt box.

How to know it worked: after sending, the thumbnail tray is empty again, your message shows the picture inside your bubble, and the answer clearly refers to what is in the image. In the browser's DevTools Network tab, the request to /api/chat contains a long "url": "data:image/…;base64,…" string, not a blob: URL.

Common mistakes:

  • "Module not found: Can't resolve '@/lib/to-data-url'" – the helper file is missing or saved under a different name or folder. It must be exactly src/lib/to-data-url.ts.
  • The model says it can't see any image – the conversion was skipped and a blob: URL was sent. Check that handleSubmit calls toDataUrlParts and passes its result, not message.files, to sendMessage.
  • The thumbnails stay after sending – key={formKey} is missing on PromptInput, or setFormKey isn't called.
  • A HEIC photo from an iPhone is refused – that's intended: it isn't in accept. Export it as JPEG first.
  • The page fails to compile after editing the route – the closing backtick of the system prompt was deleted or duplicated.

Images are kept in the conversation. useChat re-sends the whole conversation, data URLs included, with every message. Several large images make every later request heavier and cost more input tokens. For a production app, upload images to storage (for example Vercel Blob or S3) and send the hosted URL instead of a data URL.

Recap
  • AI Elements already provides attachment UI. You switched it on with accept, multiple and the limit props.
  • blob: URLs only exist in the browser, so you convert them to data: URLs before sendMessage.
  • convertToModelMessages passes image parts to the vision-capable model. You only added one line to the system prompt.
