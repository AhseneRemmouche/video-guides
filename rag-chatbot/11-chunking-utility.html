Chunking Utility

Split long text into overlapping chunks with LangChain.

▶ Watch this part (36:56)

Goal

Break the text of a PDF into small pieces (chunks), so that later you retrieve only the sections relevant to a question, not the whole document. You use LangChain's text splitters, which are built for this.

New to chunking? Why not just embed the whole document?

You could, in theory, turn an entire 30-page handbook into one embedding. It would work badly, for three reasons:

  1. One vector can only hold one "average" meaning. A handbook talks about vacation, expenses, laptops and dress code. Squeezed into one vector, it's vaguely about "company stuff", and a question about vacation days matches it only weakly. A chunk that is only about vacation matches strongly.
  2. You want to hand the model just the relevant part. In step 15 the chatbot hands the best-matching chunks to the model as part of its prompt. Three short, relevant paragraphs give a better, cheaper answer than 30 pages (which may not even fit the context window).
  3. Embedding models have an input limit. text-embedding-3-small accepts at most about 8,000 tokens per text; long documents simply don't fit.

So the plan is: split → embed each piece → store each piece as its own row. At question time you find the few pieces closest to the question.

Step by step

  1. Install the package 
    npm install @langchain/textsplitters

    npm install downloads the package and adds it to package.json. @langchain/textsplitters is a small, standalone part of the LangChain project: you get only the text splitters, not the whole LangChain framework. Run it from your project folder.

  2. Create src/lib/chunking.ts and import RecursiveCharacterTextSplitter.
  3. Configure the splitter
    OptionValueMeaning
    chunkSize900Each chunk is at most about 900 characters, roughly a solid paragraph. That is big enough to hold a whole policy rule with its context. (The video uses 150.)
    chunkOverlap150Consecutive chunks share about 150 characters (a sentence or two) at their boundaries, so a sentence cut at the edge of one chunk is complete in the next. (The video uses 20.)
    separators[" "]Split only on spaces, so words are never cut in half.
  4. Write chunkContent

    It takes the PDF's content as a string, trims leading and trailing whitespace, and returns await textSplitter.splitText(...), an array of strings where each string is a chunk.

Complete file

// src/lib/chunking.ts
import { RecursiveCharacterTextSplitter } from "@langchain/textsplitters";

export const textSplitter = new RecursiveCharacterTextSplitter({
  chunkSize: 900,
  chunkOverlap: 150,
  separators: [" "],
});

export async function chunkContent(content: string) {
  return await textSplitter.splitText(content.trim());
}

What overlap looks like

Each chunk repeats the last ~150 characters of the one before it. In the video (with its 20-character overlap) the presenter shows this in Neon: one chunk starts with "balance while delivering…", and the previous chunk ends with "balance while". With 900 / 150 the shared part is a sentence or two instead of a couple of words, so a sentence cut at a boundary is still fully readable in at least one chunk.

New to overlap? A tiny worked example

Shrink the numbers so you can follow by hand: chunkSize: 20, chunkOverlap: 8, split on spaces, and this text (43 characters):

The quick brown fox jumps over the lazy dog
  1. The splitter adds words while the chunk stays at most 20 characters: The quick brown fox (19). Adding jumps would make 25, so chunk 1 is done.
  2. For the next chunk it keeps the last words of chunk 1 that fit in 8 characters: fox. Then it adds words again: fox jumps over the (18).
  3. It keeps over the (8 characters) and continues: over the lazy dog (17).

(This is a simplified walk-through; the real splitter follows the same idea.) Without overlap you'd get The quick brown fox / jumps over the lazy / dog: the last chunk is a lonely word with no meaning of its own. Overlap makes every chunk carry a bit of its neighbour's context, so an idea that straddles a boundary still appears whole somewhere. The price: some text is stored (and embedded) twice, which costs a little more space and money.

Choosing the chunk size

  • Smaller chunks give more precise matches, but each one has less context. You may need more results to answer a question.
  • Larger chunks carry more context per hit, but the embedding becomes a blur of several topics and retrieval gets less precise.
  • The video uses 150 because its sample handbook is short. 900 with 150 overlap (about 17%) is a solid default for real documents. If answers miss details, try smaller chunks. If they lack context, try larger ones.
  • With separators: [" "] the splitter only breaks at spaces, so a chunk can start mid-sentence. Removing the separators line uses LangChain's defaults, which split on paragraphs first, then lines, then spaces. That often gives cleaner 900-character chunks.

Already uploaded documents keep their old chunks. Changing these numbers only affects files uploaded after the change. To re-index everything with the new sizes, empty the table in the Neon SQL Editor and upload your PDFs again:

DELETE FROM documents;

Mixing old 150-character chunks with new 900-character ones works, but search results will be inconsistent.

Effect on search (step 14): the chat tool fetches the top 3 chunks, so the model now gets up to ~2,700 characters of context instead of ~450. That makes answers better grounded. A bigger chunk covers several ideas, so its similarity score to a short question can be a bit lower. If the bot starts saying it found nothing, lower the threshold from 0.5 to about 0.3.

How to know it worked: as with the embeddings helper, nothing runs yet. Check that the file is at src/lib/chunking.ts (the server action imports it as @/lib/chunking) and that the import line has no red underline. If it does, the package didn't install: run the npm install command again in the project folder.

Common mistakes:

  • Setting chunkOverlap equal to or bigger than chunkSize: the splitter refuses to start.
  • Writing separators: " " (a string) instead of [" "] (an array with one string).
  • Forgetting await when calling chunkContent: you'd get a Promise instead of an array, and the next step would fail.
Recap
  • chunkContent(text) returns an array of chunks of up to ~900 characters that overlap by ~150 characters and never split words.
  • With both utilities ready (embeddings and chunking), you can build the server action.
