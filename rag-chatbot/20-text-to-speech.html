Text to Speech

A Listen button that reads answers aloud.

Extension · code type-checked against the repo

Goal

Add a Listen button (🔊) under each assistant answer. Clicking it turns the answer into speech and plays it. Clicking again stops it. Together with step 19, you can now hold a full spoken conversation with your documents.

This is text to speech (TTS): a model receives text and produces an audio file of a voice reading it.

The browser sends the answer's text to your server, the server asks OpenAI for an MP3 of it, and the browser plays that MP3. The audio travels back as base64 text inside JSON (see the base64 primer on step 18), and the browser wraps it in a data URL to play it.

Step by step

  1. Create the speech route
    • Check the body with zod, which is already installed for the tool schema. The text must be 1–4096 characters, OpenAI's limit per speech request.
    • Call the AI SDK's generateSpeech, exported as experimental_generateSpeech in this version, with openai.speech("gpt-4o-mini-tts") and a voice.
    • The result's audio contains the sound file in several forms (base64, uint8Array, mediaType). Return { audio: audio.base64, mediaType } as JSON. The browser turns that into a playable data: URL.
    New to request validation? Why the server checks the body with zod's safeParse

    A route handler is a public door: anyone signed in can send it any body, not just what your own page sends. Maybe the text is missing, maybe it's a number, maybe it's 50,000 characters long. Validation means checking the data has the expected shape before using it, so bad input gets a clear 400 error instead of a crash or a wasted paid API call.

    Zod lets you describe the expected shape once, as a schema, and then check data against it:

    • schema.parse(data) returns the clean data, or throws an error if it doesn't match.
    • schema.safeParse(data) never throws. It returns an object: { success: true, data } or { success: false, error }. You check success with a normal if.
    // illustrative only
const schema = z.object({ text: z.string().min(1) });
schema.safeParse({ text: "Hi" });  // { success: true, data: { text: "Hi" } }
schema.safeParse({ text: 42 });    // { success: false, error: ZodError … }

    safeParse is handy in routes because the "invalid" case is expected and should become a 400 response, not jump to the generic 500 catch.

    Create src/app/api/speech/route.ts:

    // src/app/api/speech/route.ts
import { experimental_generateSpeech as generateSpeech } from "ai";
import { openai } from "@ai-sdk/openai";
import { z } from "zod";

// OpenAI's speech models accept up to 4096 characters per request
const bodySchema = z.object({ text: z.string().trim().min(1).max(4096) });

export async function POST(req: Request) {
  try {
    const parsed = bodySchema.safeParse(await req.json());
    if (!parsed.success) {
      return Response.json(
        { error: "Text must be 1-4096 characters" },
        { status: 400 },
      );
    }

    const { audio } = await generateSpeech({
      model: openai.speech("gpt-4o-mini-tts"),
      text: parsed.data.text,
      voice: "alloy",
    });

    return Response.json({ audio: audio.base64, mediaType: audio.mediaType });
  } catch (error) {
    console.error("Speech generation error:", error);
    return Response.json(
      { error: "Failed to generate speech" },
      { status: 500 },
    );
  }
}

  2. Create the player hook

    useSpeechPlayer() manages one Audio element at a time:

    • play(id, text) stops anything already playing, marks that message as loading, POSTs the text, builds new Audio(`data:${mediaType};base64,${audio}`) and plays it. When playback ends, the state resets.
    • stop() pauses and forgets the current audio.
    • It tracks loadingId and playingId per message, so only the button you clicked changes.
    • toPlainText strips common Markdown first (**bold**, headings, links, code blocks), so the voice doesn't read out symbols, then trims the text to 4096 characters.
    New to the Audio element? Playing sound from JavaScript

    HTML has an <audio> tag for sound files. JavaScript can create the same thing without putting anything on the page: new Audio(url) gives you an HTMLAudioElement, an invisible player.

    • audio.play() starts playback and returns a Promise. The Promise rejects if the browser refuses to play (see autoplay below) or can't decode the file.
    • audio.pause() pauses. There is no stop(); pausing and throwing the object away has the same effect.
    • audio.onended is called when the sound reaches the end.

    The URL can be a normal web address, a blob: URL or, as here, a data: URL that contains the whole MP3.

    New to autoplay rules? Why browsers block sound that starts by itself

    Nobody likes a web page that suddenly starts shouting. So browsers have autoplay policies: a page may only start audio with sound after the user has interacted with it (a click, a tap or a key press). Playback that isn't connected to a user gesture is blocked, and audio.play() rejects with a NotAllowedError.

    In this step, playback always begins because the user clicked Listen. Browsers remember that the user has interacted with the page, so the play() call is still allowed even though it happens after a server round trip. This is also a good reason not to read every answer automatically: an auto-started voice could be blocked, and it would cost money for answers nobody wanted to hear.

    New to regular expressions? A two-minute introduction

    A regular expression (regex) is a tiny pattern language for finding text. In JavaScript it's written between slashes: /abc/ finds "abc". A few building blocks are enough to read toPlainText:

    • [abc] – any one of the characters a, b or c. [^abc] – any one character except those.
    • \s – a whitespace character (space, tab, newline); \S – any non-whitespace character. So [\s\S] means "absolutely any character, newlines included".
    • + – one or more of the previous thing; * – zero or more; *? – zero or more, but as few as possible ("lazy").
    • ( ) – a capturing group: remembers what it matched, so the replacement can reuse it as $1.
    • \[, \], \(, \) – a backslash makes a special character literal, so \[ means a real [.
    • The g flag after the closing slash means "global": replace every match, not just the first.

    Create src/hooks/use-speech-player.ts (the hooks folder exists since step 19):

    // src/hooks/use-speech-player.ts
"use client";

import { useRef, useState } from "react";

// Strip the most common Markdown so the voice doesn't read "asterisk asterisk"
function toPlainText(markdown: string) {
  return markdown
    .replace(/```[\s\S]*?```/g, " (code omitted) ")
    .replace(/[*_`#>]/g, "")
    .replace(/\[([^\]]+)\]\([^)]+\)/g, "$1")
    .trim();
}

export function useSpeechPlayer() {
  const audioRef = useRef<HTMLAudioElement | null>(null);
  const [playingId, setPlayingId] = useState<string | null>(null);
  const [loadingId, setLoadingId] = useState<string | null>(null);

  const stop = () => {
    audioRef.current?.pause();
    audioRef.current = null;
    setPlayingId(null);
  };

  const play = async (id: string, text: string) => {
    stop();
    setLoadingId(id);
    try {
      const res = await fetch("/api/speech", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ text: toPlainText(text).slice(0, 4096) }),
      });
      const data = (await res.json()) as {
        audio?: string;
        mediaType?: string;
        error?: string;
      };
      if (!res.ok || !data.audio) {
        throw new Error(data.error ?? "Speech generation failed");
      }

      const audio = new Audio(`data:${data.mediaType};base64,${data.audio}`);
      audio.onended = () => setPlayingId(null);
      audioRef.current = audio;
      await audio.play();
      setPlayingId(id);
    } catch (err) {
      console.error(err);
    } finally {
      setLoadingId(null);
    }
  };

  return { playingId, loadingId, play, stop };
}

  3. Add the Listen button to the chat page
    1. Import Volume2Icon, plus Actions and Action from @/components/ai-elements/actions. That component ships with the repo and renders small icon buttons with tooltips.
    2. The messages.map callback now has a block body. For each message it works out:
      • text: all of the message's text parts joined together.
      • isStreamingThis: whether this is the last message and it is still streaming. There is no point reading half an answer.
      • canListen: an assistant message with text that has finished streaming.
    3. Below the parts, render <Actions><Action>. It shows a spinner while loading, a stop square while playing and a speaker icon otherwise. Clicking toggles play and stop.

    A "block body" means the arrow function uses curly braces => { … return (…); } instead of returning JSX directly with => ( … ). You need braces when you want to compute some variables before returning.

// src/app/chat/page.tsx
"use client";

import { Fragment, useState } from "react";
import { useChat } from "@ai-sdk/react";
import { Loader2Icon, MicIcon, SquareIcon, Volume2Icon } from "lucide-react";
import {
  Conversation,
  ConversationContent,
  ConversationScrollButton,
} from "@/components/ai-elements/conversation";
import { Message, MessageContent } from "@/components/ai-elements/message";
import {
  PromptInput,
  PromptInputActionAddAttachments,
  PromptInputActionMenu,
  PromptInputActionMenuContent,
  PromptInputActionMenuTrigger,
  PromptInputAttachment,
  PromptInputAttachments,
  PromptInputBody,
  PromptInputButton,
  type PromptInputMessage,
  PromptInputSubmit,
  PromptInputTextarea,
  PromptInputToolbar,
  PromptInputTools,
} from "@/components/ai-elements/prompt-input";
import { Response } from "@/components/ai-elements/response";
import { Loader } from "@/components/ai-elements/loader";
import { Action, Actions } from "@/components/ai-elements/actions";
import { toDataUrlParts } from "@/lib/to-data-url";
import { useVoiceRecorder } from "@/hooks/use-voice-recorder";
import { useSpeechPlayer } from "@/hooks/use-speech-player";

export default function RAGChatBot() {
  const [input, setInput] = useState("");
  const [formKey, setFormKey] = useState(0);
  const [inputError, setInputError] = useState<string | null>(null);
  const { messages, sendMessage, status } = useChat();
  const player = useSpeechPlayer();
  const recorder = useVoiceRecorder((text) =>
    setInput((prev) => (prev ? `${prev} ${text}` : text)),
  );

  const handleSubmit = async (message: PromptInputMessage) => {
    const text = message.text?.trim() ?? "";
    const hasFiles = Boolean(message.files?.length);
    if (!text && !hasFiles) {
      return;
    }

    const files = hasFiles
      ? await toDataUrlParts(message.files ?? [])
      : undefined;

    if (text) {
      sendMessage({ text, files });
    } else if (files) {
      sendMessage({ files });
    }

    setInput("");
    setInputError(null);
    setFormKey((key) => key + 1); // remount PromptInput to clear its attachments
  };

  return (
    <div className="max-w-4xl mx-auto p-6 relative size-full h-[calc(100vh-4rem)]">
      <div className="flex flex-col h-full">
        <Conversation className="h-full">
          <ConversationContent>
            {messages.map((message, index) => {
              const text = message.parts
                .map((part) => (part.type === "text" ? part.text : ""))
                .join(" ")
                .trim();
              const isStreamingThis =
                status === "streaming" && index === messages.length - 1;
              const canListen =
                message.role === "assistant" && text !== "" && !isStreamingThis;

              return (
                <div key={message.id}>
                  {message.parts.map((part, i) => {
                    switch (part.type) {
                      case "text":
                        return (
                          <Fragment key={`${message.id}-${i}`}>
                            <Message from={message.role}>
                              <MessageContent>
                                <Response>{part.text}</Response>
                              </MessageContent>
                            </Message>
                          </Fragment>
                        );
                      case "file":
                        if (!part.mediaType.startsWith("image/")) {
                          return null;
                        }
                        return (
                          <Fragment key={`${message.id}-${i}`}>
                            <Message from={message.role}>
                              <MessageContent>
                                {/* biome-ignore lint/performance/noImgElement: data: URLs can't go through next/image optimisation */}
                                <img
                                  src={part.url}
                                  alt={part.filename ?? "Attached image"}
                                  className="max-h-64 rounded-md"
                                />
                              </MessageContent>
                            </Message>
                          </Fragment>
                        );
                      default:
                        return null;
                    }
                  })}
                  {canListen && (
                    <Actions className="mt-1">
                      <Action
                        tooltip={
                          player.playingId === message.id ? "Stop" : "Listen"
                        }
                        disabled={player.loadingId === message.id}
                        onClick={() =>
                          player.playingId === message.id
                            ? player.stop()
                            : player.play(message.id, text)
                        }
                      >
                        {player.loadingId === message.id ? (
                          <Loader2Icon className="size-4 animate-spin" />
                        ) : player.playingId === message.id ? (
                          <SquareIcon className="size-4" />
                        ) : (
                          <Volume2Icon className="size-4" />
                        )}
                      </Action>
                    </Actions>
                  )}
                </div>
              );
            })}
            {(status === "submitted" || status === "streaming") && <Loader />}
          </ConversationContent>
          <ConversationScrollButton />
        </Conversation>

        {(inputError || recorder.error) && (
          <p className="mt-2 text-sm text-destructive">
            {inputError ?? recorder.error}
          </p>
        )}

        <PromptInput
          key={formKey}
          onSubmit={handleSubmit}
          className="mt-4"
          accept="image/png,image/jpeg,image/webp,image/gif"
          multiple
          maxFiles={4}
          maxFileSize={4 * 1024 * 1024}
          onError={(err) => {
            // PromptInput reuses the form's onError prop for file errors
            if ("code" in err) setInputError(err.message);
          }}
        >
          <PromptInputBody>
            <PromptInputAttachments>
              {(attachment) => <PromptInputAttachment data={attachment} />}
            </PromptInputAttachments>
            <PromptInputTextarea
              value={input}
              onChange={(e) => setInput(e.target.value)}
            />
          </PromptInputBody>
          <PromptInputToolbar>
            <PromptInputTools>
              <PromptInputActionMenu>
                <PromptInputActionMenuTrigger />
                <PromptInputActionMenuContent>
                  <PromptInputActionAddAttachments label="Add images" />
                </PromptInputActionMenuContent>
              </PromptInputActionMenu>
              <PromptInputButton
                onClick={recorder.isRecording ? recorder.stop : recorder.start}
                disabled={recorder.isTranscribing}
                variant={recorder.isRecording ? "destructive" : "ghost"}
                aria-label={
                  recorder.isRecording ? "Stop recording" : "Record a question"
                }
              >
                {recorder.isTranscribing ? (
                  <Loader2Icon className="size-4 animate-spin" />
                ) : recorder.isRecording ? (
                  <SquareIcon className="size-4" />
                ) : (
                  <MicIcon className="size-4" />
                )}
              </PromptInputButton>
            </PromptInputTools>
            <PromptInputSubmit disabled={!input && !status} status={status} />
          </PromptInputToolbar>
        </PromptInput>
      </div>
    </div>
  );
}

Test it

  1. Ask a question. When the answer finishes streaming, a speaker icon appears under it, with a "Listen" tooltip.
  2. Click it. A spinner shows for a moment, then the answer is read aloud and the icon becomes a stop square.
  3. Click stop, or click Listen on another answer. The first one stops, so only one plays at a time.
  4. Combine with step 19: ask by voice, then listen to the answer, without using the keyboard.

How to know it worked: the speaker icon appears only under the bot's answers, never under your own messages and never while an answer is still streaming. In DevTools' Network tab, clicking it sends a POST to speech with status 200, and the response contains a "mediaType" such as "audio/mpeg" and a very long "audio" string.

Common mistakes:

  • Nothing happens and the browser console shows an error – look at the terminal running npm run dev: "Speech generation error" with a 401 means the API key is missing or wrong (restart the dev server after editing .env.local).
  • No sound, but no error – check that the tab isn't muted and the system volume is up. Some browsers show a muted-speaker icon on the tab.
  • The speaker icon never appears – the canListen condition is wrong (for example "user" instead of "assistant"), or the {canListen && (…)} block was placed outside the message's div.
  • "Module not found: Can't resolve '@/components/ai-elements/actions'" – your project doesn't have the Actions component. It ships with the repo; if you set up AI Elements yourself, add it with the AI Elements CLI.

Cost and latency. Speech is generated only when the user clicks, never automatically, so you don't pay for answers nobody listens to. For long answers, the request takes a few seconds before playback starts. The AI SDK version used here returns the finished file rather than a stream.

Recap
  • /api/speech validates the text with zod and returns base64 MP3 from generateSpeech.
  • useSpeechPlayer plays one answer at a time and tracks its state per message.
  • The Listen action only appears on finished assistant answers.
