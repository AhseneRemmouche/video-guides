Building Chatbot UI

A chat page built with AI Elements and the useChat hook.

▶ Watch this part (08:00)

Goal

Build the /chat page: a scrollable conversation, a prompt box and a loading indicator, connected to /api/chat through the useChat hook.

So far you have a server-side route handler that can talk to the AI model. Nobody can use it yet, because there is no screen to type into. On this page you build that screen. When you finish, a user can type a question in the browser, the browser sends it to /api/chat, and the answer streams back word by word.

New to React components? What they are and why they matter

A component is a JavaScript function that returns a piece of user interface. You write small components (a button, a message bubble, a text box) and combine them into bigger ones (a whole chat page). This is how React apps are built: components inside components, like boxes inside boxes.

Two rules make a function a component:

  • Its name starts with a capital letter (RAGChatBot, not ragChatBot). React uses the capital letter to tell your components apart from plain HTML tags like div.
  • It returns JSX: the HTML-like markup that describes what should appear on screen.
function Greeting() {
  return <p>Hello!</p>;
}

// used somewhere else, like an HTML tag:
<Greeting />

In the App Router of Next.js, a file called page.tsx must default-export a component. Next.js renders that component when someone visits the matching URL.

New to JSX? Why there is HTML inside JavaScript

JSX is a syntax that lets you write HTML-like tags inside JavaScript/TypeScript files (that is why the file ends in .tsx: TypeScript + JSX). A build tool turns each tag into a normal function call before the browser sees it.

A few differences from plain HTML that you will meet on this page:

  • className instead of class, because class is a reserved word in JavaScript.
  • Curly braces { } switch back to JavaScript. <p>{name}</p> shows the value of the variable name. Anything inside the braces must be an expression (something that produces a value), so you cannot put an if statement directly in them.
  • Every tag must be closed. Tags with no children close themselves: <Loader />.
  • Comments inside JSX look like {/* comment */}.
  • A component must return one outer element. If you need several siblings, wrap them in a div or a Fragment.

  2. Make it a Client Component

    The page needs state and event handlers, so add "use client"; at the very top.

    New to "use client"? Server Components vs Client Components

    In the App Router, every component is a Server Component by default. It runs on the server, produces HTML, and sends no JavaScript for itself to the browser. That is fast, but a Server Component cannot react to clicks or typing, because it never runs in the browser.

    The "use client" directive at the very top of a file says: "this component (and everything it imports) must also run in the browser". Only then can you use hooks like useState and useChat, and event handlers like onChange. See server vs client in the glossary.

    Rules: it must be the first statement in the file (comments above it are fine), and it must be in quotes with a semicolon, exactly "use client";.

    Common mistake: forgetting "use client". Next.js then fails with an error like "You're importing a component that needs useState. This React Hook only works in a Client Component." Add the directive and the error goes away.

    The class names are Tailwind CSS utility classes. Each one sets one small piece of styling. Every class is decoded in the line-by-line table below.

    TypeScript will show an error on PromptInput because onSubmit is required. You fix that in item 9 below.

    New to props? How you pass information into a component

    Props ("properties") are the inputs of a component. You write them like HTML attributes: <Message from="user"> passes a prop called from with the value "user". Use quotes for plain strings and curly braces for any other JavaScript value: <PromptInput onSubmit={handleSubmit}> passes a function.

    Whatever you put between the opening and closing tag is passed as a special prop called children. That is how <Conversation> knows what to show inside its scroll area.

    A component cannot change its own props. They flow one way, from parent to child.

  5. Add input state

    Import useState and Fragment from React. Create input/setInput, starting as an empty string, and bind it to the textarea through value and onChange.

    New to state and useState? How a component remembers things

    A component function runs again every time React redraws ("re-renders") it. Normal variables are reset on every run, so they can't remember anything. State is memory that React keeps for the component between runs.

    const [input, setInput] = useState("");
    • useState("") creates one piece of state whose starting value is "" (empty text).
    • It returns a pair. The square brackets are array destructuring: they give names to the two items. input is the current value. setInput is the function you call to change it.
    • Calling setInput("hi") stores the new value and tells React to re-render, so the screen updates. Assigning input = "hi" directly would do nothing visible (and const forbids it anyway).

    Connecting value={input} and onChange to the textarea is called a controlled input: React state is the single source of truth for what is in the box. This is what lets you clear the box later with setInput("").

    New to hooks? What "use…" functions are

    A hook is a special function whose name starts with use (useState, useChat, useRef…). Hooks let a component plug into React features like state. Two rules:

    • Call hooks only at the top level of a component, never inside an if, a loop or a nested function. React matches hooks by the order they are called, and that order must be the same on every render.
    • Call them only from components (or from other hooks), and only in Client Components.
  6. Connect to the API with useChat

    Import useChat from @ai-sdk/react and destructure:

    • messages: the conversation history.
    • sendMessage: sends a new message to the API route.
    • status: the chat state ("ready", "submitted", "streaming" or "error").

    By default useChat POSTs to /api/chat, which is exactly the route you created. Keep the same folder structure, or pass a custom transport.

    New to useChat? What it does for you

    useChat is a hook from the Vercel AI SDK. Without it you would have to write a lot of code yourself: keep a list of messages in state, fetch the API route, read the streamed response piece by piece, append each piece to the last message, and track whether a request is in progress. useChat does all of that.

    The status values move through a cycle:

    • "ready": idle, waiting for the user.
    • "submitted": the message was sent; no reply text has arrived yet.
    • "streaming": reply text is arriving and being added to the screen.
    • "error": something went wrong (for example, the API key is wrong or the server crashed).

    Every time messages or status changes, your component re-renders automatically, so the screen always matches the conversation.

  7. Render the messages

    Map over messages and render a div with key={message.id} for each. Each message has parts, so one message can hold different kinds of content. Map over the parts and switch on part.type. For now only "text" is handled:

    • Return a Fragment with a unique key `${message.id}-${i}`.
    • <Message from={message.role}> tells the component whether the message is from the user or the assistant, so it is styled correctly.
    • <Response> renders part.text as Markdown.
    • Add a default case that returns null.
    New to rendering lists with keys? How .map turns data into screen elements

    To show a list in React you turn an array of data into an array of JSX elements with the array map method. map calls your function once per item and collects what it returns:

    const fruits = ["apple", "pear"];
<ul>
  {fruits.map((f) => <li key={f}>{f}</li>)}
</ul>
// renders: <ul><li>apple</li><li>pear</li></ul>

    Each element in a list needs a key prop: a value that is unique among its siblings and stays the same for the same item over time. React uses keys to work out which item is which when the list changes (a new message is added, a message grows while streaming). Without keys React prints a warning in the browser console, and it may update the wrong element.

    Message ids are perfect keys. For parts, the code combines the message id and the position i, because parts have no id of their own.

    New to Fragment? A wrapper that adds nothing to the page

    A Fragment groups elements without creating an extra HTML element. The short form is <>…</>, but the short form cannot take a key. When you need a key on a group, you must write the long form, <Fragment key={…}>, which is why this page imports Fragment from React.

  8. Show a loader while waiting

    Just before </ConversationContent>, render <Loader /> when status is "submitted" or "streaming".

    New to conditional rendering? Showing something only sometimes

    Conditional rendering means "show this element only if a condition is true". Since you cannot write if inside JSX braces, React code uses the && (logical AND) trick:

    {isLoading && <Loader />}

    JavaScript evaluates a && b like this: if a is false, the result is a (false), and React draws nothing for false. If a is true, the result is b, the <Loader /> element, which React draws. For an either/or choice you would use the ternary operator: {ok ? <A /> : <B />}.

  9. Handle submit

    handleSubmit receives a PromptInputMessage. If there is no text, return. Otherwise call sendMessage({ text: message.text }) and clear the input. Pass it to <PromptInput onSubmit={handleSubmit}>. PromptInput passes the message as the argument, and this also fixes the TypeScript error.

    New to event handlers? Reacting to typing and clicking

    An event is something that happens in the browser: a key press, a click, a form submit. An event handler is a function you give to a component so it can call you back when the event happens. In React the props are named onSomething: onChange, onClick, onSubmit.

    Pass the function itself, do not call it: onSubmit={handleSubmit} is right; onSubmit={handleSubmit()} would run it immediately during rendering. When you need to do something small inline, pass an arrow function: onChange={(e) => setInput(e.target.value)}. Here e is the event object, e.target is the textarea that changed, and e.target.value is its current text.

Complete file

// src/app/chat/page.tsx
"use client";

import { Fragment, useState } from "react";
import { useChat } from "@ai-sdk/react";
import {
  Conversation,
  ConversationContent,
  ConversationScrollButton,
} from "@/components/ai-elements/conversation";
import { Message, MessageContent } from "@/components/ai-elements/message";
import {
  PromptInput,
  PromptInputBody,
  type PromptInputMessage,
  PromptInputSubmit,
  PromptInputTextarea,
  PromptInputToolbar,
  PromptInputTools,
} from "@/components/ai-elements/prompt-input";
import { Response } from "@/components/ai-elements/response";
import { Loader } from "@/components/ai-elements/loader";

export default function RAGChatBot() {
  const [input, setInput] = useState("");
  const { messages, sendMessage, status } = useChat();

  const handleSubmit = (message: PromptInputMessage) => {
    if (!message.text) {
      return;
    }
    sendMessage({
      text: message.text,
    });
    setInput("");
  };

  return (
    <div className="max-w-4xl mx-auto p-6 relative size-full h-[calc(100vh-4rem)]">
      <div className="flex flex-col h-full">
        <Conversation className="h-full">
          <ConversationContent>
            {messages.map((message) => (
              <div key={message.id}>
                {message.parts.map((part, i) => {
                  switch (part.type) {
                    case "text":
                      return (
                        <Fragment key={`${message.id}-${i}`}>
                          <Message from={message.role}>
                            <MessageContent>
                              <Response>{part.text}</Response>
                            </MessageContent>
                          </Message>
                        </Fragment>
                      );
                    default:
                      return null;
                  }
                })}
              </div>
            ))}
            {(status === "submitted" || status === "streaming") && <Loader />}
          </ConversationContent>
          <ConversationScrollButton />
        </Conversation>

        <PromptInput onSubmit={handleSubmit} className="mt-4">
          <PromptInputBody>
            <PromptInputTextarea
              value={input}
              onChange={(e) => setInput(e.target.value)}
            />
          </PromptInputBody>
          <PromptInputToolbar>
            <PromptInputTools>
              {/* Model selector, web search, etc. */}
            </PromptInputTools>
            <PromptInputSubmit disabled={!input && !status} status={status} />
          </PromptInputToolbar>
        </PromptInput>
      </div>
    </div>
  );
}

Reading the repo's version: this is the final file from GitHub, so two lines differ from what you type at this point in the video:

  • Height: the repo already has h-[calc(100vh-4rem)]. You start with h-[calc(100vh)] and subtract the navbar's 4rem in step 7.
  • Submit button: the repo passes status={status} to PromptInputSubmit. The button then shows a spinner while the request is submitted, a stop square while streaming, and an X on error. The video doesn't mention this. The repo also passes disabled={!input && !status}, but status is always a non-empty string, so !status is always false and the button is never disabled. If you want the button disabled while the box is empty, use disabled={!input}.

Test it

  1. Open localhost:3000/chat

    You should see a clean chat interface with a "What would you like to know?" box.

  2. Ask "What is React?"

    The answer streams in.

  3. Follow up with "Can you give me a code example?"

    The chat keeps the context and gives a relevant example, because useChat sends the whole history with each request.

  4. Ask "What is our company's vacation policy?"

    The AI can't help. It has no access to that information. This is the gap RAG fills in the rest of the tutorial.

What you should see: your question appears in a bubble, a spinner shows briefly below it, then the answer appears piece by piece with Markdown formatting (bold text, lists, code blocks). The send button icon changes while the answer streams. When it finishes, the spinner disappears and the box is empty and ready.

Common problems:

  • Nothing happens and the browser console shows a 404 for /api/chat: the route file is not at src/app/api/chat/route.ts, so useChat's default URL doesn't exist.
  • A 500 error or status becomes "error": look at the terminal running npm run dev. A missing or wrong OPENAI_API_KEY in .env.local is the usual cause. Restart the dev server after editing .env.local, because environment variables are read only at startup.
  • The text box won't accept typing: value={input} is set but onChange is missing or misspelled.
  • Messages appear as raw **asterisks**: you rendered {part.text} without wrapping it in <Response>.
  • "Each child in a list should have a unique key" warning in the console: a key is missing on line 44 or 49.
Recap
  • useChat manages messages and status and talks to /api/chat.
  • Messages are made of parts. You render text parts with Message, MessageContent and Response.
  • You now have a working standard chatbot. Before giving it internal data, you add authentication.
