Implementing Chat Route Handler

A streaming POST /api/chat endpoint with streamText.

▶ Watch this part (05:25)

Goal

Create the POST /api/chat endpoint. It receives the conversation from the UI, sends it to OpenAI with streamText, and streams the reply back in the format useChat expects.

An endpoint is an address on your server that a program can send requests to. This one is the middle box from the diagram in step 4: the browser sends it the chat, it forwards the chat to OpenAI using your secret key, and it passes OpenAI's answer back to the browser as it arrives.

New to HTTP? Requests, responses and methods in two minutes

Browsers and servers talk using HTTP. Every conversation is one request followed by one response.

A request has:

  • a URL (where): for example http://localhost:3000/api/chat;
  • a method (what kind of action): GET means "give me something", POST means "here is some data, please process it". See HTTP methods;
  • headers (extra information, such as the data format);
  • an optional body (the data itself), often in JSON format.

A response has a status code (200 = OK, 404 = not found, 500 = server error), headers and a body. For this endpoint, the request body looks roughly like this:

{
  "messages": [
    { "id": "m1", "role": "user", "parts": [{ "type": "text", "text": "Hi!" }] }
  ]
}

Sending the chat is a POST because the browser is handing data to the server, not just fetching a page.

New to route handlers? How a file becomes an API endpoint

In the Next.js App Router, a file named page.tsx becomes a page people visit, and a file named route.ts becomes an endpoint programs call. The file containing an endpoint is called a route handler.

Inside route.ts you export functions named after HTTP methods: GET, POST, PUT, DELETE… When a request arrives, Next.js calls the function whose name matches the request's method, gives it the request, and sends back whatever Response the function returns. If a method has no function (say, a GET to this file), Next.js answers 405 Method Not Allowed automatically.

Route handlers always run on the server, never in the browser, so they can safely use secrets such as OPENAI_API_KEY.

Step by step

  1. Create the file

    In src/app, create a folder api, inside it a folder chat, and inside that route.ts. In the App Router, a route.ts file inside app/api/chat/ becomes the URL /api/chat.

    The api folder name is only a convention that keeps endpoints apart from pages; Next.js doesn't require it. But the code in later steps calls exactly /api/chat, so use these names.

    Common mistakes: naming the file routes.ts or route.tsx (it must be exactly route.ts), or creating api/ at the project root or directly in src/ instead of inside src/app/. In both cases the URL does not exist and the chat page later gets a 404.

  2. Start with an empty POST handler 
    export async function POST(req: Request) {}

    This declares the function Next.js will call for every POST request to /api/chat. It does nothing yet; the next steps fill it in. Each word is explained in the line-by-line table below.

  3. Add the imports
    • streamText from ai plus the openai provider from @ai-sdk/openai. Together they stream text from OpenAI's models.
    • The UIMessage type and the convertToModelMessages helper, also from ai.
  4. Read the messages from the request

    await req.json() returns an object. Destructure messages from it and type it as UIMessage[], the format useChat sends.

  5. Call streamText

    Pass the model and the messages. convertToModelMessages converts the UI message format into the format the model expects.

  6. Return a streaming response

    result.toUIMessageStreamResponse() turns the stream into an HTTP response that useChat can read.

  7. Add error handling

    Wrap everything in try/catch. On error, log it and return a 500.

New to async/await? Why the function is async

Some operations take time: reading a request body, talking to OpenAI, querying a database. JavaScript doesn't stop and wait for them; instead it gives you a promise, a placeholder for a value that will arrive later.

Writing await in front of a promise means "pause this function here until the value is ready, then continue". You may only use await inside a function marked async. An async function itself always returns a promise, which is exactly what Next.js expects from a route handler.

const body = await req.json(); // waits until the body has been read and parsed
console.log(body.messages);     // runs only after that
New to streaming? Why the answer arrives word by word

A model writes its answer one token at a time, and a long answer can take 10 seconds or more. Without streaming, the server would wait for the whole answer and then send it, so the user stares at a blank screen.

With streaming, the HTTP response starts immediately and stays open. Each new piece of text is sent down the same connection as soon as the model produces it, and the browser displays it right away. When the model is done, the response ends. streamText and toUIMessageStreamResponse() do all of this for you.

Complete file

import { streamText, UIMessage, convertToModelMessages } from "ai";
import { openai } from "@ai-sdk/openai";

export async function POST(req: Request) {
  try {
    const { messages }: { messages: UIMessage[] } = await req.json();

    const result = streamText({
      model: openai("gpt-4.1-mini"),
      messages: convertToModelMessages(messages),
    });

    return result.toUIMessageStreamResponse();
  } catch (error) {
    console.error("Error streaming chat completion:", error);
    return new Response("Failed to stream chat completion", { status: 500 });
  }
}

New to try/catch? What it protects against

When something goes wrong in JavaScript, code throws an error, and execution stops right there. If nothing catches it, the request fails in an uncontrolled way.

try {
  riskyThing();          // if this throws...
  console.log("done");   // ...this line is skipped
} catch (error) {
  console.error(error);  // ...and execution continues here
}

Here, catch guarantees the browser always gets a clear answer (a 500) and you always get a log line. Note that it only catches errors that happen before the response is returned. Errors that happen later, while the answer is streaming (for example a wrong API key), are reported by the AI SDK inside the stream itself.

How it works

PieceWhat it does
UIMessage[]The UI's view of the conversation. Each message has an id, a role and an array of parts (text, tool calls and so on).
convertToModelMessagesConverts UI messages into the simpler shape the model API expects.
streamTextStarts generating and returns at once with a stream. It does not wait for the full answer.
toUIMessageStreamResponseSends the stream to the client in the AI SDK's UI message protocol.

The role of a message is "user" (typed by the person), "assistant" (written by the model) or "system" (instructions for the model, used in step 15).

Why gpt-4.1-mini? The presenter notes that if you use gpt-5-mini and your OpenAI organization has a zero data retention policy, there is an extra configuration step. Use gpt-4.1-mini to follow along without problems.

How to know it worked

There is no page to look at yet; the chat UI comes in step 6. For now:

  • Save the file and check the terminal running npm run dev: there should be no red error about route.ts.
  • Your editor should show no red underlines. If "ai" or "@ai-sdk/openai" is underlined with "Cannot find module", the packages from step 4 are not installed: run the npm install command again in the project root.
  • Opening http://localhost:3000/api/chat in the browser sends a GET, not a POST, so you will see a 405 error. That is expected and actually proves the route exists (a typo in the folder name would give 404 instead).

Common mistakes

  • Writing export async function post (lowercase) or forgetting export: Next.js won't find the handler.
  • Forgetting await before req.json(): messages would be undefined, and the code fails when it tries to convert it.
  • Editing .env.local without restarting the dev server: the first chat in step 6 then fails with a missing API key error, visible in the terminal.
Recap
  • /api/chat is ready. It takes UIMessage[] and streams back a model response.
  • Errors are caught, logged in the terminal and returned as a 500.
  • Next: the UI that calls it.
