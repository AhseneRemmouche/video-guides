Glossary

Every technical term in this guide, explained for beginners.

Every technical word used in this guide and in the AI & Agents Handbook, explained in plain language. Pages link here whenever a term first appears, so you can always come back. Terms are grouped by topic, and many entries link to the handbook chapter that covers them in depth.

Two maps to start with

Before the individual words, here is how they fit together. The first map shows where each piece of the project runs; the second shows how the AI ideas build on each other.

Tools & the command line

Terminal (command line)
A text window where you type commands instead of clicking. In VS Code, open it with Ctrl+`. Lines in this guide such as npm install ai are typed there and run with Enter.
Node.js
A program that runs JavaScript outside the browser, on your computer or a server. Next.js, npm and every tool in this project need it. Check your version with node -v.
npm
The Node Package Manager, installed with Node.js. npm install X downloads the package X into node_modules/ and records it in package.json. npm run dev runs the script named "dev" from package.json.
npx
Runs a package's command without installing it permanently. For example npx create-next-app@latest downloads the newest version, runs it once and leaves nothing behind. @latest means "the newest version".
Package (library, dependency)
Code someone else wrote and published so you can reuse it, for example ai, zod or drizzle-orm. A package your project needs is called a dependency.
package.json
Your project's ID card: its name, its scripts (dev, build…) and every dependency with its version. package-lock.json records the exact versions installed, so everyone gets the same setup.
node_modules
The folder where npm puts downloaded packages. It is huge, never edited by hand and never committed to Git. Delete it and run npm install to rebuild it.
Dev dependency (-D)
A package needed only while developing or building, such as types or linters, not when the app runs. Install with npm install -D X.
CLI
Command-Line Interface: a program you use from the terminal, like drizzle-kit or shadcn.
VS Code
The free code editor used in the video. Its Explorer panel on the left shows your files and folders.
Git / .gitignore
Git keeps the history of your code. .gitignore lists files Git must ignore, such as node_modules and .env.local, so secrets are never uploaded.
localhost:3000
"This computer, port 3000." While npm run dev is running, your app is served at http://localhost:3000. Only you can see it.

JavaScript & TypeScript

TypeScript
JavaScript plus types: labels that say what kind of value something is (string, number, number[]…). The editor uses them to catch mistakes before you run the code. Files end in .ts, or .tsx when they contain JSX.
Type annotation
The : something after a name: text: string means "text must be a string". string[] means a list of strings. A | B means "either A or B". T | null means "a T, or nothing".
import / export
Each file is a module. export makes something available to other files. import { x } from "y" brings it in. export default marks the file's main thing, imported without braces. import type imports only a type.
@/ path alias
@/ is a shortcut for the src/ folder, so @/lib/db-config means src/lib/db-config.ts. It saves writing long relative paths like ../../lib/db-config. A path starting with ./ means "next to this file".
const / let
Declare a named value. const can't be reassigned and is the default choice. let can be reassigned.
Function / arrow function
A reusable block of code. function f(x) { … } and const f = (x) => { … } both define one. An arrow function that is a single expression returns it directly: (x) => x * 2.
async / await / Promise
Some work takes time, like calling an API or a database. Such functions return a Promise, a "value that will arrive later". Inside an async function, await pauses until it arrives, so the code reads top to bottom.
Destructuring
Pulling values out of an object or array by name: const { messages } = body is short for const messages = body.messages. Arrays use positions: const [a, b] = list.
Template literal
A string in backticks that can contain values: `Created ${n} chunks`. Also used for multi-line strings, such as the system prompt.
Optional chaining ?. / nullish ??
a?.b reads b only if a exists, otherwise it gives undefined instead of crashing. x ?? y means "x, or y if x is null or undefined".
Non-null assertion !
process.env.X! tells TypeScript "trust me, this isn't undefined". Use it only when you're sure. Here it's a value from .env.local.
try / catch / finally
Error handling. Code in try runs. If anything throws an error, catch runs instead of the app crashing. finally always runs at the end, which makes it the place to switch a loading spinner off.
.map / .filter / .join
Array helpers. .map(fn) builds a new array by transforming each item. .filter(fn) keeps the items that pass a test. .join(", ") glues the items into one string.
Object / JSON
An object is a set of named values: { success: true, message: "ok" }. JSON is the same idea written as text, used to send data over the network. JSON.stringify turns an object into text, and .json() turns it back.
Regular expression
A pattern for finding text, written between slashes: /\n/g means "every newline" (g = global, every match).

React & Next.js

React
A library for building user interfaces from components. You describe what the screen should look like for the current data, and React updates the page when the data changes.
Component
A function that returns UI (JSX). Its name starts with a capital letter: Navigation, RAGChatBot. You use it like an HTML tag: <Navigation />.
JSX
HTML-like syntax inside JavaScript. className is used instead of class, and { … } inserts a JavaScript value: <p>{message.text}</p>.
Props
Inputs passed to a component, like HTML attributes: <Button variant="ghost"> passes variant. children is whatever you put between the opening and closing tags.
State / useState
Data a component remembers between renders. const [input, setInput] = useState("") creates input (starting as "") and setInput to change it. Calling the setter re-draws the component.
Hook
A function whose name starts with use (useState, useChat, useRef…) that gives a component extra abilities. Hooks must be called at the top level of a component.
useRef
Like state, but changing it does not re-draw the component. Good for holding things like the current audio player or recorder.
key prop
When rendering a list, React needs a unique key on each item to track it. Changing a component's key makes React throw it away and create a fresh one, a trick used in step 18.
Fragment
<Fragment> (or <>…</>) groups elements without adding an extra element to the page.
Conditional rendering
Showing something only when a condition is true: {isLoading && <Spinner />}. Or choosing between two things: {ok ? <A /> : <B />}.
Event handler
A function that runs when something happens: onClick, onChange (input edited), onSubmit (form sent). It receives an event object, for example e.target.value, the text typed.
Next.js
A framework built on React that adds routing, server code, building and deployment. One project contains both the website and its backend.
App Router / file-based routing
In Next.js, folders inside src/app become URLs. app/chat/page.tsx is the page at /chat. app/api/chat/route.ts is the API at /api/chat.
layout.tsx
A wrapper shared by every page below it, which is why the navigation bar placed there shows on every page.
Server vs client
The server is the computer running Next.js, where secrets and the database are safe. The client is the user's browser. Code that touches API keys or the database must run on the server.
"use client"
The first line of a file whose components run in the browser because they use state, hooks or clicks. Without it, Next.js components run on the server by default.
Route handler (API route)
A route.ts file that exports functions named after HTTP methods (POST, GET). It's your backend endpoint: it receives a request and returns a Response.
Server action ("use server")
A server function that a client component can call like a normal function. Next.js sends the request for you, so there's no API route to write.
Middleware
Code that runs before every matching request. It's used here to block signed-out users and non-admins. In Next.js 16 the file is renamed proxy.ts.
Environment variables / .env.local
Settings and secrets kept outside the code, such as API keys and the database URL. Next.js reads .env.local and exposes the values as process.env.NAME. Only names starting with NEXT_PUBLIC_ are visible in the browser.
Tailwind CSS
Styling with short class names directly in JSX: p-6 (padding), mx-auto (centre horizontally), flex, text-xl. h-[calc(100vh-4rem)] is a custom value: the full screen height minus 4rem.
shadcn/ui
A collection of ready-made, good-looking components (Button, Card, Alert…) that are copied into your project (src/components/ui) so you can edit them.
AI Elements
Like shadcn/ui but for AI apps: chat conversation, message bubbles, prompt box, loader. Copied into src/components/ai-elements.
Biome / linter
A tool that checks your code for mistakes and style problems (linting) and tidies its layout (formatting).
Build (npm run build)
Turns your project into an optimised version for production and checks every type. npm run dev is for development and reloads as you save.

The web: HTTP & APIs

HTTP request / response
How a browser and a server talk. The browser sends a request (method, URL, optional body), and the server sends back a response (status code, body).
GET / POST
GET reads something. POST sends data to be processed, like a chat message or a file.
Status code
A number describing the result: 200 OK, 400 bad input, 401/403 not allowed, 500 server error, 502 an upstream service failed.
API
A way for programs to talk to each other. OpenAI's API is the URL your server calls to use GPT models. Your /api/chat is your own API, called by your page.
API key
A secret password that identifies you to a service and is billed to your account. Keep it in .env.local, never in code or Git.
fetch
The built-in function for making HTTP requests from JavaScript: await fetch("/api/speech", { method: "POST", body }).
FormData
The format browsers use to send files to a server. formData.append("file", file) adds a file under a name, and the server reads it with formData.get("file").
Streaming
Sending a response piece by piece as it's produced, which is why the AI's answer appears word by word instead of all at once.
Blob / blob: URL / data: URL / base64
A Blob is raw file data in the browser. A blob: URL points to it but only works inside that browser tab. A data: URL contains the file itself, written as base64 (text made of letters and digits), so it can be sent anywhere.

AI concepts

LLM / model
A Large Language Model such as GPT-4.1-mini. It predicts text and knows only what it learned in training, plus what you put in the prompt.
Machine learning (ML)
Teaching computers by showing them examples instead of writing every rule by hand. The program finds patterns in the data and uses them to make predictions. LLMs are one kind of machine learning. See Chapter 1.
Neural network
A kind of machine-learning model made of many layers of simple maths units connected by adjustable numbers called weights. Training adjusts the weights until the network's outputs match the examples. See Chapter 1.
Transformer
The neural-network design behind today's LLMs. It reads all the tokens of the input together and uses attention to work out how they relate to each other. See Chapter 2.
Attention
The part of a transformer that lets each token "look at" the other tokens and decide which ones matter for understanding it, for example linking "it" back to the right noun. See Chapter 2.
Training / weights / parameters
Showing a model huge numbers of examples and slowly adjusting its internal numbers (weights, also called parameters) so its predictions improve. Training a large model from scratch takes enormous computing power and is done by the model's creator. See Chapter 2.
Inference
Using an already-trained model to produce an output, such as an answer, an embedding or speech. Every request your chatbot sends is inference. The model's weights don't change. See Chapter 2.
Fine-tuning
A small extra round of training that starts from an existing model and nudges it with your own examples. It's good for changing style, format or a narrow skill, and poor for teaching facts that change, which is what RAG is for. See Chapter 15.
RLHF
Reinforcement Learning from Human Feedback: a training step in which people rate or compare model answers, and the model is adjusted to prefer the kind of answers people rated well. It's a big part of what makes chat models helpful and polite. See Chapter 2.
Temperature
A setting that controls how random a model's word choices are. Low values give more focused, repeatable answers. Higher values give more varied, creative ones. Some models, such as many reasoning models, don't let you change it. See Chapter 2.
Hallucination
When a model states something false or made-up as if it were true, such as an invented policy or citation. It happens because the model predicts plausible text, not checked facts. Grounding answers in retrieved documents (RAG) reduces it. See Chapter 2.
Reasoning model
A model trained to work through a problem in internal steps ("thinking") before giving its final answer. That makes it better at multi-step problems, but usually slower and more token-hungry. See Chapter 2.
Open-weight model
A model whose trained weights are published so you can download and run it yourself. Each one comes with its own license, which may restrict how you use it, so "open weights" doesn't automatically mean "free for any use". See Chapter 3.
Local model
A model that runs on your own computer or server instead of a provider's cloud, for example through a tool like Ollama. Your data stays with you, but you need suitable hardware and smaller models are usually less capable. See Chapter 3 and Chapter 15.
GPU
Graphics Processing Unit: a chip that does thousands of calculations in parallel. That makes it much faster than a normal processor (CPU) for training and running AI models. How much memory it has limits how big a model you can run. See Chapter 15.
Quantization
Storing a model's weights with fewer bits (for example 4-bit instead of 16-bit numbers), like compressing a photo. The model gets much smaller and faster, which helps it fit on ordinary hardware, at the cost of some quality. See Chapter 15.
Prompt / system prompt
The text sent to the model. The system prompt is a hidden instruction that sets its behaviour ("You are a helpful assistant…"). The user's messages come after it.
Few-shot prompting
Including a few examples of the input and the ideal output in your prompt, so the model copies the pattern. "Zero-shot" means giving instructions with no examples. See Chapter 4.
Structured output
Asking the model for data in an exact shape (such as JSON with specific fields) instead of free text, and checking the result. In the AI SDK, generateObject does this with a zod schema. See Chapter 5.
JSON Schema
A standard way to describe what valid JSON looks like: which fields exist, their types and which are required. Zod schemas are converted to JSON Schema behind the scenes so the model knows what shape to produce. See Chapter 5.
Token
A chunk of text (about ¾ of a word) that models read and write. API pricing and limits are counted in tokens.
Context window
The maximum amount of text (in tokens) a model can consider at once. It's why you can't paste every document into every prompt.
AI SDK (Vercel)
The ai package. It gives the same simple functions (streamText, embed, tool…) for many AI providers, and React hooks like useChat.
Provider
A company serving models, such as OpenAI. @ai-sdk/openai connects the AI SDK to it.
RAG
Retrieval-Augmented Generation: find relevant passages in your own documents (retrieval), add them to the model's input (augmentation), and let it answer (generation).
Embedding / vector
A list of numbers (here 1,536) that represents the meaning of a text. Texts with similar meaning have vectors that point in similar directions.
Chunk / chunking
A small piece of a document, and the act of splitting a document into such pieces, so search can return just the relevant part.
Cosine similarity / distance
A measure of how similar two vectors' directions are. Similarity is 1 for "same meaning". Distance = 1 − similarity, so 0 means identical.
Semantic search
Searching by meaning (comparing embeddings) instead of by exact words, so "PTO" can find "vacation days".
Hybrid search
Combining keyword search (exact words) with semantic search (meaning) and merging the results. It catches both exact terms like product codes and differently worded questions. See Chapter 8.
BM25
A classic keyword-ranking formula used by search engines. It scores documents higher when they contain the query's words, especially rare words, and is often the keyword half of hybrid search. See Chapter 8.
Reranking
A second step after search: take the top results (say 20) and re-order them with a more accurate but slower model that reads the question and each passage together, then keep the best few. See Chapter 8.
HyDE
Hypothetical Document Embeddings: ask the model to write a made-up ideal answer to the question, then search with the embedding of that answer instead of the question. It sometimes finds better matches because answers look more like documents than questions do. See Chapter 8.
Tool calling
Letting the model call a function you provide (here searchKnowledgeBase). The model decides when to call it and with what input, reads the result, then answers.
Zod / schema
A library for describing the expected shape of data (z.object({ query: z.string() })) and checking real data against it. It's used for the tool's input and for validating requests.
Multimodal / vision model
A model that understands more than text, such as images, PDFs or audio. GPT-4.1-mini can "see" images.
OCR
Optical Character Recognition: reading the text inside an image or a scan.
Speech-to-text / text-to-speech
Turning recorded audio into text (transcription), and turning text into spoken audio (speech synthesis).

AI agents

AI agent
An AI system in which the model decides for itself which tools to call, and in what order, looping until the task is done. Step 22 turns the chatbot into one. See Chapter 9.
Agent loop
The cycle at the heart of an agent: the model thinks, calls a tool, reads the result, then decides whether to call another tool or answer. In the AI SDK, stopWhen: stepCountIs(n) limits how many times it can go round. See Chapter 9.
ReAct pattern
Short for Reason + Act (not related to the React library): the model alternates between reasoning about what to do next and acting by calling a tool, using each result to plan the next step. See Chapter 9.
Workflow (vs agent)
A sequence of LLM calls and tools whose order is fixed in your code, such as "summarise, then translate". It's more predictable than an agent, which chooses its own steps. Many tasks need a workflow, not an agent. See Chapter 9 and Chapter 10.
Memory
How an AI app remembers information beyond one request: short-term (the conversation messages sent with each request) and long-term (facts saved to a database and retrieved later). The model itself remembers nothing between calls. See Chapter 10.
Planning
Having the model first break a task into steps (a plan) and then carry them out, instead of reacting one step at a time. It helps with long or complex tasks. See Chapter 10.
Multi-agent system
Several agents, each with its own instructions and tools, working together. For example, an orchestrator hands sub-tasks to specialist workers. It's powerful, but harder to debug and more expensive than one agent. See Chapter 10.
Human-in-the-loop
Designing the system so a person reviews or approves important steps, for example confirming before an agent sends an email or submits a form. See Chapter 10.
MCP (Model Context Protocol)
An open standard for connecting AI apps to tools and data sources. A tool exposed through an MCP server can be used by any MCP-compatible app, so you don't write a new integration for each one. See Chapter 11.

Production & safety

Guardrails
Checks around a model that block or fix unwanted inputs and outputs, such as off-topic requests, leaked secrets or unsafe content. They're usually ordinary code or a second model call. See Chapter 13.
Prompt injection
An attack where text the model reads (a user message, or a sentence hidden in an uploaded document or web page) contains instructions such as "ignore your rules and…", trying to take control of the model. See Chapter 13.
Jailbreak
A prompt crafted to trick a model into ignoring its safety rules or instructions, for example through role-play or elaborate scenarios. See Chapter 13.
PII (personal data)
Personally Identifiable Information: anything that identifies a person, such as a name, email, ID number, salary or health details. Keep it out of prompts, logs and knowledge bases unless it's truly needed. See Chapter 13.
Eval (evaluation)
A repeatable test for an AI feature: a set of inputs with expected results, plus a way to score the outputs. Re-run it whenever you change a prompt, model or retrieval setting. See Chapter 12.
LLM-as-judge
Using a model to grade another model's answers against criteria such as "is it correct and supported by the sources?". It scales better than human review, but its grades must themselves be checked against human judgement. See Chapter 12.
Ground truth
The known correct answer (or correct source document) for a test question, written or checked by a person. Evals compare the AI's output against it. See Chapter 12.
Latency
How long the user waits, for example from sending a question until the first words appear (time to first token) or until the answer is complete. Streaming makes latency feel shorter. See Chapter 14.
Rate limit
A cap on how many requests or tokens are allowed per minute. Providers apply one to your API key, and you should apply your own per user to prevent abuse and surprise bills. Going over it usually returns status 429. See Chapter 14.
Caching
Saving a result so it can be reused instead of computed again, for example storing a document's embeddings or the answer to a frequent question. Some providers also offer prompt caching for repeated prompt beginnings. See Chapter 14.
Observability
Recording what your AI app does (prompts, tool calls, timings, token usage, errors) so you can debug problems and spot trends in production. Step 22's onStepFinish logging is a first taste. See Chapter 14.
Cost control
Keeping AI spending predictable: choosing smaller models where they're good enough, limiting tokens and agent steps, caching, rate-limiting users and setting budget alerts with your provider. See Chapter 14.

Databases

Database / table / row / column
A database stores data permanently. A table is like a spreadsheet: each row is one item (one chunk) and each column is one field (id, content, embedding).
PostgreSQL (Postgres)
A popular, free database that you talk to in SQL.
Neon / serverless
A company that hosts Postgres for you in the cloud. Serverless means you don't manage a server: it scales up and down, even to zero, automatically.
SQL
The language for talking to databases: SELECT (read), INSERT (add), DELETE (remove), CREATE TABLE…
Connection string
A URL containing the database address, user name and password (postgresql://user:pass@host/db). It's a secret, so it goes in .env.local.
ORM / Drizzle
An Object-Relational Mapper lets you query the database with TypeScript instead of writing SQL strings, with types checked. Drizzle is the ORM used here.
Schema
The description of your tables: their names, columns and column types (src/lib/db-schema.ts).
Migration
A versioned SQL file that changes the database structure, such as creating a table. drizzle-kit generate writes one, and drizzle-kit migrate applies it.
Primary key / serial
A column that uniquely identifies each row. serial numbers rows automatically: 1, 2, 3…
Extension / pgvector
An add-on that teaches Postgres new tricks. pgvector adds the vector column type, distance operators and vector indexes.
Index / HNSW
A structure that makes searches fast without reading every row, like the index at the back of a book. HNSW is the kind used for vectors. See Indexing Explained.
EXPLAIN / query plan
Putting EXPLAIN before a query shows how Postgres will run it, for example whether it uses an index or scans the whole table.

Authentication

Authentication vs authorization
Authentication checks who you are (signing in). Authorization checks what you're allowed to do (only admins may upload).
Clerk
A service that handles sign-up, sign-in and user management, including the screens and emails, so you don't build them yourself.
Session / session token / JWT
After you sign in, the browser holds a session token, a signed piece of data (a JWT) that proves who you are on every request. Clerk can add your role to it.
RBAC / role
Role-Based Access Control: give each user a role (admin, user) and allow actions by role.
Public metadata
Extra data Clerk stores on a user. Your app can read public metadata, but only the server or dashboard can change it, which makes it safe for roles.
