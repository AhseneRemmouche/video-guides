Protecting Routes

Make every route except home and auth pages private.

▶ Watch this part (22:41)

Goal

Right now anyone can open /chat, which is a problem once it can answer from internal information. This step makes every route private except the home page and Clerk's sign-in and sign-up pages.

On the previous page you added authentication: users can sign in. But nothing requires them to. Here you add the rule "you must be signed in", and you put it in the middleware so it applies to every request in one place.

New to middleware? What happens to a request before your page runs

Every time the browser asks for a page or calls an API, it sends an HTTP request to the server. In a Next.js app, the journey of one request looks like this:

  1. The browser sends a request, for example GET /chat, along with its cookies (including Clerk's session cookie, if the user signed in).
  2. Middleware runs first. It can look at the URL, headers and cookies, and then do one of three things: let the request continue, redirect it somewhere else, or answer it directly (for example with an error).
  3. If the request continues, Next.js runs the matching page or route handler and sends the response back.

Think of middleware as a security guard at the building entrance: it checks everyone before they reach any room. Because it runs before everything, it's the right place for a rule that should apply to the whole app. Putting the check in each page separately would be easy to forget on a new page.

Step by step

  1. Import createRouteMatcher

    This Clerk helper builds a function that checks whether a request matches a list of route patterns.

  2. Define the public routes

    The home page / and the auth pages (/sign-in(.*), /sign-up(.*)) are public. Everything else needs authentication. The (.*) suffix also matches sub-paths Clerk uses during sign-in.

    New to route patterns? What (.*) means

    The patterns are written in a small pattern language based on regular expressions. Two symbols do the work:

    • . means "any single character".
    • * means "the thing before me, repeated zero or more times".

    So .* means "any characters, any number of them, including none", and the parentheses group it. Examples:

    PatternMatchesDoes not match
    // (only the home page)/chat, /upload
    /sign-in(.*)/sign-in, /sign-in/factor-one, /sign-in/sso-callback/chat
    /sign-up(.*)/sign-up, /sign-up/verify-email-address/sign-in

    Without (.*), only the exact path /sign-in would be public, and the extra steps of the sign-in flow (like email verification) would be blocked, trapping users in a loop.

  3. Pass a function to clerkMiddleware

    It is an async function that receives the auth object and the request (req).

  4. Protect everything that isn't public

    If the request is not a public route, call await auth.protect(). If the user isn't signed in, it automatically redirects them to the sign-in page.

    New to redirects? How the browser gets sent somewhere else

    A redirect is a response that says "what you asked for is at another address; go there instead". The server answers with a 3xx status code (such as 307) and a Location header holding the new URL. The browser follows it automatically, so the user just sees a different page load.

    Clerk adds a redirect_url parameter to the sign-in URL that remembers where you were going (/chat). After you sign in, Clerk reads it and sends you back there.

    For API requests (like useChat's POST to /api/chat), a redirect to a web page makes no sense, so auth.protect() answers with an error status instead of a redirect (the exact code depends on your Clerk version). Either way, the request never reaches your route handler, so a signed-out caller can't use your OpenAI key.

Complete file

import { clerkMiddleware, createRouteMatcher } from "@clerk/nextjs/server";

const isPublicRoute = createRouteMatcher(["/", "/sign-in(.*)", "/sign-up(.*)"]);

export default clerkMiddleware(async (auth, req) => {
  if (!isPublicRoute(req)) {
    await auth.protect();
  }
});

export const config = {
  matcher: [
    // Skip Next.js internals and all static files, unless found in search params
    "/((?!_next|[^?]*\\.(?:html?|css|js(?!on)|jpe?g|webp|png|gif|svg|ttf|woff2?|ico|csv|docx?|xlsx?|zip|webmanifest)).*)",
    // Always run for API routes
    "/(api|trpc)(.*)",
  ],
};

Why this pattern? Listing what is public and protecting everything else is secure by default. New pages you add later (like /upload) are private automatically, and /api/chat is protected too, so nobody can call your OpenAI-backed endpoint without signing in.

The opposite approach, listing the protected routes (for example createRouteMatcher(["/chat(.*)"])), also works, but every time you add a page you must remember to add it to the list. Forgetting once leaves that page open to everyone.

Test it

  1. Sign out and visit localhost:3000/chat

    You are redirected to Clerk's hosted "Sign in to RAG Chatbot" page. Its URL contains redirect_url=…/chat.

  2. Sign in

    After signing in, you return to /chat automatically.

How to know it worked: the home page / still opens while signed out, but /chat always sends you to sign in first. Once signed in, /chat opens and the chatbot answers as before.

Common mistakes:

  • Typos in the patterns: "/signin(.*)" instead of "/sign-in(.*)", or forgetting the leading /. The pattern then doesn't match and that page is protected by mistake.
  • Making the home page private: removing "/" from the list means signed-out visitors can't even see the landing page.
  • Testing while still signed in: you won't see any redirect. Sign out first, or use a private/incognito window.
  • Forgetting !: if (isPublicRoute(req)) protects only the public pages and leaves /chat open: the exact opposite of what you want.
