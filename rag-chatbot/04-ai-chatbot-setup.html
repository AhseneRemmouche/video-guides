Creating the AI Chatbot

Install the AI SDK, shadcn/ui and AI Elements; add the OpenAI key.

▶ Watch this part (03:33)

Goal

Before any RAG features, build a standard AI chatbot. The user types a prompt, the UI sends it to a route handler, the route handler calls OpenAI, and the response streams back to the UI. This step installs everything that needs.

In the diagram below, the left box is the page in the browser, the middle box is your server code (a route handler, written in step 5), and the right box is OpenAI's servers. The browser never talks to OpenAI directly: your server sits in between, because only the server is allowed to hold the secret API key. The answer comes back as streamed tokens, small pieces of text sent one after another.

New to installing packages? What npm install actually does

When you run npm install some-package inside your project folder, npm:

  1. downloads the package (and every package it depends on) from the public npm registry,
  2. puts the code into node_modules/,
  3. adds a line such as "ai": "^5.0.0" to the dependencies section of package.json, and
  4. records the exact versions in package-lock.json.

Because the list is saved in package.json, anyone who copies your project can run plain npm install (no names) to get the exact same packages. That's why node_modules itself is never shared.

Always run install commands in the project root, the folder that contains package.json. You can leave the dev server running in one terminal and use a second terminal for these commands.

Step by step

  1. Install the AI SDK packages 
    npm install ai @ai-sdk/openai @ai-sdk/react zod

    Line by line

    Line(s)CodeWhat it does & why
    1npm installDownload the listed packages into node_modules and save them as dependencies in package.json. You can list several packages in one command, separated by spaces.
    1aiThe core of the Vercel AI SDK. Its npm name really is just ai.
    1@ai-sdk/openaiThe @ai-sdk/ part is a scope: a namespace owned by one publisher, so you know it's the official package. openai is the package inside that scope.
    1@ai-sdk/reactAnother package from the same scope, for React.
    1zodA popular standalone validation library (Zod).
    PackageRole
    aiThe core AI SDK: streamText, embed, tool, message helpers.
    @ai-sdk/openaiThe provider that connects the SDK to OpenAI's models.
    @ai-sdk/reactReact hooks for chat interfaces, mainly useChat.
    zodType-safe schemas. Used later for the tool's input schema.

    In more detail:

    • ai gives you functions that work the same no matter which AI company you use. streamText asks a model for text and returns it piece by piece; embed turns text into an embedding; tool defines a function the model may call.
    • @ai-sdk/openai is a provider: an adapter that translates the SDK's generic calls into OpenAI's specific API. To switch to another company later you would mostly swap this package, not rewrite your code.
    • @ai-sdk/react contains useChat, a React hook that keeps the list of chat messages, sends new ones to your server and updates the screen as the streamed answer arrives. You use it in step 6.
    • zod lets you describe the shape of data ("an object with a query that is a string") and check real data against it. In step 15 it tells the model what input the search tool expects.

    What you should see: after a few seconds, a summary like "added 25 packages, and audited 400 packages" (numbers vary). Lines starting with npm warn are usually harmless. Lines starting with npm error mean something failed: read the message, it often says exactly why.

  2. Initialize shadcn/ui 
    npx shadcn@latest init

    When asked for a base color, choose Neutral. This creates components.json, src/lib/utils.ts and adds CSS variables to globals.css.

    Line by line

    Line(s)CodeWhat it does & why
    1npxRun a command-line tool once without adding it to your project's dependencies.
    1shadcn@latestThe shadcn/ui command-line tool, newest version.
    1initA sub-command meaning "set up shadcn/ui in this project". You run it once per project.
    New to shadcn/ui? Why it copies code into your project

    shadcn/ui is a collection of nicely designed, accessible interface components (buttons, cards, inputs, dialogs…). Unlike most libraries, you don't install it as a package you can't touch. Its CLI copies the source code of each component into your project, under src/components/ui/. The code is then yours: you can read it and change it.

    What init changes:

    • components.json (in the project root): a small settings file for the shadcn CLI. It records your choices (style, base colour, whether you use TypeScript and Tailwind) and where to put things, for example that components go into @/components/ui and helpers into @/lib/utils. Later add commands, and the AI Elements installer, read it.
    • src/lib/utils.ts: a helper called cn() that merges Tailwind class names cleanly (so p-2 and p-4 don't conflict). Every shadcn component uses it.
    • src/app/globals.css: adds CSS variables, named colours such as --background, --foreground, --primary and --border, with one set of values for light mode and one for dark mode. Components use these names instead of fixed colours, so the whole app's theme can be changed in one place. "Neutral" picks a grey palette for them.
    • It may also install a few small packages the components need (for example clsx and tailwind-merge for cn()).
  3. Add the shadcn/ui components 
    npx shadcn@latest add

    To keep it simple, select all components: press a to select all, then Enter. Later steps use Button, Card, Label, Input and Alert from these.

    Line by line

    Line(s)CodeWhat it does & why
    1npx shadcn@latestRun the same shadcn CLI again.
    1addThe sub-command that copies components into src/components/ui/. With no component names after it, it shows an interactive checklist. (You could also name them directly, e.g. npx shadcn@latest add button card.)

    In the checklist, Space ticks one item, a ticks all, Enter confirms. If it asks whether to overwrite an existing file, answering yes is fine on a fresh project. It may also ask about React 19 peer dependencies; choose the option it recommends (often Use --legacy-peer-deps).

    What you should see: a list of created files, and a src/components/ui/ folder containing files such as button.tsx, card.tsx and input.tsx.

  4. Add AI Elements 
    npx ai-elements@latest

    AI Elements is a library of pre-built components made for AI apps: conversation, message, prompt input, loader, response and more.

    Line by line

    Line(s)CodeWhat it does & why
    1npxRun a tool once.
    1ai-elements@latestThe AI Elements installer, newest version. With no extra arguments it installs all of its components. It works on top of shadcn/ui (it reads your components.json), which is why shadcn had to be initialised first.

    Like shadcn/ui, AI Elements copies source files into your project, this time into src/components/ai-elements/. These components already know how to display chat messages, a scrolling conversation, a prompt box with a submit button, a "thinking" loader and formatted (Markdown) answers, so you don't have to build a chat interface from scratch.

  5. Check the components folder
    src/components/ ├── ai-elements/ ← AI-specific components (conversation, message, prompt-input, loader, response…) └── ui/ ← shadcn/ui components (button, card, input, label, alert…)

    Common mistake: if these folders appear somewhere else, for example in components/ at the project root instead of src/components/, the commands were probably run before choosing the src/ directory, or in the wrong folder. Imports like @/components/ui/button only work when the files are under src/.

  6. Add your OpenAI API key

    In the project root (next to package.json), create .env.local:

    OPENAI_API_KEY=sk-...your-real-key...

    @ai-sdk/openai reads OPENAI_API_KEY automatically, so no code is needed to wire it up. The presenter did this step off-camera. Use your own key.

    .env.local is already in the default .gitignore. Never commit API keys.

    Line by line

    Line(s)CodeWhat it does & why
    1OPENAI_API_KEY=sk-...your-real-key...Defines an environment variable named OPENAI_API_KEY. Left of = is the name (by convention UPPER_CASE with underscores), right of it is the value: paste your whole key, starting with sk-. No spaces around = and no quotes are needed. This exact name matters: it is the one @ai-sdk/openai looks for.
    New to environment variables? Why secrets live in .env.local

    An environment variable is a named setting given to a program from outside its code. Server code reads it as process.env.OPENAI_API_KEY.

    Why not just write the key in your code? Because code gets shared: pushed to GitHub, sent to colleagues, shown on screen. Anyone who sees the key can spend your money. Keeping it in a separate file that Git ignores means the code can be shared safely while the key stays on your machine. On a hosting service such as Vercel, you enter the same variables in its dashboard instead.

    Next.js loads .env.local automatically when the dev server starts. Variables are available only in server code unless their name starts with NEXT_PUBLIC_, which exposes them to the browser. That is why the OpenAI key must never get that prefix.

    Common mistakes

    • Wrong place: the file must be in the project root, not in src/ or src/app/.
    • Wrong name: exactly .env.local, with the leading dot. On Windows, make sure the editor didn't save it as .env.local.txt (turn on "File name extensions" in Explorer to check).
    • Not restarting: environment files are read only when the dev server starts. After creating or editing .env.local, stop the server with Ctrl+C and run npm run dev again. Otherwise the key is "missing" even though the file is correct.
    • Typos: extra spaces, quotes copied from a web page, or a cut-off key cause "Incorrect API key provided" errors later.

Build fix the repo is missing: AI Elements' code-block.tsx imports react-syntax-highlighter, which ships without TypeScript types. npm run dev works, but npm run build fails with "Could not find a declaration file for module 'react-syntax-highlighter'". The GitHub repo has this problem too: its build fails as cloned. Fix it once:

npm install -D @types/react-syntax-highlighter

Line by line

Line(s)CodeWhat it does & why
1npm installInstall a package, as before.
1-DShort for --save-dev. Saves the package under devDependencies instead of dependencies: it is needed only while developing and building, not by the running app. See dev dependency.
1@types/react-syntax-highlighterThe @types scope holds community-written TypeScript type descriptions for libraries written in plain JavaScript. This one tells TypeScript what react-syntax-highlighter exports, which is exactly what the build error complained was missing.

Why does dev work but build fail? The dev server skips full type checking to stay fast; npm run build (the production build) checks every file's types and stops at the first error.

Version note: AI Elements changes quickly. The video's version had Response and PromptInputToolbar components. In newer releases these are called MessageResponse and PromptInputFooter. If an import in step 6 fails, open src/components/ai-elements/ and use the names your version exports.
