Build an eval set and a baseline

Write 20 test questions, score a bot that knows nothing about the shop, and get the number to beat.

Lab · code run on a local model (llama3.2 via Ollama)

So far you have called a model and looked at what it says. From now on you will change the bot many times: add documents, rewrite prompts, add guardrails. Before any of that you need a way to tell whether a change made things better or worse. This lab builds that tool: 20 test questions with their expected answers, a small program that asks the bot every question and scores the answers, and a first score to beat.

Goal of this lab. Write an eval set of 20 questions in a JSONL file, run a bot that knows nothing about the shop on it, and get its baseline score with a cheap keyword check. Then look closely at where that check is wrong.

The idea in brief

An eval set is a fixed list of inputs, each with a way to decide whether the output is good. You write it once and run it after every change. The number it produces (here: the share of answers that pass) is your metric. Without it, "the new prompt seems better" is just a feeling based on the three questions you happened to try.

A baseline is the score of the simplest version of the system. Here it is llama3.2 with a one-line role prompt and no documents at all, so it can only answer from what it learned in training. It knows nothing about Trailhead Bikes, so it will guess. That is the point: the baseline shows how much the later work (retrieval in lab 06, grounded answers in lab 07) actually adds.

The scoring here is the cheapest kind: a keyword check, a relaxed form of exact match. It is fast and free, and it is often wrong. In this lab you will find four of its mistakes by reading the answers, and in lab 05 you will replace it with something smarter. For the theory behind all of this, read the concept chapters Evaluation methods and Evaluating AI systems.

New to eval sets? Why write tests before improving anything

Programmers write tests so they can change code without fear: if a test turns red, the change broke something. An eval set plays the same role for an AI system, with two differences. First, the output is free text, so "pass" needs a rule that tolerates different wording. Second, the model is random and imperfect, so you do not expect 100 %; you watch the score go up or down.

Write the eval set before improving the bot, for two reasons. You cannot measure progress without a starting number. And if you write the questions after tuning the bot, you will (without meaning to) pick questions the bot already handles well.

A good eval set covers the things users really ask, includes a few hard or tricky cases, and includes questions the bot should refuse. Twenty questions is tiny (real projects use hundreds), but it is enough to see the method and it keeps each run to a few minutes on a laptop.

Step 1: the eval set, evals/qa.jsonl

Each line is one test case. Every question was written from one of the 8 shop documents in data/docs/, and the expected keywords come straight from that document (for example, returns.md says "within 30 days", so q01 expects 30).

New to JSONL? One JSON object per line

JSONL ("JSON Lines") is a text file where every line is a complete JSON object. It is not one big JSON array, so there is no [ at the start and no comma between lines. That makes it easy to append one row, to read a huge file line by line, and to see in a diff exactly which case changed. Eval sets, run logs and training data are very often stored this way.

JSON writes "nothing" as null and booleans as true/false (lower case). When Python reads them with json.loads they become None, True and False.When TypeScript reads them with JSON.parse they stay null, true and false: JSON was born from JavaScript, so the words are the same.

Step 2: reading and writing JSONL, aie/evalset.pysrc/evalset.ts

"""Read and write the JSONL files used for evaluation."""
import json

from aie.config import EVALS


def load_jsonl(path):
    with open(path, encoding="utf-8") as f:
        return [json.loads(line) for line in f if line.strip()]


def save_jsonl(path, rows):
    path.parent.mkdir(parents=True, exist_ok=True)
    with open(path, "w", encoding="utf-8", newline="\n") as f:
        for row in rows:
            f.write(json.dumps(row, ensure_ascii=False) + "\n")


def load_qa():
    return load_jsonl(EVALS / "qa.jsonl")
// Read and write the JSONL files used for evaluation.
import { mkdirSync, readFileSync, writeFileSync } from "node:fs";
import path from "node:path";
import { EVALS } from "./config.js";

export interface Question {
  id: string;
  question: string;
  must_include: string[];
  source: string | null;
  answerable: boolean;
}

export function loadJsonl<T = Record<string, unknown>>(file: string): T[] {
  return readFileSync(file, "utf8")
    .split("\n")
    .filter((line) => line.trim())
    .map((line) => JSON.parse(line) as T);
}

export function saveJsonl(file: string, rows: unknown[]): void {
  mkdirSync(path.dirname(file), { recursive: true });
  writeFileSync(file, rows.map((row) => JSON.stringify(row) + "\n").join(""), "utf8");
}

export function loadQa(): Question[] {
  return loadJsonl<Question>(path.join(EVALS, "qa.jsonl"));
}

Step 3: running and scoring, aie/evaluate.pysrc/evaluate.ts

This module does three jobs: decide whether one answer passes (keyword_passkeywordPass), run a whole question set and save every answer (run), and turn a run into a few numbers (summary). Later labs reuse it unchanged with better bots.

"""Run a question set through an answer function and score it with cheap, exact checks."""
from aie.config import RUNS
from aie.evalset import load_jsonl, save_jsonl

REFUSALS = ("i don't know", "i do not know", "don't have information", "not able to find", "no information")


def is_refusal(text):
    return any(r in text.lower().replace("’", "'") for r in REFUSALS)


def keyword_pass(question, answer):
    """Answerable: every must_include string appears. Unanswerable: the answer says it doesn't know."""
    if not question["answerable"]:
        return is_refusal(answer)
    return all(word.lower() in answer.lower() for word in question["must_include"])


def run(name, questions, answer_fn):
    """answer_fn(question_text) -> {"answer": str, "chunks": [...], "reply": Reply}. Saves runs/<name>.jsonl."""
    rows = []
    for q in questions:
        out = answer_fn(q["question"])
        reply = out["reply"]
        rows.append({
            "id": q["id"], "question": q["question"], "answer": out["answer"], "chunks": out.get("chunks", []),
            "keyword_pass": keyword_pass(q, out["answer"]),
            "input_tokens": reply.input_tokens, "output_tokens": reply.output_tokens, "seconds": round(reply.seconds, 2),
        })
    save_jsonl(RUNS / f"{name}.jsonl", rows)
    return rows


def load_run(name):
    return load_jsonl(RUNS / f"{name}.jsonl")


def summary(rows):
    n = len(rows)
    return {
        "cases": n,
        "keyword_pass": sum(r["keyword_pass"] for r in rows) / n,
        "avg_seconds": sum(r["seconds"] for r in rows) / n,
        "avg_input_tokens": sum(r["input_tokens"] for r in rows) / n,
    }
// Run a question set through an answer function and score it with cheap, exact checks.
import path from "node:path";
import { RUNS } from "./config.js";
import { loadJsonl, saveJsonl, type Question } from "./evalset.js";
import type { Answer } from "./rag.js";

const REFUSALS = ["i don't know", "i do not know", "don't have information", "not able to find", "no information"];

export function isRefusal(text: string): boolean {
  const t = text.toLowerCase().replaceAll("’", "'");
  return REFUSALS.some((r) => t.includes(r));
}

/** Answerable: every must_include string appears. Unanswerable: the answer says it doesn't know. */
export function keywordPass(question: Pick<Question, "answerable" | "must_include">, answer: string): boolean {
  if (!question.answerable) return isRefusal(answer);
  return question.must_include.every((word) => answer.toLowerCase().includes(word.toLowerCase()));
}

export interface Row {
  id: string;
  question: string;
  answer: string;
  chunks: string[];
  keyword_pass: boolean;
  input_tokens: number;
  output_tokens: number;
  seconds: number;
}

/** Answer every question, one after another, and save runs/<name>.jsonl. */
export async function run(name: string, questions: Question[], answerFn: (q: string) => Promise<Answer>): Promise<Row[]> {
  const rows: Row[] = [];
  for (const q of questions) {
    const out = await answerFn(q.question);
    const reply = out.reply;
    rows.push({
      id: q.id, question: q.question, answer: out.answer, chunks: out.chunks,
      keyword_pass: keywordPass(q, out.answer),
      input_tokens: reply.inputTokens, output_tokens: reply.outputTokens, seconds: Math.round(reply.seconds * 100) / 100,
    });
  }
  saveJsonl(path.join(RUNS, `${name}.jsonl`), rows);
  return rows;
}

export function loadRun(name: string): Row[] {
  return loadJsonl<Row>(path.join(RUNS, `${name}.jsonl`));
}

export function summary(rows: Row[]) {
  const n = rows.length;
  const avg = (f: (r: Row) => number) => rows.reduce((sum, r) => sum + f(r), 0) / n;
  return {
    cases: n,
    keyword_pass: avg((r) => Number(r.keyword_pass)),
    avg_seconds: avg((r) => r.seconds),
    avg_input_tokens: avg((r) => r.input_tokens),
  };
}

Step 5: answering one question, aie/rag.pysrc/rag.ts

This is the function the bot uses for every answer, now and in later labs. It has an optional retriever. With retriever=Noneno retriever (undefined) (this lab), no documents are searched and the model answers from memory, meaning from whatever it learned in training. The full RAG path, where a retriever finds relevant chunks and puts them into the prompt, is used from lab 07 on.

"""Answer a question with or without retrieved context."""
from aie.config import PROMPTS
from aie.llm import chat


def load_prompt(name):
    return (PROMPTS / f"{name}.txt").read_text(encoding="utf-8")


def format_context(results):
    return "\n\n".join(f"[{chunk.id}]\n{chunk.text}" for chunk, _ in results)


def answer(question, retriever=None, prompt="rag_v2", k=3, model=None):
    """Return {"answer", "chunks", "reply"}. Without a retriever, the model answers from memory."""
    results = retriever.search(question, k=k) if retriever else []
    system = load_prompt(prompt).format(context=format_context(results)) if retriever else load_prompt(prompt)
    reply = chat([{"role": "system", "content": system}, {"role": "user", "content": question}], model=model, temperature=0)
    return {"answer": reply.text, "chunks": [chunk.id for chunk, _ in results], "reply": reply}
// Answer a question with or without retrieved context.
import { readFileSync } from "node:fs";
import path from "node:path";
import { PROMPTS } from "./config.js";
import { chat, type Reply } from "./llm.js";
import type { Result, Retriever } from "./retrieve.js";

export function loadPrompt(name: string): string {
  return readFileSync(path.join(PROMPTS, `${name}.txt`), "utf8").replaceAll("\r\n", "\n");
}

export function formatContext(results: Result[]): string {
  return results.map(([chunk]) => `[${chunk.id}]\n${chunk.text}`).join("\n\n");
}

export interface Answer {
  answer: string;
  chunks: string[];
  reply: Reply;
}

/** Without a retriever, the model answers from memory. */
export async function answer(question: string, retriever?: Retriever, prompt = "rag_v2", k = 3, model?: string): Promise<Answer> {
  const results = retriever ? await retriever.search(question, k) : [];
  const template = loadPrompt(prompt);
  const system = retriever ? template.replace("{context}", formatContext(results)) : template;
  const reply = await chat([{ role: "system", content: system }, { role: "user", content: question }], model, { temperature: 0 });
  return { answer: reply.text, chunks: results.map(([chunk]) => chunk.id), reply };
}

Read the scores: where the keyword check is wrong

Now check the check. Take each PASS and fail and ask: would a person who knows the documents agree? Four of the 20 verdicts in our run are wrong:

  • q08 is a false pass. The bot says it delivers to Switzerland, which is wrong. It passes because the keyword not appears inside another word: the full answer (only its start is printed) contains "note". A substring test cannot tell "not" from "note".
  • q13 is a false pass. The bot recommends a 17" frame "for riders between 165-175 cm"an 18" frame, which is wrong for 178 cm (the shop uses S/M/L/XL; 178 cm is L). It passes because the keyword L, after lower-casing, is just the letter "l", found in nearly any sentence.
  • q07 is a false fail. "we do not offer express delivery for complete bikes" is correct, but the check wants the exact phrase not available. (In the TypeScript run this one did not happen: the bot claimed express delivery is offered, so the fail was right. That run has three wrong verdicts, not four.)
  • q19 is a false fail. "I couldn't find any information on a CEO for Trailhead Bikes" is the right behaviour: it declines instead of inventing a name. But "couldn't find any information" matches none of the REFUSALS phrases.

Two errors push the score up and two push it down, so 30 % happens to be close to the truth here.In the TypeScript run two errors push the score up and one pushes it down, so 30 % is a little too high. Common mistakes.
  • ModuleNotFoundError: No module named 'aie': you ran python labs/04_baseline_eval.py or started from another folder. Run uv run python -m labs.04_baseline_eval from the project root.
  • json.decoder.JSONDecodeError when loading qa.jsonl: a line is not valid JSON. Typical causes: a trailing comma, single quotes instead of double quotes, True instead of true, or one object split over several lines.
  • FileNotFoundError: ... prompts\baseline.txt: the file is missing or named baseline.txt.txt (Windows hides extensions by default).
  • A SyntaxError from JSON.parse when loading qa.jsonl: a line is not valid JSON. Typical causes: a trailing comma, single quotes instead of double quotes, or one object split over several lines.
  • ENOENT: no such file or directory for prompts\baseline.txt: the file is missing or named baseline.txt.txt (Windows hides extensions by default).
  • Forgetting await in front of run(...). Then rows is a Promise, not a list, and the for loop fails with "rows is not iterable".
  • Connection error: Ollama is not running, or llama3.2 was not pulled (lab 01).
  • Believing the 30 %. Always read a sample of PASS and fail answers before trusting any score, as you did above.
  • Adding the expected answer to the prompt "to help". The bot must never see must_include; otherwise you are testing your test, not your bot.

Recap
  • An eval set is a fixed list of questions plus an answer key; you write it before improving the bot and run it after every change.
  • qa.jsonl has 18 answerable questions over all 8 documents and 2 unanswerable ones that test whether the bot declines instead of inventing.
  • The baseline (llama3.2, role prompt, no retriever) answers from memory and scored 30 % with the keyword check in our run, in Python and in TypeScript.
  • It invented a 5-year frame warranty, dollar prices and delivery to Switzerland: confident hallucinations.
  • The keyword check is cheap but wrong in both directions: false passes (q08 "note", q13 "l") and false fails (q07 wording, q19 polite refusal).
  • runs/baseline.jsonl keeps every full answer, token count and time, so runs can be re-read, re-scored and compared later.
