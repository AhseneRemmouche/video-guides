Set up the lab and call a model

Install Ollama and uv, create the project, and make your first call through one small wrapper that records tokens and time.

Lab · code run on a local model (llama3.2 via Ollama)
Goal of this lab. Install the tools the labs need (Ollama and uvNode.js with pnpm), download three free local models, create the project folder, and send your first question to a model through one small PythonTypeScript wrapper that also tells you what the call cost: how many tokens went in and out, and how many seconds it took. Every later lab reuses this wrapper.

This is the "hello world" of AI engineering. It looks small, but it sets up three habits you keep for the whole course: you talk to models through one function, settings live outside the code, and every call is measured.

Every lab exists in Python and in TypeScript. Pick your language with the switch at the top of the page (or on any code block); the code, the commands, the line-by-line tables and the outputs follow your choice, and it is remembered on the other pages. The two projects do the same things with the same data: trailhead-ai (Python) and trailhead-ai-ts (TypeScript). Neither uses a framework: both call the model with the official openai package and a little code of our own.

The idea in brief

A large language model is a program that continues text. You send it a list of messages, it sends back the next message. Running the model is called inference. You don't need to train anything: you use a ready-made foundation model and build an application around it. That "building around it" (prompts, evaluation, retrieval, safety, cost) is what AI engineering means. The concept chapter What is AI engineering? explains this in more depth; it pairs with chapter 1 of the book, Introduction to Building AI Applications with Foundation Models.

In these labs the model runs on your own computer with Ollama. Ollama offers an OpenAI-compatible API, so we use the official openai package (the Python versionthe JavaScript / TypeScript version, installed with pnpm) to talk to it. The same code can later talk to OpenAI's servers by changing two settings, without touching a single line of code.

New to Ollama? What it is and why it matters

Ollama is a free program that downloads open-weight models and runs them on your machine. After installing it, a small server runs in the background and listens on http://localhost:11434. You talk to it with the ollama command (to download and list models) or over HTTP (from code). Because it copies the shape of OpenAI's API under the path /v1, any tool written for OpenAI can use it by changing the address.

Local models are smaller and slower than the big cloud models, but they are perfect for learning: you can call them thousands of times for free, and nothing you type leaves your computer.

New to uv? What it is and why it matters

uv is a fast tool that manages Python projects. It installs the right Python version, creates a virtual environment (a private folder .venv with the packages of this project only), records the exact package versions in uv.lock, and runs commands inside that environment with uv run. You never need to "activate" anything: uv run python ... always uses the project's environment.

New to Node.js, pnpm and tsx? The three tools behind every command

Node.js runs JavaScript outside the browser: here, our lab scripts. pnpm is a package manager, like npm but faster and stricter: pnpm install reads package.json (what the project needs) and pnpm-lock.yaml (the exact versions we tested) and puts the packages into a node_modules folder inside the project, for this project only. Node.js cannot run our .ts files as they are, so the labs are started with tsx, a small tool that removes the types and runs the file straight away, with no build step. pnpm lab 01 is a shortcut defined in package.json that does exactly that.

New to TypeScript? JavaScript with types

TypeScript is JavaScript plus type annotations such as model?: string ("an optional text"). The types are checked by the TypeScript compiler (pnpm typecheck), never while the program runs: tsx removes them and runs plain JavaScript. So a type mistake does not stop pnpm lab 01 from running; run pnpm typecheck to catch it. A call to the model takes time, so it returns a Promise (a value that arrives later), and you write await in front of the call to wait for it (see async / await).

Actions

  1. Install Ollama from ollama.com/download (Windows, macOS or Linux). Open a new terminal and check it works with ollama --version. We used Ollama 0.35.1.
  2. Install uv by following docs.astral.sh/uv (one command for your system). Check with uv --version. We used uv 0.11.7.
  3. Download the three models (this takes a while the first time): 
    ollama pull llama3.2
ollama pull gemma4
ollama pull nomic-embed-text
ollama list
    llama3.2 (2.0 GB) is the app model that answers customers. gemma4 is larger and much slower; it is used as a judge from lab 05 on. nomic-embed-text (274 MB) turns text into vectors for retrieval in lab 06. ollama list should show all three.
  4. Create the project in a new, empty folder called trailhead-ai: 
    uv init --python 3.12 --name trailhead-ai --bare
uv add openai pydantic numpy
uv add --dev pytest
  5. Add the pytest setting: open pyproject.toml and add the last two lines shown in the complete file below ([tool.pytest.ini_options]). It is used by the tests, not by this lab.
  6. Create the folders aie, labs, data/docs, evals, prompts, runs and tests.
  7. Create the files of this lab: .env.example, aie/__init__.py (empty), aie/config.py, aie/llm.py and labs/01_hello.py. Each one is shown in full below.
  8. Copy the eight shop documents into data/docs/ (from the full project, see below). This lab doesn't read them yet; lab 04 onwards does.
  9. Run the lab from the project folder: uv run python -m labs.01_hello.

Create aie/__init__.py as an empty file. Its presence tells Python that the folder aie is a package you can import from (from aie import config).

TypeScript needs no package marker file like Python's aie/__init__.py: every .ts file is a module on its own, and a lab imports what it needs by file path, for example import { chat } from "../src/llm.js".

"""Settings read from environment variables, with defaults for a local Ollama server."""
import os
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent
DATA = ROOT / "data"
EVALS = ROOT / "evals"
PROMPTS = ROOT / "prompts"
RUNS = ROOT / "runs"


def _load_dotenv():
    env = ROOT / ".env"
    if not env.exists():
        return
    for line in env.read_text(encoding="utf-8").splitlines():
        line = line.strip()
        if line and not line.startswith("#") and "=" in line:
            key, value = line.split("=", 1)
            os.environ.setdefault(key.strip(), value.strip())


_load_dotenv()

BASE_URL = os.environ.get("AIE_BASE_URL", "http://localhost:11434/v1")
API_KEY = os.environ.get("AIE_API_KEY", "ollama")

The wrapper: aie/llm.pysrc/llm.ts

Every lab talks to models through this one file. Keeping all calls in one place means that measuring tokens and time, switching servers, or adding a retry happens once, for every lab at the same time.

"""One small wrapper around an OpenAI-compatible API (Ollama locally, or OpenAI).

Every call returns the text plus what it cost: tokens and seconds. Later labs log these numbers.
"""
import json
import time
from dataclasses import dataclass

from openai import OpenAI
from pydantic import BaseModel, ValidationError

from aie import config

client = OpenAI(base_url=config.BASE_URL, api_key=config.API_KEY)


@dataclass
class Reply:
    text: str
    model: str
    input_tokens: int
    output_tokens: int
    seconds: float


def chat(messages, model=None, **params):
    """Send a list of {"role", "content"} messages and return a Reply."""
    if isinstance(messages, str):
        messages = [{"role": "user", "content": messages}]
    if config.REASONING_EFFORT and "reasoning_effort" not in params:
        params["reasoning_effort"] = config.REASONING_EFFORT
    start = time.perf_counter()
    response = client.chat.completions.create(model=model or config.MODEL, messages=messages, **params)
    usage = response.usage
    return Reply(
        text=response.choices[0].message.content or "",
        model=response.model,
        input_tokens=usage.prompt_tokens if usage else 0,
        output_tokens=usage.completion_tokens if usage else 0,
        seconds=time.perf_counter() - start,
    )


def chat_json(messages, schema: type[BaseModel], model=None, retries=2, **params):
    """Ask for JSON that matches a Pydantic model; validate it and retry with the error if it doesn't."""
    if isinstance(messages, str):
        messages = [{"role": "user", "content": messages}]
    messages = list(messages)
    response_format = {
        "type": "json_schema",
        "json_schema": {"name": schema.__name__, "schema": schema.model_json_schema()},
    }
    for attempt in range(retries + 1):
        reply = chat(messages, model=model, response_format=response_format, **params)
        try:
            return schema.model_validate_json(reply.text)
        except ValidationError as error:
            if attempt == retries:
                raise
            messages += [
                {"role": "assistant", "content": reply.text},
                {"role": "user", "content": f"That JSON was invalid: {error.errors()[:3]}. Reply with corrected JSON only."},
            ]


def embed(texts, model=None):
    """Return one embedding vector (a list of floats) per input text."""
    response = client.embeddings.create(model=model or config.EMBED_MODEL, input=list(texts))
    return [item.embedding for item in response.data]


def to_json(obj):
    return json.dumps(obj, ensure_ascii=False, indent=2)
// One small wrapper around an OpenAI-compatible API (Ollama locally, or OpenAI).
//
// Every call returns the text plus what it cost: tokens and seconds. Later labs log these numbers.
import OpenAI from "openai";
import type { ChatCompletionCreateParamsNonStreaming, ChatCompletionMessageParam } from "openai/resources/chat/completions";
import { z } from "zod";
import * as config from "./config.js";

export const client = new OpenAI({ baseURL: config.BASE_URL, apiKey: config.API_KEY });

export type Message = ChatCompletionMessageParam;
export type Params = Partial<Omit<ChatCompletionCreateParamsNonStreaming, "messages" | "model">>;

export interface Reply {
  text: string;
  model: string;
  inputTokens: number;
  outputTokens: number;
  seconds: number;
}

/** Send a list of {role, content} messages (or one string) and return a Reply. */
export async function chat(messages: Message[] | string, model?: string, params: Params = {}): Promise<Reply> {
  if (typeof messages === "string") messages = [{ role: "user", content: messages }];
  if (config.REASONING_EFFORT && !("reasoning_effort" in params)) {
    params = { ...params, reasoning_effort: config.REASONING_EFFORT };
  }
  const start = performance.now();
  const response = await client.chat.completions.create({ model: model ?? config.MODEL, messages, ...params });
  return {
    text: response.choices[0]?.message.content ?? "",
    model: response.model,
    inputTokens: response.usage?.prompt_tokens ?? 0,
    outputTokens: response.usage?.completion_tokens ?? 0,
    seconds: (performance.now() - start) / 1000,
  };
}

/** Ask for JSON that matches a Zod schema; validate it and retry with the error if it doesn't. */
export async function chatJson<S extends z.ZodType>(
  messages: Message[] | string,
  schema: S,
  name: string,
  model?: string,
  params: Params = {},
  retries = 2,
): Promise<z.infer<S>> {
  messages = typeof messages === "string" ? [{ role: "user", content: messages }] : [...messages];
  const response_format = {
    type: "json_schema" as const,
    json_schema: { name, schema: z.toJSONSchema(schema) as Record<string, unknown> },
  };
  for (let attempt = 0; ; attempt++) {
    const reply = await chat(messages, model, { ...params, response_format });
    let data: unknown;
    try {
      data = JSON.parse(reply.text);
    } catch {
      data = undefined; // not JSON at all: safeParse below reports it
    }
    const result = schema.safeParse(data);
    if (result.success) return result.data;
    if (attempt === retries) throw result.error;
    messages.push(
      { role: "assistant", content: reply.text },
      {
        role: "user",
        content: `That JSON was invalid: ${JSON.stringify(result.error.issues.slice(0, 3))}. Reply with corrected JSON only.`,
      },
    );
  }
}

/** Return one embedding vector (an array of numbers) per input text. */
export async function embed(texts: string[], model?: string): Promise<number[][]> {
  const response = await client.embeddings.create({ model: model ?? config.EMBED_MODEL, input: texts });
  return response.data.map((item) => item.embedding);
}

New to messages and roles? What they are and why they matter

Chat models don't receive one long string; they receive a list of messages, each with a role. A system prompt ("system") sets the rules for the whole conversation. "user" messages are what the person typed. "assistant" messages are earlier answers of the model. The server turns the list into one sequence of tokens using the model's chat template, which is why even a short question costs a few dozen input tokens.

Common mistakes.
  • Running the file path (uv run python labs/01_hello.py) gives ModuleNotFoundError: No module named 'aie'. Use -m labs.01_hello from the project folder.
  • Ollama is not running (or a wrong AIE_BASE_URL): the script prints the server line, then fails after a few retries with openai.APIConnectionError: Connection error.a connection error from the openai package. Start the Ollama app, or run ollama serve in another terminal.
  • The model is not downloaded or its name is misspelled: we got openai.NotFoundError: Error code: 404 - {'error': {'message': "model 'llama9' not found", ...}}the server answers with a 404 error saying the model was not found. Check ollama list and ollama pull the model.
  • Running from the wrong folder: uv run and -m both depend on the folder you are in. cd into trailhead-ai first.
  • Running from the wrong folder: pnpm lab needs the project's package.json, and .env is read from the folder you are in. cd into trailhead-ai-ts first.
  • Forgetting aie/__init__.py: create it, even though it is empty.
  • Forgetting pnpm install: without node_modules there is no tsx and no openai package, so nothing runs. Run it once after creating or downloading the project.
  • An old Node.js: check node --version; the project needs 22.13 or newer.

Switching to OpenAI (optional)

Because the code only knows "an OpenAI-compatible server", moving to OpenAI's hosted models is a settings change. Copy .env.example to .env, then replace the first block of settings with the commented OpenAI block and put your own key in AIE_API_KEY. The model names in the file (gpt-5-mini, gpt-5, text-embedding-3-small) were current at the time of writing; check OpenAI's documentation for today's names and prices. We did not run the labs against OpenAI (we had no key), so the outputs on these pages all come from the local models. A hosted model costs money per token, which is exactly why the wrapper reports tokens. Never commit .env: it holds your secret key, and the project's .gitignore already excludes it.

Recap
  • Ollama runs free local models and speaks the OpenAI API at http://localhost:11434/v1.
  • uv creates the project, the virtual environment and the lock file; uv run runs inside it.
  • pnpm installs the exact library versions from package.json and pnpm-lock.yaml into node_modules; tsx runs the .ts files without a build step.
