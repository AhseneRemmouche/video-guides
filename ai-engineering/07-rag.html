RAG answers with citations

Answer from retrieved chunks with a grounded prompt and compare the score with the baseline.

Lab · code run on a local model (llama3.2 via Ollama)

In lab 06 you built a retriever that finds the right document for 17 of 18 questions. Now the bot uses it: for every question it retrieves 3 chunks, pastes them into a prompt with strict rules, and answers with citations like [returns#0]. Then you score it on the same 20 questions as the baseline of lab 04.

Goal. Answer the eval set with retrieval-augmented generation (hybrid retriever + the rag_v2 prompt), compare with the baseline, and read every failure to find out which part failed.

The idea in brief

RAG = retrieve, then generate. The model doesn't have to remember the shop's policies: it reads them in the prompt. The answer is grounded in text you can check, and the citation tells you which chunk it used. The concept chapters RAG and agents and Evaluating AI systems cover the ideas; this lab gives you the numbers.

A RAG answer can fail in three different places, and the fix is different for each:

  • Retrieval: the right chunk was not in the top 3. Fix the retriever (lab 06).
  • Generation: the right chunk was there, but the model ignored it, misread it, or gave only half of it. Fix the prompt or the model.
  • Evaluation: the answer was judged wrongly. Fix the metric.

Step 2: the retriever branch of aie/rag.py

You created aie/rag.py in lab 04, where it was always called without a retriever. These are the lines that matter now.

def format_context(results):
    return "\n\n".join(f"[{chunk.id}]\n{chunk.text}" for chunk, _ in results)
def answer(question, retriever=None, prompt="rag_v2", k=3, model=None):
    """Return {"answer", "chunks", "reply"}. Without a retriever, the model answers from memory."""
    results = retriever.search(question, k=k) if retriever else []
    system = load_prompt(prompt).format(context=format_context(results)) if retriever else load_prompt(prompt)
    reply = chat([{"role": "system", "content": system}, {"role": "user", "content": question}], model=model, temperature=0)
    return {"answer": reply.text, "chunks": [chunk.id for chunk, _ in results], "reply": reply}

New to grounding and citations? Why ask for chunk ids?

A citation turns "trust me" into "check me". If the bot says "Return shipping is free for orders over 100 EUR [returns#2]", a support agent (or a script) can open returns#2 and verify. Citations also help you debug: when an answer is wrong, the cited id tells you whether the model read the wrong chunk or misread the right one. But a citation is a claim, not a proof: in our run, q19 answered "I don't know" and still cited [service-plans#0]. Lab 10 adds an output check that blocks answers without citations.

Step 3: the evaluation script

"""Lab 07: the same 20 questions, now answered from retrieved chunks. Compare with the baseline."""
from aie import rag
from aie.docs import load_chunks
from aie.evalset import load_qa
from aie.evaluate import load_run, run, summary
from aie.retrieve import Hybrid

retriever = Hybrid(load_chunks())
rows = run("rag_v2", load_qa(), lambda q: rag.answer(q, retriever, prompt="rag_v2"))

for r in rows:
    mark = "PASS" if r["keyword_pass"] else "fail"
    print(f"{mark}  {r['id']}  {r['answer'][:120]!r}")

print("\nbaseline:", summary(load_run("baseline")))
print("rag_v2:  ", summary(rows))

What you should see. 20 lines of PASS/fail, most answers ending with a citation such as [shipping#0], then two summaries. In our run the keyword pass rate went from 0.3 (30 %) to 0.8 (80 %). Your exact answers will differ (another machine, another model version), but the jump should be large.

The cost trade-off

Every answer now carries three chunks: about 372 input tokens on average instead of 63. With a paid API, input tokens are billed, so this bot reads roughly six times more per question. The answers were not slower here (5.8 s against 8.8 s). Reading a prompt is fast compared with generating text one token at a time, and the rag_v2 answers are short (rule 3), while most baseline answers in lab 04 ran past the 110 characters it printed; on your machine the timings will differ. If cost matters, the levers are fewer or smaller chunks (lab 06's experiments) and caching (lab 11).

New to false passes? Why 80 % is not "80 % correct"

The keyword check from lab 04 is cheap and repeatable, but it only tests whether some words appear. q02 shows how it can say "pass" for an answer that means the opposite. It can also say "fail" for a reasonable answer that uses other words. That's why lab 05 built an AI judge checked against human labels. In practice you use both: the keyword check on every change (fast, free), a judge or a human on a sample (slower, closer to the truth).

Common mistakes.
  • FileNotFoundError for runs/baseline.jsonl: run lab 04 first (uv run python -m labs.04_baseline_eval).
  • KeyError when the prompt is loaded: you added braces (for example a JSON example) to rag_v2.txt. str.format treats every {…} as a placeholder; write {{ and }} for literal braces.
  • Comparing runs with different questions: if you edit evals/qa.jsonl, re-run the baseline too, or the comparison is meaningless.
  • Celebrating the average: always read the failing lines and a few passing ones (q02).
  • Overwriting your runs: run("rag_v2", …) always writes runs/rag_v2.jsonl, and lab 08 writes it again. Use a new name for experiments.

Recap
  • rag.answer(question, retriever) retrieves 3 chunks, fills {context} in prompts/rag_v2.txt and asks the model at temperature 0.
  • The rag_v2 rules: only facts from the context, an exact "I don't know" sentence, short answers with chunk-id citations, and context treated as data, not instructions.
  • Keyword pass rate went from 30 % (baseline) to 80 %; input tokens from about 63 to 372 per question; time per answer did not get worse here.
  • Failures come from retrieval (q06), generation (q03 incomplete, q08 and q16 over-cautious) or the metric itself (q02, a false pass).
