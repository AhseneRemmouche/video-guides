AI Engineering: a hands-on companion

Build, measure and harden a real support bot while you read Chip Huyen's book AI Engineering. Every concept chapter explains one part of the field in plain language. Every lab is a small program, written twice: in Python and in TypeScript. You run it on your own computer with free local models. A last part puts the bot in a React web app. Each lab was run for this guide in both languages, and its real output is shown.

The book: AI Engineering (O'Reilly, 2025)
What this guide is, and what it is not. It is an independent study companion, written from scratch. It is not a summary of the book and does not reproduce its text, figures or examples. Each concept chapter tells you which book chapter to read with it. All explanations, diagrams, code and the bike shop used in the labs are original. The author keeps free study notes and a reading list in the aie-book repository.

How to use it

  1. Read a book chapter, or first the matching concept chapter below if you want a gentler start.
  2. Do the labs linked from that concept chapter. Each lab adds one file or one idea to the same project.
  3. Pick your language with the Code in: switch at the top of every page (Python or TypeScript). Code, outputs and explanations follow your choice, and the guide remembers it from page to page.
  4. Change something (a prompt, a model, a threshold) and run the lab again. The eval set from lab 04 tells you if it got better.

The project: a support bot for a bike shop

All 14 labs work on one project, trailhead-ai: a customer-support assistant for Trailhead Bikes, an invented online bike shop with stores in Lyon, Grenoble and Annecy. Its knowledge is eight short policy documents (returns, warranty, shipping, battery care, sizes, service plans, stores, payment), plus a small orders file for the agent. The shop is made up, so you always know the right answer and can check the bot.

The project exists in two folders with the same documents, eval sets and prompts: trailhead-ai (Python, run with uv) and trailhead-ai-ts (TypeScript, run with pnpm). Both use the plain openai package against Ollama and small hand-written code, with no framework on top. The TypeScript folder also holds the React web app: a Hono server and a React page.

Part 1 · Talking to a model

Set up the project, call a model, and learn the two things that surprise beginners most: answers are random, and valid JSON can still be wrong.

  1. 01Set up the lab and call a modelInstall Ollama and uv, create the project, and make your first call through one small wrapper that records tokens and time.lab
  2. 02Sampling: temperature and seedsAsk the same question many times and see how temperature and a fixed seed change the answers.lab
  3. 03Structured output with a schemaTurn customer messages into validated JSON with Pydantic, and learn why valid JSON can still be wrong.lab

Part 2 · Evaluation

Measure before you improve: a test set, a baseline and an AI judge you have checked against human labels.

  1. 04Build an eval set and a baselineWrite 20 test questions, score a bot that knows nothing about the shop, and get the number to beat.lab
  2. 05An AI judge, checked against humansGrade answers with a stronger model and a written rubric, then measure how often it agrees with human labels.lab

Part 3 · RAG and prompts

Give the bot the shop's documents, measure retrieval, and make the prompt robust.

  1. 06Retrieval: BM25, embeddings and hybridChunk the documents, build three retrievers and measure hit rate and MRR on the eval set.lab
  2. 07RAG answers with citationsAnswer from retrieved chunks with a grounded prompt and compare the score with the baseline.lab
  3. 08Prompt versions and prompt injectionCompare two prompt versions on the eval set, then attack them with a poisoned document.lab

Part 4 · Agents and safety

Let the model use tools, then put guardrails around everything it reads and writes.

  1. 09A tool-using agentGive the model tools for policies, orders and dates, run the tool loop, and check which tools it used.lab
  2. 10Guardrails on input and outputRedact personal data, block injection attempts and stop answers that cite nothing or promise too much.lab

Part 5 · Production

Make it cheaper and faster, watch it in use, learn from feedback and prepare data for fine-tuning.

  1. 11Caching and routingAnswer repeated questions from exact and semantic caches, and send each message to the cheapest path.lab
  2. 12Tracing and user feedbackLog every answer to SQLite, collect thumbs up and down, and turn bad answers into new eval cases.lab
  3. 13Synthetic data for fine-tuningGenerate question-answer pairs from the documents, filter and deduplicate them, and export a fine-tuning file.lab
  4. 14Latency and throughputMeasure time to first token, time per token and throughput with streaming and parallel requests.lab

Part 6 · A web app (TypeScript)

The labs run in the terminal. This part puts the bot in a browser: streaming answers, sources, guardrails and feedback, all from the TypeScript project.

  1. 15The React web appPut the guarded RAG bot behind a small Node server and a React chat that streams answers, shows cited sources and guardrail flags, and saves thumbs up and down.lab

Get the code

Every file is shown in full on the lab pages with a Copy button. The whole project is also in the guide's GitHub repository, in two folders: ai-engineering/trailhead-ai (Python) and ai-engineering/trailhead-ai-ts (TypeScript and the web app). Lab 01 explains how to set up each one, and the web app page how to start the app.

Run a lab from the trailhead-ai folder, for example lab 01, and the offline tests (8 should pass):

uv run python -m labs.01_hello
uv run pytest

In the trailhead-ai-ts folder, install the packages once, run a lab by its number, and run the offline tests (9 should pass):

pnpm install
pnpm lab 01
pnpm test

The web app needs two terminals: pnpm api in one and pnpm web in the other, then open http://localhost:5173.
