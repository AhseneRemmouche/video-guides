Caching and routing

Answer repeated questions from exact and semantic caches, and send each message to the cheapest path.

Lab · code run on a local model (llama3.2 via Ollama)

Every answer from the Trailhead bot costs about 4 seconds on our laptop GPU, and on a paid API it would also cost money for every token. Many customers ask the same few questions. In this lab you add two shortcuts in front of the model: a cache that remembers answers it already gave, and a router that sends each message to the cheapest path that can handle it. You will also see where both shortcuts go wrong.

Goal. Answer repeated questions from an exact cache and a semantic cache, measure the time saved, understand the similarity threshold trade-off, and classify messages with a small router built on structured output.

The idea in brief

A cache is a lookup table: question in, stored answer out. If the question was seen before, you skip the model entirely. There are two kinds in this lab:

  • Exact cache: the new question must be the same text as an old one (after small clean-ups like lower case). It is never wrong, but it misses every rewording.
  • Semantic cache: the new question is turned into an embedding and compared with the embeddings of old questions. If the closest one is similar enough (above a threshold), its answer is reused. It catches rewordings, but it can also reuse an answer for a question that only looks similar.

A router is a cheap classification step before the expensive work: "is this small talk, a policy question, an order question or something we don't handle?" Each class gets its own path. The concept chapters explain where these pieces sit in a real system: Architecture and user feedback (step by step, caches and routers are layers of the architecture) and Inference optimization (the fastest model call is the one you never make).

New to embeddings and cosine similarity? What the similarity number means

An embedding model (here nomic-embed-text) turns a text into a list of a few hundred numbers, a vector. Texts with similar meaning get vectors that point in similar directions. Cosine similarity measures the angle between two vectors: 1.00 means the same direction (same meaning, or the same words), values near 0 mean unrelated. You met this in lab 06, where it ranked document chunks. Here it ranks old questions instead.

If both vectors are first scaled to length 1 ("normalized"), cosine similarity is just the dot product of the two lists: multiply the numbers pairwise and add them up. That is why cache.py divides each vector by its length once, then uses the fast @ (matrix product) operator.That is why cache.ts divides each vector by its length once (normalize), then uses a simple dot loop from retrieve.ts.

New to caching? Why "remember the answer" is harder than it sounds

Caching is old and simple in normal software: if a web page didn't change, serve the copy you already made. For a chatbot, three questions make it harder. Is it the same question? (exact text, or the same meaning?) Is the old answer still true? (if shipping.md changes, cached shipping answers must be thrown away). Is it safe to share? A policy answer is the same for everybody; an answer about one customer's order must never be served to another customer. Our lab cache keeps everything in memory, so it is emptied every time the program ends, which sidesteps the second question. A real one needs an expiry rule.

The two caches

"""Two caches: exact (same text) and semantic (similar meaning)."""
import numpy as np

from aie.llm import embed


class ExactCache:
    def __init__(self):
        self.store = {}

    @staticmethod
    def key(text):
        return " ".join(text.lower().split())

    def get(self, text):
        return self.store.get(self.key(text))

    def put(self, text, answer):
        self.store[self.key(text)] = answer


class SemanticCache:
    """Returns a stored answer when a new question is close enough to a previous one."""

    def __init__(self, threshold=0.9):
        self.threshold, self.vectors, self.answers = threshold, [], []

    def _vector(self, text):
        v = np.array(embed([f"search_query: {text}"])[0], dtype=np.float32)
        return v / np.linalg.norm(v)

    def get(self, text):
        if not self.vectors:
            return None, 0.0
        v = self._vector(text)
        sims = np.array(self.vectors) @ v
        best = int(np.argmax(sims))
        return (self.answers[best] if sims[best] >= self.threshold else None), float(sims[best])

    def put(self, text, answer):
        self.vectors.append(self._vector(text))
        self.answers.append(answer)
// Two caches: exact (same text) and semantic (similar meaning).
import { embed } from "./llm.js";
import { dot, normalize } from "./retrieve.js";

export class ExactCache {
  private store = new Map<string, string>();

  static key(text: string): string {
    return text.toLowerCase().split(/\s+/).filter(Boolean).join(" ");
  }

  get(text: string): string | undefined {
    return this.store.get(ExactCache.key(text));
  }

  put(text: string, answer: string): void {
    this.store.set(ExactCache.key(text), answer);
  }
}

/** Returns a stored answer when a new question is close enough to a previous one. */
export class SemanticCache {
  private vectors: number[][] = [];
  private answers: string[] = [];

  constructor(private threshold = 0.9) {}

  private async vector(text: string): Promise<number[]> {
    return normalize((await embed([`search_query: ${text}`]))[0]!);
  }

  /** Returns the cached answer (or undefined) and the best similarity found. */
  async get(text: string): Promise<[answer: string | undefined, similarity: number]> {
    if (!this.vectors.length) return [undefined, 0];
    const v = await this.vector(text);
    const sims = this.vectors.map((row) => dot(row, v));
    const best = sims.indexOf(Math.max(...sims));
    return [sims[best]! >= this.threshold ? this.answers[best] : undefined, sims[best]!];
  }

  async put(text: string, answer: string): Promise<void> {
    this.vectors.push(await this.vector(text));
    this.answers.push(answer);
  }
}

The router

"""Route each message to the cheapest path that can handle it."""
from typing import Literal

from pydantic import BaseModel

from aie.llm import chat_json


class Route(BaseModel):
    route: Literal["smalltalk", "policy_question", "order_question", "out_of_scope"]


ROUTER_PROMPT = """Classify the customer's message for a bike shop's support system.
smalltalk: greetings or thanks. policy_question: returns, warranty, shipping, batteries, sizes, service plans, stores, payment.
order_question: about a specific order. out_of_scope: anything else. Reply with JSON."""


def route(message):
    return chat_json([{"role": "system", "content": ROUTER_PROMPT}, {"role": "user", "content": message}], Route, temperature=0).route
// Route each message to the cheapest path that can handle it.
import { z } from "zod";
import { chatJson } from "./llm.js";

export const Route = z.object({
  route: z.enum(["smalltalk", "policy_question", "order_question", "out_of_scope"]),
});

const ROUTER_PROMPT = `Classify the customer's message for a bike shop's support system.
smalltalk: greetings or thanks. policy_question: returns, warranty, shipping, batteries, sizes, service plans, stores, payment.
order_question: about a specific order. out_of_scope: anything else. Reply with JSON.`;

export async function route(message: string) {
  const messages = [{ role: "system" as const, content: ROUTER_PROMPT }, { role: "user" as const, content: message }];
  return (await chatJson(messages, Route, "Route", undefined, { temperature: 0 })).route;
}

The lab script

"""Lab 11: save time and money with caches and a router."""
import time

from aie import rag
from aie.cache import ExactCache, SemanticCache
from aie.docs import load_chunks
from aie.retrieve import Hybrid
from aie.router import route

retriever = Hybrid(load_chunks())
exact, semantic = ExactCache(), SemanticCache(threshold=0.9)


def answer(question):
    start = time.perf_counter()
    if (hit := exact.get(question)) is not None:
        return hit, "exact cache", time.perf_counter() - start
    hit, similarity = semantic.get(question)
    if hit is not None:
        return hit, f"semantic cache (similarity {similarity:.2f})", time.perf_counter() - start
    text = rag.answer(question, retriever)["answer"]
    exact.put(question, text)
    semantic.put(question, text)
    return text, f"model (closest cached question: {similarity:.2f})", time.perf_counter() - start


print("1) Caching")
for q in ["How long does standard shipping take?",
          "How long does standard shipping take?",
          "how long does standard shipping take",
          "How many days does standard delivery take?",
          "How long does express shipping take?"]:
    text, source, seconds = answer(q)
    print(f"   {seconds:6.2f} s  {source:<40} {q}")
print("   Careful: a semantic cache must not answer the express question with the standard answer.")

print("\n2) Routing")
REPLIES = {"smalltalk": "You're welcome! Anything else I can help with?",
           "out_of_scope": "I can only help with Trailhead Bikes questions."}
for m in ["Thanks a lot!", "Do you ship to Belgium?", "Where is my order TH-10260?", "Write me a poem about cats"]:
    start = time.perf_counter()
    r = route(m)
    note = REPLIES.get(r, "-> RAG bot" if r == "policy_question" else "-> agent with order tools")
    print(f"   {r:<16} {time.perf_counter() - start:5.1f} s  {m!r}: {note}")
// Lab 11: save time and money with caches and a router.
import * as rag from "../src/rag.js";
import { ExactCache, SemanticCache } from "../src/cache.js";
import { loadChunks } from "../src/docs.js";
import { Hybrid } from "../src/retrieve.js";
import { route } from "../src/router.js";

const retriever = new Hybrid(loadChunks());
const exact = new ExactCache();
const semantic = new SemanticCache(0.9);
const elapsed = (start: number) => (performance.now() - start) / 1000;

async function answer(question: string): Promise<[text: string, source: string, seconds: number]> {
  const start = performance.now();
  const hit = exact.get(question);
  if (hit !== undefined) return [hit, "exact cache", elapsed(start)];
  const [similar, similarity] = await semantic.get(question);
  if (similar !== undefined) return [similar, `semantic cache (similarity ${similarity.toFixed(2)})`, elapsed(start)];
  const text = (await rag.answer(question, retriever)).answer;
  exact.put(question, text);
  await semantic.put(question, text);
  return [text, `model (closest cached question: ${similarity.toFixed(2)})`, elapsed(start)];
}

console.log("1) Caching");
for (const q of [
  "How long does standard shipping take?",
  "How long does standard shipping take?",
  "how long does standard shipping take",
  "How many days does standard delivery take?",
  "How long does express shipping take?",
]) {
  const [, source, seconds] = await answer(q);
  console.log(`   ${seconds.toFixed(2).padStart(6)} s  ${source.padEnd(40)} ${q}`);
}
console.log("   Careful: a semantic cache must not answer the express question with the standard answer.");

console.log("\n2) Routing");
const REPLIES: Record<string, string> = {
  smalltalk: "You're welcome! Anything else I can help with?",
  out_of_scope: "I can only help with Trailhead Bikes questions.",
};
for (const m of ["Thanks a lot!", "Do you ship to Belgium?", "Where is my order TH-10260?", "Write me a poem about cats"]) {
  const start = performance.now();
  const r = await route(m);
  const note = REPLIES[r] ?? (r === "policy_question" ? "-> RAG bot" : "-> agent with order tools");
  console.log(`   ${r.padEnd(16)} ${elapsed(start).toFixed(1).padStart(5)} s  ${JSON.stringify(m)}: ${note}`);
}

Reading the output

Caching: the time saved is real

Line 3 is worth a second look. "how long does standard shipping take" differs from the first question only by capitals and the missing "?". The exact cache lower-cases the text but keeps punctuation, so its key is different and it misses. The semantic cache sees the same meaning (similarity 1.00) and answers in 0.06 s (0.07 s in TypeScript), the time of one embedding call.

The threshold trade-off

The paraphrase "How many days does standard delivery take?" means the same as the cached question, and the cached answer would have been right. It scored 0.88, just below 0.9, so the bot paid for a fresh answer: a missed saving. The express question scored 0.82 and also went to the model, which was correct: express shipping takes 1 to 2 days, standard shipping 3 to 5, so reusing the cached answer would have told the customer something false.

So why not lower the threshold to 0.85 to catch the paraphrase? Because the two numbers are close. The gap between "same meaning, different words" (0.88) and "similar words, different meaning" (0.82) is only 0.06 here. A threshold low enough to catch more paraphrases will sooner or later catch a question like the express one, and then the cache confidently serves a wrong answer in 0.06 s, with no model ever looking at the new question. A missed saving costs you 4 seconds; a wrong cached answer costs you a customer's trust. That is why semantic caches start strict, are tuned on a labelled set of question pairs, and are often limited to questions where a wrong reuse is harmless.

Routing: useful, but not free

Three of the four messages were routed correctly. "Thanks a lot!" was labelled out_of_scope, although the prompt lists thanks under smalltalk, so a polite customer got "I can only help with Trailhead Bikes questions." A small model makes this kind of mistake; you only notice it if you test the router on labelled messages, exactly like the eval set of lab 04.

The second lesson is in the times. Each routing call took 2.3 to 4.4 seconds in the Python run and 1.8 to 2.4 seconds in the TypeScript run, almost as long asa large part of a full RAG answer (about 4 s in part 1), because the router is the same llama3.2 model. A router only saves time and money when it is much cheaper than the work it avoids.

Real systems therefore route with something much cheaper than the main model: keyword rules, a small classifier trained on labelled messages, an embedding compared with example messages per route, or a tiny model on fast hardware. The cache-then-route order also matters: the caches run first because a hit makes routing unnecessary.

Common mistakes
  • Lowering the threshold to "get more hits". The hit rate goes up and so does the number of confidently wrong answers. Our express question at 0.82 shows how close a wrong match can be. Tune on labelled pairs and look at the misses and the false hits.
  • Forgetting the embedding prefix. nomic-embed-text expects search_query: (or search_document: ). Without it the similarities shift and a threshold tuned with the prefix no longer fits.
  • Caching personal answers. "Where is my order TH-10260?" must never be answered from a cache shared between customers. Only cache answers that are the same for everybody, or include the customer in the key.
  • Never clearing the cache. If a policy document changes, old cached answers are now wrong. Our in-memory cache disappears when the script ends; a persistent cache needs an expiry time or a reset when documents change.
  • Assuming the router is right. It is a model making a guess. "Thanks a lot!" went to out_of_scope in our run. Give routes a safe default and measure routing accuracy.
  • Running from the wrong folder. ModuleNotFoundError: No module named 'aie' means you are not in the project folder, or you ran python labs/11_cache_router.py instead of python -m labs.11_cache_router.
  • Forgetting await on the semantic cache. SemanticCache.get and put are async because they call the embedding model. Without await, put may not have stored the vector yet when the next question arrives, and get gives you a Promise instead of the pair. The exact cache needs no await.

Recap
  • An exact cache is fast and never wrong but misses every rewording; ours even missed a lower-case copy because "?" is part of the key.
  • A semantic cache compares embeddings: it answered a reworded copy in 0.06 s instead of about 4 s.
  • The threshold is a trade-off: at 0.9 we missed a good paraphrase (0.88) but correctly refused the express question (0.82). A lower threshold risks fast, confident, wrong answers.
  • A router picks a path per message, but it is a model guess ("Thanks a lot!" was misrouted) and here it cost 2.3–4.4 s1.8–2.4 s per call. A router must be much cheaper than what it saves.
  • Only cache answers that are the same for everyone, and clear the cache when the documents change.
