Sampling: temperature and seeds

Ask the same question many times and see how temperature and a fixed seed change the answers.

Lab · code run on a local model (llama3.2 via Ollama)
Goal of this lab. Ask the model the same question 6 times at three different temperatures, count how many different answers come back, and check that a fixed seed makes a random answer repeatable. You will see for yourself why the same prompt can give different answers, and how to make a run repeatable when you need to compare things (for example in an evaluation).

The idea in brief

A model doesn't write a whole answer at once. It produces one token at a time. For each step it computes a probability for every token in its vocabulary ("Pedal" 55 %, "Gear" 25 %, …), then picks one. This picking step is called sampling, and it is the reason the same question can get different answers. Three settings control it:

  • Temperature reshapes the probabilities before picking. Low temperature makes the likely tokens even more likely; high temperature flattens the distribution so unlikely tokens get picked more often. At temperature 0 the model always takes the most likely token.
  • Top-p (also called nucleus sampling) throws away the long tail of unlikely tokens: it keeps the smallest group of top tokens whose probabilities add up to p, and picks only among those.
  • A seed fixes the random number generator used for the picking. Same seed + same input + same settings on the same server = the same "random" choices.

The concept chapter Foundation models explains where these probabilities come from; it pairs with chapter 2 of the book, Understanding Foundation Models.

New to temperature? How it works under the hood

For each next token the model outputs a raw score (a "logit") per token. A function called softmax turns these scores into probabilities that add up to 1. Temperature T divides every score by T before the softmax. Dividing by a number smaller than 1 stretches the gaps between scores, so the top token wins by more. Dividing by a number larger than 1 shrinks the gaps, so the probabilities become more equal. Temperature 0 can't be used as a divisor, so servers treat it as "always take the top token" (greedy decoding).

The code

"""Lab 02: the same prompt, sampled several times at different temperatures."""
from collections import Counter

from aie.llm import chat

PROMPT = "Suggest a name for a bike shop. Reply with the name only."
RUNS = 6

for temperature in (0.0, 0.7, 1.5):
    names = [chat(PROMPT, temperature=temperature).text.strip().strip('"*.') for _ in range(RUNS)]
    counts = Counter(names)
    print(f"temperature={temperature}: {len(counts)} different answers out of {RUNS}")
    for name, n in counts.most_common():
        print(f"   {n} x {name}")

# A fixed seed makes sampling repeatable on servers that support it (Ollama does).
a = chat(PROMPT, temperature=1.0, seed=42).text
b = chat(PROMPT, temperature=1.0, seed=42).text
print(f"\nseed=42 twice at temperature 1.0: {a!r} and {b!r} -> same: {a == b}")
// Lab 02: the same prompt, sampled several times at different temperatures.
import { chat } from "../src/llm.js";

const PROMPT = "Suggest a name for a bike shop. Reply with the name only.";
const RUNS = 6;

for (const temperature of [0.0, 0.7, 1.5]) {
  const counts = new Map<string, number>();
  for (let i = 0; i < RUNS; i++) {
    const name = (await chat(PROMPT, undefined, { temperature })).text.trim().replace(/^["*.]+|["*.]+$/g, "");
    counts.set(name, (counts.get(name) ?? 0) + 1);
  }
  console.log(`temperature=${temperature.toFixed(1)}: ${counts.size} different answers out of ${RUNS}`);
  for (const [name, n] of [...counts].sort((a, b) => b[1] - a[1])) console.log(`   ${n} x ${name}`);
}

// A fixed seed makes sampling repeatable on servers that support it (Ollama does).
const a = (await chat(PROMPT, undefined, { temperature: 1.0, seed: 42 })).text;
const b = (await chat(PROMPT, undefined, { temperature: 1.0, seed: 42 })).text;
console.log(`\nseed=42 twice at temperature 1.0: ${JSON.stringify(a)} and ${JSON.stringify(b)} -> same: ${a === b}`);

Why did 0.7 give the same name six times?

Temperature 0.7 is not "a little random on every word". It is random only where the model is unsure. For this prompt the model is very sure about the first word, and once it has written "Pedal", the rest ("& Co") is almost forced. Temperature 0.7 makes the favourite even more likely (see the first diagram), so six draws in a row can easily all land on it. With a longer answer, such as a three-sentence description, there are many more places where the model is unsure, and 0.7 would almost certainly give different texts. Don't conclude from a short test that a setting is deterministic.

Seeds, and why evaluations use temperature 0

A seed makes the random picks repeatable: the server's random number generator starts from the same point, so the same input gives the same draws and the same answer. It is reproducible only under the same conditions: same model version, same server, same settings. Changing the prompt by one character changes the probabilities, and the same random numbers then lead somewhere else.

From lab 04 on, you will compare versions of the bot on an eval set ("did my new prompt improve the score?"). If answers change randomly between runs, you can't tell whether a better score comes from your change or from luck. That is why the eval scripts call the model with temperature=0{ temperature: 0 }: the model always takes its most likely answer, so a difference in score comes from your change. Even temperature 0 is not a perfect guarantee (different hardware or server versions can round numbers differently), so treat small score changes with care.

Common mistakes.
  • Judging randomness from one run. Six identical answers at 0.7 don't mean 0.7 is deterministic (see above). Run more times, or use a longer prompt.
  • Expecting a seed to survive a change. A new prompt, model or server version gives different answers even with the same seed.
  • Very high temperatures. Values far above 1 produce strange words and broken sentences; 1.5 is already high.
  • Running the file path instead of -m labs.02_sampling gives ModuleNotFoundError: No module named 'aie' (see lab 01).
  • Forgetting await in front of chat(…): you get a Promise instead of a reply, and .text is undefined. pnpm typecheck reports it.

Recap
  • The model picks each token from a probability distribution; that picking is called sampling.
  • Temperature reshapes the distribution: 0 = always the top token, higher = more variety.
  • Top-p keeps only the most likely tokens that together reach probability p.
  • A seed makes random picks repeatable under the same conditions (it worked with Ollama: same name twice).
  • Short answers can look deterministic at 0.7; use temperature 0 for evals and extraction.
