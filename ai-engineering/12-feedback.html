Tracing and user feedback

Log every answer to SQLite, collect thumbs up and down, and turn bad answers into new eval cases.

Lab · code run on a local model (llama3.2 via Ollama)

Once real customers use the bot, the eval set of lab 04 is no longer the only source of truth. Every answer the bot gives in use is evidence: what was asked, which chunks were retrieved, what the model said, how long it took. If you don't record that, a complaint like "the bot told me something wrong yesterday" is impossible to investigate. In this lab you write every answer to a small database (a trace), attach the customer's thumbs up or down to it, print a mini dashboard, and turn the thumbs-down answers into candidate eval cases.

Goal. Log each answer with its question, chunks, model, tokens and time to SQLite; store user feedback next to it; query both; and learn why a thumbs down is a lead to investigate, not a verdict.

The idea in brief

Observability means being able to answer "what happened, and why?" about a system from the data it records. For an AI app the most useful record is the trace: one row per request with everything needed to replay it in your head. Feedback is the second half: a signal from the user about whether the answer helped. Together they let you find bad answers you never thought to test, and feed them back into the eval set. The concept chapter Architecture and user feedback explains monitoring, what feedback can and cannot tell you, and how feedback loops are designed.

New to SQLite? A database in one file

SQLite is a complete SQL database that lives in a single file (here runs/traces.db). There is no server to install: Python ships with the sqlite3 module.Node.js 22.13 and newer has SQLite built in as the node:sqlite module, so there is no package to install and nothing to compile. You create tables (like spreadsheets with fixed columns), add rows with INSERT, and ask questions with SELECT. A JOIN combines rows of two tables that share a value, here a trace's id and a feedback row's trace_id. SQLite is a good fit for a single program on one machine. A production service with many servers writing at the same time would use a server database or a dedicated tracing tool, but the idea is the same.

New to traces? What to log, and what not to

Log what you need to understand a request later: the input, the context the model saw (here the chunk ids), the output, which model and prompt version produced it, and the cost (tokens, seconds). Store the prompt version name (rag_v2), not the whole prompt, because prompts are versioned files (lab 08). Be careful with personal data: questions can contain emails or card numbers. A real system would redact them first (redact_piiredactPii from lab 10) and decide how long to keep traces. The web app of page 15 does exactly that: it logs the redacted question.

Tracing and feedback storage

"""Log every request to SQLite so you can debug it later and learn from user feedback."""
import json
import sqlite3
import uuid
from datetime import datetime, timezone

from aie.config import RUNS

SCHEMA = """
CREATE TABLE IF NOT EXISTS traces (
    id TEXT PRIMARY KEY, created TEXT, question TEXT, answer TEXT, chunks TEXT,
    model TEXT, input_tokens INT, output_tokens INT, seconds REAL, prompt TEXT
);
CREATE TABLE IF NOT EXISTS feedback (
    trace_id TEXT REFERENCES traces(id), rating INT, comment TEXT, created TEXT
);
"""


def connect(path=RUNS / "traces.db"):
    path.parent.mkdir(parents=True, exist_ok=True)
    db = sqlite3.connect(path)
    db.executescript(SCHEMA)
    return db


def log_trace(db, question, out, prompt):
    trace_id = uuid.uuid4().hex[:8]
    r = out["reply"]
    db.execute("INSERT INTO traces VALUES (?,?,?,?,?,?,?,?,?,?)", (
        trace_id, datetime.now(timezone.utc).isoformat(), question, out["answer"], json.dumps(out["chunks"]),
        r.model, r.input_tokens, r.output_tokens, round(r.seconds, 2), prompt))
    db.commit()
    return trace_id


def log_feedback(db, trace_id, rating, comment=""):
    """rating: +1 (thumbs up) or -1 (thumbs down)."""
    db.execute("INSERT INTO feedback VALUES (?,?,?,?)", (trace_id, rating, comment, datetime.now(timezone.utc).isoformat()))
    db.commit()

// node:sqlite is built into Node.js 22.13 and newer: no package to install, nothing to compile.
import { randomUUID } from "node:crypto";
import { mkdirSync } from "node:fs";
import path from "node:path";
import { DatabaseSync } from "node:sqlite";
import { RUNS } from "./config.js";
import type { Answer } from "./rag.js";

const SCHEMA = `
CREATE TABLE IF NOT EXISTS traces (
    id TEXT PRIMARY KEY, created TEXT, question TEXT, answer TEXT, chunks TEXT,
    model TEXT, input_tokens INT, output_tokens INT, seconds REAL, prompt TEXT
);
CREATE TABLE IF NOT EXISTS feedback (
    trace_id TEXT REFERENCES traces(id), rating INT, comment TEXT, created TEXT
);
`;

export function connect(file = path.join(RUNS, "traces.db")): DatabaseSync {
  mkdirSync(path.dirname(file), { recursive: true });
  const db = new DatabaseSync(file);
  db.exec(SCHEMA);
  return db;
}

export function logTrace(db: DatabaseSync, question: string, out: Answer, prompt: string): string {
  const traceId = randomUUID().replaceAll("-", "").slice(0, 8);
  const r = out.reply;
  db.prepare("INSERT INTO traces VALUES (?,?,?,?,?,?,?,?,?,?)").run(
    traceId, new Date().toISOString(), question, out.answer, JSON.stringify(out.chunks),
    r.model, r.inputTokens, r.outputTokens, Math.round(r.seconds * 100) / 100, prompt,
  );
  return traceId;
}

/** rating: +1 (thumbs up) or -1 (thumbs down). */
export function logFeedback(db: DatabaseSync, traceId: string, rating: number, comment = ""): void {
  db.prepare("INSERT INTO feedback VALUES (?,?,?,?)").run(traceId, rating, comment, new Date().toISOString());
}

The lab script

"""Lab 12: trace every answer, collect thumbs up/down, and turn bad answers into new eval cases."""
from aie import rag
from aie.config import EVALS
from aie.docs import load_chunks
from aie.evalset import save_jsonl
from aie.retrieve import Hybrid
from aie.tracing import connect, log_feedback, log_trace

retriever = Hybrid(load_chunks())
db = connect()
db.execute("DELETE FROM feedback")
db.execute("DELETE FROM traces")

# Simulated traffic: (question, the customer's rating, their comment)
traffic = [
    ("Can I return a bike I rode 80 km?", -1, "Unfair policy, I only rode it twice"),
    ("Do you ship to Italy?", +1, ""),
    ("How long does a full service take?", +1, ""),
    ("Can I cancel Trailhead Care?", +1, ""),
    ("Is express shipping available for helmets?", -1, "Not clear"),
]
for question, rating, comment in traffic:
    out = rag.answer(question, retriever, prompt="rag_v2")
    trace_id = log_trace(db, question, out, "rag_v2")
    log_feedback(db, trace_id, rating, comment)
    print(f"{trace_id}  {'+1' if rating > 0 else '-1'}  {question}\n          {out['answer'][:130]!r}")

print("\nDashboard")
row = db.execute("""SELECT COUNT(*), AVG(seconds), AVG(input_tokens), AVG(output_tokens),
                    AVG(CASE WHEN f.rating > 0 THEN 1.0 ELSE 0 END)
                    FROM traces t JOIN feedback f ON f.trace_id = t.id""").fetchone()
print(f"  {row[0]} answers, {row[1]:.1f} s average, {row[2]:.0f} input / {row[3]:.0f} output tokens, {row[4]:.0%} thumbs up")

bad = db.execute("""SELECT t.id, t.question, t.answer, f.comment FROM traces t JOIN feedback f ON f.trace_id = t.id
                    WHERE f.rating < 0""").fetchall()
new_cases = [{"id": f"fb-{tid}", "question": q, "bad_answer": a, "user_comment": c,
              "status": "needs a human to write the expected answer"} for tid, q, a, c in bad]
save_jsonl(EVALS / "from_feedback.jsonl", new_cases)
print(f"\n{len(new_cases)} thumbs-down answers saved to evals/from_feedback.jsonl for review:")
for c in new_cases:
    print(f"  {c['id']}: {c['question']}  (user: {c['user_comment']!r})")
// Lab 12: trace every answer, collect thumbs up/down, and turn bad answers into new eval cases.
import path from "node:path";
import * as rag from "../src/rag.js";
import { EVALS } from "../src/config.js";
import { loadChunks } from "../src/docs.js";
import { saveJsonl } from "../src/evalset.js";
import { Hybrid } from "../src/retrieve.js";
import { connect, logFeedback, logTrace } from "../src/tracing.js";

const retriever = new Hybrid(loadChunks());
const db = connect();
db.exec("DELETE FROM feedback");
db.exec("DELETE FROM traces");

// Simulated traffic: (question, the customer's rating, their comment)
const traffic: [string, number, string][] = [
  ["Can I return a bike I rode 80 km?", -1, "Unfair policy, I only rode it twice"],
  ["Do you ship to Italy?", +1, ""],
  ["How long does a full service take?", +1, ""],
  ["Can I cancel Trailhead Care?", +1, ""],
  ["Is express shipping available for helmets?", -1, "Not clear"],
];
for (const [question, rating, comment] of traffic) {
  const out = await rag.answer(question, retriever, "rag_v2");
  const traceId = logTrace(db, question, out, "rag_v2");
  logFeedback(db, traceId, rating, comment);
  console.log(`${traceId}  ${rating > 0 ? "+1" : "-1"}  ${question}\n          ${JSON.stringify(out.answer.slice(0, 130))}`);
}

console.log("\nDashboard");
const row = db.prepare(`SELECT COUNT(*) AS n, AVG(seconds) AS secs, AVG(input_tokens) AS tin, AVG(output_tokens) AS tout,
                        AVG(CASE WHEN f.rating > 0 THEN 1.0 ELSE 0 END) AS up
                        FROM traces t JOIN feedback f ON f.trace_id = t.id`).get() as Record<string, number>;
console.log(`  ${row.n} answers, ${row.secs!.toFixed(1)} s average, ${Math.round(row.tin!)} input / ${Math.round(row.tout!)} output tokens, ` +
  `${Math.round(100 * row.up!)}% thumbs up`);

const bad = db.prepare(`SELECT t.id, t.question, t.answer, f.comment FROM traces t JOIN feedback f ON f.trace_id = t.id
                        WHERE f.rating < 0`).all() as { id: string; question: string; answer: string; comment: string }[];
const newCases = bad.map((b) => ({
  id: `fb-${b.id}`, question: b.question, bad_answer: b.answer, user_comment: b.comment,
  status: "needs a human to write the expected answer",
}));
saveJsonl(path.join(EVALS, "from_feedback.jsonl"), newCases);
console.log(`\n${newCases.length} thumbs-down answers saved to evals/from_feedback.jsonl for review:`);
for (const c of newCases) console.log(`  ${c.id}: ${c.question}  (user: ${JSON.stringify(c.user_comment)})`);

Reading the output

The dashboard

Five answers took 4.8 s on average and used 358 input tokens4.0 s on average and used 365 input tokens but only 19 output tokens each. Almost all the tokens are the prompt: the rules of rag_v2 plus three retrieved chunks. That ratio is typical for RAG, and it tells you where cost and time go (see Inference optimization). 60% thumbs up means 3 of 5. With five ratings this is a demonstration of the mechanics, not a statistic.

A thumbs down is not proof of a wrong answer

Look at the first thumbs down. The customer asked "Can I return a bike I rode 80 km?" and the bot said no, because the limit is 50 km, citing [returns#0]. That is exactly what data/docs/returns.md says: the answer is correct. The comment, "Unfair policy, I only rode it twice", is about the policy, not about the bot. If you treated every thumbs down as a bug and "fixed" the bot until this customer was happy, you would teach it to promise returns the shop doesn't accept.

The second thumbs down ("Not clear") is on "I don't know" for "Is express shipping available for helmets?". The documents only say that express shipping is not available for complete bikes; they never mention helmets. The bot refused instead of guessing, which follows the rules of rag_v2. So the useful lesson here is a gap in the documents: the shop should add one sentence to shipping.md, and then the bot can answer.

It works the other way too. The trace stores the retrieved chunk ids, and a quick look at our Python run's traces shows that two thumbs-up answers cite the wrong chunk. "A full service takes a full day. [service-plans#0]" is true, but that fact is in stores.md, and the trace shows stores#2 and stores#1 were retrieved. "You can cancel Trailhead Care at any time" cites service-plans#1, but the cancellation sentence is only in service-plans#2. The customers were happy; the citations were still wrong. You only see this because the trace kept the chunks.

Why from_feedback.jsonl needs a human

The exported file holds the question, the bad answer and the comment, with the status "needs a human to write the expected answer". Someone who knows the policy must read each case and decide: is the answer wrong (write the expected answer and add the case to evals/qa.jsonl), is it right (keep it as a test that the bot keeps saying no to an 80 km bike), or is the problem elsewhere (fix the documents)? Once a case is in the eval set, every future change to the prompt, retriever or model is checked against it.

Common mistakes
  • Treating the thumbs-up rate as accuracy. Our 60% includes a correct answer rated down and two answers with wrong citations rated up. Use it as a trend and a pointer to cases, never as a quality score.
  • Copying the bad answer into the eval set as "expected". The script deliberately leaves the expected answer empty. A model-written "correct" answer can be just as wrong.
  • Forgetting db.commit(). Rows inserted without a commit disappear when the program ends, and your dashboard shows 0 answers next time.
  • Forgetting COMMIT in a transaction. node:sqlite saves each statement immediately, so the lab needs no commit. But if you later wrap several inserts in BEGIN … COMMIT to make them faster, forgetting the COMMIT loses them.
  • Building SQL with f-stringstemplate literals. f"INSERT ... VALUES ('{question}')"`INSERT ... VALUES ('${question}')` breaks on any question with an apostrophe ("What's ...") and opens the door to SQL injection. Always use ? placeholders.
  • Opening the wrong file. sqlite3.connectnew DatabaseSync creates an empty database if the path doesn't exist, so a typo gives you "no such table: traces" instead of "file not found". Run the one-liner from the project folder.
  • Logging personal data unfiltered. Traces keep questions verbatim. Redact first, and decide how long to keep them.

  • A trace records one request: question, chunks, answer, model, prompt version, tokens and seconds. aie/tracing.pysrc/tracing.ts stores traces and feedback in two SQLite tables joined by the trace id. The web app of page 15 writes to the same database.
  • The dashboard query showed 5 answers, 4.8 s average, 358 input4.0 s average, 365 input / 19 output tokens, 60% thumbs up. Most tokens are the prompt.
