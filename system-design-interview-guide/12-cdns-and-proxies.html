CDNs & Proxy Servers

Pull vs push CDNs and their benefits, plus forward and reverse proxies and what each is used for.

▶ Watch this part (33:28)

Caching keeps a copy of data in a faster place. A CDN takes that idea and spreads it across the globe, so the copy is not just faster but also physically closer to the user. On this page we look at CDNs — how they serve content from the nearest location, the two ways content gets onto them, and when you still have to reach the original server — and then at proxy servers, the broader family of middlemen that a CDN belongs to.

What a CDN is

A CDN (content delivery network) is a network of servers spread out geographically (at 33:28). It is generally used to serve static content — JavaScript, HTML, CSS, images and video files — by caching that content from the original server and delivering it from the CDN server nearest to the user (at 33:52). The individual CDN servers are often called edge servers, because they sit at the edge of the network, close to real users.

New to the "edge"? Why distance adds latency

Data travels through cables at a limited speed, so the farther a request has to go, the longer it takes — a round trip across the planet simply cannot be instant. An edge server shortens that distance by keeping a copy of the content near the user. The user's request reaches a nearby machine instead of crossing an ocean, which is why a CDN can turn a multi-second load into a fast one.

Pull vs push CDNs

There are two ways content ends up on a CDN. In a pull-based CDN, the CDN automatically fetches content from the origin server the first time a user requests it, then caches it for later (at 34:17). On that first request the CDN has nothing, so it goes to the origin, stores a copy, and forwards it to the user; after that, nearby users are served from the edge. Pull CDNs suit sites with lots of static content that is updated regularly, and they need less active management because the CDN keeps itself up to date (at 34:17).

In a push-based CDN, you upload content to the origin and it distributes those files out to the CDN yourself (at 34:41). This suits large files that change rarely but must be delivered quickly when they do change. It needs more active management, because you decide what is stored on the CDN and when (at 34:41). Either way, the Cache-Control header tells the CDN how long to keep the content (at 35:03).

Benefits, and when you still hit the origin

CDNs are used to deliver static assets — images, CSS, JavaScript bundles, video — and they bring several benefits (at 35:03):

  • Lower latency: serving from a location close to the user noticeably reduces latency (at 35:28).
  • High availability and scalability: a CDN can absorb high traffic loads and stay resilient when some hardware fails (at 35:28).
  • Improved security: many CDNs offer features such as DDoS protection and traffic encryption (at 35:52).
  • Less origin load: requests the CDN answers never reach your origin server, so it does less work.

A CDN is not for everything, though. You still need to hit the origin server for dynamic content that changes frequently, for tasks that need real-time processing, and for anything requiring complex server-side logic that the CDN cannot run (at 35:28).

In an interview, say: "I would put static assets behind a CDN to cut latency and offload the origin, and route dynamic, personalised responses to the origin." Splitting traffic into static and dynamic shows you know a CDN is not a substitute for your application servers.

Proxy servers

A CDN is really one example of a broader idea: the proxy server. A proxy sits between a client asking for a resource and the server providing it (at 36:16). It can serve several purposes — caching resources for faster access, anonymising requests, and balancing load across several servers. In short, it receives requests from clients, forwards them to the right servers, and returns the servers' responses back to the clients (at 36:39).

There are several types. The two most commonly used are the forward proxy and the reverse proxy; the difference is simply which side of the conversation the proxy stands in front of (at 38:11).

Forward proxy

A forward proxy sits in front of clients and sends their requests out to servers on the internet (at 37:03). It is often used inside internal networks to control internet access. When a client makes a request, it goes first to the forward proxy, which then decides — based on its configuration and rules — whether to allow, modify, or block it (at 38:35). One of its main jobs is to hide the client's IP address: to the target server, the request looks as if it came from the proxy itself (at 38:59).

Example use cases of forward proxies (at 38:59):

  • Instagram proxies let marketers manage many accounts and appear to be in different places or to be different users, without being flagged.
  • Internet-use control and monitoring lets organisations block unrelated sites, scan for viruses and malware, and watch employee usage.
  • Caching popular content reduces bandwidth and speeds up access for users inside the network.
  • Anonymising web access hides a user's IP and identifying information from the sites they visit.

Reverse proxy

A reverse proxy sits in front of one or more web servers and intercepts requests from clients before they reach those servers (at 37:03). Where a forward proxy hides the client, a reverse proxy hides the servers — or even the fact that there are several servers behind it. The client only ever talks to the reverse proxy and may not know what is behind it (at 40:33). It also spreads requests across servers so no single one is overwhelmed, and it can compress data, cache files, and manage SSL encryption, which speeds up load times and reduces server load (at 40:56).

New to SSL offloading? What "handling encryption" means

Secure websites encrypt traffic with SSL/TLS, and that encryption and decryption take processing power. SSL offloading moves that work onto the reverse proxy, so the application servers behind it do not have to spend their own resources on it and can focus on running your app. The proxy handles the secure handshake with the outside world and passes plain requests inward on the trusted network.

Common use cases of reverse proxies (at 41:19):

  • Load balancers distribute incoming traffic across multiple servers so no single server becomes a bottleneck, keeping speed and reliability high (at 41:19).
  • CDNs are themselves a kind of reverse proxy: they retrieve content from the origin and cache it closer to the user for faster delivery (at 41:43).
  • Web application firewalls sit in front of applications, inspecting incoming traffic to block hacking attempts and common web exploits (at 42:07).
  • SSL offloading moves the encryption and decryption of SSL/TLS traffic onto the proxy, freeing the web servers (at 42:07).

The video also lists other proxy types more briefly (at 37:27): an open proxy that anyone can connect to; a transparent proxy that passes requests along unchanged but is visible to the client; an anonymous proxy that admits it is a proxy but hides the original IP; a distorting proxy that reports a false original IP; and a high-anonymity (elite) proxy that is very hard to detect because it sends no identifying headers.

Common mistake: mixing up forward and reverse proxies. Remember which side each one protects: a forward proxy hides the client from the internet, while a reverse proxy hides the servers from the client. Load balancers, CDNs and web application firewalls are all reverse proxies.
Recap
  • A CDN is a geographically distributed network of edge servers that delivers static content from the location nearest to each user, cutting latency.
  • Pull CDNs fetch from the origin on the first request and need less management; push CDNs are filled by uploading content ahead of time and suit large, rarely-changed files.
  • CDN benefits include lower latency, high availability and scalability, better security, and less load on the origin — but dynamic, real-time, or complex requests still go to the origin.
  • A proxy server is a middleman between client and server. A forward proxy sits in front of clients and hides them; a reverse proxy sits in front of servers and hides them.
  • Reverse-proxy use cases include load balancers, CDNs, web application firewalls, and SSL offloading.
  • Other proxy types exist too: open, transparent, anonymous, distorting, and high-anonymity (elite).
