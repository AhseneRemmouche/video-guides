Networking Basics

IP addresses (v4/v6), packets, TCP vs UDP, DNS and records, ports, public/private IPs and firewalls.

▶ Watch this part (14:31)

Everything in system design eventually travels over a network, so an interview expects you to know the basics of how computers find and talk to each other (at 14:31). This page walks through the building blocks: how devices are addressed, how data is split into pieces and delivered, how a browser turns a domain name into a connection, and the pieces of infrastructure — ports and firewalls — that sit around it all.

IP addresses: naming each device

(at 14:31) At the heart of networking is the IP address, a unique identifier for each device on a network. There are two versions. IPv4 addresses are 32-bit, which allows roughly 4 billion unique addresses (at 14:54). Because the number of connected devices keeps growing, the world is moving to IPv6, which uses 128-bit addresses and so provides a vastly larger pool.

IPv4:  192.0.2.10
IPv6:  2001:db8::8a2e:370:7334     (illustrative addresses)
New to "32-bit" vs "128-bit"? Why it means more addresses

An address made of 32 bits has 2 to the power of 32 possible values — about 4.3 billion. That felt like plenty in the 1980s, but phones, laptops, servers and smart devices have nearly used them up. An IPv6 address has 128 bits, so 2 to the power of 128 possible values, an almost unimaginably larger number. That is why IPv6 exists: we were running out of IPv4 addresses.

Packets: how data actually travels

(at 15:16) When two computers communicate, they do not send one big blob; they send packets of data. Each packet carries an IP header that holds essential information such as the sender's and receiver's IP addresses, so the packet reaches the right destination. This is governed by the Internet Protocol — the set of rules for how data is sent and received. Alongside the IP layer there is an application layer (at 15:40), where data is formatted according to a specific application protocol, for example HTTP for web browsing, so the receiving device interprets it correctly.

Transport: TCP vs UDP

(at 16:05) Once addressing and packets are in place, the transport layer decides how packets are delivered. TCP is built for reliable communication — like a courier who confirms your package arrived and that nothing is missing. It guarantees complete, correctly ordered delivery using sequence numbers to track packet order, and it opens a stable connection with a three-way handshake (at 16:29) before any data flows.

(at 16:53) UDP is the opposite trade-off: faster, but less reliable. It does not establish a connection first and does not guarantee delivery or ordering. That makes it a good fit for time-sensitive traffic such as video calls or live streaming, where speed matters more than perfect delivery and losing a little data is acceptable.

New to the "layers"? IP, transport, and application in one breath

Networking is organised in layers that each do one job. The IP layer handles addressing — getting a packet to the right machine. The transport layer (TCP or UDP) handles how reliably it gets there. The application layer is the actual message, like an HTTP request for a web page. A single packet carries a little of each, stacked together.

DNS: the internet's phone book

(at 17:16) People remember names like example.com, but machines connect using IP addresses. DNS (Domain Name System) bridges the gap: it translates human-friendly domain names into IP addresses. When you type a URL, your browser sends a DNS query to find the matching IP address, then uses that address to connect to the server and fetch the page.

(at 17:41) DNS is overseen by ICANN, which coordinates the global IP address space and domain name system. Domain registrars such as Namecheap or GoDaddy are accredited by ICANN to sell domain names to the public. DNS stores different kinds of records; the most common are A records, which map a domain to its IPv4 address, and AAAA records, which map a domain to an IPv6 address.

example.com.   A      192.0.2.10
example.com.   AAAA   2001:db8::1       (illustrative records)
New to domains? Where DNS fits

A domain name is the readable label you buy from a registrar, like example.com. Owning it does nothing until you add DNS records that say which server it points to. An A record says "this name lives at this IPv4 address". When anyone visits the name, DNS hands back that address so their browser knows where to connect.

Infrastructure: public/private IPs, firewalls and ports

(at 18:05) Devices carry different kinds of IP addresses. A public IP is unique across the whole internet, while a private IP is only unique within a local network. An address can also be static — permanently assigned to a device — or dynamic, changing over time; dynamic addresses are common for home internet connections.

(at 18:28) To protect networks, we use firewalls, which monitor and control incoming and outgoing network traffic. And within a single device, specific processes or services are identified by ports (at 18:50). A port combined with an IP address forms a unique endpoint for a network service. Some ports are reserved for specific protocols — for example, port 80 for HTTP or port 22 for SSH.

endpoint = IP address + port
93.184.216.34:80     (illustrative)
In an interview, say… "Clients find my servers by IP address; DNS translates the domain name to that IP with an A or AAAA record. Between them I'd use TCP for reliable traffic and UDP for real-time media, place services on known ports behind a firewall, and treat each IP-plus-port as one endpoint." Tying addressing, DNS, transport and ports together shows you see the whole path a request takes.
Common mistake Confusing DNS with the IP address itself, or thinking UDP is simply "worse" than TCP. DNS only looks up the address; the real connection happens afterward over TCP or UDP. And UDP is the right choice for video and live streams precisely because it skips the handshake and reliability overhead. Also remember the TCP handshake adds latency — that cost is the price of reliable delivery.
Recap
  • An IP address identifies a device. IPv4 is 32-bit (~4 billion); IPv6 is 128-bit (vastly more).
  • Data travels in packets; each has an IP header (sender/receiver IP) plus application data such as HTTP.
  • TCP is reliable and ordered and opens a three-way handshake first; UDP is fast with no guarantee, good for video and live streams.
  • DNS maps domain names to IPs (A record to IPv4, AAAA to IPv6); ICANN oversees it and registrars sell domains.
  • IPs can be public or private and static or dynamic; firewalls filter traffic and ports plus an IP form a unique endpoint (80 HTTP, 22 SSH).
