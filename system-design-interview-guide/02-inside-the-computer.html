Inside the Computer

Bits and bytes, disk vs SSD, RAM, the L1/L2/L3 cache, the CPU and the motherboard — the foundation everything runs on.

▶ Watch this part (00:45)

Before you design systems made of many machines, it helps to know how one machine runs your code (at 0:45). A computer works as a layered system: each layer is tuned for a different job, and data moves between them as a program runs. This page walks down those layers, from the tiniest unit of data to the board that ties everything together.

Bits and bytes: how data is measured

At its core a computer understands only binary — zeros and ones. Each zero or one is a bit, the smallest unit of data in computing (at 0:45). On its own a bit is not very useful, so we group them. Eight bits make one byte, which is enough to represent a single character such as the letter “a” or the digit “1” (at 1:07).

From there the units get bigger: kilobyte (KB), megabyte (MB), gigabyte (GB), and terabyte (TB). Each step up holds roughly a thousand times more than the one before it, so a terabyte is an enormous amount of data compared with a single byte.

Where data is kept: disk, RAM, and cache

A computer keeps data in several places, and the rule of thumb is simple: the faster a store is, the smaller and more expensive it tends to be.

Disk storage holds the main, long-term data (at 1:07). Your disk storage is either an HDD (a hard disk drive with spinning platters) or a faster SSD (a solid-state drive with no moving parts). Disk is non-volatile: it keeps your data even with the power off, so after a restart your files are still there (at 1:33). It holds the operating system, your applications, and all your files, and typically ranges from hundreds of gigabytes to several terabytes. SSDs cost more but read far faster: an SSD might reach about 500 to 3,500 MB per second, while an HDD might offer only about 80 to 160 MB per second (at 1:55).

RAM (random-access memory) is the next, faster store (at 1:55). RAM holds the data a program is actively using right now: its variables, data structures, and runtime values. It allows very quick reads and writes, often above 5,000 MB per second — faster than even the quickest SSD (at 2:18). The catch is that RAM is volatile memory: it needs power to hold its contents, so after a restart the data in it may be gone (at 2:18). Sizes range from a few gigabytes on everyday devices to hundreds of gigabytes on high-end servers.

Sometimes even RAM is not fast enough, which brings us to the cache (at 3:02). The cache is smaller than RAM — usually measured in megabytes — but its access times are faster still, just a few nanoseconds for the L1 cache. It stores frequently used data so the processor can grab it almost instantly.

The CPU: running your code

The CPU is the brain of the computer. It works in a repeating cycle: it fetches an instruction, decodes it, and executes it (at 3:26). When your program runs, the CPU is what actually carries out the operations it describes.

But the CPU cannot run the high-level code you write directly. Languages like Java, C++, or Python must first be turned into machine code — the raw zeros and ones the CPU understands. A compiler performs this translation, and once the code is compiled the CPU can execute it, reading from and writing to the cache, RAM, and disk as needed (at 3:49).

When the CPU needs a piece of data, it checks the caches before the slower RAM: first the L1 cache, then L2, then L3, and only if the data is in none of them does it reach into RAM (at 3:02). This keeps the most-used data closest to the processor.

The motherboard: the connector

Finally, the motherboard (also called the main board) is the component that connects everything together (at 4:00). It provides the pathways that let data flow between the CPU, cache, RAM, and disk. Without it, the layers could not talk to one another.

New to binary? Why computers use zeros and ones

Inside the machine, data is stored and moved as electrical signals that are either on or off. It is natural to represent those two states as 1 and 0. Everything — text, images, video, your code — is ultimately a long sequence of these bits. Grouping them (8 bits to a byte, and up through KB, MB, GB, TB) just gives us convenient-sized chunks to count and talk about.

Volatile vs non-volatile memory — what is the difference?

Non-volatile storage (disk, whether HDD or SSD) keeps its contents when the power is off, which is why your files survive a shutdown. Volatile memory (RAM and cache) needs power to remember anything, so it is wiped when the machine restarts. That is the real reason you can lose unsaved work: it was only ever in volatile memory and never written to disk.

Why is the cache so tiny but so fast?

Fast memory is expensive and physically sits very close to the CPU, so there is only room for a little of it — a few megabytes. Because it is so close and so quick (nanoseconds), the CPU keeps the data it reaches for most often there. The trade-off from the last page appears again: speed costs size and money, so you get only a small amount of the fastest store.

What does a compiler do?

You write code in a human-friendly language. The CPU only understands machine code (zeros and ones). A compiler is a program that translates your high-level code into that machine code ahead of time, so the CPU can then run it. Some languages are translated as they run instead, but the idea is the same: bridge the gap between what people write and what the processor can execute.

In an interview, say…

“There is a memory hierarchy: cache is tiny and fastest, RAM is larger and fast but volatile, and disk is the largest and non-volatile but slowest. The CPU keeps hot data in cache and only reaches down to RAM or disk when it has to.” This shows you understand why data placement affects performance — the idea behind caching on later pages.

Common mistake

Mixing up RAM and disk storage. RAM is fast, volatile working memory that is wiped on restart; disk is slower, non-volatile long-term storage that survives a restart. Saying “store it in RAM so it is saved permanently” is a red flag — RAM loses its contents when the power goes.

Recap
  • A computer is a layered system; a bit (0 or 1) is the smallest unit, 8 bits make a byte, and sizes scale up through KB, MB, GB, TB.
  • Disk storage is non-volatile (HDD or SSD) and holds the OS, apps, and files; SSDs (~500–3,500 MB/s) are much faster than HDDs (~80–160 MB/s).
  • RAM is volatile working memory, fast (often >5,000 MB/s) but wiped on restart; cache is smaller still and fastest, in nanoseconds.
  • The CPU fetches, decodes, and executes machine code, which a compiler produces from high-level languages; it checks L1, L2, L3, then RAM.
  • The motherboard connects every component so data can flow between them.
