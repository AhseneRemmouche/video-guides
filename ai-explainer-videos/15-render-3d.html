Render the 3D explainer to MP4 with the voice-over

Rendering the 3D composition with WebGL in headless Chrome and muxing the voice-over, with the real output we produced.

Extension - our own code, rendered to a real MP4

This is the last step of the guide. The 3D scene from Step 13 is registered as the Explainer3D composition; now we turn it into a real file. One command renders every frame and muxes in the voice-over, producing an MP4 you can share. This page is an extension — the video gets its video from Claude directly, while here we build and render the 3D one ourselves.

It reuses the same voice-over and the same timeline as the 2D explainer from Part 2. Only the picture changed from flat SVG to 3D; the narration track (public/voiceover.mp3) and its 37.3-second, nine-line timing are shared, so the 3D plane flies to the same words.

The command

Rendering a 3D composition is almost the same as rendering the 2D one, with a single extra flag.

  1. Open a terminal in the Remotion project folder (the one with package.json from Step 08).
  2. Run the render command below. It writes out/airplane-3d.mp4.
  3. Wait for it to finish, then open the file in any video player. You should hear the voice-over and see the 3D airplane.
npx remotion render src/index.ts Explainer3D out/airplane-3d.mp4 --gl=angle

Line by line

6--gl=angleSelects the ANGLE graphics backend for the headless browser. This is what makes WebGL work while Chrome runs with no visible window. Leave it off and the 3D frames come out blank. The 2D render does not need it.
Why does 3D need --gl=angle?

Remotion renders by driving a real Chrome browser with no window on screen — a headless browser. 2D drawing (SVG, canvas 2D) works there out of the box. But 3D needs WebGL, which needs a working graphics driver, and a headless machine (especially a server) often has none. ANGLE is a translation layer that lets Chrome provide WebGL even without real GPU drivers, by routing the work through software or a system graphics API. The flag --gl=angle tells Remotion to start Chrome with that backend, so the ThreeCanvas from Step 13 can actually draw. Our locked facts confirm this is the backend that produced a correct 3D render.

The result

This is our actual rendered file, straight from the command above.

What you should see. The command finishes and writes out/airplane-3d.mp4. Per our verified render it is 37.35 seconds long, with AAC audio, and about 3.2 MB. Playing it shows the 3D airplane drifting and banking among clouds while the voice-over plays in sync — the same length and timing as the 2D render (which was about 2.5 MB).
Common mistakes.
  • Blank or black 3D frames. You forgot --gl=angle, so WebGL never started in the headless browser. Add the flag and render again.
  • A plain blue video with no plane. The camera is facing away from the objects, or they sit outside its near/far range — check the camera prop on ThreeCanvas (Step 13) points toward the origin.
  • Everything is black even with the flag. The lights are missing. MeshStandardMaterial needs light; keep the ambientLight and directionalLight from Step 13.
  • Wrong composition rendered. You typed Explainer2D by habit. Use the exact id Explainer3D for the 3D one.
  • No sound in the file. The <Audio> tag or public/voiceover.mp3 is missing. Both the picture and the audio come from the composition, so the audio tag must be present (Step 13, line 78).
Recap
  • One command renders the 3D composition: npx remotion render src/index.ts Explainer3D out/airplane-3d.mp4 --gl=angle.
  • --gl=angle selects the ANGLE backend so WebGL runs in Remotion's headless browser; 3D needs it, 2D does not.
  • The output is an MP4 with H.264 video and AAC audio — our verified render is 37.35 seconds and about 3.2 MB.
  • The 3D explainer reuses the same voice-over and timeline as the 2D one; only the picture changed.
