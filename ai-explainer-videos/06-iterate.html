Get the video, then iterate

Downloading the result, the model's run time, and how non-determinism lets you change the audience or topic for a new video.

This step covers what Claude does after you send, roughly how long it takes, and the two easy ways to get a different video next time: changing the topic, or changing the audience.

An honest note up front, following the source: the video does not show how Claude internally turns the audio into a video file. So this page does not claim a mechanism. It describes what you can actually see happen in Co-work mode: Claude works for a while, writes a short summary of what it made, and gives you a video you can download. If you want one concrete, reproducible way to build the same kind of video in code, that is what Parts 2 and 3 of this guide do.

What happens after you send

In the video (at 07:36) the creator sends Prompt 2 and Claude goes to work. First it uploads the attached voice-over, then it generates the motion-graphics video. With Opus 5.5 at medium effort, his runs took roughly 10 to 20 minutes. When it finishes, Claude writes a short summary of what it did and provides a downloadable video file.

Ten to twenty minutes is a long time to watch a chat, so it is fine to leave it and come back. The exact length varies from run to run; treat the range as a rough guide from the creator's experience, not a promise.

Get the video

  1. Let it finish. After you send, leave the chat working. You can switch away and return; the roughly 10–20 minute wait is normal for this model and effort.
  2. Read the summary. When Claude is done it posts a short description of what it made. This is a good moment to notice anything you might want changed.
  3. Download the video. Claude provides the finished video as a downloadable file. Save it to your computer and play it to check the animation lines up with the narration.
  4. Decide: keep or iterate. If you are happy, you are done. If not, you can run it again (next section). Because the model is not deterministic, simply asking again can already give a different result.
What you should see. After the wait, the chat shows a short written summary from Claude and a video file you can download and play. The spoken voice-over should match the on-screen action, and there should be no on-screen captions, because Prompt 2 asked for none.

Running it again gives a different video

Large language models are non-deterministic: the exact same prompt can produce a different answer each time you run it. That is not a bug here; it is useful. If the first video is not quite what you wanted, you can ask again with no changes and get a fresh take.

New to “non-deterministic”? What it means and why it matters

A deterministic process gives the same output for the same input every time, like a calculator: 2 + 2 is always 4. A non-deterministic process can give different valid outputs for the same input. Language models work this way by design, which is why asking Claude the same question twice can give two differently worded answers. For this workflow it means two things: you cannot expect a pixel-for-pixel identical video on a re-run, and if you did not love the first result, running it again is a cheap way to get a new one. It also means your result will not look exactly like the creator's, even with the same prompts.

Two deliberate ways to get a different video

Beyond re-running, you can change the inputs on purpose. Both levers live in Prompt 1 from step 3, which had two blanks: [topic] and [audience]. To make a new video you go back to the start of the workflow with one blank changed, regenerate the voice-over, and run Prompt 2 again.

Change the topic

Swap [topic] for a new subject and keep everything else the same. The creator's main example is “how airplanes fly”; change it to, say, “why we need sleep” and the whole pipeline produces a sleep explainer instead. The steps do not change, only the subject does.

Change the audience

Swap [audience] and the style changes a lot, not just the words. The creator made one airplane video for a 7-year-old child and another for adults; the adult version came out in a noticeably different style even though the topic was identical. Audience is the strongest lever you have over how the finished video feels.

Common mistakes.
  • Expecting it to be fast. If nothing appears for several minutes, that is normal. The creator saw roughly 10–20 minutes on Opus 5.5 medium.
  • Expecting an identical re-run. Because the model is non-deterministic, two runs of the same prompt will differ. Do not treat the first video as the only possible one.
  • Only changing the topic for a new audience. If you want a different feel (for example, grown-ups instead of kids), change [audience], not just the subject.
  • Forgetting to remake the voice-over. Changing topic or audience changes the script, so you need a new voice-over from step 4 before Prompt 2, not the old audio.
How much effort is “medium”, and why not go higher?

Effort is how hard the model works on a request; higher effort can mean more thorough results but takes longer. The creator reports that medium gave enough quality and was faster, and that pushing to a higher effort on another video came out worse and much slower. The lesson is practical: more effort is not automatically better here, so medium is a sensible default for this task.
