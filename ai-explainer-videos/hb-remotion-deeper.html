Remotion, in more depth

Compositions, sequences, interpolation, spring, props and the render CLI beyond the basics.

Remotion lets you make real videos out of React code: you describe each frame as a component, and Remotion draws every frame and encodes them into a video file. Step 8 introduces the idea and step 9 builds our 2D explainer with it. This chapter goes a little deeper into the pieces you will reach for next: compositions, sequences, the interpolate and spring helpers, parameterised renders with props, and the render command line. Everything here matches the Remotion 4.x version this project uses.

Compositions: the thing you render

A composition is one renderable video: a React component plus the facts needed to turn it into frames. You register compositions in your root file, giving each an id, a component, a frame rate, a pixel size, and a length in frames. Our project registers two, Explainer2D and Explainer3D, both at 1280 by 720, 30 fps, and a durationInFrames that covers the whole voice-over.

<Composition
  id="Explainer2D"
  component={Explainer2D}
  durationInFrames={1119}
  fps={30}
  width={1280}
  height={720}
/>

The length is deliberate: our voice-over is 37.295 seconds, and at 30 fps that is 1119 frames, so the video is exactly as long as the narration. Get this wrong and your video either cuts off the ending or trails silence. Because the component is just React, the id is how you refer to this particular video everywhere else, including on the command line.

The frame clock

Inside the component, useCurrentFrame tells you which frame is being drawn, and useVideoConfig gives you the fps and size. Converting the frame to seconds with frame / fps is the single most useful line in Remotion, because it lets you drive animation from time. Our 2D composition does exactly that, then hands the time to one pure drawing function so the preview and the final render are identical.

Sequence: placing things in time

When a video has parts that start at different moments, you wrap each part in a Sequence. A sequence shifts the frame clock for everything inside it: a child of <Sequence from={30}> sees frame 0 when the outer video is at frame 30. Add durationInFrames to also limit how long that part is shown. This keeps each scene's animation written as if it started at zero, which is far easier to reason about than offsetting every value by hand.

<Sequence from={0} durationInFrames={170}>
  <IntroScene />
</Sequence>
<Sequence from={170} durationInFrames={155}>
  <HeavyScene />
</Sequence>
Our explainer does not use Sequence. Why mention it?

Our 2D composition is one continuous drawing driven by time, with scenes fading in and out inside a single function, so it needs no sequences. That is a perfectly good design for a tightly timed piece. But as soon as you build scenes as separate components that start at different moments, Sequence is the standard tool, and you will see it in almost every Remotion project. It is worth recognising even though our code chose the simpler path.

interpolate and spring: turning a frame into a value

Animation is mostly mapping the current frame onto some value: an opacity, a position, a scale. The interpolate helper does this directly. You give it the input, an input range and an output range, and it returns the mapped value. A fourth options argument lets you clamp the ends so the value does not shoot past your range, and apply an easing curve.

const opacity = interpolate(frame, [0, 30], [0, 1], {
  extrapolateLeft: "clamp",
  extrapolateRight: "clamp",
});

That reads as: over the first 30 frames, fade from 0 to 1, and hold at 1 afterwards. For movement that should feel bouncy or physical, spring is the other workhorse. It needs the current frame and the fps, and it returns a value that eases toward its target the way a real spring settles. You can shape it with a config and bound it with a duration.

const scale = spring({
  frame,
  fps,
  config: { damping: 200 },
});
Easy mistakes with interpolate
  • Input and output ranges of different lengths; they must have the same number of points.
  • Forgetting to clamp, so a value keeps growing past the end of your range.
  • Ranges that are not increasing on the input side, which is not allowed.

Props: one composition, many videos

A composition can take props, exactly like any React component, so the same code can render many different videos. You give sensible defaultProps on the composition, read them in the component, and override them at render time. This is how you would turn our single-topic explainer into a template: pass the topic and audience as props instead of hard-coding them.

<Composition
  id="Explainer2D"
  component={Explainer2D}
  durationInFrames={1119}
  fps={30}
  width={1280}
  height={720}
  defaultProps={{ topic: "how airplanes fly" }}
/>

On the command line you override those defaults with a JSON string, so one composition becomes a little video factory. That pairs naturally with the non-determinism point from the prompting chapter: where the AI workflow gives a fresh result each run, a parameterised Remotion render gives the same video every time for the same props.

The render command line

Previewing happens in the Remotion Studio in your browser, but the finished file comes from the render command. You point it at the entry file, name the composition by its id, and give an output path. Remotion launches a headless browser, draws every frame, and encodes them, muxing in any Audio you included.

npx remotion render src/index.ts Explainer2D out/airplane-2d.mp4
npx remotion render src/index.ts Explainer2D out/topic.mp4 \
  --props='{"topic":"how boats float"}'

This is the exact shape of the command that produced our real files; step 11 walks through the 2D render and step 15 the 3D one, which needs an extra flag so WebGL works in the headless browser. The render respects your remotion.config.ts, where this project sets the image format and the concurrency.

Aspect ratios and sizes

The composition's width and height set the shape and resolution of the output. Our explainer is 1280 by 720, a 16:9 widescreen frame suited to a computer or a landscape player. For a phone-first platform you would use a tall frame such as 1080 by 1920 (9:16); for a square post, 1080 by 1080. Changing the size changes how much room your layout has, so it is a design decision as much as a technical one; the publishing chapter covers which shape fits which platform.

Recap
  • A composition is a component plus its id, fps, size and durationInFrames; register it in your root file.
  • useCurrentFrame and frame / fps turn the frame clock into time you can animate from.
  • Sequence shifts the clock so scenes that start at different moments are easy to write.
  • interpolate maps a frame onto a value with optional clamping and easing; spring gives physical motion.
  • Props plus --props turn one composition into a reusable, reproducible video template.
  • The render command names a composition by id and writes an MP4; width and height set the aspect ratio.
