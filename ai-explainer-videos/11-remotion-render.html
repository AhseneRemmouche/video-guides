Render the explainer to an MP4

Running remotion render to turn the composition into a real video file, and the same idea as a single standalone HTML page.

Extension - our own code, rendered to a real MP4

Everything so far has been preview. This step turns the composition into a real file on disk: airplane-2d.mp4, a video you can play anywhere, upload, or send to a friend. We also show a second way to get the same picture with no build step at all, using a single HTML file. This is the final extension step; the result below is the actual file we rendered.

Render with Remotion

Rendering means replaying the composition once, frame by frame, and writing the pictures and the sound into a video file. Remotion does this by opening your component in a headless browser (a real browser with no window), screenshotting every frame, and then handing the frames and the voice-over to FFmpeg, which packs them into an MP4.

  1. Make sure public/voiceover.mp3 is in place (Step 10) and the studio preview looks right.
  2. From the project folder, run the render command: 
    npx remotion render src/index.ts Explainer2D out/airplane-2d.mp4
  3. Wait for the progress bar to reach 100%. Remotion creates the out/ folder if it is missing and writes out/airplane-2d.mp4.
  4. Open the file in any video player and check the picture and voice-over play together.

What is a headless browser, and why does Remotion use one?

A headless browser is a full browser engine (Chromium) running with no visible window. Because your composition is a web page, the surest way to capture exactly what you would see is to open it in a real browser and screenshot each frame. "Headless" just means it does this invisibly, on a server or in a terminal, with no screen attached.

What is FFmpeg?

FFmpeg is the standard open-source tool for turning sequences of pictures plus an audio track into a video file. Remotion bundles it, so you do not install it separately. It takes the screenshotted frames and the voice-over and encodes them into the MP4 you get at the end.

The render settings: remotion.config.ts

This small file tweaks how the render runs. It applies to remotion render and the studio, and lives at the project root next to package.json.

import { Config } from "@remotion/cli/config";
Config.setVideoImageFormat("jpeg");
Config.setConcurrency(2);

Line by line

LineCodeWhat it does & why

2Config.setVideoImageFormat("jpeg");Tells Remotion to screenshot each frame as a JPEG. JPEG frames are smaller and faster to write than PNG, which keeps the render quick for a photographic-style scene like ours.
3Config.setConcurrency(2);Renders two frames at once (two browser tabs). More concurrency is faster but uses more memory; 2 is a safe, modest setting.
What you should see. When the render finishes you get out/airplane-2d.mp4: about 37.35 seconds long, H.264 video with AAC audio, roughly 2.5 MB. It plays in any browser or media player, picture and narration in sync.
What are MP4, H.264 and AAC?

MP4 is the container: one file that holds a video track and an audio track together. H.264 is the codec that compresses the pictures, and AAC is the codec that compresses the sound. This combination plays almost everywhere, which is why Remotion uses it by default.

The no-build alternative: one HTML file

Remotion needs Node, an install step and a render. If you only want the animation in a browser, there is a lighter path: a single, self-contained HTML file that draws the same scene with no build step. It reuses the very same buildStage logic (here written inline as render(t)), so the picture matches the Remotion version.

<script>
// The whole animation is a pure function of time: render(t) draws the exact frame
// for second t. The Play button just advances t from the audio clock; a ?t=SECONDS
// URL parameter freezes one frame (used for screenshots and for rendering to video).
const TL = {"fps":30,"durationSec":37.295,"lines":[
  {"i":0,"start":0.0,"end":5.664},{"i":1,"start":5.664,"end":10.842},
  {"i":2,"start":10.842,"end":14.696},{"i":3,"start":14.696,"end":17.03},
  {"i":4,"start":17.03,"end":22.174},{"i":5,"start":22.174,"end":26.443},
  {"i":6,"start":26.443,"end":30.412},{"i":7,"start":30.412,"end":34.691},
  {"i":8,"start":34.691,"end":37.295}
]};
const $ = (id) => document.getElementById(id);
const clamp = (x, a, b) => Math.min(b, Math.max(a, x));
const lerp = (a, b, p) => a + (b - a) * p;
// smooth 0..1 ramp used everywhere for gentle easing
const ease = (p) => (p <= 0 ? 0 : p >= 1 ? 1 : p * p * (3 - 2 * p));

// progress 0..1 through scene i (by its timeline line)
function sp(t, i) {
  const l = TL.lines[i];
  return clamp((t - l.start) / (l.end - l.start), 0, 1);
}
// fade a scene in at its start and out near its end
function sceneOpacity(t, i) {
  const l = TL.lines[i], d = l.end - l.start;
  const fin = clamp((t - l.start) / Math.min(0.5, d / 3), 0, 1);
  const fout = clamp((l.end - t) / Math.min(0.5, d / 3), 0, 1);
  return (t >= l.start - 0.01 && t <= l.end + 0.01) ? Math.min(fin, fout) : 0;
}

function planePath(cx, cy, s, flip) {
  const dir = flip ? -1 : 1;
  return `<g transform="translate(${cx} ${cy}) scale(${s * dir} ${s})">
    <ellipse cx="0" cy="0" rx="120" ry="30" fill="#e5e7eb"/>
    <path d="M -120 0 q -40 0 -55 -8 l 10 8 l -10 8 q 15 -8 55 -8 Z" fill="#cbd5e1"/>
    <polygon points="20,-8 95,-70 60,-6" fill="#93c5fd"/>
    <polygon points="20,8 95,70 60,6" fill="#60a5fa"/>
    <polygon points="-95,-6 -120,-48 -80,-6" fill="#93c5fd"/>
    <circle cx="70" cy="-2" r="7" fill="#1d4ed8"/><circle cx="90" cy="-1" r="6" fill="#1d4ed8"/>
  </g>`;
}

function render(t) {
  t = clamp(t, 0, TL.durationSec);
  for (let i = 0; i < 9; i++) $('s' + i).style.opacity = sceneOpacity(t, i);

  // Scene 0: plane drifts left->right, clouds drift slowly
  let p = sp(t, 0);
  $('plane0').innerHTML = planePath(lerp(120, 1160, ease(p)), lerp(250, 210, p), 1.0, false);
  $('clouds0').setAttribute('transform', `translate(${-40 * p} 0)`);

  // Scene 1: elephants stack onto the scale one by one
  p = sp(t, 1);
  let eh = '';
  const n = Math.floor(ease(p) * 10 + 0.001);
  for (let k = 0; k < n; k++) {
    const row = Math.floor(k / 5), col = k % 5;
    eh += `<g transform="translate(${500 + col * 60} ${520 - row * 44})"><ellipse rx="26" ry="18" fill="#9ca3af"/><circle cx="-22" cy="2" r="10" fill="#9ca3af"/></g>`;
  }
  $('elephants').innerHTML = eh;

  // Scene 4: plane accelerates along the runway, streamlines trail the wing
  p = sp(t, 4);
  const px = lerp(-150, 900, ease(p));
  $('plane4').innerHTML = planePath(px, 520, 0.9, false);
  let marks = '';
  for (let k = 0; k < 12; k++) { const mx = ((k * 140) - (px * 0.6) % 140 + 1400) % 1400 - 60; marks += `<rect x="${mx}" y="652" width="70" height="10"/>`; }
  $('runwayMarks').innerHTML = marks;
  let st = '';
  for (let k = 0; k < 3; k++) { const y = 495 + k * 14; st += `<path d="M ${px - 10} ${y} q -120 ${-20 + k * 12}, -260 ${k * 6}" opacity="${0.3 + 0.2 * k}"/>`; }
  $('stream4').innerHTML = st;

  // Scene 5: two streams race over/under the airfoil; the top one leads
  p = sp(t, 5);
  const adv = ease(p);
  $('streamTop').innerHTML = `<path d="M 300 405 C 520 330, 820 330, ${lerp(300, 1000, adv)} 388"/>`;
  $('streamBot').innerHTML = `<path d="M 300 455 C 520 470, 820 470, ${lerp(300, 820, adv * 0.72)} 452"/>`;

  // Scene 6: lift arrows grow and the plane rises
  p = sp(t, 6);
  $('plane6').innerHTML = planePath(640, lerp(470, 300, ease(p)), 1.1, false);
  const la = lerp(0, 90, ease(p));
  $('liftArrows').innerHTML = [520, 640, 760].map(x => `<line x1="${x}" y1="560" x2="${x}" y2="${560 - la}"/><polygon points="${x - 10},${560 - la} ${x + 10},${560 - la} ${x},${560 - la - 20}"/>`).join('');

  // Scene 7: thrust forward + lift up on a steady plane
  p = sp(t, 7);
  $('plane7').innerHTML = planePath(640, 400, 1.15, false);
  const g = ease(Math.min(1, p * 1.4));
  $('thrust').innerHTML = `<line x1="${520 - 120 * g}" y1="400" x2="520" y2="400"/><polygon points="520,390 520,410 545,400"/>`;
  $('lift7').innerHTML = `<line x1="640" y1="360" x2="640" y2="${360 - 120 * g}"/><polygon points="630,${360 - 120 * g} 650,${360 - 120 * g} 640,${340 - 120 * g}"/>`;

  // Scene 8: happy fly-off
  p = sp(t, 8);
  $('plane8').innerHTML = planePath(lerp(500, 820, ease(p)), lerp(430, 360, p), 1.25, false);

  $('clock').textContent = t.toFixed(1) + 's / ' + TL.durationSec.toFixed(1) + 's';
}

// Playback: drive render() from the audio clock so visuals stay in sync.
const vo = $('vo');
let raf = 0;
function loop() { render(vo.currentTime); if (!vo.paused && !vo.ended) raf = requestAnimationFrame(loop); }
$('play').addEventListener('click', () => {
  if (vo.paused) { vo.play(); raf = requestAnimationFrame(loop); $('play').textContent = 'Pause'; }
  else { vo.pause(); cancelAnimationFrame(raf); $('play').textContent = 'Play with voice-over'; }
});

// Freeze one frame when a ?t= parameter is present (screenshots / frame rendering).
const qp = new URLSearchParams(location.search);
const frozen = qp.get('t');
render(frozen !== null ? parseFloat(frozen) : 0);
window.renderFrame = render;   // exposed so a headless renderer can step frames
</script>
</body>
</html>

The ?t=SECONDS freeze is the clever bit. Open explainer.html normally and press play to watch it. Add ?t=22 to the URL and the page draws the single frame at 22 seconds and holds it still, with no playback. That is how a still picture is pulled out of a moving scene: perfect for a screenshot, a thumbnail, or feeding a frame to a renderer.

Common mistakes.
  • Forgot npm install. npx remotion fails with command not found or Cannot find module if the libraries were never installed. Run npm install first.
  • Wrong composition id or path. The id must be Explainer2D (capital E, capital D) and the entry must be src/index.ts. A typo gives No composition with the ID … found.
  • Forgot public/voiceover.mp3. The render still produces a file, but it is silent. Put the voice-over in public/ before rendering.
  • Standalone page shows no sound. The <audio> src on line 113 points at ../remotion/public/voiceover.mp3; if you move explainer.html, fix that relative path.
Recap
  • npx remotion render src/index.ts Explainer2D out/airplane-2d.mp4 writes the finished video.
  • Remotion screenshots each frame in a headless browser, then FFmpeg packs the frames and voice-over into an MP4 (H.264 + AAC).
  • Our real render is about 37.35 s, AAC audio, roughly 2.5 MB, with the local stand-in voice-over.
  • remotion.config.ts sets JPEG frames and a concurrency of 2 to keep the render fast.
  • explainer.html needs no build step, reuses the same drawing, and freezes any moment with ?t=SECONDS.
