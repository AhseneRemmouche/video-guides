Three.js inside Remotion with the three integration

Using @remotion/three so a react-three-fiber scene renders deterministically each frame and records cleanly to MP4.

Extension - our own code, rendered to a real MP4

In Step 12 the Three.js scene ran its own animation loop in a live browser. That is perfect for watching, but not for recording: a loop tied to wall-clock time gives a slightly different result every run. This step takes the same airplane and rebuilds it as a Remotion composition, so every frame is drawn on purpose and the whole thing records cleanly to a video file in Step 15.

The bridge between the two worlds is @remotion/three, Remotion's small integration with react-three-fiber. Instead of calling Three.js by hand (new THREE.Mesh(...), scene.add(...)), you describe the same scene as JSX — the HTML-like syntax React uses. This page is an extension; the video never touches code.

New to react-three-fiber? How JSX becomes Three.js objects

react-three-fiber (often shortened to r3f) lets you write a Three.js scene as React components. Every lowercase JSX tag maps to a Three.js class: <mesh> is a THREE.Mesh, <boxGeometry> is a THREE.BoxGeometry, <meshStandardMaterial> is a THREE.MeshStandardMaterial, and so on — the tag is the class name with a lowercase first letter. Nesting a geometry and a material inside a <mesh> is the JSX way of saying "this mesh uses this geometry and this material". The args prop is the list of constructor arguments, so <boxGeometry args={[0.7, 0.06, 3.4]} /> is exactly new THREE.BoxGeometry(0.7, 0.06, 3.4). You describe what the scene contains; r3f builds and wires the objects for you.

ThreeCanvas: a canvas that draws one frame at a time

A normal r3f app runs its own loop, like the standalone page. @remotion/three swaps that for ThreeCanvas, a canvas wired to Remotion's clock. It draws exactly one frame when asked, using the frame number Remotion is currently on. Because the picture is a pure function of that number, the same frame always looks the same — which is what makes it safe to record.

Why "deterministic per frame" matters

Deterministic means: same input, same output, every time. The standalone page used performance.now() (real elapsed time), so two runs never line up frame-for-frame. Remotion instead gives each frame a fixed number through useCurrentFrame. Our component turns that number into positions with plain maths, so frame 300 is identical on every machine and every run. When Remotion renders the video it simply asks for frames 0, 1, 2, … in order and saves each one — no loop, no timing drift, no surprises.

The component

This file defines three pieces: a Plane component (the airplane, animated), a Cloud component (reused three times), and the top-level ThreeExplainer that puts them in a ThreeCanvas with lights, a background and the voice-over. It is registered as the Explainer3D composition in Root.tsx from Step 08.

import React from "react";
import { AbsoluteFill, Audio, useCurrentFrame, useVideoConfig, staticFile, interpolate } from "remotion";
import { ThreeCanvas } from "@remotion/three";

// A 3D airplane built from primitive meshes (no model files), animated by the
// frame clock. @remotion/three's ThreeCanvas is a react-three-fiber canvas that
// renders deterministically for each frame, so it records cleanly to MP4.

const Plane: React.FC = () => {
  const frame = useCurrentFrame();
  const { fps, durationInFrames } = useVideoConfig();
  const t = frame / fps;
  // Gentle flight: drift across, bob up and down, bank into the turn.
  const x = interpolate(frame, [0, durationInFrames], [-3, 3]);
  const y = Math.sin(t * 1.2) * 0.4;
  const bank = Math.sin(t * 1.2) * 0.25;
  const yaw = Math.sin(t * 0.6) * 0.15;
  return (
    <group position={[x, y, 0]} rotation={[0, yaw, bank]}>
      {/* fuselage */}
      <mesh rotation={[0, 0, Math.PI / 2]}>
        <cylinderGeometry args={[0.28, 0.28, 2.4, 24]} />
        <meshStandardMaterial color="#e5e7eb" metalness={0.2} roughness={0.5} />
      </mesh>
      {/* nose cone */}
      <mesh position={[1.3, 0, 0]} rotation={[0, 0, -Math.PI / 2]}>
        <coneGeometry args={[0.28, 0.5, 24]} />
        <meshStandardMaterial color="#cbd5e1" />
      </mesh>
      {/* main wings */}
      <mesh position={[0, 0, 0]}>
        <boxGeometry args={[0.7, 0.06, 3.4]} />
        <meshStandardMaterial color="#60a5fa" />
      </mesh>
      {/* tail wing */}
      <mesh position={[-1.0, 0, 0]}>
        <boxGeometry args={[0.4, 0.05, 1.4]} />
        <meshStandardMaterial color="#93c5fd" />
      </mesh>
      {/* tail fin */}
      <mesh position={[-1.0, 0.35, 0]}>
        <boxGeometry args={[0.4, 0.6, 0.05]} />
        <meshStandardMaterial color="#93c5fd" />
      </mesh>
    </group>
  );
};

const Cloud: React.FC<{ pos: [number, number, number]; speed: number }> = ({ pos, speed }) => {
  const frame = useCurrentFrame();
  const { fps } = useVideoConfig();
  const drift = ((pos[0] - (frame / fps) * speed + 12) % 12) - 6;
  return (
    <group position={[drift, pos[1], pos[2]]}>
      {[[0, 0, 0], [0.7, 0.1, 0], [-0.7, 0.05, 0], [0.3, 0.35, 0]].map((o, k) => (
        <mesh key={k} position={o as [number, number, number]}>
          <sphereGeometry args={[0.6, 16, 16]} />
          <meshStandardMaterial color="#ffffff" />
        </mesh>
      ))}
    </group>
  );
};

export const ThreeExplainer: React.FC = () => {
  const { width, height } = useVideoConfig();
  return (
    <AbsoluteFill style={{ backgroundColor: "#8ec5ff" }}>
      <ThreeCanvas width={width} height={height} camera={{ position: [0, 1, 7], fov: 55 }}>
        <ambientLight intensity={1.1} />
        <directionalLight position={[5, 6, 5]} intensity={1.6} />
        <color attach="background" args={["#8ec5ff"]} />
        <Cloud pos={[-4, -1.6, -3]} speed={0.6} />
        <Cloud pos={[3, 1.8, -5]} speed={0.4} />
        <Cloud pos={[0, -2.2, -2]} speed={0.8} />
        <Plane />
      </ThreeCanvas>
      <Audio src={staticFile("voiceover.mp3")} />
    </AbsoluteFill>
  );
};

What you should see. With the Remotion project from Step 08 installed, running npx remotion studio and opening the Explainer3D composition shows the 3D airplane in the preview, with the timeline scrubber moving it exactly as Step 15 will render it. Scrubbing to the same frame always shows the same picture, and the voice-over plays along the timeline.
Common mistakes.
  • Using a plain <Canvas> from react-three-fiber. That runs its own loop and will not record deterministically. Inside Remotion you must use ThreeCanvas from @remotion/three.
  • Animating from Date.now() or performance.now(). Those read real time, so the render drifts. Drive every value from useCurrentFrame instead, as this file does.
  • Capitalised 3D tags. r3f tags are lowercase (<mesh>, <boxGeometry>). A capitalised <Mesh> is read as a missing React component and errors.
  • Forgetting args. A geometry with no args uses Three.js defaults, so your careful sizes are ignored and shapes look wrong.
Recap
  • @remotion/three's ThreeCanvas lets a react-three-fiber scene render one frame at a time inside Remotion.
  • Lowercase JSX tags map to Three.js classes (<mesh>, <boxGeometry>, <meshStandardMaterial>), and args is the constructor arguments.
  • All motion comes from useCurrentFrame via plain maths and interpolate, so each frame is deterministic.
  • The component mirrors Step 12's scene — same primitives, lights, camera and clouds — plus an Audio track for the voice-over.
  • It is registered as the Explainer3D composition in Root.tsx, ready to render in Step 15.
