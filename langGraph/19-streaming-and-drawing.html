Stream Steps & Draw Your Graph

stream_mode updates and values, and draw_mermaid to picture any graph.

Extension · verified against LangGraph 1.2.11

Extension: not in the video. module1/12_graph_stream_and_draw.py was run against LangGraph 1.2.11 with the offline fake model from step 15. Every output block on this page was copied from that run. Graph 2 needs no model at all, so its output is exactly what you'll get; for the agent part, only the model's final sentence and the tool-call ID will differ with a real key.

What that proves: the stream modes, the order of the chunks and the Mermaid text. What it doesn't: how fast a real model streams, or its wording.

Goal

Every graph so far was run with graph.invoke(...): you wait, and at the end you get the final state. In Studio you saw much more: each node lighting up in turn, every message appearing as it was produced. In this step you get the same view from Python with stream, and you learn to draw any graph as a picture with one line of code.

Both are everyday debugging tools ("which node ran, in which order, and what did it change?"), and streaming is how real chat apps show progress instead of a frozen screen.

Create the file

  1. Create module1/12_graph_stream_and_draw.py

    New file in module1 with the code below. It doesn't define a new graph; it loads graph 2 (step 8) and graph 8 (step 13, as fixed in step 15) and looks at them in new ways.

  2. Run it from the project root 
    python module1/12_graph_stream_and_draw.py

    Parts 1–3 use graph 2, which needs no key. Part 4 loads graph 8, which needs OPENAI_API_KEY in .env; without it, parts 1–3 print and then the run stops with openai.OpenAIError: Missing credentials ... (verified).

import importlib.util
from pathlib import Path

from langchain.messages import HumanMessage


def load(file_name):
    """Load one of the numbered course files (their names start with a digit)."""
    spec = importlib.util.spec_from_file_location(file_name, Path(__file__).with_name(file_name))
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    return module


# 1. Draw a graph as Mermaid text (paste it into https://mermaid.live to see the picture)
conditional = load("2_graph_conditional_edge.py").graph
print(conditional.get_graph().draw_mermaid())

# 2. Stream the updates: one chunk per node, as soon as that node finishes
for chunk in conditional.stream({"graph_str": "hello I am new "}, stream_mode="updates"):
    print("update:", chunk)

# 3. Stream the full state after every step
for state in conditional.stream({"graph_str": "hi I am new "}, stream_mode="values"):
    print("state:", state)

# 4. Watch the agent loop step by step: model -> tools -> model
agent = load("8_graph_agent.py").graph
for chunk in agent.stream({"messages": [HumanMessage(content="What is 12 multiplied by 7?")]},
                          stream_mode="updates"):
    for node, update in chunk.items():
        last = update["messages"][-1]
        print(f"[{node}] {type(last).__name__}: {last.content or last.tool_calls}")

New to looping over stream? Generators in one minute

invoke returns a value. stream returns a generator: an object that produces values one at a time, when you ask for the next one. A for loop keeps asking until it's exhausted.

That's what makes streaming "live": the graph runs node 1, hands you its chunk, your loop body runs (prints it), and only then does the graph continue with the next node. Nothing runs until you start looping.

chunks = graph.stream(inputs, stream_mode="updates")   # nothing has run yet
for chunk in chunks:                                    # runs step by step
    print(chunk)
# want them all at once?  list(graph.stream(...))

New to Mermaid? Diagrams written as text

Mermaid is a small language for describing diagrams in plain text; a renderer turns the text into a picture. GitHub, GitLab, many documentation tools and VS Code extensions render it, which is why LangGraph can output it without any drawing library.

  • The block between --- lines is configuration (straight lines instead of curves).
  • graph TD; means a flowchart drawn Top → Down.
  • node1(node1) declares a node with rounded corners; ([...]) is a pill shape, used for start and end.
  • --> is a normal edge; -.-> is a dotted edge. LangGraph uses dotted for conditional edges, exactly like Studio.
  • classDef lines set colours; :::first applies a class to a node.

To see the picture, copy everything from --- to the last classDef line, open mermaid.live in your browser, and paste it into the code panel on the left. The diagram appears on the right; you can download it as PNG or SVG. In a GitHub README or issue, put the text inside a code block marked ```mermaid and GitHub draws it for you.

Two related methods exist on the same object. draw_mermaid_png() returns PNG image bytes, rendered by default through the online mermaid.ink service (so it needs internet). draw_ascii() prints the graph as text characters, but needs an extra package: without it we got ImportError: Install grandalf to draw graphs: `pip install grandalf`.

ModeEach chunk isUse it when
"updates"{node_name: what_that_node_returned}, one per nodeYou want to know which node ran and what it changed: logs, progress messages ("Calling the calculator…"), debugging routing. It is also what you get when you leave stream_mode out (verified with graph 2).
"values"The full state after each step, starting with the inputYou want to redraw the whole thing each time, e.g. a UI that always shows the full conversation.

Notice that graph 2's nodes return the whole string, so its updates look like full states. With MessagesState the difference is big: an update has only the new message, while a value has the entire conversation so far. LangGraph 1.2.11 accepts these modes: "values", "updates", "checkpoints", "tasks", "debug", "messages" (the model's text token by token, for typing-style chat UIs) and "custom". You can also pass a list, e.g. stream_mode=["updates", "values"]; each chunk then becomes a pair such as ('updates', {'node1': {...}}) (verified).

When streaming matters

In a terminal script, the difference between invoke and stream is mostly convenience. In an app with a user interface it's the difference between a screen that looks frozen for ten seconds and one that keeps the user informed. An agent that calls three tools and then writes a long answer can easily take that long.

  • Progress with "updates": show "Calling multiply…" as soon as the tool-call chunk arrives, then the result.
  • Typing effect with "messages": show the answer word by word while the model writes it, like ChatGPT.
  • Debugging: print every update to see exactly which branch a conditional edge took and what each node changed, without opening Studio.

Common mistakes

  • Printing the generator instead of looping. print(graph.stream(...)) shows <generator object Pregel.stream at 0x...> (verified) and runs nothing. Loop over it, or wrap it in list(...).
  • Expecting the final state from "updates". Updates are pieces. If you need the end result too, use "values" and keep the last item, or call invoke.
  • Misspelling the mode, e.g. "update" instead of "updates". There's no error: with "update" the loop simply received no chunks at all (verified). If a stream prints nothing, check the spelling first.
  • Pasting only part of the Mermaid text into mermaid.live. Copy from the first --- to the last line, or at least from graph TD; on.
  • Running part 4 without a key. Graph 8 creates ChatOpenAI when it loads, so the script stops with OpenAIError after part 3.
  • Calling draw_ascii() without installing grandalf: ImportError. Stick with draw_mermaid(), which needs nothing extra.

Recap
  • graph.stream(input, stream_mode=...) takes the same input as invoke but yields a chunk after every step; loop over it with for.
  • "updates" gives {node_name: update} per node; "values" gives the full state after each step, starting with the input (verified: 2 updates and 3 states for graph 2).
  • Streaming the agent shows the loop: AI tool call → ToolMessage 84 → final AI message.
  • graph.get_graph().draw_mermaid() prints Mermaid text; paste it into mermaid.live or a GitHub ```mermaid block to see the picture. Dotted arrows are conditional edges.
  • In apps, streaming is how you show progress and typing effects instead of a frozen screen.
