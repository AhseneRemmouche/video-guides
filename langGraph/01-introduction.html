The course teaches LangGraph, a Python library for building AI applications as a graph of small steps. It is the follow-up to the same channel's LangChain crash course, but you do not need that course to follow this one. Every word you need is explained here or in the glossary.

New to AI apps? What a model, a tool and an agent are

A large language model (LLM), such as OpenAI's gpt-4o used in this course, is a program that reads text and writes text. In Python you talk to it through a chat model object: you send a list of messages, it sends back one new message.

On its own, a model can only write. It cannot do maths reliably, read a file or check the weather. A tool is an ordinary Python function you offer to the model (for example multiply(a, b)). The model cannot run it, but it can ask for it: "please call multiply with 12 and 7". Your program runs the function and hands the result back.

An agent is a model inside a loop: ask the model, run any tool it asked for, give it the result, ask again, until it answers without asking for a tool. That loop is the agent loop, and graph 8 builds it by hand. LangGraph is the library that lets you draw this loop (and many other shapes) as a graph.

The shape grows with you

The graphs do not just get longer, they change shape. A picture of each shape helps you know what to expect. You will draw these yourself in LangGraph Studio from step 06 on.

Besides the nine graphs, the repo has a main.py that you paste in during setup (step 04). It is LangSmith's own quickstart, a tiny weather agent, used only to prove that your keys work. You will not understand it yet, and that is fine: the presenter says so too.

What you will be able to do afterwards

  • Explain any LangGraph program with three words: state (the data that travels), nodes (Python functions that change it) and edges (the roads between them).
  • Build a graph with StateGraph, add_node, add_edge and add_conditional_edges, then compile and invoke it.
  • Write a routing function that sends the state left or right.
  • Put an OpenAI model inside a node and keep a chat history with MessagesState and its reducer add_messages.
  • Give a model tools and build the agent loop by hand, the same loop LangChain's create_agent builds for you.
  • Add memory with a checkpointer and a thread_id.
  • Run any graph in LangGraph Studio with langgraph dev, and read its trace in LangSmith.

How this guide adds to the video

The video is the teacher. This guide is the notebook you would write if you had unlimited time. On top of explaining every line, it does three things the video cannot:

  1. Verified code. Every file comes from the presenter's repository (commit e42570d) and was run against the exact versions the repo locks: LangGraph 1.2.11, LangChain 1.3.18, langchain-openai 1.6.0, Python 3.12. To run the model graphs without a paid key, a fake chat model stood in for OpenAI. That proves the wiring, routing, tool calls, loops, memory and error messages; it does not prove the exact words gpt-4o writes.
  2. The in-between versions. When the presenter runs a first version, makes a mistake on screen or writes something by hand before using a shortcut, you get that version too, in a block titled "Try the video's version", with the exact error it produces.
  3. Fixes and extensions. Running the repo turned up a few real bugs. The biggest: graph 9 uses HumanMessage without importing it, so it crashes with a NameError. Steps 15–19 fix them and then complete the README's suggested exercises: a division tool with error handling, memory that survives a restart (SQLite), tests with pytest that need no API key, and streaming plus drawing your graph as Mermaid.

New to Python? How much do you need to know?

You can follow along if you know what a variable is and roughly what a function is. Everything else the course uses (imports, dictionaries, lists, type hints, TypedDict) is explained the first time it appears.

The single most important Python idea for LangGraph: a node is just a function that takes the state and returns an update. If you can write def add_one(x): return x + 1, you can write a LangGraph node.

New to graphs? Do I need maths for this?

No. A graph here is a drawing of boxes (nodes) joined by arrows (edges), like cities joined by roads on a map. LangGraph runs your boxes in the order the arrows say. Step 05 explains it with the presenter's road-trip analogy, with no code and no maths.

Video vs repo. The repo has every course file, but two things in it are surprising at first: there is no 7_… file (skipped on purpose), and .env.example lists a TAVILY_API_KEY that no file uses. Neither is a mistake on your side.

What you should see after this page: you know the nine graphs, the stage each belongs to, and where the extension steps start. Nothing to install yet; setup is step 04.

Common mistakes

  • Jumping straight to the agent (graph 8). It is three ideas stacked on top of each other. If graph 6 is not clear, graph 8 will not be either.
  • Skipping step 05 because it has no code. The road-trip picture of state, nodes and edges is what every later page relies on.
  • Looking for 7_graph…. It does not exist.
  • Expecting it to be free. LangGraph, LangSmith's free tier and Tavily's free tier cost nothing, but every OpenAI call uses a little of your credit.
