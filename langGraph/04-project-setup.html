New to the terminal? What it is and how to open it in VS Code

The terminal is a window where you type commands instead of clicking. A command is a program name followed by words that tell it what to do, for example python --version. Press Enter to run it; its output appears below.

The presenter uses the terminal inside VS Code: Terminal → New Terminal, or Ctrl+`. On Windows it starts PowerShell (as in the video); on macOS it is usually zsh, on Linux bash. Most commands below are identical everywhere; where they differ, both versions are given.

A terminal always works "inside" one folder, shown in the prompt (for example PS D:\ACL\LangGraph_ACL>). Files you create with commands land in that folder. Opening the project folder in VS Code first makes the terminal start there.

    New to uv? Why use it instead of plain pip

    uv is one fast tool that replaces several older ones. With pip alone you create a virtual environment with python -m venv, install with pip install, and keep a requirements.txt up to date by hand. uv does all of it:

    • uv init creates a project with a pyproject.toml that lists your dependencies.
    • uv venv creates the virtual environment, and downloads the Python version you ask for if needed.
    • uv add installs a package and records it in pyproject.toml and pins the exact versions of everything in a lockfile, uv.lock.
    • uv sync makes .venv match the lockfile exactly. That is how someone who clones the repo gets the same versions in seconds.

    New to virtual environments? What they are and why every project needs one

    Without one, every package you install goes into the single global Python on your computer. Project A may need version 1 of a library and project B version 2; globally you can only have one, and sooner or later something breaks.

    A virtual environment (venv) is a folder, .venv, holding a Python interpreter and its own packages. Each project gets its own. You can delete .venv at any time and rebuild it with uv sync, so it is never committed to Git.

    New to Git? What .gitignore is for

    Git is version control: it records snapshots of your files so you can go back in time and share the project, for example on GitHub. By default it offers to track every file in the folder.

    .gitignore is a plain text file listing names and patterns Git must pretend do not exist: one per line, # for comments, a trailing / for folders, * as a wildcard (*.pyc). Ignored files stay on your disk; they just never go into a commit.

    It only works before a file is committed. If a secret was committed once, removing it later is not enough: it is still in the history. You must revoke the key and create a new one.

    New to environment variables? What a .env file is

    An environment variable is a named value that the operating system hands to every program it starts, like a sticky note on the program's door. Libraries read them by name: the openai package reads OPENAI_API_KEY, the langsmith package reads the LANGSMITH_… names.

    An .env file is a convenient place to keep those values: one NAME=value per line. But Python does not read it by itself. Something must load it into the environment first. In plain Python scripts that is load_dotenv() from the python-dotenv package (you will see what happens without it at the end of this page). langgraph dev loads it for you through langgraph.json.

    Quotes around values are optional; python-dotenv removes them. No spaces around =.

    from typing import Literal
from langchain.messages import HumanMessage
from langchain_openai import ChatOpenAI
from langchain.tools import tool
from langgraph.prebuilt import ToolNode
from langgraph.graph import StateGraph, MessagesState


@tool
def search(query: str):
    """Call to surf the web."""
    if "sf" in query.lower() or "san francisco" in query.lower():
        return "It's 60 degrees and foggy."
    return "It's 90 degrees and sunny."

tools = [search]
tool_node = ToolNode(tools)

def should_continue(state: MessagesState) -> Literal["tools", "__end__"]:
    messages = state['messages']
    last_message = messages[-1]
    if last_message.tool_calls:
        return "tools"
    return "__end__"

def call_model(state: MessagesState):
    messages = state['messages']
    # Invoking `model` will automatically infer the correct tracing context
    response = model.invoke(messages)
    return {"messages": [response]}

workflow = StateGraph(MessagesState)
workflow.add_node("agent", call_model)
workflow.add_node("tools", tool_node)
workflow.add_edge("__start__", "agent")
workflow.add_conditional_edges(
    "agent",
    should_continue,
)
workflow.add_edge("tools", 'agent')

app = workflow.compile()

final_state = app.invoke(
    {"messages": [HumanMessage(content="what is the weather in sf")]},

)

    The program finishes silently. That is expected: line 53 has no print. If you want to see the answer in the terminal too, change line 53 to:

What you should see

  • python --version inside the activated venv prints Python 3.12.x.
  • uv add ends with a list of installed packages (+ langgraph==…, + langchain==… and many more). A warning about an extra named inemem means you typed the typo; it is harmless, but make sure inmem is there too.
  • python main.py runs for a few seconds and returns to the prompt with no output and no error.
  • In LangSmith, your project has a new run named LangGraph whose steps include search with "It's 60 degrees and foggy."

Common mistakes

  • openai.OpenAIError: Missing credentials. load_dotenv() is missing or comes after ChatOpenAI(...), or .env is not in the project folder (next to main.py). Also check the spelling OPENAI_API_KEY and that you saved the file.
  • PowerShell: "running scripts is disabled on this system" when activating. Windows blocks scripts by default. Run once Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, or skip activation and use uv run main.py.
  • ModuleNotFoundError: No module named 'langgraph'. The venv is not active in this terminal, or you ran the global Python. Activate it, or use uv run.
  • zsh: "no matches found: langgraph-cli[inmem]" on macOS. Put the package in quotes.
  • The run works but no trace appears. Check LANGSMITH_API_KEY, that tracing is true, and the endpoint region (EU accounts need the eu. endpoint). Refresh the LangSmith page and check you are in the right project.
  • An error about quota or billing. The OpenAI key is valid but the account has no credit.
  • Committing .env. If it ever happens, delete the keys in each dashboard and create new ones; removing the file afterwards is not enough.
Recap
  • uv init, uv venv --python 3.12 and activation give you an isolated project on Python 3.12 (3.11–3.13 is fine).
  • .env holds three keys (OpenAI, Tavily, LangSmith) plus the LangSmith tracing settings; .gitignore keeps it private; .env.example is the shareable template.
  • uv add langchain langchain-openai langgraph dotenv "langgraph-cli[inmem]" installs everything; inmem is what makes langgraph dev work, inemem is a typo.
  • Python does not read .env by itself: load_dotenv() must run before the model is created.
  • main.py prints nothing (no print); the proof it worked is the trace in LangSmith.
