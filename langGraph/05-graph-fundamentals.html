Fundamentals of Graphs

On a whiteboard, the presenter explains what a graph is, then the three ideas every LangGraph program is made of: state, nodes and edges, plus START and END and the difference between simple and conditional edges.

This page redraws the whiteboard as diagrams, walks through the presenter's car-and-cargo simulation, maps it to AI apps, and ends with a tiny Python preview that runs the same simulation. You need no API key for anything here.

What is a graph? (20:49)

"A graph actually is a group of nodes and edges." Nodes "could be anything": objects, cities, circles, points. Edges are what links them. That is the whole definition. In everyday English "graph" often means a chart with axes; in programming it means this: things, and connections between things.

The Google Maps analogy (21:37)

The presenter's concrete example: cities are nodes, roads are edges. In one country there are many cities, and between two cities there may be several ways, some long and some short. "Think of a graph as Google Maps." When you ask for a route from point A to point B, the app runs algorithms "behind the scenes" over exactly this kind of graph. And roads are not the only edges: "the metros, the trains, the bicycle, the walking lanes, all of these are different types of edges, but in the end of the day they are edges."

New to graphs in programming? Directed edges and cycles

In a road map you can usually drive both ways. In LangGraph every edge has a direction: "after this node, go to that node". That is why the diagrams in this guide use arrows, not plain lines. A graph with arrows is called a directed graph.

Arrows may also point back to an earlier node. That makes a cycle (a loop). Graph 8 uses one: the model calls a tool, the tool's result goes back to the model, and so on until the model is done. The handbook chapter Graphs & State Machines goes deeper.

The three ideas of LangGraph (23:12)

"In LangGraph there are three important things that we have to keep on thinking about": the nodes, the edges, and something called state. The presenter keeps the map: cities and roads. Then adds a car.

State: the car (23:36)

"In our graph here the state is actually the car." Why the car? "Because this is what we are keeping track of." When you drive from city A to city B, you care about getting your car (and the people in it) there. The roads and cities only matter because of what they do to the car.

In LangGraph, the state is "our object that we would like to take from the start till the end … What is happening in our state? This is the question that we have to ask ourselves at every time." In code it is usually a dictionary with named fields, described by a TypedDict (graph 1). In graph 0 it is just a string.

Nodes: the cities, which are functions (24:47)

"Nodes in our LangGraph will actually be some kind of functions." A node "basically takes our state, which is here our car, does something to our state and then releases the state." In each city the car may change: "maybe we are buying groceries, adding groceries to the car … maybe we are picking something up or someone up." Nodes return the same kind of state they received, "because we are trying to keep up of the same state".

New to functions? Input, work, output

A function is a named block of code with inputs (parameters) and an output (the return value). def add_one(x): return x + 1 takes a number and gives back the number plus one. Calling add_one(4) gives 5.

A LangGraph node is exactly that, with one convention: the input is the current state, and the output is the part of the state you want to change. You never call node functions yourself; the graph calls them in the order the edges say.

START and END (25:56)

"In LangGraph we have also actually two [special] nodes … just beginning and end." Every graph has a starting point and an ending point, so you can see where the run begins and when it is finished. In code they are START and END, imported from langgraph.graph. They do no work; they only mark the entrance and the exit.

Edges: the roads (26:18)

"The edges actually are the roads of our map." An edge tells the state "go from START, pass by the city, and once you finish the city go to the end". Edges decide the direction; they do not change the state. "The edges do not tell what happened to the state": the cargo is added inside the node, never on the road.

There are two kinds (27:49):

  • A simple edge always goes to the same next node: "you have no other roads".
  • A conditional edge, "a smart edge", "can ask questions like: what do we have in our car? Are we very heavy, are we very light?" and, depending on the answer, sends the car to one node or another. In code, the question is a small function called a routing function.

The presenter's recap (30:10)

To master LangGraph, keep three things in mind at all times:

  • State: "the things that we are keeping track [of] all the time".
  • Edges: "which way are we taking". Simple ("you have no other roads") or conditional ("do you have a watch? Please go here. Do you not have a watch? Please go here").
  • Nodes: "what is the logic that is taking our state … and returning another state".

From road trips to AI apps

The same three ideas carry straight over to applications that use a language model. You will meet each of these in the coming steps:

  • The state becomes a list of messages: what the user said (HumanMessage), what the model answered (AIMessage), what a tool returned (ToolMessage). LangGraph's MessagesState (step 10) is exactly that.
  • A node becomes a chat function: it sends the messages to the model and returns the model's reply as an update.
  • A conditional edge asks "did the model ask for a tool?" and goes to the tool node or to END (tools_condition, step 12).

A tiny Python preview of the trip

You will write real graphs from step 06. To connect this page to code, here is the presenter's trip as a runnable LangGraph program. It is illustrative (not in the course repo), uses no model and no API key, and was run against the locked versions (LangGraph 1.2.11). Do not worry about every line yet; steps 06–08 teach each piece.

First, a node on its own is just a function. You can even call it by hand:

def city_1(state):
    return {"cargo": state["cargo"] + 1}

print(city_1({"cargo": 0}))

Now the whole trip as a graph:

from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class Car(TypedDict):
    cargo: int

def city_1(state: Car):
    return {"cargo": state["cargo"] + 1}

def city_left(state: Car):
    return {"cargo": state["cargo"] + 1}

def city_right(state: Car):
    return {"cargo": state["cargo"]}

def city_last(state: Car):
    return {"cargo": state["cargo"] - 1}

def which_road(state: Car):
    if state["cargo"] > 0:
        return "city_left"
    return "city_right"

builder = StateGraph(Car)
builder.add_node("city_1", city_1)
builder.add_node("city_left", city_left)
builder.add_node("city_right", city_right)
builder.add_node("city_last", city_last)
builder.add_edge(START, "city_1")
builder.add_conditional_edges("city_1", which_road)
builder.add_edge("city_left", "city_last")
builder.add_edge("city_right", "city_last")
builder.add_edge("city_last", END)
graph = builder.compile()

for step in graph.stream({"cargo": 0}):
    print(step)

Common mistakes (in thinking, before any code)

  • Putting logic on the edge. Edges choose the direction; they never add or remove cargo. Any change to the state happens inside a node.
  • Thinking each node gets a new state. There is one state object for the whole trip. Nodes return updates to it.
  • Forgetting START or END. Every graph needs an entrance (an edge from START) and every path needs to reach END, or the graph has nowhere to begin or finish.
  • Mixing up node names and functions. In code, edges and routing functions use the node's name (a string such as "city_left"), not the function. Step 06 shows the error you get otherwise.
  • Treating a conditional edge as a node. The "has cargo?" question is not a city; nothing is changed there. It is attached to the edge leaving city 1.
Recap
  • A graph is nodes plus edges. Google Maps: cities are nodes, roads (and trains, bike lanes…) are edges.
  • In LangGraph: state is the car you track from START to END; nodes are Python functions that take the state and return an update; edges decide where the state goes next.
  • Simple edges always go to the same node; conditional edges ask a question about the state and pick a road.
  • The whiteboard trip: cargo 0 → 1 (city 1) → left because it has cargo → 2 (left city) → 1 (last city) → END.
  • In AI apps the car is a list of messages, the cities are chat functions, and the smart edge asks "did the model request a tool?".
