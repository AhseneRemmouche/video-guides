What Is LangGraph?

A library for building AI workflows as graphs of steps, and how it relates to LangChain.

▶ Watch this part (04:34)

Goal

This short chapter (04:34–06:31) answers two questions: what is LangGraph, and why choose it instead of only LangChain. There is no code in the video here. This page adds one small, runnable comparison so you can see the difference with your own eyes: the same two-step job written as plain functions and as a LangGraph graph.

What LangGraph is (04:34)

The presenter reads the definition from LangGraph's GitHub repository: LangGraph is a Python library that lets you define AI workflows as a graph: a set of nodes connected by edges, which are the transitions between them. In a nutshell (05:05): "we can go … from a node to another and then we can tell if you hit this place go like this, if we hit that place go like this."

A workflow is just the list of steps your program goes through, and in which order. Writing it as a graph means you draw it: each step is a box, each arrow says what comes next, and some arrows are decided while the program runs.

New to libraries? What a package is and why we install one

A library, or package, is code someone else wrote and published so you can reuse it. You install it once into your project (step 04 does this with uv add langgraph) and then use it with an import, for example from langgraph.graph import StateGraph.

LangGraph is free and open source. It does not contain an AI model. It is the organiser: it runs your functions in the right order, passes data between them and remembers it. The model itself comes from a separate package (here langchain-openai, which talks to OpenAI).

Why choose LangGraph? (05:36)

The presenter's answer is control. LangChain, the bigger library LangGraph comes from, has "another layer of abstraction" that sometimes hides what happens. In a small script that is convenient. In a big project it "could be a bad thing", because you cannot see or change the steps in the middle. With LangGraph, the presenter says, "I can actually know exactly what is happening at every edge and every node of my graph at every step of the way" (05:59). They have used it for their own projects and for clients.

Control shows up in four concrete abilities, and each one has its own graph in this course:

  • Control. You write the routing yourself: a routing function looks at the data and returns the name of the next node. Nothing is hidden.
  • Loops. An edge may point back to an earlier node. That is how an agent calls a tool, reads the result and thinks again. In plain code you would write a while loop and manage the stopping condition by hand.
  • State. Every node receives the same shared state and returns an update. LangGraph merges the updates for you, and for chat messages it appends instead of overwriting.
  • Memory. Because all data lives in the state, LangGraph can save it after each step with a checkpointer and give it back next time. That is persistence, and it is how graph 9 remembers your earlier messages.

See the difference: a function pipeline vs a graph

Here is a tiny job in two steps: clean up some text (remove spaces at the ends), then shout it (upper case plus "!"). First as ordinary Python functions. These snippets are illustrative, not part of the course repo, but both were run against the locked versions (LangGraph 1.2.11). You do not need to type them now; you will be able to after step 07.

def clean(text):
    return text.strip()

def shout(text):
    return text.upper() + "!"

def pipeline(text):
    return shout(clean(text))

print(pipeline("  hello  "))

Now the same job as a LangGraph graph:

from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    text: str

def clean(state: State):
    return {"text": state["text"].strip()}

def shout(state: State):
    return {"text": state["text"].upper() + "!"}

builder = StateGraph(State)
builder.add_node("clean", clean)
builder.add_node("shout", shout)
builder.add_edge(START, "clean")
builder.add_edge("clean", "shout")
builder.add_edge("shout", END)
graph = builder.compile()

print(graph.invoke({"text": "  hello  "}))

What you should see if you run them (after step 04's setup): the function version prints HELLO!; the graph version prints {'text': 'HELLO!'}. Same result, but the graph returns the whole state, not just a string.

LangGraph and LangChain: how they relate

LangChain and LangGraph come from the same company and are used together in this course. A simple way to keep them apart:

LangChainLangGraph
JobThe building blocks: models, messages, tools.The flow: which step runs when, what data is kept.
In this courseChatOpenAI, @tool, HumanMessage, SystemMessageStateGraph, START, END, MessagesState, ToolNode, MemorySaver
Ready-made agentcreate_agent(...): one call, the loop is built for youYou build the loop yourself, node by node (graph 8)

The important detail: LangChain's create_agent is built on LangGraph. In the locked LangChain 1.3.18, its return type is CompiledStateGraph, the same kind of object builder.compile() returns in your own graphs. So when you build graph 8 by hand, you are building roughly what create_agent builds for you, but with every step visible and changeable. That is the "control" the presenter talks about.

New to LangChain? Do I need the LangChain course first?

No. This course uses only a handful of LangChain pieces, and each is explained where it first appears: ChatOpenAI (a chat model object, step 09), messages such as HumanMessage (step 10), and @tool (step 11).

If you did take the LangChain course, you already used LangGraph without knowing it: every create_agent there returned a compiled LangGraph graph.

LangSmith and LangGraph Studio, in one sentence each

The presenter mentions both at 06:12, as "the place where we are actually going to visualize our graphs":

  • LangSmith is the company's website that records a trace of every run (each node, each model call, inputs and outputs) so you can see what happened, step by step; you connect it in step 04.
  • LangGraph Studio is a page inside LangSmith that draws your graph and lets you run it with a form, while your code runs on your own computer through langgraph dev; you first use it in step 06.

Common mistakes

  • Thinking LangGraph replaces LangChain. They work together. This course imports from both: models and tools from langchain…, the graph from langgraph….
  • Thinking LangGraph is a model. It contains no AI. Graphs 0–2 use no model at all and still are LangGraph graphs.
  • Confusing LangSmith with LangGraph. LangGraph is the Python library on your computer; LangSmith is the website that shows traces and hosts the Studio page.
  • Expecting the graph to print by itself. invoke returns the final state. You only see it if you print it. Step 04 shows this exact surprise with main.py.
Recap
  • LangGraph is a Python library for writing AI workflows as graphs: nodes (steps) joined by edges (what comes next).
  • The presenter chooses it for control: you see and decide what happens at every node and edge, instead of trusting a hidden abstraction.
  • Control means four abilities: routing, loops, shared state and memory.
  • LangChain gives the building blocks (models, messages, tools); LangGraph runs the flow. create_agent returns a LangGraph graph.
  • LangSmith records traces; LangGraph Studio draws and runs your graph through langgraph dev.
