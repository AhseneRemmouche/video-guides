LangGraph Crash Course: From a String to an Agent with Memory

A beginner-friendly, step-by-step companion to the AI Career Lab crash course on LangGraph in Python. You set up a project with uv, learn what nodes, edges and state are, and build nine small graphs: one that passes a string, one that routes on a condition, one with a chat model inside, a tool-calling agent that loops until it has the answer, and finally that agent with memory. You also run every graph in LangGraph Studio. Every line of code is explained. The guide also fixes the bugs found while running the repo, adds five extension steps (including tests that need no API key) and a 10-chapter handbook.

Compared with the GitHub repo

Code is embedded unchanged from Mohamad-Hachem/LangGraph_ACL (commit e42570d, "creating LangGraph Graphs"). The repo contains every course file, so what you see in the video and in the repo match. Running the files turned up these findings. Each one is explained on the page listed:

StepFinding
14, 15Graph 9 crashes. It uses HumanMessage but never imports it, so it stops with NameError: name 'HumanMessage' is not defined. The video shows the red underline in VS Code but never runs the file. It also calls the model at import time, so importing it anywhere (tests, langgraph dev) triggers a real API call. Step 15 fixes both and adds a second turn and a second thread.
09, 15Graph 3's number check can't fail safely. isinstance(int(x), int) is always true when int(x) works, and int("Two") raises ValueError instead of reaching the else branch. The docstrings say "1 or 2" but the prompt says "1 or 3 or 2". Step 15 uses try/except.
10, 15Graph 4 has no load_dotenv(). It works under langgraph dev (which reads .env itself) but fails as plain Python with openai.OpenAIError: Missing credentials. It also has unused imports.
13, 14The system message goes last. Graphs 8 and 9 send state["messages"] + [system_message]. It works, but the convention is to put it first; step 15 does. The prompt also has a typo ("Math teach").
14, 17langgraph dev refuses a custom checkpointer. Registering graph 9 in langgraph.json (README exercise 6) makes startup fail with ValueError: Heads up! Your graph ... includes a custom checkpointer. The server already provides memory for Studio threads, so graph 9 is for plain Python runs.
04, 15pyproject.toml details. langgraph-cli[inemem,inmem] has a typo extra (the "does not have an extra" warnings at about 17:16), dotenv is a deprecated shim for python-dotenv, and colorama is never used. Compiled __pycache__/*.pyc files were committed because .gitignore lists only .env and .langgraph_api.
04.env.example details. LANGSMITH_TRACING_V2=true works (verified), but current LangSmith docs use LANGSMITH_TRACING=true. It also lists TAVILY_API_KEY, which no file uses.
15–19Not in the video or the repo: extensions written for this guide and verified the same way.

How the code was verified

No real API keys were used. An offline harness replaced ChatOpenAI with a fake chat model: when tools are bound and the question contains two numbers it asks for the right math tool, otherwise it replies with fixed text. Each course file and each extension was then imported and its graph invoked against the repo's locked versions (langgraph 1.2.11, langchain 1.3.18, langchain-openai 1.6.0). langgraph dev itself was started locally, and graphs 0 and 2 were run through its HTTP API. The pytest suite from step 18 runs 13 tests, all passing.

This proves that the wiring, routing, tool calls, loops, memory and the error messages quoted in the guide are real for these versions. It does not prove what a real model will answer, or which number GPT-4o picks in graph 3: the wording of model answers in the guide comes from the video.

Before you start. You need an OpenAI API key with a little prepaid credit (the presenter says a few dollars is enough for the course) and a free LangSmith account and key for tracing and Studio. The setup also creates a Tavily key (free tier), although no course file uses it. Keep all keys in a .env file that is listed in .gitignore. Never paste a key into code or share it in a screenshot; this guide never reproduces the keys visible in the video.
