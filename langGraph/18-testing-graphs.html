Test Your Graphs Without an API Key

pytest with a fake chat model: check routing, tools and memory for free.

Extension · verified against LangGraph 1.2.11

Extension: not in the video. This step completes README exercise 8, "Add tests that invoke each graph with a small input". tests/test_graphs.py was run with uv run pytest -q against the repo's locked versions (LangGraph 1.2.11, LangChain 1.3.18) plus pytest 9.1.1: 13 passed, with no API key and no internet. We also ran it once against the unfixed graph 3 to make sure a test really fails when the code is wrong.

What that proves: the graphs' wiring, routing, tool calls, error handling and memory. What it doesn't: anything about a real model's answers. See "What these tests can't check" at the end.

Goal

So far you have checked every graph by hand: run it, read the output, decide whether it looks right. That's fine once. But each time you change a file you would have to redo it for every graph, and calls to gpt-4o cost money and give slightly different answers each time.

In this step you write automated tests: small functions that run a graph with a known input and check the result. One command runs all of them in a few seconds. The trick that makes them free and repeatable is a fake chat model that replaces ChatOpenAI during the tests, so they never touch the internet.

New to automated tests and pytest? The basic idea

A test is a function that runs some of your code and checks the result with assert. assert x == y does nothing when the condition is true and raises an AssertionError when it's false.

pytest is the most widely used Python test runner. You don't register tests anywhere; it finds them by name: files called test_*.py, and inside them functions called test_*. It runs each one, catches failures, and prints a summary.

# tests/test_math.py
def add(a, b):
    return a + b

def test_add():
    assert add(2, 3) == 5   # passes

Tests are most useful when they run automatically and often: after every change, before every commit. That only works if they're fast, free and give the same result every time.

Set up

  1. Add pytest as a development dependency 
    uv add --dev pytest

    --dev puts pytest in the [dependency-groups] dev list of pyproject.toml (lines 16–19 in step 15) rather than in dependencies: your graphs don't need pytest to run, only you do while developing. With the repo's lock it adds pytest>=9.1.1.

  2. Create the folder and file

    Create a folder tests in the project root (next to module1, not inside it) and a file tests/test_graphs.py with the code below.

    LangGraph_ACL/
├── module1/
│   ├── 0_graph_state_str.py … 9_graph_agent_memory.py
│   └── 10_graph_division_tool.py
├── tests/
│   └── test_graphs.py
├── langgraph.json
└── pyproject.toml
  3. Make sure the step 15 and 16 fixes are in place

    The tests import graph 9 (needs the fixed import and the __main__ guard), check graph 3's "Two" fallback, and load graph 10. On the unfixed repo, some tests fail, which is the point.

"""Tests for the course graphs that run without an API key or internet.

Run with:  uv run pytest -q
The model-based graphs get a fake chat model, so the tests check the graph wiring
(nodes, edges, routing, tool calls, memory), not the wording of real model answers.
"""
import importlib.util
import os
from pathlib import Path

import pytest
from langchain_core.language_models.chat_models import BaseChatModel
from langchain_core.messages import AIMessage, HumanMessage, ToolMessage
from langchain_core.outputs import ChatGeneration, ChatResult

MODULE1 = Path(__file__).resolve().parent.parent / "module1"


class FakeChatModel(BaseChatModel):
    """Answers with a fixed text, or asks for a tool when tools are bound."""

    reply: str = "fake answer"
    tool_call: dict | None = None
    tool_names: list = []

    @property
    def _llm_type(self):
        return "fake"

    def bind_tools(self, tools, **kwargs):
        return self.model_copy(update={"tool_names": [t.name for t in tools]})

    def _generate(self, messages, stop=None, run_manager=None, **kwargs):
        conversation = [m for m in messages if m.type != "system"]
        if self.tool_call and self.tool_names and not isinstance(conversation[-1], ToolMessage):
            message = AIMessage(content="", tool_calls=[{**self.tool_call, "id": "call_1"}])
        elif isinstance(conversation[-1], ToolMessage):
            message = AIMessage(content=f"The result is {conversation[-1].content}")
        else:
            message = AIMessage(content=self.reply)
        return ChatResult(generations=[ChatGeneration(message=message)])


def load(file_name, monkeypatch, **fake):
    """Import a numbered course file with ChatOpenAI replaced by FakeChatModel."""
    monkeypatch.setenv("OPENAI_API_KEY", "sk-test-not-real")
    import langchain_openai
    monkeypatch.setattr(langchain_openai, "ChatOpenAI", lambda **kwargs: FakeChatModel(**fake))
    spec = importlib.util.spec_from_file_location(file_name[:-3], MODULE1 / file_name)
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    return module


def test_string_state_appends_greeting(monkeypatch):
    graph = load("0_graph_state_str.py", monkeypatch).graph
    assert graph.invoke("hey am new! ") == "hey am new! welcome to AI Career Lab!"


def test_typed_state_returns_a_dict(monkeypatch):
    graph = load("1_graph_state_dict.py", monkeypatch).graph
    assert graph.invoke({"graph_str": "hello"}) == {"graph_str": "hello welcome to AI Career Lab!"}


@pytest.mark.parametrize("text, node", [("hello I am new", "Node 2"), ("hi I am new", "Node 3"),
                                        ("Hello I am new", "Node 3")])  # the check is case-sensitive
def test_conditional_edge_routes_on_first_word(monkeypatch, text, node):
    graph = load("2_graph_conditional_edge.py", monkeypatch).graph
    assert graph.invoke({"graph_str": text})["graph_str"].endswith(f"I am in {node}")


@pytest.mark.parametrize("reply, expected_end, number", [("2", "passed by node 2", 2), ("3", "passed by node 3", 3),
                                                         ("1", "passed by node 1", 1), ("Two", "passed by node 1", 0)])
def test_model_number_picks_the_route(monkeypatch, reply, expected_end, number):
    graph = load("3_graph_introduction_model.py", monkeypatch, reply=reply).graph
    result = graph.invoke({"graph_str": ""})
    assert result["graph_str"].endswith(expected_end)
    assert result["graph_int"] == number


def test_messages_state_appends_the_reply(monkeypatch):
    graph = load("4_graph_messages_state.py", monkeypatch, reply="Because of Rayleigh scattering.").graph
    messages = graph.invoke({"messages": [HumanMessage(content="Why is the sky blue?")]})["messages"]
    assert [m.type for m in messages] == ["human", "ai"]


def test_agent_loops_through_the_tool(monkeypatch):
    graph = load("8_graph_agent.py", monkeypatch,
                 tool_call={"name": "multiply", "args": {"nb1": 12, "nb2": 7}}).graph
    messages = graph.invoke({"messages": [HumanMessage(content="What is 12 multiplied by 7?")]})["messages"]
    assert [m.type for m in messages] == ["human", "ai", "tool", "ai"]
    assert messages[2].content == "84"


def test_division_by_zero_becomes_a_tool_message(monkeypatch):
    graph = load("10_graph_division_tool.py", monkeypatch,
                 tool_call={"name": "division", "args": {"nb1": 5, "nb2": 0}}).graph
    messages = graph.invoke({"messages": [HumanMessage(content="Divide 5 by 0")]})["messages"]
    assert messages[2].type == "tool" and "Cannot divide by zero" in messages[2].content


def test_memory_keeps_threads_apart(monkeypatch):
    graph = load("9_graph_agent_memory.py", monkeypatch).graph
    first = {"configurable": {"thread_id": "a"}}
    graph.invoke({"messages": [HumanMessage(content="My name is Luca")]}, first)
    graph.invoke({"messages": [HumanMessage(content="What is my name?")]}, first)
    other = graph.invoke({"messages": [HumanMessage(content="What is my name?")]},
                         {"configurable": {"thread_id": "b"}})
    assert len(graph.get_state(first).values["messages"]) == 4
    assert len(other["messages"]) == 2

New to fakes and monkeypatch? Swapping a class during a test

A fake model is a "test double": an object with the same interface as the real thing, but simple, predictable behaviour. LangGraph only ever calls .invoke() and .bind_tools() on the model, so a fake that answers those can stand in anywhere.

The course files create the model themselves with from langchain_openai import ChatOpenAI and ChatOpenAI(model="gpt-4o"). To make them get our fake instead, the test replaces the name ChatOpenAI inside the langchain_openai module before the file runs. That's monkeypatching: changing something at runtime.

pytest's built-in monkeypatch fixture does this safely. You get it just by naming a parameter monkeypatch in your test function, and pytest undoes every change when that test ends, so one test can't leak into the next.

  • monkeypatch.setenv("NAME", "value"): set an environment variable for this test only.
  • monkeypatch.setattr(module, "name", new_value): replace an attribute for this test only.

New to @pytest.mark.parametrize? One test, many inputs

A decorator (the @... line above a function) changes how the function is used. @pytest.mark.parametrize("a, b", [(1, 2), (3, 4)]) tells pytest: run this test once per tuple, passing the values as the parameters a and b.

Each run is reported as its own test, with the values in its name, e.g. test_conditional_edge_routes_on_first_word[Hello I am new-Node 3]. If only one case fails, you see exactly which one. That's how 8 test functions become 13 tests: 3 cases for graph 2, 4 for graph 3, 1 each for the other six.

Run the tests

uv run pytest -q

uv run runs a command inside the project's environment (installing anything missing first); pytest finds tests/test_graphs.py; -q ("quiet") prints one dot per passing test instead of one line each. Use -v ("verbose") to see every test's name.

What you should see (verified):

.............                                                            [100%]
13 passed in 4.38s

Thirteen dots, one per test. The time varies by machine. No key and no internet needed. With -v the names include the parameter values, for example test_model_number_picks_the_route[Two-passed by node 1-0] PASSED.

What these tests can't check

A fake model makes tests free and repeatable precisely because it isn't smart. So these tests say nothing about:

  • Whether a real model picks the right tool, or passes the numbers in the right order. The fake does exactly what the test tells it.
  • The wording and quality of answers, or whether the system prompt works as intended.
  • Problems on OpenAI's side: a wrong or expired key, a model name that no longer exists, rate limits, timeouts, or the model inventing an answer instead of using a tool (a hallucination).

For those you need a few real runs: try the graphs in Studio, look at the traces in LangSmith, and, when you're ready, write a handful of real-model tests that only run when a key is present. That's where the unused import os could come in, e.g. @pytest.mark.skipif(not os.environ.get("OPENAI_API_KEY"), reason="needs a real key") (note: this file sets a fake key inside load(), so put such tests in a separate file). The handbook chapter Testing, Deploying & Production goes further.

Common mistakes

  • no tests ran: the file or function names don't start with test_, or you ran pytest from inside module1. Run from the project root.
  • pytest not found: you skipped uv add --dev pytest, or ran plain pytest outside the activated environment. Use uv run pytest.
  • The graph 9 test errors with NameError: graph 9 still has the repo's missing import. Apply step 15, fix 1.
  • FileNotFoundError for 10_graph_division_tool.py: create it first (step 16), or delete that test.
  • Forgetting the monkeypatch parameter in a new test: load() needs it, and pytest only provides it when the test function asks for it by that exact name.
  • Importing the model before patching, e.g. a course file loaded at the top of the test file: it would grab the real ChatOpenAI. Always load course files through load() inside the test.
Recap
  • uv add --dev pytest, a tests/test_graphs.py file, and uv run pytest -q give you 13 automatic checks in seconds (verified: 13 passed), with no key and no internet (README exercise 8).
  • FakeChatModel extends BaseChatModel, implements bind_tools and _generate, and answers predictably.
  • monkeypatch.setattr(langchain_openai, "ChatOpenAI", ...) swaps the model while each course file loads, and pytest undoes it after every test.
  • @pytest.mark.parametrize runs one test with many inputs, each reported separately.
  • The tests check routing, the agent loop with real tools, tool errors and thread memory, and they caught the original graph 3 bug.
  • Fake-model tests can't judge a real model's choices or wording; use Studio, LangSmith and a few key-gated real tests for that.
