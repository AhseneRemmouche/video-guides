Graph 4: MessagesState

The built-in chat state, add_messages, and why new messages are appended.

▶ Watch this part (01:24:19)

Goal

Graph 3 sent the model one fixed sentence. A chatbot needs more: it must send the whole conversation so far, and every new reply must be added to that conversation, not replace it. In this step you meet the state LangGraph provides for exactly that, MessagesState, and the small function that makes it work, add_messages.

Graph 4 is tiny (one node called chat), but every graph after it (tools, agents, memory) uses MessagesState. Understanding "append, don't overwrite" here makes steps 11 to 14 much easier.

The four kinds of messages

Before any code, the presenter explains the message types an LLM works with (84:19–85:53): a system message, a human message, an AI message and a tool message. "When we invoke an LLM … it actually takes a list, a list of messages", and each message carries its origin "so we can give it the right context, so it gives us the right answer back."

Why "append" matters

The presenter then goes back to Graph 1 (86:17): "notice how … I'm adding the state of the before … because in a normal state when we are returning it it is actually being replaced." When a node returns {"graph_str": ...}, the new value overwrites the old one, so graphs 1 to 3 had to rebuild the string by hand (state["graph_str"] + "..."). For a conversation that would be painful. With MessagesState, "whenever we're adding a message or returning a message in a node it's not replacing the state itself but actually it's being added" (87:05).

New to reducers? The rule that merges a node's update into the state

When a node returns {"key": value}, LangGraph has to combine that value with what's already in the state. The rule it uses is called a reducer: a function reducer(old_value, new_value) → merged_value.

  • No reducer declared: the default rule is "new replaces old". That's what graphs 0 to 3 used.
  • add_messages declared: the rule is "add the new messages to the end of the list". There is one extra feature: if a new message has the same id as an existing one, it replaces it instead of being added (verified: merging a message with id 7 "draft" and one with id 7 "final" leaves only "final").

You attach a reducer to one key of the state with Annotated[type, reducer]. Different keys can have different rules.

You can see this for yourself without any model or API key. These two small scripts were run in the locked environment, and the outputs below are real:

from langgraph.graph.message import add_messages
from langchain.messages import HumanMessage, AIMessage

old = [HumanMessage(content="why is the sky blue", id="1")]
new = [AIMessage(content="Because of Rayleigh scattering.", id="2")]

merged = add_messages(old, new)
print([(m.type, m.content) for m in merged])
[('human', 'why is the sky blue'), ('ai', 'Because of Rayleigh scattering.')]
from typing_extensions import TypedDict
from typing import Annotated
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages

class Plain(TypedDict):
    messages: list                                   # no reducer: overwrite

class Appending(TypedDict):
    messages: Annotated[list, add_messages]          # reducer: append

def reply(state):
    return {"messages": [("ai", "the sky is blue")]}

for State in (Plain, Appending):
    builder = StateGraph(State)
    builder.add_node("reply", reply)
    builder.add_edge(START, "reply")
    builder.add_edge("reply", END)
    out = builder.compile().invoke({"messages": [("human", "what colour is the sky?")]})
    print(State.__name__, "->", [m if isinstance(m, tuple) else (m.type, m.content) for m in out["messages"]])
Plain -> [('ai', 'the sky is blue')]
Appending -> [('human', 'what colour is the sky?'), ('ai', 'the sky is blue')]

Notice the second line: add_messages also turned the ("human", "...") pairs into real message objects. That's why the code can read m.type on them, while the plain list kept the raw tuple.

New to Annotated and AnyMessage? Reading the type on line 13

Read Annotated[List[AnyMessage], add_messages] as two parts:

  • The type, List[AnyMessage]: "a list whose items are messages of any kind". AnyMessage covers HumanMessage, AIMessage, SystemMessage, ToolMessage and some rarer types.
  • The extra information, add_messages: Python ignores it, but LangGraph looks for it and uses it as the reducer for this key.

Annotated is a standard Python feature (typing.Annotated) for attaching metadata to a type. LangGraph is simply one library that reads that metadata.

Missing load_dotenv

Graph 4 works in Studio, but the repo file has no load_dotenv(). Under langgraph dev that's fine: "env": ".env" in langgraph.json makes the server load your keys before it imports any graph. Import the same file from plain Python (a test, a script, python -i) without the key already set in your terminal, and line 14 fails before the graph even exists:

openai.OpenAIError: Missing credentials. Please pass an `api_key`, `workload_identity`, `admin_api_key`, or set the `OPENAI_API_KEY` or `OPENAI_ADMIN_KEY` environment variable.
Common mistakes
  • Returning the reply without a list: write {"messages": [reply]}, with square brackets. add_messages merges lists. A list is the safe, documented form.
  • Returning the whole history yourself, e.g. {"messages": state["messages"] + [reply]}: messages that already have IDs are matched and replaced rather than duplicated, but it's confusing and unnecessary. Return only the new message.
  • Forgetting add_messages in a hand-written state: each reply overwrites the conversation (the "Plain" output above).
  • OpenAIError: Missing credentials when running the file outside Studio: add load_dotenv() (see above).
  • langgraph.json path still pointing at graph 3 after copying a line: Studio shows the wrong graph under the name 4_graph.
Recap
  • A conversation is a list of messages: system, human, AI and tool. The model reads the whole list on every call.
  • By default a node's return value replaces a state key. A reducer changes that rule for one key.
  • MessagesState is a TypedDict with one key, messages: Annotated[list[AnyMessage], add_messages]. add_messages appends (and replaces messages that share an id).
  • The chat node sends state["messages"] to the model and returns {"messages": [reply]}: only the new message.
  • The repo file has unused imports and no load_dotenv(). It works under langgraph dev but fails from plain Python with OpenAIError: Missing credentials.
