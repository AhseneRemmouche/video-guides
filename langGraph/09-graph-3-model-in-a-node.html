Graph 3: A Model Inside a Node

ChatOpenAI picks a number, and the graph routes on the model's answer.

▶ Watch this part (01:02:52)

Goal

Until now every node was plain Python that glued strings together. In this step a real AI model moves inside a node for the first time. Node 1 asks OpenAI's gpt-4o to pick a number, stores the answer in the state, and a routing function sends the graph to node 2, node 3 or straight to the end depending on that number.

It is the same shape as Graph 2 (one node, then a fork), but now the decision comes from a model instead of from your input. That is the core idea behind every LangGraph agent: a model's answer decides where the graph goes next. The file also contains a small trap (a check that can never fail, and a crash when the model answers in words). You'll find it here and fix it in step 15.

What the presenter explains

  • A bigger state with an optional field (64:09–64:56). The state now has two fields: graph_int (a number) and graph_str (a string). The number is marked NotRequired: "I don't need my user to actually give me a number in my state. I do need him to tell me about a phrase."
  • A model inside a node (65:21–66:30). ChatOpenAI from langchain_openai creates a chat model object. It needs the OpenAI key, so the file loads the .env file first. The presenter picks gpt-4o because it is cheap: "We are here to learn" (model names are examples at the time of recording).
  • Models always return text (68:08). The reply is a string such as "2", so the code converts it with int(...). The plan: if the model replies with something that is not a number, store 0 instead (69:29). As you'll see below, the code doesn't quite do that.
  • Nodes always take a state and return a state (70:14). Nodes 2 and 3 don't call the model. They keep the number unchanged ("I want to see what the model actually chose by the end") and add "passed by node 2" or "passed by node 3".
  • Routing on the number (71:50–75:30). next_step returns "node2" for 2, "node3" for 3, and END for anything else: "if it's zero to go straight to the end".
  • Testing in Studio (79:56–83:55). The model kept choosing 2, then (after rewording the prompt) 1. It never picked 3 on camera.
New to chat models in code? What ChatOpenAI and .content are

A large language model runs on OpenAI's servers, not on your computer. ChatOpenAI(model="gpt-4o") creates a small Python object that knows how to talk to those servers. Creating it costs nothing. Every time you call .invoke(...) on it, it sends an HTTPS request with your prompt and your API key, waits for the answer, and gives you back an AIMessage object.

The answer's text lives in .content. It is always a string, even when the model "answers with a number": the reply to "pick a number" is the text "2", not the integer 2. That is why line 21 converts it with int(...).

The key is read from the environment variable OPENAI_API_KEY. load_dotenv() copies it from your .env file into the environment (you set this up in step 4).

Step by step

  1. Create the file

    In the module1 folder, create 3_graph_introduction_model.py (62:52).

  2. Import what you need

    START, END and StateGraph from langgraph.graph; TypedDict; Literal and NotRequired from typing; ChatOpenAI; load_dotenv. Then call load_dotenv().

  3. Write the state with an optional graph_int and a required graph_str.
  4. Create the model once, at the top of the file: model_llm = ChatOpenAI(model="gpt-4o").
  5. Write node1: invoke the model, convert its reply to a number, return both fields.
  6. Write node2 and node3: keep the number, append "passed by node 2/3" to the string.
  7. Write the routing function next_step with the return type Literal["node2", "node3", END].
  8. Build the graph: three nodes, START → node1, a conditional edge from node1, and edges from node2 and node3 to END. Compile it.
  9. Register it in langgraph.json (78:23). Add a line under "graphs": 
    "3_graph": "./module1/3_graph_introduction_model.py:graph"

    The presenter copied the line above (the one for graph 2) and renamed it. If you do the same, change both the name and the file path: for a moment the video shows "3_graph" still pointing at 2_graph_conditional_edge.py (frame at 78:30). Don't forget the comma after the previous line.

  10. Restart langgraph dev (stop it with Ctrl+C, run it again), pick 3_graph in Studio, type a phrase in Graph Str and press Submit.

The complete file

This is the file from the official repo. It was run against the locked versions (LangGraph 1.2.11) with a fake model that replies "1", "2", "3" or "Two" on demand.

from langgraph.graph import START, END, StateGraph
from typing_extensions import TypedDict
from typing import Literal, NotRequired
from langchain_openai import ChatOpenAI
from dotenv import load_dotenv

load_dotenv()

# State 
class State(TypedDict):
    graph_int:NotRequired[int]
    graph_str:str

model_llm = ChatOpenAI(model="gpt-4o")

# nodes
def node1(state: State) -> State:
    """take a state and ask our model to pick a number between 1 or 2"""
    model_response = model_llm.invoke("choose between 1 or 3 or 2. reply only with a number")

    if isinstance(int(model_response.content), int):
        return {"graph_int":int(model_response.content),
                "graph_str": state["graph_str"] + "passed by node 1"}
    return {"graph_int":0,
                "graph_str": state["graph_str"] + "passed by node 1"}

def node2(state: State) -> State:
    """take a state and ask our model to pick a number between 1 or 2"""
    return {"graph_int":state["graph_int"],
                "graph_str": state["graph_str"] + "passed by node 2"}

def node3(state: State) -> State:
    """take a state and ask our model to pick a number between 1 or 2"""
    return {"graph_int":state["graph_int"],
                "graph_str": state["graph_str"] + "passed by node 3"}

# create edges
def next_step(state: State) -> Literal["node2", "node3", END]:
    """check state and return which node to go"""
    number_state = state["graph_int"]
    if number_state == 2:
        return "node2"
    elif number_state == 3:
        return "node3"
    else:
        return END

# building graph
builder = StateGraph(State)

builder.add_node("node1", node1)
builder.add_node("node2", node2)
builder.add_node("node3", node3)

builder.add_edge(START, "node1")
builder.add_conditional_edges("node1", next_step)
builder.add_edge("node2", END)
builder.add_edge("node3", END)

graph = builder.compile()

New to NotRequired? Optional keys in a TypedDict

By default every key in a TypedDict is required: tools like your editor expect the dictionary to always have it. Wrapping the type in NotRequired[...] says "this key may be missing". Here it documents that the graph starts with only graph_str, and that graph_int is filled in by node 1.

LangGraph also uses this information for the input form in Studio. Optional fields can be left empty. Python itself doesn't check any of this at runtime, so if you forget a required key, you find out when a node tries to read it (KeyError).

New to Literal? Why a routing function lists its answers

Literal is a type hint that says "the value is exactly one of these". Literal["node2", "node3", END] means next_step returns one of three specific strings, not just any string.

Most type hints are only for humans and editors, but LangGraph actually reads this one when you call add_conditional_edges without a list of destinations. It uses it to know the possible next nodes. That's how Studio can draw the dashed arrows before anything runs, and how compile() can reject a destination that doesn't exist.

The other way to tell LangGraph the destinations is a third argument to add_conditional_edges, a list or a dictionary (the "options" the presenter mentions at 78:48). The repo uses the Literal way.

Why the model kept saying 2

At 81:05 the presenter tried again and again: "it doesn't want to change. My god, it's always using two." After the prompt was reworded, it answered 1 several times in a row. It never chose 3 on camera.

New to LLMs? Why a model is not a random number generator

A language model doesn't roll dice. Given the same prompt, it computes which reply is most likely and usually returns that one, so the same question tends to get the same answer. There is some built-in variation (controlled by a setting called temperature), but "most likely" still wins most of the time. Rewording the prompt changes what's "most likely", which is why the presenter's answers changed from 2 to 1 when the wording changed.

The presenter says this on purpose (69:51): "of course we can use random to do that". If you need a real random choice, use Python's random.choice([1, 2, 3]). Use a model when the decision needs understanding (is this question about maths? does the user sound angry?), not when it needs chance.

Common mistakes
  • "END" in quotes in the Literal or the return: compile fails with "unknown target 'END'". Import END and use it without quotes.
  • A routing name that doesn't match a node name ("Node2" vs "node2"): the same "unknown target" kind of error. Names are case-sensitive.
  • Empty Graph Str in Studio (or graph.invoke({}) in Python): KeyError: 'graph_str' in node 1, because only graph_int is optional.
  • langgraph.json still pointing at graph 2's file after copying the line: Studio shows graph 2 under the name 3_graph. Check the path.
  • A missing comma between lines in langgraph.json: the server can't read the file. JSON needs a comma between entries but none after the last one.
  • No key: if .env has no OPENAI_API_KEY, the file fails on line 14, before any graph exists.
  • Expecting the fallback to 0 to work: it can't (see "The trap on line 21"). A wordy reply crashes the run. Step 15 fixes it.
Recap
  • A model can live inside a node: create ChatOpenAI(model="gpt-4o") once, call .invoke(...) in the node, and read the text from .content.
  • The model's reply is always a string. Converting it is your job, and it can fail.
  • NotRequired makes a state key optional, so the input can start with just graph_str.
  • The routing function returns a node name or END. Its Literal[...] return type tells LangGraph the possible targets for drawing and checking. Use the END constant, not "END".
  • Line 21's isinstance(int(...), int) is always true or crashes (ValueError on "Two"), so the fallback never runs. The docstrings also lag behind the prompt. Both are fixed in step 15.
  • LLMs aren't random: the same prompt usually gets the same answer, which is why the video kept seeing 2.
