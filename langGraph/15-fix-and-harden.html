New to if __name__ == "__main__":? What it is and why it matters

Every Python file is a module, and every module gets a hidden variable called __name__. Python sets it differently depending on how the file is used:

  • When you run the file directly, python module1/9_graph_agent_memory.py, Python sets __name__ to the string "__main__".
  • When another file imports it, __name__ is the module's own name instead (for example "9_graph_agent_memory").

So if __name__ == "__main__": means "only when this file is the program being run". Code inside that block is a demo or a script; code outside it (imports, tools, the compiled graph) is what other files can safely reuse.

# greet.py
def hello():
    return "hi"

if __name__ == "__main__":
    print(hello())   # runs with: python greet.py
                     # does NOT run with: import greet

Fix 2: the number check in graph 3 (3_graph_introduction_model.py)

In step 9 node 1 asks the model to pick a number and then tries to make sure the answer really is a number. The repo does it like this:

def node1(state: State) -> State:
    """take a state and ask our model to pick a number between 1 or 2"""
    model_response = model_llm.invoke("choose between 1 or 3 or 2. reply only with a number")

    if isinstance(int(model_response.content), int):
        return {"graph_int":int(model_response.content),
                "graph_str": state["graph_str"] + "passed by node 1"}
    return {"graph_int":0,
                "graph_str": state["graph_str"] + "passed by node 1"}

Read line 21 from the inside out. int(model_response.content) runs first. It has only two possible outcomes:

  • The text looks like a whole number ("2"): int returns the int 2, and isinstance(2, int) is True. Always.
  • The text is anything else ("Two", "2.", "I pick 2"): int raises an exception before isinstance even runs, and the whole graph run stops.

So the return {"graph_int": 0, ...} on lines 24–25 can never run. The check looks like a safety net, but it has a hole exactly where the safety is needed. Our harness made the fake model answer "Two":

ValueError: invalid literal for int() with base 10: 'Two'
New to try / except? How Python handles errors

When something goes wrong, Python raises an exception: it stops the current line and jumps out of the function, and out of the function that called it, until something catches it. If nothing does, the program ends and prints a traceback.

try/except catches it:

try:
    number = int("Two")      # raises ValueError
except ValueError:
    number = 0               # runs instead of crashing
print(number)                # 0

Name the exact exception type you expect (ValueError here). A bare except: would also hide real bugs, such as a typo in a variable name.

from langgraph.graph import START, END, StateGraph
from typing_extensions import TypedDict
from typing import Literal, NotRequired
from langchain_openai import ChatOpenAI
from dotenv import load_dotenv

load_dotenv()

# State
class State(TypedDict):
    graph_int:NotRequired[int]
    graph_str:str

model_llm = ChatOpenAI(model="gpt-4o")

# nodes
def node1(state: State) -> State:
    """take a state and ask our model to pick 1, 2 or 3"""
    model_response = model_llm.invoke("choose between 1 or 3 or 2. reply only with a number")

    try:
        number = int(model_response.content.strip())
    except ValueError:  # the model answered with words ("Two") or extra text
        number = 0
    return {"graph_int": number,
            "graph_str": state["graph_str"] + "passed by node 1"}

def node2(state: State) -> State:
    """keep the number and record that we passed by node 2"""
    return {"graph_int":state["graph_int"],
                "graph_str": state["graph_str"] + "passed by node 2"}

def node3(state: State) -> State:
    """keep the number and record that we passed by node 3"""
    return {"graph_int":state["graph_int"],
                "graph_str": state["graph_str"] + "passed by node 3"}

# create edges
def next_step(state: State) -> Literal["node2", "node3", END]:
    """check state and return which node to go"""
    number_state = state["graph_int"]
    if number_state == 2:
        return "node2"
    elif number_state == 3:
        return "node3"
    else:
        return END

# building graph
builder = StateGraph(State)

builder.add_node("node1", node1)
builder.add_node("node2", node2)
builder.add_node("node3", node3)

builder.add_edge(START, "node1")
builder.add_conditional_edges("node1", next_step)
builder.add_edge("node2", END)
builder.add_edge("node3", END)

graph = builder.compile()

New to environment variables and .env? Where the key really lives

An environment variable is a named value the operating system hands to every program it starts. ChatOpenAI looks for one called OPENAI_API_KEY. Your .env file is only a convenient place to write it down without putting the API key in your code.

load_dotenv() (from the python-dotenv package) reads .env and copies each NAME=value line into the environment of the running program. It does not overwrite a variable that is already set, and it does nothing if there's no .env, so it's safe to call in every file.

Three small problems:

  • [inemem,inmem] asks for two extras (optional add-ons) of langgraph-cli. inmem is real; inemem is a typo. uv installs the real one and warns about the other on every command: warning: The package `langgraph-cli==0.4.31` does not have an extra named `inemem`. The presenter saw these warnings during setup (around 17:16).
  • dotenv is a tiny shim package whose only job is to install python-dotenv, the real library. Depend on the real one directly. Your code doesn't change: python-dotenv provides the module called dotenv, so from dotenv import load_dotenv keeps working.
  • colorama (coloured terminal text) is never imported by any file.
New to pyproject.toml, uv.lock and extras? How uv tracks packages

pyproject.toml lists the packages your project needs directly, with minimum versions such as >=1.2.11. uv then works out every package those need, picks exact versions and writes them all to uv.lock, so everyone who runs uv sync gets the same set.

  • uv add X adds X to pyproject.toml, updates uv.lock and installs it.
  • uv remove X does the reverse.
  • uv lock recomputes uv.lock after you edit pyproject.toml by hand; uv sync does that too and then installs exactly what the lock says.
  • An extra, written in square brackets, switches on optional parts of a package. langgraph-cli[inmem] pulls in the in-memory server that langgraph dev needs.
  1. Swap the dotenv shim for the real package and drop colorama 
    uv remove dotenv colorama
uv add python-dotenv

    uv remove takes one or more package names and deletes them from pyproject.toml and the lock. uv add python-dotenv adds it with a minimum version (python-dotenv>=1.2.3 with the repo's lock). You will still see the inemem warning during these two commands; the next step removes it.

  2. Fix the extra by hand

    Open pyproject.toml and change "langgraph-cli[inemem,inmem]>=0.4.31" to "langgraph-cli[inmem]>=0.4.31". Save. (Running uv add "langgraph-cli[inmem]" does not fix it: we tried, and uv keeps the existing extras list.)

  3. Re-lock and install 
    uv sync

    uv notices the edited file, rewrites uv.lock and installs. The warning is gone, and langgraph-cli stays at 0.4.31 (verified on a copy of the repo).

Fix 6: stop committing compiled files (.gitignore)

The repo's .gitignore has only two lines, .env and .langgraph_api. So when the presenter committed, Git also took module1/__pycache__/: eight .pyc files that Python creates automatically whenever a module is imported. They are machine-specific, change constantly and only clutter the history.

Common mistakes

  • Running from the wrong folder. python module1/9_graph_agent_memory.py must be run from the project root. From inside module1 it's python 9_graph_agent_memory.py.
  • Indentation under if __name__ == "__main__":. Every demo line must be indented by the same four spaces. A line left at the left edge runs on import again, or causes an IndentationError.
  • Writing "__main__" wrong. Two underscores on each side, in both __name__ and "__main__". With a typo the condition is never true and the demo silently never runs.
  • except: without a type in fix 2. It would also swallow unrelated bugs. Catch ValueError only.
  • Calling load_dotenv() after creating the model. The key must be in the environment before ChatOpenAI(...) runs.
  • Re-adding graph 9 to langgraph.json. The server stops with "includes a custom checkpointer". Test memory in Studio with graph 8 and the thread panel instead.
  • Forgetting --cached. git rm -r module1/__pycache__ also deletes the files from your disk. Python recreates them, so it's harmless here, but on other files it wouldn't be.
Recap
  • Graph 9 crashed with NameError because HumanMessage was never imported; the fix imports it and moves the demo under if __name__ == "__main__":, so importing the file no longer calls the model.
  • The new demo shows memory working: the same thread grows to 6 messages, a new thread starts empty.
  • isinstance(int(x), int) can't protect you: int() either succeeds or raises. Use try/except ValueError with a fallback.
  • .env is read by langgraph dev, but plain Python needs load_dotenv() in the file.
  • Put the system message first, and keep one tools list for both bind_tools and ToolNode.
