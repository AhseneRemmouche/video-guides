Study workflow

How to learn from the videos and the guides together

A fast, sticky routine for working through a course with its companion guide. The trick: don't watch and read at the same time — your attention splits. Instead run a tight loop per course day: prime → watch → consolidate → do → recall.

The one idea to remember Watch the video for intuition and the instructor's reasoning. Use the guide for exact code, definitions, and running it. Learn by building, not by re-watching. Everything below serves those three.

0. One-time setup ≈1 hour, once

Get the tools ready so every lab runs for free, then you never stop to fix setup again.

  1. Put the video and the guide side by side.

    Video player on one half of the screen, the guide's pages on the other. You'll switch between them, not read both at once.

  2. Install the tools from the Week 1 build page.

    Follow its setup steps to install uv, Node, and Ollama (ollama pull llama3.2). This lets you run every lab locally with no API keys and no cost — the guides are already wired for it.

  3. Pin two tabs you'll reuse constantly.

    The guide's index (the day-by-day list) and the Glossary.

  4. Learn the page↔day mapping.

    Guide page numbers follow the course day order. "Week 2 Day 1" in the video is the page whose slug is w2d1. Always pair the two by that label.

1. The per-day loop your core routine

Do this once per course day, in this exact order.

Prime→ Watch→ Consolidate→ Do→ Recall
  1. Prime 2–3 min

    On the guide's day page, read only the intro, glance at the diagrams, and read the recap box at the bottom. Knowing where the lesson is going before you watch boosts retention a lot.

  2. Watch at 1.25–1.5×

    Watch that day's lessons straight through. Don't pause to copy code and don't rewind for a missed word — the guide has both. Just absorb the ideas and the reasoning.

  3. Consolidate — read the page properly

    Now read the full day page: the line-by-line code tables, and open any "New to this?" primer for anything that felt fuzzy. Click each linked glossary term the first time you meet it. The code here is exact and verified, so you never transcribe from the video.

  4. Do — this is where learning happens

    Open that week's weekN-py or weekN-ts project and run the lab against Ollama. Then change one thing — a prompt, a tool, a model id — and run it again to see what shifts. Altering code beats re-watching every time.

  5. Recall 2 min

    Close the video and the page. Say or jot, from memory, "what did today add?" Check yourself against the recap box. Anything you couldn't recall is tomorrow's quick review.

Realistic pace A ~40-minute day of video takes about 60–75 minutes this way. It feels slower than binge-watching, but you finish each day actually able to use it — so you don't re-learn it later.

2. The per-week loop build it yourself

The single highest-value hour of each week.

  1. Do the Project Build page from an empty folder.

    Pick Track A (Python + uv) or Track B (React + Node + TypeScript). Follow the steps and type it — don't paste the whole thing — running after each step. This assembles the week's daily pieces into one working project.

  2. Trust the RUN-NOTES.

    Each weekN-py has a RUN-NOTES file saying what runs locally vs. what needs a paid key. Use it so you don't waste time chasing a service you don't have.

3. Reinforce & keep it fast

  • One language per week on the bilingual weeks. Learn the week in your stronger language first; revisit in the other only if you want to. Doing both at once doubles the time for little extra understanding.
  • Let the guide replace re-watching. If a lesson's idea is already clear from the page, skip re-watching it — the guide is the faster reference.
  • Playback speed: 1.5–2× for talking and overviews; drop to 1× (or just read the guide) for new concepts and code walkthroughs.
  • Spaced review (5 min, start of each session): re-read yesterday's recap box and the glossary terms you missed before starting the new day. This is what moves things into long-term memory.
  • Heed the honesty callouts. When a page says a step used a paid API or was shown-but-not-run, substitute the free Ollama path or skip it — don't get stuck reproducing something that needs a key.
Common traps that waste time Copying code from the video (slow and error-prone — use the guide's verified code). Pausing-and-rewinding every few seconds (watch once, then read). Chasing paid services while just learning (use Ollama). Trying to master both languages simultaneously (one at a time).
