Human in the loop, time travel and streaming

Pause before a write action for approval, fork a past checkpoint, and stream tokens. Book chapter 14.

Lab · code run on a local model (llama3.2 via Ollama)
Read with chapter 14 · Human-In-The-Loop, Time Travel, and Streaming of the book (Part IV · Build Agents with LangGraph). This lab is our own example on the Harbor City Library project; it does not reproduce the book's code.

Goal. Placing a hold changes a member's account, so the library wants a librarian to approve every hold the assistant tries to place. In this lab you add that approval step with interrupt() (human in the loop), resume the paused run with a "yes" or a "no", go back to an earlier checkpoint and run from there with a different question (time travel), and print the model's answer token by token as it is generated (streaming). All three features rest on the checkpointer from lab 11.

The idea in brief

Because a checkpointer saves the graph's state after every step, a run can stop in the middle and be continued later, even from another process. interrupt(value) inside a node stops the run there and hands value to your code. Your code shows it to a person, and calls the graph again with Command(resume=answer). Since every step is saved, you can also pick any older checkpoint, change the state there and run forward from it: the old history stays, and a new branch grows next to it. Streaming is separate: it lets you see results while the graph is still running. The concept chapter Agents with LangGraph puts these features in context.

New to human in the loop? Why pause an agent at all

An agent decides on its own which tools to call. For reading data that is fine. For actions that change something (placing a hold, sending an email, paying) a mistake is costly, and lab 11 showed that a small model can pick the wrong member. Human in the loop means: the agent prepares the action, a person sees exactly what it wants to do (tool name and arguments), and only an approval lets it run. The agent waits as long as needed, because its state is in the checkpointer, not in a running loop.

New to Command? One object for "resume" and "go to"

Command (from langgraph.types) is used in two places in this lab. Passed to invoke, Command(resume="yes") continues a paused run and makes the waiting interrupt() call return "yes". Returned from a node, Command(goto="tools") or Command(goto=END, update={...}) says where the graph goes next and, optionally, what to add to the state, so the node itself does the routing instead of a separate edge.

In TypeScript, Command comes from @langchain/langgraph and takes one options object: new Command({ resume: "yes" }), new Command({ goto: "tools" }) or new Command({ goto: END, update: {...} }). One extra rule in LangGraph.js: a node that returns a Command must list the places it may go when you add it, addNode("approve", approve, { ends: ["tools", END] }), so the graph knows those exits exist.

"""Lab 13: pause for a human before a write action, go back in time, and stream."""
from langchain_core.messages import AIMessage, HumanMessage
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import END, START, MessagesState, StateGraph
from langgraph.prebuilt import ToolNode
from langgraph.types import Command, interrupt

from harbor.catalog import ALL_TOOLS
from harbor.agent_graph import SYSTEM
from harbor.config import get_model

model = get_model().bind_tools(ALL_TOOLS)


def call_model(state: MessagesState):
    return {"messages": [model.invoke([SYSTEM] + state["messages"])]}


def approve(state: MessagesState):
    """Pause before any place_hold call and ask a librarian. Other tools run without asking."""
    last = state["messages"][-1]
    holds = [c for c in last.tool_calls if c["name"] == "place_hold"]
    if holds:
        decision = interrupt({"question": "Approve this hold?", "calls": holds})
        if decision != "yes":
            refused = AIMessage("A librarian did not approve this hold, so I did not place it.")
            return Command(goto=END, update={"messages": [refused]})
    return Command(goto="tools")


def route(state: MessagesState):
    return "approve" if state["messages"][-1].tool_calls else END


builder = StateGraph(MessagesState)
builder.add_node("model", call_model)
builder.add_node("approve", approve)
builder.add_node("tools", ToolNode(ALL_TOOLS))
builder.add_edge(START, "model")
builder.add_conditional_edges("model", route, ["approve", END])
builder.add_edge("tools", "model")
graph = builder.compile(checkpointer=InMemorySaver())

# 1. Human in the loop: the run stops at interrupt() and waits.
config = {"configurable": {"thread_id": "hold-1"}}
request = "I'm member M-1002. Please place a hold on item B003 for me."
result = graph.invoke({"messages": [("user", request)]}, config)
print("1) Paused:", "__interrupt__" in result)
if "__interrupt__" in result:
    print("   waiting for:", result["__interrupt__"][0].value)
    print("   next node:", graph.get_state(config).next)
    result = graph.invoke(Command(resume="yes"), config)  # the librarian approves
    print("   after 'yes':", result["messages"][-1].content)

# 2. The same request, refused.
config2 = {"configurable": {"thread_id": "hold-2"}}
result = graph.invoke({"messages": [("user", request)]}, config2)
if "__interrupt__" in result:
    print("   after 'no': ", graph.invoke(Command(resume="no"), config2)["messages"][-1].content)

# 3. Time travel: list the checkpoints of thread hold-1 and replay from an earlier one with a changed message.
history = list(graph.get_state_history(config))
print(f"\n3) Thread hold-1 has {len(history)} checkpoints (newest first):")
for snap in history:
    print(f"   step {snap.metadata['step']:>2}  next={snap.next}  messages={len(snap.values.get('messages', []))}")
first_input = next(s for s in history if s.next == ("model",) and len(s.values["messages"]) == 1)
original = first_input.values["messages"][0]
# Reusing the message id REPLACES that message; a message without its id would be appended instead.
edited = HumanMessage("I'm member M-1002. Is item B006 available?", id=original.id)
fork = graph.update_state(first_input.config, {"messages": [edited]})
replayed = graph.invoke(None, fork)
print("   forked run answered:", replayed["messages"][-1].content)
print(f"   the thread now has {len(list(graph.get_state_history(config)))} checkpoints; the old branch is still there")

# 4. Streaming: 'messages' mode yields the model's tokens as they are generated.
print("\n4) stream_mode='messages': ", end="")
for token, meta in graph.stream({"messages": [("user", "In one sentence, what can I do at the maker space?")]},
                                {"configurable": {"thread_id": "stream"}}, stream_mode="messages"):
    if meta["langgraph_node"] == "model" and token.content:
        print(token.content, end="", flush=True)
print()
// Lab 13: pause for a human before a write action, go back in time, and stream.
import { AIMessage, HumanMessage, isAIMessage } from "@langchain/core/messages";
import { Command, END, MemorySaver, MessagesAnnotation, START, StateGraph, interrupt, isInterrupted, type StateSnapshot } from "@langchain/langgraph";
import { ToolNode } from "@langchain/langgraph/prebuilt";
import { SYSTEM } from "../src/agent-graph.js";
import { ALL_TOOLS } from "../src/catalog.js";
import { getModel } from "../src/config.js";

const model = getModel().bindTools(ALL_TOOLS);
type State = typeof MessagesAnnotation.State;

async function callModel(state: State) {
  return { messages: [await model.invoke([SYSTEM, ...state.messages])] };
}

/** Pause before any place_hold call and ask a librarian. Other tools run without asking. */
function approve(state: State) {
  const last = state.messages.at(-1);
  const holds = last && isAIMessage(last) ? (last.tool_calls ?? []).filter((c) => c.name === "place_hold") : [];
  if (holds.length) {
    const decision = interrupt({ question: "Approve this hold?", calls: holds });
    if (decision !== "yes") {
      const refused = new AIMessage("A librarian did not approve this hold, so I did not place it.");
      return new Command({ goto: END, update: { messages: [refused] } });
    }
  }
  return new Command({ goto: "tools" });
}

function route(state: State) {
  const last = state.messages.at(-1);
  return last && isAIMessage(last) && last.tool_calls?.length ? "approve" : END;
}

const graph = new StateGraph(MessagesAnnotation)
  .addNode("model", callModel)
  .addNode("approve", approve, { ends: ["tools", END] }) // a node that returns Command lists where it may go
  .addNode("tools", new ToolNode(ALL_TOOLS))
  .addEdge(START, "model")
  .addConditionalEdges("model", route, ["approve", END])
  .addEdge("tools", "model")
  .compile({ checkpointer: new MemorySaver() });

// 1. Human in the loop: the run stops at interrupt() and waits.
const config = { configurable: { thread_id: "hold-1" } };
const request = "I'm member M-1002. Please place a hold on item B003 for me.";
let result = await graph.invoke({ messages: [{ role: "user", content: request }] }, config);
console.log("1) Paused:", isInterrupted(result));
if (isInterrupted(result)) {
  console.log("   waiting for:", JSON.stringify(result.__interrupt__[0].value));
  console.log("   next node:", (await graph.getState(config)).next);
  result = await graph.invoke(new Command({ resume: "yes" }), config); // the librarian approves
  console.log("   after 'yes':", result.messages.at(-1)?.content);
}

// 2. The same request, refused.
const config2 = { configurable: { thread_id: "hold-2" } };
result = await graph.invoke({ messages: [{ role: "user", content: request }] }, config2);
if (isInterrupted(result)) {
  console.log("   after 'no': ", (await graph.invoke(new Command({ resume: "no" }), config2)).messages.at(-1)?.content);
}

// 3. Time travel: list the checkpoints of thread hold-1 and replay from an earlier one with a changed message.
const history: StateSnapshot[] = [];
for await (const snap of graph.getStateHistory(config)) history.push(snap);
console.log(`\n3) Thread hold-1 has ${history.length} checkpoints (newest first):`);
for (const snap of history) {
  console.log(`   step ${String(snap.metadata?.step).padStart(2)}  next=${JSON.stringify(snap.next)}  messages=${(snap.values.messages ?? []).length}`);
}
const firstInput = history.find((s) => s.next.length === 1 && s.next[0] === "model" && s.values.messages?.length === 1)!;
const original = firstInput.values.messages[0];
// Reusing the message id REPLACES that message; a message without its id would be appended instead.
const edited = new HumanMessage({ content: "I'm member M-1002. Is item B006 available?", id: original.id });
const fork = await graph.updateState(firstInput.config, { messages: [edited] });
const replayed = await graph.invoke(null, fork);
console.log("   forked run answered:", replayed.messages.at(-1)?.content);
let count = 0;
for await (const _ of graph.getStateHistory(config)) count++;
console.log(`   the thread now has ${count} checkpoints; the old branch is still there`);

// 4. Streaming: 'messages' mode yields the model's tokens as they are generated.
process.stdout.write("\n4) streamMode 'messages': ");
const stream = await graph.stream(
  { messages: [{ role: "user", content: "In one sentence, what can I do at the maker space?" }] },
  { configurable: { thread_id: "stream" }, streamMode: "messages" },
);
for await (const [token, meta] of stream) {
  if (meta.langgraph_node === "model" && token.content) process.stdout.write(String(token.content));
}
console.log();

The run did not end with an answer; it stopped inside approve, saved its state, and returned. Nothing is running while it waits. The Command(resume="yes") call is a new call that loads the saved state from the thread and continues.

Part 3: time travel

Thread hold-1 kept a checkpoint after every step. Reading the list from the bottom (oldest) up: the empty input (step -1), the request about to go to the model (step 0), the model's tool call waiting for approve (step 1), approved and heading to tools (step 2), the tool result back to the model (step 3), and the final answer (step 4).

The bug we hit: the edit was appended, not replaced

Our first version created the edited message without an id (we hit this in Python first; in TypeScript the same mistake is new HumanMessage("I'm member M-1002. Is item B006 available?") with no id, and the reducer behaves the same way):

edited = HumanMessage("I'm member M-1002. Is item B006 available?")
fork = graph.update_state(first_input.config, {"messages": [edited]})

The fork ran, and printed an empty answer. The reason is the messages reducer of MessagesState (MessagesAnnotation in TypeScript): update_state goes through the same reducer as a node's return value, and that reducer appends any message whose id it has not seen. LangChain gives every message a fresh id, so the state at the fork became [hold request, B006 question]. The model still saw the hold request, asked for place_hold again, and the run stopped once more at the approval interrupt(). The last message of that paused result was the model's tool-call message, which has no text, so "forked run answered:" printed nothing.

The fix is line 69line 73 of the TypeScript file: give the new message the same id as the original (id=original.id, in TypeScript id: original.id). For a known id the reducer replaces the message in place, so the state at the fork is just [B006 question].

With the fix, the forked run answered that B006, "The Little Crab Who Could", is available at the Lighthouse Branch, which matches the catalog (4 of 5 copies). The thread then had 11 checkpoints: the 6 old ones, plus 5 new ones (the update_state edit, then model, approve, tools and model again). So the forked run made one tool call, which passed approve without a pause because it was not place_hold. The output does not print which tool it was.

Replay versus fork: two ways to travel

Replay means calling graph.invoke(None, old_checkpoint_config) without changing anything: the graph continues from that point as if the later steps had not happened (the model is called again, so its answer can differ). Fork means calling update_state on an old checkpoint first, as this lab does, and then continuing: you explore "what if the user had asked something else?". Both add new checkpoints; neither deletes old ones.

Part 4: streaming tokens

invoke waits for the whole answer. stream yields pieces while the graph works. LangGraph has several stream modes: "values" (the full state after each step), "updates" (what each node returned, used in lab 08) and "messages" (the model's output token by token). With "messages", every item is a (chunk, metadata) pair, and metadata["langgraph_node"] (meta.langgraph_node; the pair is unpacked with const [token, meta]) tells which node was running. That matters as soon as a graph has more than one node that calls a model, or a tools node that also produces messages.

Check the streamed answer against the data. The model said the maker space offers "woodworking, sewing, 3D printing, and more". The policy file data/policies/rooms.md lists two 3D printers, a laser cutter and sewing machines; no woodworking. This graph has only catalog tools and no policy retrieval, so the model answered from its general knowledge, partly right and partly invented. Streaming made the answer appear faster; it did not make it truer.

Common mistakes

  • No checkpointer. The graph still pauses, but Command(resume=...) fails with RuntimeError: Cannot use Command(resume=...) without checkpointer.
  • No checkpointer. There is no saved state to resume from, so new Command({ resume }) cannot work. Always pass { checkpointer } to compile.
  • Forgetting { ends: [...] }. In LangGraph.js a node that returns a Command must list where it may go when you add it (line 37).
  • Forgetting await or for await. invoke, getState, updateState return promises and getStateHistory and stream return async iterators. Without await you print Promise { <pending> } instead of the value.
  • Resuming on a different thread_id. The resume must use the config of the paused thread, or there is nothing to resume.
  • Side effects before interrupt(). The node runs again from the top on resume, so anything before the interrupt() call (an email, a database write) would happen twice.
  • Editing a message without its id in update_state. It is appended instead of replaced, exactly the bug above.
  • Printing every streamed chunk. Without the langgraph_node and token.content check you also print empty tool-call chunks, or text from other nodes.
