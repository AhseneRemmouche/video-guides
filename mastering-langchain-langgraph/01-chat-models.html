Chat models: invoke, stream, batch

Call a local model through LangChain with messages, streaming and batches, and read its token usage. Book chapter 3.

Lab · code run on a local model (llama3.2 via Ollama)
Read with chapter 3 · Chat Models of the book (Part II · Integrations and Utilities for LLMs in LangChain). This lab is our own hands-on exercise; it does not reproduce the book's examples.

This first lab sets up everything the other fifteen labs need — Ollama, uv, the two local models and the project — and then makes your first calls to a chat model through LangChain: one question, a conversation with a system message, a streamed answer, a batch of questions, and the same model created with init_chat_model.

Goal

  • Install the tools and run a lab on your own computer, with no API key and no cloud account.
  • Understand the one file every lab uses to get its model: harbor/config.py, and why it sets num_ctx, num_predict and reasoning.
  • Call a chat model four ways (invoke, invoke with messages, stream, batch) and read its token usage.

The idea in brief

A chat model is an object with a few fixed methods. You hand it text or a list of messages; it sends them to a model server and gives you back an AI message. In this guide the server is Ollama, running the small open model llama3.2 on your own machine, and LangChain talks to it through the langchain-ollama package. Because the methods are the same for every provider, the code you write here would work with a hosted model too — only the line that creates the model changes. The concept chapter Chat models, structured output and prompts explains the interface in more depth (sections "The chat-model interface" and "Messages: who says what").

New to Ollama? What it is and why we use it

Ollama is a free app that downloads open-weight language models and serves them on your machine at http://localhost:11434. "Serves" means it runs a small web server: programs send it a request with messages, and it answers with the generated text. You never pay per token and your data never leaves your computer. The price: small local models such as llama3.2 (3 billion parameters) are far less reliable than large hosted ones. This guide shows their real mistakes on purpose — they are the best teaching material.

New to uv? Why not just pip install

uv is a fast Python project manager. uv sync reads pyproject.toml (what the project needs) and uv.lock (the exact versions we tested), creates a private virtual environment in a .venv folder, and installs exactly those versions into it — even Python 3.12 itself if you don't have it. uv run … then runs a command inside that environment, so you never have to "activate" anything. You get the same library versions we used to produce the outputs on these pages.

Set up your computer (once for all labs)

  1. Install Ollama from ollama.com/download and start it. On Windows and macOS it runs as a tray/menu-bar app; on Linux the installer sets up a service. Check it with ollama --version in a terminal.
  2. Install uv by following docs.astral.sh/uv (one command). Close and reopen the terminal, then check with uv --version.
  3. Download the models (a few GB in total; do it once): 
    ollama pull llama3.2
ollama pull nomic-embed-text
ollama pull gemma4        # optional: only used for a comparison in lab 14
    ollama is the command-line tool, pull downloads a model by name. llama3.2 is the chat model every lab uses; nomic-embed-text turns text into vectors (labs 06–07); gemma4 is a larger model we compare in lab 14. ollama list shows what you have.
  4. Get the project. It lives in the folder mastering-langchain-langgraph/harbor-library-ai of the video-guides repository. Clone the repository (or use GitHub's "Code → Download ZIP" and unzip it), then go into that folder: 
    git clone https://github.com/AhseneRemmouche/video-guides.git
cd video-guides/mastering-langchain-langgraph/harbor-library-ai
  5. Install the Python libraries into the project's own environment: 
    uv sync
    This creates .venv/ and installs the locked versions (langchain 1.4.5, langchain-ollama 1.1.0, langgraph 1.2.15, …). Optional check without a model: uv run pytest runs the offline tests (7 passed for us).
  6. Run this lab (from the project folder, with Ollama running): 
    uv run python -m labs.01_chat_models

The command has four parts: uv run runs what follows inside .venv; python is the interpreter; -m labs.01_chat_models runs the file labs/01_chat_models.py as a module. Running it as a module (instead of python labs/01_chat_models.py) makes Python treat the project folder as the starting point for imports, which is what lets the lab write from harbor.config import ….

harbor/__init__.py

This file is empty (0 bytes), and that is on purpose. A folder with an __init__.py is a regular Python package, so from harbor.config import get_model works from every lab. Don't delete it.

harbor/config.py: one place that picks the model

Every lab gets its model from this file, so a setting changed here changes all sixteen labs.

"""One place that decides which models the labs use."""
import os
from pathlib import Path

from langchain_ollama import ChatOllama, OllamaEmbeddings

ROOT = Path(__file__).resolve().parent.parent
DATA = ROOT / "data"
RUNS = ROOT / "runs"

MODEL = os.environ.get("HARBOR_MODEL", "llama3.2")
EMBED_MODEL = os.environ.get("HARBOR_EMBED_MODEL", "nomic-embed-text")
# Ollama's default context window can be far larger than a small GPU holds; 8192 tokens is plenty for these labs.
NUM_CTX = int(os.environ.get("HARBOR_NUM_CTX", "8192"))


def get_model(temperature=0, num_predict=512, **kwargs):
    """The chat model every lab uses. Change HARBOR_MODEL to try another Ollama model.

    num_predict caps the answer length, so a model that never stops can't block the server.
    reasoning=False turns off the hidden "thinking" of models such as gemma4 (much faster here).
    """
    return ChatOllama(model=MODEL, temperature=temperature, num_ctx=NUM_CTX, num_predict=num_predict,
                      reasoning=False, **kwargs)


def get_embeddings():
    return OllamaEmbeddings(model=EMBED_MODEL)

The three settings, and why they are there

SettingValueWhy
num_ctx8192How many tokens the model can see at once (prompt + answer). Ollama's own default context was so large on our 4 GB graphics card that most of the model was pushed onto the much slower CPU. With 8192, ollama ps showed 3.4 GB in use, split 32 % CPU / 68 % GPU, and the 76-token call in part 1 of this lab took about 4.5 seconds once the model was loaded. 8192 tokens is plenty for every lab.
num_predict512The maximum number of tokens in one answer. We added it after a generation in lab 02 never stopped and blocked the Ollama server until we killed its stuck process. With a cap, a runaway answer simply ends.
reasoningFalseTurns off the hidden "thinking" step of models that have one (such as gemma4), which made them much slower here. llama3.2 has no such step, so it changes nothing for it.
New to tokens? Why everything is counted in them

Models do not read letters or words; they read tokens, pieces of text that are often a word or part of a word ("library" may be one token, "bibliothèque" several). Context sizes, output caps, speed and (for hosted models) prices are all measured in tokens. A rough rule for English: 100 tokens ≈ 75 words.

The lab: four ways to call a chat model

Open labs/01_chat_models.py. It has five numbered parts.

"""Lab 01: talk to a chat model through LangChain: invoke, messages, stream, batch."""
from langchain.chat_models import init_chat_model
from langchain_core.messages import HumanMessage, SystemMessage

from harbor.config import MODEL, NUM_CTX, get_model

model = get_model()

# 1. The simplest call: a string in, an AIMessage out.
reply = model.invoke("What is a public library? Answer in one sentence.")
print("1) invoke:", reply.content)
print("   usage:", reply.usage_metadata)

# 2. A list of messages: the system message sets the role, the human message asks.
messages = [
    SystemMessage("You are the assistant of Harbor City Library. Be brief and friendly."),
    HumanMessage("Hi! Can you help me find a book about the sea?"),
]
print("\n2) with a system message:", model.invoke(messages).content)

# 3. Streaming: print each piece as soon as it arrives.
print("\n3) stream: ", end="")
for chunk in model.stream("Name three things people can do in a library, as a comma-separated list."):
    print(chunk.content, end="|", flush=True)
print()

# 4. Batch: several independent prompts in one call (run in parallel threads).
answers = model.batch(["Translate 'library' into French.", "Translate 'library' into Spanish."])
print("\n4) batch:", [a.content for a in answers])

# 5. The same model through the provider-agnostic factory: only the string changes per provider.
same = init_chat_model(f"ollama:{MODEL}", temperature=0, num_ctx=NUM_CTX)
print("\n5) init_chat_model:", type(same).__name__, "->", same.invoke("Say 'ready' and nothing else.").content)

New to message roles? system, human, AI (and tool)

Chat models are trained on conversations where every turn has a role. System: instructions from the developer ("you are…, answer briefly"). Human: what the user typed. AI: what the model said. A fourth role, tool, carries the result of a function the model asked to call (lab 09). LangChain represents each as a class: SystemMessage, HumanMessage, AIMessage, ToolMessage.

Run it

  1. Make sure Ollama is running (the tray icon, or ollama list answers).
  2. From the harbor-library-ai folder run uv run python -m labs.01_chat_models.
  3. Wait. The first call loads llama3.2 into memory, which takes a little while; the next calls are faster.
1) invoke: A public library is a free, publicly funded institution that provides access to a vast collection of books, media, and other resources, as well as programs and services for community members of all ages.
   usage: {'input_tokens': 36, 'output_tokens': 40, 'total_tokens': 76}

2) with a system message: I'd be happy to help you find a book about the sea. What kind of book are you looking for? Are you interested in a specific type of sea creature, a historical account of ocean exploration, or perhaps a children's story about the ocean?

3) stream: Read|,| study|,| and| research|.|||

4) batch: ['The translation of "library" into French is "bibliothèque".', 'The translation of "library" into Spanish is "biblioteca".']

5) init_chat_model: ChatOllama -> ready
What you should see. Five numbered results. Your sentences will be worded differently — models are not deterministic, even at temperature 0 — but the shapes match: (1) one sentence plus a usage dictionary with three token counts; (2) a friendly librarian answer that follows the system message; (3) the streamed text cut by | marks, ending in a few empty pieces (|||): the last chunks carry no text, only end-of-answer information; (4) a Python list with two translations; (5) ChatOllama -> ready. Run ollama ps in a second terminal while it runs to see the loaded model and its CPU/GPU split.
Common mistakes.
  • Ollama is not running → the first invoke fails with a connection error. Start the Ollama app (or ollama serve) and try again.
  • The model was not pulled → an error saying model "llama3.2" is not found. Run ollama pull llama3.2; check the exact name with ollama list.
  • Wrong folder or wrong command → ModuleNotFoundError: No module named 'harbor' or "No module named labs.01_chat_models". Run from the harbor-library-ai folder, use -m, dots instead of slashes, and no .py at the end.
  • Forgot uv run → python -m labs.01_chat_models uses your system Python, which doesn't have LangChain: ModuleNotFoundError: No module named 'langchain'.
  • Printing the message instead of its text → print(reply) shows content='…' additional_kwargs=… response_metadata=…. Use reply.content.
  • Windows: a crash at import with "OPENSSL_Uplink … no OPENSSL_Applink". On our Windows machine an SSLKEYLOGFILE environment variable (set by some debugging or security tools) made OpenSSL crash as soon as the libraries loaded. Run without it: in Git Bash env -u SSLKEYLOGFILE uv run python -m labs.01_chat_models; in PowerShell Remove-Item Env:SSLKEYLOGFILE first (it only affects that terminal window).
  • Very slow answers → check ollama ps. If most of the model is on the CPU, close other GPU-heavy programs, or lower the context with HARBOR_NUM_CTX=4096.

Try it yourself

  1. Change the role. In line 16, replace the system message with "You are a pirate librarian. Answer in pirate speak." Run again: part 2 changes tone, the other parts don't (they have no system message).
  2. Watch the cap. In line 7 write model = get_model(num_predict=10) and run. The answers stop after about ten tokens, mid-sentence, and part 1's output_tokens is at most 10.
  3. Raise the temperature. Use get_model(temperature=1) and run the lab twice. The wording now changes much more between runs than at temperature 0.
  4. Try another model without editing code (if you pulled gemma4): run with HARBOR_MODEL=gemma4 set as shown above, and compare answers and speed.
Recap
  • Ollama serves the model locally; LangChain's ChatOllama talks to it; uv keeps the exact library versions in .venv.
  • harbor/config.py:get_model() is the one place that builds the model: 8192-token context, 512-token answer cap, no hidden reasoning, temperature 0.
  • invoke returns an AIMessage (.content + .usage_metadata); stream yields chunks; batch returns a list in input order.
  • Messages carry roles: system (instructions), human (user), AI (model). The model sees only what you send in each call.
  • init_chat_model("provider:model") makes the same kind of object; swapping providers means changing a string.
