Chat models: invoke, stream, batch

The idea in brief

A chat model is an object with a few fixed methods. You hand it text or a list of messages; it sends them to a model server and gives you back an AI message. In this guide the server is Ollama, running the small open model llama3.2 on your own machine, and LangChain talks to it through the langchain-ollama@langchain/ollama package. Because the methods are the same for every provider, the code you write here would work with a hosted model too — only the line that creates the model changes. The concept chapter Chat models, structured output and prompts explains the interface in more depth (sections "The chat-model interface" and "Messages: who says what").

New to Ollama? What it is and why we use it

Ollama is a free app that downloads open-weight language models and serves them on your machine at http://localhost:11434. "Serves" means it runs a small web server: programs send it a request with messages, and it answers with the generated text. You never pay per token and your data never leaves your computer. The price: small local models such as llama3.2 (3 billion parameters) are far less reliable than large hosted ones. This guide shows their real mistakes on purpose — they are the best teaching material.

New to uv? Why not just pip install

uv is a fast Python project manager. uv sync reads pyproject.toml (what the project needs) and uv.lock (the exact versions we tested), creates a private virtual environment in a .venv folder, and installs exactly those versions into it — even Python 3.12 itself if you don't have it. uv run … then runs a command inside that environment, so you never have to "activate" anything. You get the same library versions we used to produce the outputs on these pages.

New to Node.js, pnpm and tsx? The three tools behind every command

Node.js runs JavaScript outside the browser — here, our lab scripts. pnpm is a package manager, like npm but faster and stricter: pnpm install reads package.json (what the project needs) and pnpm-lock.yaml (the exact versions we tested) and puts the packages into a node_modules folder inside the project. Node.js cannot run TypeScript files the way we write them, so the labs are started with tsx, a small tool that strips the types and runs the file straight away, with no build step. pnpm lab 01 is a shortcut defined in package.json that does exactly that.

New to TypeScript? JavaScript with types

TypeScript is JavaScript plus type annotations such as options: Partial<ChatOllamaInput>. The types are only checked by the TypeScript compiler (pnpm typecheck), never at run time: tsx removes them and runs plain JavaScript. So a type mistake does not stop pnpm lab 01 from running — run pnpm typecheck to catch it. Everything in LangChain.js that talks to a model is asynchronous: it returns a Promise, and you write await in front of the call to wait for the result (see async).

harbor/config.pysrc/config.ts: one place that picks the model

Every lab gets its model from this file, so a setting changed here changes all sixteen labs. TypeScript needs no package marker file like Python's __init__.py: every file is a module, and a lab imports what it needs with import { getModel } from "../src/config.js" (note the .js ending, explained in the tsconfig table above).

"""One place that decides which models the labs use."""
import os
from pathlib import Path

from langchain_ollama import ChatOllama, OllamaEmbeddings

ROOT = Path(__file__).resolve().parent.parent
DATA = ROOT / "data"
RUNS = ROOT / "runs"

MODEL = os.environ.get("HARBOR_MODEL", "llama3.2")
EMBED_MODEL = os.environ.get("HARBOR_EMBED_MODEL", "nomic-embed-text")
# Ollama's default context window can be far larger than a small GPU holds; 8192 tokens is plenty for these labs.
NUM_CTX = int(os.environ.get("HARBOR_NUM_CTX", "8192"))


def get_model(temperature=0, num_predict=512, **kwargs):
    """The chat model every lab uses. Change HARBOR_MODEL to try another Ollama model.

    num_predict caps the answer length, so a model that never stops can't block the server.
    reasoning=False turns off the hidden "thinking" of models such as gemma4 (much faster here).
    """
    return ChatOllama(model=MODEL, temperature=temperature, num_ctx=NUM_CTX, num_predict=num_predict,
                      reasoning=False, **kwargs)


def get_embeddings():
    return OllamaEmbeddings(model=EMBED_MODEL)
// One place that decides which models the labs use.
import "dotenv/config";
import path from "node:path";
import { ChatOllama, OllamaEmbeddings, type ChatOllamaInput } from "@langchain/ollama";

export const ROOT = path.resolve(import.meta.dirname, "..");
export const DATA = path.join(ROOT, "data");
export const RUNS = path.join(ROOT, "runs");

export const MODEL = process.env.HARBOR_MODEL ?? "llama3.2";
export const EMBED_MODEL = process.env.HARBOR_EMBED_MODEL ?? "nomic-embed-text";
// Ollama's default context window can be far larger than a small GPU holds; 8192 tokens is plenty for these labs.
export const NUM_CTX = Number(process.env.HARBOR_NUM_CTX ?? 8192);

/**
 * The chat model every lab uses. Change HARBOR_MODEL to try another Ollama model.
 *
 * numPredict caps the answer length, so a model that never stops can't block the server.
 * think: false turns off the hidden "thinking" of models such as gemma4 (much faster here).
 */
export function getModel(options: Partial<ChatOllamaInput> = {}) {
  return new ChatOllama({ model: MODEL, temperature: 0, numCtx: NUM_CTX, numPredict: 512, think: false, ...options });
}

export function getEmbeddings() {
  return new OllamaEmbeddings({ model: EMBED_MODEL });
}

The three settings, and why they are there

The names follow JavaScript's camelCase style: numCtx and numPredict are Ollama's num_ctx and num_predict, and think: false is what Python's reasoning=False sends.

SettingValueWhy
num_ctx8192How many tokens the model can see at once (prompt + answer). Ollama's own default context was so large on our 4 GB graphics card that most of the model was pushed onto the much slower CPU. With 8192, ollama ps showed 3.4 GB in use, split 32 % CPU / 68 % GPU, and the 76-token call in part 1 of this lab took about 4.5 seconds once the model was loaded. 8192 tokens is plenty for every lab.
num_predict512The maximum number of tokens in one answer. We added it after a generation in lab 02 never stopped and blocked the Ollama server until we killed its stuck process. With a cap, a runaway answer simply ends.
reasoningFalseTurns off the hidden "thinking" step of models that have one (such as gemma4), which made them much slower here. llama3.2 has no such step, so it changes nothing for it.
New to tokens? Why everything is counted in them

Models do not read letters or words; they read tokens, pieces of text that are often a word or part of a word ("library" may be one token, "bibliothèque" several). Context sizes, output caps, speed and (for hosted models) prices are all measured in tokens. A rough rule for English: 100 tokens ≈ 75 words.

The lab: four ways to call a chat model

Open labs/01_chat_models.pylabs/01-chat-models.ts. It has five numbered parts.

"""Lab 01: talk to a chat model through LangChain: invoke, messages, stream, batch."""
from langchain.chat_models import init_chat_model
from langchain_core.messages import HumanMessage, SystemMessage

from harbor.config import MODEL, NUM_CTX, get_model

model = get_model()

# 1. The simplest call: a string in, an AIMessage out.
reply = model.invoke("What is a public library? Answer in one sentence.")
print("1) invoke:", reply.content)
print("   usage:", reply.usage_metadata)

# 2. A list of messages: the system message sets the role, the human message asks.
messages = [
    SystemMessage("You are the assistant of Harbor City Library. Be brief and friendly."),
    HumanMessage("Hi! Can you help me find a book about the sea?"),
]
print("\n2) with a system message:", model.invoke(messages).content)

# 3. Streaming: print each piece as soon as it arrives.
print("\n3) stream: ", end="")
for chunk in model.stream("Name three things people can do in a library, as a comma-separated list."):
    print(chunk.content, end="|", flush=True)
print()

# 4. Batch: several independent prompts in one call (run in parallel threads).
answers = model.batch(["Translate 'library' into French.", "Translate 'library' into Spanish."])
print("\n4) batch:", [a.content for a in answers])

# 5. The same model through the provider-agnostic factory: only the string changes per provider.
same = init_chat_model(f"ollama:{MODEL}", temperature=0, num_ctx=NUM_CTX)
print("\n5) init_chat_model:", type(same).__name__, "->", same.invoke("Say 'ready' and nothing else.").content)

import { HumanMessage, SystemMessage } from "@langchain/core/messages";
import { initChatModel } from "langchain";
import { MODEL, NUM_CTX, getModel } from "../src/config.js";

const model = getModel();

// 1. The simplest call: a string in, an AIMessage out.
const reply = await model.invoke("What is a public library? Answer in one sentence.");
console.log("1) invoke:", reply.content);
console.log("   usage:", reply.usage_metadata);

// 2. A list of messages: the system message sets the role, the human message asks.
const messages = [
  new SystemMessage("You are the assistant of Harbor City Library. Be brief and friendly."),
  new HumanMessage("Hi! Can you help me find a book about the sea?"),
];
console.log("\n2) with a system message:", (await model.invoke(messages)).content);

// 3. Streaming: print each piece as soon as it arrives.
process.stdout.write("\n3) stream: ");
for await (const chunk of await model.stream("Name three things people can do in a library, as a comma-separated list.")) {
  process.stdout.write(`${chunk.content}|`);
}
console.log();

// 4. Batch: several independent prompts in one call (sent concurrently).
const answers = await model.batch(["Translate 'library' into French.", "Translate 'library' into Spanish."]);
console.log("\n4) batch:", answers.map((a) => a.content));

// 5. The same model through the provider-agnostic factory: only the string changes per provider.
const same = await initChatModel(`ollama:${MODEL}`, { temperature: 0, numCtx: NUM_CTX });
console.log("\n5) initChatModel:", same.constructor.name, "->", (await same.invoke("Say 'ready' and nothing else.")).content);

New to message roles? system, human, AI (and tool)

Chat models are trained on conversations where every turn has a role. System: instructions from the developer ("you are…, answer briefly"). Human: what the user typed. AI: what the model said. A fourth role, tool, carries the result of a function the model asked to call (lab 09). LangChain represents each as a class: SystemMessage, HumanMessage, AIMessage, ToolMessage.

Common mistakes.
  • Ollama is not running → the first invoke fails with a connection error. Start the Ollama app (or ollama serve) and try again.
  • The model was not pulled → an error saying model "llama3.2" is not found. Run ollama pull llama3.2; check the exact name with ollama list.
  • Wrong folder → pnpm cannot find a package.json with a lab script. Run from the harbor-library-ai-ts folder.
  • Forgot pnpm install → tsx is not found, or Node reports that it cannot find a package such as @langchain/core. Run pnpm install once in the project folder.
  • Node.js too old → check node --version; the project needs 22 or newer.
  • Forgot await → const reply = model.invoke(…) gives you a Promise, not a message, and reply.content prints undefined. tsx does not check types, so the lab still runs; pnpm typecheck (or your editor) reports that content does not exist on a Promise.
  • Printing the message instead of its text → console.log(reply) prints the whole AIMessage object with all its fields. Use reply.content.
  • Very slow answers → check ollama ps. If most of the model is on the CPU, close other GPU-heavy programs, or lower the context with HARBOR_NUM_CTX=4096 (in .env or in the terminal).
