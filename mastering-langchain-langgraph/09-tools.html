Tools and the agent loop

Define tools, bind them to the model, run them by hand, then loop with ToolNode. Book chapter 11.

Lab · code run on a local model (llama3.2 via Ollama)
Read with chapter 11 · Tools and Model Context Protocol (MCP) of the book (Part IV · Build Agents with LangGraph). This lab covers the tools half; lab 10 covers MCP.

Goal. Give the model a way to do things: search the library catalog, check how many copies are on the shelf, read a member's account. You will define these tools once in harbor/catalog.pysrc/catalog.ts, see exactly what the model is shown about them, watch the model ask for a tool call, run that call yourself, and finally let LangGraph run the whole agent loop for you.

Why the project needs it. RAG (labs 04–08) answers from fixed policy text. But "Is this book on the shelf right now?" or "What do I owe?" need live data from the catalog and the member records. Tools are how a model reaches that data. Every agent in labs 10 to 15 uses the tools in this file.

The idea in brief

A model cannot run code. What it can do, when you describe some tools to it, is reply with a structured request: "please call check_availability with item_id="B004"". This is tool calling. Your program runs the function, sends the result back as a message, and calls the model again. Repeat until the model answers with plain text: that repetition is the agent loop, and LangGraph's prebuilt ToolNode plus tools_conditiontoolsCondition build it in a few lines. The concept chapter LangGraph and agents covers the theory.

New to tool calling? What the model really sees

When you bind tools, LangChain turns each one into a small description in JSON Schema: a name, a sentence saying what it does, and the names and types of its arguments. That description is sent to the model with every request. Models trained for tool use have learned to answer either with normal text or with a tool request that matches one of those descriptions.

Two consequences matter for beginners. First, the model chooses tools only from their names and descriptions, so the docstring (in TypeScript, the description option) is part of your prompt, and badly worded descriptions give bad tool choices. Second, the model may also choose not to call a tool and answer from imagination. This lab shows that happening.

"""The library's catalog and member records, and the tools an agent may call on them."""
import csv
import json

from langchain_core.tools import tool

from harbor.config import DATA

with open(DATA / "catalog.csv", encoding="utf-8") as f:
    CATALOG = {row["id"]: row for row in csv.DictReader(f)}
MEMBERS = json.loads((DATA / "members.json").read_text(encoding="utf-8"))


@tool
def search_catalog(query: str) -> str:
    """Search the catalog by words in the title, author or genre. Returns matching items with their ids."""
    words = query.lower().split()
    hits = [b for b in CATALOG.values()
            if any(w in f"{b['title']} {b['author']} {b['genre']}".lower() for w in words)]
    if not hits:
        return f"No items match '{query}'."
    return "\n".join(f"{b['id']}: {b['title']} by {b['author']} ({b['format']}, {b['year']})" for b in hits[:5])


@tool
def check_availability(item_id: str) -> str:
    """Tell how many copies of an item (id like B004) are on the shelf, and at which branch."""
    b = CATALOG.get(item_id.strip().upper())
    if not b:
        return f"There is no item {item_id}."
    return f"{b['title']}: {b['available']} of {b['copies']} copies available at {b['branch']}."


@tool
def get_member_account(member_id: str) -> str:
    """Show a member's loans with due dates, holds and unpaid fees. Member ids look like M-1001."""
    m = MEMBERS.get(member_id.strip().upper())
    if not m:
        return f"There is no member {member_id}."
    loans = ", ".join(f"{CATALOG[l['id']]['title']} (due {l['due']})" for l in m["loans"]) or "none"
    return f"{m['name']} ({m['card']} card). Loans: {loans}. Holds: {m['holds'] or 'none'}. Fees: {m['fees_eur']:.2f} EUR."


@tool
def place_hold(member_id: str, item_id: str) -> str:
    """Place a hold on an item for a member. This changes the member's account."""
    m, b = MEMBERS.get(member_id.strip().upper()), CATALOG.get(item_id.strip().upper())
    if not m or not b:
        return "Unknown member or item."
    if len(m["holds"]) >= 5:
        return "This member already has 5 holds, the maximum."
    m["holds"].append(b["id"])  # in memory only: the labs never write the JSON file
    return f"Hold placed on {b['title']} for {m['name']}. We keep it for 7 days once it is back."


READ_TOOLS = [search_catalog, check_availability, get_member_account]
ALL_TOOLS = READ_TOOLS + [place_hold]
// The library's catalog and member records, and the tools an agent may call on them.
import { readFileSync } from "node:fs";
import path from "node:path";
import { tool } from "langchain";
import { z } from "zod";
import { DATA } from "./config.js";

export type Item = {
  id: string; title: string; author: string; year: string; format: string;
  genre: string; branch: string; copies: string; available: string;
};
export type Member = {
  name: string; card: string; fees_eur: number;
  loans: { id: string; due: string }[]; holds: string[];
};

// The CSV has no quoted fields, so splitting on commas is enough here.
const [header, ...rows] = readFileSync(path.join(DATA, "catalog.csv"), "utf-8").trim().split(/\r?\n/);
const columns = header.split(",");
export const CATALOG: Record<string, Item> = Object.fromEntries(
  rows.map((line) => {
    const item = Object.fromEntries(line.split(",").map((v, i) => [columns[i], v])) as Item;
    return [item.id, item];
  }),
);
export const MEMBERS: Record<string, Member> = JSON.parse(readFileSync(path.join(DATA, "members.json"), "utf-8"));

export function findItems(query: string): Item[] {
  const words = query.toLowerCase().split(/\s+/).filter(Boolean);
  return Object.values(CATALOG).filter((b) =>
    words.some((w) => `${b.title} ${b.author} ${b.genre}`.toLowerCase().includes(w)));
}

export const searchCatalog = tool(
  ({ query }) => {
    const hits = findItems(query);
    if (!hits.length) return `No items match '${query}'.`;
    return hits.slice(0, 5).map((b) => `${b.id}: ${b.title} by ${b.author} (${b.format}, ${b.year})`).join("\n");
  },
  {
    name: "search_catalog",
    description: "Search the catalog by words in the title, author or genre. Returns matching items with their ids.",
    schema: z.object({ query: z.string() }),
  },
);

export const checkAvailability = tool(
  ({ item_id }) => {
    const b = CATALOG[item_id.trim().toUpperCase()];
    if (!b) return `There is no item ${item_id}.`;
    return `${b.title}: ${b.available} of ${b.copies} copies available at ${b.branch}.`;
  },
  {
    name: "check_availability",
    description: "Tell how many copies of an item (id like B004) are on the shelf, and at which branch.",
    schema: z.object({ item_id: z.string() }),
  },
);

export const getMemberAccount = tool(
  ({ member_id }) => {
    const m = MEMBERS[member_id.trim().toUpperCase()];
    if (!m) return `There is no member ${member_id}.`;
    const loans = m.loans.map((l) => `${CATALOG[l.id].title} (due ${l.due})`).join(", ") || "none";
    const holds = m.holds.length ? JSON.stringify(m.holds) : "none";
    return `${m.name} (${m.card} card). Loans: ${loans}. Holds: ${holds}. Fees: ${m.fees_eur.toFixed(2)} EUR.`;
  },
  {
    name: "get_member_account",
    description: "Show a member's loans with due dates, holds and unpaid fees. Member ids look like M-1001.",
    schema: z.object({ member_id: z.string() }),
  },
);

export const placeHold = tool(
  ({ member_id, item_id }) => {
    const m = MEMBERS[member_id.trim().toUpperCase()];
    const b = CATALOG[item_id.trim().toUpperCase()];
    if (!m || !b) return "Unknown member or item.";
    if (m.holds.length >= 5) return "This member already has 5 holds, the maximum.";
    m.holds.push(b.id); // in memory only: the labs never write the JSON file
    return `Hold placed on ${b.title} for ${m.name}. We keep it for 7 days once it is back.`;
  },
  {
    name: "place_hold",
    description: "Place a hold on an item for a member. This changes the member's account.",
    schema: z.object({ member_id: z.string(), item_id: z.string() }),
  },
);

export const READ_TOOLS = [searchCatalog, checkAvailability, getMemberAccount];
export const ALL_TOOLS = [...READ_TOOLS, placeHold];

New to decorators? What @tool does to a function

A decorator is a function that takes your function and returns something new in its place. After @tool, the name check_availability no longer refers to a plain function but to a StructuredTool object that contains it. That is why you run it with check_availability.invoke({"item_id": "B004"}); calling it like a function, check_availability("B004"), fails with TypeError: 'StructuredTool' object is not callable. The object also has .name, .description and .args, which part 1 of the lab prints.

New to tool()? A function wrapped in an object

tool(fn, { name, description, schema }) returns a tool object that contains your function. That is why you run it with await checkAvailability.invoke({ item_id: "B004" }); calling it like a function, checkAvailability("B004"), is a TypeScript error because the object is not a function. invoke checks the arguments against the Zod schema first, then calls your function. The object also has .name, .description and .schema, which part 1 of the lab prints.

"""Lab 09: tools. First by hand, then with LangGraph's ToolNode in a loop."""
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import START, MessagesState, StateGraph
from langgraph.prebuilt import ToolNode, tools_condition

from harbor.catalog import READ_TOOLS, check_availability
from harbor.config import get_model

# 1. A tool is a function plus a name, a description and an argument schema the model reads.
print("1) What the model sees for check_availability:")
print("  ", check_availability.name, "|", check_availability.description)
print("  ", check_availability.args)

# 2. bind_tools: the model can now answer with tool calls instead of text. It does not run them.
model = get_model().bind_tools(READ_TOOLS)
reply = model.invoke("Is The Quiet Engine on the shelf? Its id is B004.")
print("\n2) The model asked for:", reply.tool_calls)

# 3. We run the tool ourselves and could send the result back. ToolNode automates exactly this.
for call in reply.tool_calls:
    print("   running it gives:", check_availability.invoke(call["args"]))

# 4. The agent loop as a graph: model -> (tools -> model)* -> end.
SYSTEM = SystemMessage("You are Harbor City Library's assistant. Use the tools to look things up. Answer briefly.")


def call_model(state: MessagesState):
    return {"messages": [model.invoke([SYSTEM] + state["messages"])]}


builder = StateGraph(MessagesState)
builder.add_node("model", call_model)
builder.add_node("tools", ToolNode(READ_TOOLS))
builder.add_edge(START, "model")
builder.add_conditional_edges("model", tools_condition)  # goes to "tools" if there are tool calls, else ends
builder.add_edge("tools", "model")
agent = builder.compile()

for question in ["Do you have any books by Mara Quint? Is one available?",
                 "What are member M-1001's loans and fees?"]:
    print(f"\n4) Q: {question}")
    result = agent.invoke({"messages": [HumanMessage(question)]})
    for m in result["messages"][1:]:
        if m.type == "ai" and m.tool_calls:
            print("   model -> tools:", [(c["name"], c["args"]) for c in m.tool_calls])
        elif m.type == "tool":
            print(f"   tool {m.name} -> {m.content[:100]!r}")
        else:
            print("   answer:", m.content)
// Lab 09: tools. First by hand, then with LangGraph's ToolNode in a loop.
import { HumanMessage, SystemMessage } from "@langchain/core/messages";
import { MessagesAnnotation, START, StateGraph } from "@langchain/langgraph";
import { ToolNode, toolsCondition } from "@langchain/langgraph/prebuilt";
import { toJSONSchema } from "zod";
import { READ_TOOLS, checkAvailability } from "../src/catalog.js";
import { getModel } from "../src/config.js";
import { printRun } from "../src/show.js";

// 1. A tool is a function plus a name, a description and an argument schema the model reads.
console.log("1) What the model sees for check_availability:");
console.log("  ", checkAvailability.name, "|", checkAvailability.description);
console.log("  ", JSON.stringify(toJSONSchema(checkAvailability.schema).properties));

// 2. bindTools: the model can now answer with tool calls instead of text. It does not run them.
const model = getModel().bindTools(READ_TOOLS);
const reply = await model.invoke("Is The Quiet Engine on the shelf? Its id is B004.");
console.log("\n2) The model asked for:", reply.tool_calls);

// 3. We run the tool ourselves and could send the result back. ToolNode automates exactly this.
for (const call of reply.tool_calls ?? []) {
  console.log("   running it gives:", await checkAvailability.invoke(call.args as { item_id: string }));
}

// 4. The agent loop as a graph: model -> (tools -> model)* -> end.
const SYSTEM = new SystemMessage("You are Harbor City Library's assistant. Use the tools to look things up. Answer briefly.");

async function callModel(state: typeof MessagesAnnotation.State) {
  return { messages: [await model.invoke([SYSTEM, ...state.messages])] };
}

const agent = new StateGraph(MessagesAnnotation)
  .addNode("model", callModel)
  .addNode("tools", new ToolNode(READ_TOOLS))
  .addEdge(START, "model")
  .addConditionalEdges("model", toolsCondition) // goes to "tools" if there are tool calls, else ends
  .addEdge("tools", "model")
  .compile();

for (const question of ["Do you have any books by Mara Quint? Is one available?", "What are member M-1001's loans and fees?"]) {
  console.log(`\n4) Q: ${question}`);
  const result = await agent.invoke({ messages: [new HumanMessage(question)] });
  printRun(result.messages.slice(1));
}

The helper: src/show.ts

This small file has no Python twin. The Python lab prints the messages with a loop that checks m.type; the TypeScript labs share two helpers instead.

// Print what happened in an agent run: tool calls, tool results and the answer.
import { isAIMessage, isToolMessage, type BaseMessage } from "@langchain/core/messages";

export function toolCalls(messages: BaseMessage[]): [string, unknown][] {
  return messages.flatMap((m) => (isAIMessage(m) ? (m.tool_calls ?? []).map((c): [string, unknown] => [c.name, c.args]) : []));
}

export function printRun(messages: BaseMessage[], indent = "   ") {
  for (const m of messages) {
    if (isAIMessage(m) && m.tool_calls?.length) {
      console.log(`${indent}model -> tools:`, JSON.stringify(toolCalls([m])));
    } else if (isToolMessage(m)) {
      console.log(`${indent}tool ${m.name} -> ${JSON.stringify(String(m.content).slice(0, 100))}`);
    } else {
      console.log(`${indent}answer:`, m.content);
    }
  }
}

The real hallucination in this run

Look closely at the Mara Quint answer: "We have two books by Mara Quint available". The model only called search_catalog, which lists titles but says nothing about copies. It never called check_availability. The truth, from catalog.csv: B001 has 1 of 3 copies on the shelf, and B010, The Cartographer's Daughter, has 0 of 4. The model filled the gap with a confident guess. This is a hallucination, and tool access alone does not prevent it: the model has to decide to use the tool, and here it did not. The TypeScript run made exactly the same claim with the same tool call: the code around the model changed, the model's behaviour did not.

How would you reduce this? Common approaches (not run in this lab): say it in the system message ("Never say an item is available unless check_availability returned it"); make search_catalog include the availability in its own result so there is nothing to guess; or use a stronger tool-calling model. Lab 14 compares llama3.2 with gemma4 on a similar question.

Common mistakes
  • Expecting bind_tools to run tools. It only lets the model ask. The request is in reply.tool_calls, not in reply.content (which usually holds little or no text when the model asks for a tool).
  • A tool function without a docstring fails at import with ValueError: Function must have a docstring if description not provided.
  • Calling a tool like a function: check_availability("B004") gives TypeError: 'StructuredTool' object is not callable. Use .invoke({"item_id": "B004"}).
  • Naming the tool node something else, like "run_tools". tools_condition returns "tools", so the run fails with ValueError: At 'model' node, 'tools_condition' branch found unknown target 'tools'. Name it "tools" (or pass a mapping as the third argument).
  • Forgetting add_edge("tools", "model"). No error: the tools run and the run simply stops. The last message is the ToolMessage, the model never sees the result, and there is no answer.
  • Trusting a fluent answer. Check claims against the tool results printed above them, as with the Mara Quint answer.
Common mistakes
  • Expecting bindTools to run tools. It only lets the model ask. The request is in reply.tool_calls, not in reply.content (which usually holds little or no text when the model asks for a tool).
  • Calling a tool like a function: checkAvailability("B004") is a type error. Use await checkAvailability.invoke({ item_id: "B004" }).
  • Forgetting await on invoke: you print a pending Promise instead of the result.
  • A schema that does not match the function. The function's arguments come from the Zod schema. If the function unpacks { itemId } but the schema says item_id, TypeScript reports it; keep the two names identical.
  • Naming the tool node something else, like "run_tools". toolsCondition returns "tools", so there must be a node with exactly that name.
  • Forgetting .addEdge("tools", "model"). The tools run and the run simply stops. The last message is the ToolMessage, the model never sees the result, and there is no answer.
  • Trusting a fluent answer. Check claims against the tool results printed above them, as with the Mara Quint answer.

Recap
  • @tool builds a tool from a function: name from the function, description from the docstring, argument schema from the type hints. The model sees only those three.
  • tool(fn, { name, description, schema }) builds a tool from a function and a Zod schema; toJSONSchema shows what the model gets. The model sees only those three.
  • Example ids in descriptions (B004, M-1001) help, but small models copy them: labs 11 and 14 show it.
  • bind_tools lets the model return tool_calls; it never runs them. Running one is just tool.invoke(call["args"]).
  • bindTools lets the model return tool_calls; it never runs them. Running one is just await tool.invoke(call.args).
  • ToolNode + tools_conditiontoolsCondition + an edge back to the model make the agent loop.
  • READ_TOOLS for safe lookups; ALL_TOOLS adds place_hold, which changes memory only.
  • The agent claimed two books were available without checking; B010 has 0 copies. Verify, don't trust.
