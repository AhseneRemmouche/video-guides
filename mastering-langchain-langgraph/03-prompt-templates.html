Prompt templates

Templates with variables, chat history and few-shot examples, piped into the model as a chain. Book chapter 5.

Lab · code run on a local model (llama3.2 via Ollama)
Read with chapter 5 · Prompt Templates of the book (Part II · Integrations and Utilities for LLMs in LangChain). This lab is our own hands-on exercise; it does not reproduce the book's examples.

So far every prompt was a string typed straight into invoke. Real applications reuse the same instructions with different values: another branch, another language, another question. In this lab you build prompt templates with variables, connect them to the model as a chain, slot a whole conversation into a prompt, and teach an output style with examples. You will also catch the model inventing facts twice.

Goal

  • Build a ChatPromptTemplate and see exactly which messages it produces with format_messages.
  • Write your first chain, prompt | model | StrOutputParser(), and call it with a dictionary.
  • Build a ChatPromptTemplate and see exactly which messages it produces with formatMessages.
  • Write your first chain, prompt.pipe(model).pipe(new StringOutputParser()), and call it with an object.
  • Insert chat history with MessagesPlaceholder and examples with FewShotChatMessagePromptTemplate.
  • Recognise a hallucination when the model has no data to go on.

The idea in brief

A prompt template is a recipe for a list of messages, with {placeholders} that you fill in at call time. Templates, models and parsers are all runnables: objects with invoke, stream and batch. The | operator (in TypeScript, the .pipe() method) connects runnables so the output of one becomes the input of the next — that is LCEL, which lab 16 explores in depth. The concept chapter Chat models, structured output and prompts (section "Prompt templates") covers partial variables and the other template types.

"""Lab 03: reusable prompts with variables, chat history and examples."""
from langchain_core.messages import AIMessage, HumanMessage
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate, FewShotChatMessagePromptTemplate, MessagesPlaceholder

from harbor.config import get_model

model = get_model()

# 1. A template with variables. format_messages shows exactly what the model will receive.
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are the assistant of Harbor City Library's {branch}. Answer in {language}, in one sentence."),
    ("human", "{question}"),
])
filled = prompt.format_messages(branch="Lighthouse Branch", language="French", question="When is story time?")
for m in filled:
    print(f"{m.type:>6}: {m.content}")

# 2. Prompt | model | parser: a chain. The parser turns the AIMessage into a plain string.
chain = prompt | model | StrOutputParser()
print("\n2) chain:", chain.invoke({"branch": "Central Library", "language": "English", "question": "Do you have a maker space?"}))

# 3. MessagesPlaceholder: slot a whole conversation into the prompt.
with_history = ChatPromptTemplate.from_messages([
    ("system", "You are a friendly librarian. Use the conversation so far."),
    MessagesPlaceholder("history"),
    ("human", "{question}"),
])
history = [HumanMessage("My name is Lea and I love science fiction."), AIMessage("Nice to meet you, Lea!")]
print("\n3) history:", (with_history | model | StrOutputParser()).invoke({"history": history, "question": "What's my name and favourite genre?"}))

# 4. Few-shot: show the model examples of the exact output style you want.
examples = [
    {"title": "The Quiet Engine", "tag": "science fiction · adults · 2021"},
    {"title": "The Little Crab Who Could", "tag": "children · picture book · 2020"},
]
few_shot = FewShotChatMessagePromptTemplate(
    examples=examples,
    example_prompt=ChatPromptTemplate.from_messages([("human", "{title}"), ("ai", "{tag}")]),
)
tagger = ChatPromptTemplate.from_messages([
    ("system", "Reply with a short catalog tag in the same style as the examples, nothing else."),
    few_shot,
    ("human", "{title}"),
]) | model | StrOutputParser()
print("\n4) few-shot:", tagger.invoke({"title": "Tides of Harbor City: A History"}))
// Lab 03: reusable prompts with variables, chat history and examples.
import { AIMessage, HumanMessage } from "@langchain/core/messages";
import { StringOutputParser } from "@langchain/core/output_parsers";
import { ChatPromptTemplate, FewShotChatMessagePromptTemplate, MessagesPlaceholder } from "@langchain/core/prompts";
import { getModel } from "../src/config.js";

const model = getModel();

// 1. A template with variables. formatMessages shows exactly what the model will receive.
const prompt = ChatPromptTemplate.fromMessages([
  ["system", "You are the assistant of Harbor City Library's {branch}. Answer in {language}, in one sentence."],
  ["human", "{question}"],
]);
const filled = await prompt.formatMessages({ branch: "Lighthouse Branch", language: "French", question: "When is story time?" });
for (const m of filled) console.log(`${m.type.padStart(6)}: ${m.content}`);

// 2. prompt.pipe(model).pipe(parser): a chain. The parser turns the AIMessage into a plain string.
const chain = prompt.pipe(model).pipe(new StringOutputParser());
console.log("\n2) chain:", await chain.invoke({ branch: "Central Library", language: "English", question: "Do you have a maker space?" }));

// 3. MessagesPlaceholder: slot a whole conversation into the prompt.
const withHistory = ChatPromptTemplate.fromMessages([
  ["system", "You are a friendly librarian. Use the conversation so far."],
  new MessagesPlaceholder("history"),
  ["human", "{question}"],
]);
const history = [new HumanMessage("My name is Lea and I love science fiction."), new AIMessage("Nice to meet you, Lea!")];
console.log("\n3) history:", await withHistory.pipe(model).pipe(new StringOutputParser())
  .invoke({ history, question: "What's my name and favourite genre?" }));

// 4. Few-shot: show the model examples of the exact output style you want.
const examples = [
  { title: "The Quiet Engine", tag: "science fiction · adults · 2021" },
  { title: "The Little Crab Who Could", tag: "children · picture book · 2020" },
];
const fewShot = new FewShotChatMessagePromptTemplate({
  examples,
  examplePrompt: ChatPromptTemplate.fromMessages([["human", "{title}"], ["ai", "{tag}"]]),
  inputVariables: [],
});
// The examples become real human/AI message pairs that sit between the system message and the question.
const exampleMessages = await fewShot.formatMessages({});
const tagger = ChatPromptTemplate.fromMessages([
  ["system", "Reply with a short catalog tag in the same style as the examples, nothing else."],
  ...exampleMessages,
  ["human", "{title}"],
]).pipe(model).pipe(new StringOutputParser());
console.log("\n4) few-shot:", await tagger.invoke({ title: "Tides of Harbor City: A History" }));

New to .pipe()? How LangChain.js connects steps

Python lets a class redefine operators, so LangChain uses |. JavaScript has no way to redefine operators, so LangChain.js gives every runnable a .pipe() method instead: a.pipe(b) builds a new runnable that calls a, then feeds the result to b. The chain is itself a runnable, so it has invoke, stream and batch too, and you can pipe it into more steps. RunnableSequence.from([a, b, c]) builds the same chain from an array (lab 16). Nothing runs when you write the chain; only when you call it.

New to the | pipe? Why it works on LangChain objects

In plain Python | means "bitwise or". LangChain classes redefine it (with the __or__ method) so that a | b builds a new runnable that calls a, then feeds the result to b. The chain is itself a runnable, so it has invoke, stream and batch too, and you can pipe it into more steps. Nothing runs when you write the chain; only when you call it.

New to few-shot prompting? Teaching by example

Instead of describing the output format in words, you show the model a few finished examples ("shots") as if it had already answered them. Models copy patterns very well, so the style, length and separators of your examples tend to appear in the answer. That is few-shot prompting. What examples cannot do is give the model facts it doesn't have — as part 4 shows.

Reading the output

Our TypeScript run printed exactly the same eight lines as the Python run, word for word, so the reading below applies to both. Same model, same prompts, temperature 0: the library around the model changed nothing here.

Lines 1–2 are the filled template from part 1: the variables are replaced, and nothing else. The model never saw them, so there is no French answer — that is expected.

Line 4 is a hallucination. The chain answered confidently that Central Library has "a well-equipped makerspace called the "Innovation Studio"". Our data (data/policies/rooms.md) does describe a maker space at the Central Library, with two 3D printers, a laser cutter and sewing machines — but it has no name, and the model never saw that file. Nothing in this prompt contains library data, so the model filled the gap with a plausible-sounding answer. The equipment list sounds right only because maker spaces usually have such machines; the name is invented, and the rules that matter (the free safety session before using the laser cutter, 0.05 EUR per gram of 3D printing) are missing. The cure is to put the real policy text into the prompt: that is retrieval-augmented generation, built in lab 07.

Line 6 is correct: the name and genre came from the history placeholder.

Line 8 copies the style but invents the facts. The tag historical fiction · adults · 2019 follows the examples' "words · words · year" pattern perfectly. But data/catalog.csv says item B002, "Tides of Harbor City: A History" by Jonas Field, is local history (not fiction) from 2008 (not 2019). The model only saw the title; the genre and year are guesses.

What you should see. First the two filled messages (identical to ours — part 1 doesn't involve the model). Then three model answers. Yours will be worded differently and may or may not invent a name for the maker space, but expect: a confident answer to the maker-space question, a correct "Lea / science fiction" answer, and a tag of the form … · … · year.
Common mistakes.
  • A missing variable → formatMessages or invoke without question throws an error that names the missing variable. Print prompt.inputVariables to see what a template needs.
  • Forgetting await on formatMessages → you get a Promise, and the for … of loop on line 15 fails because a Promise is not iterable.
  • Calling a chain with a string → a template with several variables needs an object: chain.invoke({ branch: …, language: …, question: … }).
  • Literal curly braces → text such as {"title": …} inside a template is read as a variable. Double the braces ({{ and }}) to mean real braces.
  • Passing text to a placeholder → new MessagesPlaceholder("history") expects an array of messages, not one long string.
  • Putting the few-shot template straight into fromMessages (as in Python) → pnpm typecheck reports a type error. Format the examples first and spread them, as lines 42–45 do.
  • Adding .content after a chain that ends in StringOutputParser → the result is already a string, which has no content property: you print undefined.
  • Trusting fluent answers → part 2 and part 4 sound sure of themselves and are partly invented. Without data in the prompt, check every fact.
Common mistakes.
  • A missing variable → format_messages without question=… raises KeyError: 'question'; a chain called without a key raises KeyError: "Input to ChatPromptTemplate is missing variables {'history'}. …". Check prompt.input_variables to see what a template needs.
  • Calling a chain with a string → a template with several variables needs a dict: chain.invoke({"branch": …, "language": …, "question": …}).
  • Literal curly braces → text such as {"title": …} inside a template is read as a variable. Double the braces ({{ and }}) to mean real braces.
  • Passing text to a placeholder → MessagesPlaceholder("history") expects a list of messages, not one long string.
  • Adding .content after a chain that ends in StrOutputParser → the result is already a str: AttributeError: 'str' object has no attribute 'content'.
  • Trusting fluent answers → part 2 and part 4 sound sure of themselves and are partly invented. Without data in the prompt, check every fact.

Recap
  • ChatPromptTemplate.from_messages([(role, text), …]) makes a reusable prompt; {name} marks a variable; format_messages(…) shows the result without calling the model.
  • prompt | model | StrOutputParser() is a chain: dict in, string out.
  • ChatPromptTemplate.fromMessages([[role, text], …]) makes a reusable prompt; {name} marks a variable; await formatMessages({…}) shows the result without calling the model.
  • prompt.pipe(model).pipe(new StringOutputParser()) is a chain: object in, string out.
  • MessagesPlaceholder("history") inserts a list of messages — that is how chat history reaches the model.
  • FewShotChatMessagePromptTemplate turns examples into fake earlier turns; the model copies their style. In LangChain.js you format them with formatMessages({}) and spread them into fromMessages.
  • Templates control the form, not the facts: without retrieval llama3.2 invented the "Innovation Studio" and a 2019 date (the catalog says 2008).
