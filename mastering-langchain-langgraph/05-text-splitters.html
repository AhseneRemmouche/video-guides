Goal

Lab 04 gave you six Documents, one per policy file. A search should not return a whole file when the question is about one rule in it: the extra text costs space in the prompt and can distract the model. In this lab you cut the Documents into smaller pieces called chunks with text splitters, compare three settings, and see a real mistake a splitter makes. You also write harbor/knowledge.py, the shared module that every later RAG lab and agent imports.

The idea in brief

Splitting is the second stage of the RAG pipeline (load, split, embed, store, retrieve). The concept chapter The RAG pipeline explains why chunk size is a trade-off. In short:

  • Too big: a chunk mixes several topics, its meaning gets blurry, and fewer chunks fit in the model's context window.
  • Too small: a chunk loses the context that makes it understandable (a sentence without its heading, or a heading without its sentence).
  • Overlap: neighbouring chunks may repeat a little text, so a sentence cut at a border still appears whole in one of them.

A good chunk is one that makes sense on its own. With well-structured files, the best cut points are the document's own headings.

New to text splitting? What a splitter actually does

A splitter takes long text and returns a list of shorter strings (or Documents). chunk_size is the maximum length of a chunk, measured here in characters (not words or tokens). chunk_overlap is how many characters at the end of one chunk may be repeated at the start of the next. split_documents(docs) splits a list of Documents and copies each Document's metadata onto every chunk made from it, so every chunk still knows its source file.

New to the recursive splitter? How it chooses where to cut

RecursiveCharacterTextSplitter has a list of separators, from "best" to "worst". By default it is ["\n\n", "\n", " ", ""]: blank line (between paragraphs), line break, space (between words), and finally nothing (between any two characters). It splits on the first separator, then glues small neighbouring pieces back together until a chunk is almost chunk_size long. Any piece that is still too long is split again with the next separator. That second round is the "recursive" part.

The shared module: harbor/knowledge.py

This file is shown here for the first time. It has four small functions. Labs 05 and 06 use the first two, labs 07 and later use all four, and the agents in later labs search the policies through it.

"""Load, split and index the library's policy documents. Labs 04-07 build this step by step."""
from pathlib import Path

from langchain_community.document_loaders import DirectoryLoader, TextLoader
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_text_splitters import RecursiveCharacterTextSplitter

from harbor.config import DATA, get_embeddings


def load_policies():
    loader = DirectoryLoader(str(DATA / "policies"), glob="*.md", loader_cls=TextLoader,
                             loader_kwargs={"encoding": "utf-8"})
    return loader.load()


def split(docs, chunk_size=400, chunk_overlap=60):
    splitter = RecursiveCharacterTextSplitter(chunk_size=chunk_size, chunk_overlap=chunk_overlap,
                                              separators=["\n## ", "\n\n", "\n", ". ", " ", ""])
    return splitter.split_documents(docs)


def build_vector_store(chunks=None):
    chunks = chunks if chunks is not None else split(load_policies())
    return InMemoryVectorStore.from_documents(chunks, get_embeddings())


def format_docs(docs):
    """Turn retrieved chunks into one context string, each chunk tagged with its source file."""
    return "\n\n".join(f"[{Path(d.metadata['source']).name}]\n{d.page_content}" for d in docs)

The lab script

"""Lab 05: split documents into chunks that fit a prompt and still make sense alone."""
from pathlib import Path

from langchain_text_splitters import MarkdownHeaderTextSplitter, RecursiveCharacterTextSplitter

from harbor.knowledge import load_policies

docs = load_policies()

# 1. The general-purpose splitter: tries "\n\n", then "\n", then " ", then characters.
plain = RecursiveCharacterTextSplitter(chunk_size=200, chunk_overlap=40)
chunks = plain.split_documents(docs)
sizes = [len(c.page_content) for c in chunks]
print(f"1) Recursive, size 200 / overlap 40: {len(chunks)} chunks, {min(sizes)}-{max(sizes)} characters")
fees = [c for c in chunks if Path(c.metadata["source"]).name == "fees.md"]
for c in fees[:3]:
    print(f"   {c.page_content[:90]!r}")

# 2. Bigger chunks, and separators that prefer to cut at a "## " heading (what harbor/knowledge.py uses).
smart = RecursiveCharacterTextSplitter(chunk_size=400, chunk_overlap=60,
                                       separators=["\n## ", "\n\n", "\n", ". ", " ", ""])
chunks = smart.split_documents(docs)
print(f"\n2) Recursive, size 400, heading-first: {len(chunks)} chunks")
print("   example:", repr(chunks[3].page_content[:120]))

# 3. Split on Markdown headings and keep the headings as metadata.
md = MarkdownHeaderTextSplitter(headers_to_split_on=[("#", "page"), ("##", "section")])
sections = [s for d in docs for s in md.split_text(d.page_content)]
print(f"\n3) MarkdownHeaderTextSplitter: {len(sections)} sections")
for s in sections[:3]:
    print(f"   {s.metadata}  {s.page_content[:60]!r}")

What happened in part 1: the orphan heading

The first two fees chunks look fine: each starts at a heading and contains its rule. The third one is just '## Lost or damaged items', a 24-character chunk with a heading and no content. Here is why. The section "Lost or damaged items" is longer than 200 characters, so the splitter cannot keep it in one piece. It splits that section at the next separator, "\n", which sits right after the heading. The paragraph that follows is still too long to join the heading, so the heading is left alone and the paragraph is cut again at spaces.

The result is a chunk that will never answer anything, and a paragraph that lost its heading. We checked the other files too (by running the same splitter and printing every chunk): ## Central Library, ## Lighthouse Branch, ## E-books and audiobooks, ## Study rooms and ## Maker space are also orphaned, and the shortest chunks (14 characters) are ## Study rooms and ## Maker space.

Overlap, seen in the same file

Chunks 4 and 5 above also show what chunk_overlap=40 does. Chunk 4 ends with "…we refund the replacement price but" and chunk 5 starts with "we refund the replacement price but not the processing fee." The 35-character phrase appears in both, so whichever chunk is retrieved, the sentence is not completely lost.

What happened in part 2: heading-first chunks

With chunk_size=400 and "\n## " as the first separator, the six files become 12 chunks: exactly two per file (we confirmed this by printing every chunk offline). Each chunk starts at a heading and holds one or two whole sections. The example, chunks[3], is the second chunk of digital.md: it starts at ## Wi-Fi and computers, and, because both sections fit in 400 characters, it also contains the whole ## Printing section. Keep that in mind: in lab 06 a search for "printing price" returns this very chunk.

Why no visible overlap here? The overlap only re-uses whole pieces from the end of the previous chunk, and the pieces at this level are whole sections, all longer than 60 characters. So when cuts happen at headings, the chunks simply do not overlap. That is fine: a cut at a heading does not break a sentence.

What happened in part 3: splitting on Markdown headings

MarkdownHeaderTextSplitter does not count characters at all. It cuts at every heading you list and stores the heading text as metadata. The six files have 17 ## sections in total (three in each file, two in rooms.md), so you get 17 pieces, and each one knows its page and section. That metadata is useful: you could later filter on "section = Late fees" or show the section title next to an answer. The price: the pieces can be any length, so in a real project you often run a size-based splitter on them afterwards.

What you should see
  • 1) Recursive, size 200 / overlap 40: 30 chunks, 14-198 characters, then three fees chunks, the last of which is only '## Lost or damaged items'.
  • 2) Recursive, size 400, heading-first: 12 chunks and an example that starts with '## Wi-Fi and computers\n…'.
  • 3) MarkdownHeaderTextSplitter: 17 sections and three lines of metadata like {'page': 'Branches and opening hours', 'section': 'Central Library'}.
Common mistakes
  • Overlap bigger than the chunk size. The default overlap is 200, so RecursiveCharacterTextSplitter(chunk_size=10) fails with ValueError: Got a larger chunk overlap (200) than chunk size (10), should be smaller. Always set both numbers together.
  • Thinking chunk_size is in words or tokens. Here it counts characters. 400 characters is roughly 60 to 80 English words.
  • Losing the source. split_text(string) returns pieces without your Document's metadata (part 3 of this lab). Use split_documents(docs) when you need to know where a chunk came from, or add the metadata yourself.
  • Reading chunks[3] as "the third chunk". Python lists count from 0, so chunks[3] is the fourth chunk (the second one of digital.md).
  • Changing the chunk size in only one place. Change it in harbor/knowledge.py and every later lab uses it; but the numbers in labs 06 and 07 (12 chunks, the scores) will change too.

Try it yourself

  1. Change line 11 to chunk_size=300, chunk_overlap=40 and run again. You get 17 chunks, and the whole "Lost or damaged items" section (heading and paragraph) now fits in one chunk.
  2. Add separators=["\n## ", "\n\n", "\n", ". ", " ", ""] to the 200-character splitter on line 11. Surprise: still 30 chunks, and the orphans stay. At 200 characters most sections are simply too long, so the splitter must cut after their heading anyway. Separators help only when the size leaves room for whole sections.
  3. Pass strip_headers=False to MarkdownHeaderTextSplitter on line 27. The heading lines (for example ## Central Library) stay in the text as well as in the metadata.
  4. At the end of the file, add from harbor.knowledge import format_docs and print(format_docs(chunks[:2])). You will see each chunk prefixed with [branches.md]: the exact text lab 07 puts into the prompt.
Recap
  • Splitters cut Documents into chunks; split_documents copies each Document's metadata to its chunks.
  • RecursiveCharacterTextSplitter tries separators from best to worst; chunk_size and chunk_overlap are counted in characters.
  • At 200/40 with default separators, headings like ## Lost or damaged items ended up alone: 30 chunks, many useless.
  • At 400/60 with "\n## " first: 12 clean chunks, two per file. This is what harbor/knowledge.py uses.
  • MarkdownHeaderTextSplitter gave 17 sections with the headings as metadata.
