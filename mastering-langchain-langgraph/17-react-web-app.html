The React web app

Put the agent behind a small Node server and a React chat with sources, a tool-call log and an approval card. TypeScript only.

TypeScript · run on a local model (llama3.2 via Ollama)
TypeScript only. This page has no book chapter and no Python version. It builds on lab 09 (tools), lab 13 (pausing for approval and streaming) and lab 15 (middleware), and puts the same library agent in a web page. The code is in the folder harbor-library-ai-ts, under server/ and web/.

Goal

Turn the agent from the terminal labs into a small web app that a visitor can use in a browser. The visitor types a question and watches the answer appear word by word. Under each answer they see which policy files were looked up. A side panel lists every tool call and its result. When the agent wants to place a hold, an approval card appears and a librarian clicks Approve or Reject. You will read every file of the app, from the server to the last line of the user interface.

The idea in brief

  • Two programs, two terminals. A Node.js server (server/) owns the agent, the tools and the model. A React app (web/) runs in the browser and only shows things. The browser never talks to Ollama directly.
  • The agent is the one from lab 15, built with createAgent, plus one new tool, search_policies, which wraps the retriever from labs 04–07. Human approval before place_hold comes from humanInTheLoopMiddleware, and a MemorySaver checkpointer gives each conversation its own memory.
  • The server streams. Two API endpoints, POST /api/chat and POST /api/resume, run the agent and send what happens as Server-Sent Events: answer tokens, tool calls, tool results, an approval request, and "done".
  • The browser reacts. Each event changes a piece of React state, and React redraws the parts of the page that depend on it.
New to React? Components, state and why the page redraws itself

React is a library for building user interfaces out of components: functions that return a description of what the screen should look like, written in JSX (HTML-like tags inside TypeScript, in .tsx files). You never change the page by hand. Instead you keep the data that matters in state, created with the hook useState. Calling a state setter, such as setMessages(...), tells React "this data changed"; React calls your component again and updates only the parts of the page that differ. In this app, every event from the server becomes one or two setter calls, and the chat, the side panel and the approval card follow automatically.

New to Server-Sent Events? How a server streams to a browser

A normal HTTP request gets one reply and is finished. With Server-Sent Events (SSE), the server keeps the reply open and writes small text messages into it whenever it has something new. Each message has an event: line (its type) and a data: line (its content), and ends with a blank line. This is how the answer appears word by word: each new token from the model becomes one event. It is the web version of the streaming you saw in lab 13.

New to web servers? What an API endpoint and Hono are

A web server listens on a port (here 8787) and answers requests. An API endpoint is one address plus a method, like POST /api/chat, that runs a piece of your code and returns data instead of a web page. Hono is a small TypeScript framework for writing such servers: you create an app, register a function per endpoint with app.post(path, handler), and start it. The handler receives a context object c with the request (c.req) and helpers to build the response.

Run it

  1. Open a terminal in the project folder harbor-library-ai-ts. If you have not done it yet for the earlier labs, run pnpm install.
  2. Check that Ollama is running and has both models: ollama list should show llama3.2 and nomic-embed-text. The server needs the embedding model as soon as it starts.
  3. Start the API server: pnpm api. It builds the policy search index first (a few seconds), then prints Harbor assistant API on http://localhost:8787. Leave this terminal open.
  4. Open a second terminal in the same folder and start the web app: pnpm web. Vite prints the address of the app.
  5. Open http://localhost:5173 in your browser. Click one of the example questions (it fills the input box), then Send.
  6. To stop, press Ctrl+C in each terminal.

The server: server/agent.ts

This file builds the agent once, when the server starts, and exports it. It reuses the shared code from src/: the model settings, the four catalog tools and the policy search pipeline.

// The agent behind the web app: catalog tools, a policy search tool, memory per conversation,
// and a librarian's approval before any hold is placed.
import { MemorySaver } from "@langchain/langgraph";
import { createAgent, humanInTheLoopMiddleware, tool } from "langchain";
import { z } from "zod";
import { ALL_TOOLS } from "../src/catalog.js";
import { getModel } from "../src/config.js";
import { buildVectorStore, formatDocs } from "../src/knowledge.js";

const retriever = (await buildVectorStore()).asRetriever({ k: 2 });

const searchPolicies = tool(
  async ({ question }) => formatDocs(await retriever.invoke(question)),
  {
    name: "search_policies",
    description: "Search the library's rules: cards, loans, renewals, late fees, branches and opening hours, " +
      "rooms and the maker space, Wi-Fi, printing and e-books. Returns text tagged with its source file.",
    schema: z.object({ question: z.string() }),
  },
);

export const agent = createAgent({
  model: getModel(),
  tools: [searchPolicies, ...ALL_TOOLS],
  systemPrompt: "You are Harbor City Library's assistant. Use search_policies for questions about rules, fees, " +
    "rooms and opening hours, and the catalog tools for books and member accounts. " +
    "Name the source file when you answer from a policy. Answer briefly.",
  middleware: [humanInTheLoopMiddleware({ interruptOn: { place_hold: true } })],
  checkpointer: new MemorySaver(), // one memory per conversation (thread_id), kept while the server runs
});

The server: server/index.ts

This file is the web server. It has two endpoints and one helper, relay, that runs the agent and turns everything that happens into events for the browser.

// A small HTTP server for the web app. Run: pnpm api  (then pnpm web in a second terminal)
//   POST /api/chat    { threadId, message }            -> a stream of events
//   POST /api/resume  { threadId, approve, reason? }   -> continues a run that paused for approval
// Events are Server-Sent Events: "token" (answer text), "tool_call", "tool_result", "approval", "done", "error".
import { serve } from "@hono/node-server";
import { isAIMessage, isToolMessage, type BaseMessage } from "@langchain/core/messages";
import { Command, isInterrupted } from "@langchain/langgraph";
import { Hono } from "hono";
import { streamSSE, type SSEStreamingApi } from "hono/streaming";
import type { HITLRequest } from "langchain";
import { agent } from "./agent.js";

type AgentInput = Parameters<typeof agent.stream>[0];

/** Run the agent and forward what happens to the browser, step by step. */
async function relay(sse: SSEStreamingApi, input: AgentInput, threadId: string) {
  const send = (event: string, data: unknown) => sse.writeSSE({ event, data: JSON.stringify(data) });
  try {
    const stream = await agent.stream(input, {
      configurable: { thread_id: threadId },
      streamMode: ["messages", "updates"], // tokens as they are written, and each finished step
    });
    for await (const [mode, chunk] of stream) {
      if (mode === "messages") {
        const [token, meta] = chunk;
        // Only text the model writes; tool results also pass through this stream.
        if (meta.langgraph_node === "model_request" && typeof token.content === "string" && token.content) {
          await send("token", token.content);
        }
        continue;
      }
      if (isInterrupted<HITLRequest>(chunk)) { // the run paused before place_hold: ask the librarian
        const request = chunk.__interrupt__[0].value!;
        await send("approval", request.actionRequests.map((a) => ({ name: a.name, args: a.args })));
        continue;
      }
      for (const update of Object.values(chunk)) {
        const messages = (update as { messages?: BaseMessage[] } | undefined)?.messages ?? [];
        for (const m of messages) {
          if (isAIMessage(m)) {
            for (const call of m.tool_calls ?? []) await send("tool_call", { id: call.id, name: call.name, args: call.args });
          } else if (isToolMessage(m)) {
            await send("tool_result", { id: m.tool_call_id, name: m.name, content: String(m.content) });
          }
        }
      }
    }
    await send("done", {});
  } catch (error) {
    await send("error", (error as Error).message);
  }
}

const app = new Hono();

app.post("/api/chat", async (c) => {
  const { threadId, message } = await c.req.json<{ threadId: string; message: string }>();
  return streamSSE(c, (sse) => relay(sse, { messages: [{ role: "user", content: message }] }, threadId));
});

app.post("/api/resume", async (c) => {
  const { threadId, approve, reason } = await c.req.json<{ threadId: string; approve: boolean; reason?: string }>();
  const decision = approve
    ? { type: "approve" as const }
    : { type: "reject" as const, message: `A librarian rejected this hold: ${reason || "no reason given"}.` };
  return streamSSE(c, (sse) => relay(sse, new Command({ resume: { decisions: [decision] } }) as AgentInput, threadId));
});

const port = Number(process.env.PORT ?? 8787);
serve({ fetch: app.fetch, port });
console.log(`Harbor assistant API on http://localhost:${port}`);

The web app: web/src/sse.ts

The browser has a built-in reader for Server-Sent Events, EventSource, but it can only send GET requests without a body. Our endpoints need a JSON body, so this file sends a POST with fetch and reads the event stream itself.

// POST a JSON body and read the Server-Sent Events that come back.
// (The browser's EventSource only does GET requests, so we read the stream ourselves.)
export type AgentEvent =
  | { event: "token"; data: string }
  | { event: "tool_call"; data: { id: string; name: string; args: Record<string, unknown> } }
  | { event: "tool_result"; data: { id: string; name: string; content: string } }
  | { event: "approval"; data: { name: string; args: Record<string, unknown> }[] }
  | { event: "done"; data: Record<string, never> }
  | { event: "error"; data: string };

export async function postEvents(url: string, body: unknown, onEvent: (e: AgentEvent) => void) {
  const response = await fetch(url, {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify(body),
  });
  if (!response.ok || !response.body) throw new Error(`Server answered ${response.status}`);

  const reader = response.body.pipeThrough(new TextDecoderStream()).getReader();
  let buffer = "";
  for (;;) {
    const { value, done } = await reader.read();
    if (done) break;
    buffer += value;
    // Events are separated by a blank line; each has "event: ..." and "data: ..." lines.
    const blocks = buffer.split(/\r?\n\r?\n/);
    buffer = blocks.pop()!; // the last piece may be incomplete: keep it for the next read
    for (const block of blocks) {
      const event = block.match(/^event: (.*)$/m)?.[1];
      const data = block.match(/^data: (.*)$/m)?.[1];
      if (event && data !== undefined) onEvent({ event, data: JSON.parse(data) } as AgentEvent);
    }
  }
}

The web app: web/src/App.tsx

The whole user interface is one component. Read it in four parts: the state (lines 15–21), the event handler handle (27–54), the actions that start a request (56–91), and the JSX that draws the page (96–158).

import { useState, type FormEvent } from "react";
import { postEvents, type AgentEvent } from "./sse";

type Message = { role: "user" | "assistant"; text: string; sources: string[] };
type Step = { id: string; name: string; args: Record<string, unknown>; result?: string };
type Approval = { name: string; args: Record<string, unknown> }[];

const EXAMPLES = [
  "How much is the late fee for a book?",
  "Do you have books by Mara Quint? Is one on the shelf?",
  "I'm member M-1001. Please place a hold on B007.",
];

export default function App() {
  const [threadId, setThreadId] = useState(() => crypto.randomUUID()); // one memory per conversation
  const [messages, setMessages] = useState<Message[]>([]);
  const [steps, setSteps] = useState<Step[]>([]);
  const [approval, setApproval] = useState<Approval | null>(null);
  const [reason, setReason] = useState("");
  const [input, setInput] = useState("");
  const [busy, setBusy] = useState(false);

  // Change only the last message (the answer being written).
  const updateLast = (change: (m: Message) => Message) =>
    setMessages((all) => [...all.slice(0, -1), change(all[all.length - 1])]);

  function handle(e: AgentEvent) {
    switch (e.event) {
      case "token":
        updateLast((m) => ({ ...m, text: m.text + e.data }));
        break;
      case "tool_call": {
        const call = e.data;
        setSteps((all) => (all.some((s) => s.id === call.id) ? all : [...all, call]));
        break;
      }
      case "tool_result": {
        const result = e.data;
        setSteps((all) => all.map((s) => (s.id === result.id ? { ...s, result: result.content } : s)));
        if (result.name === "search_policies") {
          const files = [...result.content.matchAll(/\[([\w-]+\.md)\]/g)].map((match) => match[1]);
          updateLast((m) => ({ ...m, sources: [...new Set([...m.sources, ...files])] }));
        }
        break;
      }
      case "approval":
        setApproval(e.data);
        updateLast((m) => (m.text ? m : { ...m, text: "Paused: a librarian must approve this first." }));
        break;
      case "error":
        updateLast((m) => ({ ...m, text: `${m.text}\n[Error: ${e.data}]` }));
        break;
    }
  }

  async function run(url: string, body: unknown, userText?: string) {
    setBusy(true);
    setMessages((all) => [
      ...all,
      ...(userText ? [{ role: "user" as const, text: userText, sources: [] }] : []),
      { role: "assistant", text: "", sources: [] },
    ]);
    try {
      await postEvents(url, body, handle);
    } catch (error) {
      handle({ event: "error", data: (error as Error).message });
    } finally {
      setBusy(false);
    }
  }

  function send(event: FormEvent) {
    event.preventDefault();
    const text = input.trim();
    if (!text || busy) return;
    setInput("");
    void run("/api/chat", { threadId, message: text }, text);
  }

  function decide(approve: boolean) {
    setApproval(null);
    void run("/api/resume", { threadId, approve, reason });
    setReason("");
  }

  function newConversation() {
    setThreadId(crypto.randomUUID());
    setMessages([]);
    setSteps([]);
    setApproval(null);
  }

  // What an answer shows before its first word arrives.
  const placeholder = (isLast: boolean) => (isLast && busy ? "…" : "");

  return (
    <div className="page">
      <header>
        <div>
          <p className="eyebrow">Harbor City Library</p>
          <h1>Ask the library assistant</h1>
        </div>
        <button className="ghost" onClick={newConversation} disabled={busy}>New conversation</button>
      </header>

      <main>
        <section className="chat" aria-label="Conversation">
          {messages.length === 0 && (
            <div className="empty">
              <p>Ask about opening hours, fees, rooms or the catalog. Try:</p>
              {EXAMPLES.map((q) => (
                <button key={q} className="example" onClick={() => setInput(q)}>{q}</button>
              ))}
            </div>
          )}
          {messages.map((m, i) => (
            <article key={i} className={`bubble ${m.role}`}>
              <p>{m.text || placeholder(i === messages.length - 1)}</p>
              {m.sources.length > 0 && <p className="sources">Looked up in: {m.sources.join(", ")}</p>}
            </article>
          ))}

          {approval && (
            <div className="approval" role="alert">
              <strong>A librarian must approve this action</strong>
              {approval.map((a, i) => (
                <code key={i}>{a.name}({JSON.stringify(a.args)})</code>
              ))}
              <input value={reason} onChange={(e) => setReason(e.target.value)} placeholder="Reason if you reject (optional)" />
              <div className="row">
                <button onClick={() => decide(true)}>Approve</button>
                <button className="ghost" onClick={() => decide(false)}>Reject</button>
              </div>
            </div>
          )}

          <form onSubmit={send}>
            <input value={input} onChange={(e) => setInput(e.target.value)} placeholder="Type a question" disabled={busy || !!approval} />
            <button disabled={busy || !!approval || !input.trim()}>Send</button>
          </form>
        </section>

        <aside aria-label="What the agent did">
          <h2>What the agent did</h2>
          {steps.length === 0 && <p className="muted">Tool calls appear here as they happen.</p>}
          <ol>
            {steps.map((s) => (
              <li key={s.id}>
                <code>{s.name}({JSON.stringify(s.args)})</code>
                {s.result !== undefined ? <pre>{s.result}</pre>
                  : <span className="muted"> {approval ? "waiting for approval" : "running…"}</span>}
              </li>
            ))}
          </ol>
        </aside>
      </main>
    </div>
  );
}

Approving a hold: pause and resume

Ask "I'm member M-1001. Please place a hold on B007." The model asks for place_hold, the middleware pauses the run, and the first request ends with an approval event. Nothing happens until the librarian clicks. The click starts a second request, to /api/resume, in the same thread.

What you should see. These are the runs we checked in Chrome. The wording of the answers will differ from ours, and sometimes the model chooses differently.

  • "How much is the late fee for a book?" The side panel shows a search_policies call and its result. The answer says 0.20 EUR per item per day, up to a maximum of 5 EUR per item, and under it: Looked up in: fees.md, digital.md. Two files, because the retriever returns the 2 closest chunks; that does not mean the answer used both.
  • "I'm member M-1001. Please place a hold on B007." The run pauses. The answer bubble says Paused: a librarian must approve this first. (unless the model wrote something first), and the card shows place_hold({"item_id":"B007","member_id":"M-1001"}). The side panel says "waiting for approval". Click Approve: the tool result appears, "Hold placed on Machine Learning for Curious Minds for Lea Martin…", followed by the model's answer.

A source the model made up. While testing the server with curl, the model once ended an answer with "(Source: Search Policies, Section 3.3: Holds)". There is no section 3.3 in any policy file; the model invented a reference that looks official. This is why the app shows the "Looked up in" line from the real tool result, written by our code, and does not rely on the model to name its sources.

Common problems.

  • Why pnpm api and not pnpm server? pnpm has a built-in command called server, and built-in commands win over scripts with the same name: pnpm server runs pnpm's own command and exits without starting anything. (pnpm run server would work.) Naming the script api avoids the clash.
  • Port already in use. If pnpm api fails with EADDRINUSE, another program (often a server you started earlier and forgot) uses port 8787. Stop it, or start with another port (PORT variable) and change the proxy target in web/vite.config.ts to match. If 5173 is busy, Vite picks the next free port and prints it; open that address.
  • Ollama is not running. The server needs Ollama as soon as it starts, to embed the policies, so it fails before printing its address. If Ollama stops later, the answer bubble shows [Error: ...]. Start Ollama and check ollama list.
  • Only pnpm web is running. The page loads, but every question ends with "[Error: Server answered 502]", and the pnpm web terminal prints http proxy error: /api/chat with ECONNREFUSED, because the proxy has nowhere to forward /api. Start pnpm api in the other terminal.
  • The agent forgot the conversation. MemorySaver keeps conversations in the server's memory. Restarting pnpm api erases them all, including a hold that was waiting for approval: clicking Approve then has no paused run to resume. Click New conversation and ask again. For memory that survives restarts, use the SQLite checkpointer from lab 11.
  • Answers vary. The same question can lead to different tool calls, a different wording, or no tool call at all (then no "Looked up in" line). With a small local model this is normal; check the side panel to see what really happened.

Try it yourself

  1. Reject with a reason. Ask for the B007 hold again, type a reason ("this copy is reserved for a class") and click Reject. Read the tool result in the side panel and compare it with the model's answer: did it describe the refusal correctly?
  2. Check memory. Ask "What is the late fee for a book?", then "And with a junior card?" in the same conversation. Then click New conversation and ask only the second question. The difference is the thread id.
  3. Show more chunks. In server/agent.ts line 10, change k: 2 to k: 4 and restart the server. The "Looked up in" line gets longer; does the answer get better?
  4. Watch the raw events. Open the browser's developer tools (F12), tab Network, send a question and click the chat request. You can see the events arrive one by one.
  5. Add an event. Make the server send send("thread", threadId) at the start of relay, add the case to the AgentEvent type in sse.ts, and run pnpm typecheck. TypeScript tells you where the new event is not handled yet.
Recap
  • The app is two programs: a Hono server that owns the agent (pnpm api, port 8787) and a React app served by Vite (pnpm web, port 5173), which forwards /api to the server.
  • The server runs agent.stream with the "messages" and "updates" modes and forwards tokens, tool calls, tool results, approval requests and errors as Server-Sent Events.
  • sse.ts reads those events from a POST response with fetch, because EventSource only does GET.
  • App.tsx keeps everything in useState; each event becomes a state change and React redraws the page. Tool calls are paired with results by id, and repeated ids are skipped.
  • A hold is two requests in the same thread: /api/chat pauses with an approval event, /api/resume continues with the librarian's decision. The pause lives in MemorySaver, so it is lost if the server restarts.
