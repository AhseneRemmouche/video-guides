Self-hosted setup

Imagination Studio on your Ubuntu + NVIDIA server

A local AI film studio — generate images, video with sound, voices and music, then edit and export. This walks you through installing it on an Ubuntu 24.04 box with NVIDIA GPU(s), reaching it safely from your laptop, and actually using it.

The 60-second shape of it

Install the NVIDIA driver + CUDA 13 → clone the repo → run one install script (it builds the GPU engines from source and downloads the model weights) → start the app on 127.0.0.1:7870 → reach it from your laptop over an SSH tunnel. Everything lives on your server; nothing is sent to a cloud.

Source: drowzeys/Imagination-Studio-by-keys-Wasserman · Apache-2.0 code, model weights keep their own licences. Commands here are quoted from the repo's docs/rtx-pro-6000.md and docs/installation.md.

Read first

This is a big, real installation, not a lightweight app: it builds CUDA engines on your machine and downloads ~125 GB of model weights for the core install (~400 GB for everything). Run the commands yourself and review each download — I've written them out but deliberately don't run anything on your server for you.

What this installs

The core install gives you picture generation (Qwen-Image-2.1-Turbo), FastH3 text-to-video with sound, motion graphics, the Finish/export tools, and phone notifications. Optional add-ons (with --all or individual flags) include FLUX3-K images, reference-to-video, voices (Fish Audio Drama 3), music (MiniMax-Music3 / YuE2), sound effects, and the Bolt "brain".

1 · Check your hardware

Run these on the server first and keep the output — it decides which features you can run.

# GPU model(s), VRAM and driver version
nvidia-smi --query-gpu=index,name,memory.total,driver_version --format=csv

# System RAM (need 64 GB min, 128 GB recommended)
free -g

# Ubuntu version (want 22.04 or 24.04) and architecture (must be x86_64)
lsb_release -d && uname -m

# Free disk where models will live (want 125 GB core / ~400 GB for --all)
df -h /

If nvidia-smi isn't found, you don't have the driver yet — that's Step 2. If uname -m says aarch64 you have an ARM machine (e.g. a DGX Spark); use the Spark path in the README instead of this x86_64 one.

Tip

Multiple mid-size cards don't combine their VRAM for one render — a single job runs on a single card (extra cards render other jobs in parallel, see Step 8). So the biggest single card you have is what sets your ceiling. Paste me your nvidia-smi output and I'll tell you exactly which flags to use.

2 · Prerequisites: driver, CUDA 13, tools

You need NVIDIA driver 580+, the CUDA 13 toolkit (so nvcc can compile the engines for your card), plus git, ffmpeg, curl. Docker is optional and its prebuilt engines are ARM/Spark-only, so on x86_64 the installer always builds from source.

# Add NVIDIA's CUDA repo for Ubuntu 24.04 (skip if already added)
wget https://developer.download.nvidia.com/compute/cuda/repos/ubuntu2404/x86_64/cuda-keyring_1.1-1_all.deb
sudo dpkg -i cuda-keyring_1.1-1_all.deb
sudo apt update

# Driver + CUDA 13 toolkit + the build/runtime tools
sudo apt install -y git ffmpeg curl cuda-toolkit-13-0 nvidia-driver-580

# Put nvcc on PATH and confirm it is 12.9 or newer
export PATH=/usr/local/cuda/bin:$PATH
nvcc --version

# If the driver was just installed, reboot so it loads, then re-check
sudo reboot
# after reboot:  nvidia-smi

Pick the driver your card/distro recommends — nvidia-driver-580 is the minimum branch. On a headless server, keep nvidia-persistenced enabled (it ships enabled); stopping it can break GPU start-up.

3 · Install Studio

Clone the repo and run the CUDA installer. oneshot-setup-rtx-6000.sh is the generic x86_64 entry point — it pins the GPU you choose, then runs the shared CUDA install. The four PREFIX/SPARK_MODELS/STUDIO_HOME/STUDIO_GPU values below control where things go and which GPU is the "head" card; you must pass the same four again when you start the app.

git clone https://github.com/drowzeys/Imagination-Studio-by-keys-Wasserman.git
cd Imagination-Studio-by-keys-Wasserman

# STUDIO_GPU is the nvidia-smi index of the card to use (0 = first card).
# Required when the machine has more than one compute GPU.
# /data/studio is just an example — use any path with enough free disk.
PREFIX=/data/studio SPARK_MODELS=/data/studio/models \
STUDIO_HOME=/data/studio/ImaginationStudio STUDIO_GPU=0 \
bash oneshot-setup-rtx-6000.sh

Run with no flag and it shows a checklist of every part your machine can run, each with its download size, then installs what you leave ticked. Useful flags:

FlagInstallsExtra size
(none)Core: pictures + FastH3 video with sound, motion graphics, Finish, notifications~125 GB
--allEvery feature the card runs~400 GB total
--image-onlyQwen-Image-2.1 only (good for smaller cards)~26 GB

--voiceFish Audio Drama 3 voices+41 GB
--music / --yue2MiniMax Music 3 / YuE2 songs+22 / +14 GB
--soundSound effects & foley HF-gated+11 GB
--verifyCheck an existing install, download nothing—

The installer builds the video, music and voice CUDA engines from source for your card — each takes a few minutes. Grab a coffee; the model downloads are the long part.

4 · Accept the gated model licences (if using FLUX3-K or sound)

FLUX3-K and the sound-effects models are gated on Hugging Face. Before downloading them the installer checks your signed-in HF account has accepted each licence. If you're only doing the core install (Qwen + FastH3), you can skip this.

# Install the HF CLI if needed, then sign in (paste a token from huggingface.co/settings/tokens)
pip install -U "huggingface_hub[cli]"
hf auth login

Then open each gated model's page while signed in and click Agree before re-running the install with its flag. Anything whose licence isn't accepted is simply left out, and the install prints the command to add it later.

Don't paste secrets in chat

Enter your HF token directly on the server with hf auth login — never post tokens, access keys or private addresses into issues, logs or screenshots.

5 · First start

Start the app with the same four values you installed with. It renders a quick test image/clip on first run and then serves the UI on localhost port 7870.

PREFIX=/data/studio SPARK_MODELS=/data/studio/models \
STUDIO_HOME=/data/studio/ImaginationStudio STUDIO_GPU=0 \
bash scripts/app.sh

# It prints:  http://127.0.0.1:7870
Where your work lives

Projects, renders, uploads, voices, music, LoRAs and settings are kept under ~/ImaginationStudio (or your STUDIO_HOME). Back that folder up before changing installs — models and the Python env are separate from it.

6 · Open it from your laptop (the safe way)

Studio binds to 127.0.0.1 by default — it is not exposed to the network, which is exactly what you want. To use it from your Windows laptop, forward the port over SSH. Nothing is published to the internet.

Option A — SSH tunnel (recommended)

# Run this in a terminal on YOUR LAPTOP (PowerShell/Windows has ssh built in).
# Replace user@your-server with your real login/host.
ssh -L 7870:127.0.0.1:7870 user@your-server

# Leave it open, then browse on the laptop to:
http://127.0.0.1:7870

Option B — phone / other devices on the LAN

For a phone or another machine, the Studio has a built-in access key: in the app go to Settings → Access key for a QR code and remote sign-in. Other devices need that key; this host itself never does.

Don't do this

Avoid binding the app to 0.0.0.0 or opening port 7870 on a public firewall. It's a local creative tool, not a hardened public service — keep it behind the SSH tunnel or your VPN/LAN with the access key.

7 · Keep it running after you log out

scripts/app.sh runs in the foreground, so a plain SSH session ends when you disconnect. Two easy options:

herdr (quick)

herdr is a single Rust binary that keeps your terminals running in a background server, so the app survives when you close the client or your SSH connection drops.

# install herdr (one binary, no dependencies)
curl -fsSL https://herdr.dev/install.sh | sh

# start it where the repo lives
cd ~/Imagination-Studio-by-keys-Wasserman
herdr

# inside herdr, start the app with your four env values (Step 5), then:
#   detach with  Ctrl-b  q   — the app keeps running in herdr's background server
#   reattach later (even after a new SSH login) with:
herdr

herdr survives a disconnect, but a full machine reboot doesn't preserve the running processes (it restores the layout, not the live render). For start-on-boot, use the systemd service below.

systemd service (starts on boot)

sudo tee /etc/systemd/system/imagination-studio.service >/dev/null <<'UNIT'
[Unit]
Description=Imagination Studio
After=network-online.target

[Service]
User=YOUR_USER
WorkingDirectory=/home/YOUR_USER/Imagination-Studio-by-keys-Wasserman
Environment=PREFIX=/data/studio
Environment=SPARK_MODELS=/data/studio/models
Environment=STUDIO_HOME=/data/studio/ImaginationStudio
Environment=STUDIO_GPU=0
Environment=PATH=/usr/local/cuda/bin:/usr/bin:/bin
ExecStart=/bin/bash scripts/app.sh
Restart=on-failure

[Install]
WantedBy=multi-user.target
UNIT
sudo systemctl daemon-reload
sudo systemctl enable --now imagination-studio
# logs:  journalctl -u imagination-studio -f
Heads up

Edit YOUR_USER and the paths to match your box. A render holds the GPU, so don't run the systemd service and a manual app.sh for the same card at once.

8 · Using more than one GPU

You start one head (the STUDIO_GPU card). Add the rest from inside the app at Machine → Sparks → Local GPUs:

  1. Local GPUs lists each card with its VRAM and live readings.
  2. Press Start on another card — it spins up a private worker process (own ports, home, GPU lock) that shares the same install and weights; no SSH or re-download.
  3. A single Studio manages up to four local GPUs including the head.
  4. Set Render clips on to a worker. Only independent single video jobs move to workers; images, audio, training and exports stay on the head. No render spans multiple cards, and their VRAM is never added together.

Remote machines (other servers) can also be added as Sparks over SSH to render in parallel — the worker apps stay on their own localhost and are reached through tunnels the head opens itself.

9 · Using the Studio (the UI)

Open http://127.0.0.1:7870. The header shows your build (e.g. CUDA · <card> · H3-CUDA). The main areas:

AreaWhat you do there
Story & ProductionImport scripts, plan shots, keep a film bible, build storyboards (the "Slate" workflow).
Image & VideoPick a model, make candidate pictures, edit them, and generate clips with sound (first/last keyframes, LoRAs).
SoundDrama 3 voices, MiniMax-Music3 / YuE2 songs, effects and foley (where installed).
Edit & FinishOrganize takes, grade, mix, motion graphics, and export to Resolve / Premiere / After Effects.
Machine & SettingsRuntime memory, model installation, the access key, connected GPUs/Sparks.
Verify features first

Go to Machine → Feature checks and run the opt-in checks: each one renders a small test and, if it passes, unlocks that feature's settings on your hardware. That's the honest way to see what your GPU can actually do.

10 · Render from the shell (optional)

Everything the UI does has a command-line equivalent — handy for scripting or a quick smoke test. Run these from the repo folder.

# Text → image
bash scripts/image.sh "A neon shop sign that reads OPEN LATE, rainy night, reflections" out.png

# Text → video (with sound). Prints out.mp4 (+ out.png first frame)
bash scripts/video.sh "A hummingbird hovering over red flowers, soft wing hum" out.mp4

# Animate an image you already have
FIRST_FRAME=photo.jpg WIDTH=1344 HEIGHT=768 bash scripts/video.sh "She turns and smiles" out.mp4

# Text → image → video in one go
bash scripts/studio.sh "A lighthouse keeper on a cliff at dusk, storm clouds" \
                       "He raises a lantern; waves crash. He says: Storm's coming." out.mp4

Useful env vars: FRAMES= (must be 17n+5: 56, 90, 124, 192, 243…), WIDTH/HEIGHT, SEED, QUALITY=high. Pass the same PREFIX/STUDIO_GPU env values if you set custom paths.

Upgrades

cd Imagination-Studio-by-keys-Wasserman
git pull
# moves the install to the new version; downloads NO new weights, leaves your projects alone
PREFIX=/data/studio SPARK_MODELS=/data/studio/models \
STUDIO_HOME=/data/studio/ImaginationStudio STUDIO_GPU=0 \
bash oneshot-setup-rtx-6000.sh --upgrade
# then restart the app (Step 5) so it serves the new pages. Run it when nothing is rendering.

Troubleshooting

SymptomFix
Jobs refused for memory on an idle GPU, driver 590+Newer drivers keep freed memory in hidden pools. Either install NVIDIA's validated R580 branch, or disable the pools: echo "options nvidia NVreg_EnableSystemMemoryPools=0" | sudo tee /etc/modprobe.d/nvidia-no-sysmem-pools.conf then sudo update-initramfs -u and reboot. One-off relief: sudo sysctl vm.drop_caches=2.
A clip is refused as too bigThe memory guard estimates peak use and blocks jobs that won't fit, suggesting the nearest size/length that will. Lower the resolution or frame count.
The "Bolt" brain won't installBolt's native engine is DGX-Spark-only. On x86_64 run it via llama.cpp (BOLT_BACKEND=llamacpp) or point Settings → Connections at any OpenAI-compatible server. The rest of the studio installs fine without it.
Renders lose their sound / fail at encodeffmpeg is missing — sudo apt install -y ffmpeg and restart.
Video builds but is very slowYour card is offloading weights to RAM. Expect it on sub-96 GB cards; add system RAM or use --image-only.

A note on licences

The Studio code is Apache-2.0, but the model weights keep their own terms. Several are non-commercial (Qwen-Image-2.1, MMAudio), MiniMax H3 has territory limits, and Fish Audio hosted services need separate licensing. Check each model's licence before any commercial use — the repo doesn't redistribute the weights and surfaces each gate during install.
