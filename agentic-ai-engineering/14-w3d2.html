Week 3 · Day 2 — Tools and Context: a Financial Research Crew

Give a crew real tools (web search) and pass one task's output as context to the next. Build a financial-research crew that researches a company and writes a report.

Companion to Ed Donner's course · uv setup · Python (+ TypeScript/React where it fits) · code from the course repo

Day two keeps the same five-step rhythm from day one but adds two new abilities to a crew. First, tools: how you give a CrewAI agent a capability beyond the model's own knowledge — here, live web search. Second, context: how you pass one task's output into the next task as input. The project is a financial_researcher crew: a researcher agent gathers up-to-date information about a company, and an analyst agent turns that research into a polished report.

This builds directly on day one. You create the project the same way (crewai create crew financial_researcher), fill in the same YAML files, wire the same crew.py and main.py. The two genuinely new ideas are the tools=[...] list on an agent and the context: list on a task. Everything else should feel familiar.

Why a tool is needed: the knowledge cut-off

An LLM only knows what it saw during training. Ask it about a company's "recent" news and it answers from its training cut-off, which may be a year or two old. The instructor hits exactly this: without a tool, the research came back "as of October 2023", which is clearly stale. The fix is to give the researcher agent a tool that runs real Google searches, so it can read today's news.

New to this? What a tool is

A tool is a capability you hand an agent so it can do something the model cannot do on its own — search the web, read a file, send a message, call an API. The model decides when to use the tool; the tool does the actual work and returns a result the model can read. This is the same idea as function calling from earlier weeks, wrapped in CrewAI's own Tool objects. CrewAI ships several ready-made tools in the crewai_tools package; today we use one of them.

Sign up for Serper (free)

The web-search tool is SerperDevTool, which calls a service named Serper — a fast, cheap API for running Google searches from code.

  1. Go to serper.dev and sign up. You get 2,500 free credits, far more than this course needs.
  2. Copy your API key from the dashboard.
  3. Add it to your .env file as SERPER_API_KEY.
Serper, not SerpAPI. The environment variable must be SERPER_API_KEY (Serper, the service at serper.dev). There is a different, similarly named service called SerpAPI — do not mix them up. "SERP" stands for Search Engine Results Page, the common name for this kind of service.
Honesty note. Serper is a keyed, paid-tier service (with a free credit allowance). The search calls in this project were not run live for this guide, because they need your own Serper key. The code and the instructor's results are shown as in the course; the crew wiring was verified locally with a free Ollama model and web search left out.

The agents

Two agents: a researcher and an analyst. Both carry the {company} template placeholder, filled at run time from main.py. The tool is not mentioned here — it is attached in crew.py, not in the YAML.

The tasks: passing context forward

Two tasks. The new idea is on the second task: context: [research_task] tells CrewAI to feed the research task's output into the analysis task as input. Without it, the analyst would have nothing to analyse.

# src/research_crew/config/tasks.yaml
research_task:
  description: >
    Conduct thorough research on company {company}. Focus on:
    1. Current company status and health
    2. Historical company performance
    3. Major challenges and opportunities
    4. Recent news and events
    5. Future outlook and potential developments

    Make sure to organize your findings in a structured format with clear sections.
  expected_output: >
    A comprehensive research document with well-organized sections covering
    all the requested aspects of {company}. Include specific facts, figures,
    and examples where relevant.
  agent: researcher

analysis_task:
  description: >
    Analyze the research findings and create a comprehensive report on {company}.
    Your report should:
    1. Begin with an executive summary
    2. Include all key information from the research
    3. Provide insightful analysis of trends and patterns
    4. Offer a market outlook for company, noting that this should not be used for trading decisions
    5. Be formatted in a professional, easy-to-read style with clear headings
  expected_output: >
    A polished, professional report on {company} that presents the research
    findings with added analysis and insights. The report should be well-structured
    with an executive summary, main sections, and conclusion.
  agent: analyst
  context:
    - research_task
  output_file: output/report.md
New to this? What context does

By default each task starts fresh. The context: field lists other tasks whose outputs should be handed to this task as background. Here the analysis task lists research_task, so the researcher's findings become part of the analyst's input. This is how information flows between agents in a crew: not through shared variables in your code, but by naming which earlier tasks a later task depends on.

The crew module: attaching the tool

Here is where the search tool is wired on. It is imported from crewai_tools and passed to the researcher through a tools=[...] list. Only the researcher gets it; the analyst does not need search because it works from the research it is handed.

# src/financial_researcher/crew.py
from crewai import Agent, Crew, Process, Task
from crewai.project import CrewBase, agent, crew, task
from crewai_tools import SerperDevTool

@CrewBase
class ResearchCrew():
    """Research crew for comprehensive topic analysis and reporting"""

    @agent
    def researcher(self) -> Agent:
        return Agent(
            config=self.agents_config['researcher'],
            verbose=True,
            tools=[SerperDevTool()]
        )

    @agent
    def analyst(self) -> Agent:
        return Agent(
            config=self.agents_config['analyst'],
            verbose=True
        )

    @task
    def research_task(self) -> Task:
        return Task(
            config=self.tasks_config['research_task']
        )

    @task
    def analysis_task(self) -> Task:
        return Task(
            config=self.tasks_config['analysis_task'],
            output_file='output/report.md'
        )

    @crew
    def crew(self) -> Crew:
        """Creates the research crew"""
        return Crew(
            agents=self.agents,
            tasks=self.tasks,
            process=Process.sequential,
            verbose=True,
        )

The runner

main.py sets the company and runs the crew. It also makes sure the output folder exists before the run.

#!/usr/bin/env python
# src/financial_researcher/main.py
import os
from financial_researcher.crew import ResearchCrew

# Create output directory if it doesn't exist
os.makedirs('output', exist_ok=True)

def run():
    """
    Run the research crew.
    """
    inputs = {
        'company': 'Apple'
    }

    # Create and run the crew
    result = ResearchCrew().crew().kickoff(inputs=inputs)

    # Print the result
    print("\n\n=== FINAL REPORT ===\n\n")
    print(result.raw)

    print("\n\nReport has been saved to output/report.md")

if __name__ == "__main__":
    run()

What you should see. On the first run without the tool, the report is dated from the model's training cut-off. After adding SerperDevTool() you will see search activity in the verbose output ("Search the internet with Serper…"), and the report now includes current news. The finished output/report.md reads like a genuine, useful analyst report, built in minutes.
Common mistakes.
  • No Serper key. Without SERPER_API_KEY in .env, the search tool fails. Add the key, or remove the tool to run offline.
  • Forgetting context. Leave out context: [research_task] and the analyst writes from nothing, producing a vague or empty report.
  • Stale data looks like a bug. A report "as of 2023" is not broken code — it means the agent answered from training data because the tool was not attached yet.
  • Running from the wrong folder. crewai run must run from inside the financial_researcher folder.
In TypeScript. CrewAI's tools and context have no TypeScript equivalent, because the framework itself is Python only. In Node you would reproduce this by hand: call the Serper HTTP API yourself to fetch search results, stuff them into the prompt for a "research" model call, then pass that text into a second "analyst" model call. CrewAI's value is that tools=[SerperDevTool()] and context: [research_task] replace all of that plumbing with two short declarations.
Recap
  • A tool gives an agent a capability the model lacks. SerperDevTool adds live Google search and fixes the knowledge cut-off problem.
  • Attach a tool in crew.py with tools=[SerperDevTool()] on the agent that needs it — not in the YAML.
  • Serper (serper.dev) is a keyed service with a free credit tier; its key goes in .env as SERPER_API_KEY and was not run live for this guide.
  • context: [research_task] passes one task's output into the next as input — the way information flows between agents in a crew.
  • The researcher gathers current facts; the analyst, given those facts as context, writes the report. Both run in a simple sequential crew.
