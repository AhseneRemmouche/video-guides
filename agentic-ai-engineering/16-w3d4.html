Week 3 · Day 4 — Memory and a Coder Crew

Add memory (short-term, long-term, entity) backed by vector storage and SQLite, and build a coder crew whose agent writes and runs Python in a safe sandbox.

Companion to Ed Donner's course · uv setup · Python (+ TypeScript/React where it fits) · code from the course repo

Day four has two halves. First we go back to the stock_picker crew and explain the memory feature that was wired in on day three — how a crew can remember things across steps and even across runs. Then we build a brand new, very small crew: the coder, a single agent that writes Python code and runs it inside a safe Docker sandbox.

Part one: memory

Memory is about giving an LLM relevant information from the past each time you call it. You could do this by hand — store things in variables and paste them into prompts — but CrewAI offers ready-made memory building blocks. The benefit is you get up and running fast; the trade-off is that a lot happens behind the scenes, so it is harder to see exactly what the model receives.

New to this? What "memory" really means for an LLM

An LLM has no memory of its own between calls — each call is fresh. "Memory" is just a system that stores useful text and slips the relevant bits back into the prompt next time. So when the instructor says memory can feel magical, the plain truth underneath is: memory means more relevant context shoved into the prompt. CrewAI decides what to store and what to retrieve for you.

The three memory types this crew uses

New to this? Vector stores, RAG storage and embeddings

A vector store keeps text as lists of numbers (embeddings) that capture meaning, so you can find the most relevant past notes by similarity, not exact words. This is the retrieval half of "retrieval-augmented generation" (RAG). CrewAI's RAGStorage uses an embedding model to turn stored text into vectors and a local Chroma database to hold them. You do not need to understand the internals to use it — you create the objects and CrewAI does the rest.

The memory wiring lives in the stock_picker crew.py from day three. Here is that file again, this time to read the memory parts (imports at the top, the three memory objects and memory=True inside @crew).

from crewai import Agent, Crew, Process, Task
from crewai.project import CrewBase, agent, crew, task
from crewai_tools import SerperDevTool
from pydantic import BaseModel, Field
from typing import List
from .tools.push_tool import PushNotificationTool
from crewai.memory import LongTermMemory, ShortTermMemory, EntityMemory
from crewai.memory.storage.rag_storage import RAGStorage
from crewai.memory.storage.ltm_sqlite_storage import LTMSQLiteStorage

class TrendingCompany(BaseModel):
    """ A company that is in the news and attracting attention """
    name: str = Field(description="Company name")
    ticker: str = Field(description="Stock ticker symbol")
    reason: str = Field(description="Reason this company is trending in the news")

class TrendingCompanyList(BaseModel):
    """ List of multiple trending companies that are in the news """
    companies: List[TrendingCompany] = Field(description="List of companies trending in the news")

class TrendingCompanyResearch(BaseModel):
    """ Detailed research on a company """
    name: str = Field(description="Company name")
    market_position: str = Field(description="Current market position and competitive analysis")
    future_outlook: str = Field(description="Future outlook and growth prospects")
    investment_potential: str = Field(description="Investment potential and suitability for investment")

class TrendingCompanyResearchList(BaseModel):
    """ A list of detailed research on all the companies """
    research_list: List[TrendingCompanyResearch] = Field(description="Comprehensive research on all trending companies")


@CrewBase
class StockPicker():
    """StockPicker crew"""

    agents_config = 'config/agents.yaml'
    tasks_config = 'config/tasks.yaml'

    @agent
    def trending_company_finder(self) -> Agent:
        return Agent(config=self.agents_config['trending_company_finder'],
                     tools=[SerperDevTool()], memory=True)
    
    @agent
    def financial_researcher(self) -> Agent:
        return Agent(config=self.agents_config['financial_researcher'], 
                     tools=[SerperDevTool()])

    @agent
    def stock_picker(self) -> Agent:
        return Agent(config=self.agents_config['stock_picker'], 
                     tools=[PushNotificationTool()], memory=True)
    
    @task
    def find_trending_companies(self) -> Task:
        return Task(
            config=self.tasks_config['find_trending_companies'],
            output_pydantic=TrendingCompanyList,
        )

    @task
    def research_trending_companies(self) -> Task:
        return Task(
            config=self.tasks_config['research_trending_companies'],
            output_pydantic=TrendingCompanyResearchList,
        )

    @task
    def pick_best_company(self) -> Task:
        return Task(
            config=self.tasks_config['pick_best_company'],
        )
    



    @crew
    def crew(self) -> Crew:
        """Creates the StockPicker crew"""

        manager = Agent(
            config=self.agents_config['manager'],
            allow_delegation=True
        )
            
        return Crew(
            agents=self.agents,
            tasks=self.tasks, 
            process=Process.hierarchical,
            verbose=True,
            manager_agent=manager,
            memory=True,
            # Long-term memory for persistent storage across sessions
            long_term_memory = LongTermMemory(
                storage=LTMSQLiteStorage(
                    db_path="./memory/long_term_memory_storage.db"
                )
            ),
            # Short-term memory for current context using RAG
            short_term_memory = ShortTermMemory(
                storage = RAGStorage(
                        embedder_config={
                            "provider": "openai",
                            "config": {
                                "model": 'text-embedding-3-small'
                            }
                        },
                        type="short_term",
                        path="./memory/"
                    )
                ),            # Entity memory for tracking key information about entities
            entity_memory = EntityMemory(
                storage=RAGStorage(
                    embedder_config={
                        "provider": "openai",
                        "config": {
                            "model": 'text-embedding-3-small'
                        }
                    },
                    type="short_term",
                    path="./memory/"
                )
            ),
        )

What you should see. On the next crewai run of stock_picker, a memory/ folder appears containing a Chroma vector store and a SQLite .db file. You do not call anything extra — setting memory=True and passing the three stores is enough. The run may wander a little more as the manager consults memory, and the pick changes from run to run (the instructor saw Microsoft one time).
Common mistakes with memory.
  • Turning memory on but never mentioning it in prompts. Memory only helps if your goals and tasks ask for it ("pick new companies", "don't recommend the same one twice"). Otherwise the stored context is there but unused.
  • Expecting visibility. You cannot easily see what memory fed into each prompt. That reduced transparency is the price of the convenience.
  • Embeddings need a key. The RAG stores call OpenAI's embedding model, so they need an OpenAI key in .env.

Part two: the coder crew

Now something new and striking: an agent that not only writes Python but executes it to check the answer. This is often called a "coder agent". In CrewAI it takes just a couple of options on the agent.

New to this? Code execution and the Docker sandbox

Setting allow_code_execution=True lets an agent run the code it writes. With code_execution_mode="safe", CrewAI runs that code inside a Docker container — a sealed, throwaway environment isolated from your real computer, so a mistake (or malicious code) cannot damage your files. You need Docker Desktop installed for safe mode to work. Running code lets the agent check its own output and fix itself, rather than just guessing what the code would produce.

The agent

One agent, described in YAML. Its goal spells out a plan-then-write-then-run workflow.

coder:
  role: >
    Python Developer
  goal: >
    You write python code to achieve this assignment: {assignment}
    First you plan how the code will work, then you write the code, then you run it and check the output.
  backstory: >
    You're a seasoned python developer with a knack for writing clean, efficient code.
  llm: gpt-4o-mini

The crew module

The new options are all on the agent. The crew itself is a plain sequential crew — in fact the default scaffolding would have done, but here it is written out.

from crewai import Agent, Crew, Process, Task
from crewai.project import CrewBase, agent, crew, task



@CrewBase
class Coder():
    """Coder crew"""

    agents_config = 'config/agents.yaml'
    tasks_config = 'config/tasks.yaml'

    # One click install for Docker Desktop:
    #https://docs.docker.com/desktop/

    @agent
    def coder(self) -> Agent:
        return Agent(
            config=self.agents_config['coder'],
            verbose=True,
            allow_code_execution=True,
            code_execution_mode="safe",  # Uses Docker for safety
            max_execution_time=30, 
            max_retry_limit=3 
    )


    @task
    def coding_task(self) -> Task:
        return Task(
            config=self.tasks_config['coding_task'],
        )


    @crew
    def crew(self) -> Crew:
        """Creates the Coder crew"""


        return Crew(
            agents=self.agents, 
            tasks=self.tasks,
            process=Process.sequential,
            verbose=True,
        )

The runner

The assignment is chosen so the model cannot fake the answer: compute an approximation of pi the slow way, by summing 10,000 terms of a series and multiplying by 4.

#!/usr/bin/env python
import sys
import warnings
import os
from datetime import datetime

from coder.crew import Coder

warnings.filterwarnings("ignore", category=SyntaxWarning, module="pysbd")

# Create output directory if it doesn't exist
os.makedirs('output', exist_ok=True)

assignment = 'Write a python program to calculate the first 10,000 terms \
    of this series, multiplying the total by 4: 1 - 1/3 + 1/5 - 1/7 + ...'

def run():
    """
    Run the crew.
    """
    inputs = {
        'assignment': assignment,
    }
    
    result = Coder().crew().kickoff(inputs=inputs)
    print(result.raw)

The agent writes a loop, runs it in Docker, and prints a result near 3.14149 — close to pi but wrong after a few decimals, exactly as a 10,000-term approximation should be. That slight inaccuracy is the proof it really ran the code rather than recalling that the series equals pi. An output/code_and_output.txt file holds the code and its output.
Common mistakes.
  • Docker not installed or not running. Safe mode needs Docker Desktop running. Without it, code execution in safe mode fails.
  • Too-easy assignment. Ask for "print hello world" and you cannot tell whether the agent ran the code or just knew the answer. A task with a non-obvious numeric result proves execution happened.
  • Timeouts. A heavy task can exceed max_execution_time. Raise it if needed.
In TypeScript. CrewAI's memory and code-execution features have no TypeScript port. In Node you would build memory yourself (store text, embed it, retrieve by similarity, paste it into the prompt) and run generated code in your own sandbox or container. The point of CrewAI is that memory=True plus a few storage objects, and allow_code_execution=True with code_execution_mode="safe", replace all of that with a handful of lines — in Python only.
Recap
  • Memory gives agents relevant past context. CrewAI offers short-term and entity memory (vector/RAG stores, via Chroma) and long-term memory (a SQLite file that survives between runs).
  • Turn it on with memory=True on the agents that need it and on the crew, and pass the storage objects. Underneath, memory just means more relevant text added to the prompt.
  • The coder crew writes and runs code. allow_code_execution=True plus code_execution_mode="safe" runs the code in a Docker sandbox; max_execution_time and max_retry_limit bound each attempt.
  • Asking for the code and its output, with a task whose answer cannot be guessed, proves the agent truly executed the code.
