13. Day 4 - Crew AI Memory Vector Storage & SQL Implementation for AI Agents.mp4 · 12:14

Memory is about giving an LLM relevant information from the past each time you call it. You could do this by hand — store things in variables and paste them into prompts — but CrewAI offers ready-made memory building blocks. The benefit is you get up and running fast; the trade-off is that a lot happens behind the scenes, so it is harder to see exactly what the model receives.

New to this? What "memory" really means for an LLM

An LLM has no memory of its own between calls — each call is fresh. "Memory" is just a system that stores useful text and slips the relevant bits back into the prompt next time. So when the instructor says memory can feel magical, the plain truth underneath is: memory means more relevant context shoved into the prompt. CrewAI decides what to store and what to retrieve for you.

Ed's slides list five memory types: short-term (recent interactions, in a vector store), long-term (important facts in SQLite), entity (people, places, concepts, in a vector store), contextual (an umbrella for those three) and user memory (mostly left to you). Then he adds the first three to the stock picker's crew.py.

New to this? Vector stores, RAG storage and embeddings

A vector store keeps text as lists of numbers (embeddings) that capture meaning, so you can find the most relevant past notes by similarity, not exact words. This is the retrieval half of "retrieval-augmented generation" (RAG). CrewAI's RAGStorage uses an embedding model to turn stored text into vectors and a local Chroma database to hold them. You do not need to understand the internals to use it — you create the objects and CrewAI does the rest.

@CrewBase
class StockPicker():
    """StockPicker crew"""

    agents_config = 'config/agents.yaml'
    tasks_config = 'config/tasks.yaml'

    @agent
    def trending_company_finder(self) -> Agent:
        return Agent(config=self.agents_config['trending_company_finder'], tools=[SerperDevTool()], memory=True)

    @agent
    def financial_researcher(self) -> Agent:
        return Agent(config=self.agents_config['financial_researcher'], tools=[SerperDevTool()])

    @agent
    def stock_picker(self) -> Agent:
        return Agent(config=self.agents_config['stock_picker'], tools=[PushNotificationTool()], memory=True)

    @task
    def find_trending_companies(self) -> Task:
        return Task(
            config=self.tasks_config['find_trending_companies'],
            output_pydantic=TrendingCompanyList,
        )

    @task
    def research_trending_companies(self) -> Task:
        return Task(
            config=self.tasks_config['research_trending_companies'],
            output_pydantic=TrendingCompanyResearchList,
        )

    @task
    def pick_best_company(self) -> Task:
        return Task(
            config=self.tasks_config['pick_best_company'],
        )

    @crew
    def crew(self) -> Crew:
        """Creates the StockPicker crew"""

        manager = Agent(
            config=self.agents_config['manager'],
            allow_delegation=True
        )

        short_term_memory = ShortTermMemory(
                storage = RAGStorage(
                        embedder_config={
                            "provider": "openai",
                            "config": {
                                "model": 'text-embedding-3-small'
                            }
                        },
                        type="short_term",
                        path="./memory/"
                    )
                )
        long_term_memory = LongTermMemory(
                storage=LTMSQLiteStorage(
                    db_path="./memory/long_term_memory_storage.db"
                )
            )
        entity_memory = EntityMemory(
                storage=RAGStorage(
                    embedder_config={
                        "provider": "openai",
                        "config": {
                            "model": 'text-embedding-3-small'
                        }
                    },
                    type="short_term",
                    path="./memory/"
                )
            )



        return Crew(
            agents=self.agents,
            tasks=self.tasks,
            process=Process.hierarchical,
            verbose=True,
            manager_agent=manager,
            memory=True,
            long_term_memory=long_term_memory,
            short_term_memory=short_term_memory,
            entity_memory=entity_memory
        )

Common mistakes with memory.
  • Turning memory on but never mentioning it in prompts. Memory only helps if your goals and tasks ask for it ("pick new companies", "don't recommend the same one twice"). Otherwise the stored context is there but unused.
  • Expecting visibility. You cannot easily see what memory fed into each prompt. That reduced transparency is the price of the convenience.
  • Embeddings need a key. The RAG stores call OpenAI's embedding model, so they need an OpenAI key in .env.

from crewai.tools import BaseTool
from typing import Type
from pydantic import BaseModel, Field
import os
import requests


class PushNotificationInput(BaseModel):
    """A message to be sent to the user"""
    message: str = Field(..., description="The message to be sent to the user")

class PushNotificationTool(BaseTool):
    name: str = "Send a push notification"
    description: str = (
        "This tool is used to send a push notification to the user."
    )
    args_schema: Type[BaseModel] = PushNotificationInput

    def _run(self, message: str) -> str:
        pushover_user = os.getenv("PUSHOVER_USER")
        pushover_token = os.getenv("PUSHOVER_TOKEN")
        pushover_url = "https://api.pushover.net/1/messages.json"

        print(f"Push: {message}")
        payload = {"user": pushover_user, "token": pushover_token, "message": message}
        requests.post(pushover_url, data=payload)
        return '{"notification": "ok"}'

Video 14 · The coder: an agent that writes and runs Python

14. Day 4 - Crew AI for Coding Tasks Agents That Generate & Run Python Code.mp4 · 8:06

Now something new and striking: an agent that not only writes Python but executes it to check the answer. This is often called a "coder agent". In CrewAI it takes just a couple of options on the agent.

Ed's slide: "It's hard and it's complex, but you can have an Agent in Crew that has the ability to write code, execute it in a Docker container, and investigate the results. Except it's not." Agents like this are often called coder agents: running code is a means to an end, a step towards solving a bigger problem.

New to this? Code execution and the Docker sandbox

Setting allow_code_execution=True lets an agent run the code it writes. With code_execution_mode="safe", CrewAI runs that code inside a Docker container — a sealed, throwaway environment isolated from your real computer, so a mistake (or malicious code) cannot damage your files. You need Docker Desktop installed for safe mode to work. Running code lets the agent check its own output and fix itself, rather than just guessing what the code would produce.

# CrewAI's built-in code execution (allow_code_execution) is gone, so the agent gets
# four small tools instead: list, read and write files in a sandbox folder, and run a
# Python file there inside a throwaway Docker container.
from crewai.tools import tool
from pathlib import Path
import subprocess


SANDBOX_DIR = Path(__file__).parents[3] / "sandbox"
SANDBOX_DIR.mkdir(parents=True, exist_ok=True)

@tool("List Sandbox Files")
def list_sandbox_files() -> str:
    """
    List the filenames currently in the sandbox directory.

    Returns:
        A newline-separated list of filenames, or a message if the
        sandbox is empty.
    """
    names = sorted(p.name for p in SANDBOX_DIR.iterdir())
    return "\n".join(names) if names else "The sandbox is empty."


@tool("Read Sandbox File")
def read_sandbox_file(filename: str) -> str:
    """
    Read and return the text contents of a file in the sandbox directory.

    Args:
        filename: The name of the file to read (e.g. "solution.py").
    Returns:
        The file's contents, or a message if the file does not exist.
    """
    path = SANDBOX_DIR / filename
    if not path.is_file():
        return f"No such file in the sandbox: {filename}"
    return path.read_text()


@tool("Write Sandbox File")
def write_sandbox_file(filename: str, content: str) -> str:
    """
    Write text to a file in the sandbox directory, replacing any existing
    file with the same name.

    Args:
        filename: The name of the file to write (e.g. "solution.py").
        content: The text content to write.
    Returns:
        A confirmation message.
    """
    path = SANDBOX_DIR / filename
    path.write_text(content)
    return f"Wrote {len(content)} characters to {filename}."


@tool("Run Sandbox Python File")
def run_sandbox_python(filename: str) -> str:
    """
    Execute a Python file from the sandbox directory inside an ephemeral
    Docker container, with the sandbox mounted as the working directory,
    and return whatever the script printed to stdout.

    Args:
        filename: The name of the Python file to run (e.g. "solution.py").
    Returns:
        The text printed to stdout by the executed script.
    """
    result = subprocess.run(
        [
            "docker", "run", "--rm",
            "-v", f"{SANDBOX_DIR}:/workspace",
            "-w", "/workspace",
            "python:3.13-slim",
            "python", filename,
        ],
        capture_output=True,
        text=True,
        timeout=60,
    )
    return result.stdout

sandbox_tools = [list_sandbox_files, read_sandbox_file, write_sandbox_file, run_sandbox_python]

# Calculate the first 10,000 terms of the series: 1 - 1/3 + 1/5 - 1/7 + ...
def calculate_series(n_terms):
    total = 0
    for i in range(n_terms):
        term = (-1) ** i / (2 * i + 1)  # Calculate each term
        total += term                   # Add the term to the total
    return total * 4                   # Multiply the total by 4

# Define the number of terms

Common mistakes.
  • Docker not installed or not running. Safe mode needs Docker Desktop running. Without it, code execution in safe mode fails.
  • Too-easy assignment. Ask for "print hello world" and you cannot tell whether the agent ran the code or just knew the answer. A task with a non-obvious numeric result proves execution happened.
  • Timeouts. A heavy task can exceed max_execution_time. Raise it if needed.
  • allow_code_execution on current CrewAI. It is deprecated and does nothing useful any more (CrewAI only prints a warning), so the agent cannot run code. Use the sandbox tools from the "Runs today" tab.

Recap
  • Memory gives agents relevant past context. CrewAI offers short-term and entity memory (vector/RAG stores, via Chroma) and long-term memory (a SQLite file that survives between runs).
  • Turn it on with memory=True on the agents that need it and on the crew, and pass the storage objects. Current CrewAI replaces the three stores with one unified memory: memory=True plus an embedder. Underneath, memory just means more relevant text added to the prompt.
  • The coder crew writes and runs code. allow_code_execution=True plus code_execution_mode="safe" runs the code in a Docker sandbox; max_execution_time and max_retry_limit bound each attempt. Current CrewAI has removed that built-in execution; give the agent Docker sandbox tools instead.
  • Asking for the code and its output, with a task whose answer cannot be guessed, proves the agent truly executed the code.
