Week 2 · Day 1 — The OpenAI Agents SDK

Your first framework: Agent, Runner and traces. Set up async Python, create an agent, run it, and read the trace of what happened - in Python and TypeScript with @openai/agents.

Welcome to week two. The whole week is about the OpenAI Agents SDK, a small, flexible framework for building agents. Day one has two jobs. First it teaches a piece of plain Python you will meet in every agent framework from here on: asynchronous Python (the async and await keywords, and the asyncio library). Then it introduces the three pieces of the SDK you need to run your very first agent, and we run one: a tiny joke-teller.

In week one we talked to models by hand. We built the list of messages ourselves, called chat.completions.create(...), and when we wanted the model to use a tool we wrote a pile of JSON by hand to describe it. The Agents SDK takes that boilerplate away while leaving you in full control. The instructor runs the lab cell by cell in Cursor and explains each piece rather than typing it live, and that is how we will read it here.

This is a lab, not a project yet. The code lives in a notebook (1_lab1.ipynb; 1_lab1.py is the same cells exported as a script). The goal is to feel the three core pieces of the SDK, not to build an app. The real project starts tomorrow on day two.

Why a framework at all?

An agent framework is just a thin layer of code on top of the same model calls you already know. It does not add intelligence; the thinking still happens on the provider's servers. What it adds is structure and plumbing: a tidy way to name an agent and give it a system prompt, automatic handling of tool calls (no more hand-written JSON), and a built-in log of everything that happened, called a trace. The instructor calls this SDK not opinionated: it gives you building blocks and gets out of your way, rather than forcing one way of working.

New to this? What "a framework" means here

A framework is reusable code that organises your own code. It does not do the clever part for you. In this week's SDK the clever part is still the language model, running on OpenAI's (or another provider's) servers. The framework gives you names and helpers — an Agent object, a Runner to run it, a trace to log it — so you write less glue and make fewer mistakes. You could do all of it by hand; the framework just saves you the repetitive parts.

A half-hour on async Python

Before any SDK code, the instructor stops for an important sidebar: asynchronous Python. Every agent framework in this course uses it, so it is worth understanding rather than just copying. The short version is two rules. The long version explains why those rules exist.

New to this? The short version (the two rules)

asyncio is a lightweight way to let code run concurrently. In practice you follow two rules. Rule one: if a function might need to wait (for a network reply, say), define it with async def instead of def. Rule two: when you call such a function, put await in front of it. So result = do_work() becomes result = await do_work(). Follow those two rules and most async code just works.

New to this? The longer story: coroutines and the event loop

When you write async def do_work(): the thing you defined is no longer called a function; it is a coroutine. Calling a coroutine does not run it — it just hands you back a "coroutine object" that is ready to run. To actually run it you await it. Behind the scenes a piece of asyncio called the event loop runs one coroutine at a time. When a coroutine pauses to wait on the network (waiting for a model to reply, for example), the event loop quietly starts another waiting coroutine instead of sitting idle. Because the work is nearly all waiting, this lets thousands of calls overlap cheaply. It is not true multithreading; it is one worker that never wastes time waiting.

One more construct matters this week: asyncio.gather(...). You hand it several coroutines, and the event loop runs them so they overlap — while one waits on the network another makes progress. You get back a list of their results, in order. We use this on day two to ask three agents at once. Today we just need to know await, because Runner.run(...) is a coroutine.

The three building blocks

The SDK comes with only a little vocabulary. The instructor highlights three terms: agents (a wrapper around one model call with a particular role), handoffs (how agents pass work to each other, covered on day two), and guardrails (safety checks, covered on day three). To run an agent today you take three small steps.

New to this? What an Agent really is

An Agent is a small object that bundles three things: a name (just a label, used in traces), instructions (this is the agent's system prompt — the standing brief that shapes how it behaves), and a model (which LLM to use, here gpt-4o-mini). Creating the agent does not call the model. It just describes one. You run it later with the Runner.

New to this? Does the SDK only use OpenAI models?

No. If you pass a bare model name like "gpt-4o-mini", the SDK assumes you mean OpenAI, which is why it looks OpenAI-only at first. But it is not tied to OpenAI — on day three we point the same SDK at Gemini, DeepSeek and others through their OpenAI-compatible endpoints. The name "Agents SDK" is about the pattern, not the provider.

Set up and run

You only need an OpenAI API key in your .env for this first lab. If you followed the course setup with uv, the openai-agents package is already installed.

  1. Open the 2_openai folder and then 1_lab1.ipynb (the notebook; 1_lab1.py is the same cells exported as a script).
  2. Make sure your .env file has OPENAI_API_KEY=.... The first line of code reads it with load_dotenv(override=True).
  3. Run the cells from top to bottom. Run the import cell first, or the later cells fail with name errors.
  4. When the agent runs, read the joke it prints. Then open https://platform.openai.com/traces and find the trace named "Telling a joke".
Why await appears at the top level here. In a normal .py script you cannot write await outside an async def — you would wrap the code in a coroutine and start it with asyncio.run(...). A Jupyter notebook already runs inside an event loop, so it lets you await directly in a cell. That is why the notebook can say await Runner.run(...) with no asyncio.run. The TypeScript port below shows the script-style wrapping instead.

The full lab

Here is the complete file in both languages. Python is the version shown in the course video. The TypeScript port does the same job with the official @openai/agents package for Node. Use the Code in: switch to pick a language; the line-by-line walkthrough below follows your choice.

# The imports

from dotenv import load_dotenv
from agents import Agent, Runner, trace



# The usual starting point

load_dotenv(override=True)



# Make an agent with name, instructions, model

agent = Agent(name="Jokester", instructions="You are a joke teller", model="gpt-4o-mini")

# Run the joke with Runner.run(agent, prompt) then print final_output

with trace("Telling a joke"):
    result = await Runner.run(agent, "Tell a joke about Autonomous AI Agents")
    print(result.final_output)
// Week 2 Day 1 - a first Agent and run() (TypeScript port of 2_openai/1_lab1.py)
// Python: Agent(name, instructions, model) -> Runner.run(agent, prompt) -> result.final_output
// TypeScript: new Agent({ name, instructions, model }) -> run(agent, prompt) -> result.finalOutput
import { Agent, run, withTrace } from "@openai/agents";
import { MODEL } from "./setup.js";

// Make an agent with a name, instructions and a model.
const agent = new Agent({
  name: "Jokester",
  instructions: "You are a joke teller",
  model: MODEL,
});

// Run the joke with run(agent, prompt), inside a single trace, then print finalOutput.
await withTrace("Telling a joke", async () => {
  const result = await run(agent, "Tell a joke about Autonomous AI Agents");
  console.log(result.finalOutput);
});

What a trace looks like

New to this? What a "trace" is and why you want one

A trace is a recorded timeline of everything an agent run did: which agent was called, what its instructions were, what the user prompt was, and what the model replied. The SDK sends this to OpenAI's traces dashboard automatically when you wrap a run in a trace. For one joke it is barely interesting. But once a run involves several agents and tools, being able to open one named trace and see the whole sequence is how you understand and debug what happened.

What you should see. The cell prints a short joke about autonomous AI agents (the instructor's run produced one about agents "following their own self-driving instructions"). Then, at https://platform.openai.com/traces, a trace named "Telling a joke" appears at the top. Open it and you will find one LLM call showing the system instructions, the user prompt, and the assistant's reply. Your joke will differ every run — models are non-deterministic.
Common mistakes.
  • Missing await. result = Runner.run(...) without await gives you a coroutine object, not a joke. Add await.
  • No API key. If OPENAI_API_KEY is missing from .env, the run fails with an authentication error. Check the key loaded.
  • Running a plain script. Top-level await works in a notebook but not in a normal .py file; there you must wrap the code in an async def main() and call asyncio.run(main()).
  • Imports not run. Run the import cell first or later cells fail with name errors.
  • Expecting great jokes. As the instructor says, the SDK is better at running agents than the model is at comedy. The point is the mechanism, not the punchline.
Recap
  • The Agents SDK is a thin, un-opinionated layer over normal model calls; it removes boilerplate but adds no intelligence of its own.
  • Async Python: define waiting functions with async def (they become coroutines) and call them with await. The event loop runs one at a time but reuses waiting time, which is why agents use it.
  • Three steps to run an agent: create an Agent(name, instructions, model), optionally wrap it in with trace("..."), then await Runner.run(agent, prompt).
  • instructions is the agent's system prompt; result.final_output is the answer text.
  • A bare model name means OpenAI, but the SDK works with other providers too (day three).
  • Traces record the whole run in OpenAI's dashboard — trivial for one joke, essential once many agents are involved.
