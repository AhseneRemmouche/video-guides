Week 5 · Day 1 — AutoGen AgentChat

Microsoft's AutoGen and how it compares to other frameworks. In AgentChat: model clients, messages and agents, and giving an agent tools.

Companion to Ed Donner's course · uv setup · Python (+ TypeScript/React where it fits) · code from the course repo

Welcome to Week 5. This week the course meets its last framework before the big finale: AutoGen, an open-source agent framework from Microsoft. The good news, as the instructor promises, is that it will feel quick and familiar. So much of AutoGen looks like the frameworks you already know that you will be writing working agents within minutes. Day 1 is the gentle on-ramp: we meet AutoGen's building blocks and build a small airline assistant that can look up ticket prices in a database.

Because AutoGen is a Python framework (there is a separate .NET version, but no first-class JavaScript port), every day this week shows a single Python code block rather than a Python-and-TypeScript pair. There is a short honest note about TypeScript at the foot of each page, and the React side of the week is only a small demo screen on the build page.

This is a lab, not a finished app. The code lives in a notebook (1_lab1_autogen_agentchat.py is the exported version). The goal is to feel how AutoGen packages up a model, a message and an agent, not to ship a product. The week's project comes on Day 5.

A little drama: which AutoGen?

Before any code, the instructor clears up a genuine source of confusion. Microsoft rewrote AutoGen from the ground up for version 0.4 (released January 2025) with an asynchronous, event-driven design; the course uses the current 0.5.1. But late in 2024 some of the original creators left Microsoft and forked the older 0.2 line into a separate project called AG2. Awkwardly, the plain autogen package name on PyPI now belongs to that fork, so a bare pip install autogen gives you AG2, not Microsoft's official framework.

You do not have to worry about any of this, because the course installs everything with uv. The project files already pin Microsoft's official packages (autogen-agentchat, autogen-core, autogen-ext), so uv sync gives you the right ones. Just be careful when reading documentation online: check whether it is for the 0.4-plus Microsoft line (what we use) or the older 0.2 / AG2 line, because they look and feel quite different.

What AutoGen actually is

Like the other frameworks, AutoGen is really several things under one name. Two parts matter for this course:

  • AutoGen Core — the bottom layer. It is a generic framework for building scalable multi-agent systems: it creates agents and carries messages between them, even when they live in different processes. Think of it as a runtime, a fabric agents run inside. It does not care how each agent is implemented. We meet it on Days 3 and 4.
  • AutoGen AgentChat — built on top of Core. This is the lightweight, friendly layer, very close to CrewAI and the OpenAI Agents SDK: you make an agent, give it a model and some tools, and let it answer. Days 1 and 2 live here.

Built on top of AgentChat are two more offerings the course does not use: Studio, a low-code / no-code visual builder, and Magentic-One, a ready-made command-line console. Both are research tools, not production products. We stay with code, so we focus on Core and AgentChat.

The building blocks

AgentChat has a handful of core ideas, all of which you have met before under other names: models, messages, agents and teams. Today covers the first three; teams come on Day 2.

New to this? The model client

A model client is AutoGen's wrapper around a large language model. It is the equivalent of the "LLM" object in other frameworks: a thin piece of code that knows how to send your request to a particular model and read the reply back. You create one with a model name and then hand it to an agent. The agent does the thinking through this client.

New to this? Messages and sources

In AgentChat a message is an object, not just a string. A TextMessage holds the text in content and records who sent it in source (for example "user"). AutoGen treats "message" quite broadly: as well as a human talking to a model, a message can be something passing between agents, or an event inside an agent such as a tool being called. Keeping messages as objects lets the framework pass that extra information around.

New to this? The AssistantAgent

The AssistantAgent is the class you will use most in AgentChat. You give it a name, a model client, a system_message (its standing instructions, like the "instructions" in the OpenAI Agents SDK) and, optionally, a list of tools. To make it respond you call on_messages(...) with a list of messages. It is a lightweight abstraction: there is very little ceremony between you and the model.

Set up and run

  1. Open the 5_autogen folder, then the first notebook, 1_lab1_autogen_agentchat.ipynb (the .py file is the same cells exported as a script).
  2. Make sure your .env file holds an OPENAI_API_KEY. That is the only key this lab needs.
  3. For the optional local model, install Ollama and run ollama pull llama3.2 once. The lab shows that you can swap the OpenAI client for an Ollama one and keep everything else the same.
  4. Run the cells from top to bottom. The database cells build a fresh tickets.db each time you run them.
Good news for free runs. Line 7–8 of the lab build an OllamaChatCompletionClient(model="llama3.2") right beside the OpenAI one. Anywhere the lab uses model_client you could use ollamamodel_client instead and run the whole thing on your own machine for free. This is exactly how we verified the AgentChat examples for this guide.

The full lab

from dotenv import load_dotenv
load_dotenv(override=True)

from autogen_ext.models.openai import OpenAIChatCompletionClient
model_client = OpenAIChatCompletionClient(model="gpt-4o-mini")

from autogen_ext.models.ollama import OllamaChatCompletionClient
ollamamodel_client = OllamaChatCompletionClient(model="llama3.2")

from autogen_agentchat.messages import TextMessage
message = TextMessage(content="I'd like to go to London", source="user")
message

from autogen_agentchat.agents import AssistantAgent

agent = AssistantAgent(
    name="airline_agent",
    model_client=model_client,
    system_message="You are a helpful assistant for an airline. You give short, humorous answers.",
    model_client_stream=True
)

from autogen_core import CancellationToken

response = await agent.on_messages([message], cancellation_token=CancellationToken())
response.chat_message.content

import os
import sqlite3

# Delete existing database file if it exists
if os.path.exists("tickets.db"):
    os.remove("tickets.db")

# Create the database and the table
conn = sqlite3.connect("tickets.db")
c = conn.cursor()
c.execute("CREATE TABLE cities (city_name TEXT PRIMARY KEY, round_trip_price REAL)")
conn.commit()
conn.close()

# Populate our database
def save_city_price(city_name, round_trip_price):
    conn = sqlite3.connect("tickets.db")
    c = conn.cursor()
    c.execute("REPLACE INTO cities (city_name, round_trip_price) VALUES (?, ?)", (city_name.lower(), round_trip_price))
    conn.commit()
    conn.close()

# Some cities!
save_city_price("London", 299)
save_city_price("Paris", 399)
save_city_price("Rome", 499)
save_city_price("Madrid", 550)
save_city_price("Barcelona", 580)
save_city_price("Berlin", 525)

# Method to get price for a city
def get_city_price(city_name: str) -> float | None:
    """ Get the roundtrip ticket price to travel to the city """
    conn = sqlite3.connect("tickets.db")
    c = conn.cursor()
    c.execute("SELECT round_trip_price FROM cities WHERE city_name = ?", (city_name.lower(),))
    result = c.fetchone()
    conn.close()
    return result[0] if result else None

get_city_price("Rome")

from autogen_agentchat.agents import AssistantAgent

smart_agent = AssistantAgent(
    name="smart_airline_agent",
    model_client=model_client,
    system_message="You are a helpful assistant for an airline. You give short, humorous answers, including the price of a roundtrip ticket.",
    model_client_stream=True,
    tools=[get_city_price],
    reflect_on_tool_use=True
)

response = await smart_agent.on_messages([message], cancellation_token=CancellationToken())
for inner_message in response.inner_messages:
    print(inner_message.content)
response.chat_message.content

Your exact wording changes every run — the model is not deterministic.
Common mistakes.
  • Forgetting await. on_messages is asynchronous. Without await you get a coroutine object, not an answer.
  • Skipping the import cell. Run the cells top to bottom, or later cells fail with name errors.
  • No docstring or type hints on the tool. AutoGen builds the tool's description from them. Leave them off and the model gets a vaguer, worse tool.
  • Re-running the database cells out of order. The create cell deletes tickets.db; run the populate cell afterwards or the table will be empty.
  • Expecting a bare pip install autogen to work. That installs AG2, not this framework. Let uv sync install the pinned Microsoft packages.

In TypeScript

There is no honest line-by-line TypeScript twin this week, and it would be wrong to pretend otherwise. AutoGen is a Python framework (Microsoft also ships a .NET version), with no first-class JavaScript port. The TypeScript side of Week 5 is only a small React demo screen that imitates an AgentChat-style exchange in the browser; it is not AutoGen running in Node. You will see it as a screenshot on the build page. If you want this airline agent in production, write it in Python.

Recap
  • AutoGen is Microsoft's open-source agent framework; we use the official 0.4-plus line (0.5.1), installed by uv, not the AG2 fork that owns the bare autogen name on PyPI.
  • Its two layers that matter here are Core (the runtime that carries messages) and AgentChat (the friendly layer, like Crew and the OpenAI Agents SDK).
  • AgentChat's building blocks are the model client, the message (a TextMessage with content and source) and the agent (an AssistantAgent).
  • You run an agent with await agent.on_messages([...], cancellation_token=CancellationToken()) and read the reply at response.chat_message.content.
  • Tools are plain Python functions passed to tools=[...]; AutoGen reads their type hints and docstrings, so no decorator or wrapper is needed. reflect_on_tool_use=True lets the agent turn a raw result into a proper answer.
  • Swapping OpenAIChatCompletionClient for OllamaChatCompletionClient runs the same lab locally and for free.
Honesty note. The cloud calls are shown exactly as in the course and need an OPENAI_API_KEY to run; they were not re-run live for this guide. The AgentChat examples were verified locally against Ollama using OllamaChatCompletionClient(model="llama3.2"), which the course code already includes.
