Week 5 · Day 2 — Multimodal, Structured Output and an Evaluator

Richer AgentChat: images and multimodal messages, structured outputs, a primary/evaluator pair, and reaching an MCP fetch server for headless web scraping.

Companion to Ed Donner's course · uv setup · Python (+ TypeScript/React where it fits) · code from the course repo

Day 2 stays inside AgentChat but goes a step deeper. In one lab the instructor rattles through five things: sending an image to a model (multimodal), getting a typed object back (structured output), borrowing tools from LangChain, running a two-agent team where one agent critiques the other, and a teaser of MCP (the subject of Week 6). It is fast and mostly familiar, so we slow each piece down here.

One lab, five mini-demos. This is still a notebook, 5_autogen/2_lab2_autogen_agentchat.ipynb. Each section is independent, so you can run them one at a time. Several need an OPENAI_API_KEY; the search and MCP sections also reach the internet.

1. Multimodal: sending a picture

So far our messages have been text. A MultiModalMessage lets a message carry images too. The lab downloads a picture from the instructor's website, opens it with the Python Imaging Library (PIL), wraps it in AutoGen's own Image type, and puts it in a message alongside a text instruction. Sending that to gpt-4o-mini is no different from sending plain text — the same agent, the same on_messages call.

New to this? What "multimodal" means

A mode is a kind of input: text, images, audio. A multimodal model can take more than one at once. Here we hand the model a picture and the words "Describe the content of this image in detail", and it answers about the picture. Behind the scenes the image is encoded and sent along with the text in a single request. Not every model can see images; gpt-4o-mini can.

2. Structured output: a typed object back

Often you do not want prose, you want fields you can store or display. The lab defines a Pydantic class ImageDescription with four fields (scene, message, style, orientation) and passes it to the agent as output_content_type. Now the reply is not a string — it is a populated ImageDescription object. Under the hood AutoGen turns the class into a JSON schema, the model returns JSON, and AutoGen fills the object from it. This is the same structured output idea you have met before, made very easy.

3. Borrowing LangChain tools

AutoGen can reuse the huge ecosystem of LangChain tools through a small wrapper called LangChainToolAdapter. The lab takes the Google Serper web-search tool and the file-management toolkit you saw in Week 4, wraps each one, and hands them to an agent. Now the agent can search the web and write files — the same prompt asks it to find a flight, save the options to flights.md, and pick the best.

New to this? What the adapter does

LangChain and AutoGen each have their own idea of what a "tool" object looks like. The adapter is a thin translator: you give it a LangChain tool, it hands back something AutoGen recognises. Nothing about the tool's behaviour changes — it is still the same web search — only its outer shape. This is why one line, LangChainToolAdapter(langchain_serper), is enough to unlock LangChain's whole tool library inside AutoGen.

4. A team: primary and evaluator

The fourth demo introduces teams, the building block Day 1 left out. A RoundRobinGroupChat takes a list of agents and lets them speak in turn. Here a primary agent searches for a flight and an evaluator agent critiques it. They go back and forth until the evaluator replies with the word APPROVE, which a TextMentionTermination condition watches for. The video has no other limit (Ed had to interrupt a runaway first run); the repository later added a max_turns=20 cap, and the Runs today tab has it.

New to this? The primary / evaluator pattern

This is the evaluator-optimiser pattern from earlier in the course: one agent produces, another judges and sends feedback, and the producer tries again. It can genuinely raise quality, but it has a danger — if the judge is never satisfied, the two can talk forever. AutoGen does not impose a recursion limit the way LangGraph does, so you add your own stopping rule. Here it is a keyword (APPROVE), and a turn cap is a sensible extra. The instructor notes that matching a hard-coded word is brittle; a real system would use structured output to decide when it is done.

5. A teaser of MCP

The last demo is a preview of Week 6. MCP (Model Context Protocol, from Anthropic) is an open standard for packaging tools so any model can use them — the instructor calls it "the USB-C connector for AI". AutoGen has a wrapper for MCP tools just as it does for LangChain tools. The lab starts a public tool called mcp-server-fetch, which runs a headless browser locally, hands its tools to an agent, and asks the agent to read and summarise a website. Do not worry about the detail yet; Week 6 explains it fully.

5. Day 2 - Advanced Autogen Agent Chat Multimodal Features & Structured Outputs.mp4 · 9:27

After a quick plan for the day (multimodal, structured outputs, LangChain tools, teams, and a "special guest"), Ed opens 5_autogen/2_lab2_autogen_agentchat.ipynb. He sends a picture plus a question in one message, then asks for the description as a typed Pydantic object instead of prose.

About the Runs today model. AutoGen recognises the OpenAI models it was released with by name, gpt-4o-mini among them. A newer model such as gpt-6-luna also needs model_info: a small description of what the model can do (see pictures, call tools, return JSON). Without it AutoGen stops with "model_info is required when model name is not a valid OpenAI model". reasoning_effort="none" makes the new model answer straight away, like the older chat models did.

pil_image = Image.open(BytesIO(requests.get(url).content))

img

multi_modal_message = MultiModalMessage(content=["Describe the content of this image in detail", img], source="User")

model_client = OpenAIChatCompletionClient(model="gpt-4o-mini")

describer = AssistantAgent(
    name="description_agent",
    model_client=model_client,
    system_message="You are good at describing images",
)

response = await describer.on_messages([multi_modal_message], cancellation_token=CancellationToken())
reply = response.chat_message.content
display(Markdown(reply))


class ImageDescription(BaseModel):
    scene: str = Field(description="Briefly, the overall scene of the image")
    message: str = Field(description="The point that the image is trying to convey")
    style: str = Field(description="The artistic style of the image")
    orientation: Literal["portrait", "landscape", "square"] = Field(description="The orientation of the image")

model_client = OpenAIChatCompletionClient(model="gpt-4o-mini")

describer = AssistantAgent(
    name="description_agent",
    model_client=model_client,
    system_message="You are good at describing images in detail",
    output_content_type=ImageDescription,
)

response = await describer.on_messages([multi_modal_message], cancellation_token=CancellationToken())

# AutoGen's wrapper:

from autogen_ext.tools.langchain import LangChainToolAdapter

# LangChain tools:

from langchain_community.utilities import GoogleSerperAPIWrapper
from langchain_community.agent_toolkits import FileManagementToolkit
from langchain.agents import Tool


prompt = """Your task is to find a one-way non-stop flight from JFK to LHR in June 2025.
First search online for promising deals.
Next, write all the deals to a file called flights.md with full details.
Finally, select the one you think is best and reply with a short summary.
Reply with the selected flight only, and only after you have written the details to the file."""


serper = GoogleSerperAPIWrapper()
langchain_serper =Tool(name="internet_search", func=serper.run, description="useful for when you need to search the internet")
autogen_serper = LangChainToolAdapter(langchain_serper)
autogen_tools = [autogen_serper]

langchain_file_management_tools = FileManagementToolkit(root_dir="sandbox").get_tools()
for tool in langchain_file_management_tools:
    autogen_tools.append(LangChainToolAdapter(tool))

for tool in autogen_tools:
    print(tool.name, tool.description)

model_client = OpenAIChatCompletionClient(model="gpt-4o-mini")
agent = AssistantAgent(name="searcher", model_client=model_client, tools=autogen_tools, reflect_on_tool_use=True)
message = TextMessage(content=prompt, source="user")
result = await agent.on_messages([message], cancellation_token=CancellationToken())
for message in result.inner_messages:
    print(message.content)
display(Markdown(result.chat_message.content))

# Now we need to call the agent again to write the file

message = TextMessage(content="OK proceed", source="user")

result = await agent.on_messages([message], cancellation_token=CancellationToken())
for message in result.inner_messages:
    print(message.content)
display(Markdown(result.chat_message.content))

Common mistakes.
  • Using a text-only model for the image. Multimodal needs a vision-capable model such as gpt-4o-mini. A small local text model cannot see the picture.
  • Missing a Serper key. The web-search tool needs SERPER_API_KEY in .env, or the search calls fail.
  • The team never stops. If the evaluator keeps finding fault it loops. Add max_turns (the Runs today tab does), and interrupt the kernel if it thrashes — the instructor had to restart a runaway run.
  • The old LangChain import. from langchain.agents import Tool fails with LangChain 1.x; import Tool from langchain_core.tools.
  • MCP on Windows. In May 2025 Ed added a warning to this notebook that MCP servers failed on Windows PCs and suggested running the lab in WSL. If the last cell hangs or errors on Windows, that is the likely cause.
  • Relying on an exact word. TextMentionTermination("APPROVE") is brittle; if the evaluator phrases things differently it may never trigger. A real system would use structured output to decide completion.
  • No sandbox folder. The file tools write into sandbox; create that directory first or the writes fail.

In TypeScript

As on Day 1, there is no TypeScript twin. Multimodal messages, structured output with Pydantic, the LangChain adapter, teams and the MCP wrapper are all Python APIs with no JavaScript equivalent in AutoGen. The Week 5 React demo only mimics a chat exchange in the browser; it does not run any of this. Build these in Python.

Recap
  • A MultiModalMessage carries text and an image together; a vision model (gpt-4o-mini in the video) reads both.
  • Setting output_content_type to a Pydantic class makes the reply a typed object; AutoGen handles the JSON schema behind the scenes.
  • LangChainToolAdapter wraps any LangChain tool into an AutoGen tool, unlocking a large tool ecosystem. An agent that stops halfway can be nudged with a second message such as "OK proceed".
  • A RoundRobinGroupChat is a team; a primary/evaluator pair improves an answer and stops on a termination condition such as TextMentionTermination("APPROVE") plus max_turns.
  • AutoGen also wraps MCP tools (a Week 6 topic): mcp_server_tools launches a server like mcp-server-fetch and returns tools you drop into tools=.
  • Through all five demos the agent API barely changes — the same AssistantAgent and on_messages/run.
