Week 5 · Day 2 — Multimodal, Structured Output and an Evaluator

Richer AgentChat: images and multimodal messages, structured outputs, a primary/evaluator pair, and reaching an MCP fetch server for headless web scraping.

Companion to Ed Donner's course · uv setup · Python (+ TypeScript/React where it fits) · code from the course repo

Day 2 stays inside AgentChat but goes a step deeper. In one lab the instructor rattles through five things: sending an image to a model (multimodal), getting a typed object back (structured output), borrowing tools from LangChain, running a two-agent team where one agent critiques the other, and a teaser of MCP (the subject of Week 6). It is fast and mostly familiar, so we slow each piece down here.

One lab, five mini-demos. This is still a notebook (2_lab2_autogen_agentchat.py is the exported version). Each section is independent, so you can run them one at a time. Several need an OPENAI_API_KEY; the search and MCP sections also reach the internet.

1. Multimodal: sending a picture

So far our messages have been text. A MultiModalMessage lets a message carry images too. The lab downloads a picture from the instructor's website, opens it with the Python Imaging Library (PIL), wraps it in AutoGen's own Image type, and puts it in a message alongside a text instruction. Sending that to gpt-4o-mini is no different from sending plain text — the same agent, the same on_messages call.

New to this? What "multimodal" means

A mode is a kind of input: text, images, audio. A multimodal model can take more than one at once. Here we hand the model a picture and the words "Describe the content of this image in detail", and it answers about the picture. Behind the scenes the image is encoded and sent along with the text in a single request. Not every model can see images; gpt-4o-mini can.

2. Structured output: a typed object back

Often you do not want prose, you want fields you can store or display. The lab defines a Pydantic class ImageDescription with four fields (scene, message, style, orientation) and passes it to the agent as output_content_type. Now the reply is not a string — it is a populated ImageDescription object. Under the hood AutoGen turns the class into a JSON schema, the model returns JSON, and AutoGen fills the object from it. This is the same structured output idea you have met before, made very easy.

3. Borrowing LangChain tools

AutoGen can reuse the huge ecosystem of LangChain tools through a small wrapper called LangChainToolAdapter. The lab takes the Google Serper web-search tool and the file-management toolkit you saw in Week 4, wraps each one, and hands them to an agent. Now the agent can search the web and write files — the same prompt asks it to find a flight, save the options to flights.md, and pick the best.

New to this? What the adapter does

LangChain and AutoGen each have their own idea of what a "tool" object looks like. The adapter is a thin translator: you give it a LangChain tool, it hands back something AutoGen recognises. Nothing about the tool's behaviour changes — it is still the same web search — only its outer shape. This is why one line, LangChainToolAdapter(langchain_serper), is enough to unlock LangChain's whole tool library inside AutoGen.

4. A team: primary and evaluator

The fourth demo introduces teams, the building block Day 1 left out. A RoundRobinGroupChat takes a list of agents and lets them speak in turn. Here a primary agent searches for a flight and an evaluator agent critiques it. They go back and forth until the evaluator replies with the word APPROVE, which a TextMentionTermination condition watches for. A max_turns=20 cap stops a runaway loop.

New to this? The primary / evaluator pattern

This is the evaluator-optimiser pattern from earlier in the course: one agent produces, another judges and sends feedback, and the producer tries again. It can genuinely raise quality, but it has a danger — if the judge is never satisfied, the two can talk forever. AutoGen does not impose a recursion limit the way LangGraph does, so you add your own stopping rule. Here it is a keyword (APPROVE) plus a turn cap. The instructor notes that matching a hard-coded word is brittle; a real system would use structured output to decide when it is done.

5. A teaser of MCP

The last demo is a preview of Week 6. MCP (Model Context Protocol, from Anthropic) is an open standard for packaging tools so any model can use them — the instructor calls it "the USB-C connector for AI". AutoGen has a wrapper for MCP tools just as it does for LangChain tools. The lab starts a public tool called mcp-server-fetch, which runs a headless browser locally, hands its tools to an agent, and asks the agent to read and summarise a website. Do not worry about the detail yet; Week 6 explains it fully.

What you should see. The describer returns a paragraph about the picture, then the structured version prints Scene / Message / Style / Orientation as separate fields (the instructor's run classed the image as landscape). The searcher writes a flights.md file in the sandbox folder and recommends a flight. The team prints a back-and-forth that ends with the evaluator saying APPROVE. The MCP fetcher returns a short Markdown summary of the website.
Common mistakes.
  • Using a text-only model for the image. Multimodal needs a vision-capable model such as gpt-4o-mini. A small local text model cannot see the picture.
  • Missing a Serper key. The web-search tool needs SERPER_API_KEY in .env, or the search calls fail.
  • The team never stops. If the evaluator keeps finding fault it loops. Keep max_turns set, and interrupt the kernel if it thrashes — the instructor had to restart a runaway run.
  • Relying on an exact word. TextMentionTermination("APPROVE") is brittle; if the evaluator phrases things differently it may never trigger. A real system would use structured output to decide completion.
  • No sandbox folder. The file tools write into sandbox; create that directory first or the writes fail.

In TypeScript

As on Day 1, there is no TypeScript twin. Multimodal messages, structured output with Pydantic, the LangChain adapter, teams and the MCP wrapper are all Python APIs with no JavaScript equivalent in AutoGen. The Week 5 React demo only mimics a chat exchange in the browser; it does not run any of this. Build these in Python.

Recap
  • A MultiModalMessage carries text and an image together; a vision model like gpt-4o-mini reads both.
  • Setting output_content_type to a Pydantic class makes the reply a typed object; AutoGen handles the JSON schema behind the scenes.
  • LangChainToolAdapter wraps any LangChain tool into an AutoGen tool, unlocking a large tool ecosystem.
  • A RoundRobinGroupChat is a team; a primary/evaluator pair improves an answer and stops on a termination condition such as TextMentionTermination("APPROVE") plus max_turns.
  • AutoGen also wraps MCP tools (a Week 6 topic): mcp_server_tools launches a server like mcp-server-fetch and returns tools you drop into tools=.
  • Through all five demos the agent API barely changes — the same AssistantAgent and on_messages/run.
Honesty note. Every demo on this page calls gpt-4o-mini and some reach the internet (Serper search, the MCP fetch server), so they need the matching keys and were not re-run live for this guide. They are shown exactly as in the course. What we verified locally against Ollama is the plain AgentChat conversational loop from Day 1; vision, web search and MCP depend on external services.
