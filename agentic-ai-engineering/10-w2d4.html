Week 2 · Day 4 — Deep Research, a Multi-Agent Team

A team that researches the web: a planner designs searches, search agents run them in parallel, and a writer composes a report. Hosted web-search tool and a typed plan. Python and TypeScript.

Companion to Ed Donner's course · uv setup · Python (+ TypeScript/React where it fits) · code from the course repo

Day 4 is the week's first big project: Deep Research, an agentic workflow that takes a topic, searches the web, and writes a report. This is the pattern the big labs ship as a "deep research" button, and it is built here from a small team of agents you already know how to make. Three familiar ideas carry the whole thing: agents, structured outputs, and running work in parallel with asyncio. The one new piece is a hosted tool.

The team has four members. A planner turns your query into a short list of searches. A search agent runs each search on the web. A writer folds the findings into a long report. An email agent sends it. The notebook builds these step by step; tomorrow (Day 5) the same steps move into Python modules and a ResearchManager class with a Gradio UI.

The web search is paid and hosted — we did not run it live. OpenAI's WebSearchTool runs on OpenAI's servers and costs about 2.5 cents per call at the settings used here (and sometimes more, since one call can trigger several searches). Ten searches can add up to a few dollars. This guide shows the search exactly as in the course but did not call it live. Start with a small number of searches and watch your spend.

The deep research team

The hosted WebSearchTool

Until now every tool was a Python function you wrote. A hosted tool is different: OpenAI runs it on their servers. There are three — web search, file search, and a computer tool — and this project uses web search. You give the search agent a WebSearchTool and the SDK handles the actual searching remotely. The agent's job is just to summarise what comes back.

New to this? What tool_choice="required" does

The search agent is created with model_settings=ModelSettings(tool_choice="required"). Normally a model decides for itself whether to use a tool. "Required" removes that choice: the agent must call its tool. Since the whole point of this agent is to run a web search, you do not want it to answer from memory and skip the search, so you force the tool call. search_context_size="low" keeps each search small and cheap.

The planner and structured outputs

The planner's job is to turn one query into a handful of good searches. It uses a structured output so the result is data, not prose. Two Pydantic models describe the shape: a WebSearchItem has a reason and a query, and a WebSearchPlan holds a list of those items. Setting the planner's output type to WebSearchPlan guarantees you get back a tidy list you can loop over.

New to this? Why ask for a reason as well as a query

Two reasons. First, the reason is passed to the search agent as context, so it searches with purpose. Second, asking the model to write the reason before the query nudges it to think — a light version of "chain of thought". Because the model predicts the next most-likely words, having just written a rationale makes the query it writes next more coherent with that rationale. You tend to get better queries as a side effect, with no extra code. The description written under each field (a string in the video; Field(description=...) in today's repository) is sent to the model too, so it knows what each field is for.

Running the searches in parallel

Searches do not depend on each other, so there is no reason to run them one at a time. Each search mostly waits on the network, which is exactly what async/await and asyncio are good at. The lab creates one task per search and then awaits them all together, so three searches take about as long as the slowest one, not the sum of all three.

import "dotenv/config";
import { Agent, run, withTrace, webSearchTool } from "@openai/agents";

const SEARCH_INSTRUCTIONS = "You are a research assistant. Given a search term, you search the web for that term and " +
  "produce a concise summary of the results. The summary must 2-3 paragraphs and less than 300 " +
  "words. Capture the main points. Write succintly, no need to have complete sentences or good " +
  "grammar. This will be consumed by someone synthesizing a report, so it's vital you capture the " +
  "essence and ignore any fluff. Do not include any additional commentary other than the summary itself.";

// webSearchTool() is OpenAI's hosted web search; toolChoice "required" forces the agent to use it
const searchAgent = new Agent({
  name: "Search agent",
  instructions: SEARCH_INSTRUCTIONS,
  tools: [webSearchTool({ searchContextSize: "low" })],
  model: "gpt-6-luna",
  modelSettings: { toolChoice: "required" },
});

const message = "Latest AI Agent frameworks in 2025";

await withTrace("Search", async () => {
  const result = await run(searchAgent, message);
  console.log(result.finalOutput); // Markdown text; a notebook would render it with display(Markdown(...))
});

// Video 16 in TypeScript: a planner agent with structured outputs (run: npx tsx day4_planner.ts)
import "dotenv/config";
import { Agent, run, withTrace } from "@openai/agents";
import { z } from "zod";

// See note above about cost of the web search tool
const HOW_MANY_SEARCHES = 3;

const PLANNER_INSTRUCTIONS = "You are a helpful research assistant. Given a query, come up with a set of web searches " +
  `to perform to best answer the query. Output ${HOW_MANY_SEARCHES} terms to query for.`;

// zod schemas play the Pydantic classes; .describe() is the docstring under each field
const WebSearchItem = z.object({
  reason: z.string().describe("Your reasoning for why this search is important to the query."),
  query: z.string().describe("The search term to use for the web search."),
});
const WebSearchPlan = z.object({
  searches: z.array(WebSearchItem).describe("A list of web searches to perform to best answer the query."),
});

const plannerAgent = new Agent({
  name: "PlannerAgent",
  instructions: PLANNER_INSTRUCTIONS,
  model: "gpt-6-luna",
  outputType: WebSearchPlan,
});

const message = "Latest AI Agent frameworks in 2025";

await withTrace("Search", async () => {
  const result = await run(plannerAgent, message);
  console.log(JSON.stringify(result.finalOutput, null, 2)); // { searches: [{ reason, query }, ...] }
});

async def plan_searches(query: str):
    """ Use the planner_agent to plan which searches to run for the query """
    print("Planning searches...")
    result = await Runner.run(planner_agent, f"Query: {query}")
    print(f"Will perform {len(result.final_output.searches)} searches")
    return result.final_output

async def perform_searches(search_plan: WebSearchPlan):
    """ Call search() for each item in the search plan """
    print("Searching...")
    num_completed = 0
    tasks = [asyncio.create_task(search(item)) for item in search_plan.searches]
    results = await asyncio.gather(*tasks)
    print("Finished searching")
    return results

async def search(item: WebSearchItem):
    """ Use the search agent to run a web search for each item in the search plan """
    input = f"Search term: {item.query}\nReason for searching: {item.reason}"
    result = await Runner.run(search_agent, input)
    return result.final_output

async def write_report(query: str, search_results: list[str]):
    """ Use the writer agent to write a report based on the search results"""
    print("Thinking about report...")
    input = f"Original query: {query}\nSummarized search results: {search_results}"
    result = await Runner.run(writer_agent, input)
    print("Finished writing report")
    return result.final_output

async function sendgrid(subject: string, content: string, type: "text/plain" | "text/html") {
  const response = await fetch("https://api.sendgrid.com/v3/mail/send", {
    method: "POST",
    headers: { Authorization: `Bearer ${process.env.SENDGRID_API_KEY}`, "Content-Type": "application/json" },
    body: JSON.stringify({
      from: { email: "your-verified-sender@example.com" }, // change to your verified sender
      personalizations: [{ to: [{ email: "your-inbox@example.com" }] }], // change to your recipient
      subject,
      content: [{ type, value: content }],
    }),
  });
  return response.status; // 202 means SendGrid accepted it
}

// The next 3 functions plan and execute the search, using plannerAgent and searchAgent
async function planSearches(query: string) {
  console.log("Planning searches...");
  const result = await run(plannerAgent, `Query: ${query}`);
  const plan = result.finalOutput!; // the ! says "this is set" (the run succeeded)
  console.log(`Will perform ${plan.searches.length} searches`);
  return plan;
}

async function performSearches(searchPlan: z.infer<typeof WebSearchPlan>) {
  console.log("Searching...");
  const results = await Promise.all(searchPlan.searches.map((item) => search(item))); // asyncio.gather
  console.log("Finished searching");
  return results;
}

async function search(item: z.infer<typeof WebSearchItem>) {
  const input = `Search term: ${item.query}\nReason for searching: ${item.reason}`;
  const result = await run(searchAgent, input);
  return result.finalOutput ?? "";
}

// The next 2 functions write a report and email it
async function writeReport(query: string, searchResults: string[]) {
  console.log("Thinking about report...");
  const input = `Original query: ${query}\nSummarized search results: ${JSON.stringify(searchResults)}`;
  const result = await run(writerAgent, input);
  console.log("Finished writing report");
  return result.finalOutput!;
}

// (Python reuses the name send_email for this step; TypeScript cannot, so the tool above is sendEmailTool)
async function sendEmail(report: z.infer<typeof ReportData>) {
  console.log("Writing email...");
  await run(emailAgent, report.markdown_report);
  console.log("Email sent");
  return report;
}

// Showtime!
const query = "Latest AI Agent frameworks in 2025";

await withTrace("Research trace", async () => {
  console.log("Starting research...");
  const searchPlan = await planSearches(query);
  const searchResults = await performSearches(searchPlan);
  const report = await writeReport(query, searchResults);
  await sendEmail(report);
  console.log("Hooray!");
});

Common mistakes.
  • Surprise cost. Each hosted web search costs roughly 2.5 cents, and a single call can run several searches. Raising HOW_MANY_SEARCHES multiplies the bill. Start at 3 and watch the dashboard.
  • Forgetting tool_choice="required". Without it the search agent may answer from memory and never search, giving stale, made-up results.
  • Reading a structured field off free text. result.final_output.searches only works because the planner has an output_type. Without it the output is a string and the attribute access fails.
  • Running searches in a plain loop. Awaiting each search one at a time works but is slow. The parallel version (asyncio.gather / Promise.all) is the whole reason the project feels fast.
  • Retired model. gpt-4o-mini from the video is gone; use the "Runs today" tabs.
  • SendGrid not set up. The email step needs a verified sender and SENDGRID_API_KEY in .env; change the hard-coded addresses to your own.
Recap
  • Deep Research is a team of four agents: a planner, a web-searcher, a writer, and an emailer, run in order by a manager.
  • The WebSearchTool is a hosted tool — it runs on OpenAI's servers and is billed per call, so it was shown but not run live here.
  • The planner uses a structured output: output_type=WebSearchPlan returns a typed list of searches, each with a query and a reason.
  • Asking for a reason as well as a query gives the searcher context and nudges the model toward better queries.
  • Searches are independent and network-bound, so they run in parallel with asyncio.gather (lab) or asyncio.as_completed (tomorrow's project) — Promise.all in TypeScript.
  • The writer returns a ReportData (summary, markdown report, follow-up questions); the manager turns the notebook's loose steps into a reusable class with progress and error handling.
