Week 5 · Day 3 — AutoGen Core: Message Passing

The lower-level Core layer: registering agents, message handlers and dispatching. Build standalone agents that play rock-paper-scissors with different models.

Companion to Ed Donner's course · uv setup · Python (+ TypeScript/React where it fits) · code from the course repo

Day 3 drops below AgentChat to the layer it is built on: AutoGen Core. Where AgentChat is about making one agent answer nicely, Core is about many agents finding and messaging each other. The instructor is clear that this is a flavour, not a deep dive — the examples are deliberately small — but it shows the idea that makes AutoGen distinctive.

What Core is for. Core is an agent interaction framework. It takes care of creating agents and delivering messages between them, even across processes or programming languages. It does not care how you implement an agent — you could call an LLM directly, or delegate to an AgentChat agent, or write no AI at all. That separation (delivery versus logic) is the whole point.

The core idea: decouple logic from delivery

In Core you are responsible for one thing — what an agent does when it gets a message. The framework is responsible for everything else: creating agents, giving each a unique identity, and routing messages to the right handler. The instructor compares it to LangGraph, which also coordinates agents but is built around replayable, repeatable workflows. Core's emphasis is different: it is about supporting diverse agents interacting, possibly spread across many machines.

New to this? What a runtime is

A runtime is the world your agents live in. It keeps track of which agents exist, instantiates them when needed, and delivers messages between them. Core offers two kinds: a standalone runtime that runs on one machine (today), and a distributed runtime that spans processes and machines (Day 4). You write your agents once; the runtime decides where and how they actually run.

Messages and agents in Core

Two things are new here. First, you define your own message type — a plain @dataclass that just holds data, because a message is a parcel of information, not behaviour. Second, a Core agent is a subclass of RoutedAgent: a management wrapper that can be created, identified and messaged. It is not itself an LLM. If it needs intelligence, it delegates to something — often an AgentChat AssistantAgent.

New to this? AgentId — type and key

Every agent has an AgentId made of two parts: a type (like a class name, for example "simple_agent") and a key (an instance label, usually "default"). Together they are unique, so any agent anywhere can address any other just by knowing its type and key. In a distributed world with thousands of agents, that pair is how one agent is told apart from the next.

New to this? The @message_handler decorator

A method decorated with @message_handler is a place messages can arrive. The runtime looks at the type of the incoming message and dispatches it to the handler whose parameter matches that type. So you can have several handlers on one agent — one for text messages, one for image messages — and Core routes each to the right one automatically. That routing is the clever part you get for free.

The standalone runtime, step by step

The lab's first agent, SimpleAgent, has no AI at all: it just disagrees with whatever you say. That is on purpose — it shows the plumbing without the distraction of an LLM. You register the agent type with a runtime (passing a factory that can build instances), start the runtime, send a message to an AgentId, read the reply, then stop and close the runtime.

Giving an agent a brain, then a game

The second agent, MyLLMAgent, shows Core does not care about intelligence: inside its handler it delegates to an AgentChat AssistantAgent and returns whatever that produces. Watch the two message types — TextMessage is the AgentChat message used to talk to the delegate, while Message is our own dataclass used between Core agents. They look alike but belong to different layers.

The finale is rock-paper-scissors between three agents: player1 backed by gpt-4o-mini, player2 backed by local llama3.2, and a referee that messages both players, collects their choices, and asks its own model who wins. It is trivial as a game, but it demonstrates agents discovering and messaging one another through the runtime.

The full lab

Here is the complete file: the disagreeable agent, the LLM-backed agent, and the three-way game.

from dataclasses import dataclass
from autogen_core import AgentId, MessageContext, RoutedAgent, message_handler
from autogen_core import SingleThreadedAgentRuntime
from autogen_agentchat.agents import AssistantAgent
from autogen_agentchat.messages import TextMessage
from autogen_ext.models.openai import OpenAIChatCompletionClient
from dotenv import load_dotenv

load_dotenv(override=True)


# Let's have a simple one!

@dataclass
class Message:
    content: str


class SimpleAgent(RoutedAgent):
    def __init__(self) -> None:
        super().__init__("Simple")

    @message_handler
    async def on_my_message(self, message: Message, ctx: MessageContext) -> Message:
        return Message(content=f"This is {self.id.type}-{self.id.key}. You said '{message.content}' and I disagree.")
        


runtime = SingleThreadedAgentRuntime()
await SimpleAgent.register(runtime, "simple_agent", lambda: SimpleAgent())

runtime.start()

agent_id = AgentId("simple_agent", "default")
response = await runtime.send_message(Message("Well hi there!"), agent_id)
print(">>>", response.content)

await runtime.stop()
await runtime.close()


class MyLLMAgent(RoutedAgent):
    def __init__(self) -> None:
        super().__init__("LLMAgent")
        model_client = OpenAIChatCompletionClient(model="gpt-4o-mini")
        self._delegate = AssistantAgent("LLMAgent", model_client=model_client)

    @message_handler
    async def handle_my_message_type(self, message: Message, ctx: MessageContext) -> Message:
        print(f"{self.id.type} received message: {message.content}")
        text_message = TextMessage(content=message.content, source="user")
        response = await self._delegate.on_messages([text_message], ctx.cancellation_token)
        reply = response.chat_message.content
        print(f"{self.id.type} responded: {reply}")
        return Message(content=reply)

from autogen_ext.models.ollama import OllamaChatCompletionClient


class Player1Agent(RoutedAgent):
    def __init__(self, name: str) -> None:
        super().__init__(name)
        model_client = OpenAIChatCompletionClient(model="gpt-4o-mini", temperature=1.0)
        self._delegate = AssistantAgent(name, model_client=model_client)

    @message_handler
    async def handle_my_message_type(self, message: Message, ctx: MessageContext) -> Message:
        text_message = TextMessage(content=message.content, source="user")
        response = await self._delegate.on_messages([text_message], ctx.cancellation_token)
        return Message(content=response.chat_message.content)
    
class Player2Agent(RoutedAgent):
    def __init__(self, name: str) -> None:
        super().__init__(name)
        model_client = OllamaChatCompletionClient(model="llama3.2", temperature=1.0)
        self._delegate = AssistantAgent(name, model_client=model_client)

    @message_handler
    async def handle_my_message_type(self, message: Message, ctx: MessageContext) -> Message:
        text_message = TextMessage(content=message.content, source="user")
        response = await self._delegate.on_messages([text_message], ctx.cancellation_token)
        return Message(content=response.chat_message.content)

JUDGE = "You are judging a game of rock, paper, scissors. The players have made these choices:\n"

class RockPaperScissorsAgent(RoutedAgent):
    def __init__(self, name: str) -> None:
        super().__init__(name)
        model_client = OpenAIChatCompletionClient(model="gpt-4o-mini", temperature=1.0)
        self._delegate = AssistantAgent(name, model_client=model_client)

    @message_handler
    async def handle_my_message_type(self, message: Message, ctx: MessageContext) -> Message:
        instruction = "You are playing rock, paper, scissors. Respond only with the one word, one of the following: rock, paper, or scissors."
        message = Message(content=instruction)
        inner_1 = AgentId("player1", "default")
        inner_2 = AgentId("player2", "default")
        response1 = await self.send_message(message, inner_1)
        response2 = await self.send_message(message, inner_2)
        result = f"Player 1: {response1.content}\nPlayer 2: {response2.content}\n"
        judgement = f"{JUDGE}{result}Who wins?"
        message = TextMessage(content=judgement, source="user")
        response = await self._delegate.on_messages([message], ctx.cancellation_token)
        return Message(content=result + response.chat_message.content)


runtime = SingleThreadedAgentRuntime()
await Player1Agent.register(runtime, "player1", lambda: Player1Agent("player1"))
await Player2Agent.register(runtime, "player2", lambda: Player2Agent("player2"))
await RockPaperScissorsAgent.register(runtime, "rock_paper_scissors", lambda: RockPaperScissorsAgent("rock_paper_scissors"))
runtime.start()

agent_id = AgentId("rock_paper_scissors", "default")
message = Message(content="go")
response = await runtime.send_message(message, agent_id)
print(response.content)

await runtime.stop()
await runtime.close()

Common mistakes.
  • Not starting the runtime. Messages sent before runtime.start() are never processed.
  • Forgetting stop and close. AutoGen wants each runtime stopped and closed before you build the next; skipping it can cause errors on the following example.
  • Confusing the two message types. Message is your Core dataclass; TextMessage is AgentChat's. Mixing them up where one is expected raises errors. Some people alias one to keep them clear.
  • Ollama not running for player 2. Player 2 uses local llama3.2, so Ollama must be started and the model pulled, or that agent's call fails.
  • Wrong AgentId. The type and key must match what you registered ("player1", "default"), or the runtime cannot find the agent.

In TypeScript

AutoGen Core is a Python runtime (Microsoft's other implementation is .NET). There is no JavaScript port, so none of RoutedAgent, @message_handler, AgentId or SingleThreadedAgentRuntime exists in TypeScript. The Week 5 React demo does not reproduce Core; it only shows a chat-style UI. Core work is Python work.

Recap
  • AutoGen Core separates message delivery (the framework's job) from agent logic (yours).
  • Messages are your own @dataclass; agents subclass RoutedAgent and are management wrappers, not LLMs.
  • Each agent has an AgentId of a type plus a key, which is how any agent addresses any other.
  • A method marked @message_handler receives messages; Core routes each message to the handler whose parameter matches its type.
  • The standalone SingleThreadedAgentRuntime lifecycle is register a type, start(), send_message(), then stop() and close().
  • An agent gains intelligence by delegating to an AgentChat AssistantAgent; an agent can message others with self.send_message, as the rock-paper-scissors referee does.
Honesty note. The disagreeable SimpleAgent uses no model, so it runs anywhere. The LLM agent and player 1 call gpt-4o-mini and need an OPENAI_API_KEY; player 2 uses local llama3.2. For this guide we verified a Core message-passing example against local Ollama; the cloud calls are shown as in the course and were not re-run live.
