Agentic AI Engineering · a beginner's companion

One page per course day. Each page explains the lessons in plain language, shows the exact code from the course (from the official repo), and records what was checked by running it. Where a framework has a JavaScript port, every lab is shown in both Python and TypeScript (with a small React web app); where it does not, the day is Python-first with a small React demo UI. The project is set up with uv. Written for people just starting as developers.

This guide uses uv (not Anaconda) for setup. The runnable week1-ts … week6-ts and week1-py … week6-py projects were verified against a free local Ollama model, and each has a RUN-NOTES file saying what ran and what was shown as in the course.

How this guide is organised

The course runs over six weeks, and this guide follows it with one page per course day, plus a project-build page at the end of each week. All six weeks are built. Week 1 builds agents from scratch with no framework; Weeks 2 to 6 each take on one major framework — the OpenAI Agents SDK, CrewAI, LangGraph, AutoGen and MCP — ending with an autonomous trading floor.

Stack

These are the tools the guide uses across the six weeks. You set each project up once with uv sync (Python) or npm install (TypeScript). Model calls go either to a paid cloud API, as in the course, or to Ollama — a free program that runs a model on your own computer — which is how the runnable projects here were verified.

The course, day by day

Week 1 · Foundations: Agents from Scratch

Before any framework: set up with uv, call several LLMs through one API, learn the agent-vs-workflow design patterns, give a model tools and structured outputs, and build a career "digital twin" agent that answers questions about you and pings you on your phone. Every lab in Python and TypeScript/React.

  1. 01Week 1 · Day 1 — Setup and Your First Agentic WorkflowInstall the tools with uv, see what an agent is, and build your first multi-step LLM workflow that plans and then acts - in Python and TypeScript.~70 min
  2. 02Week 1 · Day 2 — Workflow Design PatternsThe difference between a workflow and an agent, and the five everyday patterns (chaining, routing, parallelisation, orchestrator-workers, evaluator-optimiser) for building reliable LLM systems.~35 min
  3. 03Week 1 · Day 3 — Orchestrating Multiple LLMsCall OpenAI, Claude, Gemini and DeepSeek through one OpenAI-style client, then build a little system that asks several models the same question and has a model judge the answers.~50 min
  4. 04Week 1 · Day 4 — Tools, Resources and Structured OutputsGive a model tools and resources, get structured (typed) output, put a Gradio chat UI on it, and build a multi-LLM pipeline where one model evaluates another.~50 min
  5. 05Week 1 · Day 5 — The Career AgentBuild a career "digital twin": a chatbot that answers as you, uses tools to record unknown questions and leads, pushes you a phone alert, and deploys to a public URL.~55 min
  6. 06Week 1 · Project Build — The Career Agent, Step by StepBuild the career "digital twin" agent from an empty folder in two stacks: Python with uv (Gradio), and a React + Node + TypeScript chat app with a Hono API.build

Week 2 · The OpenAI Agents SDK

Your first real framework. Create agents with the OpenAI Agents SDK, give them tools, hand off between them and use agents as tools, add structured outputs and guardrails, then build a deep-research team of agents that plans, searches and writes a report. Python and a TypeScript/React port with @openai/agents.

  1. 07Week 2 · Day 1 — The OpenAI Agents SDKYour first framework: Agent, Runner and traces. Set up async Python, create an agent, run it, and read the trace of what happened - in Python and TypeScript with @openai/agents.~60 min
  2. 08Week 2 · Day 2 — Tools, Handoffs and Agents as ToolsBuild a sales team of agents: give them tools (including sending email), run several in parallel with asyncio, use agents as tools, and hand off between them. Python and TypeScript.~70 min
  3. 09Week 2 · Day 3 — Structured Outputs and GuardrailsMix models (Gemini, DeepSeek, Grok) through the SDK, force typed output with Pydantic, and add input/output guardrails that stop an agent before it does something unwanted. Python and TypeScript.~55 min
  4. 10Week 2 · Day 4 — Deep Research, a Multi-Agent TeamA team that researches the web: a planner designs searches, search agents run them in parallel, and a writer composes a report. Hosted web-search tool and a typed plan. Python and TypeScript.~60 min
  5. 11Week 2 · Day 5 — Finishing and Deploying Deep ResearchWire the deep-research team to a Gradio UI, email the finished report, and deploy it. Plus a React + TypeScript version of the research app.~50 min
  6. 12Week 2 · Project Build — Deep Research, Step by StepBuild the deep-research multi-agent team from an empty folder in two stacks: Python with uv (Agents SDK + Gradio), and a React + Node + TypeScript app with a Hono API over @openai/agents.build

Week 3 · CrewAI — Teams of Agents

CrewAI models a team: agents with roles, the tasks they do, and a process that runs them in sequence or with a manager. Build a debate, a financial-research crew, a stock-picker with typed output and a custom tool, add memory, and finish with a crew that writes software. Python with uv; a small React demo UI for the result.

  1. 13Week 3 · Day 1 — CrewAI: Agents, Tasks and a DebateMeet CrewAI: agents have a role, goal and backstory; tasks describe the work; a process runs them. Build a debate crew where different LLMs argue a motion and a judge decides.~65 min
  2. 14Week 3 · Day 2 — Tools and Context: a Financial Research CrewGive a crew real tools (web search) and pass one task's output as context to the next. Build a financial-research crew that researches a company and writes a report.~40 min
  3. 15Week 3 · Day 3 — Structured Output and Custom Tools: the Stock PickerForce typed results with Pydantic output_pydantic, write a custom tool (a push notification), and use a hierarchical process with a manager. Build a stock-picker crew.~45 min
  4. 16Week 3 · Day 4 — Memory and a Coder CrewAdd memory (short-term, long-term, entity) backed by vector storage and SQLite, and build a coder crew whose agent writes and runs Python in a safe sandbox.~40 min
  5. 17Week 3 · Day 5 — The Engineering TeamThe capstone crew: an engineering lead, a backend and a frontend engineer and a tester collaborate to turn requirements into working software.~50 min
  6. 18Week 3 · Project Build — the Stock Picker Crew, Step by StepBuild the stock-picker crew from an empty folder with uv and CrewAI: agents and tasks in YAML, Pydantic output, a custom push tool and a hierarchical manager, plus a small React demo UI that shows the result.build

Week 4 · LangGraph — Agents as Graphs

LangGraph makes an agent an explicit graph: a shared state, nodes that change it, and edges (some conditional) that decide what runs next, with checkpointing for memory. Build chatbots, tool-calling graphs, and a browser-using "Sidekick" with a worker/evaluator loop. Python and a TypeScript/React port with LangGraph.js.

  1. 19Week 4 · Day 1 — LangGraph: Agents as GraphsWhy LangGraph models an agent as a graph, and how Framework, Studio and Platform fit together. The core pieces: state, nodes, edges and the graph you compile and run - in Python and TypeScript.~40 min
  2. 20Week 4 · Day 2 — State, Nodes and Edges: a Chatbot GraphDefine a State object with reducers, add nodes and edges, and build a working chatbot graph around an LLM. Python (LangGraph) and TypeScript (LangGraph.js).~50 min
  3. 21Week 4 · Day 3 — Tools, Conditional Edges and MemoryAdd tools with a ToolNode and conditional edges, trace with LangSmith, and keep memory between turns with SQLite checkpointing. Python and TypeScript.~55 min
  4. 22Week 4 · Day 4 — The Sidekick: Browser Automation and an EvaluatorBuild a "Sidekick" that browses the web with Playwright and a worker/evaluator feedback loop that checks its own work against success criteria. Python and TypeScript.~60 min
  5. 23Week 4 · Day 5 — Finishing the SidekickAdd web search, a file system and a Python REPL tool, isolate each user's session, and wire it to a Gradio UI. Python and a React + TypeScript version.~60 min
  6. 24Week 4 · Project Build — the Sidekick, Step by StepBuild the Sidekick from an empty folder in two stacks: Python with uv (LangGraph + Playwright + Gradio), and a React + Node + TypeScript app with a Hono API over LangGraph.js.build

Week 5 · AutoGen — Conversation and Distribution

Microsoft's AutoGen has two layers: AgentChat for quick conversational agents with tools and structured output, and AutoGen Core for message-passing agents that can run distributed across processes. Finish with agents that create and run other agents. Python with uv; a small React demo UI.

  1. 25Week 5 · Day 1 — AutoGen AgentChatMicrosoft's AutoGen and how it compares to other frameworks. In AgentChat: model clients, messages and agents, and giving an agent tools.~50 min
  2. 26Week 5 · Day 2 — Multimodal, Structured Output and an EvaluatorRicher AgentChat: images and multimodal messages, structured outputs, a primary/evaluator pair, and reaching an MCP fetch server for headless web scraping.~45 min
  3. 27Week 5 · Day 3 — AutoGen Core: Message PassingThe lower-level Core layer: registering agents, message handlers and dispatching. Build standalone agents that play rock-paper-scissors with different models.~50 min
  4. 28Week 5 · Day 4 — Distributed AgentsAutoGen Core's distributed runtime: run agents across processes that talk over a gRPC host. The architecture and a cross-process example.~45 min
  5. 29Week 5 · Day 5 — Agents That Create AgentsThe capstone: an autonomous "world" where a creator agent writes and deploys other agents that collaborate over async messaging.~45 min
  6. 30Week 5 · Project Build — the Agent World, Step by StepBuild the AutoGen Core "world" from an empty folder with uv: a creator agent, message templates and collaborating agents, plus a small React demo UI.build

Week 6 · MCP and the Trading Floor

The Model Context Protocol (MCP) is a standard way to plug tools and data into agents. Use existing MCP servers, build your own, connect market-data servers, and run the capstone: an autonomous trading floor of agents. Python with uv; a small React demo UI. Plus how to choose a framework.

  1. 31Week 6 · Day 1 — MCP: the USB-C of Agentic AIWhat the Model Context Protocol is: hosts, clients and servers. Use existing MCP servers from the OpenAI Agents SDK, including node-based ones, and wire several into one agent.~65 min
  2. 32Week 6 · Day 2 — Build Your Own MCP ServerWrite an MCP server from scratch, wire your own business logic (an accounts system) into it, and write client code that an agent uses to call it.~50 min
  3. 33Week 6 · Day 3 — Market Data and Agent MemoryTypes of MCP servers and giving an agent memory, then connecting market-data servers (Brave search, Polygon) so agents can see the web and live prices.~50 min
  4. 34Week 6 · Day 4 — The Trading FloorThe capstone: four autonomous trader agents manage portfolios, make decisions and operate a trading floor, with a UI that shows their activity.~50 min
  5. 35Week 6 · Day 5 — Launching, and Choosing a FrameworkLaunch the trading system, then step back: how to choose among the frameworks you've learned, ten lessons for building agent solutions, and a course recap.~55 min
  6. 36Week 6 · Project Build — the Trading Floor, Step by StepBuild the trading-floor system from an empty folder with uv: a custom accounts MCP server, market-data servers, autonomous trader agents and a scheduler, plus a small React demo UI that shows portfolios.build

Compared with the GitHub repo

Code is embedded from ed-donner/agents, pinned at commit 02573939 (2025-10-01) so it matches the 2025 videos rather than a later refresh. Unlike some courses, the pinned code uses real, period-correct model ids (gpt-4o-mini, gpt-4.1-mini, claude-3-7-sonnet-latest, gemini-2.0-flash, deepseek-chat, llama3.2), so there is no "repo ahead of video" divergence — the ids are kept as-is. The one deliberate change in this guide's runnable projects is pointing the models at a free local Ollama server for verification; each weekN-py / weekN-ts folder has a RUN-NOTES file listing exactly what was run locally and what (paid APIs, hosted search, long-running systems) is shown as in the course but not re-run.
