Week 6 · Day 3 — Market Data and Agent Memory

Types of MCP servers and giving an agent memory, then connecting market-data servers (Brave search, Polygon) so agents can see the web and live prices.

Companion to Ed Donner's course · uv setup · Python (+ TypeScript/React where it fits) · code from the course repo

Today is the fun shopping trip. We plug several ready-made MCP servers into an agent: a knowledge-graph memory server, a Brave web-search server, and a Polygon stock-market data server. Along the way the instructor sorts MCP servers into three kinds by where they do their work, and shows a neat caching trick so the free market-data plan does not hit its rate limit.

Three kinds of MCP server

New to this? The three configurations
  1. Local-only. Runs on your machine and only touches your machine — like the accounts server we built, or the filesystem server. Today's memory server is this kind.
  2. Local, calling the internet. Runs on your machine but reaches out to a web API. This is the most common kind — fetch, Brave and Polygon all work this way.
  3. Remote (hosted/managed). The server itself runs on someone else's machine and you connect over SSE. Rare, and often flaky, so we only look at examples.

Agent memory with a knowledge graph

The first server gives an agent memory. It is a JavaScript server, mcp-memory-libsql, that stores entities, observations and relationships in a SQLite database. The instructor's key insight: in the MCP age, "memory" is not one magic feature — it is just another set of tools that put relevant context into the prompt. This one offers tools like create entities, search nodes, read graph and create relations.

Brave web search

The second server is Brave Search, Anthropic's reference server @modelcontextprotocol/server-brave-search. It is kind 2: it runs locally with npx but calls Brave's search API over the web. It needs a free API key passed in through the server's env — a new wrinkle compared with the earlier servers.

Polygon market data

The third is market data from Polygon, a well-known financial data provider. It has a free plan (prices as of the previous day's close) and paid plans (15-minute delayed, or real-time). The course sticks to the free plan.

Brave and Polygon are keyed services and were not run live for this guide. Brave has a free tier (about 2,000 searches a month) and Polygon has a free tier (end-of-day prices), but both need you to sign up for an API key, and the paid Polygon tiers cost roughly $20–30 a month. These are shown exactly as in the course. What is verified locally for the guide is the earlier accounts server and an agent calling its tools over stdio against Ollama.

The handcrafted market server

The project's own market server is tiny — the same FastMCP pattern as the accounts server, exposing a single tool that prices a stock.

from mcp.server.fastmcp import FastMCP
from market import get_share_price

mcp = FastMCP("market_server")

@mcp.tool()
async def lookup_share_price(symbol: str) -> float:
    """This tool provides the current price of the given stock symbol.

    Args:
        symbol: the symbol of the stock
    """
    return get_share_price(symbol)

if __name__ == "__main__":
    mcp.run(transport='stdio')

The market wrapper and its caching trick

Behind that one tool is market.py, which hides Polygon's rate limits. On the free plan Polygon only allows a few calls per minute, but asking for the whole market's prices counts as a single call. So the wrapper fetches every price once, caches it, and serves all later lookups from the cache.

from polygon import RESTClient
from dotenv import load_dotenv
import os
from datetime import datetime
import random
from database import write_market, read_market
from functools import lru_cache
from datetime import timezone

load_dotenv(override=True)

polygon_api_key = os.getenv("POLYGON_API_KEY")
polygon_plan = os.getenv("POLYGON_PLAN")

is_paid_polygon = polygon_plan == "paid"
is_realtime_polygon = polygon_plan == "realtime"


def is_market_open() -> bool:
    client = RESTClient(polygon_api_key)
    market_status = client.get_market_status()
    return market_status.market == "open"


def get_all_share_prices_polygon_eod() -> dict[str, float]:
    """With much thanks to student Reema R. for fixing the timezone issue with this!"""
    client = RESTClient(polygon_api_key)

    probe = client.get_previous_close_agg("SPY")[0]
    last_close = datetime.fromtimestamp(probe.timestamp / 1000, tz=timezone.utc).date()

    results = client.get_grouped_daily_aggs(last_close, adjusted=True, include_otc=False)
    return {result.ticker: result.close for result in results}


@lru_cache(maxsize=2)
def get_market_for_prior_date(today):
    market_data = read_market(today)
    if not market_data:
        market_data = get_all_share_prices_polygon_eod()
        write_market(today, market_data)
    return market_data


def get_share_price_polygon_eod(symbol) -> float:
    today = datetime.now().date().strftime("%Y-%m-%d")
    market_data = get_market_for_prior_date(today)
    return market_data.get(symbol, 0.0)


def get_share_price_polygon_min(symbol) -> float:
    client = RESTClient(polygon_api_key)
    result = client.get_snapshot_ticker("stocks", symbol)
    return result.min.close or result.prev_day.close


def get_share_price_polygon(symbol) -> float:
    if is_paid_polygon:
        return get_share_price_polygon_min(symbol)
    else:
        return get_share_price_polygon_eod(symbol)


def get_share_price(symbol) -> float:
    if polygon_api_key:
        try:
            return get_share_price_polygon(symbol)
        except Exception as e:
            print(f"Was not able to use the polygon API due to {e}; using a random number")
    return float(random.randint(1, 100))

Gathering all the servers: mcp_params.py

The project keeps every server's params in one tidy module. It defines the trader's servers (accounts, push notifications, market) and a function for the researcher's servers (fetch, Brave, memory) — and switches the market server based on your Polygon plan.

Common mistakes.
  • Missing API keys. Brave and Polygon need their keys in .env, then re-run the load step. No key means no data.
  • Too many tools on the free plan. Giving the model all of Polygon's tools on the free plan makes most calls fail; use the single cached tool instead.
  • Stale memory. An old memory/*.db keeps answers from a previous run. Delete it to start fresh.
  • Chasing remote servers. Hosted (SSE) servers are rare and often down; stick to local servers.
Recap
  • MCP servers come in three kinds: local-only, local-but-calling-the-web (most common), and remote/SSE (rare).
  • Memory is not magic — it is a server of tools (create entity, search nodes, relations) that feed context into the prompt; here it is a knowledge graph in SQLite.
  • Brave search and Polygon market data are keyed services (free tiers plus paid); they were not run live for this guide.
  • Pass a server its API key through the params' env dictionary.
  • The market wrapper dodges Polygon's rate limit by caching one whole-market snapshot, and falls back to random prices when there is no key.
  • mcp_params.py gathers the trader's servers (accounts, push, market) and the researcher's servers (fetch, Brave, memory) in one place.
