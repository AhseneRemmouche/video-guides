Week 6 · Day 4 — The Trading Floor

The capstone: four autonomous trader agents manage portfolios, make decisions and operate a trading floor, with a UI that shows their activity.

Companion to Ed Donner's course · uv setup · Python (+ TypeScript/React where it fits) · code from the course repo

This is the capstone. We build autonomous traders: agents that research the market, decide what to do, and buy or sell in the simulated accounts we built on Day 2. Each trader has its own researcher agent (used as a tool) armed with web search and memory. Today we assemble one trader in the lab, then see the same thing refactored into clean Python modules.

Not real financial advice. The instructor repeats this several times: this is an experimental project. Do not use it to make real trading decisions. The "trades" happen only in our own simulated accounts.

The shape of the system

Each trader is an agent with a set of MCP servers for acting (accounts, push notifications, market data) and a researcher agent it can call as a tool. The researcher has its own servers for investigating (fetch, Brave, memory). This is the agent-as-tool pattern from week 2: wrap one agent so another can call it.

Start in the lab, not in architecture diagrams. A theme the instructor hammers: approach agent projects with a "data scientist hat" — experiment in a notebook first, understand what the models can actually do, and only then refactor into modules. That is exactly the order of today: lab first, modules second.

The push-notification server

One new server is push_server.py: a tiny MCP server with a single tool that sends a push notification to your phone, so you feel the autonomy when a trader acts. The instructor notes this is a case where a plain function tool would be fine — it is wrapped as a server only to keep the project uniformly MCP.

import os
from dotenv import load_dotenv
import requests
from pydantic import BaseModel, Field
from mcp.server.fastmcp import FastMCP

load_dotenv(override=True)

pushover_user = os.getenv("PUSHOVER_USER")
pushover_token = os.getenv("PUSHOVER_TOKEN")
pushover_url = "https://api.pushover.net/1/messages.json"


mcp = FastMCP("push_server")


class PushModelArgs(BaseModel):
    message: str = Field(description="A brief message to push")


@mcp.tool()
def push(args: PushModelArgs):
    """Send a push notification with this brief message"""
    print(f"Push: {args.message}")
    payload = {"user": pushover_user, "token": pushover_token, "message": args.message}
    requests.post(pushover_url, data=payload)
    return "Push notification sent"


if __name__ == "__main__":
    mcp.run(transport="stdio")

The lab: assembling one trader

Lab 4 gathers the server params, builds the researcher and turns it into a tool, then builds the trader and runs it. Note how the trader's prompt is filled using MCP resources — the account report and strategy are read from the accounts server and pasted into the instructions.

In TypeScript: there is no TypeScript port of the trading floor. MCP is language-neutral, but this capstone (FastMCP servers, the Account business logic, the Trader class) is Python only, so these are single Python blocks. The React side this week is a small demo UI on the build page, not a port of this code.

The Trader class: traders.py

The lab, cleaned into a class. A Trader is created with a name, an optional model, and knows how to build its agent, run it, and flip between trading and rebalancing each run. It also supports many different model providers.

def get_model(model_name: str):
    if "/" in model_name:
        return OpenAIChatCompletionsModel(model=model_name, openai_client=openrouter_client)
    elif "deepseek" in model_name:
        return OpenAIChatCompletionsModel(model=model_name, openai_client=deepseek_client)
    elif "grok" in model_name:
        return OpenAIChatCompletionsModel(model=model_name, openai_client=grok_client)
    elif "gemini" in model_name:
        return OpenAIChatCompletionsModel(model=model_name, openai_client=gemini_client)
    else:
        return model_name

class Trader:
    def __init__(self, name: str, lastname="Trader", model_name="gpt-4o-mini"):
        self.name = name
        self.lastname = lastname
        self.agent = None
        self.model_name = model_name
        self.do_trade = True

    async def create_agent(self, trader_mcp_servers, researcher_mcp_servers) -> Agent:
        tool = await get_researcher_tool(researcher_mcp_servers, self.model_name)
        self.agent = Agent(
            name=self.name,
            instructions=trader_instructions(self.name),
            model=get_model(self.model_name),
            tools=[tool],
            mcp_servers=trader_mcp_servers,
        )
        return self.agent

    async def get_account_report(self) -> str:
        account = await read_accounts_resource(self.name)
        account_json = json.loads(account)
        account_json.pop("portfolio_value_time_series", None)
        return json.dumps(account_json)

    async def run_agent(self, trader_mcp_servers, researcher_mcp_servers):
        self.agent = await self.create_agent(trader_mcp_servers, researcher_mcp_servers)
        account = await self.get_account_report()
        strategy = await read_strategy_resource(self.name)
        message = (
            trade_message(self.name, strategy, account)
            if self.do_trade
            else rebalance_message(self.name, strategy, account)
        )
        await Runner.run(self.agent, message, max_turns=MAX_TURNS)

    async def run_with_mcp_servers(self):
        async with AsyncExitStack() as stack:
            trader_mcp_servers = [
                await stack.enter_async_context(
                    MCPServerStdio(params, client_session_timeout_seconds=120)
                )
                for params in trader_mcp_server_params
            ]
            async with AsyncExitStack() as stack:
                researcher_mcp_servers = [
                    await stack.enter_async_context(
                        MCPServerStdio(params, client_session_timeout_seconds=120)
                    )
                    for params in researcher_mcp_server_params(self.name)
                ]
                await self.run_agent(trader_mcp_servers, researcher_mcp_servers)

    async def run_with_trace(self):
        trace_name = f"{self.name}-trading" if self.do_trade else f"{self.name}-rebalancing"
        trace_id = make_trace_id(f"{self.name.lower()}")
        with trace(trace_name, trace_id=trace_id):
            await self.run_with_mcp_servers()

    async def run(self):
        try:
            await self.run_with_trace()
        except Exception as e:
            print(f"Error running trader {self.name}: {e}")
        self.do_trade = not self.do_trade

For this guide, what is verified locally is the accounts MCP server and an agent calling its tools over stdio against Ollama; the live trading floor was not re-run.
Recap
  • A trader is an agent that acts (accounts, push, market servers) and calls a researcher agent as a tool (fetch, Brave, memory servers).
  • Build in the lab first with a data-scientist mindset, then refactor into modules.
  • Resources let you read an account's report and strategy and paste them straight into the trader's prompt.
  • templates.py keeps every prompt in one place; traders.py packages it all into a Trader class.
  • A trader alternates trading and rebalancing by flipping a do_trade flag each run, and can even change its own strategy.
  • AsyncExitStack opens many MCP servers cleanly; the whole system runs on six servers and dozens of tools, and get_model lets each trader use a different provider.
