Week 4 · Day 4 — The Sidekick: Browser Automation and an Evaluator

Build a "Sidekick" that browses the web with Playwright and a worker/evaluator feedback loop that checks its own work against success criteria. Python and TypeScript.

Companion to Ed Donner's course · uv setup · Python (+ TypeScript/React where it fits) · code from the course repo

Today we start the week's project: the Sidekick, a personal co-worker that can browse the web, run tools, and keep trying until the job is actually done. First (lab 3) the agent gets a real browser through Playwright. The engine behind it is a worker/evaluator loop — two LLM roles that cooperate inside one LangGraph. A worker does the task (and may call tools); an evaluator judges the worker's answer against the user's success criteria and decides whether to finish or send it back for another try. The evaluator answers with a structured output, and conditional edges do the routing.

Two notebooks today: 3_lab3.ipynb builds a chatbot that drives a browser, and 4_lab4.ipynb adds the evaluator and a Gradio UI. Tomorrow (day 5) the same graph is packaged as the Sidekick class in Python modules, with more tools.

This is a true agent, not a fixed workflow. Because the evaluator can keep bouncing work back to the worker, the loop can run many times. That open-ended quality is what makes it an agent rather than a straight pipeline.

The worker/evaluator loop

There are two decision points. After the worker speaks, a router asks "did it call a tool?" — if yes, run the tools and loop back; if no, the answer is ready, so go to the evaluator. After the evaluator speaks, a second router asks "are we done?" — done means either the success criteria are met or the worker needs the user, in which case the graph ends; otherwise it loops back to the worker with the evaluator's feedback.

The evaluator's structured output

The evaluator must return a precise verdict, not prose. We define a Pydantic schema called EvaluatorOutput with three fields, and tell the evaluator model to fill exactly that shape.

New to this? Structured output in LangGraph

Instead of bind_tools, the evaluator model is wrapped with with_structured_output(EvaluatorOutput). That tells the model "your reply must match this schema", turns the schema into JSON rules behind the scenes, and parses the model's JSON back into a filled EvaluatorOutput object. If a model cannot do structured output, the fallback is the old way: ask for JSON in the prompt and parse it yourself. Here it is one line.

A meatier state

Until now the State held only messages. The Sidekick's state carries five fields, because the worker and evaluator need to pass information to each other across the loop.

FieldMeaning
messagesThe running conversation. Uses the add_messages reducer, so new messages are appended.
success_criteriaWhat "done" means for this task. Set once by the user and read by both the worker and evaluator.
feedback_on_workThe evaluator's latest feedback. When present, the worker knows a previous attempt was rejected and why.
success_criteria_metThe evaluator's verdict: is the criteria satisfied?
user_input_neededThe evaluator's other verdict: does the worker need the human?

Only messages has a reducer. The other four are plain values, so when a node returns a new value it simply overwrites the old one for everything downstream — exactly what we want for a verdict.

const State = Annotation.Root({
  messages: Annotation<BaseMessage[], Messages>({ reducer: addMessages, default: () => [] }),
});

const toolPush = tool(
  async ({ text }) => {
    await fetch("https://api.pushover.net/1/messages.json", {
      method: "POST",
      body: new URLSearchParams({
        token: process.env.PUSHOVER_TOKEN ?? "",
        user: process.env.PUSHOVER_USER ?? "",
        message: text,
      }),
    });
    return "success";
  },
  {
    name: "send_push_notification",
    description: "useful for when you want to send a push notification",
    schema: z.object({ text: z.string() }),
  },

const page = await browser.newPage();
const navigateTool = tool(async ({ url }) => `Navigating to ${url} returned status code ${(await page.goto(url))?.status()}`, {
  name: "navigate_browser",
  description: "Navigate a browser to the specified URL",
  schema: z.object({ url: z.string().describe("url to navigate to") }),
});
const extractTextTool = tool(async () => page.locator("body").innerText(), {
  name: "extract_text",
  description: "Extract all the text on the current webpage",
  schema: z.object({}),

const tools = [
  navigateTool,
  extractTextTool,
  tool(async () => JSON.stringify(await page.$$eval("a[href]", (links: Element[]) => links.map((a) => a.getAttribute("href")))), {
    name: "extract_hyperlinks",
    description: "Extract all hyperlinks on the current webpage",
    schema: z.object({}),
  }),
  tool(async () => page.url(), {
    name: "current_webpage",
    description: "Returns the URL of the current page",
    schema: z.object({}),
  }),
];

// Try two tools by hand, no LLM involved: open CNN and read its text
await navigateTool.invoke({ url: "https://www.cnn.com" });
const text: string = await extractTextTool.invoke({});
console.log(text.slice(0, 1000));

const allTools = [...tools, toolPush];

// The LLM, bound to every tool, and the chatbot node
const llm = new ChatOpenAI({ model: "gpt-6-luna", reasoning: { effort: "none" } });
const llmWithTools = llm.bindTools(allTools);

async function chatbot(state: typeof State.State) {
  return { messages: [await llmWithTools.invoke(state.messages)] };
}

// The graph: chatbot -> tools (only if the model asked for one) -> back to chatbot
const memory = new MemorySaver();
const graph = new StateGraph(State)
  .addNode("chatbot", chatbot)
  .addNode("tools", new ToolNode(allTools))
  .addConditionalEdges("chatbot", toolsCondition)
  .addEdge("tools", "chatbot")
  .addEdge(START, "chatbot")
  .compile({ checkpointer: memory });

const config = { configurable: { thread_id: "10" } };

async function chat(userInput: string): Promise<string> {
  const result = await graph.invoke({ messages: [{ role: "user", content: userInput }] }, config);
  return String(result.messages[result.messages.length - 1].content);
}

const rl = createInterface({ input, output });
for (;;) {
  const userInput = await rl.question("You (empty line to quit): ");
  if (!userInput.trim()) break;
  console.log("Bot:", await chat(userInput));
}
rl.close();
await browser.close();

# First define a structured output

class EvaluatorOutput(BaseModel):
    feedback: str = Field(description="Feedback on the assistant's response")
    success_criteria_met: bool = Field(description="Whether the success criteria have been met")
    user_input_needed: bool = Field(description="True if more input is needed from the user, or clarifications, or the assistant is stuck")

# The state

class State(TypedDict):
    messages: Annotated[List[Any], add_messages]
    success_criteria: str
    feedback_on_work: Optional[str]
    success_criteria_met: bool
    user_input_needed: bool

# Get our async Playwright tools

import nest_asyncio
nest_asyncio.apply()
async_browser =  create_async_playwright_browser(headless=False)  # headful mode
toolkit = PlayWrightBrowserToolkit.from_browser(async_browser=async_browser)
tools = toolkit.get_tools()

# Initialize the LLMs

worker_llm = ChatOpenAI(model="gpt-4o-mini")
worker_llm_with_tools = worker_llm.bind_tools(tools)

evaluator_llm = ChatOpenAI(model="gpt-4o-mini")
evaluator_llm_with_output = evaluator_llm.with_structured_output(EvaluatorOutput)

# The worker node

def worker(state: State) -> Dict[str, Any]:
    system_message = f"""You are a helpful assistant that can use tools to complete tasks.
You keep working on a task until either you have a question or clarification for the user, or the success criteria is met.
This is the success criteria:
{state['success_criteria']}
You should reply either with a question for the user about this assignment, or with your final response.
If you have a question for the user, you need to reply by clearly stating your question. An example might be:

Question: please clarify whether you want a summary or a detailed answer

If you've finished, reply with the final answer, and don't ask a question; simply reply with the answer.
"""
    
    if state.get("feedback_on_work"):
        system_message += f"""
Previously you thought you completed the assignment, but your reply was rejected because the success criteria was not met.
Here is the feedback on why this was rejected:
{state['feedback_on_work']}
With this feedback, please continue the assignment, ensuring that you meet the success criteria or have a question for the user."""
    
    # Add in the system message

    found_system_message = False
    messages = state["messages"]
    for message in messages:
        if isinstance(message, SystemMessage):
            message.content = system_message

export function workerRouter(state: StateT): "tools" | "evaluator" {

  if (lastMessage instanceof AIMessage && lastMessage.tool_calls?.length) {
    return "tools";
  }
  return "evaluator";
}

// The conversation as plain "User: ... / Assistant: ..." text for the evaluator
export function formatConversation(messages: BaseMessage[]): string {
  let conversation = "Conversation history:\n\n";
  for (const message of messages) {
    if (message instanceof HumanMessage) {
      conversation += `User: ${message.content}\n`;
    } else if (message instanceof AIMessage) {
      conversation += `Assistant: ${message.content || "[Tools use]"}\n`;
    }
  }
  return conversation;
}

export async function evaluator(state: StateT) {
  const lastResponse = state.messages[state.messages.length - 1].content;

  const systemMessage = `You are an evaluator that determines if a task has been completed successfully by an Assistant.
Assess the Assistant's last response based on the given criteria. Respond with your feedback, and with your decision on whether the success criteria has been met,
and whether more input is needed from the user.`;

  let userMessage = `You are evaluating a conversation between the User and Assistant. You decide what action to take based on the last response from the Assistant.

The entire conversation with the assistant, with the user's original request and all replies, is:
${formatConversation(state.messages)}

The success criteria for this assignment is:
${state.success_criteria}

And the final response from the Assistant that you are evaluating is:
${lastResponse}

Respond with your feedback, and decide if the success criteria is met by this response.
Also, decide if more user input is required, either because the assistant has a question, needs clarification, or seems to be stuck and unable to answer without help.
`;
  if (state.feedback_on_work) {
    userMessage += `Also, note that in a prior attempt from the Assistant, you provided this feedback: ${state.feedback_on_work}\n`;
    userMessage += "If you're seeing the Assistant repeating the same mistakes, then consider responding that user input is required.";
  }

  const evalResult = await evaluatorLlmWithOutput.invoke([new SystemMessage(systemMessage), new HumanMessage(userMessage)]);
  return {
    messages: [{ role: "assistant", content: `Evaluator Feedback on this answer: ${evalResult.feedback}` }],
    feedback_on_work: evalResult.feedback,
    success_criteria_met: evalResult.success_criteria_met,
    user_input_needed: evalResult.user_input_needed,
  };
}

// After the evaluator: finish, or back to the worker?
export function routeBasedOnEvaluation(state: StateT): "END" | "worker" {
  return state.success_criteria_met || state.user_input_needed ? "END" : "worker";
}

// Set up the graph: three nodes, two conditional edges, memory
export function buildGraph(worker: (state: StateT) => Promise<{ messages: BaseMessage[] }>, tools: StructuredToolInterface[]) {
  return new StateGraph(State)
    .addNode("worker", worker)
    .addNode("tools", new ToolNode(tools))
    .addNode("evaluator", evaluator)
    .addConditionalEdges("worker", workerRouter, { tools: "tools", evaluator: "evaluator" })
    .addEdge("tools", "worker")
    .addConditionalEdges("evaluator", routeBasedOnEvaluation, { worker: "worker", END: END })
    .addEdge(START, "worker")
    .compile({ checkpointer: new MemorySaver() });
}

  feedback_on_work: Annotation<string | null>(),
  success_criteria_met: Annotation<boolean>(),
  user_input_needed: Annotation<boolean>(),
});
type StateT = typeof State.State;

// Our browser tools (the Python lab uses LangChain's PlayWrightBrowserToolkit)
const browser = await chromium.launch({ headless: false });
const page = await browser.newPage();
const tools = [
  tool(async ({ url }) => `Navigating to ${url} returned status code ${(await page.goto(url))?.status()}`, {
    name: "navigate_browser",
    description: "Navigate a browser to the specified URL",
    schema: z.object({ url: z.string().describe("url to navigate to") }),
  }),
  tool(async () => page.locator("body").innerText(), {
    name: "extract_text",
    description: "Extract all the text on the current webpage",
    schema: z.object({}),
  }),
];

// Initialize the LLMs: the worker gets tools, the evaluator gets the output schema
const workerLlm = new ChatOpenAI({ model: "gpt-6-luna", reasoning: { effort: "none" } });
const workerLlmWithTools = workerLlm.bindTools(tools);
const evaluatorLlm = new ChatOpenAI({ model: "gpt-6-luna", reasoning: { effort: "none" } });
const evaluatorLlmWithOutput = evaluatorLlm.withStructuredOutput(EvaluatorOutput);

// The worker node
async function worker(state: StateT) {
  let systemMessage = `You are a helpful assistant that can use tools to complete tasks.
You keep working on a task until either you have a question or clarification for the user, or the success criteria is met.
This is the success criteria:
${state.success_criteria}
You should reply either with a question for the user about this assignment, or with your final response.
If you have a question for the user, you need to reply by clearly stating your question. An example might be:

Question: please clarify whether you want a summary or a detailed answer

If you've finished, reply with the final answer, and don't ask a question; simply reply with the answer.
`;
  if (state.feedback_on_work) {
    systemMessage += `
Previously you thought you completed the assignment, but your reply was rejected because the success criteria was not met.
Here is the feedback on why this was rejected:
${state.feedback_on_work}
With this feedback, please continue the assignment, ensuring that you meet the success criteria or have a question for the user.`;
  }

  // Add in the system message: replace an old one, or put a new one first
  let messages = state.messages;
  let foundSystemMessage = false;
  for (const message of messages) {
    if (message instanceof SystemMessage) {
      message.content = systemMessage;
      foundSystemMessage = true;
    }
  }
  if (!foundSystemMessage) {
    messages = [new SystemMessage(systemMessage), ...messages];
  }

  // Invoke the LLM with tools, return the update
  const response = await workerLlmWithTools.invoke(messages);
  return { messages: [response] };
}

// After the worker: did it ask for a tool?
function workerRouter(state: StateT): "tools" | "evaluator" {
  const lastMessage = state.messages[state.messages.length - 1];
  if (lastMessage instanceof AIMessage && lastMessage.tool_calls?.length) {
    return "tools";
  }
  return "evaluator";
}

// The conversation as plain "User: ... / Assistant: ..." text for the evaluator
function formatConversation(messages: BaseMessage[]): string {
  let conversation = "Conversation history:\n\n";
  for (const message of messages) {
    if (message instanceof HumanMessage) {
      conversation += `User: ${message.content}\n`;
    } else if (message instanceof AIMessage) {
      conversation += `Assistant: ${message.content || "[Tools use]"}\n`;
    }
  }
  return conversation;
}

async function evaluator(state: StateT) {
  const lastResponse = state.messages[state.messages.length - 1].content;

  const systemMessage = `You are an evaluator that determines if a task has been completed successfully by an Assistant.
Assess the Assistant's last response based on the given criteria. Respond with your feedback, and with your decision on whether the success criteria has been met,
and whether more input is needed from the user.`;

  let userMessage = `You are evaluating a conversation between the User and Assistant. You decide what action to take based on the last response from the Assistant.

The entire conversation with the assistant, with the user's original request and all replies, is:
${formatConversation(state.messages)}

The success criteria for this assignment is:
${state.success_criteria}

And the final response from the Assistant that you are evaluating is:
${lastResponse}

Respond with your feedback, and decide if the success criteria is met by this response.
Also, decide if more user input is required, either because the assistant has a question, needs clarification, or seems to be stuck and unable to answer without help.
`;
  if (state.feedback_on_work) {
    userMessage += `Also, note that in a prior attempt from the Assistant, you provided this feedback: ${state.feedback_on_work}\n`;
    userMessage += "If you're seeing the Assistant repeating the same mistakes, then consider responding that user input is required.";
  }

  const evalResult = await evaluatorLlmWithOutput.invoke([new SystemMessage(systemMessage), new HumanMessage(userMessage)]);
  return {
    messages: [{ role: "assistant", content: `Evaluator Feedback on this answer: ${evalResult.feedback}` }],
    feedback_on_work: evalResult.feedback,
    success_criteria_met: evalResult.success_criteria_met,
    user_input_needed: evalResult.user_input_needed,
  };
}

// After the evaluator: finish, or back to the worker?
function routeBasedOnEvaluation(state: StateT): "END" | "worker" {
  return state.success_criteria_met || state.user_input_needed ? "END" : "worker";
}

// Set up the graph: three nodes, two conditional edges, memory
const graph = new StateGraph(State)
  .addNode("worker", worker)
  .addNode("tools", new ToolNode(tools))
  .addNode("evaluator", evaluator)
  .addConditionalEdges("worker", workerRouter, { tools: "tools", evaluator: "evaluator" })
  .addEdge("tools", "worker")
  .addConditionalEdges("evaluator", routeBasedOnEvaluation, { worker: "worker", END: END })
  .addEdge(START, "worker")
  .compile({ checkpointer: new MemorySaver() });
console.log((await graph.getGraphAsync()).drawMermaid());

// The callback that kicks off a super-step (Gradio's process_message)
const makeThreadId = () => randomUUID();

async function processMessage(message: string, successCriteria: string, thread: string) {
  const config = { configurable: { thread_id: thread } };
  const state = {
    messages: [{ role: "user", content: message }],
    success_criteria: successCriteria,
    feedback_on_work: null,
    success_criteria_met: false,
    user_input_needed: false,
  };
  const result = await graph.invoke(state, config);
  const reply = result.messages[result.messages.length - 2].content;
  const feedback = result.messages[result.messages.length - 1].content;
  return { reply, feedback };
}

// A terminal "UI": a request, then success criteria; type "reset" for a fresh thread
let thread = makeThreadId();
const rl = createInterface({ input, output });
for (;;) {
  const message = await rl.question("\nYour request to your sidekick (empty line to quit): ");
  if (!message.trim()) break;
  if (message.trim() === "reset") {
    thread = makeThreadId();
    continue;
  }
  const successCriteria = await rl.question("What are your success criteria? ");
  const { reply, feedback } = await processMessage(message, successCriteria, thread);
  console.log(`\nSidekick: ${reply}\n${feedback}`);
}
rl.close();
await browser.close();

Common mistakes.
  • Skipping the browser install. The Playwright tools need Chromium: run playwright install once (Linux: playwright install --with-deps chromium).
  • Forgetting nest_asyncio in the notebook. Async Playwright inside Jupyter's own event loop fails without nest_asyncio.apply().
  • Giving every field a reducer. Only messages should append. The verdict fields must overwrite, or old verdicts would pile up.
  • Loose success criteria. A vague criterion makes the evaluator loop forever. Be specific about what "done" means.
  • An evaluator stuck in a loop. In testing it kept rejecting the same mistake; the extra line "if the assistant repeats the same mistakes, consider responding that user input is required" lets it hand back to the user.
  • The video's Gradio code on Gradio 6. type="messages" no longer exists and theme= moved to launch(); see the Runs today tabs.
  • Dropping the tools→worker edge. As before, tool results must return to the worker, or the loop breaks.
Recap
  • The Sidekick is a worker/evaluator loop: the worker does the task (using tools), the evaluator judges the answer against the success criteria.
  • The evaluator returns a structured output (EvaluatorOutput) with feedback, success_criteria_met and user_input_needed.
  • Two conditional edges route the graph: worker→tools or worker→evaluator, and evaluator→END or evaluator→worker.
  • The state carries five fields; only messages has a reducer, so verdicts overwrite cleanly.
  • Playwright's browser tools (navigate, extract text, click, …) let an agent browse on its own; in a notebook, async code needs nest_asyncio and await graph.ainvoke.
  • The Gradio UI gives each session its own random thread_id, so conversations stay separate.
  • Because the loop can repeat, this is a genuine agent, not a fixed workflow.
