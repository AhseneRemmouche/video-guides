Week 1 · Project Build — The Career Agent, Step by Step

Build the career "digital twin" agent from an empty folder in two stacks: Python with uv (Gradio), and a React + Node + TypeScript chat app with a Hono API.

Build it yourself · Python + uv and React + Node + TypeScript

This is the Week 1 project: a career digital twin — a chatbot that answers as you. It reads a short profile (your summary plus a LinkedIn PDF), replies in your voice to questions about your career and skills, and uses two tools to look after the things a plain chatbot cannot: when a visitor leaves an email it records their details, and when it is asked something it cannot answer it records that question. Each of those tool calls fires a push notification to your phone. That is the whole Week 1 agent.

We build the same agent twice, in two stacks:

  • Track A — Python + uv: the original course build, with a Gradio chat window, deployed to Hugging Face Spaces.
  • Track B — React + Node + TypeScript: the same logic ported to the JavaScript world, with a React chat page talking to a small Hono API.

Both stacks share the same core idea: build a list of messages, send it to an LLM together with a description of the available tools, and run a loop — if the model asks to call a tool, run it and feed the result back; otherwise return the reply. That loop is what turns a one-shot chat completion into something that can take actions.

Build it step by step

Run it locally (Python + uv)

A runnable version of this whole week lives in week1-py/. It runs with no paid keys by pointing the OpenAI SDK at a local Ollama server, so you can watch the exact code run end to end:

# 1. Install Ollama from https://ollama.com, then pull the models it uses
ollama pull llama3.2
ollama pull dolphin3:8b      # only day3 needs this second model

# 2. Install dependencies and run (UV_NATIVE_TLS=1 avoids corporate TLS errors)
cd week1-py
UV_NATIVE_TLS=1 uv sync

# 3. Run any script (one at a time - they share the single Ollama queue)
uv run python src/career_agent.py          # the career "digital twin" + tool-call loop
uv run python src/day1_workflow.py         # plan -> act 2-step workflow
uv run python src/day2_patterns.py         # chaining + routing patterns
uv run python src/day3_multi_llm.py        # llama3.2 vs dolphin3:8b, judged by llama3.2
uv run python src/day4_tools_structured.py # structured output + a tool

All five scripts run locally against Ollama with no paid keys; small local models call tools less reliably than the frontier models, so the course itself uses paid frontier models (OpenAI and others) and a real Pushover account, and the local pushover() here is a print-only stub.

New to the tool-call loop? What it is and why it matters

A normal chat call sends messages and gets back one text reply. Function calling adds a second kind of reply: instead of text, the model can say "please run tool X with these arguments". Your code runs the real function, appends the result as a new message, and calls the model again. You keep looping until the model stops asking for tools and returns normal text. That loop is the difference between a chatbot and an agent that can take actions.

Track A - Python + uv (Gradio)

  1. Scaffold the project. Either start fresh with uv init career-agent, or clone the course repo and open its 1_foundations folder. uv creates the project and manages a local .venv for you.
  2. Add the dependencies: uv add openai python-dotenv gradio pypdf requests. openai is the chat client, python-dotenv loads your keys, gradio gives the chat window, pypdf reads your LinkedIn PDF, and requests sends the Pushover push.
  3. Create a .env file with your keys (never commit it): 
    OPENAI_API_KEY=sk-...
PUSHOVER_TOKEN=your-pushover-app-token
PUSHOVER_USER=your-pushover-user-key
    At the top of the script, load_dotenv(override=True) reads this file into the environment.
  4. Build the system prompt from your profile. Read me/summary.txt and extract the text of me/linkedin.pdf with PdfReader, then write a system prompt that tells the model to act as you, answer from that background, and use the two tools when needed. This is what makes it your digital twin.
  5. Write the chat(message, history) function. It prepends the system prompt, appends the running history and the new user message, then calls openai.chat.completions.create(model="gpt-4o-mini", messages=messages, tools=tools).
  6. Add the two tools and the tool-call loop. Define record_user_details(email, name, notes) and record_unknown_question(question), describe each as a JSON schema in the tools list, and wrap the chat call in while not done: — when finish_reason == "tool_calls", run the requested tools, append their results, and loop; otherwise return the reply.
  7. Add the push() alert. A small function POSTs the message to https://api.pushover.net/1/messages.json with your token and user key, so each recorded lead or unknown question pings your phone.
  8. Wrap it in a UI: gr.ChatInterface(chat, type="messages").launch() opens a local chat window in your browser — no front-end code to write.
  9. Deploy to Hugging Face Spaces. Push the app and the me/ folder to a Gradio Space and set the same keys as Space secrets, so your twin is live on a public URL.

The full, verified code for the chat function, the tools and the loop is embedded line by line on the Day 4 and Day 5 pages — build those first, this page is the map that joins them into one project.

Track B - React + Node + TypeScript

Track B is the real week1-ts/ project. The same chat-plus-tools logic moves to the official openai JavaScript SDK, but now a browser cannot hold the API key, so the agent runs on a tiny server and the React page talks to it over HTTP.

  1. Scaffold a React + TypeScript app with Vite, then turn the folder into an npm project: 
    npm create vite@latest week1-ts -- --template react-ts
cd week1-ts
npm init -y
  2. Add the runtime dependencies with npm: npm add openai hono @hono/node-server dotenv. openai is the same SDK as Python, hono + @hono/node-server are the small web server, and dotenv loads your key.
  3. Add the dev tool that runs TypeScript directly: npm add -D tsx. tsx lets you run a .ts file without a separate compile step, which is how every script below starts.
  4. Create src/career.ts — the brain. It exports an async chat(message, history) that builds the [system, ...history, user] messages, defines the two tools (record_user_details, record_unknown_question) with their JSON schemas, and runs the same while (true) tool-call loop until the model returns text. It also has a guarded push() that only hits Pushover when both keys are set.
  5. Create server/index.ts — a Hono app with one route, POST /api/career. It validates the body with zod, calls chat(message, history) from career.ts, and returns { reply }. With no OPENAI_API_KEY set it returns a clear 400 instead of crashing, and it also serves the built React app.
  6. Build the React chat in web/src/App.tsx. A small component keeps the message list in useState, fetches POST /api/career with the text and the running history, and renders each reply as markdown with marked.
  7. Wire up the scripts. The real package.json already defines them: 
    "scripts": {
  "day1": "tsx src/day1.ts",
  "day2": "tsx src/day2.ts",
  "day3": "tsx src/day3.ts",
  "day4": "tsx src/day4.ts",
  "career": "tsx src/career.ts",
  "api": "tsx server/index.ts",
  "web": "vite --config web/vite.config.ts",
  "typecheck": "tsc --noEmit -p tsconfig.json",
  "build": "tsc --noEmit -p tsconfig.json && vite build --config web/vite.config.ts"
}
  8. Run it in two terminals. Start the API with npm run api (Hono on port 8788), and the dev front end with npm run web (Vite on 5173, which proxies /api to the API). Open the Vite URL and chat.
New to Hono? What it is and why it matters

Hono is a very small, fast web framework for JavaScript servers. Here it does one job: expose a single POST /api/career endpoint that the React page can call. Keeping the OpenAI call on the server means your secret key never ships to the browser — the browser only ever sees the message it sent and the reply it got back.
