Week 1 · Project Build — The Career Agent, Step by Step

Build the career "digital twin" agent from an empty folder in two stacks, one tab each: Python with uv (Gradio), or a React + Node + TypeScript chat app with a Hono API. Every step shows its full code and why you do it.

Build it yourself · Python + uv and React + Node + TypeScript

This is the Week 1 project: a career digital twin — a chatbot that answers as you. It reads a short profile (your summary plus a LinkedIn PDF), replies in your voice to questions about your career and skills, and uses two tools to look after the things a plain chatbot cannot: when a visitor leaves an email it records their details, and when it is asked something it cannot answer it records that question. Each of those tool calls fires a push notification to your phone. That is the whole Week 1 agent.

You can build it in either of two stacks. Choose one with the tabs in Build it step by step; each tab is complete on its own:

  • Python + uv: the course's own app, with a Gradio chat window, deployed to Hugging Face Spaces.
  • React + Node + TypeScript: the same agent in the JavaScript world, with a React chat page and a small Hono API server.

Both stacks share the same core idea: build a list of messages, send it to an LLM together with a description of the available tools, and run a loop — if the model asks to call a tool, run it and feed the result back; otherwise return the reply. That loop is what turns a one-shot chat completion into something that can take actions.

Build it step by step

New to the tool-call loop? What it is and why it matters

A normal chat call sends messages and gets back one text reply. Function calling adds a second kind of reply: instead of text, the model can say "please run tool X with these arguments". Your code runs the real function, appends the result as a new message, and calls the model again. You keep looping until the model stops asking for tools and returns normal text. That loop is the difference between a chatbot and an agent that can take actions.

    def record_user_details(email, name="Name not provided", notes="not provided"):

  15. Add handle_tool_call(): run what the model asks for. 
        def handle_tool_call(self, tool_calls):
        results = []
        for tool_call in tool_calls:
            tool_name = tool_call.function.name
            arguments = json.loads(tool_call.function.arguments)
            print(f"Tool called: {tool_name}", flush=True)
            tool = globals().get(tool_name)
            result = tool(**arguments) if tool else {}
            results.append({"role": "tool","content": json.dumps(result),"tool_call_id": tool_call.id})
        return results

    When the model wants tools, it sends back their names and the arguments as a JSON string. This method turns the string into a dictionary with json.loads, finds the Python function with the same name using globals().get(tool_name) (so you never need an if per tool), runs it, and wraps the result in a "tool" message. The tool_call_id is required: it tells the model which of its requests this result answers.

    The system prompt sets the rules for the whole conversation: speak as this person, stay professional, use record_unknown_question when you do not know, and steer interested visitors towards leaving an email.   17. Add chat(): the agent loop. 
        def chat(self, message, history):
        messages = [{"role": "system", "content": self.system_prompt()}] + history + [{"role": "user", "content": message}]
        done = False
        while not done:
            response = self.openai.chat.completions.create(model="gpt-4o-mini", messages=messages, tools=tools)
            if response.choices[0].finish_reason=="tool_calls":
                message = response.choices[0].message
                tool_calls = message.tool_calls
                results = self.handle_tool_call(tool_calls)
                messages.append(message)
                messages.extend(results)
            else:
                done = True
        return response.choices[0].message.content

    This loop is what turns a chatbot into an agent. Each call sends the system prompt, the earlier conversation and the new message, plus the list of tools. If the model's answer ends with finish_reason == "tool_calls", the code runs the tools, adds both the model's request and the tool results to messages, and asks again. Only when the model replies with plain text does the loop stop and return that text to the chat window.

    async function handleToolCalls(
  toolCalls: OpenAI.Chat.Completions.ChatCompletionMessageToolCall[],
): Promise<OpenAI.Chat.Completions.ChatCompletionToolMessageParam[]> {
  const results: OpenAI.Chat.Completions.ChatCompletionToolMessageParam[] = [];
  for (const toolCall of toolCalls) {
    if (toolCall.type !== "function") continue;
    const toolName = toolCall.function.name;
    const args = JSON.parse(toolCall.function.arguments || "{}");
    console.log(`Tool called: ${toolName}`);
    const fn = toolFunctions[toolName];
    const result = fn ? await fn(args) : {};
    results.push({ role: "tool", content: JSON.stringify(result), tool_call_id: toolCall.id });
  }
  return results;
}

    For each request it parses the JSON arguments, runs the matching function and returns a "tool" message carrying the same tool_call_id. The id is required: it tells the model which of its requests each result answers.

  18. Add chat(): the agent loop. 
    // The chat function. `history` is the prior turns (user/assistant messages);
// we prepend the system prompt and append the new user message, then run the
// tool-call loop until the model produces a normal text reply.
export async function chat(message: string, history: ChatMessage[] = []): Promise<string> {
  const openai = getClient();
  if (!openai) throw new Error("OPENAI_API_KEY is not set");

  const messages: ChatMessage[] = [
    { role: "system", content: SYSTEM_PROMPT },
    ...history,
    { role: "user", content: message },
  ];

  // eslint-disable-next-line no-constant-condition
  while (true) {
    const response = await openai.chat.completions.create({ model: MODEL, messages, tools });
    const choice = response.choices[0];
    if (choice?.finish_reason === "tool_calls" && choice.message.tool_calls) {
      const results = await handleToolCalls(choice.message.tool_calls);
      messages.push(choice.message);
      messages.push(...results);
    } else {
      return choice?.message.content ?? "";
    }
  }
}

    This loop is what makes it an agent. Each turn sends the system prompt, the earlier conversation and the new message, plus the tools. If the model answers with "tool_calls", the code runs them, appends the request and the results, and asks again; when the model replies with text, the function returns it. It is exported so the server can call it.

  const results: OpenAI.Chat.Completions.ChatCompletionToolMessageParam[] = [];
  for (const toolCall of toolCalls) {
    if (toolCall.type !== "function") continue;
    const toolName = toolCall.function.name;
    const args = JSON.parse(toolCall.function.arguments || "{}");
    console.log(`Tool called: ${toolName}`);
    const fn = toolFunctions[toolName];
    const result = fn ? await fn(args) : {};
    results.push({ role: "tool", content: JSON.stringify(result), tool_call_id: toolCall.id });
  }
  return results;
}

// The chat function. `history` is the prior turns (user/assistant messages);
// we prepend the system prompt and append the new user message, then run the
// tool-call loop until the model produces a normal text reply.
export async function chat(message: string, history: ChatMessage[] = []): Promise<string> {
  const openai = getClient();
  if (!openai) throw new Error("OPENAI_API_KEY is not set");

  const messages: ChatMessage[] = [
    { role: "system", content: SYSTEM_PROMPT },
    ...history,
    { role: "user", content: message },
  ];

  // eslint-disable-next-line no-constant-condition
  while (true) {
    const response = await openai.chat.completions.create({ model: MODEL, messages, tools });
    const choice = response.choices[0];
    if (choice?.finish_reason === "tool_calls" && choice.message.tool_calls) {
      const results = await handleToolCalls(choice.message.tool_calls);
      messages.push(choice.message);
      messages.push(...results);
    } else {
      return choice?.message.content ?? "";
    }
  }
}

    // The API behind the React career-chat page.
//   POST /api/career {message, history} -> {reply}
// `history` is the prior turns in OpenAI message format. With no OPENAI_API_KEY
// set, the route returns a clear 400 JSON error instead of crashing.
import "dotenv/config";
import { Hono } from "hono";
import { serve } from "@hono/node-server";
import { serveStatic } from "@hono/node-server/serve-static";
import { z } from "zod";
import { chat, type ChatMessage } from "../src/career.js";

// Only the two conversational roles are accepted from the client; the server
// adds the system prompt itself inside career.chat().
const messageSchema = z.object({
  role: z.enum(["user", "assistant"]),
  content: z.string(),
});

const careerBody = z.object({
  message: z.string().min(1),
  history: z.array(messageSchema).optional(),
});

const app = new Hono();

app.post("/api/career", async (c) => {
  if (!process.env.OPENAI_API_KEY) {
    return c.json({ error: "OPENAI_API_KEY is not set on the server" }, 400);
  }

  const parsed = careerBody.safeParse(await c.req.json().catch(() => ({})));
  if (!parsed.success) {
    return c.json({ error: "Body must be { message: string, history?: {role, content}[] }" }, 400);
  }

  try {
    const history = (parsed.data.history ?? []) as ChatMessage[];
    const reply = await chat(parsed.data.message, history);
    return c.json({ reply });
  } catch (err) {
    return c.json({ error: String(err) }, 500);
  }
});

serve({ fetch: app.fetch, port });

  27. Build the chat UI: web/src/App.tsx. 
    // Week 1 capstone UI: chat with the "digital twin" career agent.
// Each message is sent to /api/career along with the running history; the
// reply is rendered as markdown with `marked`.
import { useState } from "react";
import { marked } from "marked";

interface Message {
  role: "user" | "assistant";
  content: string;
}

export function App() {
  const [messages, setMessages] = useState<Message[]>([]);
  const [input, setInput] = useState("");
  const [busy, setBusy] = useState(false);
  const [error, setError] = useState("");

  async function send() {
    const text = input.trim();
    if (!text || busy) return;

    const history = messages;
    const nextMessages: Message[] = [...messages, { role: "user", content: text }];
    setMessages(nextMessages);
    setInput("");
    setBusy(true);
    setError("");

    try {
      const res = await fetch("/api/career", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ message: text, history }),
      });
      const data = await res.json();
      if (!res.ok) {
        setError(data.error ?? "Request failed");
      } else {
        setMessages([...nextMessages, { role: "assistant", content: data.reply ?? "" }]);
      }
    } catch (e) {
      setError(String(e));
    } finally {
      setBusy(false);
    }
  }

  function onKeyDown(e: React.KeyboardEvent<HTMLInputElement>) {
    if (e.key === "Enter") send();
  }

  return (
    <main className="wrap">
      <h1>Career Chat</h1>
      <p className="sub">
        Ask the digital twin about its career, background, skills and experience. Built on plain
        LLM calls + tools - Week 1 of the Agentic AI course, in TypeScript.
      </p>

      <div className="chat">
        {messages.length === 0 && !busy && (
          <div className="empty">Try: "What did you do before Nebula.io?"</div>
        )}
        {messages.map((m, i) => (
          <div key={i} className={`msg ${m.role}`}>
            {m.role === "assistant" ? (
              <div
                className="bubble"
                dangerouslySetInnerHTML={{ __html: marked.parse(m.content) as string }}
              />
            ) : (
              <div className="bubble">{m.content}</div>
            )}
          </div>
        ))}
        {busy && <div className="msg assistant"><div className="bubble muted">Thinking...</div></div>}
      </div>

      {error && <div className="error">{error}</div>}

      <div className="row">
        <input
          value={input}
          onChange={(e) => setInput(e.target.value)}
          onKeyDown={onKeyDown}
          placeholder="Ask a question..."
          disabled={busy}
        />
        <button onClick={send} disabled={busy || !input.trim()}>
          Send
        </button>
      </div>
    </main>
  );
}
    • Lines 13–16, state. The message list, the input text, a busy flag and an error. Why: when any of these change, React redraws the page for you.
    • Lines 18–46, send(). Shows your message straight away, posts { message, history } to /api/career, then adds the reply (or shows the error). Why: history is the conversation before this message, because the server adds the new message itself, exactly like the Python chat(message, history).
    • Lines 48–50, Enter to send. Why: the behaviour people expect from a chat box.
    • Lines 52–94, the markup. Assistant replies go through marked so lists and bold text from the model display properly; your own messages are shown as plain text. Why: the model answers in markdown, and your own text never needs to be interpreted as HTML.

    This is the part people actually use. Keeping the conversation in React state and sending the earlier turns with each message gives the agent its memory, while the server stays stateless and simple.
