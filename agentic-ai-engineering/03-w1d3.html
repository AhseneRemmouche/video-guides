Week 1 · Day 3 — Orchestrating Multiple LLMs

Call OpenAI, Claude, Gemini and DeepSeek through one OpenAI-style client, then build a little system that asks several models the same question and has a model judge the answers.

Day 3 is the first really code-heavy day. We take the second lab in the 1_foundations folder and use it to meet a whole cast of language models: OpenAI's GPT, Anthropic's Claude, Google's Gemini, DeepSeek, a Llama model served by Groq, and a small model running on your own machine through Ollama. We ask them all the same hard question, collect every answer, and then hand the answers to one more model and ask it to be a judge and rank them. This is our first taste of using several LLMs together.

The surprise of the day is how little code it takes. Almost every provider copied OpenAI's web format, so one client library talks to all of them. You only change two things: the web address it calls and the key it sends. The instructor runs the lab cell by cell in Cursor, explaining each piece rather than typing it live, and that is exactly how we will read it here.

This is a lab, not a project. The code lives in a notebook (2_lab2.py is the exported version). The goal is to feel how the APIs work and to try a little orchestration between models, not to build an app yet. That comes later in the week.

What this lab does

There are two ideas to take away. First, the OpenAI client library is not magic and is not a model. It is a thin piece of code that packages your request as an HTTP call to an endpoint of a particular shape. Second, almost every provider decided to offer an OpenAI-compatible endpoint, so you can point that same library at them by passing a different base_url and API key.

New to this? What the "OpenAI client library" actually is

When you write from openai import OpenAI and call openai.chat.completions.create(...), you are using a small helper library. It takes your model name and your list of messages, turns them into a web request (an HTTP POST with a JSON body), sends it to a server, waits for the reply, and hands the text back to you. It does not "think". The thinking happens on the provider's servers. Because it is just making web requests, it can call any server that speaks the same request-and-reply format.

New to this? What an "OpenAI-compatible endpoint" means

An endpoint is a web address that accepts requests. OpenAI's chat endpoint expects a request in a specific shape: a model name, and a list of messages where each message has a role and content. It replies with a predictable shape too. That shape became so popular that other providers built endpoints that accept exactly the same shape. These are called "OpenAI-compatible". Google, DeepSeek, Groq and Ollama all offer one. You will notice that Google's and Groq's addresses even end in the word openai, which is their way of saying "send OpenAI-style requests here".

New to this? Meet the six providers
  • OpenAI — the makers of GPT. The lab uses gpt-4o-mini, a small, cheap, fast model.
  • Anthropic Claude — OpenAI's main rival. The lab uses claude-3-7-sonnet-latest. Anthropic is the one provider here that needs its own library.
  • Google Gemini — Google's model. The lab uses gemini-2.0-flash, which has a free usage tier.
  • DeepSeek — a Chinese model known for strong results at low training cost. The lab uses deepseek-chat, the full 671-billion-parameter model served by DeepSeek.
  • Groq (with a q) — not a model but a company with very fast hardware that serves open models. The lab runs llama-3.3-70b-versatile on it.
  • Ollama — software that runs small open models on your own computer and exposes a local OpenAI-compatible endpoint. The lab uses llama3.2.

Set up your keys

The lab reads one key per provider from your .env file. You do not need all of them. Any provider whose key is missing is simply skipped, so you can run the whole thing with just an OpenAI key, or even with only Ollama and spend nothing.

  1. Open the 1_foundations folder and then 2_lab2.ipynb (the notebook; 2_lab2.py is the same cells exported as a script).
  2. Make sure your .env file holds the keys you have: OPENAI_API_KEY, and optionally ANTHROPIC_API_KEY, GOOGLE_API_KEY, DEEPSEEK_API_KEY, GROQ_API_KEY.
  3. For the local model, install Ollama from https://ollama.com, then run ollama pull llama3.2 once to download it. Check it is running by visiting http://localhost:11434 — you should see "Ollama is running".
  4. Run the cells from top to bottom. Run the import cell first or you will get name errors.
Do not pull llama3.3 for local use. It is a 70-billion-parameter model and will swamp a normal computer. That big Llama is the one we reach through Groq's fast hardware, not locally. For Ollama stick to llama3.2 (about 3 billion) or the even smaller llama3.2:1b.

// Day 2 (Lab 2) - many LLMs through ONE client, then an LLM judge.
// TS port of 2_lab2.py. The trick: every provider below copied OpenAI's HTTP
// shape, so the same `openai` client library talks to all of them - you only
// change `baseURL` + `apiKey`. We ask them all the same question, then have a
// final model rank the answers (an "LLM as judge" pattern).
import "dotenv/config";
import OpenAI from "openai";

if (!process.env.OPENAI_API_KEY) {
  console.log("OPENAI_API_KEY not set - add it to your .env (see .env.example).");
  process.exit(0);
}

const openai = new OpenAI();

// One competitor = a label plus a ready-to-call client and its model id.
interface Competitor {
  name: string;
  client: OpenAI;
  model: string;
}

async function ask(client: OpenAI, model: string, content: string): Promise<string> {
  const response = await client.chat.completions.create({
    model,
    messages: [{ role: "user", content }],
  });
  return response.choices[0]?.message.content ?? "";
}

async function main() {
  // 1) Have OpenAI invent a nuanced question we can pose to everyone.
  const request =
    "Please come up with a challenging, nuanced question that I can ask a number " +
    "of LLMs to evaluate their intelligence. Answer only with the question, no explanation.";
  const question = await ask(openai, "gpt-4o-mini", request);
  console.log("Question:\n", question, "\n");

  // 2) Assemble the field of competitors. Each is the SAME client class, only
  //    pointed at a different OpenAI-compatible endpoint. Any whose key is
  //    missing is simply skipped, so this runs with whatever you have.
  const competitors: Competitor[] = [{ name: "gpt-4o-mini", client: openai, model: "gpt-4o-mini" }];

  if (process.env.ANTHROPIC_API_KEY) {
    competitors.push({
      name: "claude-3-7-sonnet-latest",
      client: new OpenAI({
        apiKey: process.env.ANTHROPIC_API_KEY,
        baseURL: "https://api.anthropic.com/v1/",
      }),
      model: "claude-3-7-sonnet-latest",
    });
  }
  if (process.env.GOOGLE_API_KEY) {
    competitors.push({
      name: "gemini-2.0-flash",
      client: new OpenAI({
        apiKey: process.env.GOOGLE_API_KEY,
        baseURL: "https://generativelanguage.googleapis.com/v1beta/openai/",
      }),
      model: "gemini-2.0-flash",
    });
  }
  if (process.env.DEEPSEEK_API_KEY) {
    competitors.push({
      name: "deepseek-chat",
      client: new OpenAI({
        apiKey: process.env.DEEPSEEK_API_KEY,
        baseURL: "https://api.deepseek.com/v1",
      }),
      model: "deepseek-chat",
    });
  }
  if (process.env.GROQ_API_KEY) {
    competitors.push({
      name: "llama-3.3-70b-versatile",
      client: new OpenAI({
        apiKey: process.env.GROQ_API_KEY,
        baseURL: "https://api.groq.com/openai/v1",
      }),
      model: "llama-3.3-70b-versatile",
    });
  }

  // 3) Collect each competitor's answer to the one question.
  const names: string[] = [];
  const answers: string[] = [];
  for (const c of competitors) {
    const answer = await ask(c.client, c.model, question);
    names.push(c.name);
    answers.push(answer);
    console.log(`Competitor: ${c.name}\n\n${answer}\n`);
  }

  // 4) Bundle the answers and ask a judge model to rank them. We request pure
  //    JSON so the result is machine-readable.
  let together = "";
  answers.forEach((answer, index) => {
    together += `# Response from competitor ${index + 1}\n\n${answer}\n\n`;
  });

  const judgePrompt =
    `You are judging a competition between ${names.length} competitors.\n` +
    `Each model has been given this question:\n\n${question}\n\n` +
    "Your job is to evaluate each response for clarity and strength of argument, " +
    "and rank them in order of best to worst.\n" +
    'Respond with JSON, and only JSON, with the following format:\n' +
    '{"results": ["best competitor number", "second best competitor number", ...]}\n\n' +
    `Here are the responses from each competitor:\n\n${together}\n` +
    "Now respond with the JSON with the ranked order of the competitors, nothing else. " +
    "Do not include markdown formatting or code blocks.";

  const results = await ask(openai, "o3-mini", judgePrompt);
  console.log("Judge raw result:\n", results, "\n");

  // 5) Turn the ranked competitor numbers back into names.
  const ranks = (JSON.parse(results) as { results: string[] }).results;
  ranks.forEach((result, index) => {
    console.log(`Rank ${index + 1}: ${names[Number(result) - 1]}`);
  });
}

main().catch((err) => {
  console.error(err);
  process.exit(1);
});

How the orchestration flows

New to this? Using a model as a judge

Reading six long answers and deciding which is best is tedious, so the lab asks an LLM to do it. We paste all the answers into one prompt, number them, and tell a model to rank them and reply in JSON. This is called "LLM as judge". Two details matter: the judge is only shown numbered answers, not model names, so it cannot favour a brand; and we force plain JSON so the program can read the result automatically. It is a quick, rough signal — useful, but not a scientific benchmark.

What you should see. The first call prints a genuinely hard question (the instructor's run produced one about the ethics of AI in predictive policing). Each competitor then prints a formatted answer. Finally the judge prints a JSON list like {"results": ["3", "1", …]} and the code turns it into "Rank 1: gemini-2.0-flash", "Rank 2: gpt-4o-mini", and so on. Your exact ranking will differ every time — the models are non-deterministic.
Common mistakes.
  • Missing keys. If a provider's key is not in .env, do not call that model — just skip its cell (or let the if skip it in TypeScript). Calling it without a key raises an authentication error.
  • Forgot the imports. Run the top cell first or later cells fail with name errors.
  • Ollama not running, or wrong model. The local call fails if Ollama is not started or if you never ran ollama pull llama3.2. The model name in the call must match what you pulled.
  • Judge returns extra text. If a model wraps its JSON in a code fence, json.loads fails. The prompt's last line ("no markdown, no code blocks") is there to prevent that — keep it.
  • Different models have different strengths. A small local model like llama3.2 often trails the big cloud models on a hard question, and that is expected. Judge rankings are a fun signal, not a scientific benchmark.
Recap
  • The openai client library is just an HTTP wrapper. It is not a model and has no intelligence of its own.
  • Most providers — Gemini, DeepSeek, Groq, Ollama — offer OpenAI-compatible endpoints, so one client reaches them all by changing base_url and the key.
  • Anthropic's Claude is the exception in the Python lab and uses its own SDK; the TypeScript port reaches it through an OpenAI-compatible base URL instead.
  • The lab orchestrates models in three steps: one writes a question, all answer it, and a judge model ranks the anonymous answers as JSON.
  • Any provider without a key is simply skipped, so you can run everything for free using only local Ollama.
  • This "ask many, then judge" pattern is widely useful whenever you want to raise the quality or robustness of an LLM result.
Honesty note. The cloud API calls are shown exactly as in the course and need each provider's own key to run; they were not re-run live for this guide. The pattern was verified locally against Ollama, and the TypeScript port type-checks and builds with vite.
